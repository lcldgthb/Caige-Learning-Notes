# 13. 智能指针的使用及其原理

## 1. 智能指针的使用场景分析

在正式学习智能指针之前，先思考一个问题：

> **为什么 C++ 需要智能指针？**

因为 C++ 中经常需要动态申请资源：

```cpp
int* p = new int(10);
```

用完以后必须：

```cpp
delete p;
```

看起来很简单，但实际代码中很容易出现问题。

### 1.1 最基本的问题：忘记 `delete`

```cpp
void Func()
{
    int* p = new int(10);

    // 一堆代码……

} // 忘记 delete
```

这里：

```text
new
 ↓
申请堆空间
 ↓
p 指向这块空间
 ↓
函数结束
 ↓
p 被销毁
 ↓
但是 new 出来的空间还在
```

于是就产生了：

> **内存泄漏（Memory Leak）**

---

### 1.2 提前 `return` 导致忘记释放

```cpp
void Func()
{
    int* p = new int(10);

    if (条件)
        return;

    delete p;
}
```

如果条件成立：

```text
new
 ↓
return
 ↓
delete 根本没有执行
```

还是内存泄漏。

---

### 1.3 异常更加麻烦

这也是和你刚刚学习的 **RAII** 最重要的联系。

```cpp
void Func()
{
    int* p = new int(10);

    throw exception();

    delete p;
}
```

执行到：

```cpp
throw exception();
```

程序直接进入异常处理流程：

```text
new
 ↓
发生异常
 ↓
跳出当前函数
 ↓
delete 没执行
```

又产生了内存泄漏。

所以我们发现：

> **手动管理资源最大的麻烦，不是不会 `delete`，而是很难保证所有路径都正确地 `delete`。**

---

## 2. RAII 和智能指针的设计思路

这时候就轮到 **RAII** 出场了。

你刚刚学过：

> **RAII：把资源交给对象管理，利用对象的生命周期自动释放资源。**

那么我们可以自己设计一个简单的智能指针。

### 2.1 最简单的智能指针

```cpp
template<class T>
class SmartPtr
{
public:
    SmartPtr(T* ptr)
        : _ptr(ptr)
    {}

    ~SmartPtr()
    {
        delete _ptr;
    }

private:
    T* _ptr;
};
```

使用：

```cpp
void Func()
{
    SmartPtr<int> p(new int(10));
}
```

这里发生了什么？

```text
SmartPtr<int> p
      ↓
构造 SmartPtr
      ↓
保存 new int 得到的指针
      ↓
函数结束
      ↓
p 析构
      ↓
~SmartPtr()
      ↓
delete _ptr
```

于是我们不需要手动：

```cpp
delete p;
```

而是：

> **让对象的析构函数自动完成资源释放。**

这就是智能指针最核心的设计思想。

---

## 2.2 为什么异常情况下也能释放？

例如：

```cpp
void Func()
{
    SmartPtr<int> p(new int(10));

    throw exception();
}
```

发生异常以后，C++ 会进行我们前面讲过的：

> **栈展开（Stack Unwinding）**

局部对象会被自动析构：

```text
throw
 ↓
栈展开
 ↓
p 是局部对象
 ↓
调用 p.~SmartPtr()
 ↓
delete _ptr
 ↓
资源释放
```

所以：

> **RAII + 异常机制 = 即使异常发生，也可以自动释放资源。**

这就是智能指针非常重要的意义。

---

# 3. 为什么不直接使用普通指针？

你可能会问：

```cpp
SmartPtr<int> p(new int(10));
```

相比：

```cpp
int* p = new int(10);
```

到底多了什么？

关键就在于：

```text
普通指针：
int* p
 ↓
只是保存地址
 ↓
不会自动 delete

智能指针：
SmartPtr<int> p
 ↓
保存地址
 ↓
对象析构时自动释放资源
```

所以要注意：

> **智能指针本质上不是“更智能的指针”，而是“利用对象生命周期管理指针所指向资源的类”。**

当然，现代 C++ 标准库中的智能指针远比我们这个简单版本复杂。

---

# 4. 我们自己设计的智能指针有什么问题？

先别急着认为：

```cpp
template<class T>
class SmartPtr
```

这样就已经解决所有问题了。

例如：

```cpp
SmartPtr<int> p1(new int(10));
SmartPtr<int> p2 = p1;
```

如果我们的类没有特殊处理，可能发生：

```text
p1 ─────┐
        ↓
      int(10)
        ↑
        ↓
p2 ─────┘
```

那么当：

```cpp
p1
```

析构：

```cpp
delete _ptr;
```

之后：

```text
p2 ──→ 已经被释放的内存
```

然后 `p2` 再析构：

```cpp
delete _ptr;
```

就可能发生：

> **重复释放（double free）**

所以智能指针真正困难的地方并不是：

> “怎么自动 `delete`？”

而是：

> **多个指针之间到底应该如何管理同一个资源的所有权？**

这就引出了后面非常重要的：

```text
unique_ptr
shared_ptr
weak_ptr
```

它们解决的是不同的资源所有权问题。

---

# 5. 先建立整个智能指针体系

你后面学习的时候，可以先记住这张关系：

| 智能指针         | 核心思想A         | 是否共享所有权 |
| ------------ | ------------ | ------- |
| `unique_ptr` | 一个资源只能有一个拥有者 | ❌       |
| `shared_ptr` | 多个对象共同拥有资源   | ✅       |
| `weak_ptr`   | 观察资源，但不拥有资源  | ❌       |

例如：

### `unique_ptr`

```cpp
unique_ptr<int> p1(new int(10));
```

表示：

> **这个资源归 `p1` 独占。**

不能随便：

```cpp
unique_ptr<int> p2 = p1; // 错误
```

---

### `shared_ptr`

```cpp
shared_ptr<int> p1(new int(10));
shared_ptr<int> p2 = p1;
```

表示：

```text
        ┌── p1
        │
int(10) ┤
        │
        └── p2
```

两个智能指针共同管理这块资源。

只有最后一个 `shared_ptr` 消失以后，资源才会释放。

---

### `weak_ptr`

`weak_ptr` 更特殊：

```text
shared_ptr
    ↓
真正拥有资源

weak_ptr
    ↓
只是观察资源
    ↓
不增加引用计数
```

它主要用来解决后面非常经典的：

> **`shared_ptr` 循环引用问题**

---

你可以把这一章的前半部分串成这样：

```text
手动 new/delete
       ↓
容易忘记释放资源
       ↓
内存泄漏
       ↓
异常情况下更加危险
       ↓
RAII
       ↓
把资源交给对象生命周期管理
       ↓
智能指针
       ↓
自动管理动态内存
       ↓
进一步解决所有权问题
       ↓
unique_ptr / shared_ptr / weak_ptr
```

而你刚刚学的 **RAII**，实际上就是这条链的核心：

> **智能指针 = RAII 思想在动态内存管理中的典型应用。**

### 总结

这一部分你先牢牢记住三个东西：

1. **普通指针不会自动释放 `new` 出来的资源。**
2. **RAII 利用对象析构函数自动释放资源，即使发生异常也能通过栈展开完成清理。**
3. **智能指针本质上是利用 RAII 管理动态资源，并进一步解决资源所有权问题。**

# 3. C++ 标准库智能指针的使用

C++ 标准库主要提供三个智能指针：

```cpp
unique_ptr
shared_ptr
weak_ptr
```

可以先这样理解：

```text
unique_ptr → 独占资源
shared_ptr → 共享资源
weak_ptr   → 观察资源，不拥有资源
```

## 3.1 `unique_ptr`

`unique_ptr` 的核心思想非常简单：

> **一个资源只能有一个 `unique_ptr` 拥有。**

例如：

```cpp
#include <memory>

unique_ptr<int> p(new int(10));
```

或者更推荐：

```cpp
unique_ptr<int> p = make_unique<int>(10);
```

`p` 就拥有这块动态内存。

当 `p` 生命周期结束：

```text
p 析构
 ↓
自动 delete
 ↓
资源释放
```

因此不需要：

```cpp
delete p;
```

### `unique_ptr` 不能进行普通拷贝

例如：

```cpp
unique_ptr<int> p1 = make_unique<int>(10);

unique_ptr<int> p2 = p1;  // ❌
```

为什么？

因为这样就会出现两个对象同时拥有同一块资源：

```text
p1 ──┐
     ↓
    int
     ↑
p2 ──┘
```

最终两个对象都可能尝试释放同一块内存。

所以 `unique_ptr` 禁止拷贝。

但是它可以**移动**：

```cpp
unique_ptr<int> p1 = make_unique<int>(10);

unique_ptr<int> p2 = std::move(p1);
```

移动之后：

```text
p1 ──→ nullptr

p2 ──→ int(10)
```

也就是：

> **所有权从 `p1` 转移给 `p2`。**

所以你可以把 `unique_ptr` 理解成：

> **“这块资源现在归我，之后可以把所有权转给别人，但不能两个人同时拥有。”**

---

## 3.2 `shared_ptr`

`shared_ptr` 和 `unique_ptr` 最大的区别就是：

> **允许多个智能指针共同拥有同一份资源。**

例如：

```cpp
shared_ptr<int> p1 = make_shared<int>(10);
shared_ptr<int> p2 = p1;
```

现在：

```text
        ┌── p1
        │
int(10) ┤
        │
        └── p2
```

这时候不会立刻释放资源。

因为还有两个 `shared_ptr` 在管理它。

### 引用计数

`shared_ptr` 的核心机制就是：

> **引用计数（reference count）**

例如：

```cpp
shared_ptr<int> p1 = make_shared<int>(10);
```

此时：

```text
p1
 ↓
资源

引用计数 = 1
```

然后：

```cpp
shared_ptr<int> p2 = p1;
```

变成：

```text
p1 ──┐
     ↓
    资源
     ↑
p2 ──┘

引用计数 = 2
```

再：

```cpp
shared_ptr<int> p3 = p1;
```

变成：

```text
引用计数 = 3
```

当：

```cpp
p2.reset();
```

那么：

```text
引用计数 = 2
```

当最后一个 `shared_ptr` 被销毁：

```text
引用计数 = 0
       ↓
释放资源
```

所以：

> **`shared_ptr` 只有在最后一个拥有者消失时，才会释放资源。**

---

## 3.3 `shared_ptr` 的常用操作

### `use_count()`

可以查看当前有多少个 `shared_ptr` 共同拥有资源：

```cpp
shared_ptr<int> p1 = make_shared<int>(10);

cout << p1.use_count() << endl; // 1

shared_ptr<int> p2 = p1;

cout << p1.use_count() << endl; // 2
```

---

### `reset()`

让当前 `shared_ptr` 放弃所有权：

```cpp
shared_ptr<int> p1 = make_shared<int>(10);

p1.reset();
```

此时：

```text
p1 → nullptr
```

如果还有其他 `shared_ptr`：

```cpp
shared_ptr<int> p1 = make_shared<int>(10);
shared_ptr<int> p2 = p1;

p1.reset();
```

那么资源仍然存在：

```text
p1 → nullptr

p2 ──→ 资源
```

因为：

```text
引用计数 = 1
```

---

## 3.4 `make_shared`

你经常会看到：

```cpp
shared_ptr<int> p = make_shared<int>(10);
```

而不是：

```cpp
shared_ptr<int> p(new int(10));
```

一般更推荐：

```cpp
make_shared
```

因为它可以让标准库更加高效地完成 `shared_ptr` 对象和相关控制信息的分配，而且代码也更简洁。

你现在先记住：

```cpp
unique_ptr<int> p = make_unique<int>(10);

shared_ptr<int> p = make_shared<int>(10);
```

这是现代 C++ 中非常常见的写法。

---

# 4. `weak_ptr`

现在来看第三种：

```cpp
weak_ptr
```

它和前面两个最大的不同是：

> **`weak_ptr` 不拥有资源。**

例如：

```cpp
shared_ptr<int> p = make_shared<int>(10);

weak_ptr<int> w = p;
```

现在：

```text
        ┌── shared_ptr
        │
资源 ───┤
        │
        └── weak_ptr
```

但是这里的 `weak_ptr`：

> **只是观察资源，并没有拥有资源。**

因此它不会让 `shared_ptr` 的引用计数增加。

例如：

```cpp
shared_ptr<int> p = make_shared<int>(10);

cout << p.use_count() << endl; // 1

weak_ptr<int> w = p;

cout << p.use_count() << endl; // 仍然是 1
```

这就是 `weak_ptr` 和 `shared_ptr` 一个非常重要的区别。

---

## 4.1 为什么需要 `weak_ptr`？

这个问题先留一个入口，因为后面会专门讲：

> **`shared_ptr` 最大的问题之一：循环引用。**

例如两个对象：

```text
A ──shared_ptr──→ B
↑                 │
└────shared_ptr───┘
```

A 持有 B：

```cpp
shared_ptr<B> _b;
```

B 又持有 A：

```cpp
shared_ptr<A> _a;
```

结果：

```text
A → B → A → B → ...
```

即使外面的 `shared_ptr` 全部销毁，A 和 B 内部依然互相持有：

```text
A 的引用计数 ≠ 0
B 的引用计数 ≠ 0
```

于是：

> **A、B 都无法释放，形成内存泄漏。**

而 `weak_ptr` 就是专门用来解决这种问题的重要工具之一。

这个我们下一部分会详细讲。

---

# 5. 三种智能指针放在一起

现在先形成一个整体认识：

| 智能指针         | 是否拥有资源 | 是否允许拷贝 | 核心机制  |
| ------------ | -----: | -----: | ----- |
| `unique_ptr` |      ✅ |      ❌ | 独占所有权 |
| `shared_ptr` |      ✅ |      ✅ | 引用计数  |
| `weak_ptr`   |      ❌ |      ✅ | 弱引用   |

可以用一句话记：

```text
unique_ptr：我一个人拥有
shared_ptr：我们一起拥有
weak_ptr：我只观察，不拥有
```

这三句话非常重要。

### 一个容易混淆的地方

不要认为：

```text
unique_ptr → shared_ptr → weak_ptr
```

是“越来越高级”的关系。

它们实际上是**三种不同的所有权语义**：

```text
             资源
              │
      ┌───────┼───────┐
      ↓       ↓       ↓
 unique_ptr shared_ptr weak_ptr
   独占       共享      观察
```

后面真正进入原理时，你会发现：

* `unique_ptr` 的实现相对简单，核心就是 RAII + 所有权转移；
* `shared_ptr` 的核心是**控制块 + 引用计数**；
* `weak_ptr` 的核心是**控制块 + 弱引用计数 + 解决循环引用**。

### 总结

这一部分最需要记住的是：

> **`unique_ptr`：独占资源，不能拷贝，只能移动。**
>
> **`shared_ptr`：共享资源，通过引用计数决定什么时候释放。**
>
> **`weak_ptr`：不拥有资源，只观察 `shared_ptr` 管理的资源，不增加强引用计数。**

下一部分就是这章最值得认真理解的内容：**“智能指针的原理”**——我们会自己实现一个简化版 `unique_ptr`，再理解 `shared_ptr` 的**控制块、引用计数、拷贝、析构、移动**到底是怎么工作的。

继续，这一部分进入 **第 4 节：智能指针的原理**。这一节建议重点理解 `unique_ptr` 和 `shared_ptr` 的实现思路，因为你后面学 `shared_ptr + weak_ptr` 循环引用时，就会发现前面的内容全部串起来了。

# 4. 智能指针的原理

## 4.1 `unique_ptr` 的原理

我们先自己实现一个最简单的 `unique_ptr`：

```cpp
template<class T>
class MyUniquePtr
{
public:
    MyUniquePtr(T* ptr)
        : _ptr(ptr)
    {}

    ~MyUniquePtr()
    {
        delete _ptr;
    }

private:
    T* _ptr;
};
```

使用：

```cpp
MyUniquePtr<int> p(new int(10));
```

本质上就是：

```text
p
↓
保存 int* 指针
↓
p 生命周期结束
↓
调用析构函数
↓
delete _ptr
```

这就是最核心的 **RAII**。

### 但是有一个严重问题：拷贝

如果我们允许：

```cpp
MyUniquePtr<int> p1(new int(10));
MyUniquePtr<int> p2 = p1;
```

那么：

```text
p1 ──┐
     ↓
    int(10)
     ↑
p2 ──┘
```

最终：

```text
p1 析构 → delete
p2 析构 → 再次 delete
```

所以 `unique_ptr` 必须禁止拷贝。

实际上就是把拷贝构造和拷贝赋值禁掉：

```cpp
MyUniquePtr(const MyUniquePtr&) = delete;

MyUniquePtr& operator=(const MyUniquePtr&) = delete;
```

于是：

```cpp
MyUniquePtr<int> p1(new int(10));

MyUniquePtr<int> p2 = p1;  // ❌
```

就不允许了。

---

## 4.2 那 `unique_ptr` 怎么转移所有权？

虽然不能拷贝，但是可以**移动**：

```cpp
MyUniquePtr<int> p1(new int(10));

MyUniquePtr<int> p2 = std::move(p1);
```

转移之后：

```text
p1 → nullptr

p2 ──→ int(10)
```

所以移动构造大致可以这样理解：

```cpp
MyUniquePtr(MyUniquePtr&& other)
{
    _ptr = other._ptr;
    other._ptr = nullptr;
}
```

关键就是：

```cpp
_ptr = other._ptr;
other._ptr = nullptr;
```

也就是：

> **把资源的所有权拿过来，然后让原对象放弃所有权。**

这就是 `unique_ptr` 的核心原理。

---

# 4.3 `shared_ptr` 的原理

`shared_ptr` 就比 `unique_ptr` 复杂很多。

因为它允许：

```cpp
shared_ptr<int> p1 = make_shared<int>(10);
shared_ptr<int> p2 = p1;
shared_ptr<int> p3 = p1;
```

三个对象共同管理同一份资源。

那么问题来了：

> **到底什么时候才能 `delete`？**

答案就是：

> **引用计数。**

例如：

```text
p1 ──┐
     │
p2 ──┼──→ int(10)
     │
p3 ──┘

引用计数 = 3
```

销毁 `p1`：

```text
引用计数 = 2
```

销毁 `p2`：

```text
引用计数 = 1
```

销毁 `p3`：

```text
引用计数 = 0
       ↓
delete
```

所以：

> **`shared_ptr` 的核心就是：多个 `shared_ptr` 共享一个引用计数。**

---

# 4.4 引用计数放在哪里？

这就是 `shared_ptr` 实现中的关键。

假设：

```cpp
shared_ptr<int> p1(new int(10));
```

不能简单地让每个 `shared_ptr` 自己保存一个计数：

```text
p1 → int
     count = 1

p2 → int
     count = 1
```

因为：

```cpp
shared_ptr<int> p2 = p1;
```

之后两个计数必须是**同一个计数**。

所以需要一个大家共享的东西：

> **控制块（Control Block）**

大致可以理解成：

```text
p1 ─────────┐
            ↓
        ┌─────────────┐
        │ 控制块       │
        │             │
        │ 引用计数=2   │
        │ 弱引用计数   │
        │ 其他信息     │
        └──────┬──────┘
               │
               ↓
            int(10)
```

因此，一个 `shared_ptr` 实际上需要关注两部分：

```text
shared_ptr
   │
   ├── 管理的资源
   │
   └── 控制块
          └── 引用计数
```

---

# 4.5 自己实现一个简化版 `shared_ptr`

我们可以写一个非常简化的版本：

```cpp
template<class T>
class MySharedPtr
{
public:
    MySharedPtr(T* ptr)
        : _ptr(ptr)
        , _pcount(new int(1))
    {}

    MySharedPtr(const MySharedPtr& sp)
        : _ptr(sp._ptr)
        , _pcount(sp._pcount)
    {
        ++(*_pcount);
    }

    ~MySharedPtr()
    {
        if (--(*_pcount) == 0)
        {
            delete _ptr;
            delete _pcount;
        }
    }

private:
    T* _ptr;
    int* _pcount;
};
```

先不要纠结代码细节，我们只看思想。

创建：

```cpp
MySharedPtr<int> p1(new int(10));
```

此时：

```text
p1 ──────────→ int(10)
 │
 └──────────→ count = 1
```

拷贝：

```cpp
MySharedPtr<int> p2 = p1;
```

此时：

```text
p1 ──┐
     ├────────→ int(10)
p2 ──┘

      count = 2
```

再拷贝：

```cpp
MySharedPtr<int> p3 = p1;
```

变成：

```text
p1 ──┐
p2 ──┼───────→ int(10)
p3 ──┘

      count = 3
```

---

# 4.6 `shared_ptr` 析构的时候发生什么？

假设现在：

```text
count = 3
```

`p1` 析构：

```text
--count
count = 2
```

资源不释放。

`p2` 析构：

```text
--count
count = 1
```

资源仍然不释放。

最后 `p3` 析构：

```text
--count
count = 0
```

此时：

```cpp
delete _ptr;
```

资源释放。

所以核心逻辑就是：

```cpp
if (--引用计数 == 0)
{
    delete 资源;
}
```

你可以把它直接记下来。

---

# 4.7 `shared_ptr` 为什么需要控制块？

实际的标准库 `shared_ptr` 比我们刚才写的复杂得多。

控制块中除了强引用计数，通常还会保存：

```text
控制块
├── 强引用计数 strong count
├── 弱引用计数 weak count
├── 删除器 deleter
└── 其他管理信息
```

其中：

> **强引用计数决定资源什么时候释放。**

而：

> **弱引用计数决定控制块什么时候释放。**

这句话非常重要。

因为后面学习 `weak_ptr` 时会用到。

---

# 4.8 `shared_ptr` 的拷贝到底发生了什么？

例如：

```cpp
shared_ptr<int> p1 = make_shared<int>(10);
shared_ptr<int> p2 = p1;
```

不是：

```text
p2 重新创建一个 int
```

而是：

```text
p1 ──┐
     │
     ├────→ 同一个 int
     │
p2 ──┘
```

并且：

```text
p1 ──┐
     ├────→ 控制块
p2 ──┘

控制块：
strong_count = 2
```

所以：

> **`shared_ptr` 的拷贝，本质上是“共享资源 + 增加引用计数”。**

---

# 4.9 `shared_ptr` 的移动又是什么？

例如：

```cpp
shared_ptr<int> p1 = make_shared<int>(10);

shared_ptr<int> p2 = std::move(p1);
```

它和拷贝不一样。

移动并不需要增加引用计数，而是直接转移内部管理信息：

```text
移动前：

p1 ──→ 控制块 ──→ int


移动后：

p1 ──→ nullptr

p2 ──→ 控制块 ──→ int
```

所以：

> **拷贝 `shared_ptr`：引用计数 +1。**
>
> **移动 `shared_ptr`：转移所有权关系，通常不增加引用计数。**

---

# 5. 现在理解 `unique_ptr` 和 `shared_ptr` 的本质区别

可以从“所有权”角度理解：

```text
unique_ptr
     ↓
独占所有权
     ↓
不能拷贝
     ↓
只能移动
```

而：

```text
shared_ptr
     ↓
共享所有权
     ↓
可以拷贝
     ↓
通过引用计数管理生命周期
```

所以不要简单记成：

> `unique_ptr` 比 `shared_ptr` 简单。

更准确的是：

> **它们表达的是不同的所有权语义。**

如果一个资源天然就应该只有一个拥有者，那么 `unique_ptr` 就很合适；如果确实存在多个对象共同拥有资源的情况，才需要 `shared_ptr`。

---

# 6. 一个非常重要的细节：`shared_ptr` 的引用计数 ≠ 资源本身

这一点你后面学习 `weak_ptr` 时一定会遇到。

例如：

```text
              控制块
           ┌────────────┐
           │ strong=2   │
           │ weak=0     │
           └─────┬──────┘
                 │
                 ↓
              int(10)
```

这里实际上有两个生命周期：

```text
shared_ptr 的生命周期
        ↓
强引用计数

资源的生命周期
        ↓
strong_count == 0 时释放
```

而控制块本身又有自己的生命周期。

这就是为什么 `weak_ptr` 会比较复杂。

# 7. 先把整个原理串起来

你现在可以形成这样的知识链：

```text
RAII
 ↓
对象析构时自动释放资源
 ↓
unique_ptr
 ↓
独占资源
 ↓
不能拷贝，只能移动

RAII
 ↓
多个对象共同管理资源
 ↓
shared_ptr
 ↓
控制块
 ↓
引用计数
 ↓
最后一个 shared_ptr 消失
 ↓
释放资源
```

然后马上会出现一个问题：

```text
A ──shared_ptr──→ B
↑                 │
└────shared_ptr───┘
```

如果两个对象互相持有 `shared_ptr`：

```text
引用计数永远不为 0
        ↓
资源永远无法释放
        ↓
循环引用
        ↓
内存泄漏
```

这就是下一部分目录中的：

> **5.1 `shared_ptr` 循环引用问题**

而解决它的关键就是：

> **5.2 `weak_ptr`**

### 总结

这一部分最重要的不是背代码，而是理解三个底层模型：

```text
unique_ptr：
对象 → 资源
```

```text
shared_ptr：
对象 → 控制块 → 资源
         ↑
     引用计数
```

```text
weak_ptr：
对象 → 控制块
         ↓
       观察资源
       但不拥有
```

# 5. `shared_ptr` 和 `weak_ptr`

## 5.1 `shared_ptr` 的循环引用问题

先看一个非常经典的例子：

```cpp
struct Node
{
    shared_ptr<Node> _next;
    shared_ptr<Node> _prev;
};
```

假设：

```cpp
shared_ptr<Node> node1 = make_shared<Node>();
shared_ptr<Node> node2 = make_shared<Node>();

node1->_next = node2;
node2->_prev = node1;
```

现在形成：

```text
node1 ──shared_ptr──→ node2
  ↑                    │
  └────shared_ptr──────┘
```

看起来没什么问题，但我们来数引用计数。

### 第一步：创建两个节点

```cpp
shared_ptr<Node> node1 = make_shared<Node>();
shared_ptr<Node> node2 = make_shared<Node>();
```

此时：

```text
node1 → Node1

Node1 引用计数 = 1


node2 → Node2

Node2 引用计数 = 1
```

---

### 第二步：`node1->_next = node2`

现在 Node1 内部又有一个 `shared_ptr` 指向 Node2：

```text
node2 ───────┐
             ↓
node1 → Node1 → Node2
```

所以：

```text
Node1 引用计数 = 1
Node2 引用计数 = 2
```

为什么 Node2 是 2？

因为：

```text
node2
  ↓
Node2

Node1->_next
  ↓
Node2
```

有两个 `shared_ptr` 拥有 Node2。

---

### 第三步：`node2->_prev = node1`

现在反过来：

```text
        ┌──────────────┐
        ↓              │
node1 → Node1 → Node2
        ↑              │
        └──────────────┘
```

此时：

```text
Node1 引用计数 = 2
Node2 引用计数 = 2
```

因为：

```text
Node1：
node1
node2->_prev

Node2：
node2
node1->_next
```

各有两个 `shared_ptr` 指向它们。

---

## 5.1.1 问题出现了

现在假设外部的：

```cpp
node1
node2
```

都销毁了。

你可能认为：

```text
node1 销毁
 ↓
Node1 引用计数 -1

node2 销毁
 ↓
Node2 引用计数 -1
```

最终：

```text
Node1 引用计数 = 1
Node2 引用计数 = 1
```

注意：

> **并没有变成 0！**

因为：

```text
Node1 ←── node2->_prev
Node2 ←── node1->_next
```

它们还在互相持有。

于是：

```text
Node1 → Node2
  ↑       │
  └───────┘
```

两个对象永远等着对方释放。

但是：

```text
Node1 不释放
 ↓
node2->_prev 不释放
 ↓
Node1 引用计数无法归零

Node2 不释放
 ↓
node1->_next 不释放
 ↓
Node2 引用计数无法归零
```

最终：

> **形成循环引用，导致内存泄漏。**

---

# 5.2 `weak_ptr`

那么怎么解决？

核心思路：

> **有些关系并不需要“拥有”对象，只需要“观察”对象。**

例如：

```text
Node1 → Node2
```

`Node1` 可能需要知道自己的下一个节点是谁。

但：

```text
Node2 → Node1
```

这个关系实际上不一定需要拥有 Node1。

所以可以把：

```cpp
shared_ptr<Node> _prev;
```

改成：

```cpp
weak_ptr<Node> _prev;
```

完整代码：

```cpp
struct Node
{
    shared_ptr<Node> _next;
    weak_ptr<Node> _prev;
};
```

然后：

```cpp
shared_ptr<Node> node1 = make_shared<Node>();
shared_ptr<Node> node2 = make_shared<Node>();

node1->_next = node2;
node2->_prev = node1;
```

现在：

```text
node1 ──shared_ptr──→ Node1
                         │
                         ↓
                      Node2
                         ↑
                         │
node2 ──shared_ptr───────┘

Node2 ──weak_ptr──→ Node1
```

更准确地画：

```text
node1 ──┐
        ↓
      Node1 ──shared_ptr──→ Node2
        ↑                    ↑
        │                    │
        └── weak_ptr ───── node2
```

关键区别：

```text
shared_ptr → 拥有资源
weak_ptr   → 不拥有资源
```

所以 `weak_ptr` **不会增加 `shared_ptr` 的强引用计数**。

---

# 5.2.1 为什么这样就能解决循环引用？

创建：

```cpp
node1->_next = node2;
```

Node2：

```text
强引用计数 = 2
```

创建：

```cpp
node2->_prev = node1;
```

因为 `_prev` 是 `weak_ptr`：

```text
Node1 强引用计数 = 1
```

而不是 2。

所以现在：

```text
Node1：
强引用计数 = 1

Node2：
强引用计数 = 2
```

外面的：

```cpp
node1
node2
```

销毁后：

```text
Node1：
强引用计数 = 0
 ↓
释放 Node1
```

Node2：

```text
强引用计数 = 1
```

但是 Node1 被释放之后：

```text
Node1->_next
```

也被析构：

```text
Node2 强引用计数 = 0
 ↓
释放 Node2
```

于是两个对象最终都能正常释放。

---

# 5.2.2 `weak_ptr` 怎么访问资源？

这里有一个非常重要的问题：

既然：

```cpp
weak_ptr<Node> _prev;
```

不拥有对象，那么我如果想访问它怎么办？

不能直接：

```cpp
_prev->_xxx; // ❌
```

而是需要：

```cpp
auto p = _prev.lock();
```

例如：

```cpp
weak_ptr<int> w = p;

shared_ptr<int> s = w.lock();
```

`lock()` 会尝试获取一个 `shared_ptr`。

如果资源还存在：

```text
weak_ptr
   ↓
资源还存在
   ↓
lock()
   ↓
得到 shared_ptr
```

如果资源已经释放：

```text
weak_ptr
   ↓
资源已经不存在
   ↓
lock()
   ↓
得到空 shared_ptr
```

所以通常写成：

```cpp
if (auto p = w.lock())
{
    cout << *p << endl;
}
```

意思就是：

> **如果资源还存在，就临时获取一个 `shared_ptr` 来访问它。**

---

# 5.2.3 `expired()`

`weak_ptr` 还有一个常见函数：

```cpp
expired()
```

它可以判断：

> **它所观察的资源是否已经释放。**

例如：

```cpp
if (w.expired())
{
    cout << "资源已经释放" << endl;
}
```

但是实际使用中，通常更推荐直接：

```cpp
if (auto p = w.lock())
{
    // 使用资源
}
```

因为 `lock()` 本身就可以完成：

```text
资源存在 → 获取 shared_ptr
资源不存在 → 得到空 shared_ptr
```

---

# 5.3 `weak_ptr` 的核心特点

你可以记住这四点：

| 特点        | `weak_ptr`               |
| --------- | ------------------------ |
| 是否拥有资源    | ❌                        |
| 是否增加强引用计数 | ❌                        |
| 能否直接访问对象  | ❌                        |
| 如何访问      | `lock()` 获取 `shared_ptr` |

最重要的一句话：

> **`weak_ptr` 是一种不拥有资源的智能指针，它只是观察 `shared_ptr` 管理的资源。**

---

# 5.4 为什么叫“弱引用”？

这里的“弱”其实很好理解。

`shared_ptr`：

```text
我拥有这个对象
```

所以：

```text
shared_ptr → 强引用
```

而 `weak_ptr`：

```text
我只是看看这个对象还在不在
```

所以：

```text
weak_ptr → 弱引用
```

它不会阻止对象被销毁。

---

# 5.5 最重要的一个认识

你现在应该能理解为什么：

```cpp
shared_ptr
```

不能简单地理解为：

> “多个指针一起指向一个对象。”

更准确地说：

> **多个 `shared_ptr` 共同拥有一个对象。**

而：

```cpp
weak_ptr
```

则是：

> **可以指向这个对象，但不参与对象所有权管理。**

这就是两者最本质的区别。

---

# 5.6 一个实际中非常典型的场景

比如：

```text
父对象
  ↓
子对象
```

父对象拥有子对象：

```cpp
shared_ptr<Child> child;
```

这是合理的：

```text
Parent
  │
  └──shared_ptr──→ Child
```

但是如果 Child 又需要知道自己的 Parent：

```cpp
weak_ptr<Parent> parent;
```

就很合适：

```text
Parent
  │
  └──shared_ptr──→ Child
                         │
                         └──weak_ptr──→ Parent
```

为什么 Child 不应该再用 `shared_ptr`？

因为那样就可能变成：

```text
Parent → Child → Parent
```

形成循环引用。

所以实际工程中经常会出现这样的设计：

> **拥有关系使用 `shared_ptr`，反向观察关系使用 `weak_ptr`。**

---

# 5.7 现在把整个 `shared_ptr + weak_ptr` 串起来

```text
shared_ptr
    ↓
控制块
    ↓
强引用计数
    ↓
决定资源什么时候释放
```

而：

```text
weak_ptr
    ↓
控制块
    ↓
不增加强引用计数
    ↓
不拥有资源
    ↓
避免循环引用
```

最终：

```text
shared_ptr
    ↓
拥有资源
    ↓
引用计数归零
    ↓
释放资源


weak_ptr
    ↓
只观察资源
    ↓
lock()
    ↓
临时获得 shared_ptr
```

### 总结

这一部分你重点记住这几个结论：

> **① `shared_ptr` 通过引用计数管理共享资源。**

> **② 两个对象互相持有 `shared_ptr`，会形成循环引用，使引用计数无法归零，从而导致内存泄漏。**

> **③ `weak_ptr` 不拥有资源，也不会增加强引用计数，因此可以打破循环引用。**

> **④ `weak_ptr` 不能直接访问资源，需要通过 `lock()` 获取一个 `shared_ptr`。**

> **⑤ `shared_ptr` 解决“共享所有权”，`weak_ptr` 解决“只观察、不拥有”，其中一个重要用途就是解决循环引用。**

# 6. `shared_ptr` 的线程安全问题

首先记住一个非常重要的结论：

> **`shared_ptr` 的引用计数操作通常是线程安全的，但 `shared_ptr` 管理的对象本身不一定是线程安全的。**

这句话很容易混淆，我们拆开来看。

## 6.1 多个线程操作不同的 `shared_ptr`

例如：

```cpp
shared_ptr<int> p = make_shared<int>(10);
```

然后：

```text
线程1：使用 p1
线程2：使用 p2
```

其中：

```cpp
shared_ptr<int> p1 = p;
shared_ptr<int> p2 = p;
```

现在：

```text
p1 ──┐
     │
p2 ──┼──→ int(10)
     │
p  ──┘
```

多个线程分别操作自己的 `shared_ptr`：

```text
线程1 → p1
线程2 → p2
```

这种情况下，**引用计数的增减由标准库进行必要的同步处理**，不会因为多个线程同时销毁各自的 `shared_ptr` 而把引用计数搞乱。

可以简单理解为：

```text
线程1                  线程2
  │                      │
  ↓                      ↓
p1 析构                 p2 析构
  │                      │
  └──────→ 引用计数 ←────┘
             ↓
        安全地进行计数管理
```

---

## 6.2 但是，管理的对象不一定线程安全

例如：

```cpp
shared_ptr<int> p = make_shared<int>(0);
```

两个线程同时：

```cpp
(*p)++;
```

这里真正被修改的是：

```text
int(0)
```

而不是 `shared_ptr` 本身。

所以：

> **`shared_ptr` 的线程安全 ≠ `shared_ptr` 指向的对象线程安全。**

例如：

```cpp
shared_ptr<vector<int>> p = make_shared<vector<int>>();
```

两个线程同时：

```cpp
p->push_back(1);
p->push_back(2);
```

这里 `vector` 本身的并发修改就需要另外考虑同步问题。

---

## 6.3 同一个 `shared_ptr` 对象被多个线程同时修改

这个情况又不一样。

例如：

```cpp
shared_ptr<int> p;
```

线程 1：

```cpp
p = make_shared<int>(10);
```

线程 2：

```cpp
p = make_shared<int>(20);
```

这里多个线程直接同时修改**同一个 `shared_ptr` 对象 `p`**。

这就不能简单地说：

> "`shared_ptr` 是线程安全的，所以没问题。"

因为这里发生的是：

```text
线程1 ──→ 修改 p
             ↑
线程2 ───────┘
```

也就是**同一个 `shared_ptr` 对象本身发生并发访问/修改**，需要额外同步。

你现在先记住：

> **多个 `shared_ptr` 实例共享一个资源：引用计数管理可以安全地进行；但同一个 `shared_ptr` 对象被多个线程同时读写，不能直接认为安全。**

---

## 6.4 一个非常实用的区分

可以把线程安全问题拆成三个层次：

| 情况                         | 是否可以直接认为安全   |
| -------------------------- | ------------ |
| 多个 `shared_ptr` 共同管理同一资源   | 引用计数层面可以安全管理 |
| 多线程同时修改 `shared_ptr` 指向的对象 | ❌ 不保证        |
| 多线程同时修改同一个 `shared_ptr` 对象 | ❌ 需要同步       |

所以考试/面试时如果问：

> **`shared_ptr` 是线程安全的吗？**

不要简单回答：

```text
是
```

也不要简单回答：

```text
不是
```

更准确的是：

> **`shared_ptr` 的引用计数管理具有线程安全保证，但它不保证所管理对象的线程安全，也不能让同一个 `shared_ptr` 对象的并发读写自动变得安全。**

# 7. C++11 和 Boost 中智能指针的关系

这一部分主要是历史背景。

在 C++11 之前，C++ 标准库还没有现在这些：

```cpp
unique_ptr
shared_ptr
weak_ptr
```

但是 **Boost** 很早就提供了智能指针。

例如：

```cpp
boost::shared_ptr
boost::weak_ptr
```

Boost 是一个非常大的 C++ 第三方库集合，其中很多功能后来被 C++ 标准吸收。

所以你可能会看到这样的代码：

```cpp
boost::shared_ptr<int> p;
```

也会看到：

```cpp
std::shared_ptr<int> p;
```

它们的思想非常接近。

---

## 7.1 C++11 引入标准智能指针

C++11 后，标准库提供：

```cpp
std::unique_ptr
std::shared_ptr
std::weak_ptr
```

所以现代 C++ 一般优先使用：

```cpp
std::unique_ptr
std::shared_ptr
std::weak_ptr
```

而不是：

```cpp
boost::shared_ptr
```

例如：

```cpp
std::shared_ptr<int> p = std::make_shared<int>(10);
```

---

## 7.2 Boost 为什么还存在？

不是说：

> **C++11 出现以后 Boost 就没用了。**

Boost 依然包含大量标准库没有直接提供的功能。

而且 Boost 中有些库后来进入了 C++ 标准，例如：

```text
Boost
 ↓
经过实践、改进
 ↓
部分功能进入 C++ 标准
 ↓
成为 std::xxx
```

智能指针就是一个典型例子。

所以可以简单理解：

> **Boost 在现代 C++ 的发展过程中起到了重要的“试验场”和补充库作用。**

---

# 8. C++11 智能指针简单对照

你可以整理成：

| Boost               | C++11 标准库                         |
| ------------------- | --------------------------------- |
| `boost::shared_ptr` | `std::shared_ptr`                 |
| `boost::weak_ptr`   | `std::weak_ptr`                   |
| `boost::scoped_ptr` | `std::unique_ptr`（思想接近，但不是严格一一对应） |

这里特别注意：

```cpp
boost::scoped_ptr
```

和：

```cpp
std::unique_ptr
```

不能简单说成“完全一样”，但二者都体现了**独占所有权**这一思想。

现代 C++ 开发中，优先考虑标准库版本即可。

---

# 9. 为什么现在更推荐 `unique_ptr`？

你学习到这里可能会产生一个问题：

> 既然 `shared_ptr` 这么方便，为什么不所有地方都用 `shared_ptr`？

因为：

```text
shared_ptr
```

需要维护：

```text
控制块
引用计数
强引用
弱引用
```

它的管理成本比 `unique_ptr` 更高。

而：

```text
unique_ptr
```

核心就是：

```text
一个指针
+
析构时自动释放
```

所以如果资源明确只有一个拥有者：

```cpp
unique_ptr<Foo> p = make_unique<Foo>();
```

通常更符合它的所有权语义。

可以记一个现代 C++ 中非常重要的思想：

> **默认优先考虑 `unique_ptr`，确实需要共享所有权时再使用 `shared_ptr`。**

---

# 10. 到这里，智能指针的主体已经串起来了

整个知识体系可以画成：

```text
智能指针
│
├── unique_ptr
│     ├── RAII
│     ├── 独占所有权
│     ├── 禁止拷贝
│     └── 支持移动
│
├── shared_ptr
│     ├── 共享所有权
│     ├── 控制块
│     ├── 引用计数
│     ├── 拷贝 → 引用计数 +1
│     ├── 析构 → 引用计数 -1
│     └── 计数归零 → 释放资源
│
└── weak_ptr
      ├── 不拥有资源
      ├── 不增加强引用计数
      ├── lock()
      └── 解决 shared_ptr 循环引用
```

然后：

```text
Boost
 ↓
提供智能指针等功能
 ↓
部分思想/实现进入 C++ 标准
 ↓
C++11
 ↓
std::unique_ptr
std::shared_ptr
std::weak_ptr
```

### 总结

这一部分重点记住：

> **① `shared_ptr` 的引用计数管理可以安全地支持多个 `shared_ptr` 实例并发进行生命周期管理。**

> **② `shared_ptr` 不保证所管理对象本身的线程安全。**

> **③ 同一个 `shared_ptr` 对象被多个线程同时修改，也需要额外同步。**

> **④ Boost 很多功能是现代 C++ 标准库发展的重要来源之一。**

> **⑤ C++11 以后，智能指针通常优先使用 `std::unique_ptr`、`std::shared_ptr`、`std::weak_ptr`。**

> **⑥ 没有共享所有权需求时，通常优先考虑 `unique_ptr`；确实需要共享所有权时再考虑 `shared_ptr`。**

下一部分就是你目录最后的 **8. 内存泄漏：什么是内存泄漏、有什么危害、怎么检测、怎么避免**。这部分会把前面学的 **RAII + 智能指针 + 循环引用** 全部收束起来。

继续讲最后一大部分：**8. 内存泄漏**。这一部分其实是在给前面的 RAII、智能指针、循环引用做总结，所以理解起来会比较顺。

# 8. 内存泄漏

## 8.1 什么是内存泄漏？

先看最简单的例子：

```cpp
void Func()
{
    int* p = new int(10);
}
```

函数结束后：

```text
p 被销毁
 ↓
p 保存的地址丢失
 ↓
new 出来的内存还存在
 ↓
无法再找到这块内存
```

这就是：

> **内存泄漏（Memory Leak）：程序申请的动态内存没有被正确释放，并且已经无法再访问这块内存。**

注意一个很重要的点：

> **变量 `p` 消失 ≠ `new` 出来的内存自动释放。**

因为：

```cpp
int* p = new int(10);
```

这里其实有两个东西：

```text
栈上：
p
↓
保存地址

堆上：
int(10)
```

函数结束：

```text
p 消失
```

但是：

```text
int(10)
```

还在堆上。

---

# 8.2 内存泄漏有什么危害？

假设一个函数不断执行：

```cpp
void Func()
{
    int* p = new int[1000];
}
```

每执行一次：

```text
申请内存
 ↓
没有释放
 ↓
再申请
 ↓
没有释放
 ↓
……
```

程序运行时间越长，占用的内存可能越来越多。

最终可能出现：

```text
内存占用不断增加
        ↓
系统可用内存减少
        ↓
程序性能下降
        ↓
严重时申请内存失败
```

所以内存泄漏特别容易出现在：

* 长时间运行的服务器程序
* 后台服务
* 游戏
* 高并发程序
* 数据库等长期运行的软件

对于你以后学习的 **C++ 后端开发**，这个问题尤其重要。

---

# 8.3 最常见的内存泄漏情况

## 情况一：忘记 `delete`

```cpp
int* p = new int(10);

// 忘记 delete
```

这是最基础的一种。

正确：

```cpp
int* p = new int(10);

delete p;
```

---

## 情况二：异常导致 `delete` 没执行

例如：

```cpp
void Func()
{
    int* p = new int(10);

    throw exception();

    delete p;
}
```

这里：

```text
new
 ↓
throw
 ↓
delete 没执行
```

因此产生泄漏。

这也是为什么前面我们一直强调：

> **RAII 对异常安全非常重要。**

---

## 情况三：多个分支导致遗漏

例如：

```cpp
void Func(int x)
{
    int* p = new int(10);

    if (x == 0)
        return;

    delete p;
}
```

当：

```cpp
x == 0
```

时：

```text
return
 ↓
delete 没执行
```

又泄漏了。

这也是手动资源管理容易出错的地方。

---

# 8.4 `shared_ptr` 的循环引用也是内存泄漏

前面我们已经学过：

```cpp
struct Node
{
    shared_ptr<Node> next;
    shared_ptr<Node> prev;
};
```

形成：

```text
Node1 → Node2
  ↑       ↓
  └───────┘
```

即使外部的 `shared_ptr` 全部销毁：

```text
Node1 引用计数 = 1
Node2 引用计数 = 1
```

永远无法变成：

```text
0
```

所以：

```text
资源无法释放
 ↓
内存泄漏
```

解决方法：

```cpp
weak_ptr<Node> prev;
```

因此你现在应该能理解：

> **智能指针并不意味着“100%不会内存泄漏”。**

这是一个非常重要的认识。

---

# 8.5 如何检测内存泄漏？

你的目录这里写的是：

> **了解**

所以不用在这里深入工具原理，知道常见工具即可。

### Windows

Visual Studio 本身就提供了一些内存泄漏检测机制，例如：

```cpp
#define _CRTDBG_MAP_ALLOC
#include <crtdbg.h>
```

配合：

```cpp
_CrtDumpMemoryLeaks();
```

可以检测一些未释放的内存。

---

### Linux

以后你学习 Linux/C++ 后，会经常接触：

```text
Valgrind
```

其中比较常用的是：

```bash
valgrind --leak-check=full ./test
```

它可以帮助检查：

```text
内存泄漏
非法内存访问
未释放内存
```

另外现代 C++ 项目中还经常使用：

```text
AddressSanitizer（ASan）
```

它对：

```text
越界访问
Use-After-Free
内存泄漏
```

等问题都有很好的检测能力。

你以后学 Linux 和 C++ 后端时，这几个工具值得掌握。

# 8.6 如何避免内存泄漏？

核心思想其实就是一句：

> **谁负责申请资源，谁就必须保证资源最终能够被正确释放；更推荐直接使用 RAII 自动管理。**

现代 C++ 中最重要的方法就是：

### 方法一：优先使用 RAII

例如不要：

```cpp
int* p = new int(10);

// 手动管理
delete p;
```

而是：

```cpp
auto p = make_unique<int>(10);
```

让：

```text
p 生命周期结束
 ↓
自动释放
```

---

### 方法二：使用 `unique_ptr`

```cpp
unique_ptr<int> p = make_unique<int>(10);
```

它负责：

```text
new
 ↓
管理
 ↓
析构
 ↓
delete
```

不需要手动：

```cpp
delete
```

---

### 方法三：确实需要共享所有权时使用 `shared_ptr`

```cpp
shared_ptr<int> p = make_shared<int>(10);
```

多个对象需要共同拥有资源时：

```cpp
auto p2 = p;
```

通过引用计数管理资源。

---

### 方法四：避免 `shared_ptr` 循环引用

错误：

```cpp
shared_ptr<Node> next;
shared_ptr<Node> prev;
```

如果形成：

```text
A → B → A
```

可能产生循环引用。

可以使用：

```cpp
weak_ptr<Node> prev;
```

打破强引用环。

---

# 8.7 一个非常重要的现代 C++ 思想

学习到这里，你应该逐渐改变一个习惯：

以前可能觉得：

```cpp
new
delete
```

是 C++ 编程的基本操作。

实际上现代 C++ 更推荐：

```text
能不用裸 new/delete
就尽量不用
```

例如：

```cpp
int* p = new int(10);
delete p;
```

可以改成：

```cpp
auto p = make_unique<int>(10);
```

而：

```cpp
shared_ptr<int> p(new int(10));
```

更推荐：

```cpp
auto p = make_shared<int>(10);
```

因为这样资源的生命周期更加明确，也更不容易出现异常路径、提前 `return` 等导致的资源泄漏。

---

# 8.8 但是注意：智能指针不是万能的

这个一定要记住。

例如：

```cpp
shared_ptr<Node> p1 = make_shared<Node>();
shared_ptr<Node> p2 = make_shared<Node>();

p1->next = p2;
p2->prev = p1;
```

依然可能泄漏。

所以：

> **“用了智能指针” ≠ “绝对不会内存泄漏”。**

真正应该记住的是：

```text
RAII
 ↓
正确设计资源所有权
 ↓
选择合适的智能指针
 ↓
避免循环引用
 ↓
减少内存泄漏
```

---

# 9. 把整个智能指针章节串起来

到这里，你这章的内容实际上已经形成了一条非常完整的知识链：

```text
手动管理资源
new / delete
      ↓
容易忘记释放
      ↓
内存泄漏
      ↓
异常情况下更加危险
      ↓
RAII
      ↓
利用对象生命周期自动管理资源
      ↓
智能指针
      ↓
┌──────────────┬──────────────┐
│              │              │
unique_ptr   shared_ptr     weak_ptr
│              │              │
独占           共享           观察
│              │              │
移动           引用计数       不增加强引用
               │
               ↓
           循环引用问题
               ↓
           weak_ptr解决
```

再结合你刚刚学的**异常**：

```text
异常发生
   ↓
栈展开
   ↓
局部对象析构
   ↓
RAII
   ↓
智能指针析构
   ↓
资源自动释放
```

所以你可以把这一章最核心的思想浓缩成一句话：

> **现代 C++ 的资源管理，本质上是利用 RAII，把资源的生命周期绑定到对象生命周期，再通过 `unique_ptr`、`shared_ptr`、`weak_ptr` 表达不同的资源所有权关系，从而减少手动管理资源导致的内存泄漏。**

## 总结

你这章现在需要真正掌握的不是每个 API，而是这几个**核心关系**：

| 知识点          | 你需要理解什么                          |
| ------------ | -------------------------------- |
| RAII         | 对象析构时自动释放资源                      |
| `unique_ptr` | 独占所有权，不能拷贝，只能移动                  |
| `shared_ptr` | 共享所有权，通过引用计数管理                   |
| 控制块          | 保存 `shared_ptr` 的引用计数等管理信息       |
| `weak_ptr`   | 不拥有资源，不增加强引用                     |
| 循环引用         | `shared_ptr` 相互持有导致引用计数无法归零      |
| 内存泄漏         | 资源没有被正确释放                        |
| 异常安全         | RAII 能保证异常路径上的资源释放               |
| 线程安全         | `shared_ptr` 的引用计数安全 ≠ 所管理对象线程安全 |
| Boost        | C++11 标准智能指针的重要前身/来源之一           |

**这一章学完以后，你实际上已经把 C++ 中“资源管理”最核心的一套思想串起来了：**

> **资源 → RAII → 智能指针 → 所有权 → 引用计数 → 循环引用 → 内存泄漏。**
