## 一、本讲核心主线

这一讲围绕 **“类对象在创建、销毁、拷贝和运算时到底发生了什么”** 展开，核心主线如下：

1. **默认成员函数**：类在你不写时，编译器会默认生成一批函数，但这些函数是否够用要具体分析。
2. **构造函数 / 析构函数**：对象创建时做初始化，对象销毁时做资源清理，核心是生命周期管理。
3. **拷贝构造**：新对象用已有对象初始化时触发，重点是“什么时候会自动调用、默认行为够不够用”。
4. **赋值运算符重载**：两个已经存在的对象之间赋值时触发，和拷贝构造一定要区分开。
5. **运算符重载**：让类对象支持 `==`、`++`、`+=`、`<<` 等操作，但要遵守规则，不能乱改语言语义。
6. **日期类实现**：把前面这些零散规则落到完整类设计中，形成“可用、可维护”的类。

这节仍然属于**知识型 + 实战型混合课件**：前半段偏规则，后半段偏类实现与设计。二刷时应重点抓：

- 默认生成行为的边界
- 资源类为什么必须自己写深拷贝
- 拷贝构造和赋值重载的触发时机区别
- 运算符重载的语法规则与常见设计方式

## 二、为什么学 / 这一讲解决什么问题

学完“类和对象(上)”后，很多人只能写出表面上的类，但遇到下面这些问题就会出错：

- 为什么有的类不写构造函数也能用，有的类就不行？
- 为什么 `Stack st2 = st1;` 可能导致程序崩溃？
- 为什么一个类只写析构不够，还常常要配套写拷贝构造和赋值重载？
- 为什么 `Date d4 = d1;` 是拷贝构造，而 `d1 = d3;` 是赋值重载？
- 为什么 `d1 == d2` 最终会变成函数调用？
- 为什么有些运算符能重载，有些不能？为什么 `<<` 常常写成全局函数？

这一讲解决的本质问题是：

> **让你真正理解类对象的生命周期、拷贝语义和运算语义，而不是只会“把代码写出来”。**

这些知识会直接影响后面：

- `string` / `vector` 等容器的理解
- 模拟实现类
- 资源管理类设计
- 面试里最常见的 C++ 基础问题

## 三、核心内容展开

### 3.1 类的默认成员函数

#### 1）什么是默认成员函数

当用户没有显式实现时，编译器会自动生成一批成员函数，这些函数叫默认成员函数。

课件当前阶段重点先抓住这 **6 个**：

- 构造函数
- 析构函数
- 拷贝构造函数
- 赋值运算符重载
- 普通对象取地址
- `const` 对象取地址

> 后面 C++11 / C++14 还会扩展，但这节先把经典 6 个吃透。

#### 2）复习这部分的正确角度

课件特别强调要从两个角度看默认成员函数：

1. **如果我不写，编译器默认生成的行为是什么？**
2. **默认行为是否满足我的类需求？不满足时我要不要自己写？**

这比死背“有哪几个默认成员函数”更重要。

#### 3）核心判断标准

默认生成 ≠ 一定能用。判断要看：

- 类成员是不是纯内置类型
- 是否涉及动态资源（堆空间、文件句柄、锁、网络连接等）
- 成员里是否包含自定义类型对象
- 是否需要自定义语义

---

### 3.2 构造函数

#### 1）构造函数的本质

构造函数是特殊成员函数，它的核心任务不是“开空间”，而是：

> **在对象创建时，完成对象的初始化。**

对象空间本身：

- 局部对象通常在栈上开空间
- 动态对象通常在堆上开空间

这些不是构造函数本身负责的重点。

#### 2）构造函数的特点

必须记住的规则：

1. 函数名与类名相同。
2. 没有返回值，也不用写 `void`。
3. 对象实例化时，系统自动调用对应构造函数。
4. 构造函数可以重载。
5. 如果类中没有显式定义构造函数，编译器会生成默认构造函数。

#### 3）默认构造函数到底指什么

课件这里特别容易出选择题，必须区分清楚：

- **无参构造函数**
- **全缺省构造函数**
- **编译器默认生成的构造函数**

这三者在很多场景下都能“无参调用”，所以都可以叫**默认构造**。

但要注意：

- 它们**一次只能存在一个可作为默认构造的入口**，否则会调用歧义；
- 无参构造和全缺省构造虽然构成重载，但同时提供时常会导致无参调用冲突。

一句话记忆：

> **凡是“不传参就能调用”的构造，本质上都属于默认构造。**

#### 4）默认生成的构造函数行为

如果你不写构造函数：

- 对**内置类型成员**，编译器默认生成的构造函数通常不负责给你初始化到想要的值，结果往往不确定；
- 对**自定义类型成员**，会调用该成员自己的默认构造函数完成初始化。

这也是为什么：

- `Date` 这种只有 `int` 成员的类，不手写构造时成员值通常不可靠；
- `MyQueue` 里如果成员是 `Stack pushst; Stack popst;`，编译器默认生成的构造会去调用这两个 `Stack` 对象的构造函数。

#### 5）本节复习结论

- 构造函数负责初始化，不是负责“开空间”。
- 默认构造不只指编译器生成那个，也包括无参构造和全缺省构造。
- 内置类型成员靠默认生成构造往往不够，自定义类型成员会继续调用其构造。

### 3.3 析构函数

#### 1）析构函数的本质

析构函数和构造函数相反，它的核心任务不是“销毁对象本身”，而是：

> **在对象生命周期结束时，清理对象管理的资源。**

例如：

- `Date` 这类只含普通成员的类，通常没有额外资源需要释放；
- `Stack` 若内部申请了堆空间 `_a`，就必须在析构中 `free` / `delete`。

#### 2）析构函数的特点

1. 函数名是在类名前加 `~`。
2. 无参数、无返回值。
3. 一个类只能有一个析构函数，不能重载。
4. 对象生命周期结束时，系统自动调用析构函数。
5. 若未显式定义，系统会生成默认析构函数。

#### 3）默认生成的析构函数行为

课件里要重点理解：

- 对**内置类型成员**，默认析构基本没什么可做；
- 对**自定义类型成员对象**，会自动调用它们的析构函数。

所以像：

```cpp
class MyQueue
{
private:
    Stack pushst;
    Stack popst;
};
```

即使 `MyQueue` 自己不写析构，成员对象 `pushst`、`popst` 的析构也会自动调用。

#### 4）什么时候必须自己写析构

核心标准：

> **类自己是否管理了需要释放的资源。**

- 没资源：可以不写，例如简单 `Date`
- 有堆资源：通常必须写，例如 `Stack`

#### 5）局部对象析构顺序

课件强调：

> **同一局部域中的多个对象，后定义的先析构。**

这和栈的“后进先出”一致，是结果题高频点。

#### 6）本节复习结论

- 析构函数重点是“资源清理”，不是“对象没了”。
- 资源类一定要关注析构，否则会泄漏。
- 有成员对象时，即使你自己不写，成员对象的析构仍会走。

---

### 3.4 构造 + 析构带来的类设计提升

课件用 `Stack` 版本的括号匹配题 `isValid` 对比了 C 与 C++ 写法，说明：

- C 风格下，常常需要手动 `Init` / `Destroy`
- C++ 风格下，把初始化放到构造函数，把清理放到析构函数

这样做的好处：

1. **不容易忘记初始化和销毁**
2. **代码更短，接口更自然**
3. **对象一创建就处于可用状态**
4. **作用域结束自动回收资源**

这其实就是面向对象封装的一大价值：

> **把资源管理交给对象生命周期自动处理。**

### 3.5 拷贝构造函数

#### 1）什么是拷贝构造

如果一个构造函数的第一个参数是**自身类类型对象的引用**，且其余参数都有默认值，那么这个函数就是拷贝构造函数。

它本质上是一个特殊构造函数，作用是：

> **用一个已经存在的同类对象，初始化一个新对象。**

#### 2）拷贝构造的特点

1. 它本质上仍然是构造函数的重载。
2. 第一个参数必须是**同类对象引用**，不能传值。
3. 传值会导致无限递归调用，逻辑上走不通。
4. C++ 规定：**自定义类型对象发生拷贝行为时，必须调用拷贝构造。**

#### 3）为什么参数必须是引用

如果写成：

```cpp
Date(Date d)
```

那么调用这个函数本身就需要先把参数 `d` 拷贝出来，而“拷贝出参数 d”又要调用拷贝构造，于是无限套娃。

因此必须写成：

```cpp
Date(const Date& d)
```

一般还会加 `const`，因为：

- 不需要修改源对象
- 可接收 const 对象
- 更符合语义

#### 4）哪些场景会触发拷贝构造

必须重点掌握：

- `Date d2(d1);`
- `Date d3 = d1;`
- **传值传参**
- **传值返回**（底层可能伴随优化，但语义上属于拷贝相关场景）

注意：

> `Date d3 = d1;` 看起来像赋值，其实是**定义并初始化新对象**，所以是拷贝构造。

#### 5）默认生成的拷贝构造行为

如果不显式定义，编译器会生成默认拷贝构造：

- 对**内置类型成员**，做值拷贝 / 浅拷贝；
- 对**自定义类型成员对象**，调用该成员的拷贝构造。

#### 6）什么时候默认拷贝构造不够用

关键点在于是否涉及资源。

例如：

- `Date` 只含普通整型成员，默认拷贝构造通常够用；
- `Stack` 中 `_a` 指向堆空间，若只做浅拷贝，就会让两个对象指向同一块资源，析构时二次释放，程序崩溃。

所以对资源类，必须自己实现**深拷贝**。

#### 7）自定义成员类带来的连锁拷贝

如果一个类包含另一个自定义类型成员，例如 `MyQueue` 内含两个 `Stack`，那么：

- `MyQueue` 默认生成的拷贝构造会调用 `Stack` 的拷贝构造；
- 只要 `Stack` 自己把深拷贝处理好，`MyQueue` 往往就不用再单独写。

#### 8）引用返回的风险

课件特别强调：

- 传引用返回不会产生拷贝，但返回的是对象别名；
- 如果返回的是函数内局部对象的引用，那么函数结束后局部对象已经销毁，引用就悬空，变成野引用。

这是高频坑点。

#### 9）本节复习结论

- 拷贝构造服务于“新对象由旧对象初始化”。
- 参数必须是 `const T&` 这种引用形式。
- 资源类默认浅拷贝往往不够，必须自己写深拷贝。
- `T a = b;` 在定义场景下是拷贝构造，不是赋值重载。

### 3.6 运算符重载

#### 1）运算符重载的意义

当运算符作用于类类型对象时，C++ 允许你通过运算符重载重新定义其行为。

本质上：

> **运算符重载就是一个名字特殊的函数。**

例如：

```cpp
d1 == d2
```

最终会转成类似：

```cpp
operator==(d1, d2)
```

或成员函数形式：

```cpp
d1.operator==(d2)
```

#### 2）运算符重载的基本规则

必须记住：

1. 运算符重载函数名字是 `operator` + 运算符。
2. 参数个数要和该运算符操作数个数匹配。
3. 如果重载为成员函数，则左操作数默认作为 `this`，参数少一个。
4. 运算符重载后，其优先级和结合性不变。

#### 3）哪些运算符不能重载

课件特别标出了常见不可重载项：

- `.*`
- `::`
- `sizeof`
- `?:`
- `.`

这是常考选择题。

#### 4）至少有一个操作数必须是类类型

不能通过运算符重载改变纯内置类型的语义，例如不能写：

```cpp
int operator+(int x, int y)
```

去篡改内置 `int` 的加法含义。

#### 5）前置++与后置++的区分

- 前置 `++d1` ：一般重载为 `operator++()`
- 后置 `d1++` ：一般重载为 `operator++(int)`

这里多出来的 `int` 只是为了和前置区分，不代表真的要传一个有意义的整数。

#### 6）`<<` / `>>` 为什么常写成全局函数

如果把 `<<` 重载成成员函数，那么左操作数会默认是 `this`，就不符合：

```cpp
cout << d;
```

这种使用方式，因为左边是 `cout`，不是 `Date` 对象。

所以：

- `<<`、`>>` 常写成**全局函数**；
- 若需要访问私有成员，通常再配合**友元**。

#### 7）成员函数指针的小点

课件里还带到一个知识点：成员函数指针取地址写法需要 `&类名::函数名`，调用时用 `.*` 等语法，这属于拓展理解，考试里偶尔混合出现。

### 3.7 赋值运算符重载

#### 1）赋值重载和拷贝构造的区别

这是本讲最重要的区分点之一：

- **拷贝构造**：一个新对象，用另一个对象来初始化
- **赋值重载**：两个对象都已经存在，把右边对象内容赋给左边对象

对比：

```cpp
Date d4 = d1; // 拷贝构造
Date d3(2024, 7, 6);
d1 = d3;      // 赋值运算符重载
```

#### 2）赋值运算符重载的典型写法

建议形式：

```cpp
Date& operator=(const Date& d)
```

为什么这么写：

1. 参数写 `const T&`，避免额外拷贝。
2. 返回 `T&`，提高效率并支持连续赋值。
3. 语义上返回左操作数本身，也就是 `*this`。

#### 3）默认生成的赋值重载行为

如果不显式写：

- 对内置类型成员做值拷贝 / 浅拷贝；
- 对自定义类型成员调用其赋值运算符重载。

对于 `Date` 这种纯值类，通常够用；
对于 `Stack` 这种资源类，浅拷贝仍然不够，需要自己写深拷贝版本。

#### 4）为什么常常“析构 + 拷贝构造 + 赋值重载”一起考虑

因为只要类自己管理资源：

- 析构要负责释放资源
- 拷贝构造要负责创建独立副本
- 赋值重载要负责已有对象间安全复制

否则极容易出现：

- 内存泄漏
- 重复释放
- 野指针
- 自赋值问题

这就是经典的“三件套”思想。

#### 5）自赋值检查

虽然课件示例里主要点到：

```cpp
if (this != &d)
```

本质就是防止：

```cpp
d1 = d1;
```

导致不必要甚至危险的操作。

#### 6）本节复习结论

- `=` 不一定是默认那个语义，对类对象会转成赋值重载调用。
- 赋值重载只处理“两个已存在对象之间”的赋值。
- 返回 `*this` 是标准写法。
- 资源类一定要认真处理深拷贝与自赋值。

### 3.8 日期类实现：把零散知识串起来

课件最后用 `Date` 类把前面的规则串成一个相对完整的小类设计，重点应关注：

#### 1）接口组织

例如：

- 构造函数
- `Print()`
- 判断日期合法性
- 获取某年某月天数
- 比较运算符：`< <= > >= == !=`
- 加减天数：`+= -= + -`
- 日期差值：`d1 - d2`
- 前置 / 后置 `++ --`
- 输入输出：`<< >>`

这说明一个实际类往往不是只写一个构造，而是要围绕**对象语义**把整套操作组织起来。

#### 2）`GetMonthDay` 里的静态数组思路

课件示例里用：

- `static int monthDayArray[13]`
- 特判闰年 2 月

这属于非常经典的日期类辅助函数写法。

#### 3）友元与输入输出重载的结合

`ostream<<`、`istream>>` 常常配合友元声明使用，因为：

- 形式上更符合使用习惯
- 又可能需要访问私有成员

#### 4）这部分真正要学会什么

不是把 `Date` 所有代码背下来，而是学会：

- 如何把一个类设计成“能比较、能运算、能输入输出”的自然对象
- 如何选成员函数还是全局函数
- 如何让接口风格统一
- 如何让对象行为接近日常数学 / 日期直觉

## 四、易错点汇总

### 1. 误以为默认成员函数“有生成就一定能用”

错误。默认生成是否够用，取决于类是否涉及资源、是否需要自定义语义。

### 2. 把默认构造只理解成“编译器生成的无参构造”

不完整。无参构造、全缺省构造、本质上都可能作为默认构造入口。

### 3. 以为析构函数负责“销毁对象本身”

更准确的说法是：析构函数主要负责清理对象管理的资源。

### 4. 忘记局部对象析构顺序是“后定义先析构”

结果题常考。

### 5. 把 `Date d3 = d1;` 误判成赋值重载

这是**拷贝构造**，因为 `d3` 是新定义对象。

### 6. 拷贝构造参数写成传值

会导致逻辑递归错误，必须写成引用，一般是 `const T&`。

### 7. 对资源类使用默认浅拷贝

像 `Stack` 这种内部持有堆内存的类，浅拷贝会导致双重释放。

### 8. 返回局部对象引用

会产生野引用，是严重错误。

### 9. 误以为所有运算符都能重载

`.*`、`::`、`sizeof`、`?:`、`.` 等不能重载。

### 10. 误以为运算符重载能改变内置类型语义

不行，至少有一个操作数必须是类类型。

### 11. 前置++和后置++写法混淆

后置版通过额外 `int` 参数与前置区分。

### 12. 误把 `<<` / `>>` 写成不合适的成员函数

输出流对象在左边，所以这类运算符通常更适合全局函数配合友元。

### 13. 拷贝构造与赋值重载的触发时机混淆

这是整讲最该反复练的点。

## 六、一页纸记忆版

### 1）一句话串全讲

> **默认成员函数解决“你不写时编译器会做什么”，构造 / 析构管理生命周期，拷贝构造和赋值重载管理复制语义，运算符重载负责让类对象像内置类型一样自然使用。**

### 2）高频结论表

| 主题 | 最关键结论 |
|---|---|
| 默认成员函数 | 编译器会生成，但未必满足资源类需求 |
| 构造函数 | 负责初始化，可重载，无返回值 |
| 默认构造 | 无参构造、全缺省构造、编译器生成构造都可能承担该角色 |
| 析构函数 | 负责资源清理，一个类只能有一个 |
| 析构顺序 | 局部对象后定义先析构 |
| 拷贝构造 | 用已有对象初始化新对象 |
| 拷贝构造参数 | 必须是 `const T&` 形式，不能传值 |
| 默认拷贝 | 对资源类常常只是浅拷贝，不够用 |
| 运算符重载 | 本质是特殊函数，优先级和结合性不变 |
| 不可重载 | `.*`、`::`、`sizeof`、`?:`、`.` |
| 前置++ | `operator++()` |
| 后置++ | `operator++(int)` |
| 赋值重载 | 两个已存在对象之间赋值，典型返回 `*this` |
| `Date d2 = d1` | 是拷贝构造，不是赋值重载 |
| `d1 = d2` | 是赋值重载 |
| `<< >>` | 常重载为全局函数，必要时配合友元 |

### 3）结果题 / 设计题通用判断顺序

遇到类设计题或程序结果题，建议按下面顺序看：

1. 这个类是否有资源需要管理？
2. 默认生成的构造 / 析构 / 拷贝 / 赋值是否够用？
3. 当前语句是在“定义新对象”还是“给已有对象赋值”？
4. 是否发生了拷贝构造？
5. 是否存在浅拷贝导致共享同一资源？
6. 当前运算符适合写成员函数还是全局函数？
7. 是否涉及返回局部对象引用等生命周期错误？

## 七、二刷重点建议

### 第一遍复习：先把四组基础概念卡死

优先背熟：

- 默认成员函数有哪些、怎么看待它们
- 构造函数 vs 析构函数的职责
- 拷贝构造 vs 赋值重载的触发区别
- 浅拷贝 vs 深拷贝的本质差别

### 第二遍复习：专项练“判断当前调用的是谁”

建议专门练下面这些语句：

- `Date d2(d1);`
- `Date d3 = d1;`
- `d1 = d3;`
- `Func1(d1);`
- `Date ret = Func2();`
- `++d1;`
- `d1++;`
- `cout << d1;`

目标不是背答案，而是看到语句就能立刻判断：

- 调的是构造？
- 拷贝构造？
- 赋值重载？
- 普通成员函数？
- 全局重载函数？

### 第三遍复习：把资源类和纯值类区分开

这是本讲真正容易拉开差距的地方：

- `Date`：通常是**纯值类**，默认行为很多时候够用
- `Stack`：是**资源类**，默认浅拷贝不够，必须自己接管
- `MyQueue`：内部含资源类成员，很多默认行为会“递归调用成员的实现”

### 第四遍复习：用日期类理解“完整类设计”

你后面再学 `string`、`vector`、`list`、`map` 时，会越来越感受到：

- 类不是只写几个函数
- 真正的类设计是让对象行为自然、接口统一、语义清晰

而这节的 `Date` 类，就是第一次比较完整地练这个思路。

## 附：本讲最值得反复看的 12 句话

1. 默认成员函数是“编译器帮你补”，不是“永远适合你”。
2. 构造函数负责初始化，不负责决定对象在哪开空间。
3. 默认构造不只指编译器生成那个，也包括无参和全缺省构造。
4. 析构函数最重要的职责是释放资源。
5. 资源类不写析构，很容易泄漏。
6. 拷贝构造服务于“新对象由旧对象初始化”。
7. 拷贝构造参数必须是引用，通常写成 `const T&`。
8. 对资源类，默认浅拷贝通常不够，必须自己实现深拷贝。
9. `Date d2 = d1` 是拷贝构造，不是赋值重载。
10. `d1 = d2` 才是赋值运算符重载。
11. 运算符重载不会改变优先级和结合性，也不能随便改内置类型语义。
12. `<<` / `>>` 常重载为全局函数，常配合友元使用。
