## 0. 本章一句话总览

**C++ 内存管理的核心是：知道对象放在哪里、用什么方式申请释放、申请释放时有没有调用构造和析构。**

本章最容易考的不是“背 API”，而是下面三类判断：

1. **变量在哪个内存区域？** 栈、堆、数据段、代码段/常量区。
2. **`malloc/free` 和 `new/delete` 有什么区别？** 尤其是自定义类型是否调用构造/析构。
3. **`new/delete` 底层做了什么？** `new` 调 `operator new` 申请空间，再构造；`delete` 先析构，再调 `operator delete` 释放空间。

## 2. 内存分布：变量到底在哪里？

### 2.1 先记住四大区域

| 区域 | 放什么 | 典型例子 | 增长方向 / 特点 |
|---|---|---|---|
| 栈 | 非静态局部变量、函数参数、返回值 | `int localVar`、`int* ptr1` 这个指针变量本身 | 通常向低地址增长，自动创建和销毁 |
| 堆 | 程序运行时动态申请的空间 | `malloc`、`calloc`、`realloc`、`new` 得到的空间 | 通常向高地址增长，需要手动释放 |
| 数据段 / 静态区 | 全局变量、静态变量 | `globalVar`、`staticGlobalVar`、`staticVar` | 生命周期贯穿程序运行期 |
| 代码段 / 常量区 | 可执行代码、只读常量 | 字符串字面量 `"abcd"` | 通常只读 |

> 记忆口诀：**局部上栈，动态上堆，全局静态进数据，字面常量进代码。**

---

### 2.2 课件例题逐项判断

源代码：

```cpp
int globalVar = 1;
static int staticGlobalVar = 1;

void Test()
{
    static int staticVar = 1;
    int localVar = 1;
    int num1[10] = { 1, 2, 3, 4 };
    char char2[] = "abcd";
    const char* pChar3 = "abcd";
    int* ptr1 = (int*)malloc(sizeof(int) * 4);
    int* ptr2 = (int*)calloc(4, sizeof(int));
    int* ptr3 = (int*)realloc(ptr2, sizeof(int) * 4);
    free(ptr1);
    free(ptr3);
}
```

| 表达式 | 所在区域 | 原因 |
|---|---|---|
| `globalVar` | 数据段 / 静态区 | 全局变量 |
| `staticGlobalVar` | 数据段 / 静态区 | 静态全局变量 |
| `staticVar` | 数据段 / 静态区 | 静态局部变量，虽然写在函数里，但生命周期不是函数调用期间 |
| `localVar` | 栈 | 普通局部变量 |
| `num1` | 栈 | 局部数组，数组整体在栈上 |
| `char2` | 栈 | 局部字符数组本身在栈上 |
| `*char2` | 栈 | `char2` 数组中的元素也在栈上，比如 `char2[0]` |
| `pChar3` | 栈 | `pChar3` 是局部指针变量，指针变量本身在栈上 |
| `*pChar3` | 代码段 / 常量区 | 指向字符串字面量 `"abcd"` 的内容 |
| `ptr1` | 栈 | `ptr1` 是局部指针变量本身 |
| `*ptr1` | 堆 | `ptr1` 指向 `malloc` 申请的动态空间 |
| `ptr2` | 栈 | 局部指针变量本身 |
| `*ptr2` | 堆 | `calloc` 申请的动态空间；注意 `realloc` 后原 `ptr2` 可能失效 |
| `ptr3` | 栈 | 局部指针变量本身 |
| `*ptr3` | 堆 | `realloc` 后得到的动态空间 |

### 2.3 最容易混的点

#### 易混点 1：指针变量本身和它指向的空间不是一回事

```cpp
int* p = (int*)malloc(sizeof(int));
```

- `p`：局部变量，放在**栈**。
- `*p`：动态申请的 `int` 空间，放在**堆**。

可以把指针想成“快递单号”：

- 快递单号纸条放在桌上：这是指针变量本身。
- 快递实际存放在仓库：这是指向的动态空间。

#### 易混点 2：字符数组和字符串字面量不同

```cpp
char arr[] = "abcd";
const char* p = "abcd";
```

| 写法 | 内容在哪里 | 能否改内容 |
|---|---|---|
| `char arr[] = "abcd";` | 字符数组在栈上，字符串内容被拷贝进数组 | 可以改，如 `arr[0] = 'x'` |
| `const char* p = "abcd";` | `p` 在栈上，`"abcd"` 在代码段/常量区 | 不能通过 `p` 改字面量 |

## 3. C 语言动态内存管理

### 3.1 四个函数的定位

| 函数 | 作用 | 是否初始化 | 典型用法 |
|---|---|---|---|
| `malloc` | 申请一块指定字节数的空间 | 不初始化，内容不确定 | `malloc(sizeof(int) * n)` |
| `calloc` | 申请若干个元素的空间 | 会初始化为 0 | `calloc(n, sizeof(int))` |
| `realloc` | 调整已有动态空间大小 | 新增部分通常不保证初始化 | `realloc(p, newSize)` |
| `free` | 释放动态空间 | 不适用 | `free(p)` |

### 3.2 `malloc/calloc/realloc` 区别

```cpp
int* p1 = (int*)malloc(sizeof(int) * 4);
int* p2 = (int*)calloc(4, sizeof(int));
int* p3 = (int*)realloc(p2, sizeof(int) * 10);
```

| 对比点 | `malloc` | `calloc` | `realloc` |
|---|---|---|---|
| 主要功能 | 申请空间 | 申请空间并清零 | 调整已有空间大小 |
| 参数 | 总字节数 | 元素个数 + 单个元素大小 | 原指针 + 新总字节数 |
| 初始化 | 不初始化 | 初始化为 0 | 原内容尽量保留，新空间不一定初始化 |
| 返回值 | `void*` | `void*` | `void*` |

### 3.3 `realloc` 后还需要 `free(p2)` 吗？

课件代码：

```cpp
int* p2 = (int*)calloc(4, sizeof(int));
int* p3 = (int*)realloc(p2, sizeof(int) * 10);

// 这里需要 free(p2) 吗？
free(p3);
```

**不应该再 `free(p2)`。**

原因：

1. `realloc(p2, newSize)` 成功后，返回的新指针是 `p3`。
2. 成功后原来的 `p2` 可能已经被释放，也可能和 `p3` 地址相同。
3. 此时继续 `free(p2)` 可能造成重复释放或释放无效地址。
4. 正确做法是释放 `p3`。

更稳妥的写法：

```cpp
int* p = (int*)calloc(4, sizeof(int));
int* tmp = (int*)realloc(p, sizeof(int) * 10);

if (tmp != nullptr)
{
    p = tmp;
}
else
{
    // realloc 失败时，原 p 仍然有效，需要后续 free(p)
}

free(p);
```

## 4. C++ 动态内存管理：new/delete

### 4.1 基本使用

```cpp
void Test()
{
    // 动态申请一个 int 类型的空间，未显式初始化
    int* ptr4 = new int;

    // 动态申请一个 int 类型的空间，并初始化为 10
    int* ptr5 = new int(10);

    // 动态申请 3 个 int 类型的连续空间
    int* ptr6 = new int[3];

    delete ptr4;
    delete ptr5;
    delete[] ptr6;
}
```

### 4.2 匹配规则：怎么申请，就怎么释放

| 申请方式 | 释放方式 | 是否正确 |
|---|---|---|
| `new int` | `delete p` | 正确 |
| `new int[10]` | `delete[] p` | 正确 |
| `new int` | `delete[] p` | 错误 |
| `new int[10]` | `delete p` | 错误 |
| `malloc` / `calloc` / `realloc` | `free` | 正确 |
| `new` | `free` | 错误 |
| `malloc` | `delete` | 错误 |

> 记忆口诀：**单个 new 配 delete，数组 new[] 配 delete[]，C 的 malloc 配 free，别乱配。**

## 5. 自定义类型：new/delete 和 malloc/free 的本质差异

### 5.1 示例类

```cpp
class A
{
public:
    A(int a = 0)
        : _a(a)
    {
        cout << "A():" << this << endl;
    }

    ~A()
    {
        cout << "~A():" << this << endl;
    }

private:
    int _a;
};
```

### 5.2 对比代码

```cpp
A* p1 = (A*)malloc(sizeof(A));
A* p2 = new A(1);

free(p1);
delete p2;
```

| 写法 | 是否申请空间 | 是否调用构造函数 | 是否调用析构函数 |
|---|---:|---:|---:|
| `malloc(sizeof(A))` | 是 | 否 | 否 |
| `free(p1)` | 释放空间 | 否 | 否 |
| `new A(1)` | 是 | 是 | 否 |
| `delete p2` | 释放空间 | 否 | 是，且在释放空间前调用 |

**关键结论：申请自定义类型对象时，`new/delete` 不只是申请和释放空间，还负责对象生命周期。**

如果类中有资源，例如堆内存、文件句柄、网络连接，构造和析构就非常重要。此时用 `malloc/free` 很容易出错。

## 6. `operator new` 与 `operator delete`

### 6.1 它们和 `new/delete` 不是同一个层级

| 名称 | 身份 | 作用 |
|---|---|---|
| `new` | 操作符 / 表达式 | 申请空间 + 调用构造函数 |
| `delete` | 操作符 / 表达式 | 调用析构函数 + 释放空间 |
| `operator new` | 全局函数，可重载 | 只负责申请原始空间 |
| `operator delete` | 全局函数，可重载 | 只负责释放原始空间 |
| `malloc` | C 库函数 | 申请原始空间 |
| `free` | C 库函数 | 释放原始空间 |

### 6.2 `new` 的底层流程

```text
new A(1)
  ├── 1. 调用 operator new(sizeof(A)) 申请原始空间
  └── 2. 在这块空间上调用 A 的构造函数
```

### 6.3 `delete` 的底层流程

```text
delete p
  ├── 1. 对 p 指向的对象调用析构函数
  └── 2. 调用 operator delete(p) 释放原始空间
```

### 6.4 `operator new` 和 `malloc` 的关系

课件强调：

- `operator new` 实际通常通过 `malloc` 申请空间。
- 如果 `malloc` 申请成功，直接返回。
- 如果申请失败，会尝试执行用户设置的空间不足处理措施。
- 如果没有处理措施，`operator new` 会抛出 `bad_alloc` 异常。

因此：

```text
new 失败：通常抛异常
malloc 失败：返回 NULL / nullptr
```

## 7. new/delete 的实现原理

### 7.1 内置类型

对于内置类型：

```cpp
int* p1 = (int*)malloc(sizeof(int));
int* p2 = new int;
```

二者主要都是从堆上申请一块 `int` 大小的空间。区别在于：

1. `new int` 写法更符合类型语义，不需要手动写 `sizeof(int)`。
2. `new int(10)` 可以初始化。
3. `new` 失败通常抛异常，`malloc` 失败返回 `NULL`。
4. `new/delete` 是 C++ 风格，`malloc/free` 是 C 风格。

### 7.2 自定义类型单对象

```cpp
A* p = new A(10);
delete p;
```

流程：

```text
new A(10)
  ├── operator new：申请 sizeof(A) 大小的空间
  └── A::A(10)：调用构造函数

delete p
  ├── A::~A()：调用析构函数
  └── operator delete：释放空间
```

### 7.3 自定义类型数组

```cpp
A* p = new A[10];
delete[] p;
```

流程：

```text
new A[10]
  ├── operator new[]：申请数组空间
  └── 调用 10 次 A 的构造函数

delete[] p
  ├── 调用 10 次 A 的析构函数
  └── operator delete[]：释放数组空间
```

> 注意：`new[]` 和 `delete[]` 需要匹配，尤其是自定义类型数组。否则可能析构次数不对，造成资源泄漏或未定义行为。

## 8. placement new：定位 new

### 8.1 它解决什么问题？

普通 `new` 做两件事：

1. 申请空间。
2. 调用构造函数。

而 **placement new 只在已有空间上调用构造函数**。

也就是说：

```text
已有一块原始内存，但它还不是对象
↓
placement new 在这块内存上调用构造函数
↓
这块内存才变成真正的对象
```

### 8.2 基本格式

```cpp
new (place_address) type;
new (place_address) type(initializer_list);
```

其中：

- `place_address` 必须是一个指针。
- `initializer_list` 是构造函数参数列表。

### 8.3 课件示例

```cpp
A* p1 = (A*)malloc(sizeof(A));

// p1 指向的是一段和 A 对象一样大的原始空间，
// 但此时还不能算真正的 A 对象，因为构造函数没执行。
new(p1) A;

// 手动调用析构函数
p1->~A();

// 释放原始空间
free(p1);
```

### 8.4 为什么需要手动析构？

因为这块空间不是通过普通 `new A` 申请出来的，所以不能直接依赖 `delete` 完成完整流程。使用 placement new 后，通常需要：

```text
malloc / 内存池申请原始空间
↓
placement new 调构造
↓
手动调用析构函数
↓
free / 内存池归还空间
```

### 8.5 常见使用场景

课件提到：placement new 常和**内存池**配合使用。

内存池可以提前申请大块原始内存，提高频繁申请释放小对象时的效率。但原始内存没有构造对象，所以自定义类型需要 placement new 显式调用构造函数。

## 9. malloc/free 和 new/delete 总对比

| 对比项 | `malloc/free` | `new/delete` |
|---|---|---|
| 身份 | 函数 | 操作符 |
| 使用语言 | C / C++ 都可用 | C++ |
| 申请大小 | 需要手动计算字节数 | 根据类型自动计算 |
| 返回类型 | `void*`，通常需要强转 | 返回对应类型指针，不需要强转 |
| 初始化 | `malloc` 不初始化，`calloc` 清零 | 可以初始化，如 `new int(10)` |
| 失败处理 | 返回 `NULL` / `nullptr` | 通常抛出 `bad_alloc` 异常 |
| 自定义类型构造 | 不调用构造函数 | 调用构造函数 |
| 自定义类型析构 | 不调用析构函数 | 调用析构函数 |
| 释放方式 | `free(p)` | `delete p` / `delete[] p` |
| 推荐场景 | C 代码、底层原始内存控制 | C++ 对象管理 |

### 面试/考试标准回答版

`malloc/free` 和 `new/delete` 都可以从堆上申请和释放空间，但区别主要有：

1. `malloc/free` 是函数，`new/delete` 是操作符。
2. `malloc` 需要手动计算空间大小，返回 `void*`，使用时通常需要强转；`new` 根据类型自动计算大小，返回对应类型指针。
3. `malloc` 申请空间不会初始化，`new` 可以初始化对象。
4. `malloc` 失败返回 `NULL`，`new` 失败通常抛出 `bad_alloc` 异常。
5. 对自定义类型来说，`malloc/free` 只申请和释放原始空间，不调用构造函数和析构函数；`new/delete` 会调用构造和析构，真正管理对象生命周期。

## 10. 高频易错点清单

### 易错点 1：`delete` 和 `delete[]` 混用

错误：

```cpp
A* p = new A[10];
delete p;       // 错误
```

正确：

```cpp
A* p = new A[10];
delete[] p;
```

原因：数组对象需要析构多个元素，`delete[]` 才知道按数组方式释放。

---

### 易错点 2：`malloc` 出来的自定义类型对象没有构造

错误理解：

```cpp
A* p = (A*)malloc(sizeof(A));
// 以为 p 已经是完整 A 对象
```

正确理解：

- `p` 只是指向一块和 `A` 一样大的原始内存。
- 构造函数没有执行。
- 严格来说，它还没有完成对象初始化。

如果一定要在这块空间上构造对象，要用 placement new：

```cpp
new(p) A(10);
p->~A();
free(p);
```

---

### 易错点 3：`realloc` 成功后继续释放原指针

错误：

```cpp
int* p2 = (int*)calloc(4, sizeof(int));
int* p3 = (int*)realloc(p2, sizeof(int) * 10);
free(p2); // 错误风险
free(p3);
```

正确：

```cpp
int* p2 = (int*)calloc(4, sizeof(int));
int* p3 = (int*)realloc(p2, sizeof(int) * 10);
free(p3);
```

更健壮写法见前文第 3.3 节。

---

### 易错点 4：把指针所在区域和指向区域混为一谈

```cpp
int* p = new int(10);
```

- `p`：局部指针变量，在栈上。
- `*p`：动态申请的 `int` 对象，在堆上。

考试如果问 `p` 在哪里，答栈；问 `*p` 在哪里，答堆。

## 11. 代码跟踪题：构造和析构次数

### 题目 1

```cpp
A* p = new A;
delete p;
```

答案：

- 构造函数调用 1 次。
- 析构函数调用 1 次。
- 申请空间 1 次。
- 释放空间 1 次。

---

### 题目 2

```cpp
A* p = new A[5];
delete[] p;
```

答案：

- 构造函数调用 5 次。
- 析构函数调用 5 次。
- 数组空间申请 1 次。
- 数组空间释放 1 次。

---

### 题目 3

```cpp
A* p = (A*)malloc(sizeof(A));
free(p);
```

答案：

- 构造函数调用 0 次。
- 析构函数调用 0 次。
- 原始空间申请 1 次。
- 原始空间释放 1 次。

---

### 题目 4

```cpp
A* p = (A*)malloc(sizeof(A));
new(p) A(10);
p->~A();
free(p);
```

答案：

- `malloc` 申请原始空间 1 次。
- placement new 调用构造函数 1 次。
- 手动调用析构函数 1 次。
- `free` 释放原始空间 1 次。

## 12. 速记卡片

### 卡片 1：四区判断

```text
普通局部变量：栈
动态申请空间：堆
全局 / 静态变量：数据段 / 静态区
字符串字面量 / 只读常量：代码段 / 常量区
```

### 卡片 2：C 和 C++ 动态内存

```text
C：malloc / calloc / realloc / free
C++：new / delete / new[] / delete[]
```

### 卡片 3：new 的本质

```text
new = operator new 申请空间 + 构造函数
```

### 卡片 4：delete 的本质

```text
delete = 析构函数 + operator delete 释放空间
```

### 卡片 5：自定义类型别乱用 malloc/free

```text
malloc/free 只管空间，不管构造析构；
new/delete 既管空间，也管对象生命周期。
```

### 卡片 6：placement new

```text
placement new：在已有原始内存上调用构造函数。
常见流程：malloc → placement new → 手动析构 → free。
```

### 13.2 简答题

#### 题 1：简述 `malloc/free` 与 `new/delete` 的区别。

<details>
<summary>参考答案</summary>

`malloc/free` 是函数，`new/delete` 是操作符。`malloc` 需要手动计算字节数，返回 `void*`，通常需要强转，失败返回 `NULL`；`new` 根据类型自动计算空间大小，返回对应类型指针，失败通常抛异常。对于自定义类型，`malloc/free` 只申请和释放原始空间，不调用构造函数和析构函数；`new/delete` 会在申请空间后调用构造函数，在释放空间前调用析构函数。

</details>

---

#### 题 2：说明 `new A(10)` 的底层过程。

<details>
<summary>参考答案</summary>

`new A(10)` 首先调用 `operator new(sizeof(A))` 申请一块足够存放 `A` 对象的原始空间；申请成功后，在这块空间上调用 `A` 的构造函数，并传入参数 `10`，最终返回 `A*` 类型的指针。

</details>

---

#### 题 3：说明 `delete p` 的底层过程。

<details>
<summary>参考答案</summary>

`delete p` 首先对 `p` 指向的对象调用析构函数，完成对象内部资源清理；然后调用 `operator delete(p)` 释放对象占用的原始内存空间。

</details>

---

#### 题 4：什么是 placement new？一般什么时候使用？

<details>
<summary>参考答案</summary>

placement new 是在已经分配好的原始内存空间上调用构造函数，用来把这块原始内存初始化成一个对象。它不会重新申请空间。常见使用场景是内存池，因为内存池分配出的只是原始内存，如果要存放自定义类型对象，需要用 placement new 显式调用构造函数。

</details>

## 15. 一页版最终总结

```text
1. 内存分布
   - 栈：普通局部变量、函数参数、返回值
   - 堆：malloc/calloc/realloc/new 申请的动态空间
   - 数据段：全局变量、静态变量
   - 代码段/常量区：代码、只读常量、字符串字面量

2. 指针题核心
   - 指针变量本身可能在栈上
   - 指针指向的空间可能在堆或常量区
   - 问 p 和问 *p 是两回事

3. C 动态内存
   - malloc：申请，不初始化
   - calloc：申请，并清零
   - realloc：调整空间
   - free：释放

4. C++ 动态内存
   - new/delete：单个对象
   - new[]/delete[]：对象数组
   - 必须匹配使用

5. 自定义类型
   - malloc/free：只管空间，不调构造析构
   - new/delete：申请/释放空间 + 调构造析构

6. operator new/delete
   - operator new：申请原始空间，底层通常用 malloc
   - operator delete：释放原始空间，底层通常用 free

7. new/delete 原理
   - new：operator new → 构造函数
   - delete：析构函数 → operator delete
   - new[]：申请数组空间 → N 次构造
   - delete[]：N 次析构 → 释放数组空间

8. placement new
   - 在已有原始内存上调用构造函数
   - 常配合内存池使用
```
