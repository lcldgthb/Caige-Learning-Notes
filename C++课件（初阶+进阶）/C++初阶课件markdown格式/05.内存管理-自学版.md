## 0. 本章学习路线

本章建议按下面顺序学习：

1. **先理解内存分布**：栈、堆、数据段、代码段分别存什么。
2. **复习 C 语言动态内存管理**：`malloc`、`calloc`、`realloc`、`free`。
3. **学习 C++ 的动态内存管理**：`new`、`delete`、`new[]`、`delete[]`。
4. **理解自定义类型的核心差异**：`new/delete` 会调用构造函数和析构函数，`malloc/free` 不会。
5. **理解底层机制**：`new` 底层会调用 `operator new`，`delete` 底层会调用 `operator delete`。
6. **了解定位 new**：在已有内存上显式构造对象，常用于内存池。
7. **总结面试题**：能清楚回答 `malloc/free` 和 `new/delete` 的区别。

# 1. C/C++ 内存分布

## 1.1 先看一段代码

```cpp
int globalVar = 1;
static int staticGlobalVar = 1;

void Test()
{
    static int staticVar = 1;
    int localVar = 1;

    int num1[10] = { 1, 2, 3, 4 };
    char char2[] = "abcd";
    const char* pChar3 = "abcd";

    int* ptr1 = (int*)malloc(sizeof(int) * 4);
    int* ptr2 = (int*)calloc(4, sizeof(int));
    int* ptr3 = (int*)realloc(ptr2, sizeof(int) * 4);

    free(ptr1);
    free(ptr3);
}
```

课件中的选择题：

选项：

- A. 栈
- B. 堆
- C. 数据段，也叫静态区
- D. 代码段，也可理解为常量区的一部分

问题：

| 对象 | 在哪里？ | 解释 |
|---|---|---|
| `globalVar` | 数据段 / 静态区 | 全局变量，程序整个运行期间存在。 |
| `staticGlobalVar` | 数据段 / 静态区 | 静态全局变量，也具有静态存储期。 |
| `staticVar` | 数据段 / 静态区 | 静态局部变量，不在栈上，生命周期到程序结束。 |
| `localVar` | 栈 | 普通局部变量，函数调用时创建，函数结束时销毁。 |
| `num1` | 栈 | 局部数组，数组本身在栈上。 |
| `char2` | 栈 | 局部字符数组，数组整体在栈上。 |
| `*char2` | 栈 | `char2` 数组中的字符元素也在栈上。 |
| `pChar3` | 栈 | `pChar3` 是局部指针变量，指针变量本身在栈上。 |
| `*pChar3` | 代码段 / 常量区 | 指向字符串字面量 `"abcd"`，字符串字面量通常存放在只读常量区。 |
| `ptr1` | 栈 | `ptr1` 是局部指针变量，变量本身在栈上。 |
| `*ptr1` | 堆 | `ptr1` 指向 `malloc` 申请的动态空间。 |

## 1.2 常见内存区域

### 1. 栈

栈又叫堆栈，主要存放：

- 非静态局部变量
- 函数参数
- 函数返回值相关信息
- 函数调用过程中的临时数据

特点：

- 由编译器自动管理。
- 函数调用时创建栈帧，函数结束时释放栈帧。
- 栈空间通常较小。
- 栈一般是向低地址方向增长，也就是课件中说的“向下增长”。

示例：

```cpp
void Func(int x)
{
    int a = 10;
    int arr[10] = {0};
}
```

这里的 `x`、`a`、`arr` 一般都在栈上。

### 2. 堆

堆用于程序运行时的动态内存分配。

在 C 中常用：

```cpp
malloc
calloc
realloc
free
```

在 C++ 中常用：

```cpp
new
delete
new[]
delete[]
```

特点：

- 由程序员手动申请和释放。
- 生命周期由程序员控制，不随函数结束自动释放。
- 忘记释放会造成内存泄漏。
- 重复释放或释放错误地址会导致严重问题。
- 堆通常是向高地址方向增长，也就是课件中说的“向上增长”。

### 3. 数据段 / 静态区

数据段主要存放：

- 全局变量
- 静态全局变量
- 静态局部变量

示例：

```cpp
int g_val = 10;
static int s_global = 20;

void Func()
{
    static int s_local = 30;
}
```

这些变量的生命周期通常都是整个程序运行期间。

### 4. 代码段 / 常量区

代码段主要存放：

- 可执行代码
- 只读常量
- 字符串字面量，例如 `"abcd"`

示例：

```cpp
const char* p = "abcd";
```

这里要区分：

- `p` 是局部指针变量，通常在栈上。
- `"abcd"` 是字符串字面量，通常在常量区。
- `*p` 访问的是字符串字面量中的字符。

### 5. 内存映射段

课件说明：

> 内存映射段是高效的 I/O 映射方式，用于装载一个共享的动态内存库。用户可使用系统接口创建共享内存，做进程间通信。

这个阶段只需要知道：

- 动态库加载可能用到内存映射。
- 文件映射、共享内存、进程间通信可能涉及这块区域。
- 对当前 C++ 初阶学习来说，了解即可。

## 1.3 `char2` 和 `pChar3` 的区别，这是本节易错点

```cpp
char char2[] = "abcd";
const char* pChar3 = "abcd";
```

### `char2` 的情况

```cpp
char char2[] = "abcd";
```

含义是：创建一个局部字符数组，并把字符串内容拷贝到数组中。

所以：

- `char2` 数组在栈上。
- `char2[0]`、`char2[1]` 等元素也在栈上。
- 数组内容可以修改。

示例：

```cpp
char char2[] = "abcd";
char2[0] = 'x'; // 可以，变成 "xbcd"
```

### `pChar3` 的情况

```cpp
const char* pChar3 = "abcd";
```

含义是：创建一个局部指针变量 `pChar3`，它指向字符串字面量 `"abcd"`。

所以：

- `pChar3` 这个指针变量本身在栈上。
- `"abcd"` 这个字符串字面量在常量区。
- 不应该修改字符串字面量。

示例：

```cpp
const char* pChar3 = "abcd";
// pChar3[0] = 'x'; // 错误，不允许修改字符串字面量
```

如果写成下面这样，在 C++ 中本身就不推荐：

```cpp
char* p = "abcd"; // C++ 中不推荐，甚至可能直接报错
```

因为字符串字面量是只读的，不应该用普通 `char*` 指向它。

# 2. C 语言中的动态内存管理

C 语言中动态内存管理主要使用：

```cpp
malloc
calloc
realloc
free
```

示例：

```cpp
void Test()
{
    // malloc/calloc/realloc 的区别是什么？
    int* p2 = (int*)calloc(4, sizeof(int));
    int* p3 = (int*)realloc(p2, sizeof(int) * 10);

    // 这里需要 free(p2) 吗？
    free(p3);
}
```

## 2.1 `malloc`

函数原型大致是：

```cpp
void* malloc(size_t size);
```

作用：向堆申请 `size` 字节的空间。

特点：

- 只负责开空间。
- 不负责初始化。
- 返回值是 `void*`。
- 在 C++ 中使用时通常需要强制类型转换。
- 申请失败返回 `NULL`。

示例：

```cpp
int* p = (int*)malloc(sizeof(int) * 10);
if (p == NULL)
{
    // 申请失败处理
}

free(p);
p = NULL;
```

注意：`malloc` 的单位是字节，所以需要自己计算空间大小。

```cpp
sizeof(int) * 10
```

表示申请 10 个 `int` 的空间。

## 2.2 `calloc`

函数原型大致是：

```cpp
void* calloc(size_t num, size_t size);
```

作用：申请 `num` 个元素，每个元素 `size` 字节，并把空间初始化为 0。

示例：

```cpp
int* p = (int*)calloc(10, sizeof(int));
```

特点：

- 会初始化为 0。
- 参数更像“元素个数 × 单个元素大小”。
- 适合希望申请后默认清零的场景。

## 2.3 `realloc`

函数原型大致是：

```cpp
void* realloc(void* ptr, size_t size);
```

作用：调整已有动态内存块的大小。

示例：

```cpp
int* p2 = (int*)calloc(4, sizeof(int));
int* p3 = (int*)realloc(p2, sizeof(int) * 10);
free(p3);
```

重点理解：`realloc` 有两种可能情况。

### 情况一：原地扩容成功

如果原来的空间后面还有足够空间，`realloc` 可能直接在原地址扩容。

这时：

- `p3` 和 `p2` 的地址可能相同。
- 原空间仍然有效，但应该以后用 `p3` 管理。

### 情况二：搬家扩容

如果原来的空间后面不够用，`realloc` 可能会：

1. 重新找一块更大的空间。
2. 把原数据拷贝过去。
3. 释放原空间。
4. 返回新空间地址。

这时：

- `p3` 和 `p2` 的地址不同。
- 原来的 `p2` 已经失效。
- 不能再 `free(p2)`。

所以课件里的问题：

```cpp
int* p2 = (int*)calloc(4, sizeof(int));
int* p3 = (int*)realloc(p2, sizeof(int) * 10);

// 这里需要 free(p2) 吗？
free(p3);
```

答案：**不需要，也不能再单独 `free(p2)`。应该释放 `p3`。**

但是更严谨的写法是：

```cpp
int* p2 = (int*)calloc(4, sizeof(int));
int* tmp = (int*)realloc(p2, sizeof(int) * 10);
if (tmp == NULL)
{
    // realloc 失败时，原来的 p2 仍然有效，需要释放 p2
    free(p2);
    p2 = NULL;
}
else
{
    p2 = tmp;
    free(p2);
    p2 = NULL;
}
```

为什么不建议直接写：

```cpp
p2 = (int*)realloc(p2, newSize);
```

因为如果 `realloc` 失败，会返回 `NULL`，这会导致原来的地址丢失，从而造成内存泄漏。

## 2.4 `free`

作用：释放堆上的动态内存。

示例：

```cpp
int* p = (int*)malloc(sizeof(int) * 10);
free(p);
p = NULL;
```

注意：

- `free` 只能释放动态申请的堆空间。
- 不能释放栈上的变量。
- 不能重复释放同一块空间。
- `free(NULL)` 是安全的。

错误示例：

```cpp
int a = 10;
free(&a); // 错误，a 是栈变量
```

```cpp
int* p = (int*)malloc(sizeof(int));
free(p);
free(p); // 错误，重复释放
```

---

## 2.5 面试题：`malloc`、`calloc`、`realloc` 的区别

可以这样回答：

1. `malloc(size)` 申请指定字节数的空间，不初始化内容。
2. `calloc(num, size)` 申请 `num * size` 字节空间，并把内容初始化为 0。
3. `realloc(ptr, size)` 用于调整已有动态内存的大小，可能原地扩容，也可能重新申请新空间并拷贝旧数据。
4. 三者申请失败都会返回 `NULL`。
5. 申请到的空间最终都需要用 `free` 释放。

## 2.6 面试题：`malloc` 的实现原理，了解即可

课件提到：

> malloc 的实现原理？glibc 中 malloc 实现原理。

初阶阶段不需要深入到源码，但需要知道大概方向：

- `malloc` 并不是每次都直接向操作系统要内存。
- C 运行库内部会维护一个堆内存管理器。
- 小块内存通常从运行库已经管理的内存池中分配。
- 大块内存可能通过系统调用向操作系统申请。
- `free` 后的内存不一定马上还给操作系统，可能被运行库缓存起来，供后续 `malloc` 复用。

在 Linux 的 glibc 中，`malloc` 涉及：

- `brk` / `sbrk`
- `mmap`
- chunk 管理
- bin 链表
- tcache

这些属于更深入的系统编程或底层内存管理内容，当前只需知道它们是 `malloc` 底层实现的一部分。

# 3. C++ 内存管理方式

C 语言的内存管理方式在 C++ 中仍然可以使用，例如：

```cpp
malloc
free
```

但是 C++ 有类和对象，类对象的创建不仅是“开空间”，还涉及：

- 构造函数
- 析构函数
- 初始化
- 资源管理

所以 C++ 提供了自己的动态内存管理方式：

```cpp
new
delete
```

以及数组版本：

```cpp
new[]
delete[]
```

---

# 4. `new/delete` 操作内置类型

示例：

```cpp
void Test()
{
    // 动态申请一个 int 类型的空间
    int* ptr4 = new int;

    // 动态申请一个 int 类型的空间并初始化为 10
    int* ptr5 = new int(10);

    // 动态申请 3 个 int 类型的空间
    int* ptr6 = new int[3];

    delete ptr4;
    delete ptr5;
    delete[] ptr6;
}
```

## 4.1 单个对象

```cpp
int* p = new int;
delete p;
```

这里表示：

- `new int`：在堆上申请一个 `int` 的空间。
- `delete p`：释放这个 `int` 空间。

如果想初始化：

```cpp
int* p = new int(10);
```

表示申请一个 `int`，并初始化为 `10`。

## 4.2 多个对象，也就是数组

```cpp
int* arr = new int[10];
delete[] arr;
```

这里表示：

- `new int[10]`：在堆上申请 10 个连续的 `int` 空间。
- `delete[] arr`：释放数组空间。

## 4.3 必须匹配使用

课件强调：

> 申请和释放单个元素的空间，使用 `new` 和 `delete` 操作符；申请和释放连续的空间，使用 `new[]` 和 `delete[]`，注意匹配起来使用。

正确匹配：

```cpp
int* p = new int;
delete p;
```

```cpp
int* arr = new int[10];
delete[] arr;
```

错误示例：

```cpp
int* arr = new int[10];
delete arr; // 错误，应该使用 delete[]
```

```cpp
int* p = new int;
delete[] p; // 错误，应该使用 delete
```

对于内置类型，有时候错误匹配不一定马上崩溃，但它仍然是未定义行为。对于自定义类型，错误匹配尤其危险，因为析构函数调用次数可能不正确。

# 5. `new/delete` 操作自定义类型

## 5.1 示例代码

```cpp
class A
{
public:
    A(int a = 0)
        : _a(a)
    {
        cout << "A():" << this << endl;
    }

    ~A()
    {
        cout << "~A():" << this << endl;
    }

private:
    int _a;
};

int main()
{
    // new/delete 和 malloc/free 最大区别是：
    // new/delete 对于自定义类型除了开空间，还会调用构造函数和析构函数
    A* p1 = (A*)malloc(sizeof(A));
    A* p2 = new A(1);

    free(p1);
    delete p2;

    // 内置类型几乎是一样的
    int* p3 = (int*)malloc(sizeof(int));
    int* p4 = new int;

    free(p3);
    delete p4;

    A* p5 = (A*)malloc(sizeof(A) * 10);
    A* p6 = new A[10];

    free(p5);
    delete[] p6;

    return 0;
}
```

## 5.2 核心结论

对于自定义类型：

- `malloc` 只申请空间，不调用构造函数。
- `free` 只释放空间，不调用析构函数。
- `new` 先申请空间，再调用构造函数。
- `delete` 先调用析构函数，再释放空间。
- `new[]` 会给 N 个对象申请空间，并调用 N 次构造函数。
- `delete[]` 会调用 N 次析构函数，再释放数组空间。

## 5.3 为什么这件事很重要？

因为 C++ 对象往往不仅仅包含普通数据，还可能管理资源，例如：

- 动态内存
- 文件句柄
- 网络连接
- 锁
- 系统资源

构造函数负责初始化资源，析构函数负责释放资源。

如果使用 `malloc/free` 管理 C++ 对象，就可能跳过构造和析构，导致对象状态不完整或资源泄漏。

例如：

```cpp
class MyString
{
public:
    MyString()
    {
        _str = new char[10];
    }

    ~MyString()
    {
        delete[] _str;
    }

private:
    char* _str;
};
```

如果这样写：

```cpp
MyString* p = (MyString*)malloc(sizeof(MyString));
free(p);
```

问题是：

- 构造函数没有执行，`_str` 没有正确初始化。
- 析构函数没有执行，资源清理逻辑不会运行。

正确写法：

```cpp
MyString* p = new MyString;
delete p;
```

# 6. `operator new` 与 `operator delete` 函数

这是本章的重点之一。

## 6.1 先区分两个概念

很多初学者会混淆：

```cpp
new
operator new
```

它们不是同一个东西。

| 名称 | 本质 | 作用 |
|---|---|---|
| `new` | 操作符 / 表达式 | 申请空间，并在需要时调用构造函数。 |
| `operator new` | 函数 | 只负责申请原始内存空间，类似 `malloc`。 |
| `delete` | 操作符 / 表达式 | 调用析构函数，并释放空间。 |
| `operator delete` | 函数 | 只负责释放原始内存空间，类似 `free`。 |

## 6.2 `new` 的底层大致过程

对于：

```cpp
A* p = new A(1);
```

底层大致做了两件事：

1. 调用 `operator new(sizeof(A))` 申请原始空间。
2. 在这块空间上调用 `A` 的构造函数。

## 6.3 `delete` 的底层大致过程

对于：

```cpp
delete p;
```

底层大致做了两件事：

1. 调用 `A` 的析构函数。
2. 调用 `operator delete(p)` 释放原始空间。

---

## 6.4 课件中的 `operator new` 示例

课件给出的实现大致如下：

```cpp
/*
operator new：该函数实际通过 malloc 来申请空间。
当 malloc 申请空间成功时直接返回；
申请空间失败，尝试执行空间不足应对措施，
如果该应对措施用户设置了，则继续申请，否则抛异常。
*/
void* operator new(size_t size)
{
    void* p;
    while ((p = malloc(size)) == 0)
    {
        if (_callnewh(size) == 0)
        {
            static const std::bad_alloc nomem;
            _RAISE(nomem);
        }
    }

    return p;
}
```

这段代码说明：

- `operator new` 底层通常会用 `malloc` 申请空间。
- 如果申请成功，直接返回。
- 如果申请失败，可能会调用用户设置的内存不足处理函数。
- 如果仍然失败，会抛出 `std::bad_alloc` 异常。

所以，`new` 和 `malloc` 在失败时的表现不同：

```cpp
int* p1 = (int*)malloc(sizeof(int));
if (p1 == NULL)
{
    // malloc 失败
}
```

```cpp
try
{
    int* p2 = new int;
}
catch (const std::bad_alloc& e)
{
    // new 失败
}
```

## 6.5 课件中的 `operator delete` 示例

课件给出的结论：

```cpp
/*
operator delete：该函数最终是通过 free 来释放空间的
*/
void operator delete(void* pUserData)
{
    // ...
    free(pUserData);
}
```

也就是说：

- `operator delete` 负责释放原始内存。
- 它底层通常会调用 `free`。

## 6.6 本节核心结论

通过上述两个全局函数可以知道：

1. `operator new` 实际通常通过 `malloc` 申请空间。
2. `operator delete` 实际通常通过 `free` 释放空间。
3. `new` 不等于 `operator new`。
4. `delete` 不等于 `operator delete`。
5. `new/delete` 比 `operator new/operator delete` 多了构造和析构这一步。

# 7. `new` 和 `delete` 的实现原理

## 7.1 内置类型

如果申请的是内置类型空间，例如：

```cpp
int* p = new int;
delete p;
```

那么 `new/delete` 和 `malloc/free` 基本类似。

不同点主要有：

1. `new/delete` 用于单个元素，`new[]/delete[]` 用于连续空间。
2. `new` 可以直接初始化。
3. `new` 申请失败时默认抛异常。
4. `malloc` 申请失败时返回 `NULL`。
5. `malloc` 需要手动计算字节数，`new` 只需要写类型。

对比：

```cpp
int* p1 = (int*)malloc(sizeof(int));
int* p2 = new int;

free(p1);
delete p2;
```

## 7.2 自定义类型

这是重点。

### `new` 的原理

对于：

```cpp
A* p = new A(10);
```

步骤是：

1. 调用 `operator new` 函数申请空间。
2. 在申请的空间上执行构造函数，完成对象构造。

### `delete` 的原理

对于：

```cpp
delete p;
```

步骤是：

1. 在对象空间上执行析构函数，完成对象中资源的清理工作。
2. 调用 `operator delete` 函数释放对象空间。

### `new T[N]` 的原理

对于：

```cpp
A* arr = new A[10];
```

步骤是：

1. 调用 `operator new[]` 函数申请空间。
2. `operator new[]` 内部通常会调用 `operator new` 完成空间申请。
3. 在申请的空间上执行 N 次构造函数。

### `delete[]` 的原理

对于：

```cpp
delete[] arr;
```

步骤是：

1. 对数组中的 N 个对象执行 N 次析构函数。
2. 调用 `operator delete[]` 释放空间。
3. `operator delete[]` 内部通常会调用 `operator delete` 释放空间。

# 8. 定位 new 表达式：placement new

这一节课件标注为“了解”。

## 8.1 什么是定位 new？

定位 new 表达式是在已经分配好的原始内存空间中调用构造函数初始化一个对象。

使用格式：

```cpp
new (place_address) type;
new (place_address) type(initializer_list);
```

其中：

- `place_address` 必须是一个指针。
- `initializer_list` 是类型的初始化参数列表。

普通 `new` 是：

```cpp
A* p = new A(10);
```

它做两件事：

1. 申请空间。
2. 构造对象。

定位 `new` 是：

```cpp
new(p) A(10);
```

它只做一件事：

- 在已有空间 `p` 上调用构造函数。

它**不负责申请空间**。

---

## 8.2 示例代码

```cpp
class A
{
public:
    A(int a = 0)
        : _a(a)
    {
        cout << "A():" << this << endl;
    }

    ~A()
    {
        cout << "~A():" << this << endl;
    }

private:
    int _a;
};

int main()
{
    // p1 现在指向的只不过是与 A 对象相同大小的一段空间，
    // 还不能算是一个完整对象，因为构造函数没有执行。
    A* p1 = (A*)malloc(sizeof(A));

    new(p1) A; // 如果 A 的构造函数有参数，此处需要传参

    p1->~A();  // 显式调用析构函数
    free(p1);  // 释放原始空间

    A* p2 = (A*)operator new(sizeof(A));
    new(p2) A(10);

    p2->~A();
    operator delete(p2);

    return 0;
}
```

## 8.3 为什么要显式调用析构函数？

因为定位 `new` 只是在已有空间上构造对象，不会改变这块空间的释放方式。

如果你是这样申请的空间：

```cpp
A* p = (A*)malloc(sizeof(A));
new(p) A(10);
```

那么你不能直接：

```cpp
delete p; // 不推荐，申请和释放方式不匹配
```

应该：

```cpp
p->~A();
free(p);
```

也就是说：

- 构造：用定位 `new` 手动构造。
- 析构：用 `p->~A()` 手动析构。
- 空间释放：用与申请方式匹配的释放函数。

如果空间来自 `malloc`，就用 `free`。

如果空间来自 `operator new`，就用 `operator delete`。

## 8.4 定位 new 的使用场景

课件中说：

> 定位 new 表达式在实际中一般是配合内存池使用。因为内存池分配出的内存没有初始化，所以如果是自定义类型的对象，需要使用定位 new 表达式显式调用构造函数进行初始化。

简单理解：

内存池可能提前准备好一大块原始内存，然后需要在这块内存上创建对象。

这时就可以：

1. 从内存池拿一块原始空间。
2. 用定位 `new` 在这块空间上构造对象。
3. 对象不用时显式调用析构函数。
4. 把空间还给内存池。

# 9. `malloc/free` 和 `new/delete` 的区别

课件原文核心结论：

> `malloc/free` 和 `new/delete` 的共同点是：都是从堆上申请空间，并且需要用户手动释放。

不同点如下：

| 对比点 | `malloc/free` | `new/delete` |
|---|---|---|
| 本质 | 函数 | 操作符 |
| 申请单位 | 字节数 | 类型 |
| 是否需要强转 | 在 C++ 中通常需要 | 不需要 |
| 是否初始化 | `malloc` 不初始化，`calloc` 初始化为 0 | `new` 可以初始化，并会调用构造函数 |
| 失败处理 | 返回 `NULL` | 默认抛出 `std::bad_alloc` 异常 |
| 自定义类型 | 不调用构造和析构 | 调用构造和析构 |
| 释放方式 | `free` | `delete` / `delete[]` |
| 数组申请 | 手动计算大小 | `new T[N]` |

## 9.1 详细解释版

### 1. `malloc/free` 是函数，`new/delete` 是操作符

```cpp
int* p1 = (int*)malloc(sizeof(int));
int* p2 = new int;
```

`malloc` 是库函数，`new` 是 C++ 的操作符。

### 2. `malloc` 不会初始化，`new` 可以初始化

```cpp
int* p1 = (int*)malloc(sizeof(int)); // 内容不确定
int* p2 = new int(10);               // 初始化为 10
```

### 3. `malloc` 需要手动计算空间大小，`new` 不需要

```cpp
int* p1 = (int*)malloc(sizeof(int) * 10);
int* p2 = new int[10];
```

`new` 后面直接跟类型和数量，表达更自然。

### 4. `malloc` 返回 `void*`，`new` 返回对应类型指针

```cpp
int* p1 = (int*)malloc(sizeof(int));
int* p2 = new int;
```

在 C++ 中，`void*` 不能自动转换成 `int*`，所以通常需要强制类型转换。

### 5. 失败处理不同

`malloc` 失败：

```cpp
int* p = (int*)malloc(sizeof(int));
if (p == NULL)
{
    // 处理申请失败
}
```

`new` 失败：

```cpp
try
{
    int* p = new int;
}
catch (const std::bad_alloc& e)
{
    // 处理申请失败
}
```

### 6. 对自定义类型的处理不同

```cpp
A* p1 = (A*)malloc(sizeof(A)); // 只开空间，不调用构造函数
A* p2 = new A;                 // 开空间 + 调用构造函数

free(p1);   // 只释放空间，不调用析构函数
delete p2;  // 调用析构函数 + 释放空间
```

这也是最核心的区别。

# 10. 本章常见错误总结

## 错误 1：`new[]` 和 `delete` 混用

错误：

```cpp
int* arr = new int[10];
delete arr;
```

正确：

```cpp
int* arr = new int[10];
delete[] arr;
```

## 错误 2：`new` 和 `free` 混用

错误：

```cpp
int* p = new int;
free(p);
```

正确：

```cpp
int* p = new int;
delete p;
```

## 错误 3：`malloc` 和 `delete` 混用

错误：

```cpp
int* p = (int*)malloc(sizeof(int));
delete p;
```

正确：

```cpp
int* p = (int*)malloc(sizeof(int));
free(p);
```

## 错误 4：忘记释放动态内存

错误：

```cpp
void Func()
{
    int* p = new int[100];
    // 忘记 delete[] p
}
```

结果：内存泄漏。

正确：

```cpp
void Func()
{
    int* p = new int[100];
    delete[] p;
}
```

更现代的 C++ 写法是尽量使用容器或智能指针：

```cpp
#include <vector>

void Func()
{
    std::vector<int> v(100);
}
```

或者：

```cpp
#include <memory>

void Func()
{
    std::unique_ptr<int[]> p(new int[100]);
}
```

不过在学习内存管理这一章时，仍然要先理解手动管理的原理。

## 错误 5：`realloc` 直接覆盖原指针

不推荐：

```cpp
p = (int*)realloc(p, newSize);
```

如果失败，原来的地址会丢失，导致内存泄漏。

推荐：

```cpp
int* tmp = (int*)realloc(p, newSize);
if (tmp != NULL)
{
    p = tmp;
}
else
{
    // p 仍然有效，后续可以继续使用或 free(p)
}
```

## 错误 6：修改字符串字面量

错误：

```cpp
char* p = "abcd";
p[0] = 'x';
```

正确：

```cpp
char arr[] = "abcd";
arr[0] = 'x';
```

# 11. 本章面试题整理

## 11.1 `malloc`、`calloc`、`realloc` 的区别？

答：

`malloc` 用于申请指定字节数的动态内存，不会初始化内容；`calloc` 用于申请若干个元素的空间，并会把空间初始化为 0；`realloc` 用于调整已有动态内存块大小，可能原地扩容，也可能重新申请空间、拷贝旧数据并释放旧空间。三者申请失败都会返回 `NULL`，申请到的空间最终都需要用 `free` 释放。

## 11.2 `realloc` 后原指针还需要 `free` 吗？

答：

如果 `realloc` 成功，应该释放 `realloc` 返回的新指针，不应该再释放原指针。因为成功后原指针要么和新指针相同，要么原空间已经被释放。如果 `realloc` 失败，它会返回 `NULL`，此时原指针仍然有效，需要后续释放原指针。为了避免内存泄漏，推荐用临时指针接收 `realloc` 的返回值。

## 11.3 `malloc/free` 和 `new/delete` 的区别？

答：

它们都可以从堆上申请空间，并且都需要手动释放。区别是：`malloc/free` 是 C 语言库函数，`new/delete` 是 C++ 操作符；`malloc` 需要手动计算字节数，返回 `void*`，在 C++ 中通常需要强转，而 `new` 根据类型自动计算大小并返回对应类型指针；`malloc` 申请失败返回 `NULL`，`new` 默认失败时抛出 `std::bad_alloc`；最重要的是，对于自定义类型，`malloc/free` 只申请和释放原始空间，不调用构造函数和析构函数，而 `new/delete` 会自动调用构造函数和析构函数。

## 11.4 `new` 和 `operator new` 的区别？

答：

`new` 是 C++ 的操作符或表达式，它不仅会申请空间，还会调用构造函数。`operator new` 是一个函数，只负责申请原始内存空间，类似于 `malloc`。对于自定义类型，`new A` 大致等价于先调用 `operator new(sizeof(A))` 申请空间，再在这块空间上调用 `A` 的构造函数。

## 11.5 `delete` 和 `operator delete` 的区别？

答：

`delete` 是 C++ 的操作符或表达式，它会先调用对象的析构函数，再调用 `operator delete` 释放空间。`operator delete` 是一个函数，只负责释放原始内存空间，类似于 `free`。

## 11.6 什么是定位 new？

答：

定位 `new`，也叫 placement new，是在一块已经分配好的原始内存上调用构造函数，用于把这块内存初始化成一个对象。它不会申请空间，只负责构造对象。常见使用场景是内存池。使用定位 `new` 构造出来的对象，通常需要显式调用析构函数，然后再用对应的方式释放原始内存。

# 14. 一页速记版

## 内存区域

- 栈：普通局部变量、函数参数、局部数组。
- 堆：动态申请的空间，`malloc/new` 得到的空间。
- 数据段 / 静态区：全局变量、静态变量。
- 代码段 / 常量区：代码、只读常量、字符串字面量。

## C 动态内存管理

```cpp
malloc  // 申请空间，不初始化
calloc  // 申请空间，并初始化为 0
realloc // 调整空间大小
free    // 释放空间
```

## C++ 动态内存管理

```cpp
new      // 申请单个对象空间，并构造
delete   // 析构单个对象，并释放空间
new[]    // 申请对象数组，并逐个构造
delete[] // 逐个析构对象数组，并释放空间
```

## 核心区别

```cpp
A* p1 = (A*)malloc(sizeof(A)); // 只开空间
A* p2 = new A;                 // 开空间 + 构造函数

free(p1);   // 只释放空间
delete p2;  // 析构函数 + 释放空间
```

## 匹配规则

```cpp
malloc  <-> free
new     <-> delete
new[]   <-> delete[]
```

不要混用。
