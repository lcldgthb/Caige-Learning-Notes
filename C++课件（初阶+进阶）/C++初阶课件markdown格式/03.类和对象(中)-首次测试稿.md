## 一、本章内容总览

这一讲的核心不是“类怎么定义”，而是：

1. C++ 在类对象身上默认会生成哪些成员函数；
2. 构造、析构、拷贝构造分别负责什么；
3. 为什么有资源的类不能直接依赖默认拷贝；
4. 运算符重载到底是在重载什么；
5. `const` 成员函数和普通成员函数有什么边界。

一句话主线：

> 这一讲是在把“对象如何被创建、拷贝、销毁、比较和修改”这一整套机制补齐，它们共同决定了类对象的生命周期和行为边界。

## 二、核心知识结构

### 1. 默认成员函数
- 默认成员函数是编译器在用户未显式实现时，可能为类自动生成的一组特殊成员函数。
- 本讲重点集中在：构造函数、析构函数、拷贝构造函数、赋值重载、取地址重载等相关机制。

### 2. 构造与析构
- 构造函数负责对象初始化；
- 析构函数负责对象生命周期结束时的资源清理；
- 对于带资源的类，析构函数往往不可省略。

### 3. 拷贝构造与赋值
- 拷贝构造解决“用一个同类对象初始化另一个对象”；
- 赋值重载解决“两个已存在对象之间赋值”；
- 对资源类，默认拷贝通常会导致浅拷贝问题。

### 4. 运算符重载
- 让自定义类型支持 `==`、`++`、`<<`、`>>`、`+=`、`-=` 等运算；
- 本质上仍是函数调用；
- 并不是所有运算符都可以重载。

### 5. `const` 成员函数
- 用于约束成员函数在逻辑上不修改对象状态；
- 允许 `const` 对象调用只读接口；
- 本质上约束的是隐藏的 `this` 指针权限。

## 三、核心知识讲解

### 1. 默认成员函数到底是什么

**结论：** 默认成员函数是编译器在需要时为类提供的一组特殊成员函数，它们主要围绕“对象的创建、拷贝、赋值、销毁和地址获取”展开。

这一讲里最需要先掌握的，不是死记“有几个函数”，而是先知道它们各自负责哪类对象行为：

- 构造：对象刚创建时怎么初始化；
- 析构：对象结束时怎么清理；
- 拷贝构造：怎么用已有对象初始化新对象；
- 赋值重载：两个已有对象之间如何赋值；
- 取地址重载：对象取地址时是否使用自定义行为。

### 2. 构造函数：核心任务是初始化对象

**结论：** 构造函数的核心职责是初始化对象，而不是“申请对象空间”。

对象的空间往往在进入构造函数之前就已经准备好了，构造函数做的是：

- 给成员变量赋初值；
- 建立对象初始状态；
- 对需要资源的成员进行初始化。

最容易混淆的点：

- **无参构造函数**：形参为空；
- **全缺省构造函数**：所有参数都有默认值；
- **默认构造函数**：不传实参就能调用的构造函数。

最重要区别：

> **默认构造函数不是只指“编译器自动生成的那个构造函数”，而是指“可以不传参数直接调用的构造函数”。**

这意味着：

- 无参构造函数可以是默认构造；
- 全缺省构造函数也可以是默认构造；
- 二者不能同时都以“默认构造”的身份参与无参调用，否则会出现歧义。

### 3. 析构函数：资源类的生命线

**结论：** 析构函数负责对象生命周期结束时的资源清理，尤其是堆内存、文件句柄、锁等外部资源。

对像 `Date` 这种只含普通值成员的类，析构函数通常可以不用显式写；
但对像 `Stack` 这种内部通过 `malloc` 申请了堆空间的类，如果不写析构函数，就会造成资源泄漏。

最重要区别：

> **没有资源的类，析构函数通常可以依赖默认行为；有资源的类，析构函数往往必须显式实现。**

局部对象的析构顺序还要记住：

- 同一作用域中的局部对象，通常按“后定义先析构”的顺序销毁。

### 4. 拷贝构造函数：初始化新对象，不是给旧对象重新赋值

**结论：** 拷贝构造函数解决的是“用一个同类对象去初始化一个新对象”。

典型场景：

- `Date d2(d1);`
- `Date d3 = d1;`
- 值传参；
- 值返回（在未被优化掉时）。

最重要区别：

> **拷贝构造发生在“新对象创建时”，赋值重载发生在“两个对象都已经存在之后”。**

为什么参数通常写成 `const T&`？

- 写成传值会再次触发拷贝构造，形成无限递归；
- 写成引用可以避免不必要复制；
- 加 `const` 可以接受常对象和临时对象，也保证不误改源对象。

### 5. 为什么资源类不能直接依赖默认拷贝

**结论：** 对带堆资源的类，默认拷贝常常只是逐成员拷贝地址，会导致浅拷贝问题。

以 `Stack` 为例：

- 内部有 `_a` 指向堆空间；
- 如果直接默认拷贝，两个对象会指向同一块堆空间；
- 其中一个对象析构后，另一个对象里的指针就悬空；
- 两个对象最终析构时还可能重复释放同一块内存。

最重要区别：

> **值成员的默认拷贝通常没问题；资源句柄类成员的默认拷贝往往有风险。**

因此资源类通常需要：

- 自定义拷贝构造；
- 按需自定义赋值重载；
- 深拷贝资源，而不是只复制指针值。

### 6. 运算符重载：本质上还是函数

**结论：** 运算符重载的本质不是“改变运算符含义”，而是为自定义类型提供对应的函数形式。

例如：

- `d1 == d2` 本质可理解为调用比较函数；
- `++d1` 和 `d1++` 对应不同重载；
- `<<` / `>>` 常配合流对象实现输出输入。

最重要区别：

> **运算符重载是“给自定义类型提供自然写法”，不是让任何符号都能随意重定义。**

需要重点记住：

- 不是所有运算符都能重载；
- `++` 的前置与后置不同，后置版本额外用一个 `int` 占位参数区分；
- `<<` / `>>` 通常更适合写成非成员或友元形式，因为左操作数常常不是当前类对象，而是流对象。

### 7. 赋值重载：解决已存在对象之间的赋值

**结论：** 赋值重载 `operator=` 处理的是两个已存在对象之间的状态复制。

典型场景：

```cpp
Date d1(2024, 7, 5);
Date d2(2024, 7, 6);
d1 = d2;
```

最重要区别：

> **拷贝构造是“创建新对象时初始化”，赋值重载是“老对象覆盖自己原状态”。**

资源类写赋值重载时，通常还要处理：

- 自赋值判断；
- 原资源释放时机；
- 新资源复制。

### 8. `const` 成员函数：约束的是 `this` 指针权限

**结论：** `const` 成员函数承诺“不会通过当前对象修改成员状态”。

比如：

```cpp
void Print() const;
```

其意义不是“这个函数什么都不能做”，而是：

- 可以读取成员；
- 不能修改普通成员；
- 因此可以让 `const` 对象也安全调用。

最重要区别：

> **普通成员函数默认拿到的是可写对象视角；`const` 成员函数拿到的是只读对象视角。**

这就是为什么：

- `const` 对象能调用 `Print() const`；
- 但不能调用会修改对象状态的普通成员函数。

## 四、关键代码与案例

### 1. 默认构造、无参构造、全缺省构造的关系

这段代码主要用于说明“默认构造”不是只指编译器自动生成的那个函数：

```cpp
class Date
{
public:
    Date()
    {
        _year = 1;
        _month = 1;
        _day = 1;
    }

    Date(int year, int month, int day)
    {
        _year = year;
        _month = month;
        _day = day;
    }

    // Date(int year = 1, int month = 1, int day = 1) { ... }
};
```

要点：

- 无参构造和全缺省构造都可以成为默认构造；
- 但不要同时让两个“无参可调用”的构造并存，否则会产生调用歧义；
- `Date d3();` 在这里不是创建对象，而是函数声明式写法的经典陷阱。

### 2. 资源类的浅拷贝风险

这段代码主要说明为什么 `Stack` 不能直接依赖默认拷贝：

```cpp
class Stack
{
public:
    Stack(int n = 4)
    {
        _a = (STDataType*)malloc(sizeof(STDataType) * n);
        _capacity = n;
        _top = 0;
    }

    ~Stack()
    {
        free(_a);
        _a = nullptr;
        _top = _capacity = 0;
    }

private:
    STDataType* _a;
    size_t _capacity;
    size_t _top;
};
```

要点：

- `_a` 指向堆空间；
- 默认拷贝只会把地址值复制一份；
- 两个对象共享同一块堆内存时，析构会出问题；
- 因此需要自定义拷贝构造实现深拷贝。

### 3. 拷贝构造参数为什么通常写 `const T&`

```cpp
Date(const Date& d)
{
    _year = d._year;
    _month = d._month;
    _day = d._day;
}
```

要点：

- 不能写成 `Date(Date d)`；
- 传值会再次触发拷贝构造，逻辑走不通；
- `const T&` 既避免递归，又不多做复制，还能保证源对象不被误改。

### 4. 运算符重载里的前置 `++` 和后置 `++`

```cpp
Date& operator++()
{
    *this += 1;
    return *this;
}

Date operator++(int)
{
    Date tmp(*this);
    *this += 1;
    return tmp;
}
```

要点：

- 前置 `++`：先改后返回；
- 后置 `++`：先保存旧值，再自增，最后返回旧值；
- 后置版本里的 `int` 只是占位参数，不表示真正传入有意义的整数。

## 五、易混概念与易错点

### 易混概念

| 概念 A | 概念 B | 最重要区别 |
|---|---|---|
| 默认构造函数 | 编译器自动生成的构造函数 | 默认构造强调“不传参可调用”，不等于“编译器生成” |
| 拷贝构造 | 赋值重载 | 前者在新对象创建时发生，后者在已有对象之间赋值时发生 |
| 浅拷贝 | 深拷贝 | 浅拷贝复制地址值，深拷贝复制资源本体 |
| 前置 `++` | 后置 `++` | 前置返回更新后对象，后置保留旧值再返回 |
| 普通成员函数 | `const` 成员函数 | 后者承诺不通过当前对象修改状态 |

### 易错点

1. 误以为默认构造函数只指“编译器自动生成的那个构造函数”。
2. 写出 `Date d3();` 却以为创建了对象。
3. 拷贝构造参数写成传值，导致逻辑错误。
4. 资源类直接依赖默认拷贝，导致浅拷贝与重复释放。
5. 混淆拷贝构造和赋值重载的使用场景。
6. 误以为所有运算符都能重载。
7. 不理解后置 `++` 里 `int` 参数只是区分签名。
8. 给 `const` 对象调用非 `const` 成员函数。

## 七、核心总结

- **这一讲的核心是对象生命周期与对象行为控制。**
- **构造函数负责初始化对象，不负责申请对象空间。**
- **析构函数负责清理资源类对象内部持有的资源。**
- **默认构造函数强调“无参可调用”，不只指编译器生成版本。**
- **拷贝构造用于“新对象初始化”，赋值重载用于“已有对象赋值”。**
- **资源类若默认拷贝，常会导致浅拷贝问题。**
- **运算符重载本质仍是函数，只是给自定义类型提供更自然的写法。**
- **前置 `++` 和后置 `++` 行为不同，后置版本通过额外 `int` 参数区分。**
- **`const` 成员函数的本质是限制 `this` 的可写权限。**
