## 一句话主线

**这一章真正要掌握的，不只是会调 `std::string` 的几个接口，而是：为什么它比 C 风格字符串更适合 C++、它在刷题里怎么用、以及自己实现 `String` 类时为什么会遇到浅拷贝和资源管理问题。**

---

## 必会结论

1. **`string` 是类，不只是字符数组。**  
   它把字符串数据和常用操作封装在一起，比 `char*` / `char[]` 更适合 C++ 的对象化写法。

2. **C 风格字符串的核心问题是：操作分散、容易越界、资源管理麻烦。**  
   `string` 的意义就是把这些麻烦收拢成统一接口。

3. **学 `string` 前，`auto` 和范围 `for` 基本要会。**  
   这一章课件一开始就补这两个工具，因为遍历字符串、容器时会经常出现。

4. **`size()` / `length()` 看的是当前长度，`capacity()` 看的是容量。**  
   长度和容量不是一回事。

5. **`reserve` 和 `resize` 必须分清。**  
   - `reserve(n)`：预留容量，主要影响空间规模。  
   - `resize(n)`：直接改逻辑长度，可能补字符，也可能截断内容。

6. **`find` / `rfind` / `substr` 是字符串题高频接口。**  
   尤其是 `rfind(' ')` 配合 `getline`，经常用来处理“最后一个单词长度”这类题。

7. **`cin >> s` 读单词，`getline(cin, s)` 读整行。**  
   只要题目里可能有空格，就要想到 `getline`。

8. **OJ 里 `string` 最常见的模型不是背接口，而是：双指针、统计、查找切分、模拟。**

9. **课件后半章的真正难点是自定义 `String` 类。**  
   如果类内部有动态开辟的 `char*`，默认拷贝通常会造成浅拷贝问题。

10. **浅拷贝的本质问题不是“长得像拷贝”，而是多个对象共享同一块资源。**  
    析构时会重复释放，所以必须用深拷贝或拷贝交换法处理。

11. **`String` 这类资源类的重点是：构造、析构、拷贝构造、赋值运算符要保持资源所有权一致。**

12. **VS / g++ 下 `string` 的对象大小和内部结构现象只能当“实现观察”，不能当作标准保证。**

## 最容易错

- **把 `reserve` 和 `resize` 混为一谈**：  
  错误理解：都是“改大小”。  
  正确理解：`reserve` 偏空间，`resize` 偏内容长度。

- **以为范围 `for` 一定能改原字符串**：  
  错误理解：`for (auto ch : s)` 可以直接改 `s`。  
  正确理解：值传递只改副本；要改原串必须写 `auto&`。

- **不会判断查找失败**：  
  错误理解：没找到就写 `-1`。  
  正确理解：规范写法是 `string::npos`。

- **把 `cin >>` 和 `getline` 用混**：  
  错误理解：`cin >> s` 也能把一整句带空格的话读进来。  
  正确理解：`>>` 遇空白停止，整行读取用 `getline`。

- **把 `string` 的内部实现现象当标准**：  
  错误理解：VS 下一定是某个固定字节数、一定按课件图那样存。  
  正确理解：这些只能作为实现示意，不是语言标准承诺。

- **自定义 `String` 类时不写拷贝构造和赋值**：  
  错误理解：编译器默认生成就够了。  
  正确理解：如果内部管理动态资源，默认逐成员拷贝往往会埋下重复释放问题。

- **只知道“深拷贝更安全”，但说不清为什么**：  
  正确答案必须能说明：每个对象都要拥有独立资源，否则析构阶段会出问题。

## 最小代码 / 贯穿案例

### 案例 1：先分清 `reserve` 和 `resize`

```cpp
string s = "abc";

s.reserve(10);   // 预留容量，不直接把内容变成 10 个字符
s.resize(5, 'x');

cout << s << endl;   // abcxx
cout << s.size() << endl;
```

你复习时要能直接说出：

- `reserve` 更像“先把教室留大”；
- `resize` 更像“直接改变现在班里人数”。

---

### 案例 2：`getline + rfind` 处理整行字符串

```cpp
string line;
while (getline(cin, line))
{
    size_t pos = line.rfind(' ');
    if (pos == string::npos)
        cout << line.size() << endl;
    else
        cout << line.size() - pos - 1 << endl;
}
```

这段代码很适合作为本章的“接口组合题”模板：

- `getline` 负责读整行；
- `rfind` 负责从后往前找；
- `string::npos` 负责判断没找到。

---

### 案例 3：自定义 `String` 类为什么会浅拷贝

```cpp
class String
{
public:
    String(const char* str = "")
    {
        _str = new char[strlen(str) + 1];
        strcpy(_str, str);
    }

    ~String()
    {
        delete[] _str;
        _str = nullptr;
    }

private:
    char* _str;
};
```

如果写：

```cpp
String s1("hello");
String s2(s1);
```

这时如果没有自己写拷贝构造，编译器默认做的是逐成员复制，也就是把 `_str` 这个地址直接拷一份。结果两个对象指向同一块空间，析构时就可能重复 `delete[]`。

这就是这一章后半段真正要你理解的点。

## OJ 题型速记

### 1. 双指针类

代表题：

- 只反转字母
- 验证回文串

你要记住的不是题面，而是模板：

1. 左右指针向中间逼近；
2. 遇到不符合条件的字符先跳过；
3. 需要比较就比较，需要交换就交换。

---

### 2. 统计类

代表题：

- 第一个只出现一次的字符

核心套路：

1. 第一遍统计次数；
2. 第二遍找满足条件的第一个位置。

这是“字符串 + 计数数组”的标准题型。

---

### 3. 查找切分类

代表题：

- 最后一个单词的长度

核心套路：

- 先整行读取；
- 再从后往前定位关键分隔符；
- 最后做长度差。

---

### 4. 模拟类

代表题：

- 字符串相加

核心套路：

1. 从尾部开始；
2. 逐位处理；
3. 保存进位；
4. 最后反转答案。

这类题训练的是“把数位操作映射到字符串下标”。

## 分层理解：后半章为什么会转向自己写 `String`

## 结论

因为课件不想让你停在“会调接口”这一层，而是要你看到：**`std::string` 之所以能安全使用，本质上依赖于它内部已经替你做好了资源管理和拷贝控制。**

## 为什么

如果你只学前半章，很容易产生错觉：

> `string` 不就是“更好用的字符数组”吗？

但一旦你尝试自己写一个字符串类，就会发现问题立刻出现：

- 空间要不要自己开？
- 析构时谁来释放？
- 复制对象时地址能不能直接抄过去？
- 赋值时旧空间什么时候释放？

于是这一章自然回到前面学过的类和对象、内存管理、深浅拷贝这些核心主题。

## 机制

对资源类来说，真正关键的是“所有权”：

- 这块内存归谁管？
- 拷贝之后是共享，还是一人一份？
- 析构时谁负责释放？

如果一个类内部用裸指针独占资源，那么：

- 默认逐成员拷贝通常只复制地址；
- 这会让多个对象以为自己都拥有同一块资源；
- 最终析构阶段就会冲突。

所以你需要：

- 深拷贝；或
- 更稳妥的拷贝交换法。

## 标准修正

### 标准结论

`std::string` 的对象大小、内部字段布局、小字符串优化方式，都不是语言标准固定死的。不同编译器和标准库实现可以不同。

### 课件表述

课件用 VS 和 g++ 的实现现象来帮助你理解：`string` 不是简单的一个 `char*`，它背后还会维护长度、容量，甚至可能做小字符串优化。
