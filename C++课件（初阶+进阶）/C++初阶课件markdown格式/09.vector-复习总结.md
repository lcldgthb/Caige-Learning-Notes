## 一、本讲核心主线

这一讲主要围绕两个层面展开：

1. **会使用 `std::vector`**
   - 构造、遍历、容量、增删查改、二维 `vector`。
2. **理解 `vector` 的底层行为**
   - 扩容机制、迭代器失效、模拟实现时的拷贝问题。

一句话概括：

> `vector` 本质上是“可动态扩容的顺序表 / 动态数组”，用起来像数组，底层却涉及扩容、拷贝、迭代器失效等重要细节。

## 二、vector 的定位

### 1. vector 是什么？

`vector` 是 STL 中最常用的顺序容器之一，可以理解成：

> 自动管理空间、支持动态扩容的数组。

它的优点：

- 支持随机访问，像数组一样方便。
- 支持自动扩容。
- 和 STL 算法、迭代器体系天然配合。
- OJ 和工程中都极其常用。

---

### 2. 学 vector 的目标

按照 STL 的三个层次学：

1. **能用**：会写、会调接口。
2. **明理**：知道扩容、失效、复杂度。
3. **能扩展**：能自己模拟实现简化版 `vector`。

这节课主要覆盖前两层，并开始接触第三层。

## 三、vector 的常见构造

常见构造方式：

| 构造形式 | 含义 |
|---|---|
| `vector()` | 空 `vector` |
| `vector(n, val)` | 构造 `n` 个 `val` |
| `vector(const vector& x)` | 拷贝构造 |
| `vector(first, last)` | 使用迭代器区间构造 |

示例：

```cpp
vector<int> v1;
vector<int> v2(5, 1);
vector<int> v3(v2);
int a[] = {1, 2, 3, 4};
vector<int> v4(a, a + 4);
```

复习重点：

- `vector<int>(5, 1)` 表示 5 个元素，每个值是 1。
- 迭代器区间构造非常常用，尤其在数组、字符串、其他容器之间转换时。

## 四、迭代器与遍历

### 1. begin 和 end

```cpp
vector<int> v{1, 2, 3, 4};
for (auto it = v.begin(); it != v.end(); ++it)
{
    cout << *it << " ";
}
```

含义：

- `begin()`：指向第一个元素。
- `end()`：指向最后一个元素的下一个位置。

注意：

> `end()` 不是有效元素位置，不能解引用。

---

### 2. rbegin 和 rend

```cpp
for (auto rit = v.rbegin(); rit != v.rend(); ++rit)
{
    cout << *rit << " ";
}
```

用于反向遍历：

- `rbegin()`：最后一个元素。
- `rend()`：第一个元素前一个逻辑位置。

---

### 3. 下标遍历

`vector` 最常用的遍历方式之一：

```cpp
for (size_t i = 0; i < v.size(); ++i)
{
    cout << v[i] << " ";
}
```

优点：

- 简单直观。
- 适合 OJ 题。
- 随机访问效率高。

---

### 4. 范围 for

```cpp
for (auto e : v)
{
    cout << e << " ";
}
```

修改元素时：

```cpp
for (auto& e : v)
{
    e *= 2;
}
```

---

## 五、容量相关接口

常用接口：

| 接口 | 作用 |
|---|---|
| `size()` | 当前有效元素个数 |
| `capacity()` | 当前容量 |
| `empty()` | 判断是否为空 |
| `resize()` | 改变有效元素个数 |
| `reserve()` | 改变容量 |

---

### 1. size

```cpp
v.size()
```

返回当前元素个数。

例如：

```cpp
vector<int> v{1, 2, 3};
cout << v.size(); // 3
```

---

### 2. capacity

```cpp
v.capacity()
```

返回当前底层空间能容纳的元素数量。

重点区分：

- `size`：已经有多少个元素。
- `capacity`：最多能装多少个元素而不扩容。

---

### 3. empty

```cpp
if (v.empty())
{
}
```

比 `v.size() == 0` 语义更直接。

---

### 4. reserve

```cpp
v.reserve(100);
```

作用：

> 预留容量，尽量减少后续频繁扩容带来的代价。

特点：

- 只改变容量。
- 不改变有效元素个数。
- 不会给新增空间构造实际元素。

如果已经大致知道要放多少数据，提前 `reserve()` 非常有价值。

---

### 5. resize

```cpp
v.resize(10);
v.resize(10, 8);
```

作用：

> 改变有效元素个数。

特点：

- 可能扩容。
- 扩大时会对新增位置进行初始化。
- 缩小时只是减少有效元素个数，通常不缩容量。

例如：

```cpp
vector<int> v{1, 2, 3};
v.resize(5, 8);
```

结果：

```text
1 2 3 8 8
```

---

### 6. reserve 和 resize 的区别

| 对比 | `reserve` | `resize` |
|---|---|---|
| 是否改变 `size` | 否 | 是 |
| 是否改变 `capacity` | 可能 | 可能 |
| 是否初始化新增元素 | 否 | 是 |
| 主要用途 | 提前预留空间 | 改变有效元素个数 |

口诀：

> `reserve` 管容量，`resize` 管元素个数。

---

## 六、vector 的扩容机制

### 1. 扩容不是固定标准的一部分

课件中指出：

- VS 下通常按 **1.5 倍** 扩容。
- g++ / SGI STL 下通常按 **2 倍** 扩容。

结论：

> 不要死记“vector 一定 2 倍扩容”。扩容策略和具体 STL 实现有关。

---

### 2. 为什么要扩容？

`vector` 底层是连续空间。

当 `push_back()` 插入新元素而当前容量不够时，就要：

1. 申请更大的新空间。
2. 把旧元素拷贝到新空间。
3. 释放旧空间。
4. 让底层指针指向新空间。

这个过程是有代价的。

---

### 3. 为什么 reserve 很重要？

如果边插入边扩容：

```cpp
for (int i = 0; i < 100; ++i)
{
    v.push_back(i);
}
```

会发生多次扩容和多次元素搬移。

如果提前预留：

```cpp
v.reserve(100);
```

再插入时就能减少扩容次数，效率更高。

结论：

> 当大概知道数据量时，优先 `reserve()`。

## 七、增删查改接口

常用接口：

| 接口 | 作用 |
|---|---|
| `push_back()` | 尾插 |
| `pop_back()` | 尾删 |
| `find()` | 查找（算法，不是成员函数） |
| `insert()` | 在某位置前插入 |
| `erase()` | 删除某位置元素 |
| `swap()` | 交换两个 `vector` 的数据空间 |
| `operator[]` | 像数组一样访问 |

---

### 1. push_back

```cpp
v.push_back(10);
```

尾部插入元素。

特点：

- 平均效率高。
- 容量不足时可能扩容。

---

### 2. pop_back

```cpp
v.pop_back();
```

删除最后一个元素。

注意：

> 调用前应确保容器非空。

---

### 3. find

`find` 属于算法模块，不是 `vector` 自己的成员函数。

```cpp
auto pos = find(v.begin(), v.end(), 3);
```

如果找到，返回对应迭代器；否则返回 `v.end()`。

---

### 4. insert

```cpp
v.insert(v.begin(), 0);
```

在指定位置前插入元素。

注意：

> 插入可能导致扩容，一旦扩容，所有旧迭代器都可能失效。

---

### 5. erase

```cpp
v.erase(pos);
```

删除 `pos` 位置元素。

返回值：

> 返回被删元素后一个位置的新迭代器。

这点非常重要。

---

### 6. swap

```cpp
v1.swap(v2);
```

作用：

> 交换两个 `vector` 的底层数据空间。

通常效率很高，因为本质主要是交换内部指针和元数据，而不是逐个拷贝元素。

---

### 7. operator[]

```cpp
v[i]
```

像数组一样访问元素。

这是 `vector` 最常用接口之一，OJ 中非常高频。

---

## 八、迭代器失效问题（重点）

这是 `vector` 最重要的底层细节之一。

### 1. 为什么会失效？

`vector` 的迭代器底层通常可以看作原生指针 `T*`。

一旦底层空间发生变化：

- 旧空间被释放。
- 旧迭代器仍指向已释放空间。

这时迭代器就失效了。

本质：

> 迭代器失效 = 它底层指向的空间已经不再是原来那块有效空间。

---

### 2. 哪些操作可能导致扩容，从而让所有迭代器失效？

课件列出的典型操作：

- `resize`
- `reserve`
- `insert`
- `assign`
- `push_back`

只要有可能引起底层空间改变，就可能导致旧迭代器失效。

---

### 3. 扩容后的迭代器为什么不能继续用？

例如：

```cpp
auto it = v.begin();
v.reserve(100);
cout << *it << endl;
```

如果 `reserve(100)` 导致重新开空间，那么：

- `it` 仍指向旧空间。
- 旧空间已经释放。
- 再访问 `*it`，就是非法访问。

VS 下可能直接崩溃；Linux 下有时不崩，但结果错。

结论：

> 不崩溃不代表没问题，只要迭代器失效，结果就不可信。

---

### 4. erase 的失效特点

`erase` 不一定导致底层扩容，但也会导致相关位置迭代器失效。

原因：

- 删除后，后面的元素会整体向前搬移。
- 原来位置的语义已经变了。
- 特别是删最后一个元素时，返回位置会变成 `end()`。

因此：

> `erase(pos)` 之后，`pos` 不能继续使用，应使用返回值。

---

### 5. 错误示例：删偶数

错误写法：

```cpp
auto it = v.begin();
while (it != v.end())
{
    if (*it % 2 == 0)
        v.erase(it);
    ++it;
}
```

问题：

- `erase(it)` 后，`it` 已失效。
- 再执行 `++it` 属于对失效迭代器操作。

---

### 6. 正确写法：接收 erase 返回值

```cpp
auto it = v.begin();
while (it != v.end())
{
    if (*it % 2 == 0)
        it = v.erase(it);
    else
        ++it;
}
```

这是标准写法。

重点原因：

> `erase()` 返回的是删除位置之后的新有效迭代器。

---

### 7. VS 和 Linux 表现差异

课件中强调：

- VS 对迭代器失效检查更严格，很多时候会直接崩溃。
- g++ / Linux 下有时程序还能运行，但结果可能已经错了。

结论：

> 不能因为某段代码“Linux 下能跑”就说明是对的。

---

### 8. string 也有类似问题

`string` 在插入、扩容、`erase` 之后，迭代器同样可能失效。

本质一样：

> 底层连续空间发生变化，旧迭代器就不再可靠。

---

### 9. 解决办法

一句话：

> 在可能导致失效的操作之后，重新获取迭代器。

例如：

```cpp
it = v.begin();
```

或者：

```cpp
it = v.erase(it);
```

## 九、vector 在 OJ 中的高频使用

### 1. 只出现一次的数字 I

题意：除一个数外，其余都出现两次。

核心：按位异或。

```cpp
int singleNumber(vector<int>& nums)
{
    int value = 0;
    for (auto e : nums)
    {
        value ^= e;
    }
    return value;
}
```

复习重点：

- `vector` 作为输入容器。
- 范围 `for` 遍历很方便。
- 这里主要是算法思想，不是 `vector` 接口难点。

---

### 2. 杨辉三角

典型二维 `vector` 题。

```cpp
vector<vector<int>> vv(numRows);
for (int i = 0; i < numRows; ++i)
{
    vv[i].resize(i + 1, 1);
}
for (int i = 2; i < numRows; ++i)
{
    for (int j = 1; j < i; ++j)
    {
        vv[i][j] = vv[i - 1][j] + vv[i - 1][j - 1];
    }
}
```

重点：

- 外层 `vector` 存每一行。
- 每一行又是一个 `vector<int>`。
- `resize(i+1, 1)` 很关键：先把每一行长度准备好，并且头尾默认就是 1。

这题非常适合掌握：

- `vector<vector<int>>`
- `resize`
- 下标访问 `operator[]`

---

### 3. 二维 vector 的理解

```cpp
vector<vector<int>> vv(n);
```

含义：

- `vv` 有 `n` 个元素。
- 每个元素又是一个 `vector<int>`。
- 一开始每一行是空的。

后续可以按需给每一行：

```cpp
vv[i].resize(...);
```

所以二维 `vector` 可以看作：

> 动态二维数组。

但比原始二维数组更灵活，因为每一行长度可以不同。

## 十、vector 模拟实现中的关键问题

### 1. reserve 中不能乱用 memcpy

课件重点指出：

> 如果 `vector` 存的是带资源管理的自定义类型对象，扩容时不能直接用 `memcpy` 进行拷贝。

为什么？

`memcpy` 做的是：

> 原封不动的二进制拷贝。

这对内置类型通常没问题，但对资源管理类会出大问题。

---

### 2. 自定义类型中的浅拷贝问题

例如：

```cpp
bit::vector<bit::string> v;
v.push_back("1111");
v.push_back("2222");
v.push_back("3333");
```

如果扩容时直接 `memcpy`：

- `string` 对象内部指针也被原样复制。
- 多个对象共享同一块字符资源。
- 析构时会多次释放同一块空间。
- 可能崩溃或内存泄漏。

结论：

> 只要对象中涉及资源管理，就不能用 `memcpy` 代替对象拷贝语义。

---

### 3. 正确思想

对于管理资源的对象，扩容搬移时应：

- 调用拷贝构造或赋值语义。
- 保证每个对象对资源管理是独立且正确的。

这和前面 `string` 模拟实现中的深拷贝思想是相通的。

## 十一、易错点汇总

### 易错点 1：混淆 size 和 capacity

- `size`：元素个数。
- `capacity`：容量大小。

---

### 易错点 2：混淆 reserve 和 resize

- `reserve`：只预留容量。
- `resize`：改元素个数，并可能初始化新增元素。

---

### 易错点 3：误以为 vector 总是 2 倍扩容

不是标准固定规则，不同 STL 实现不同。

---

### 易错点 4：erase 后继续用旧迭代器

错误：

```cpp
v.erase(it);
++it;
```

正确：

```cpp
it = v.erase(it);
```

---

### 易错点 5：扩容后继续使用旧迭代器

```cpp
auto it = v.begin();
v.reserve(100);
cout << *it; // 错误
```

扩容后应重新获取迭代器。

---

### 易错点 6：Linux 下没崩溃就以为没问题

迭代器失效后，即使程序还能运行，结果也可能已经错了。

---

### 易错点 7：把 find 当成 vector 成员函数

```cpp
find(v.begin(), v.end(), x)
```

这是算法库函数，不是 `vector` 自己的成员接口。

---

### 易错点 8：模拟 vector 扩容时对资源管理类使用 memcpy

只要元素管理资源，就不能直接二进制拷贝。

## 十三、一页纸记忆版

- **`vector` = 支持动态扩容的顺序表 / 动态数组。**
- **最常用遍历方式：下标、迭代器、范围 `for`。**
- **`size()` 表示元素个数，`capacity()` 表示容量。**
- **`reserve()` 预留容量，不改元素个数。**
- **`resize()` 改元素个数，必要时扩容并初始化。**
- **`push_back()` 尾插，容量不够时可能扩容。**
- **扩容后旧空间释放，旧迭代器全部可能失效。**
- **`erase()` 返回删除位置之后的新迭代器。**
- **删除过程中遍历，标准写法是 `it = v.erase(it)`。**
- **二维 `vector` 本质是“元素是 `vector` 的 `vector`”。**
- **资源管理类不能用 `memcpy` 做扩容拷贝。**
- **扩容策略不是标准固定的，不同 STL 实现可能不同。**
