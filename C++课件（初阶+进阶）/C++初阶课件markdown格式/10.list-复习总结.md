## 一、本讲核心主线

这一讲主要围绕两个层面展开：

1. **会使用 `std::list`**
   - 构造、遍历、容量判断、头尾访问、增删改查。
2. **理解 `list` 的底层行为**
   - 双向循环链表、迭代器本质、删除失效、反向迭代器、与 `vector` 的差异。

一句话概括：

> `list` 本质上是一个带头结点的双向循环链表，擅长任意位置高效插入和删除，但不擅长随机访问。

## 二、list 的定位

### 1. list 是什么？

`list` 是 STL 中的顺序容器之一，但它和 `vector` 的底层完全不同。

可以理解成：

> 基于双向链表封装出来的可动态增长容器。

它的典型特点：

- 任意位置插入、删除效率高。
- 不支持随机访问。
- 适合频繁插入删除的场景。

---

### 2. 学 list 的目标

学习 `list` 也按 STL 的三个层次来：

1. **能用**：会构造、遍历、插入、删除。
2. **明理**：理解链表结构、迭代器失效、与 `vector` 的区别。
3. **能扩展**：能模拟实现简化版 `list` 和反向迭代器。

---

## 三、list 的常见构造

常见构造方式：

| 构造形式 | 含义 |
|---|---|
| `list()` | 空链表 |
| `list(n, val)` | 构造 `n` 个 `val` |
| `list(const list& x)` | 拷贝构造 |
| `list(first, last)` | 用区间 `[first, last)` 构造 |

示例：

```cpp
list<int> l1;
list<int> l2(5, 1);
list<int> l3(l2);
int a[] = {1, 2, 3, 4};
list<int> l4(a, a + 4);
```

复习重点：

- `list<int>(5, 1)` 是 5 个值为 1 的节点。
- 区间构造和 `vector` 类似，但底层插入的是链表节点。

---

## 四、迭代器与遍历

### 1. begin 和 end

```cpp
for (auto it = l.begin(); it != l.end(); ++it)
{
    cout << *it << " ";
}
```

含义：

- `begin()`：第一个有效节点位置。
- `end()`：最后一个有效节点的下一个逻辑位置。

注意：

> 对 `end()` 不能解引用。

---

### 2. rbegin 和 rend

```cpp
for (auto rit = l.rbegin(); rit != l.rend(); ++rit)
{
    cout << *rit << " ";
}
```

含义：

- `rbegin()`：反向遍历起点，对应最后一个元素。
- `rend()`：反向遍历终点，对应第一个元素之前。

注意：

> 正向迭代器执行 `++` 是向后走；反向迭代器执行 `++` 是向前走。

---

### 3. list 的迭代器先暂时怎么理解？

课件里给出的当前阶段理解方式是：

> 先把 `list` 的迭代器理解成一个“指向节点的指针”或者“对节点指针的封装”。

这比 `vector` 的原生指针迭代器要更抽象一些。

原因：

- `vector` 底层是连续空间，迭代器很像原生指针。
- `list` 底层是链表节点，迭代器本质上是对节点指针的封装。

---

## 五、容量与访问接口

### 1. empty

```cpp
if (l.empty())
{
}
```

判断链表是否为空。

---

### 2. size

```cpp
cout << l.size();
```

返回有效节点个数。

当前阶段直接按接口理解即可，不需要纠结不同实现里 `size()` 是否一定为 O(1)。

---

### 3. front

```cpp
cout << l.front();
```

返回第一个节点中值的引用。

可读可写：

```cpp
l.front() = 100;
```

前提：链表不能为空。

---

### 4. back

```cpp
cout << l.back();
```

返回最后一个节点中值的引用。

同样要求链表不能为空。

---

## 六、修改操作接口

常用修改接口：

| 接口 | 作用 |
|---|---|
| `push_front` | 头插 |
| `pop_front` | 头删 |
| `push_back` | 尾插 |
| `pop_back` | 尾删 |
| `insert` | 在某位置前插入 |
| `erase` | 删除某位置节点 |
| `swap` | 交换两个 list |
| `clear` | 清空有效节点 |

---

### 1. push_front / pop_front

```cpp
l.push_front(10);
l.pop_front();
```

- `push_front`：在第一个节点前插入新节点。
- `pop_front`：删除第一个节点。

这类操作是 `list` 的优势场景之一。

---

### 2. push_back / pop_back

```cpp
l.push_back(20);
l.pop_back();
```

- `push_back`：尾插。
- `pop_back`：尾删。

---

### 3. insert

```cpp
auto pos = l.begin();
l.insert(pos, 100);
```

表示在 `pos` 所指节点之前插入新节点。

由于 `list` 是链表：

> 插入不需要搬移大量元素，只需要调整相关节点指针。

---

### 4. erase

```cpp
auto pos = l.begin();
pos = l.erase(pos);
```

作用：

> 删除 `pos` 所指节点，并返回它后一个位置的新迭代器。

这是本节最重要的细节之一。

---

### 5. swap

```cpp
l1.swap(l2);
```

交换两个链表的数据结构。

通常效率很高，因为本质不是逐节点拷贝，而是交换内部结构。

---

### 6. clear

```cpp
l.clear();
```

清空所有有效节点。

注意：

> 清空后，链表变为空，但容器对象本身仍然存在。

---

## 七、list 的迭代器失效（重点）

### 1. 什么叫失效？

迭代器失效就是：

> 迭代器所指向的节点已经无效了，继续使用它会出错。

对于 `list` 来说：

- 插入节点时，一般不会导致其他迭代器失效。
- 删除节点时，**指向被删除节点的迭代器失效**。

---

### 2. 为什么 list 插入通常不导致迭代器失效？

因为 `list` 底层是双向链表。

插入新节点时：

- 只是新建一个节点。
- 修改前后节点指针链接。
- 其他节点的位置并没有整体搬移。

所以：

> 插入不会像 `vector` 那样因为扩容而导致整片空间变化。

这就是 `list` 和 `vector` 很大的不同。

---

### 3. 为什么删除会导致当前迭代器失效？

例如：

```cpp
auto it = l.begin();
l.erase(it);
++it; // 错误
```

原因：

- `erase(it)` 后，`it` 指向的节点已经被删除。
- 此时 `it` 再也不是合法节点位置。
- 再执行 `++it`，就属于对失效迭代器操作。

---

### 4. 错误示例

```cpp
auto it = l.begin();
while (it != l.end())
{
    l.erase(it);
    ++it;
}
```

问题：

- `erase(it)` 执行后，`it` 立即失效。
- 下一句 `++it` 是错误操作。

---

### 5. 正确写法

课件给出两种等价思路：

#### 写法一：接收返回值

```cpp
auto it = l.begin();
while (it != l.end())
{
    it = l.erase(it);
}
```

#### 写法二：利用后置 `++`

```cpp
auto it = l.begin();
while (it != l.end())
{
    l.erase(it++);
}
```

不过从可读性和通用性上，推荐更清晰地记住：

> `it = erase(it)`

---

### 6. list 和 vector 在失效机制上的本质差异

| 容器 | 插入失效 | 删除失效 |
|---|---|---|
| `vector` | 可能扩容，所有旧迭代器都可能失效 | 当前迭代器失效，扩容或搬移也可能影响其他 |
| `list` | 一般不会导致其他迭代器失效 | 只有指向被删节点的迭代器失效 |

这就是为什么：

> 大量中间插入删除时，`list` 在“稳定性”上优于 `vector`。

---

## 八、list 的底层结构

课件给出的底层结构结论：

> `list` 底层是 **带头结点的双向循环链表**。

这个结论很关键。

它意味着：

1. 每个节点通常有：
   - 数据域
   - 前驱指针
   - 后继指针
2. 头结点不存放业务数据，主要用于统一边界处理。
3. 循环结构使首尾处理更统一。

这也是 `push_front / push_back / insert / erase` 能高效实现的重要基础。

## 九、模拟实现 list 的重点

### 1. 要模拟实现什么？

课件要求模拟实现 `list`，本质上要你掌握：

- 节点结构
- 链表的连接与断开
- 迭代器设计
- 插入和删除接口
- 反向迭代器的封装思想

---

### 2. list 迭代器为什么不是原生指针？

因为节点不是一块连续数组空间。

对于 `vector`：

```text
底层连续空间 → 迭代器像 T*
```

对于 `list`：

```text
底层链式节点 → 迭代器需要封装节点指针行为
```

所以 `list` 迭代器通常要自己定义类，支持：

- `*it`
- `it->`
- `++it`
- `--it`
- `it != other`

---

## 十、反向迭代器

### 1. 核心思想

课件的重点思想是：

> 反向迭代器可以借助正向迭代器实现。

本质：

- 反向迭代器内部保存一个正向迭代器。
- 反向的 `++`，对应正向的 `--`。
- 反向的 `--`，对应正向的 `++`。

---

### 2. operator* 的关键

反向迭代器内部如果保存的是“当前正向迭代器位置”，那么：

```cpp
Ref operator*()
{
    Iterator temp(_it);
    --temp;
    return *temp;
}
```

为什么要 `--temp`？

因为：

- 反向迭代器的逻辑当前位置
- 对应的是正向迭代器前一个节点的数据

这和 `reverse_iterator` 的经典实现思路一致。

---

### 3. typename 的作用

课件里这个点也很重要：

```cpp
typedef typename Iterator::Ref Ref;
typedef typename Iterator::Ptr Ptr;
```

这里 `typename` 的作用是：

> 明确告诉编译器，`Iterator::Ref` 和 `Iterator::Ptr` 是类型，不是静态成员变量。

这是模板里非常常见的写法。

---

## 十一、list 与 vector 的对比（高频）

这部分非常重要，经常考。

| 维度 | `vector` | `list` |
|---|---|---|
| 底层结构 | 动态顺序表，连续空间 | 带头结点的双向循环链表 |
| 随机访问 | 支持，`O(1)` | 不支持，`O(N)` |
| 任意位置插入删除 | 效率低，通常 `O(N)`，可能扩容 | 效率高，通常 `O(1)` |
| 空间利用率 | 连续空间，缓存命中高，不易碎片 | 节点离散，易碎片，缓存命中差 |
| 迭代器本质 | 原生指针或类似原生指针 | 对节点指针的封装 |
| 插入后的迭代器稳定性 | 扩容后可能全部失效 | 插入一般不导致其他迭代器失效 |
| 删除后的迭代器稳定性 | 当前位置失效，其他可能受搬移影响 | 仅当前被删节点迭代器失效 |
| 适用场景 | 高效存储、随机访问、尾插较多 | 大量中间插入删除、不关心随机访问 |

---

## 十二、什么时候用 vector，什么时候用 list？

### 适合 vector 的场景

- 需要随机访问。
- 更关注读取和遍历效率。
- 主要在尾部插入删除。
- 希望缓存命中率高。

### 适合 list 的场景

- 大量中间插入删除。
- 不关心随机访问。
- 更关心迭代器在插入时的稳定性。

一句话判断：

> 要像数组一样访问，用 `vector`；要像链表一样频繁插删，用 `list`。

## 十三、易错点汇总

### 易错点 1：把 list 当成支持随机访问的容器

错误想法：

```cpp
l[i]
```

`list` 不支持 `operator[]`，因为底层不是连续空间。

---

### 易错点 2：erase 后继续用旧迭代器

错误：

```cpp
l.erase(it);
++it;
```

正确：

```cpp
it = l.erase(it);
```

---

### 易错点 3：认为 list 插入也会导致大量迭代器失效

不会像 `vector` 那样整体失效。

`list` 插入通常不会让其他迭代器失效。

---

### 易错点 4：认为 list 插入删除一定整体更快

要看场景。

- 插入删除：`list` 更有优势。
- 随机访问、缓存局部性、遍历速度：`vector` 常常更强。

所以不是“list 全面优于 vector”。

---

### 易错点 5：误以为反向迭代器的 `++` 还是向后走

在反向迭代器里：

- `++` 逻辑上是向前遍历原容器。
- 本质对应正向迭代器的 `--`。

---

### 易错点 6：模板里忘记 `typename`

例如：

```cpp
Iterator::Ref
```

如果这是依赖于模板参数的嵌套类型，通常需要写：

```cpp
typename Iterator::Ref
```

## 十五、一页纸记忆版

- **`list` 底层是带头结点的双向循环链表。**
- **`list` 不支持随机访问，访问第 i 个元素通常要顺着链走。**
- **`list` 擅长任意位置插入和删除。**
- **`begin/end` 是正向迭代器，`rbegin/rend` 是反向迭代器。**
- **`front/back` 返回首尾节点值的引用。**
- **插入通常不会导致其他迭代器失效。**
- **删除只会让被删节点对应迭代器失效。**
- **删除遍历时标准写法：`it = erase(it)`。**
- **`list` 迭代器是对节点指针的封装，不是原生数组指针。**
- **反向迭代器的 `++` 对应正向迭代器的 `--`。**
- **`vector` 适合随机访问；`list` 适合频繁插删。**

```text
反向迭代器内部保存正向迭代器
反向++ -> 正向--

```

这部分不只是 `list` 知识，也和模板、迭代器设计思想有关。
