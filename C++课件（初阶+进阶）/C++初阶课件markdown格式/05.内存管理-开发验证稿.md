# C/C++ 内存管理复习总结

> 来源：`05.内存管理.pdf`
> 定位：已学过一遍后的复习稿，重点用于快速回忆内存区域、动态内存管理、`new/delete`、`operator new/delete` 与 `placement new` 的核心区别。

## 一、本讲内容总览

- 这讲主要回答三个问题：
  1. C/C++ 程序里的不同对象通常位于哪类内存区域？
  2. C 语言和 C++ 分别如何申请、扩容、释放动态内存？
  3. `malloc/free`、`new/delete`、`operator new/delete`、`placement new` 的关系到底是什么？
- 本讲最核心的主线是：
  - **`malloc/free` 解决的是“原始空间”的申请与释放；`new/delete` 解决的是“对象”的构造、析构与空间管理。**
- 学完后至少要能判断：
  - 一个变量本身在哪里、它指向的内容又在哪里；
  - 为什么自定义类型通常优先用 `new/delete`；
  - `placement new` 为什么“只构造，不分配空间”。

## 二、核心知识结构

### 1. 内存区域判断
- 自动对象、静态存储期对象、动态分配对象分别处在不同区域。
- 要区分“指针变量本身在哪里”和“指针指向的内容在哪里”。

### 2. C 语言动态内存管理
- `malloc`：申请原始字节空间，不初始化。
- `calloc`：申请空间并清零。
- `realloc`：调整空间大小，地址可能变化。
- `free`：释放堆空间，不会调用析构函数。

### 3. C++ 动态内存管理
- `new / delete`
- `new[] / delete[]`
- 对自定义类型会自动参与构造和析构。

### 4. 底层分配接口
- `operator new / operator delete`
- 语法层面的 `new/delete` 会使用这些底层分配/释放接口。

### 5. 特殊形式：`placement new`
- 在已经准备好的原始内存上显式构造对象。
- 常与内存池、自定义对象生命周期控制一起出现。

## 三、核心知识讲解

### 1. C/C++ 常见内存区域

教学口径下，常把程序中的主要区域分为：

| 区域 | 典型内容 |
|---|---|
| 栈 | 局部变量、函数参数、局部数组等自动对象 |
| 堆 | 运行时动态申请的空间 |
| 数据段 / 静态区 | 全局变量、静态变量 |
| 代码段 / 常量区 | 可执行代码、字符串常量、只读常量等 |
| 内存映射段 | 动态库、共享内存等，了解即可 |

注意：这里是课程复习常用的教学划分；更细的段划分和具体落点会受平台、编译器和链接方式影响。

### 2. 典型变量位置判断：重点是“变量本身”和“指向内容”分开看

核心示例：

```cpp
int globalVar = 1;
static int staticGlobalVar = 1;

void Test()
{
    static int staticVar = 1;
    int localVar = 1;
    int num1[10] = {1, 2, 3, 4};
    char char2[] = "abcd";
    const char* pChar3 = "abcd";
    int* ptr1 = (int*)malloc(sizeof(int) * 4);
}
```

关键判断：

| 名称 | 所在区域 | 原因 |
|---|---|---|
| `globalVar` | 数据段 / 静态区 | 全局变量 |
| `staticGlobalVar` | 数据段 / 静态区 | 静态全局变量 |
| `staticVar` | 数据段 / 静态区 | 静态局部变量 |
| `localVar` | 栈 | 普通局部变量 |
| `num1` | 栈 | 局部数组对象本身在栈上 |
| `char2` | 栈 | 局部字符数组本身在栈上 |
| `pChar3` | 栈 | 指针变量本身是局部变量 |
| `*pChar3` 指向的字符串字面量 | 常量区 / 只读区 | 字符串字面量通常不在栈上 |
| `ptr1` | 栈 | 指针变量本身在栈上 |
| `*ptr1` 指向的动态空间 | 堆 | `malloc` 申请的空间 |

最容易错的点：

```cpp
char char2[] = "abcd";
const char* pChar3 = "abcd";
```

- `char2` 是一个局部数组，数组对象本身在栈上；
- `pChar3` 是一个局部指针，指针本身在栈上，但它指向的字符串字面量通常位于只读区域。

### 3. C 语言动态内存管理：本质是“原始空间管理”

#### `malloc`

```cpp
int* p = (int*)malloc(sizeof(int) * 4);
```

要点：

- 按字节数申请空间；
- 不负责对象语义；
- 不初始化申请到的内容；
- 失败时返回空指针。

#### `calloc`

```cpp
int* p = (int*)calloc(4, sizeof(int));
```

要点：

- 申请 `4` 个 `int` 大小的空间；
- 会把这块空间按字节清零。

#### `realloc`

```cpp
int* p2 = (int*)realloc(p1, sizeof(int) * 10);
```

要点：

- 用于扩容或缩容；
- 可能原地调整，也可能搬迁到新地址；
- **成功后应以返回值为准继续使用。**

因此像下面这样理解更安全：

```cpp
int* p3 = (int*)realloc(p2, sizeof(int) * 10);
free(p3);
```

如果 `realloc` 已成功返回新的有效指针，就不应再按旧地址重复释放。

#### `free`

```cpp
free(p);
```

要点：

- 只释放堆上的原始空间；
- 不会调用构造函数或析构函数；
- 适合与 `malloc/calloc/realloc` 配对。

### 4. C++ 动态内存管理：`new/delete`

#### 操作内置类型

```cpp
int* p1 = new int;
int* p2 = new int(10);
int* p3 = new int[3];

delete p1;
delete p2;
delete[] p3;
```

要点：

- `new` / `delete` 配对；
- `new[]` / `delete[]` 配对；
- 对内置类型来说，和 `malloc/free` 的差距主要体现在：
  - 写法更自然；
  - 能直接初始化；
  - 失败时通常以异常而不是空指针的方式报告。

#### 操作自定义类型

```cpp
class A
{
public:
    A() { cout << "A()" << endl; }
    ~A() { cout << "~A()" << endl; }
};

A* p = new A;
delete p;
```

这里的关键区别不是“语法长得不一样”，而是：

- `new A`：申请原始空间，再在这块空间上构造对象；
- `delete p`：先析构对象，再释放空间。

而下面这组写法：

```cpp
A* p = (A*)malloc(sizeof(A));
free(p);
```

只是拿到和释放了一段原始内存，并没有自动完成对象构造与析构。

### 5. `operator new / operator delete`：底层分配接口，不等于语法层面的 `new/delete`

重点区分：

| 名称 | 本质 |
|---|---|
| `new` | 语言层面的操作符表达式 |
| `delete` | 语言层面的操作符表达式 |
| `operator new` | 用于分配原始内存的函数接口 |
| `operator delete` | 用于释放原始内存的函数接口 |

可以先用课程复习口径记成：

```text
new
  ≈ 分配原始内存 + 构造对象

delete
  ≈ 析构对象 + 释放原始内存
```

而在默认实现里，`operator new` 常常最终会基于底层堆分配函数工作，`operator delete` 常常最终会基于底层堆释放函数工作。但这里应理解为：

- **`new/delete` 是语言层面的完整对象操作；**
- **`operator new/delete` 更接近底层原始内存分配接口。**

### 6. `new/delete` 的工作过程：对象视角比 API 名字更重要

对自定义类型，可先用下面的简化流程理解：

#### `new T(args...)`

1. 获取一块足够大的原始内存；
2. 在这块内存上调用构造函数；
3. 返回类型正确的指针。

#### `delete p`

1. 调用析构函数；
2. 释放对象占用的原始内存。

#### `new T[N]`

- 为多个对象准备连续空间；
- 逐个构造数组元素。

#### `delete[] p`

- 逐个析构数组元素；
- 释放整块空间。

这里要避免一个误区：

> `new[]/delete[]` 不是“多了个方括号而已”，它们和对象个数管理、逐个构造/析构直接相关。

### 7. `placement new`：只构造，不负责申请空间

格式：

```cpp
new(place_address) Type;
new(place_address) Type(args...);
```

最小示例：

```cpp
A* p = (A*)malloc(sizeof(A));
new(p) A(10);
p->~A();
free(p);
```

这段代码说明：

1. `malloc` 只负责给你一块原始空间；
2. `new(p) A(10)` 在这块已有空间上显式构造对象；
3. 这时对象的析构也需要你显式管理；
4. 最后还要自己释放这块原始空间。

因此，`placement new` 的本质是：

> **在指定地址上调用构造函数，而不是申请空间。**

### 8. `malloc/free` 与 `new/delete` 的真正区别

| 对比项 | `malloc/free` | `new/delete` |
|---|---|---|
| 关注对象 | 原始空间 | 对象 + 空间 |
| 申请单位 | 手动计算字节数 | 由类型决定 |
| 返回值 | `void*`（C++ 中通常需显式转换） | 对应类型指针 |
| 初始化 | `malloc` 不初始化，`calloc` 清零 | `new` 可直接初始化 |
| 失败处理 | 返回空指针 | 常见实现下抛异常 |
| 自定义类型 | 不自动构造 / 析构 | 自动参与构造 / 析构 |
| 数组 | 手动算总字节数 | `new[] / delete[]` |

真正最值得记住的一句是：

> **对自定义类型，`malloc/free` 管的是“空间”；`new/delete` 管的是“对象生命周期 + 空间”。**

## 四、关键代码与案例

### 1. 变量位置判断案例

这段代码主要用于训练“对象本身”和“对象指向内容”分开判断：

```cpp
char char2[] = "abcd";
const char* pChar3 = "abcd";
int* ptr1 = (int*)malloc(sizeof(int) * 4);
```

要点：

- `char2` 是数组对象本身；
- `pChar3` 是指针变量本身；
- `pChar3` 指向的字符串字面量与 `pChar3` 自己不在同一区域；
- `ptr1` 在栈上，但 `ptr1` 指向的动态空间在堆上。

### 2. 自定义类型下 `malloc/free` 与 `new/delete` 的差异

```cpp
A* p1 = (A*)malloc(sizeof(A));
A* p2 = new A(1);
free(p1);
delete p2;
```

这段代码主要说明：

- `malloc/free` 不会自动构造和析构对象；
- `new/delete` 会把对象生命周期纳入操作。

### 3. `placement new` 案例

```cpp
A* p = (A*)malloc(sizeof(A));
new(p) A(10);
p->~A();
free(p);
```

要点：

- 先有原始空间；
- 再显式构造；
- 析构和释放都要手动做完；
- 非常适合帮助理解“空间”和“对象”是两层概念。

## 五、易混概念与易错点

### 易混概念

| 概念 A | 概念 B | 关键区别 |
|---|---|---|
| 指针变量本身 | 指针指向的内容 | 变量自身的位置由定义方式决定，所指内容的位置由地址来源决定 |
| `new/delete` | `operator new/delete` | 前者是语言层面的对象操作，后者是底层原始内存分配/释放接口 |
| 普通 `new` | `placement new` | 前者会参与空间获取，后者只在指定地址上构造对象 |
| `malloc/free` | `new/delete` | 前者偏原始空间管理，后者偏对象生命周期管理 |

### 易错点

1. 看到 `char[]` 和 `const char*` 指向同样的字符串，就误以为它们的内容一定在同一块区域。
2. 只看 `ptr` 的类型，不分清“指针变量本身”和“指针所指对象”的位置。
3. 把 `new/delete` 仅理解成“更好用的 malloc/free”，忽略了构造与析构。
4. `new[]` 与 `delete[]` 配错。
5. 认为 `placement new` 会顺便申请空间。
6. 认为 `operator new` 就等于 `new` 本身。
7. `realloc` 成功后仍继续拿旧指针当最终有效地址使用。

## 七、核心总结

- **先分清“对象本身在哪里”和“对象指向的内容在哪里”。**
- **栈主要放自动对象，堆主要放动态申请的空间，静态存储期对象通常在数据段 / 静态区。**
- **`malloc/calloc/realloc/free` 解决的是原始堆空间的申请、调整与释放。**
- **`new/delete` 处理的不只是空间，还有对象构造与析构。**
- **`new[]/delete[]` 用于对象数组，不能和单对象形式混用。**
- **`operator new/delete` 是底层分配接口，不等于语法层面的 `new/delete`。**
- **`placement new` 的关键不是“申请空间”，而是“在指定地址上构造对象”。**
- **对自定义类型，真正要记的是“对象生命周期”和“原始空间管理”是两层事情。**
