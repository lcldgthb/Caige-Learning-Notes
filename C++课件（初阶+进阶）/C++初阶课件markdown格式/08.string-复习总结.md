> 来源：`08.string.pdf`
> 定位：已学一遍后的重点复习笔记，用于快速回忆 `string` 的常用接口、典型题型、实现主线与易错点。

---

## 一、本讲核心主线

这节课不要拆成一堆零碎接口去背，而要按下面 **3 条主线** 来复习：

1. **为什么 C++ 里要用 `string`**
   - C 风格字符串不好管空间、容易越界、字符串和操作函数分离。
   - `string` 把“数据 + 操作”封装到类里，更符合 OOP，也更适合 OJ 和开发。

2. **怎么高频使用标准库 `string`**
   - 构造、容量、访问、遍历、追加、查找、截取、输入输出。
   - 这部分决定你能不能顺手写字符串题。

3. **`string` 底层资源是怎么管的**
   - 为什么浅拷贝会出问题。
   - 为什么资源类需要深拷贝。
   - 传统写法、现代写法、写时拷贝分别在解决什么问题。

一句话概括：

> **使用层重点是“会调接口、会做题”，实现层重点是“会处理资源、会拷贝控制”。**

---

## 二、为什么学 / 这一讲解决什么问题

### 1. C 语言字符串的问题

C 风格字符串本质是：

> **以 `\0` 结尾的一组字符。**

常用库函数有：

```cpp
strlen
strcpy
strcat
strcmp
strstr
```

但它有几个明显问题：

- 字符串本身和操作它的函数是分离的。
- 底层空间需要程序员自己申请、释放、扩容。
- 越界、漏掉 `\0`、容量不够等问题很常见。
- 拼接、插入、修改不够直观。

### 2. `string` 的价值

`string` 的优势就是把这些事统一收进类里：

- 自动管理字符空间
- 提供丰富接口
- 支持拷贝、比较、查找、追加
- 和迭代器、范围 `for`、算法配合自然
- OJ、竞赛、日常开发都高频使用

这节课真正解决的是：

> **把“只会写 C 风格字符串”升级为“能熟练用 `string`，并理解它为什么这么设计”。**

## 三、核心内容展开

### 3.1 `auto` 和范围 `for`：给 `string` 使用做铺垫

这部分不是本课主角，但它和 `string`、容器遍历经常绑在一起考。

#### 1）`auto` 的核心作用

`auto` 的作用是：

> **让编译器根据初始化表达式推导变量类型。**

例如：

```cpp
int a = 10;
auto b = a;    // int
auto c = 'a';  // char
auto d = 3.14; // double
```

#### 2）`auto` 的高频规则

必须记住：

- `auto` **必须有初始化值**。
- 一条语句里多个 `auto` 变量，推导出的类型必须一致。
- 推导引用时必须显式写 `&`。
- 推导指针时，`auto` 和 `auto*` 都行。
- 本课阶段把它理解成：**简化类型书写，不是动态类型。**

例如：

```cpp
int x = 10;
auto y = &x;  // int*
auto* z = &x; // int*
auto& m = x;  // int&
```

#### 3）`auto` 的典型价值

最常见场景是：

- 迭代器类型很长
- 模板类型很长
- 右侧表达式已经很清楚地表明类型

例如：

```cpp
std::map<std::string, std::string>::iterator it1 = dict.begin();
auto it2 = dict.begin();
```

#### 4）范围 `for`

基本格式：

```cpp
for (元素变量 : 可迭代对象)
{
}
```

可用于：

- 数组
- `string`
- STL 容器

例如：

```cpp
for (auto ch : str)
{
    cout << ch << " ";
}
```

#### 5）值遍历和引用遍历的区别

只读：

```cpp
for (auto ch : str)
```

可修改原字符串：

```cpp
for (auto& ch : str)
```

这是一个高频坑：

> **想改原字符串，一定要写引用。**

### 3.2 `string` 的常见构造

课件重点列了以下构造方式：

| 构造方式 | 含义 | 复习重点 |
|---|---|---|
| `string()` | 空字符串 | 高频 |
| `string(const char* s)` | 用 C 字符串构造 | 高频 |
| `string(size_t n, char c)` | 构造 n 个字符 c | 了解 |
| `string(const string& s)` | 拷贝构造 | 高频 |

典型例子：

```cpp
string s1;
string s2("hello bit");
string s3(s2);
```

二刷时要抓住：

- `string` 可以直接吃 C 字符串。
- `string` 也有拷贝构造，本质上仍然是类对象。
- 以后你手写 `String` 类时，也要支持这些基本构造行为。

### 3.3 容量相关接口：这一组最容易混

课件列出的容量相关重点接口：

| 接口 | 作用 |
|---|---|
| `size()` | 返回有效字符个数 |
| `length()` | 返回有效字符个数 |
| `capacity()` | 返回当前容量 |
| `empty()` | 判断是否为空 |
| `clear()` | 清空有效字符 |
| `reserve(n)` | 预留底层空间 |
| `resize(n)` | 修改有效字符个数 |
| `resize(n, c)` | 扩展部分用字符 `c` 填充 |

#### 1）`size()` 和 `length()`

这两个接口在 `string` 中意义基本相同。

但建议优先记：

```cpp
size()
```

因为它和其他 STL 容器更统一。

#### 2）`empty()`

判断是否为空串，语义最直接：

```cpp
if (s.empty())
{
}
```

#### 3）`clear()`

`clear()` 的本质是：

- 清掉**有效字符**
- 不要把它简单理解成“彻底回收底层空间”

本课阶段记成：

> **逻辑清空，不重点强调缩容。**

#### 4）`resize()`

`resize()` 调的是：

> **字符串里“有效字符的个数”**

两种情况：

- 缩小：截断
- 变大：新增字符，默认补 `\0` 风格的字符位，或按给定字符填充

例如：

```cpp
string s = "abcdef";
s.resize(3);      // "abc"
s.resize(6, 'x'); // "abcxxx"
```

#### 5）`reserve()`

`reserve()` 调的是：

> **预留底层空间**

特点：

- 不直接改变有效字符个数
- 常用于大量追加前先扩容，减少重复扩容开销

例如：

```cpp
string ret;
ret.reserve(100);
```

#### 6）最重要的一句区分

> **`resize` 管“内容长度”，`reserve` 管“预留空间”。**

这句一定要背熟。

### 3.4 访问与遍历

课件给出的访问 / 遍历方式主要有：

| 方式 | 作用 |
|---|---|
| `operator[]` | 下标访问字符 |
| `begin()` / `end()` | 正向迭代器遍历 |
| `rbegin()` / `rend()` | 反向迭代器遍历 |
| 范围 `for` | 简洁遍历 |

#### 1）`operator[]`

最常用、最直接：

```cpp
s[i]
```

适用于：

- 读字符
- 改字符
- 双指针题
- 模拟题

#### 2）正向迭代器

```cpp
for (auto it = s.begin(); it != s.end(); ++it)
{
    cout << *it;
}
```

关键点：

- `begin()` 指向首字符
- `end()` 指向尾字符后一个位置

#### 3）反向迭代器

```cpp
for (auto rit = s.rbegin(); rit != s.rend(); ++rit)
{
    cout << *rit;
}
```

适用于倒序遍历。

#### 4）范围 `for`

```cpp
for (auto ch : str)
{
    cout << ch << ' ';
}
```

需要修改原字符串时：

```cpp
for (auto& ch : str)
{
    ch = toupper(ch);
}
```

### 3.5 修改与查找：高频做题接口区

课件列出的重点接口：

| 接口 | 作用 | 高频程度 |
|---|---|---|
| `push_back` | 尾插一个字符 | 高频 |
| `append` | 追加字符串 | 高频 |
| `operator+=` | 追加字符 / 字符串 | 高频 |
| `c_str()` | 转 C 风格字符串 | 高频 |
| `find` + `npos` | 从前往后找 | 高频 |
| `rfind` | 从后往前找 | 高频 |
| `substr` | 截子串 | 高频 |

#### 1）尾插与追加

三种常用方式：

```cpp
s.push_back('c');
s.append("abc");
s += 'x';
s += "hello";
```

复习结论：

- `push_back`：加单个字符
- `append`：加字符串
- `+=`：最顺手，字符和字符串都能加

#### 2）`c_str()`

作用：

> **把 `string` 转成 C 风格字符串。**

适用于：

- 调老的 C 接口
- 需要 `const char*` 的场景

#### 3）`find()` 与 `string::npos`

`find()` 是字符串题里的超级高频接口。

例如：

```cpp
size_t pos = s.find('a');
if (pos != string::npos)
{
}
```

二刷重点：

- 找到：返回位置
- 找不到：返回 `string::npos`

不要偷懒写成“记成 -1 就完事”，正式写法要会。

#### 4）`rfind()`

`rfind()` 是从后往前找。

典型应用：

- 找最后一个空格
- 找最后一个分隔符
- 找最后一个某字符

#### 5）`substr()`

```cpp
string sub = s.substr(pos, n);
```

作用：

- 从 `pos` 开始
- 截取 `n` 个字符
- 返回新字符串

适合：

- 截单词
- 截路径
- 截文件名
- 截字段

### 3.6 非成员相关接口与输入输出

课件点到的重点有：

| 接口 / 运算符 | 作用 | 复习建议 |
|---|---|---|
| `operator+` | 拼接 | 尽量少用 |
| `operator>>` | 输入单词 | 高频 |
| `operator<<` | 输出 | 高频 |
| `getline` | 读整行 | 高频 |
| 关系运算符 | 比较大小 / 相等 | 高频 |

#### 1）为什么 `operator+` 尽量少用

课件给出的结论是：

> **尽量少用 `operator+`，因为它常伴随传值返回，效率相对低。**

基础阶段先直接记：

- 高频拼接优先 `+=`
- `append()` 也很常用

#### 2）`cin >> s` 和 `getline()`

这是做题高频坑点：

- `cin >> s`：遇空格 / 换行就停
- `getline(cin, s)`：读取整行，包括中间空格

所以像“最后一个单词长度”这种题，往往应优先考虑：

```cpp
getline(cin, line)
```

#### 3）关系运算符

`string` 支持：

- `==`
- `!=`
- `<`
- `>`
- `<=`
- `>=`

比较本质上是字典序比较。

### 3.7 典型字符串题：要学的是套路，不是题目本身

课件给了几个代表题，二刷时要把它们提炼成方法。

#### 1）仅反转字母

核心套路：

- 双指针
- 左右各走
- 不是字母就跳过
- 是字母才交换

对应能力：

- `s[i]`
- `size()`
- `swap`
- 双指针

#### 2）找第一个只出现一次的字符

核心套路：

- 先统计字符出现次数
- 再按原顺序扫一遍找第一个次数为 1 的字符

对应能力：

- 下标访问
- 遍历字符串
- 计数数组 / 哈希思想

#### 3）最后一个单词长度

核心套路：

- `getline` 读整行
- `rfind(' ')` 找最后一个空格
- 用总长度减位置算答案

#### 4）验证回文串

核心套路：

- 忽略非字母数字
- 双指针
- 统一大小写后比较

#### 5）字符串相加

核心套路：

- 从后往前模拟竖式加法
- 维护进位
- 结果往往先反着存，最后 `reverse`

这类题训练的是：

- 字符转数字
- 尾插 / 反转
- 遍历和边界处理

### 3.8 VS 与 g++ 下 `string` 结构：知道差异，不死背细节

课件提到了不同实现下 `string` 的结构差异。

#### 1）VS 下的思路

课件展示的是典型的短字符串优化思路：

- 字符串短时，可能放在对象内部的小缓冲区里
- 字符串长时，再去堆上开空间

这类思路的价值是：

- 小字符串不用频繁堆分配
- 效率更高

#### 2）g++ 下的结构说明

课件还展示了 g++ 下某类 `string` 结构信息，例如：

- 有效长度
- 容量
- 指向字符存储区的指针
- 某些实现里还可能有引用计数相关字段

#### 3）这部分怎么记

不要死背平台细节，正确复习结论是：

> **不同实现细节可能不同，但 `string` 本质一定是在管理字符资源，并维护长度、容量等元信息。**

### 3.9 `string` 的模拟实现：最能拉开差距的一部分

这是这节课最值得反复看的地方。

#### 1）经典错误：只写构造和析构

如果一个 `String` 类：

- 写了构造函数
- 写了析构函数
- **没写拷贝构造和赋值运算符重载**

那么一旦发生：

```cpp
String s2(s1);
```

编译器默认生成的拷贝构造就会做浅拷贝。

结果：

- `s1` 和 `s2` 指向同一块字符空间
- 析构时会重复释放
- 程序崩溃

#### 2）浅拷贝的本质

> **只拷贝地址，不拷贝地址背后的资源。**

这对值类型可能没问题，对资源类就是灾难。

#### 3）深拷贝的本质

> **给每个对象都分配一份独立资源，并把内容复制过去。**

对 `String` 来说，就是：

- 重新 `new` 一块字符空间
- 把原字符串拷贝进去
- 保证对象之间不共享底层字符资源

#### 4）传统写法的三件套

资源类通常要配齐：

- 构造函数
- 拷贝构造
- 赋值运算符重载
- 析构函数

其中赋值重载的关键点是：

- 处理自赋值
- 先拿到新资源
- 再释放旧资源
- 返回 `*this`

#### 5）现代写法：交换思想

课件后面给了更现代的写法，核心是：

- 先构造一个安全副本
- 再 `swap`
- 旧资源交给临时对象析构时释放

优点：

- 代码更简洁
- 逻辑更清楚
- 异常安全性更好

#### 6）写时拷贝（了解）

课件最后还带到了写时拷贝（COW）的思路。

当前阶段记住：

- 它是在共享资源基础上引入引用计数
- 只有真正写入时才分离资源
- 知道思想即可，不要求当前阶段自己完整实现标准库版本

## 四、易错点汇总

### 1. 把 `size()` 和 `capacity()` 混淆

- `size()`：有效字符个数
- `capacity()`：底层容量

### 2. 把 `resize()` 和 `reserve()` 混淆

- `resize()`：改内容长度
- `reserve()`：改预留空间

### 3. 误以为 `clear()` 等于“彻底释放空间”

本课阶段应理解为清空有效字符，而不是强制缩容。

### 4. 修改字符串元素时，范围 `for` 没写引用

错误写法：

```cpp
for (auto ch : str)
```

正确写法：

```cpp
for (auto& ch : str)
```

### 5. 误把 `find` 找不到的返回值当成固定 `-1`

正式写法应记为：

```cpp
string::npos
```

### 6. 处理含空格输入时仍然用 `cin >> s`

该用 `getline` 的题，一定要果断换。

### 7. 高频拼接时无脑用 `operator+`

基础阶段就记结论：**优先 `+=` / `append`。**

### 8. 手写 `String` 类时只写构造和析构

这样一拷贝就会触发浅拷贝问题。

### 9. 不理解浅拷贝为什么危险

本质是多个对象共享同一资源，析构时重复释放。

### 10. 只背接口，不会迁移到 OJ 题型

真正要会的是：

- 遍历
- 双指针
- 统计
- 查找
- 截取
- 模拟

| 查找 | `substr` | 截子串 |

| 输入 | `getline` | 读整行 |

### 3）本讲最关键的 8 句话

1. `size` 看长度，`capacity` 看容量。
2. `resize` 改内容长度，`reserve` 改预留空间。
3. 修改字符串元素时，范围 `for` 要用引用。
4. 查找失败返回 `string::npos`。
5. 含空格输入优先考虑 `getline`。
6. 高频拼接优先 `+=` / `append`。
7. 浅拷贝只拷贝地址，资源类会出事。
8. 深拷贝的核心是每个对象都有独立资源。

## 附：本讲最值得反复看的 10 句话

1. `string` 比 C 风格字符串更符合 OOP，也更常用于开发和 OJ。
2. `auto` 最典型的价值是简化迭代器类型。
3. 范围 `for` 修改元素时必须用引用。
4. `size()` 看长度，`capacity()` 看容量。
5. `resize()` 改有效字符个数，`reserve()` 改预留空间。
6. 高频拼接优先考虑 `+=` / `append`，少依赖 `operator+`。
7. 查找失败返回 `string::npos`。
8. `getline` 能读整行，`cin >> s` 遇空格停。
9. 手写 `String` 类时，浅拷贝会导致共享资源和重复释放问题。
10. 深拷贝的核心是：每个对象拥有自己独立的一份字符资源。
