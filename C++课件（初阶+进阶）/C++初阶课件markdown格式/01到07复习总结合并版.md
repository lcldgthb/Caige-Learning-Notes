## 三、C++ 的第一个程序

### 1. C 风格写法仍然可用

C++ 兼容 C 语言绝大多数语法，所以 C 的 `hello world` 仍然可以运行。

```cpp
#include <stdio.h>

int main()
{
    printf("hello world\n");
    return 0;
}
```

注意：

- C++ 源文件后缀一般是 `.cpp`。
- Windows / VS 中 `.cpp` 会调用 C++ 编译器。
- Linux 下 C++ 程序通常用 `g++` 编译，而不是 `gcc`。

---

### 2. C++ 风格写法

```cpp
#include <iostream>
using namespace std;

{
    cout << "hello world" << endl;

}
```

几个关键词：

| 写法 | 含义 |
|---|---|
| `#include <iostream>` | 引入 C++ 输入输出流库 |
| `using namespace std;` | 展开标准命名空间 |
| `cout` | 标准输出对象 |
| `<<` | 流插入运算符 |
| `endl` | 换行并刷新缓冲区 |

## 四、命名空间 `namespace`

## 1. 为什么需要命名空间？

C / C++ 中变量、函数、类型名都可能出现在全局作用域中，容易产生命名冲突。

例如：

```cpp
#include <stdlib.h>

int rand = 10;
```

这里自定义变量 `rand` 可能和库函数 `rand` 冲突。

命名空间的作用：

> 把标识符放到一个独立的域中，避免命名冲突和名字污染。

---

## 2. 命名空间定义

```cpp
namespace bit
{
    int rand = 10;

    int Add(int left, int right)
    {
        return left + right;
    }

    struct Node
    {
        Node* next;
        int val;
    };
}
```

命名空间中可以定义：

- 变量
- 函数
- 类型
- 结构体
- 类
- 其他命名空间

本质：

> `namespace` 定义了一个新的作用域。

---

## 3. 域的种类

 C++ 常见的域：

- 局部域
- 全局域
- 命名空间域
- 类域

注意区别：

| 域 | 是否影响名字查找 | 是否影响变量生命周期 |
|---|---:|---:|
| 局部域 | 是 | 是 |
| 全局域 | 是 | 是 |
| 命名空间域 | 是 | 不直接影响 |
| 类域 | 是 | 不直接影响 |

重点：

> 域主要影响编译时查找变量、函数、类型声明或定义的规则。

---

## 4. 命名空间可以嵌套

```cpp
namespace bit
{
    namespace pg
    {
        int rand = 1;
        int Add(int left, int right)
        {
            return left + right;
        }
    }

    namespace hg
    {
        int rand = 2;
        int Add(int left, int right)
        {
            return (left + right) * 10;
        }
    }
}
```

访问方式：

```cpp
bit::pg::rand;
bit::hg::rand;
bit::pg::Add(1, 2);
bit::hg::Add(1, 2);
```

---

## 5. 多文件中的同名命名空间会合并

多个文件中可以定义同名 `namespace`，它们会被认为是同一个命名空间。

例如：

```cpp
// Stack.h
namespace bit
{
    struct Stack;
    void STInit(Stack* ps);
}

// Queue.h
namespace bit
{
    struct Queue;
    void QueueInit(Queue* pq);
}
```

这两个 `bit` 命名空间不会冲突，而是合并。

---

## 6. 命名空间的三种使用方式

### 方式一：指定命名空间访问

```cpp
std::cout << "hello" << std::endl;
bit::STInit(&st);
```

特点：

- 最安全
- 不容易冲突
- 项目开发中推荐

---

### 方式二：展开某个成员

```cpp
using std::cout;
using std::endl;

cout << "hello" << endl;
```

特点：

- 比完全展开更安全
- 适合经常使用且不容易冲突的成员

---

### 方式三：展开整个命名空间

```cpp
using namespace std;
```

特点：

- 写代码方便
- 但容易引入命名冲突
- 日常练习可以用
- 实际项目不推荐滥用

## 五、C++ 输入输出

### 1. 基本对象

```cpp
#include <iostream>
```

`iostream` 是标准输入输出流库。

常见对象：

| 对象 | 含义 |
|---|---|
| `std::cin` | 标准输入对象 |
| `std::cout` | 标准输出对象 |
| `std::endl` | 换行并刷新缓冲区 |

---

### 2. 流插入和流提取

```cpp
cout << a << endl;
cin >> a;
```

| 运算符 | 在 IO 中的含义 |
|---|---|
| `<<` | 流插入，用于输出 |
| `>>` | 流提取，用于输入 |

注意：

> `<<` 和 `>>` 在 C 语言中也可以表示位移运算，C++ IO 中通过运算符重载让它们具有输入输出含义。

---

### 3. C++ IO 的优点

相比 `printf` / `scanf`，C++ IO 的优势：

- 不需要手动写格式控制符。
- 能自动识别变量类型。
- 更适合后续自定义类型对象的输入输出。

例如：

```cpp
int a = 0;
double b = 0.1;
char c = 'x';

cout << a << " " << b << " " << c << endl;
cin >> a >> b >> c;
```

---

### 4. 竞赛中提高 C++ IO 效率

在大量输入输出的场景中，可以加：

```cpp
ios_base::sync_with_stdio(false);
cin.tie(nullptr);
cout.tie(nullptr);
```

常见竞赛写法：

```cpp
#include <iostream>
using namespace std;

int main()
{
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    cout.tie(nullptr);

    return 0;
}
```

注意：

> 关闭同步后，不建议混用 `cin/cout` 和 `scanf/printf`，否则可能出现输入输出顺序或缓冲问题。

## 六、缺省参数

### 1. 缺省参数概念

缺省参数也叫默认参数。

定义：

> 在声明或定义函数时，为函数参数指定一个默认值。调用时如果不传实参，就使用默认值；如果传了实参，就使用传入的值。

例如：

```cpp
void Func(int a = 0)
{
    cout << a << endl;
}

Func();    // 使用默认值 0
Func(10);  // 使用传入值 10
```

---

### 2. 全缺省参数

所有参数都有默认值：

```cpp
void Func1(int a = 10, int b = 20, int c = 30)
{
}
```

调用方式：

```cpp
Func1();
Func1(1);
Func1(1, 2);
Func1(1, 2, 3);
```

---

### 3. 半缺省参数

部分参数有默认值：

```cpp
void Func2(int a, int b = 10, int c = 20)
{
}
```

正确调用：

```cpp
Func2(100);
Func2(100, 200);
Func2(100, 200, 300);
```

---

### 4. 半缺省参数必须从右往左连续给

正确：

```cpp
void Func(int a, int b = 10, int c = 20);
```

错误：

```cpp
void Func(int a = 10, int b, int c = 20); // 错误
```

原因：

> 函数调用传参是从左往右依次匹配的，不能跳跃传参。

---

### 5. 声明和定义分离时，缺省参数只能给一次

推荐在声明中给默认值：

```cpp
// Stack.h
void STInit(ST* ps, int n = 4);

// Stack.cpp
void STInit(ST* ps, int n)
{
}
```

错误写法：

```cpp
// 声明和定义都写默认值，错误
void STInit(ST* ps, int n = 4);
void STInit(ST* ps, int n = 4)
{
}
```

重点记忆：

> 缺省参数一般写在函数声明处，函数定义处不要重复写。

## 七、函数重载

### 1. 函数重载概念

C++ 支持在同一作用域中定义多个同名函数，但要求形参不同。

函数重载体现了 C++ 的多态行为。

例如：

```cpp
int Add(int left, int right)
{
    return left + right;
}

double Add(double left, double right)
{
    return left + right;
}
```

调用时编译器根据实参类型选择对应函数：

```cpp
Add(10, 20);       // 调用 int 版本
Add(10.1, 20.2);   // 调用 double 版本
```

---

### 2. 构成函数重载的条件

函数名相同，参数列表不同。

参数列表不同包括：

#### 情况一：参数类型不同

```cpp
int Add(int left, int right);
double Add(double left, double right);
```

#### 情况二：参数个数不同

```cpp
void f();
void f(int a);
```

#### 情况三：参数类型顺序不同

```cpp
void f(int a, char b);
void f(char b, int a);
```

---

### 3. 返回值不同不能构成重载

错误示例：

```cpp
void fxx();
int fxx();
```

原因：

> 函数调用时通常无法仅根据返回值判断要调用哪个函数。

例如：

```cpp
fxx(); // 编译器不知道选 void 版本还是 int 版本
```

---

### 4. 缺省参数可能导致调用歧义

```cpp
void f1()
{
}

void f1(int a = 10)
{
}
```

这两个函数本身可以构成重载，但调用时：

```cpp
f1();
```

会产生歧义，因为：

- 可以调用无参版本。
- 也可以调用带默认参数的版本。

结论：

> 函数能构成重载，不代表每种调用都没有歧义。

## 八、引用

## 1. 引用的概念

引用不是新定义一个变量，而是给已存在变量取别名。

格式：

```cpp
类型& 引用名 = 被引用对象;
```

例如：

```cpp
int a = 0;
int& b = a;
int& c = a;
```

这里：

- `b` 是 `a` 的别名。
- `c` 也是 `a` 的别名。
- 操作 `b` 或 `c`，本质上就是操作 `a`。

```cpp
++b;
```

等价于：

```cpp
++a;
```

---

## 2. 引用和取地址符号的区别

`&` 在不同场景下含义不同：

```cpp
int& b = a;  // 引用符号，表示 b 是 a 的别名
&a;          // 取地址符号，表示取 a 的地址
```

判断方式：

| 写法位置 | 含义 |
|---|---|
| 类型后面，如 `int& b` | 引用 |
| 表达式前面，如 `&a` | 取地址 |

---

## 3. 引用的三个特性

### 特性一：引用定义时必须初始化

错误：

```cpp
int& ra; // 错误，引用必须初始化
```

正确：

```cpp
int a = 10;
int& ra = a;
```

---

### 特性二：一个变量可以有多个引用

```cpp
int a = 10;
int& b = a;
int& c = a;
int& d = b;
```

`b`、`c`、`d` 都是 `a` 的别名。

---

### 特性三：引用一旦绑定，不能再引用其他对象

```cpp
int a = 10;
int& b = a;

int c = 20;
b = c;
```

注意：

> `b = c` 不是让 `b` 改为引用 `c`，而是把 `c` 的值赋给 `a`。

引用不像指针，不能改变指向。

---

## 九、引用的使用场景

### 1. 引用传参

引用传参可以达到类似指针传参的效果，但写法更自然。

```cpp
void Swap(int& rx, int& ry)
{
    int tmp = rx;
    rx = ry;
    ry = tmp;
}
```

调用：

```cpp
int x = 0, y = 1;
Swap(x, y);
``` 
优点：

- 可以直接修改实参。
- 不需要像指针那样写 `&x` 和 `*px`。
- 语法更简洁。

---

### 2. 引用用于数据结构接口

例如 Stack 初始化：

```cpp
void STInit(ST& rs, int n = 4)
{
    rs.a = (STDataType*)malloc(n * sizeof(STDataType));
    rs.top = 0;
    rs.capacity = n;
}
```

调用时：

```cpp
ST st;
STInit(st);
```

相比指针传参：

```cpp
STInit(&st);
```

引用写法更简洁。

---

### 3. 指针变量也可以有引用

例如链表尾插时，可以用指针引用替代二级指针：

```cpp
void ListPushBack(LTNode*& phead, int x)
{
}
```

含义：

> `LTNode*& phead` 是给一个指针变量取别名。

可以理解为：

- `LTNode*` 是指针类型。
- `&` 表示对这个指针变量取引用。

这种写法可以避免使用二级指针：

```cpp
void ListPushBack(LTNode** phead, int x);
```

---

### 4. 引用返回值

函数可以返回引用：

```cpp
int& STTop(ST& rs)
{
    assert(rs.top > 0);
    return rs.a[rs.top - 1];
}
```

这样调用结果可以作为左值：

```cpp
STTop(st) += 10;
```

含义：

> 返回的是栈顶元素的别名，因此可以直接修改栈顶元素。

注意：

> 引用返回值后面会在类和对象章节继续深入，尤其要注意不能返回局部变量的引用。

## 十、`const` 引用

### 1. 权限不能放大，只能缩小

如果对象本身是 `const`，必须用 `const` 引用。

```cpp
const int a = 10;
const int& ra = a;
```

错误：

```cpp
int& ra = a; // 错误，权限放大
```

原因：

- `a` 是只读的。
- `int&` 允许修改。
- 用可修改引用绑定只读对象，相当于权限放大，不允许。

---

### 2. 普通对象可以被 `const` 引用绑定

```cpp
int b = 20;
const int& rb = b;
```

这是允许的，因为：

> 对普通变量使用 `const` 引用，是权限缩小。

但不能通过 `rb` 修改 `b`：

```cpp
rb++; // 错误
```

---

### 3. 临时对象具有常性

下面写法错误：

```cpp
int a = 10;
int& rb = a * 3; // 错误
```

原因：

- `a * 3` 的结果会放到一个临时对象中。
- 临时对象具有常性。
- 普通引用不能绑定临时对象。

正确写法：

```cpp
const int& rb = a * 3;
```

---

### 4. 类型转换也可能产生临时对象

```cpp
double d = 12.34;
const int& rd = d;
```

这里会发生类型转换：

```text
double -> int
```

转换结果存放在临时对象中，所以必须用 `const int&`。

错误：

```cpp
int& rd = d;
```

---

## 十一、指针和引用的区别

引用和指针功能有重叠，但不是同一个东西。

| 对比项 | 引用 | 指针 |
|---|---|---|
| 概念 | 变量的别名 | 存储地址的变量 |
| 是否开空间 | 语法概念上不开新空间 | 指针变量本身要开空间 |
| 初始化 | 必须初始化 | 建议初始化，但语法上不强制 |
| 是否能改变指向 | 不能 | 可以 |
| 访问对象 | 直接访问 | 需要解引用 `*p` |
| 空值问题 | 一般较少 | 容易有空指针、野指针 |
| `sizeof` | 得到被引用类型大小 | 得到指针大小，32 位 4 字节，64 位 8 字节 |
| 使用感受 | 更安全、更简洁 | 更灵活、更底层 |

重点记忆：

> 引用像“别名”，指针像“地址变量”。引用更安全，指针更灵活，二者互相不能完全替代。

## 十二、`inline` 内联函数

### 1. 内联函数概念

用 `inline` 修饰的函数叫内联函数。

```cpp
inline int Add(int x, int y)
{
    return x + y;
}
```

编译器可能会在函数调用处直接展开函数代码，从而减少函数调用建立栈帧的开销。

---

### 2. `inline` 只是给编译器的建议

重点：

> `inline` 只是建议，不是命令。

编译器可以选择：

- 展开这个函数。
- 不展开这个函数。

一般适合内联的函数：

- 短小
- 频繁调用
- 逻辑简单

一般不适合内联的函数：

- 递归函数
- 代码量大的函数
- 复杂逻辑函数

---

### 3. `inline` 和宏函数的区别

C 语言中常用宏函数：

```cpp
#define ADD(a, b) ((a) + (b))
```

宏函数问题：

- 容易写错括号。
- 不方便调试。
- 没有类型检查。
- 预处理阶段直接替换，容易出现优先级问题。

例如宏必须写成：

```cpp
#define ADD(a, b) ((a) + (b))
```

原因：

- 外层括号保护整体优先级。
- 内层括号保护参数优先级。
- 不能随便加分号。

`inline` 的价值：

> 在保留函数语义、类型检查和可调试性的基础上，尽量获得类似宏函数展开的效率。

---

### 4. `inline` 不建议声明和定义分离到两个文件

错误倾向：

```cpp
// F.h
inline void f(int i);

// F.cpp
void f(int i)
{
    cout << i << endl;
}
```

可能导致链接错误。

原因：

> `inline` 函数可能在编译阶段展开，链接时未必能找到正常函数地址。

推荐：

> 内联函数通常直接在头文件中给出完整定义。

## 十三、`nullptr`

### 1. `NULL` 的问题

传统 C / C++ 中常用 `NULL` 表示空指针。

但在 C++ 中，`NULL` 可能被定义为：

```cpp
#define NULL 0
```

这会带来函数重载问题。

例如：

```cpp
void f(int x)
{
    cout << "f(int x)" << endl;
}

void f(int* ptr)
{
    cout << "f(int* ptr)" << endl;
}
```

调用：

```cpp
f(NULL);
```

如果 `NULL` 被定义为 `0`，实际会调用：

```cpp
f(int x)
```

这可能不是程序员想要的结果。

---

### 2. `nullptr` 的作用

C++11 引入 `nullptr`。

```cpp
int* p = nullptr;
```

特点：

- `nullptr` 是关键字。
- 它表示空指针。
- 它可以转换为任意指针类型。
- 它不能被隐式转换为整数类型。

所以：

```cpp
f(nullptr);
```

会正确调用：

```cpp
f(int* ptr)
```

---

### 3. 推荐写法

C++ 中推荐：

```cpp
int* p = nullptr;
```

不推荐：

```cpp
int* p = NULL;
int* p = 0;
```

核心原因：

> `nullptr` 类型更明确，可以避免 `NULL` 被当成整数 `0` 引发的重载歧义或调用错误。

## 十四、易错点汇总

### 易错点 1：项目中滥用 `using namespace std`

日常练习可以：

```cpp
using namespace std;
```

项目中更推荐：

```cpp
std::cout << std::endl;
```

或只展开常用成员：

```cpp
using std::cout;
using std::endl;
```

---

### 易错点 2：命名空间中的变量不会被默认查找

```cpp
namespace bit
{
    int a = 0;
}

cout << a << endl; // 错误
```

正确：

```cpp
cout << bit::a << endl;
```

---

### 易错点 3：半缺省参数不是随便给

错误：

```cpp
void Func(int a = 10, int b, int c = 20);
```

正确：

```cpp
void Func(int a, int b = 10, int c = 20);
```

口诀：

> 缺省参数必须从右往左连续给。

---

### 易错点 4：声明和定义同时写缺省值

错误：

```cpp
void Func(int a = 10);
void Func(int a = 10) {}
```

正确：

```cpp
void Func(int a = 10);
void Func(int a) {}
```

---

### 易错点 5：返回值不同不能函数重载

错误：

```cpp
void f();
int f();
```

原因：

> 调用时无法只靠返回值区分。

---

### 易错点 6：引用不是指针，不能重新绑定

```cpp
int a = 10;
int& r = a;
int b = 20;
r = b;
```

这里不是让 `r` 改为引用 `b`，而是：

```cpp
a = b;
```

---

### 易错点 7：普通引用不能绑定临时对象

错误：

```cpp
int a = 10;
int& r = a * 3;
```

正确：

```cpp
const int& r = a * 3;
```

---

### 易错点 8：`inline` 不是一定展开

```cpp
inline int Add(int x, int y)
{
    return x + y;
}
```

不代表编译器一定展开。

正确理解：

> `inline` 是建议，最终是否展开由编译器决定。

---

### 易错点 9：`NULL` 不等于类型安全的空指针

```cpp
f(NULL);
```

可能调用整数版本。

推荐：

```cpp
f(nullptr);
```

## 一、这一讲的核心主线

本节主要围绕 C++ 面向对象入门中的三个基础问题展开：

1. **类怎么定义？**
   - 类的成员变量、成员函数、访问限定符、类域。

   - 类是抽象描述，对象是实际占内存的实体。
3. **成员函数如何知道自己操作的是哪个对象？**
   - 通过隐藏的 `this` 指针。

可以用一句话概括：

> **类把数据和操作数据的函数封装到一起；对象负责存储具体数据；成员函数通过 `this` 指针找到当前对象的数据。**

## 二、类的定义

### 1. 类定义的基本格式

```cpp
class Stack
{
public:
    void Init(int n = 4)
    {
        // 成员函数
    }

private:
    int* _array;
    size_t _capacity;
    size_t _top;
};
```

注意点：

- `class` 是定义类的关键字。
- `{}` 内部是类体。
- 类体中的变量叫：
  - 成员变量
  - 属性
- 类体中的函数叫：
  - 成员函数
  - 方法
- **类定义结束后的分号不能省略。**

```cpp
}; // 必须有分号
```

---

### 2. 成员变量命名习惯

为了区分普通变量和成员变量，常见写法有：

```cpp
int _year;
int year_;
int m_year;
```

课件中更常用 `_xxx` 风格，例如：

```cpp
int _year;
int _month;
int _day;
```

注意：

> 这只是编码习惯，不是 C++ 语法强制要求。

---

### 3. `class` 和 `struct` 的区别

C++ 中 `struct` 也可以定义类，并且可以在结构体中写函数。

```cpp
struct ListNodeCPP
{
    void Init(int x)
    {
        next = nullptr;
        val = x;
    }

    ListNodeCPP* next;
    int val;
};
```

重点区别：

| 对比项 | `class` | `struct` |
|---|---|---|
| 默认访问权限 | `private` | `public` |
| 是否能定义成员函数 | 可以 | 可以 |
| C++ 中是否能表示类型 | 可以 | 可以 |
| 推荐用途 | 更常用于封装类 | 更常用于简单数据结构 |

最重要的区别：

```cpp
class A
{
    int x; // 默认 private
};

struct B
{
    int x; // 默认 public
};
```

---

## 三、访问限定符

### 1. 三种访问限定符

```cpp
public:
protected:
private:
```

本节重点掌握：

| 访问限定符 | 类外能否直接访问 | 当前阶段理解 |
|---|---:|---|
| `public` | 可以 | 对外提供的接口 |
| `private` | 不可以 | 内部实现细节 |
| `protected` | 不可以 | 暂时和 `private` 类似，继承中再区分 |

---

### 2. 访问限定符的作用范围

访问限定符从出现的位置开始生效，一直到：

- 下一个访问限定符出现；或者
- 类结束 `}`。

例如：

```cpp
class Date
{
public:
    void Init(int year, int month, int day);
    void Print();

private:
    int _year;
    int _month;
    int _day;
};
```

这里：

- `Init`、`Print` 是 `public`。
- `_year`、`_month`、`_day` 是 `private`。

---

### 3. 封装的初步体现

C++ 通过访问限定符实现封装：

- 成员变量一般设为 `private` 或 `protected`。
- 成员函数中需要给外部使用的接口设为 `public`。

这样做的好处：

> 防止外部随意修改对象内部数据，让对象的状态由成员函数统一管理。

例如 Stack 中：

```cpp
private:
    STDataType* _a;
    size_t _capacity;
    size_t _top;
```

外部不能直接改 `_top`、`_capacity`，只能通过：

```cpp
s.Push(1);
s.Pop();
s.Top();
s.Empty();
```

这就是封装的基础价值。

---

## 四、类域

### 1. 类会形成新的作用域

类定义了一个新的作用域，类中所有成员都属于这个类域。

如果成员函数在类外定义，需要使用作用域限定符 `::`。

```cpp
class Stack
{
public:
    void Init(int n = 4);

private:
    int* _array;
    size_t _capacity;
    size_t _top;
};

void Stack::Init(int n)
{
    _array = (int*)malloc(sizeof(int) * n);
    _capacity = n;
    _top = 0;
}
```

---

### 2. 为什么类外定义要写 `Stack::`？

如果写成：

```cpp
void Init(int n)
{
    _array = ...;
}
```

编译器会认为这是一个**全局函数**，而不是 `Stack` 的成员函数。

这样函数内部访问 `_array`、`_capacity`、`_top` 时，编译器在当前作用域找不到这些成员，就会报错。

所以必须写：

```cpp
void Stack::Init(int n)
```

表示：

> `Init` 是 `Stack` 类域中的成员函数。

## 五、实例化

### 1. 类和对象的关系

核心区别：

| 概念 | 含义 | 是否占用对象数据空间 |
|---|---|---:|
| 类 | 抽象描述、设计图、类型 | 不占具体对象空间 |
| 对象 | 根据类创建出来的实体 | 占实际物理空间 |

经典类比：

> 类像建筑设计图，对象像根据设计图建出来的房子。设计图不能住人，房子才能住人。

---

### 2. 成员变量什么时候开空间？

在类中写成员变量时：

```cpp
class Date
{
private:
    int _year;
    int _month;
    int _day;
};
```

这里的 `_year`、`_month`、`_day` 只是声明对象将来有哪些数据成员。

真正开空间是在实例化对象时：

```cpp
Date d1;
Date d2;
```

此时：

- `d1` 有自己独立的 `_year/_month/_day`。
- `d2` 也有自己独立的 `_year/_month/_day`。

---

### 3. 一个类可以实例化多个对象

```cpp
Date d1;
Date d2;

d1.Init(2024, 3, 31);
d2.Init(2024, 7, 5);
```

`d1` 和 `d2` 共享同一套成员函数代码，但拥有各自独立的成员变量。

重点：

> 对象中存储的是成员变量，不存储普通成员函数代码。

---

## 六、对象大小

### 1. 对象中到底存什么？

类对象中主要存储：

```cpp
成员变量
```

普通成员函数不会存储在每个对象中。

原因：

- 成员函数编译后是指令，放在代码段。
- 多个对象调用的是同一份函数代码。
- 如果每个对象都存函数代码或函数指针，会造成浪费。

例如：

```cpp
Date d1;
Date d2;
```

`d1` 和 `d2` 各自有独立数据，但 `Init`、`Print` 函数代码只有一份。

---

### 2. 对象大小遵循内存对齐

类对象大小遵循结构体内存对齐规则。

内存对齐核心规则：

1. 第一个成员放在偏移量为 `0` 的位置。
2. 后续成员要放到自己对齐数整数倍的位置。
3. 对齐数 = `编译器默认对齐数` 和 `成员自身大小` 的较小值。
4. VS 中默认对齐数通常为 `8`。
5. 结构体或类的总大小是最大对齐数的整数倍。
6. 如果有嵌套结构体，嵌套结构体按自己的最大对齐数对齐。

---

### 3. 典型对象大小问题

```cpp
class A
{
private:
    char _ch;
    int _i;
};
```

分析：

- `_ch` 占 1 字节。
- 为了让 `_i` 对齐到 4 的整数倍，中间会填充 3 字节。
- `_i` 占 4 字节。
- 总大小为 8 字节。

所以：

```cpp
sizeof(A) == 8
```

---

### 4. 空类大小为什么是 1？

```cpp
class B
{
public:
    void Print()
    {
    }
};

class C
{
};
```

`B` 没有成员变量，只有成员函数。  
`C` 是完全空类。

但是：

```cpp
sizeof(B) == 1
sizeof(C) == 1
```

原因：

> 即使没有成员变量，也要给对象 1 个字节，用来标识这个对象真实存在。

注意：

- 这个 1 字节不是用来存成员函数的。
- 它只是占位标识。

---

## 七、`this` 指针

### 1. 为什么需要 `this` 指针？

成员函数代码只有一份，但可以被多个对象调用：

```cpp
Date d1;
Date d2;

d1.Init(2024, 3, 31);
d2.Init(2024, 7, 5);
```

问题是：

> 同一个 `Init` 函数，怎么知道当前应该修改 `d1` 还是 `d2`？

答案：

> 编译器会给非静态成员函数隐含传递一个 `this` 指针。

---

### 2. `this` 指针的本质

你写的成员函数：

```cpp
void Init(int year, int month, int day)
{
    _year = year;
    _month = month;
    _day = day;
}
```

编译器大致会理解成：

```cpp
void Init(Date* const this, int year, int month, int day)
{
    this->_year = year;
    this->_month = month;
    this->_day = day;
}
```

重点：

- `this` 是当前对象的地址。
- 成员函数中访问成员变量，本质都是通过 `this` 指针访问。
- `this` 指针由编译器自动传递。

---

### 3. `this` 指针的几个关键结论

#### 结论一：不能在形参和实参位置显式写 `this`

不能这样写：

```cpp
void Init(Date* const this, int year, int month, int day); // 错误理解方式，不是用户写法
```

调用时也不能这样写：

```cpp
d1.Init(&d1, 2024, 3, 31); // 错误
```

应该写：

```cpp
d1.Init(2024, 3, 31);
```

---

#### 结论二：可以在函数体内部显式使用 `this`

```cpp
void Init(int year, int month, int day)
{
    this->_year = year;
    this->_month = month;
    this->_day = day;
}
```

---

#### 结论三：`this` 的类型可以理解为 `类类型* const`

例如在 `Date` 类中：

```cpp
Date* const this
```

含义：

- `this` 是指向当前对象的指针。
- `this` 本身不能被修改。

所以不能写：

```cpp
this = nullptr; // 错误
```

但可以通过 `this` 修改对象成员：

```cpp
this->_year = 2024;
```

---

### 4. `this` 指针存在哪里？

课件选择题结论：

> `this` 指针本质是成员函数的一个隐含形参，所以通常存在栈帧中。

对应选项：

```text
A. 栈
```

注意：

> `this` 指针不在对象里面。

对象里面存的是成员变量。

## 八、典型选择题结论

### 题 1：空指针调用不访问成员变量的成员函数

```cpp
class A
{
public:
    void Print()
    {
        cout << "A::Print()" << endl;
    }
private:
    int _a;
};

int main()
{
    A* p = nullptr;
    p->Print();
    return 0;
}
```

结论：

```text
正常运行
```

原因：

- `p->Print()` 会把 `p` 作为 `this` 指针传给成员函数。
- 函数体内没有访问成员变量，也就没有解引用空指针访问对象数据。
- 因此通常可以正常打印。

---

### 题 2：空指针调用访问成员变量的成员函数

```cpp
class A
{
public:
    void Print()
    {
        cout << "A::Print()" << endl;
        cout << _a << endl;
    }
private:
    int _a;
};

int main()
{
    A* p = nullptr;
    p->Print();
    return 0;
}
```

结论：

```text
运行崩溃
```

原因：

- `_a` 本质是 `this->_a`。
- 此时 `this == nullptr`。
- 访问 `this->_a` 等价于通过空指针访问对象成员，会崩溃。

---

## 九、C 和 C++ 实现 Stack 的对比

### 1. C 语言写法特点

C 语言中，数据和函数是分离的：

```cpp
typedef struct Stack
{
    STDataType* a;
    int top;
    int capacity;
} ST;

void STInit(ST* ps);
void STPush(ST* ps, STDataType x);
void STPop(ST* ps);
```

使用时要手动传地址：

```cpp
ST s;
STInit(&s);
STPush(&s, 1);
STPop(&s);
```

---

### 2. C++ 写法特点

C++ 中，数据和函数放进类里：

```cpp
class Stack
{
public:
    void Init(int n = 4);
    void Push(STDataType x);
    void Pop();
    bool Empty();
    int Top();
    void Destroy();

private:
    STDataType* _a;
    size_t _capacity;
    size_t _top;
};
```

使用时：

```cpp
Stack s;
s.Init();
s.Push(1);
s.Pop();
```

---

### 3. 二者核心区别

| 对比项 | C 语言实现 | C++ 实现 |
|---|---|---|
| 数据和函数 | 分离 | 封装到类中 |
| 是否手动传对象地址 | 需要 `&s` | 不需要，隐藏传 `this` |
| 成员变量保护 | 外部可以随意访问结构体成员 | 可以用 `private` 限制 |
| 类型命名 | 常需要 `typedef` | 类名本身就是类型名 |
| 默认参数 | 不支持 | 支持，如 `Init(int n = 4)` |

---

### 4. 最重要的变化：封装

本节中 C++ Stack 的底层逻辑和 C 语言差别不大，仍然是：

- 动态数组；
- `top` 表示栈顶位置；
- 容量不足时扩容；
- 入栈、出栈、取栈顶。

真正重要的是形态变化：

> C++ 把数据和操作数据的函数绑定到一起，并通过访问限定符控制外部访问，这是封装的体现。

## 十、易错点汇总

### 易错点 1：类定义最后忘记分号

```cpp
class Date
{
}; // 不能少
```

---

### 易错点 2：误以为类定义时成员变量已经开空间

错误理解：

> 类里面写了 `int _year;`，所以类本身已经有空间。

正确理解：

> 类只是类型描述，实例化对象时才为成员变量分配空间。

---

### 易错点 3：误以为对象中存成员函数

正确结论：

> 对象中只存成员变量，普通成员函数代码在公共代码区，不属于某一个对象。

---

### 易错点 4：空类大小不是 0

```cpp
class C {};
sizeof(C) == 1
```

原因：

> 至少给 1 字节用于标识对象存在。

---

### 易错点 5：`this` 指针不是对象成员

正确结论：

> `this` 是成员函数的隐含形参，不存储在对象中。

---

### 易错点 6：空指针调用成员函数不一定立刻崩溃

分情况：

| 情况 | 结果 |
|---|---|
| 成员函数不访问成员变量 | 可能正常运行 |
| 成员函数访问成员变量 | 通常运行崩溃 |

本质判断标准：

> 是否通过 `this` 解引用访问对象数据。

---

### 易错点 7：类外定义成员函数忘记加类域

错误：

```cpp
void Init(int n)
{
}
```

正确：

```cpp
void Stack::Init(int n)
{
}
```

这一讲是 C++ 类和对象中非常重要的一讲，核心围绕：

## 二、类的默认成员函数

### 1. 什么是默认成员函数？

默认成员函数是指：

> 用户没有显式实现时，编译器会自动生成的成员函数。

一个类中常说的 6 个默认成员函数：

| 默认成员函数 | 作用 | 重要程度 |
|---|---|---|
| 构造函数 | 初始化对象 | 非常重要 |
| 析构函数 | 清理对象资源 | 非常重要 |
| 拷贝构造函数 | 用已有对象初始化新对象 | 非常重要 |
| 赋值运算符重载 | 两个已存在对象之间赋值 | 非常重要 |
| 普通取地址运算符重载 | 获取对象地址 | 了解即可 |
| `const` 取地址运算符重载 | 获取 `const` 对象地址 | 了解即可 |

C++11 后还新增：

- 移动构造
- 移动赋值

但本讲主要掌握前 4 个。

---

### 2. 学默认成员函数要抓住两个问题

学习默认成员函数时，始终问两个问题：

1. **我不写时，编译器默认生成的行为是什么？**
2. **默认生成的行为是否满足当前类的需求？如果不满足，应该怎么自己写？**

尤其是遇到资源管理类，例如：

```cpp
class Stack
{
private:
    int* _a;
    size_t _capacity;
    size_t _top;
};
```

这种类内部有指针管理堆资源，默认生成的拷贝和赋值通常就不够用。

---

## 三、构造函数

## 1. 构造函数的作用

构造函数是特殊成员函数。

它的主要任务不是“开空间创建对象”，而是：

> 对象实例化时自动完成初始化。

例如以前写 Stack 时需要手动调用：

```cpp
Stack st;
st.Init();
```

有构造函数后：

```cpp
Stack st;
```

对象创建时自动调用构造函数完成初始化。

---

## 2. 构造函数特点

构造函数特点：

1. 函数名与类名相同。
2. 没有返回值，连 `void` 都不写。
3. 对象实例化时自动调用。
4. 构造函数可以重载。
5. 如果类中没有显式定义构造函数，编译器会自动生成一个默认构造函数。
6. 一旦用户显式定义构造函数，编译器就不再生成默认构造函数。

示例：

```cpp
class Date
{
public:
    Date()
    {
        _year = 1;
        _month = 1;
        _day = 1;
    }

    Date(int year, int month, int day)
    {
        _year = year;
        _month = month;
        _day = day;
    }

private:
    int _year;
    int _month;
    int _day;
};
```

---

## 3. 什么是默认构造函数？

重点：

> 不传实参就能调用的构造函数，都叫默认构造函数。

包括三类：

1. 编译器自动生成的构造函数
2. 用户写的无参构造函数
3. 用户写的全缺省构造函数

例如：

```cpp
Date();
Date(int year = 1, int month = 1, int day = 1);
```

这两个都可以不传参调用，所以都叫默认构造函数。

---

## 4. 默认构造函数不能同时存在多个可匹配版本

无参构造和全缺省构造虽然能构成函数重载：

```cpp
Date();
Date(int year = 1, int month = 1, int day = 1);
```

但调用：

```cpp
Date d;
```

会产生歧义，因为两个构造函数都能不传参调用。

结论：

> 默认构造函数只能有一个可用版本。

---

## 5. 无参构造创建对象不要加括号

```cpp
Date d1;   // 正确，定义对象
Date d2(); // 注意：这是函数声明，不是对象实例化
```

`Date d2();` 会被编译器理解成：

> 声明一个名为 `d2`、无参数、返回值为 `Date` 的函数。

这是非常经典的易错点。

---

## 6. 编译器默认生成的构造函数行为

如果你不写构造函数，编译器默认生成构造函数。

它的行为：

| 成员类型 | 默认构造函数行为 |
|---|---|
| 内置类型成员 | 是否初始化不确定，看编译器 |
| 自定义类型成员 | 调用该成员自己的默认构造函数 |

内置类型：

```cpp
int;
char;
double;
指针;
```

自定义类型：

```cpp
class / struct 定义出来的类型
```

重点：

> 默认构造函数对内置类型成员不保证初始化。

---

## 7. 自定义类型成员会自动调用构造函数

例如两个栈实现队列：

```cpp
class MyQueue
{
private:
    Stack pushst;
    Stack popst;
};
```

如果 `MyQueue` 没有显式写构造函数，编译器会自动生成默认构造函数。

这个默认构造函数会自动调用：

```cpp
pushst.Stack();
popst.Stack();
```

也就是说：

> 自定义类型成员会自动调用它自己的默认构造函数。

---

## 四、析构函数

## 1. 析构函数的作用

析构函数与构造函数功能相反。

析构函数不是销毁对象本身，而是在对象生命周期结束时：

> 自动清理对象内部申请的资源。

比如 Stack 中申请了堆空间：

```cpp
_a = (STDataType*)malloc(sizeof(STDataType) * n);
```

析构函数中应该释放：

```cpp
free(_a);
```

---

## 2. 析构函数特点

析构函数特点：

1. 函数名是在类名前加 `~`。
2. 无参数、无返回值。
3. 一个类只能有一个析构函数。
4. 对象生命周期结束时自动调用。
5. 如果没有显式定义，编译器会自动生成默认析构函数。
6. 默认析构函数对内置类型成员不做处理。
7. 默认析构函数会调用自定义类型成员的析构函数。

示例：

```cpp
class Stack
{
public:
    ~Stack()
    {
        free(_a);
        _a = nullptr;
        _top = _capacity = 0;
    }

private:
    STDataType* _a;
    size_t _capacity;
    size_t _top;
};
```

---

## 3. 什么时候必须自己写析构函数？

判断标准：

> 类内部是否直接管理资源。

需要自己写析构函数的典型情况：

- `malloc` / `free`
- `new` / `delete`
- 文件句柄
- 网络连接
- 锁资源
- 其他需要手动释放的资源

例如：

```cpp
class Stack
{
private:
    STDataType* _a;
};
```

`_a` 指向堆资源，必须写析构函数释放。

---

## 4. 什么时候可以不写析构函数？

例如 Date：

```cpp
class Date
{
private:
    int _year;
    int _month;
    int _day;
};
```

它没有申请资源，因此不需要显式写析构函数。

再如 MyQueue：

```cpp
class MyQueue
{
private:
    Stack pushst;
    Stack popst;
};
```

`MyQueue` 自己没有直接申请资源，它内部的 `Stack` 成员会自动调用自己的析构函数，因此 `MyQueue` 也可以不写析构函数。

---

## 5. 自定义类型成员一定会自动析构

无论你是否显式写当前类的析构函数，自定义类型成员都会在当前对象析构时自动调用自己的析构函数。

例如：

```cpp
class MyQueue
{
public:
    ~MyQueue()
    {
        // 即使这里什么也不写，pushst 和 popst 也会自动析构
    }

private:
    Stack pushst;
    Stack popst;
};
```

---

## 6. 局部对象析构顺序

一个局部域中有多个对象时：

> 后定义的对象先析构。

例如：

```cpp
Stack st;
MyQueue mq;
```

析构顺序：

```text
先析构 mq
再析构 st
```

---

## 7. 构造和析构对括号匹配题的意义

C 语言版本 Stack 使用时需要手动：

```cpp
STInit(&st);
STDestroy(&st);
```

如果中途 `return false`，每个分支都要记得 `STDestroy(&st)`，否则容易资源泄漏。

C++ 版本有构造和析构后：

```cpp
Stack st;
```

函数返回时自动调用析构函数，即使中途 `return`，也能自动释放资源。

这体现了 C++ 资源管理优势：

> 对象生命周期结束时自动清理资源，减少忘记释放资源的问题。

---

## 五、拷贝构造函数

## 1. 拷贝构造函数概念

如果一个构造函数的第一个参数是自身类类型的引用，且额外参数都有默认值，则它是拷贝构造函数。

常见写法：

```cpp
Date(const Date& d)
{
    _year = d._year;
    _month = d._month;
    _day = d._day;
}
```

拷贝构造本质：

> 用一个已有对象初始化一个新对象。

---

## 2. 拷贝构造是构造函数的重载

```cpp
Date(int year = 1, int month = 1, int day = 1);
Date(const Date& d);
```

它们都是构造函数，只是参数不同。

---

## 3. 拷贝构造参数必须是引用

错误写法：

```cpp
Date(Date d)
{
}
```

原因：

> 传值传参需要先调用拷贝构造，而拷贝构造参数如果又是传值，就会无限递归调用。

正确写法：

```cpp
Date(const Date& d)
{
}
```

一般还要加 `const`，因为只是读取被拷贝对象。

---

## 4. 哪些场景会调用拷贝构造？

### 场景一：同类型对象初始化新对象

```cpp
Date d1(2024, 7, 5);
Date d2(d1);
Date d3 = d1;
```

注意：

```cpp
Date d3 = d1;
```

这里是拷贝构造，不是赋值。

因为 `d3` 是新创建的对象。

---

### 场景二：自定义类型传值传参

```cpp
void Func(Date d)
{
}

Date d1;
Func(d1);
```

传参时要用 `d1` 拷贝构造形参 `d`。

---

### 场景三：传值返回

```cpp
Date Func()
{
    Date tmp;
    return tmp;
}
```

返回时可能产生临时对象，涉及拷贝构造。

注意现代编译器可能有返回值优化，但语义上要理解为有拷贝构造行为。

---

## 5. 传引用返回要避免野引用

错误示例：

```cpp
Date& Func2()
{
    Date tmp(2024, 7, 5);
    return tmp;
}
```

问题：

- `tmp` 是局部对象。
- 函数结束后 `tmp` 被销毁。
- 返回它的引用，相当于返回野引用。

结论：

> 传引用返回可以减少拷贝，但必须保证返回对象在函数结束后仍然存在。

---

## 6. 编译器默认生成的拷贝构造行为

如果不写拷贝构造，编译器会自动生成。

默认行为：

| 成员类型 | 默认拷贝构造行为 |
|---|---|
| 内置类型成员 | 值拷贝 / 浅拷贝，一个字节一个字节拷贝 |
| 自定义类型成员 | 调用该成员自己的拷贝构造 |

---

## 7. Date 类通常不需要自己写拷贝构造

```cpp
class Date
{
private:
    int _year;
    int _month;
    int _day;
};
```

Date 的成员都是内置类型，且没有指向堆资源。

默认拷贝构造就够用。

---

## 8. Stack 类必须自己写拷贝构造

```cpp
class Stack
{
private:
    STDataType* _a;
    size_t _capacity;
    size_t _top;
};
```

如果使用默认拷贝构造，会发生浅拷贝：

```cpp
Stack st2 = st1;
```

结果：

```text
st1._a 和 st2._a 指向同一块堆空间
```

问题：

- 一个对象修改资源，另一个对象受影响。
- 两个对象析构时会释放同一块空间两次。
- 程序可能崩溃。

所以 Stack 需要深拷贝：

```cpp
Stack(const Stack& st)
{
    _a = (STDataType*)malloc(sizeof(STDataType) * st._capacity);
    memcpy(_a, st._a, sizeof(STDataType) * st._top);
    _top = st._top;
    _capacity = st._capacity;
}
```

---

## 9. 是否需要写拷贝构造的小技巧

课件给出的实用判断：

> 如果一个类显式写了析构函数并释放资源，那么通常也需要显式写拷贝构造。

原因：

- 你写析构说明类管理资源。
- 管理资源时，默认浅拷贝大概率不符合需求。

---

## 六、运算符重载

## 1. 运算符重载概念

当运算符用于类类型对象时，C++ 允许通过运算符重载指定新的含义。

例如：

```cpp
Date d1;
Date d2;

d1 == d2;
```

本质会转换成：

```cpp
operator==(d1, d2);
```

或成员函数形式：

```cpp
d1.operator==(d2);
```

---

## 2. 运算符重载函数格式

运算符重载函数名由：

```cpp
operator + 运算符
```

组成。

例如：

```cpp
bool operator==(const Date& d1, const Date& d2);
```

成员函数形式：

```cpp
bool Date::operator==(const Date& d) const;
```

---

## 3. 运算符重载的参数个数

规则：

> 重载运算符函数的参数个数与该运算符的操作数个数有关。

如果是全局函数：

```cpp
bool operator==(const Date& d1, const Date& d2);
```

二元运算符有两个参数。

如果是成员函数：

```cpp
bool Date::operator==(const Date& d);
```

左操作数由隐含的 `this` 指针传递，所以只需要一个显式参数。

---

## 4. 运算符重载不能改变优先级和结合性

重载后：

> 运算符的优先级和结合性仍然与内置类型中的对应运算符一致。

例如 `+` 的优先级不会因为重载而改变。

---

## 5. 不能创造新的运算符

错误：

```cpp
operator@ // 不允许
```

C++ 只能重载已有运算符，不能自己发明新符号。

---

## 6. 不能重载的 5 个运算符

重点选择题常考：

```text
.*
::
sizeof
?:
.
```

记忆：

> 成员指针访问、作用域、大小、三目、点运算符不能重载。

---

## 7. 重载运算符至少有一个类类型参数

不能这样写：

```cpp
int operator+(int x, int y)
{
    return x - y;
}
```

原因：

> 不能通过运算符重载改变内置类型运算符原有含义。

---

## 8. 哪些运算符该不该重载，看语义是否合理

例如 Date：

| 运算符 | 是否合理 | 原因 |
|---|---:|---|
| `Date - Date` | 合理 | 两个日期差多少天 |
| `Date + int` | 合理 | 日期加天数 |
| `Date - int` | 合理 | 日期减天数 |
| `Date + Date` | 不合理 | 两个日期相加没有自然语义 |

原则：

> 运算符重载不是为了炫技，而是为了让类对象使用方式更符合直觉。

---

## 9. 前置 `++` 和后置 `++` 的区分

前置 `++`：

```cpp
Date& operator++();
```

后置 `++`：

```cpp
Date operator++(int);
```

后置多出来的 `int` 参数只是为了和前置构成重载。

调用关系：

```cpp
++d1; // d1.operator++()
d1++; // d1.operator++(0)
```

注意：

> 这个 `int` 参数没有实际意义，一般不用写形参名。

---

## 10. `<<` 和 `>>` 一般重载为全局函数

如果把 `<<` 重载为成员函数：

```cpp
d.operator<<(cout);
```

对应写法会变成：

```cpp
d << cout;
```

这不符合使用习惯。

我们希望写：

```cpp
cout << d;
cin >> d;
```

所以通常重载为全局函数：

```cpp
ostream& operator<<(ostream& out, const Date& d);
istream& operator>>(istream& in, Date& d);
```

第一个参数是左操作数：

- `cout` 是 `ostream` 对象
- `cin` 是 `istream` 对象

---

## 七、赋值运算符重载

## 1. 赋值运算符重载的作用

赋值运算符重载用于：

> 两个已经存在的对象之间进行拷贝赋值。

例如：

```cpp
Date d1(2024, 7, 5);
Date d2(2024, 7, 6);

d1 = d2;
```

这里 `d1` 和 `d2` 都已经存在，所以调用赋值运算符重载。

---

## 2. 拷贝构造和赋值重载的区别

这是本讲最高频易错点之一。

| 写法 | 本质 |
|---|---|
| `Date d2(d1);` | 拷贝构造 |
| `Date d2 = d1;` | 拷贝构造 |
| `d1 = d2;` | 赋值运算符重载 |

判断标准：

> 如果是创建新对象时用已有对象初始化，就是拷贝构造；如果两个对象都已经存在，再赋值，就是赋值运算符重载。

---

## 3. 赋值运算符必须重载为成员函数

赋值运算符重载规定必须是成员函数。

推荐写法：

```cpp
Date& operator=(const Date& d)
{
    if (this != &d)
    {
        _year = d._year;
        _month = d._month;
        _day = d._day;
    }
    return *this;
}
```

---

## 4. 参数为什么用 `const 当前类类型&`？

```cpp
Date& operator=(const Date& d)
```

原因：

- 用引用避免传值拷贝。
- 用 `const` 表示不会修改右操作数。

不要写成：

```cpp
Date& operator=(Date d)
```

否则传参时会发生额外拷贝。

---

## 5. 返回值为什么是当前类类型引用？

```cpp
Date& operator=(const Date& d)
```

原因：

1. 引用返回减少拷贝。
2. 支持连续赋值。

例如：

```cpp
d1 = d2 = d3;
```

表达式 `d2 = d3` 应该返回 `d2` 本身，也就是：

```cpp
return *this;
```

---

## 6. 为什么要检查自己给自己赋值？

```cpp
if (this != &d)
{
    // 执行赋值
}
```

对 Date 这种简单类影响不大，但对 Stack 这种资源管理类非常重要。

如果没有自赋值检查，可能出现：

1. 先释放自己的资源。
2. 发现右操作数其实也是自己。
3. 再从已经释放的资源中拷贝。

会导致严重问题。

---

## 7. 默认赋值运算符重载行为

如果不写，编译器会自动生成默认赋值运算符重载。

默认行为：

| 成员类型 | 默认赋值行为 |
|---|---|
| 内置类型成员 | 值拷贝 / 浅拷贝 |
| 自定义类型成员 | 调用该成员自己的赋值运算符重载 |

---

## 8. 哪些类需要自己写赋值运算符重载？

和拷贝构造类似。

Date：

```cpp
int _year;
int _month;
int _day;
```

默认赋值够用。

Stack：

```cpp
STDataType* _a;
```

默认浅拷贝不够用，需要自己写深拷贝赋值。

小技巧：

> 如果一个类显式写了析构并释放资源，那么通常也需要显式写赋值运算符重载。

---

## 八、日期类实现复习重点

日期类是本讲综合案例，重点不在背代码，而在理解每个运算符的设计逻辑。

---

## 1. 日期类主要接口

```cpp
class Date
{
public:
    Date(int year = 1900, int month = 1, int day = 1);
    void Print() const;
    int GetMonthDay(int year, int month);
    bool CheckDate();

    bool operator<(const Date& d) const;
    bool operator<=(const Date& d) const;
    bool operator>(const Date& d) const;
    bool operator>=(const Date& d) const;
    bool operator==(const Date& d) const;
    bool operator!=(const Date& d) const;

    Date& operator+=(int day);
    Date operator+(int day) const;
    Date& operator-=(int day);
    Date operator-(int day) const;
    int operator-(const Date& d) const;

    Date& operator++();
    Date operator++(int);
    Date& operator--();
    Date operator--(int);

private:
    int _year;
    int _month;
    int _day;
};
```

---

## 2. 获取某月天数 `GetMonthDay`

核心逻辑：

```cpp
static int monthDayArray[13] = { -1, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31 };
```

数组下标从 1 开始对应月份。

闰年 2 月返回 29：

```cpp
if (month == 2 && ((year % 4 == 0 && year % 100 != 0) || (year % 400 == 0)))
{
    return 29;
}
```

注意运算符优先级，建议加括号：

```cpp
month == 2 && (闰年条件)
```

---

## 3. 日期合法性检查

```cpp
bool Date::CheckDate()
{
    if (_month < 1 || _month > 12
        || _day < 1 || _day > GetMonthDay(_year, _month))
    {
        return false;
    }
    return true;
}
```

核心判断：

- 月份在 `1~12`
- 日期在 `1~当月最大天数`

---

## 4. 日期比较运算符

推荐先实现 `<` 和 `==`，其他复用。

```cpp
bool Date::operator<(const Date& d) const
{
    if (_year < d._year)
        return true;
    else if (_year == d._year)
    {
        if (_month < d._month)
            return true;
        else if (_month == d._month)
            return _day < d._day;
    }
    return false;
}
```

其他比较可以复用：

```cpp
bool Date::operator<=(const Date& d) const
{
    return *this < d || *this == d;
}

bool Date::operator>(const Date& d) const
{
    return !(*this <= d);
}

bool Date::operator>=(const Date& d) const
{
    return !(*this < d);
}

bool Date::operator!=(const Date& d) const
{
    return !(*this == d);
}
```

复习重点：

> 运算符之间要学会复用，减少重复代码和出错概率。

---

## 5. `+=` 和 `+` 的关系

`+=` 修改当前对象，返回当前对象引用：

```cpp
Date& Date::operator+=(int day)
{
    _day += day;
    while (_day > GetMonthDay(_year, _month))
    {
        _day -= GetMonthDay(_year, _month);
        ++_month;
        if (_month == 13)
        {
            ++_year;
            _month = 1;
        }
    }
    return *this;
}
```

`+` 不修改当前对象，所以用临时对象：

```cpp
Date Date::operator+(int day) const
{
    Date tmp = *this;
    tmp += day;
    return tmp;
}
```

重点：

| 运算符 | 是否修改当前对象 | 返回值 |
|---|---:|---|
| `+=` | 修改 | `Date&` |
| `+` | 不修改 | `Date` |

---

## 6. `-=` 和 `-` 的关系

`-=` 修改当前对象：

```cpp
Date& Date::operator-=(int day)
{
    _day -= day;
    while (_day <= 0)
    {
        --_month;
        if (_month == 0)
        {
            _month = 12;
            --_year;
        }
        _day += GetMonthDay(_year, _month);
    }
    return *this;
}
```

`-` 不修改当前对象：

```cpp
Date Date::operator-(int day) const
{
    Date tmp = *this;
    tmp -= day;
    return tmp;
}
```

---

## 7. 支持负数天数的技巧

```cpp
Date& Date::operator+=(int day)
{
    if (day < 0)
    {
        return *this -= -day;
    }
    // 正数加天数逻辑
}
```

```cpp
Date& Date::operator-=(int day)
{
    if (day < 0)
    {
        return *this += -day;
    }
    // 正数减天数逻辑
}
```

这样可以统一逻辑，避免重复处理。

---

## 8. 前置和后置 `++`

前置 `++`：先加，再返回自身引用。

```cpp
Date& Date::operator++()
{
    *this += 1;
    return *this;
}
```

后置 `++`：先保存旧值，再加，返回旧值。

```cpp
Date Date::operator++(int)
{
    Date tmp(*this);
    *this += 1;
    return tmp;
}
```

区别：

| 写法 | 行为 | 返回值 |
|---|---|---|
| `++d` | 先加后用 | 加完后的对象引用 |
| `d++` | 先用后加 | 加之前的临时对象 |

---

## 9. 两个日期相减

```cpp
int Date::operator-(const Date& d) const
{
    Date max = *this;
    Date min = d;
    int flag = 1;

    if (*this < d)
    {
        max = d;
        min = *this;
        flag = -1;
    }

    int n = 0;
    while (min != max)
    {
        ++min;
        ++n;
    }
    return n * flag;
}
```

核心思想：

- 先找较大日期和较小日期。
- 小日期不断 `++`，直到等于大日期。
- 统计天数差。
- 如果左操作数较小，则返回负数。

注意：

> 这种实现简单易懂，但效率不是最高。复习阶段重点理解逻辑即可。

---

## 10. 流插入和流提取

```cpp
ostream& operator<<(ostream& out, const Date& d)
{
    out << d._year << "年" << d._month << "月" << d._day << "日" << endl;
    return out;
}
```

返回 `ostream&` 是为了支持连续输出：

```cpp
cout << d1 << d2;
```

输入：

```cpp
istream& operator>>(istream& in, Date& d)
{
    in >> d._year >> d._month >> d._day;
    return in;
}
```

返回 `istream&` 是为了支持连续输入：

```cpp
cin >> d1 >> d2;
```

---

## 11. 为什么 `<<` 和 `>>` 需要友元？

如果成员变量是私有的：

```cpp
private:
    int _year;
    int _month;
    int _day;
```

全局函数不能直接访问私有成员。

解决方式：

1. 成员变量设为 `public`，不推荐。
2. 提供 `GetXXX` 函数。
3. 声明为友元函数。
4. 改成成员函数，但 `<<` / `>>` 不适合。

课件中采用友元：

```cpp
friend ostream& operator<<(ostream& out, const Date& d);
friend istream& operator>>(istream& in, Date& d);
```

## 九、`const` 成员函数

## 1. 什么是 `const` 成员函数？

`const` 修饰成员函数时，写在参数列表后面：

```cpp
void Print() const;
```

含义：

> 该成员函数内部不能修改对象的成员变量。

---

## 2. `const` 实际修饰的是 `this` 指针

普通成员函数中，`this` 可以理解为：

```cpp
Date* const this
```

`const` 成员函数中，`this` 变成：

```cpp
const Date* const this
```

也就是说：

- `this` 本身不能变。
- `this` 指向的对象也不能被修改。

---

## 3. 为什么 `const` 对象只能调用 `const` 成员函数？

```cpp
const Date d1(2024, 4, 14);
d1.Print();
```

如果 `Print` 不是 `const` 成员函数，那么它的 `this` 类型是：

```cpp
Date* const this
```

这相当于把 `const Date*` 权限放大为 `Date*`，不允许。

所以 `Print` 应写成：

```cpp
void Print() const
{
    cout << _year << "-" << _month << "-" << _day << endl;
}
```

---

## 4. 非 `const` 对象可以调用 `const` 成员函数

```cpp
Date d1;
d1.Print();
```

这是允许的，因为：

> 普通对象调用 `const` 成员函数属于权限缩小。

---

## 5. 哪些函数应该加 `const`？

原则：

> 只读取对象状态、不修改成员变量的成员函数，都应该加 `const`。

例如 Date 中：

```cpp
void Print() const;
bool operator<(const Date& d) const;
bool operator==(const Date& d) const;
Date operator+(int day) const;
Date operator-(int day) const;
int operator-(const Date& d) const;
```

不应该加 `const` 的函数：

```cpp
Date& operator+=(int day);
Date& operator-=(int day);
Date& operator++();
Date operator++(int);
```

因为它们会修改当前对象。

---

## 十、取地址运算符重载

## 1. 两种取地址运算符重载

普通对象取地址：

```cpp
Date* operator&()
{
    return this;
}
```

`const` 对象取地址：

```cpp
const Date* operator&() const
{
    return this;
}
```

---

## 2. 一般不需要自己写

取地址运算符重载通常由编译器自动生成即可。

只有极特殊场景才需要自己写，比如：

> 不想让外部拿到对象真实地址，故意返回 `nullptr` 或其他地址。

普通学习和项目中基本不用显式写。

## 十一、易错点汇总

### 易错点 1：误以为默认构造函数只指编译器生成的构造函数

正确：

> 不传实参就能调用的构造函数都叫默认构造函数。

包括：

- 编译器生成的默认构造
- 无参构造
- 全缺省构造

---

### 易错点 2：无参构造实例化对象时加括号

```cpp
Date d(); // 函数声明，不是对象
```

正确：

```cpp
Date d;
```

---

### 易错点 3：以为编译器默认构造会初始化所有成员

默认构造对内置类型成员不保证初始化。

```cpp
int _year;
int _month;
int _day;
```

这些是否被初始化是不确定的。

---

### 易错点 4：有资源申请但不写析构函数

```cpp
_a = (int*)malloc(...);
```

如果不写析构：

```cpp
free(_a);
```

会导致资源泄漏。

---

### 易错点 5：拷贝构造参数写成传值

错误：

```cpp
Date(Date d);
```

正确：

```cpp
Date(const Date& d);
```

传值会导致无限递归调用拷贝构造。

---

### 易错点 6：混淆拷贝构造和赋值重载

```cpp
Date d2 = d1; // 拷贝构造

d2 = d1;      // 赋值运算符重载
```

判断关键：

> 是否在创建新对象。

---

### 易错点 7：Stack 使用默认拷贝构造导致浅拷贝

```cpp
Stack st2 = st1;
```

如果默认拷贝：

```text
两个对象的 _a 指向同一块空间
```

析构时会二次释放。

---

### 易错点 8：返回局部对象引用

错误：

```cpp
Date& Func()
{
    Date tmp;
    return tmp;
}
```

函数结束后 `tmp` 销毁，返回的是野引用。

---

### 易错点 9：返回值不同不能决定运算符重载选择

运算符重载本质也是函数，重载规则仍然不能只靠返回值区分。

---

### 易错点 10：忘记 5 个不能重载的运算符

必须记住：

```text
.*  ::  sizeof  ?:  .
```

---

### 易错点 11：后置 `++` 的 `int` 参数没有实际含义

```cpp
Date operator++(int);
```

这里的 `int` 只是为了和前置 `++` 构成重载。

---

### 易错点 12：`const` 成员函数的 `const` 写错位置

正确：

```cpp
void Print() const;
```

不是：

```cpp
const void Print(); // 不是这个意思
```

- **默认成员函数是用户不写时编译器自动生成的函数，重点掌握构造、析构、拷贝构造、赋值重载。**
- **构造函数负责初始化对象，不负责给对象本身开空间。**

- **析构函数负责对象销毁前释放资源。**
- **有资源申请的类必须考虑析构、拷贝构造、赋值重载。**
- **拷贝构造用于“用已有对象创建新对象”。**
- **赋值重载用于“两个已存在对象之间赋值”。**

## 二、再探构造函数：初始化列表

## 1. 构造函数体赋值 vs 初始化列表

之前写构造函数时，经常在函数体内给成员变量赋值：

```cpp
Date(int year, int month, int day)
{
    _year = year;
    _month = month;
    _day = day;
}
```

但更规范的初始化方式是初始化列表：

```cpp
Date(int year, int month, int day)
    : _year(year)
    , _month(month)
    , _day(day)
{
}
```

初始化列表格式：

```cpp
构造函数名(参数列表)
    : 成员1(初始值)
    , 成员2(初始值)
    , 成员3(初始值)
{
    // 构造函数体
}
```

---

## 2. 初始化列表的本质

初始化列表可以理解为：

> 成员变量真正定义初始化的地方。

函数体内赋值并不是初始化，而是：

> 成员已经初始化完成后，再进行赋值。

这点非常重要。

例如：

```cpp
Date(int year)
    : _year(year) // 初始化
{
    _month = 1;  // 赋值
}
```

---

## 3. 每个成员变量只能在初始化列表中出现一次

错误：

```cpp
Date(int year)
    : _year(year)
    , _year(2024)
{
}
```

一个成员不能被初始化两次。

---

## 4. 必须使用初始化列表的成员

下面三类成员必须放在初始化列表中初始化：

1. 引用成员变量
2. `const` 成员变量
3. 没有默认构造函数的自定义类型成员变量

示例：

```cpp
class Time
{
public:
    Time(int hour)
        : _hour(hour)
    {}

private:
    int _hour;
};

class Date
{
public:
    Date(int& x, int year = 1, int month = 1, int day = 1)
        : _year(year)
        , _month(month)
        , _day(day)
        , _t(12)
        , _ref(x)
        , _n(1)
    {}

private:
    int _year;
    int _month;
    int _day;
    Time _t;      // 没有默认构造
    int& _ref;    // 引用
    const int _n; // const
};
```

如果不放初始化列表，会报错：

- `Time` 没有默认构造函数。
- 引用成员必须初始化。
- `const` 成员必须初始化。

---

## 5. 为什么引用和 const 必须初始化？

### 引用成员

引用定义时必须初始化，且不能重新绑定：

```cpp
int& _ref;
```

所以只能在初始化列表中完成初始化。

---

### const 成员

`const` 成员一旦初始化后不能修改：

```cpp
const int _n;
```

如果不在初始化阶段给值，进入函数体后就不能再赋值了。

---

### 没有默认构造的自定义类型成员

```cpp
Time _t;
```

如果 `Time` 只有：

```cpp
Time(int hour);
```

没有：

```cpp
Time();
```

那么编译器没办法默认构造 `_t`，必须在初始化列表中显式传参：

```cpp
_t(12)
```

---

## 6. C++11 支持成员变量声明处给缺省值

示例：

```cpp
class Date
{
private:
    int _year = 1;
    int _month = 1;
    int _day;
    Time _t = 1;
    const int _n = 1;
    int* _ptr = (int*)malloc(12);
};
```

注意：

> 这里不是初始化，而是给初始化列表提供缺省值。

如果某个成员没有在初始化列表中显式初始化，就会使用声明处给的缺省值。

例如：

```cpp
Date()
    : _month(2)
{
}
```

则：

- `_month` 使用初始化列表中的 `2`。
- `_year` 使用声明处缺省值 `1`。
- `_t` 使用声明处缺省值 `1` 构造。
- `_n` 使用声明处缺省值 `1`。
- `_day` 如果没有缺省值，则是否初始化不确定。

---

## 7. 即使不写初始化列表，成员也会走初始化列表

课件总结非常重要：

> 无论是否显式写初始化列表，每个构造函数都有初始化列表。  
> 无论是否在初始化列表中显式初始化成员变量，每个成员变量都要走初始化列表初始化。

也就是说：

```cpp
Date()
{
}
```

并不代表成员不初始化，而是它们仍然经过默认初始化逻辑。

---

## 8. 初始化顺序由成员声明顺序决定

这是本节最容易考的点之一。

初始化列表中成员的书写顺序不决定真正初始化顺序。

真正顺序由类中成员声明顺序决定。

示例：

```cpp
class A
{
public:
    A(int a)
        : _a1(a)
        , _a2(_a1)
    {}

    void Print()
    {
        cout << _a1 << " " << _a2 << endl;
    }

private:
    int _a2 = 2;
    int _a1 = 2;
};
```

虽然初始化列表写的是：

```cpp
_a1(a), _a2(_a1)
```

但成员声明顺序是：

```cpp
int _a2 = 2;
int _a1 = 2;
```

所以实际先初始化 `_a2`，再初始化 `_a1`。

此时 `_a2(_a1)` 中的 `_a1` 还没有初始化，结果可能是随机值。

因此运行结果不是直觉中的 `1 1`。

复习结论：

> 成员初始化顺序只看声明顺序，不看初始化列表顺序。建议声明顺序和初始化列表顺序保持一致。

---

## 9. 初始化列表使用建议

建议：

> 尽量使用初始化列表初始化成员变量。

原因：

1. 有些成员必须用初始化列表。
2. 初始化列表比函数体赋值更符合对象初始化语义。
3. 对自定义类型成员来说，初始化列表可以避免“先默认构造再赋值”的额外成本。
4. 代码风格更统一。

## 三、类型转换

## 1. 内置类型可以隐式转换为类类型

如果一个类有以某个内置类型为参数的构造函数，那么 C++ 支持从该内置类型隐式转换为类类型对象。

示例：

```cpp
class A
{
public:
    A(int a1)
        : _a1(a1)
    {}

private:
    int _a1 = 1;
    int _a2 = 2;
};
```

可以写：

```cpp
A aa1 = 1;
```

本质：

1. 用 `1` 构造一个 `A` 的临时对象。
2. 再用临时对象拷贝构造 `aa1`。
3. 编译器通常会优化为直接构造。

---

## 2. const 引用可以绑定转换出的临时对象

```cpp
const A& aa2 = 1;
```

本质：

- `1` 先隐式转换成 `A` 临时对象。
- `const A&` 绑定这个临时对象。

这和前面学过的 `const` 引用绑定临时对象是一致的。

---

## 3. C++11 支持多参数隐式转换

例如：

```cpp
class A
{
public:
    A(int a1, int a2)
        : _a1(a1)
        , _a2(a2)
    {}
};
```

C++11 后可以写：

```cpp
A aa3 = { 2, 2 };
```

---

## 4. 类类型之间也可以隐式转换

示例：

```cpp
class B
{
public:
    B(const A& a)
        : _b(a.Get())
    {}

private:
    int _b = 0;
};
```

如果 `B` 有接收 `A` 的构造函数，就可以写：

```cpp
A aa3 = { 2, 2 };
B b = aa3;
const B& rb = aa3;
```

本质：

> 通过构造函数把 `A` 对象转换成 `B` 对象。

---

## 5. explicit 禁止隐式类型转换

如果不希望构造函数支持隐式转换，可以在构造函数前加 `explicit`。

```cpp
class A
{
public:
    explicit A(int a1)
        : _a1(a1)
    {}
};
```

此时不允许：

```cpp
A aa1 = 1; // 错误
```

但可以显式构造：

```cpp
A aa1(1);
A aa2 = A(1);
```

复习结论：

> 单参数构造函数容易触发隐式类型转换，不希望发生时加 `explicit`。

---

## 四、static 成员

## 1. 静态成员变量

用 `static` 修饰的成员变量叫静态成员变量。

```cpp
class A
{
private:
    static int _scount;
};
```

特点：

1. 静态成员变量属于整个类，不属于某个具体对象。
2. 所有对象共享同一份静态成员变量。
3. 静态成员变量不存储在对象中。
4. 静态成员变量存放在静态区。
5. 静态成员变量一定要在类外定义初始化。

类内声明：

```cpp
static int _scount;
```

类外定义初始化：

```cpp
int A::_scount = 0;
```

---

## 2. 静态成员变量不走构造函数初始化列表

静态成员变量不属于某个对象，因此：

> 它不会进入构造函数初始化列表。

所以不能像普通成员那样依赖声明处缺省值给构造函数用。

课件强调：

> 静态成员变量不能在声明位置给缺省值初始化，因为缺省值是给构造函数初始化列表用的，而静态成员不走初始化列表。

注意：现代 C++ 对 `static const` 整型、`inline static` 有更多规则，但按本课当前阶段记课件结论即可。

---

## 3. 静态成员函数

用 `static` 修饰的成员函数叫静态成员函数。

```cpp
static int GetACount()
{
    return _scount;
}
```

特点：

1. 静态成员函数没有 `this` 指针。
2. 静态成员函数可以访问静态成员变量和静态成员函数。
3. 静态成员函数不能直接访问非静态成员变量。
4. 非静态成员函数可以访问静态成员和非静态成员。

为什么静态成员函数不能访问非静态成员？

> 因为非静态成员属于具体对象，访问它们需要 `this` 指针；而静态成员函数没有 `this`。

---

## 4. 静态成员的访问方式

静态成员可以通过类名访问：

```cpp
A::GetACount();
```

也可以通过对象访问：

```cpp
a1.GetACount();
```

但更推荐用类名访问，因为静态成员本来就属于类。

---

## 5. 静态成员也受访问限定符限制

例如：

```cpp
class A
{
private:
    static int _scount;
};
```

外部不能直接访问：

```cpp
cout << A::_scount << endl; // 错误，private
```

可以提供公共静态函数访问：

```cpp
static int GetACount()
{
    return _scount;
}
```

---

## 6. 用 static 统计对象数量

```cpp
class A
{
public:
    A()
    {
        ++_scount;
    }

    A(const A& t)
    {
        ++_scount;
    }

    ~A()
    {
        --_scount;
    }

    static int GetACount()
    {
        return _scount;
    }

private:
    static int _scount;
};

int A::_scount = 0;
```

逻辑：

- 构造对象：数量加一。
- 拷贝构造对象：数量加一。
- 析构对象：数量减一。
- 静态成员变量 `_scount` 记录当前对象数量。

## 7. 牛客题：求 1+2+...+n

利用静态成员变量和对象数组：

```cpp
class Sum
{
public:
    Sum()
    {
        _ret += _i;
        ++_i;
    }

    static int GetRet()
    {
        return _ret;
    }

private:
    static int _i;
    static int _ret;
};

int Sum::_i = 1;
int Sum::_ret = 0;
```

调用：

```cpp
Sum arr[n];
return Sum::GetRet();
```

创建 `n` 个对象，每次构造累加一次。

注意：

> 这个题利用的是构造函数自动调用和静态成员共享状态。

## 五、友元

## 1. 什么是友元？

友元提供了一种突破类访问限定符的方式。

友元分为：

1. 友元函数
2. 友元类

声明方式是在类内部写：

```cpp
friend 函数声明;
friend class 类名;
```

友元可以访问类的 `private` 和 `protected` 成员。

---

## 2. 友元函数

示例：

```cpp
class B;

class A
{
    friend void func(const A& aa, const B& bb);

private:
    int _a1 = 1;
    int _a2 = 2;
};

class B
{
    friend void func(const A& aa, const B& bb);

private:
    int _b1 = 3;
    int _b2 = 4;
};

void func(const A& aa, const B& bb)
{
    cout << aa._a1 << endl;
    cout << bb._b1 << endl;
}
```

注意：

- `func` 可以访问 `A` 和 `B` 的私有成员。
- `func` 不是 `A` 或 `B` 的成员函数。
- 它只是被声明为友元的普通函数。

---

## 3. 友元函数声明位置不受访问限定符限制

友元声明写在：

```cpp
public:
private:
protected:
```

任何位置都可以。

因为友元声明不是类成员，不受访问限定符限制。

---

## 4. 一个函数可以是多个类的友元

如上例：

```cpp
friend void func(const A& aa, const B& bb);
```

`func` 同时是 `A` 和 `B` 的友元函数，因此可以同时访问两者的私有成员。

---

## 5. 友元类

示例：

```cpp
class A
{
    friend class B;

private:
    int _a1 = 1;
    int _a2 = 2;
};

class B
{
public:
    void func1(const A& aa)
    {
        cout << aa._a1 << endl;
    }

    void func2(const A& aa)
    {
        cout << aa._a2 << endl;
    }
};
```

含义：

> `B` 是 `A` 的友元类，所以 `B` 的所有成员函数都可以访问 `A` 的私有和保护成员。

---

## 6. 友元关系的特点

### 特点一：友元关系是单向的

如果：

```cpp
class A
{
    friend class B;
};
```

表示：

> B 可以访问 A 的私有成员。

但不表示：

> A 可以访问 B 的私有成员。

---

### 特点二：友元关系不具有传递性

如果：

```text
A 是 B 的友元
B 是 C 的友元
```

不能推出：

```text
A 是 C 的友元
```

---

### 特点三：友元会破坏封装

友元确实方便，但它允许外部函数或其他类访问私有成员，会增加耦合度。

结论：

> 友元不宜多用，只在确实能明显简化设计时使用。

典型合理场景：

```cpp
operator<<
operator>>
```

因为它们通常需要作为全局函数访问类的私有成员。

---

## 六、内部类

## 1. 什么是内部类？

如果一个类定义在另一个类内部，这个类叫内部类。

```cpp
class A
{
public:
    class B
    {
    public:
        void foo(const A& a)
        {}
    };
};
```

这里 `B` 是 `A` 的内部类。

---

## 2. 内部类是独立的类

重点：

> 内部类是一个独立的类，不是外部类对象的一部分。

例如：

```cpp
class A
{
public:
    class B
    {
        int _b1;
    };

private:
    int _h = 1;
};
```

`sizeof(A)` 不会因为 `B` 中有 `_b1` 就增加。

因为：

> 外部类对象中不包含内部类对象。

---

## 3. 内部类受外部类类域限制

如果 `B` 是 `A` 的内部类，外部使用时要写：

```cpp
A::B b;
```

如果 `B` 放在 `private` 或 `protected` 区域，则类外不能直接使用。

---

## 4. 内部类默认是外部类的友元类

课件重点：

> 内部类默认是外部类的友元类。

因此内部类可以访问外部类的私有成员。

示例：

```cpp
class A
{
private:
    static int _k;
    int _h = 1;

public:
    class B
    {
    public:
        void foo(const A& a)
        {
            cout << _k << endl;    // 可以访问静态私有成员
            cout << a._h << endl;  // 可以通过对象访问非静态私有成员
        }
    };
};
```

注意：

- 访问静态成员 `_k` 不需要对象。
- 访问非静态成员 `_h` 需要通过外部类对象 `a`。

---

## 5. 内部类的使用场景

当一个类主要服务于另一个类，并且二者关系非常紧密时，可以考虑内部类。

例如：

```text
A 类实现出来主要就是给 B 类内部使用
```

可以把 A 设计成 B 的内部类。

如果放到 `private` 区域，就变成 B 的专属内部实现，外部无法直接使用。

这也是一种封装。

---

## 6. 用内部类改写求和题

```cpp
class Solution
{
    class Sum
    {
    public:
        Sum()
        {
            _ret += _i;
            ++_i;
        }
    };

    static int _i;
    static int _ret;

public:
    int Sum_Solution(int n)
    {
        Sum arr[n];
        return _ret;
    }
};
```

这里 `Sum` 只服务于 `Solution`，放成内部类更封装。

---

## 七、匿名对象

## 1. 什么是匿名对象？

普通有名对象：

```cpp
A aa1;
A aa2(2);
```

匿名对象：

```cpp
A();
A(1);
```

定义方式：

```cpp
类型(实参)
```

没有对象名，所以叫匿名对象。

---

## 2. 匿名对象生命周期

匿名对象生命周期：

> 只在当前这一行。

示例：

```cpp
A();
A(1);
A aa2(2);
```

`A();` 和 `A(1);` 创建出的匿名对象，在当前语句结束后立即析构。

---

## 3. 匿名对象适合临时用一下

例如：

```cpp
Solution().Sum_Solution(10);
```

含义：

1. 临时构造一个 `Solution` 匿名对象。
2. 调用它的 `Sum_Solution(10)`。
3. 当前语句结束后匿名对象销毁。

适合场景：

> 只需要临时调用一次成员函数，不想专门定义一个对象名。

---

## 4. 匿名对象和函数声明易混点

不能这样定义无参对象：

```cpp
A aa1();
```

这会被理解为函数声明。

但匿名对象可以这样写：

```cpp
A();
```

因为它没有对象名，不会被解释成函数声明。

---

## 八、对象拷贝时的编译器优化

## 1. 为什么会有拷贝优化？

对象传参和返回值过程中可能产生很多临时对象和拷贝构造。

现代编译器为了提高效率，会在不影响程序正确性的前提下：

> 尽可能减少不必要的拷贝。

---

## 2. 优化规则不是完全固定的

课件强调：

> C++ 标准没有严格规定所有优化方式，不同编译器会根据情况自行处理。

不同环境可能看到不同输出：

- VS2019 Debug
- VS2022 Debug
- g++
- clang++

都可能不完全一样。

在 Linux 下可以用：

```bash
g++ test.cpp -fno-elide-constructors
```

关闭构造相关优化，观察原始拷贝过程。

---

## 3. 传值传参场景

示例：

```cpp
void f1(A aa)
{}
```

调用：

```cpp
A aa1;
f1(aa1);
```

一般语义：

- `aa1` 已经存在。
- 传值给形参 `aa`。
- 需要调用拷贝构造。

---

## 4. 隐式类型转换 + 传值传参可能被优化

```cpp
f1(1);
```

语义上可能是：

1. 用 `1` 构造一个临时 `A` 对象。
2. 再拷贝构造形参 `aa`。

但编译器通常会把：

```text
构造 + 拷贝构造
```

优化为：

```text
直接构造形参
```

---

## 5. 匿名对象传参也可能被优化

```cpp
f1(A(2));
```

语义上：

1. 创建匿名对象 `A(2)`。
2. 拷贝构造形参 `aa`。

编译器可能优化为直接构造形参。

---

## 6. 传值返回场景

```cpp
A f2()
{
    A aa;
    return aa;
}
```

语义上：

- 函数内部构造局部对象 `aa`。
- 返回时可能拷贝构造返回临时对象。

但现代编译器可能进行返回值优化，把局部对象和返回对象合并。

---

## 7. 接收返回值时的优化

```cpp
A aa2 = f2();
```

语义上可能涉及：

1. `f2` 内构造局部对象。
2. 拷贝构造返回临时对象。
3. 用返回临时对象拷贝构造 `aa2`。

编译器可能把多次拷贝合并为更少的构造，甚至直接构造 `aa2`。

---

## 8. 赋值场景通常难以完全消除赋值

```cpp
aa1 = f2();
```

这里 `aa1` 已经存在。

即使返回值过程可以优化，最终仍然要把返回结果赋给 `aa1`，所以赋值运算符重载通常仍会参与。

---

## 9. 复习时如何看待拷贝优化？

重点不是死背某个编译器打印几次构造、几次拷贝，而是理解：

1. 从语义上看，哪些地方可能调用构造、拷贝构造、赋值。
2. 从实际运行看，编译器可能优化掉一些临时对象。
3. 不同编译器、不同模式下输出可能不同。

复习结论：

> 学习时先按语义理解调用过程，再知道编译器可能优化，不要用某一次打印结果反推语言规则。

## 九、易错点汇总

### 易错点 1：把构造函数体赋值当成初始化

```cpp
Date(int year)
{
    _year = year;
}
```

这里 `_year = year` 是赋值，不是初始化。

真正初始化发生在初始化列表阶段。

---

### 易错点 2：引用、const、无默认构造成员不放初始化列表

必须放初始化列表：

```cpp
int& _ref;
const int _n;
Time _t; // Time 没有默认构造
```

---

### 易错点 3：误以为初始化列表顺序决定初始化顺序

错误理解：

```cpp
:_a1(a), _a2(_a1)
```

就以为一定先初始化 `_a1`。

正确：

> 初始化顺序只看成员在类中的声明顺序。

---

### 易错点 4：成员声明处的值不是直接初始化对象

```cpp
int _year = 1;
```

它是给初始化列表提供缺省值，不是说类定义时就初始化了对象。

---

### 易错点 5：单参数构造函数导致隐式类型转换

```cpp
A aa = 1;
```

如果不想支持这种写法，构造函数前加：

```cpp
explicit
```

---

### 易错点 6：静态成员变量忘记类外初始化

类内只是声明：

```cpp
static int _scount;
```

类外要定义初始化：

```cpp
int A::_scount = 0;
```

---

### 易错点 7：静态成员函数访问非静态成员

错误原因：

> 静态成员函数没有 `this` 指针，不能直接访问属于具体对象的非静态成员。

---

### 易错点 8：友元函数误认为是成员函数

友元函数不是成员函数。

它只是普通函数，只是被允许访问类的私有和保护成员。

---

### 易错点 9：误以为友元关系双向或可传递

友元关系：

- 单向
- 不传递

---

### 易错点 10：认为内部类对象包含在外部类对象中

内部类只是定义在类域内部的独立类。

外部类对象不自动包含内部类对象。

---

### 易错点 11：匿名对象生命周期以为很长

匿名对象生命周期只在当前语句。

```cpp
A(1); // 这一行结束就析构
```

---

### 易错点 12：根据打印次数死背拷贝优化

不同编译器可能输出不同构造/拷贝次数。

正确做法：

> 先理解语义，再理解优化。

---

## 十一、一页纸记忆版

如果只记最核心内容，记下面这些：

- **初始化列表是成员真正初始化的地方，构造函数体内是赋值。**
- **引用成员、`const` 成员、无默认构造的自定义类型成员必须放初始化列表。**
- **每个构造函数都有初始化列表，每个成员都会走初始化列表。**
- **成员初始化顺序只看声明顺序，不看初始化列表书写顺序。**

- **单参数构造函数可能导致隐式类型转换，不想允许就加 `explicit`。**
- **静态成员变量属于类，所有对象共享，不存在对象中，类外初始化。**
- **静态成员函数没有 `this`，不能直接访问非静态成员。**
- **友元可以访问私有成员，但不是类成员，会破坏封装，不宜滥用。**
- **友元关系单向、不传递。**
- **内部类是独立类，不占外部类对象空间，默认是外部类友元。**
- **匿名对象生命周期只在当前语句。**
- **编译器会优化对象拷贝，打印次数可能因编译器不同而不同。**

### 第一优先级：初始化列表

重点掌握：

```text

必须初始化列表的三类成员

成员声明处缺省值的作用
```

尤其是下面这题要能秒判断：

```cpp
class A
{
public:

private:
    int _a2 = 2;
    int _a1 = 2;
};
```

结论：

> 先初始化 `_a2`，此时 `_a1` 未初始化，所以结果不是 `1 1`。

重点掌握：

这些背后的临时对象和构造逻辑。

如果不想支持隐式转换，加：

```cpp
explicit
```

重点掌握：

### 第五优先级：匿名对象和拷贝优化

# C/C++ 内存管理复习总结

## 一、本讲核心主线

这一讲主要解决三个问题：

1. C/C++ 程序中的变量分别存在哪里？
2. C 和 C++ 分别如何动态申请和释放堆空间？
3. `malloc/free` 和 `new/delete` 到底有什么区别？

一句话概括：

> `malloc/free` 只负责堆空间申请和释放；`new/delete` 除了申请和释放空间，还会对自定义类型自动调用构造函数和析构函数。

## 二、C/C++ 内存分布

常见内存区域：

| 区域 | 存放内容 |
|---|---|
| 栈 | 非静态局部变量、函数参数、返回值等 |
| 堆 | 程序运行时动态申请的空间 |
| 数据段 / 静态区 | 全局变量、静态变量 |
| 代码段 / 常量区 | 可执行代码、只读常量、字符串常量 |
| 内存映射段 | 动态库映射、共享内存等，了解即可 |

---

## 三、典型变量位置判断

示例：

```cpp
int globalVar = 1;
static int staticGlobalVar = 1;

void Test()
{
    static int staticVar = 1;
    int localVar = 1;
    int num1[10] = { 1, 2, 3, 4 };
    char char2[] = "abcd";
    const char* pChar3 = "abcd";
    int* ptr1 = (int*)malloc(sizeof(int) * 4);
}
```

重点结论：

| 名称 | 所在区域 | 原因 |
|---|---|---|
| `globalVar` | 数据段 / 静态区 | 全局变量 |
| `staticGlobalVar` | 数据段 / 静态区 | 静态全局变量 |
| `staticVar` | 数据段 / 静态区 | 静态局部变量 |
| `localVar` | 栈 | 普通局部变量 |
| `num1` | 栈 | 局部数组整体在栈上 |
| `char2` | 栈 | 局部字符数组整体在栈上 |
| `*char2` | 栈 | 数组元素在数组内部 |
| `pChar3` | 栈 | 局部指针变量本身在栈上 |
| `*pChar3` | 代码段 / 常量区 | 指向字符串常量 |
| `ptr1` | 栈 | 局部指针变量本身在栈上 |
| `*ptr1` | 堆 | `malloc` 申请的空间 |

最容易错的是：

```cpp
char char2[] = "abcd";      // 字符数组，内容拷贝到栈上
const char* pChar3 = "abcd"; // 指针在栈上，字符串常量在常量区
```

---

## 四、C 语言动态内存管理

C 语言中常用：

```cpp
malloc
calloc
realloc
free
```

### 1. `malloc`

```cpp
int* p = (int*)malloc(sizeof(int) * 4);
```

特点：

- 在堆上申请指定字节数的空间。
- 不初始化申请到的空间。
- 返回 `void*`，C++ 中需要强转。
- 申请失败返回 `NULL`。

---

### 2. `calloc`

```cpp
int* p = (int*)calloc(4, sizeof(int));
```

特点：

- 申请 `4` 个 `int` 大小的空间。
- 会把空间初始化为 `0`。

---

### 3. `realloc`

```cpp
int* p2 = (int*)realloc(p1, sizeof(int) * 10);
```

特点：

- 调整原动态内存块大小。
- 可能原地扩容，也可能重新开空间并拷贝旧数据。
- 返回新地址。

注意：

```cpp
int* p3 = (int*)realloc(p2, sizeof(int) * 10);
free(p3);
```

这里不需要再 `free(p2)`，因为 `realloc` 成功后应以返回的新指针为准。

---

### 4. `free`

```cpp
free(p);
```

特点：

- 释放堆空间。
- 只释放空间，不会调用析构函数。

---

## 五、C++ 动态内存管理：`new/delete`

C++ 中推荐使用：

```cpp
new
delete
new[]
delete[]
```

### 1. 操作内置类型

```cpp
int* p1 = new int;
int* p2 = new int(10);
int* p3 = new int[3];

delete p1;
delete p2;
delete[] p3;
```

注意匹配：

| 申请 | 释放 |
|---|---|
| `new` | `delete` |
| `new[]` | `delete[]` |

一定要匹配使用。

---

### 2. 操作自定义类型

```cpp
class A
{
public:
    A() { cout << "A()" << endl; }
    ~A() { cout << "~A()" << endl; }
};

A* p = new A;
delete p;
```

核心区别：

- `new A`：申请空间 + 调用构造函数。
- `delete p`：调用析构函数 + 释放空间。

而：

```cpp
A* p = (A*)malloc(sizeof(A));
free(p);
```

只会申请和释放空间，不会调用构造和析构。

---

## 六、`operator new` 和 `operator delete`

重点区分：

| 名称 | 本质 |
|---|---|
| `new` | 操作符，用户使用 |
| `delete` | 操作符，用户使用 |
| `operator new` | 全局函数，底层负责申请空间 |
| `operator delete` | 全局函数，底层负责释放空间 |

`new` 的底层会调用 `operator new`。  
`delete` 的底层会调用 `operator delete`。

大致关系：

```text
new -> operator new -> malloc

delete -> operator delete -> free
```

`operator new` 申请失败时通常会抛出 `bad_alloc` 异常，而不是像 `malloc` 那样返回 `NULL`。

---

## 七、`new/delete` 实现原理

### 1. 内置类型

对于内置类型：

```cpp
int* p1 = (int*)malloc(sizeof(int));
int* p2 = new int;
```

差别相对较小。

主要区别：

- `malloc` 失败返回 `NULL`。
- `new` 失败抛异常。
- `new` 写法更简单，不用手动计算字节数和强转。

---

### 2. 自定义类型的 `new` 原理

```cpp
A* p = new A(10);
```

步骤：

1. 调用 `operator new` 申请空间。
2. 在申请到的空间上调用构造函数，完成对象构造。

---

### 3. 自定义类型的 `delete` 原理

```cpp
delete p;
```

步骤：

1. 调用析构函数，清理对象内部资源。
2. 调用 `operator delete` 释放对象空间。

---

### 4. `new T[N]` 原理

```cpp
A* p = new A[10];
```

步骤：

1. 调用 `operator new[]` 申请连续空间。
2. 实际底层会调用 `operator new`。
3. 对 N 个对象分别调用构造函数。

---

### 5. `delete[]` 原理

```cpp
delete[] p;
```

步骤：

1. 对 N 个对象分别调用析构函数。
2. 调用 `operator delete[]` 释放空间。
3. 实际底层会调用 `operator delete`。

---

## 八、定位 new：`placement new`

定位 `new` 的作用：

> 在已经分配好的原始内存空间上调用构造函数初始化对象。

格式：

```cpp
new(place_address) Type;
new(place_address) Type(initializer-list);
```

示例：

```cpp
A* p = (A*)malloc(sizeof(A));
new(p) A(10);
p->~A();
free(p);
```

解释：

1. `malloc` 只申请一段原始空间，还不是对象。
2. `new(p) A(10)` 在这段空间上调用构造函数。
3. `p->~A()` 显式调用析构函数。
4. `free(p)` 释放空间。

使用场景：

> 常和内存池配合使用。内存池只提供原始内存，自定义类型对象还需要显式构造。

---

## 九、`malloc/free` 和 `new/delete` 的区别

共同点：

> 都是从堆上申请空间，都需要用户手动释放。

区别：

| 对比项 | `malloc/free` | `new/delete` |
|---|---|---|
| 本质 | 函数 | 操作符 |
| 空间大小 | 手动计算字节数 | 根据类型自动计算 |
| 返回类型 | `void*`，C++ 中需强转 | 返回对应类型指针 |
| 初始化 | `malloc` 不初始化，`calloc` 清零 | `new` 可以初始化 |
| 失败处理 | 返回 `NULL` | 抛异常 |
| 自定义类型 | 不调用构造 / 析构 | 自动调用构造 / 析构 |
| 数组申请 | 手动算总大小 | `new[]` 指定对象个数 |
| 释放方式 | `free` | `delete` / `delete[]` |

最重要区别：

> 对自定义类型，`new/delete` 会调用构造函数和析构函数，`malloc/free` 不会。

---

## 十、易错点汇总

1. `char arr[] = "abcd"` 的内容在栈上，`const char* p = "abcd"` 指向常量区。
2. 指针变量本身在哪里，看它怎么定义；它指向哪里，看它保存的地址来自哪里。
3. `malloc` 申请失败返回 `NULL`，`new` 失败抛异常。
4. `new` / `delete` 要配对，`new[]` / `delete[]` 要配对。
5. `malloc/free` 不会调用构造和析构。
6. `operator new` 不是 `new` 操作符本身，而是底层申请空间的函数。
7. 定位 `new` 只调用构造函数，不负责申请空间。
8. 用定位 `new` 构造的对象，需要手动调用析构函数。

---

## 十一、一页纸记忆版

- **栈：局部变量、参数、返回值。**
- **堆：动态申请空间。**
- **数据段：全局变量、静态变量。**
- **代码段 / 常量区：代码、只读常量、字符串常量。**
- **`malloc/free` 是函数，只管空间。**
- **`new/delete` 是操作符，既管空间，也管构造和析构。**
- **内置类型下，`new/delete` 和 `malloc/free` 差别较小。**
- **自定义类型下，差别巨大：构造和析构是否自动调用。**
- **`new` 底层调用 `operator new`，`operator new` 通常再调用 `malloc`。**
- **`delete` 先析构，再调用 `operator delete` 释放空间。**
- **定位 `new` 是在已有空间上显式构造对象。**

---

## 十二、二刷重点建议

优先复习：

1. 内存区域判断题。
2. `char[]` 和 `const char*` 指向字符串常量的区别。
3. `new/delete` 操作自定义类型时的构造、析构调用。
4. `operator new/delete` 与 `new/delete` 的区别。
5. `new[]/delete[]` 的匹配使用。
6. `malloc/free` 和 `new/delete` 面试区别表。
# C++ 模板初阶复习总结

> 来源：`06.模板初阶.pdf`  
> 定位：已学一遍后的复习笔记，重点用于快速回忆泛型编程、函数模板、类模板、模板实例化和匹配规则。

---

## 一、本讲核心主线

模板初阶主要解决一个问题：

> 如何写一份与类型无关的通用代码，让编译器根据不同类型自动生成对应代码？

核心内容：

1. 泛型编程思想
2. 函数模板
3. 函数模板实例化
4. 函数模板匹配规则
5. 类模板
6. 类模板实例化

一句话概括：

> 模板是 C++ 泛型编程的基础，它把重复写多份不同类型代码的工作交给编译器完成。

---

## 二、泛型编程

### 1. 为什么需要泛型编程？

如果要写交换函数，普通做法可能是函数重载：

```cpp
void Swap(int& left, int& right)
{
    int temp = left;
    left = right;
    right = temp;
}

void Swap(double& left, double& right)
{
    double temp = left;
    left = right;
    right = temp;
}

void Swap(char& left, char& right)
{
    char temp = left;
    left = right;
    right = temp;
}
```

问题：

1. 代码逻辑完全一样，只是类型不同。
2. 每出现一个新类型，就要新增一个函数。
3. 代码复用率低。
4. 维护成本高，一个逻辑错误可能每个重载版本都要改。

---

### 2. 泛型编程的思想

泛型编程：

> 编写与类型无关的通用代码，是代码复用的一种重要手段。

模板就是泛型编程的基础。

可以把模板理解成一个“模具”：

```text
模板 = 模具
类型 = 材料
实例化后的函数/类 = 具体成品
```

---

## 三、函数模板

### 1. 函数模板概念

函数模板代表一个函数家族。

特点：

- 它本身不是某一个具体函数。
- 它与具体类型无关。
- 使用时根据实参类型生成对应类型版本的函数。

---

### 2. 函数模板格式

```cpp
template<typename T>
返回值类型 函数名(参数列表)
{
}
```

也可以写：

```cpp
template<class T>
```

注意：

> `typename` 和 `class` 在模板参数中都可以使用，但不能用 `struct` 替代这里的 `class`。

---

### 3. 通用 Swap 函数模板

```cpp
template<typename T>
void Swap(T& left, T& right)
{
    T temp = left;
    left = right;
    right = temp;
}
```

调用：

```cpp
int a = 1, b = 2;
Swap(a, b);

double x = 1.1, y = 2.2;
Swap(x, y);
```

编译器会根据实参类型生成：

```cpp
void Swap(int& left, int& right);
void Swap(double& left, double& right);
```

---

## 四、函数模板的原理

### 1. 函数模板不是函数

重点：

> 函数模板本身不是函数，而是编译器生成具体函数的蓝图。

编译期间，编译器会根据模板使用情况生成具体类型的函数。

例如：

```cpp
Swap(a, b); // a、b 是 int
```

编译器推导出：

```cpp
T = int
```

于是生成一份处理 `int` 的 `Swap` 函数。

---

### 2. 模板把重复工作交给编译器

原来需要程序员手写：

```cpp
Swap(int&)
Swap(double&)
Swap(char&)
```

使用模板后：

> 程序员写一份模板，编译器按需生成多份具体函数。

---

## 五、函数模板实例化

用不同类型的参数使用函数模板，称为函数模板实例化。

分为：

1. 隐式实例化
2. 显式实例化

---

## 1. 隐式实例化

让编译器根据实参类型推导模板参数。

```cpp
template<class T>
T Add(const T& left, const T& right)
{
    return left + right;
}

int a1 = 10, a2 = 20;
double d1 = 10.0, d2 = 20.0;

Add(a1, a2); // T 推导为 int
Add(d1, d2); // T 推导为 double
```

---

## 2. 隐式实例化的类型冲突

```cpp
Add(a1, d1);
```

如果模板是：

```cpp
template<class T>
T Add(const T& left, const T& right)
```

编译器推导：

- 根据 `a1` 推导 `T = int`
- 根据 `d1` 推导 `T = double`

同一个 `T` 推导出两个类型，编译器无法决定，因此报错。

---

## 3. 解决方式一：强制类型转换

```cpp
Add(a1, (int)d1);
```

此时两个实参都可以推导为 `int`。

---

## 4. 解决方式二：显式实例化

显式指定模板参数类型：

```cpp
Add<int>(a1, d1);
```

表示强制实例化出 `T = int` 的版本。

如果类型不匹配，编译器会尝试隐式类型转换。

---

## 六、模板参数匹配原则

### 1. 普通函数和函数模板可以同名共存

```cpp
int Add(int left, int right)
{
    return left + right;
}

template<class T>
T Add(T left, T right)
{
    return left + right;
}
```

这两个可以同时存在。

---

### 2. 普通函数和模板都匹配时，优先普通函数

```cpp
Add(1, 2);
```

如果普通函数完全匹配，编译器优先调用普通函数，而不是从模板生成一个实例。

---

### 3. 如果模板能生成更匹配的版本，会选择模板

例如：

```cpp
int Add(int left, int right);

template<class T1, class T2>
T1 Add(T1 left, T2 right);

Add(1, 2.0);
```

普通函数需要把 `2.0` 转成 `int`。

模板可以生成：

```cpp
Add(int, double)
```

更匹配，所以会选择模板。

---

### 4. 模板一般不主动做类型转换

课件重点：

> 在模板中，编译器一般不会进行类型转换操作，因为一旦转换出问题，编译器就需要背锅。

例如：

```cpp
template<class T>
T Add(T left, T right);

Add(1, 2.0); // T 推导冲突，通常报错
```

除非你显式指定模板参数：

```cpp
Add<int>(1, 2.0);
```

---

## 七、类模板

## 1. 类模板定义格式

```cpp
template<class T1, class T2, ..., class Tn>
class 类模板名
{
    // 类内成员定义
};
```

示例：

```cpp
template<typename T>
class Stack
{
public:
    Stack(size_t capacity = 4)
    {
        _array = new T[capacity];
        _capacity = capacity;
        _size = 0;
    }

    void Push(const T& data);

private:
    T* _array;
    size_t _capacity;
    size_t _size;
};
```

---

## 2. 类模板成员函数在类外定义

类外定义成员函数时要写模板参数：

```cpp
template<class T>
void Stack<T>::Push(const T& data)
{
    _array[_size] = data;
    ++_size;
}
```

注意两点：

1. 前面要写：

```cpp
template<class T>
```

2. 类名位置要写：

```cpp
Stack<T>::
```

---

## 3. 模板不建议声明和定义分离到 `.h` 和 `.cpp`

课件强调：

> 模板不建议像普通函数那样声明放 `.h`、定义放 `.cpp`，否则容易出现链接错误。

当前阶段先记结论：

> 模板通常把声明和定义都放在头文件中。

后面深入模板编译原理时再理解原因。

---

## 八、类模板实例化

类模板实例化和函数模板不同。

函数模板可以根据实参自动推导：

```cpp
Swap(a, b);
```

但类模板使用时通常需要显式写类型：

```cpp
Stack<int> st1;
Stack<double> st2;
```

重点：

> `Stack` 是类模板名，不是真正的类型；`Stack<int>` 才是真正的类型。

---

## 九、易错点汇总

### 易错点 1：把函数模板当成函数

函数模板不是函数，而是生成函数的模具。

---

### 易错点 2：模板参数中用 `struct`

正确：

```cpp
template<typename T>
template<class T>
```

错误：

```cpp
template<struct T>
```

---

### 易错点 3：同一个 `T` 被推导成不同类型

```cpp
Add(1, 2.0);
```

如果模板只有一个 `T`，编译器无法同时让 `T` 是 `int` 和 `double`。

---

### 易错点 4：以为模板会自动类型转换

模板推导阶段通常不会主动做类型转换。

要么手动强转：

```cpp
Add(1, (int)2.0);
```

要么显式实例化：

```cpp
Add<int>(1, 2.0);
```

---

### 易错点 5：类模板实例化忘记写 `<类型>`

错误：

```cpp
Stack st;
```

正确：

```cpp
Stack<int> st;
```

---

### 易错点 6：类模板成员函数类外定义忘记 `Stack<T>::`

正确：

```cpp
template<class T>
void Stack<T>::Push(const T& data)
{
}
```

---

## 十、一页纸记忆版

- **泛型编程：写与类型无关的通用代码。**
- **模板是泛型编程的基础。**
- **函数模板不是函数，是生成函数的蓝图。**
- **模板实例化：编译器根据类型生成具体函数或类。**
- **隐式实例化：编译器根据实参推导类型。**
- **显式实例化：程序员用 `<>` 指定类型。**
- **同一个模板参数不能同时推导成多个类型。**
- **普通函数和模板都匹配时，普通函数优先。**
- **模板能生成更匹配版本时，会选择模板。**
- **模板一般不会在推导阶段主动做类型转换。**
- **`Stack` 是类模板名，`Stack<int>` 才是真正类型。**
- **模板定义通常放头文件，不建议声明定义分离到 `.h/.cpp`。**

## 一、本讲核心主线

这一讲主要是 STL 的入门介绍，重点不是具体使用细节，而是建立整体框架：

1. STL 是什么
2. STL 有哪些版本
3. STL 的六大组件

5. STL 应该怎么学

一句话概括：

> STL 是 C++ 标准库的重要组成部分，它把常用数据结构和算法做成了可复用的软件框架，让我们不用重复造轮子。

## 二、什么是 STL

STL 全称：

```text
Standard Template Library
标准模板库
```

它是 C++ 标准库的重要组成部分。

STL 不只是一个简单的组件库，而是：

> 包含数据结构与算法的软件框架。

它提供了大量通用组件，例如：

- 顺序表 / 动态数组：`vector`
- 链表：`list`
- 栈：`stack`
- 队列：`queue`
- 优先级队列：`priority_queue`
- 集合：`set`
- 映射：`map`
- 哈希表相关容器：`unordered_map`、`unordered_set`
- 通用算法：排序、查找、遍历等

## 三、STL 的版本

课件中介绍了几个 STL 版本，复习时不需要死背细节，但要知道 SGI 版本比较重要。

---

### 1. 原始版本 / HP 版本

由：

- Alexander Stepanov
- Meng Lee

在惠普实验室完成。

特点：

- STL 的原始版本。
- 具有开源精神。
- 是所有 STL 实现版本的始祖。

---

### 2. P. J. 版本

由 P. J. Plauger 开发。

特点：

- 继承自 HP 版本。
- 被 Windows Visual C++ 采用。
- 不能公开或修改。
- 可读性较低，符号命名较怪。

---

### 3. RW 版本

由 Rouge Wage 公司开发。

特点：

- 继承自 HP 版本。
- 被 C++ Builder 采用。
- 不能公开或修改。
- 可读性一般。

---

### 4. SGI 版本

由 Silicon Graphics Computer Systems 公司开发。

特点：

- 继承自 HP 版本。
- 被 GCC / Linux 采用。
- 可移植性好。
- 可以公开、修改甚至贩卖。
- 命名风格和编程风格可读性较高。

复习重点：

> 后续学习 STL 源码时，主要参考 SGI 版本。

## 四、STL 的六大组件

STL 通常分为六大组件：

| 组件 | 作用 |
|---|---|
| 容器 | 存储数据的数据结构 |
| 算法 | 操作数据的通用算法 |
| 迭代器 | 连接容器和算法，类似泛化指针 |
| 仿函数 | 像函数一样使用的对象 |
| 适配器 | 对已有组件进行包装转换 |
| 空间配置器 | 负责内存申请和释放 |

---

### 1. 容器

容器用于存储数据。

常见容器：

```cpp
vector
list
deque
stack
queue
priority_queue
set
map
unordered_set
unordered_map
```

可以把容器理解为：

> STL 中封装好的常用数据结构。

---

### 2. 算法

算法用于操作容器中的数据。

例如：

```cpp
sort
find
count
reverse
lower_bound
upper_bound
```

算法通常不直接依赖某一种容器，而是通过迭代器操作数据。

---

### 3. 迭代器

迭代器是 STL 中非常核心的概念。

作用：

> 连接容器和算法。

可以把迭代器先粗略理解为：

> 类似指针的东西，用来访问容器中的元素。

例如：

```cpp
vector<int> v;
vector<int>::iterator it = v.begin();
```

后面学习 STL 时，迭代器是重点。

---

### 4. 仿函数

仿函数是像函数一样使用的对象。

本质通常是重载了 `operator()` 的类对象。

例如后续可能看到：

```cpp
greater<int>()
less<int>()
```

当前阶段了解即可。

---

### 5. 适配器

适配器是对已有组件做包装，让它表现出另一种使用形式。

典型例子：

```cpp
stack
queue
priority_queue
```

它们底层通常依赖已有容器实现，但对外提供特定接口。

例如：

- `stack` 提供栈接口。
- `queue` 提供队列接口。
- `priority_queue` 提供堆 / 优先级队列接口。

---

### 6. 空间配置器

空间配置器负责内存管理。

它是 STL 底层组件，主要负责：

- 空间申请
- 空间释放
- 对象构造
- 对象析构

当前阶段知道它是 STL 的底层内存管理组件即可。

## 五、STL 的重要性

### 1. 笔试中常见

课件提到的笔试题：

- 二叉树层序打印
- 重建二叉树
- 两个栈实现一个队列

这些题虽然是数据结构题，但如果熟悉 STL，可以更快写出代码。

例如：

- 层序遍历常用 `queue`。
- 两个栈实现队列可以用 `stack`。
- 查找映射关系可能用 `map` / `unordered_map`。

---

### 2. 面试中常见

面试中 STL 常考：

- 容器使用场景
- `vector` 扩容机制
- `list` 和 `vector` 区别
- `map` 和 `unordered_map` 区别
- 迭代器失效
- 常见算法复杂度
- 底层数据结构

这一讲只是简介，后续学习每个容器时要重点掌握底层原理。

---

### 3. 工作中重要

课件中提到一句话：

> 不懂 STL，不要说你会 C++。

原因：

- STL 提供大量成熟数据结构和算法。
- 能避免重复造轮子。
- 能显著提高开发效率。
- 很多工程代码都会大量使用 STL。

## 六、如何学习 STL

课件总结：

```text
能用，明理，能扩展
```

这三个层次非常重要。

---

### 第一层：能用

目标：

> 会查文档，会使用常见容器和算法解决问题。

例如：

- 会用 `vector` 存数组。
- 会用 `stack` 模拟栈。
- 会用 `queue` 做 BFS。
- 会用 `map` 统计映射关系。
- 会用 `sort` 排序。

这是刷题和项目的基础。

---

### 第二层：明理

目标：

> 理解 STL 容器和算法的底层原理。

例如：

- `vector` 底层是动态数组。
- `list` 底层是链表。
- `map` 底层通常是红黑树。
- `unordered_map` 底层是哈希表。
- `stack` / `queue` 是容器适配器。
- 迭代器失效为什么会发生。

这是面试和深入 C++ 的关键。

---

### 第三层：能扩展

目标：

> 能根据 STL 的思想设计自己的组件，甚至阅读和改造部分源码。

例如：

- 自己实现简单 `vector`。
- 自己实现迭代器。
- 理解空间配置器思想。
- 理解算法和容器如何通过迭代器解耦。

这是进阶方向。

---

## 七、STL 学习建议

结合你已经学过 C++ 类和对象、模板初阶，接下来学习 STL 时建议这样抓重点：

### 1. 先会用

先掌握常见容器基本接口：

```cpp
push_back
pop_back
push
pop
insert
erase
find
size
empty
begin
end
```

不要一开始就陷入源码细节。

---

### 2. 再理解底层结构

每学一个容器，都问：

1. 底层是什么数据结构？
2. 插入删除复杂度是多少？
3. 查找复杂度是多少？
4. 什么时候迭代器会失效？
5. 适合什么场景？

---

### 3. 最后做对比

STL 很多容器要通过对比来记：

| 对比 | 重点 |
|---|---|
| `vector` vs `list` | 连续空间 vs 链式空间 |
| `map` vs `unordered_map` | 红黑树 vs 哈希表 |
| `set` vs `map` | 只存 key vs 存 key-value |
| `stack` vs `queue` | 后进先出 vs 先进先出 |
| `deque` vs `vector` | 分段连续 vs 完全连续 |

---

## 八、易错点汇总

1. STL 不只是容器，还包括算法、迭代器、仿函数、适配器、空间配置器。
2. STL 是标准库的重要组成部分，不是某一个单独容器。
3. `stack`、`queue`、`priority_queue` 更准确地说是容器适配器。
4. 学 STL 不能只停留在会调接口，面试还要理解底层原理。
5. 迭代器是连接容器和算法的核心，后续要重点掌握。
6. SGI STL 版本可读性较高，后续源码学习主要参考它。
