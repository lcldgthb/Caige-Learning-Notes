## 三、C++ 的第一个程序

### 1. C 风格写法仍然可用

C++ 兼容 C 语言绝大多数语法，所以 C 的 `hello world` 仍然可以运行。

```cpp
#include <stdio.h>

int main()
{
    printf("hello world\n");
    return 0;
}
```

注意：

- C++ 源文件后缀一般是 `.cpp`。
- Windows / VS 中 `.cpp` 会调用 C++ 编译器。
- Linux 下 C++ 程序通常用 `g++` 编译，而不是 `gcc`。

---

### 2. C++ 风格写法

```cpp
#include <iostream>
using namespace std;

int main()
{
    cout << "hello world" << endl;
    return 0;
}
```

几个关键词：

| 写法 | 含义 |
|---|---|
| `#include <iostream>` | 引入 C++ 输入输出流库 |
| `using namespace std;` | 展开标准命名空间 |
| `cout` | 标准输出对象 |
| `<<` | 流插入运算符 |
| `endl` | 换行并刷新缓冲区 |

## 四、命名空间 `namespace`

## 1. 为什么需要命名空间？

C / C++ 中变量、函数、类型名都可能出现在全局作用域中，容易产生命名冲突。

例如：

```cpp
#include <stdlib.h>

int rand = 10;
```

这里自定义变量 `rand` 可能和库函数 `rand` 冲突。

命名空间的作用：

> 把标识符放到一个独立的域中，避免命名冲突和名字污染。

---

## 2. 命名空间定义

```cpp
namespace bit
{
    int rand = 10;

    int Add(int left, int right)
    {
        return left + right;
    }

    struct Node
    {
        Node* next;
        int val;
    };
}
```

命名空间中可以定义：

- 变量
- 函数
- 类型
- 结构体
- 类
- 其他命名空间

本质：

> `namespace` 定义了一个新的作用域。

---

## 3. 域的种类

 C++ 常见的域：

- 局部域
- 全局域
- 命名空间域
- 类域

注意区别：

| 域 | 是否影响名字查找 | 是否影响变量生命周期 |
|---|---:|---:|
| 局部域 | 是 | 是 |
| 全局域 | 是 | 是 |
| 命名空间域 | 是 | 不直接影响 |
| 类域 | 是 | 不直接影响 |

重点：

> 域主要影响编译时查找变量、函数、类型声明或定义的规则。

---

## 4. 命名空间可以嵌套

```cpp
namespace bit
{
    namespace pg
    {
        int rand = 1;
        int Add(int left, int right)
        {
            return left + right;
        }
    }

    namespace hg
    {
        int rand = 2;
        int Add(int left, int right)
        {
            return (left + right) * 10;
        }
    }
}
```

访问方式：

```cpp
bit::pg::rand;
bit::hg::rand;
bit::pg::Add(1, 2);
bit::hg::Add(1, 2);
```

---

## 5. 多文件中的同名命名空间会合并

多个文件中可以定义同名 `namespace`，它们会被认为是同一个命名空间。

例如：

```cpp
// Stack.h
namespace bit
{
    struct Stack;
    void STInit(Stack* ps);
}

// Queue.h
namespace bit
{
    struct Queue;
    void QueueInit(Queue* pq);
}
```

这两个 `bit` 命名空间不会冲突，而是合并。

---

## 6. 命名空间的三种使用方式

### 方式一：指定命名空间访问

```cpp
std::cout << "hello" << std::endl;
bit::STInit(&st);
```

特点：

- 最安全
- 不容易冲突
- 项目开发中推荐

---

### 方式二：展开某个成员

```cpp
using std::cout;
using std::endl;

cout << "hello" << endl;
```

特点：

- 比完全展开更安全
- 适合经常使用且不容易冲突的成员

---

### 方式三：展开整个命名空间

```cpp
using namespace std;
```

特点：

- 写代码方便
- 但容易引入命名冲突
- 日常练习可以用
- 实际项目不推荐滥用

## 五、C++ 输入输出

### 1. 基本对象

```cpp
#include <iostream>
```

`iostream` 是标准输入输出流库。

常见对象：

| 对象 | 含义 |
|---|---|
| `std::cin` | 标准输入对象 |
| `std::cout` | 标准输出对象 |
| `std::endl` | 换行并刷新缓冲区 |

---

### 2. 流插入和流提取

```cpp
cout << a << endl;
cin >> a;
```

| 运算符 | 在 IO 中的含义 |
|---|---|
| `<<` | 流插入，用于输出 |
| `>>` | 流提取，用于输入 |

注意：

> `<<` 和 `>>` 在 C 语言中也可以表示位移运算，C++ IO 中通过运算符重载让它们具有输入输出含义。

---

### 3. C++ IO 的优点

相比 `printf` / `scanf`，C++ IO 的优势：

- 不需要手动写格式控制符。
- 能自动识别变量类型。
- 更适合后续自定义类型对象的输入输出。

例如：

```cpp
int a = 0;
double b = 0.1;
char c = 'x';

cout << a << " " << b << " " << c << endl;
cin >> a >> b >> c;
```

---

### 4. 竞赛中提高 C++ IO 效率

在大量输入输出的场景中，可以加：

```cpp
ios_base::sync_with_stdio(false);
cin.tie(nullptr);
cout.tie(nullptr);
```

常见竞赛写法：

```cpp
#include <iostream>
using namespace std;

int main()
{
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    cout.tie(nullptr);

    return 0;
}
```

注意：

> 关闭同步后，不建议混用 `cin/cout` 和 `scanf/printf`，否则可能出现输入输出顺序或缓冲问题。

## 六、缺省参数

### 1. 缺省参数概念

缺省参数也叫默认参数。

定义：

> 在声明或定义函数时，为函数参数指定一个默认值。调用时如果不传实参，就使用默认值；如果传了实参，就使用传入的值。

例如：

```cpp
void Func(int a = 0)
{
    cout << a << endl;
}

Func();    // 使用默认值 0
Func(10);  // 使用传入值 10
```

---

### 2. 全缺省参数

所有参数都有默认值：

```cpp
void Func1(int a = 10, int b = 20, int c = 30)
{
}
```

调用方式：

```cpp
Func1();
Func1(1);
Func1(1, 2);
Func1(1, 2, 3);
```

---

### 3. 半缺省参数

部分参数有默认值：

```cpp
void Func2(int a, int b = 10, int c = 20)
{
}
```

正确调用：

```cpp
Func2(100);
Func2(100, 200);
Func2(100, 200, 300);
```

---

### 4. 半缺省参数必须从右往左连续给

正确：

```cpp
void Func(int a, int b = 10, int c = 20);
```

错误：

```cpp
void Func(int a = 10, int b, int c = 20); // 错误
```

原因：

> 函数调用传参是从左往右依次匹配的，不能跳跃传参。

---

### 5. 声明和定义分离时，缺省参数只能给一次

推荐在声明中给默认值：

```cpp
// Stack.h
void STInit(ST* ps, int n = 4);

// Stack.cpp
void STInit(ST* ps, int n)
{
}
```

错误写法：

```cpp
// 声明和定义都写默认值，错误
void STInit(ST* ps, int n = 4);
void STInit(ST* ps, int n = 4)
{
}
```

重点记忆：

> 缺省参数一般写在函数声明处，函数定义处不要重复写。

## 七、函数重载

### 1. 函数重载概念

C++ 支持在同一作用域中定义多个同名函数，但要求形参不同。

函数重载体现了 C++ 的多态行为。

例如：

```cpp
int Add(int left, int right)
{
    return left + right;
}

double Add(double left, double right)
{
    return left + right;
}
```

调用时编译器根据实参类型选择对应函数：

```cpp
Add(10, 20);       // 调用 int 版本
Add(10.1, 20.2);   // 调用 double 版本
```

---

### 2. 构成函数重载的条件

函数名相同，参数列表不同。

参数列表不同包括：

#### 情况一：参数类型不同

```cpp
int Add(int left, int right);
double Add(double left, double right);
```

#### 情况二：参数个数不同

```cpp
void f();
void f(int a);
```

#### 情况三：参数类型顺序不同

```cpp
void f(int a, char b);
void f(char b, int a);
```

---

### 3. 返回值不同不能构成重载

错误示例：

```cpp
void fxx();
int fxx();
```

原因：

> 函数调用时通常无法仅根据返回值判断要调用哪个函数。

例如：

```cpp
fxx(); // 编译器不知道选 void 版本还是 int 版本
```

---

### 4. 缺省参数可能导致调用歧义

```cpp
void f1()
{
}

void f1(int a = 10)
{
}
```

这两个函数本身可以构成重载，但调用时：

```cpp
f1();
```

会产生歧义，因为：

- 可以调用无参版本。
- 也可以调用带默认参数的版本。

结论：

> 函数能构成重载，不代表每种调用都没有歧义。

## 八、引用

## 1. 引用的概念

引用不是新定义一个变量，而是给已存在变量取别名。

格式：

```cpp
类型& 引用名 = 被引用对象;
```

例如：

```cpp
int a = 0;
int& b = a;
int& c = a;
```

这里：

- `b` 是 `a` 的别名。
- `c` 也是 `a` 的别名。
- 操作 `b` 或 `c`，本质上就是操作 `a`。

```cpp
++b;
```

等价于：

```cpp
++a;
```

---

## 2. 引用和取地址符号的区别

`&` 在不同场景下含义不同：

```cpp
int& b = a;  // 引用符号，表示 b 是 a 的别名
&a;          // 取地址符号，表示取 a 的地址
```

判断方式：

| 写法位置 | 含义 |
|---|---|
| 类型后面，如 `int& b` | 引用 |
| 表达式前面，如 `&a` | 取地址 |

---

## 3. 引用的三个特性

### 特性一：引用定义时必须初始化

错误：

```cpp
int& ra; // 错误，引用必须初始化
```

正确：

```cpp
int a = 10;
int& ra = a;
```

---

### 特性二：一个变量可以有多个引用

```cpp
int a = 10;
int& b = a;
int& c = a;
int& d = b;
```

`b`、`c`、`d` 都是 `a` 的别名。

---

### 特性三：引用一旦绑定，不能再引用其他对象

```cpp
int a = 10;
int& b = a;

int c = 20;
b = c;
```

注意：

> `b = c` 不是让 `b` 改为引用 `c`，而是把 `c` 的值赋给 `a`。

引用不像指针，不能改变指向。

---

## 九、引用的使用场景

### 1. 引用传参

引用传参可以达到类似指针传参的效果，但写法更自然。

```cpp
void Swap(int& rx, int& ry)
{
    int tmp = rx;
    rx = ry;
    ry = tmp;
}
```

调用：

```cpp
int x = 0, y = 1;
Swap(x, y);
``` 
优点：

- 可以直接修改实参。
- 不需要像指针那样写 `&x` 和 `*px`。
- 语法更简洁。

---

### 2. 引用用于数据结构接口

例如 Stack 初始化：

```cpp
void STInit(ST& rs, int n = 4)
{
    rs.a = (STDataType*)malloc(n * sizeof(STDataType));
    rs.top = 0;
    rs.capacity = n;
}
```

调用时：

```cpp
ST st;
STInit(st);
```

相比指针传参：

```cpp
STInit(&st);
```

引用写法更简洁。

---

### 3. 指针变量也可以有引用

例如链表尾插时，可以用指针引用替代二级指针：

```cpp
void ListPushBack(LTNode*& phead, int x)
{
}
```

含义：

> `LTNode*& phead` 是给一个指针变量取别名。

可以理解为：

- `LTNode*` 是指针类型。
- `&` 表示对这个指针变量取引用。

这种写法可以避免使用二级指针：

```cpp
void ListPushBack(LTNode** phead, int x);
```

---

### 4. 引用返回值

函数可以返回引用：

```cpp
int& STTop(ST& rs)
{
    assert(rs.top > 0);
    return rs.a[rs.top - 1];
}
```

这样调用结果可以作为左值：

```cpp
STTop(st) += 10;
```

含义：

> 返回的是栈顶元素的别名，因此可以直接修改栈顶元素。

注意：

> 引用返回值后面会在类和对象章节继续深入，尤其要注意不能返回局部变量的引用。

## 十、`const` 引用

### 1. 权限不能放大，只能缩小

如果对象本身是 `const`，必须用 `const` 引用。

```cpp
const int a = 10;
const int& ra = a;
```

错误：

```cpp
int& ra = a; // 错误，权限放大
```

原因：

- `a` 是只读的。
- `int&` 允许修改。
- 用可修改引用绑定只读对象，相当于权限放大，不允许。

---

### 2. 普通对象可以被 `const` 引用绑定

```cpp
int b = 20;
const int& rb = b;
```

这是允许的，因为：

> 对普通变量使用 `const` 引用，是权限缩小。

但不能通过 `rb` 修改 `b`：

```cpp
rb++; // 错误
```

---

### 3. 临时对象具有常性

下面写法错误：

```cpp
int a = 10;
int& rb = a * 3; // 错误
```

原因：

- `a * 3` 的结果会放到一个临时对象中。
- 临时对象具有常性。
- 普通引用不能绑定临时对象。

正确写法：

```cpp
const int& rb = a * 3;
```

---

### 4. 类型转换也可能产生临时对象

```cpp
double d = 12.34;
const int& rd = d;
```

这里会发生类型转换：

```text
double -> int
```

转换结果存放在临时对象中，所以必须用 `const int&`。

错误：

```cpp
int& rd = d;
```

---

## 十一、指针和引用的区别

引用和指针功能有重叠，但不是同一个东西。

| 对比项 | 引用 | 指针 |
|---|---|---|
| 概念 | 变量的别名 | 存储地址的变量 |
| 是否开空间 | 语法概念上不开新空间 | 指针变量本身要开空间 |
| 初始化 | 必须初始化 | 建议初始化，但语法上不强制 |
| 是否能改变指向 | 不能 | 可以 |
| 访问对象 | 直接访问 | 需要解引用 `*p` |
| 空值问题 | 一般较少 | 容易有空指针、野指针 |
| `sizeof` | 得到被引用类型大小 | 得到指针大小，32 位 4 字节，64 位 8 字节 |
| 使用感受 | 更安全、更简洁 | 更灵活、更底层 |

重点记忆：

> 引用像“别名”，指针像“地址变量”。引用更安全，指针更灵活，二者互相不能完全替代。

## 十二、`inline` 内联函数

### 1. 内联函数概念

用 `inline` 修饰的函数叫内联函数。

```cpp
inline int Add(int x, int y)
{
    return x + y;
}
```

编译器可能会在函数调用处直接展开函数代码，从而减少函数调用建立栈帧的开销。

---

### 2. `inline` 只是给编译器的建议

重点：

> `inline` 只是建议，不是命令。

编译器可以选择：

- 展开这个函数。
- 不展开这个函数。

一般适合内联的函数：

- 短小
- 频繁调用
- 逻辑简单

一般不适合内联的函数：

- 递归函数
- 代码量大的函数
- 复杂逻辑函数

---

### 3. `inline` 和宏函数的区别

C 语言中常用宏函数：

```cpp
#define ADD(a, b) ((a) + (b))
```

宏函数问题：

- 容易写错括号。
- 不方便调试。
- 没有类型检查。
- 预处理阶段直接替换，容易出现优先级问题。

例如宏必须写成：

```cpp
#define ADD(a, b) ((a) + (b))
```

原因：

- 外层括号保护整体优先级。
- 内层括号保护参数优先级。
- 不能随便加分号。

`inline` 的价值：

> 在保留函数语义、类型检查和可调试性的基础上，尽量获得类似宏函数展开的效率。

---

### 4. `inline` 不建议声明和定义分离到两个文件

错误倾向：

```cpp
// F.h
inline void f(int i);

// F.cpp
void f(int i)
{
    cout << i << endl;
}
```

可能导致链接错误。

原因：

> `inline` 函数可能在编译阶段展开，链接时未必能找到正常函数地址。

推荐：

> 内联函数通常直接在头文件中给出完整定义。

## 十三、`nullptr`

### 1. `NULL` 的问题

传统 C / C++ 中常用 `NULL` 表示空指针。

但在 C++ 中，`NULL` 可能被定义为：

```cpp
#define NULL 0
```

这会带来函数重载问题。

例如：

```cpp
void f(int x)
{
    cout << "f(int x)" << endl;
}

void f(int* ptr)
{
    cout << "f(int* ptr)" << endl;
}
```

调用：

```cpp
f(NULL);
```

如果 `NULL` 被定义为 `0`，实际会调用：

```cpp
f(int x)
```

这可能不是程序员想要的结果。

---

### 2. `nullptr` 的作用

C++11 引入 `nullptr`。

```cpp
int* p = nullptr;
```

特点：

- `nullptr` 是关键字。
- 它表示空指针。
- 它可以转换为任意指针类型。
- 它不能被隐式转换为整数类型。

所以：

```cpp
f(nullptr);
```

会正确调用：

```cpp
f(int* ptr)
```

---

### 3. 推荐写法

C++ 中推荐：

```cpp
int* p = nullptr;
```

不推荐：

```cpp
int* p = NULL;
int* p = 0;
```

核心原因：

> `nullptr` 类型更明确，可以避免 `NULL` 被当成整数 `0` 引发的重载歧义或调用错误。

## 十四、易错点汇总

### 易错点 1：项目中滥用 `using namespace std`

日常练习可以：

```cpp
using namespace std;
```

项目中更推荐：

```cpp
std::cout << std::endl;
```

或只展开常用成员：

```cpp
using std::cout;
using std::endl;
```

---

### 易错点 2：命名空间中的变量不会被默认查找

```cpp
namespace bit
{
    int a = 0;
}

cout << a << endl; // 错误
```

正确：

```cpp
cout << bit::a << endl;
```

---

### 易错点 3：半缺省参数不是随便给

错误：

```cpp
void Func(int a = 10, int b, int c = 20);
```

正确：

```cpp
void Func(int a, int b = 10, int c = 20);
```

口诀：

> 缺省参数必须从右往左连续给。

---

### 易错点 4：声明和定义同时写缺省值

错误：

```cpp
void Func(int a = 10);
void Func(int a = 10) {}
```

正确：

```cpp
void Func(int a = 10);
void Func(int a) {}
```

---

### 易错点 5：返回值不同不能函数重载

错误：

```cpp
void f();
int f();
```

原因：

> 调用时无法只靠返回值区分。

---

### 易错点 6：引用不是指针，不能重新绑定

```cpp
int a = 10;
int& r = a;
int b = 20;
r = b;
```

这里不是让 `r` 改为引用 `b`，而是：

```cpp
a = b;
```

---

### 易错点 7：普通引用不能绑定临时对象

错误：

```cpp
int a = 10;
int& r = a * 3;
```

正确：

```cpp
const int& r = a * 3;
```

---

### 易错点 8：`inline` 不是一定展开

```cpp
inline int Add(int x, int y)
{
    return x + y;
}
```

不代表编译器一定展开。

正确理解：

> `inline` 是建议，最终是否展开由编译器决定。

---

### 易错点 9：`NULL` 不等于类型安全的空指针

```cpp
f(NULL);
```

可能调用整数版本。

推荐：

```cpp
f(nullptr);
```

## 十六、一页纸记忆版

如果只记最核心内容，记下面这些：

- **命名空间用于解决命名冲突，本质是定义一个新的域。**
- **项目中推荐 `std::cout` 或 `using std::cout`，不推荐滥用 `using namespace std`。**
- **`cin/cout` 能自动识别类型，本质后面会由函数重载支持。**
- **缺省参数调用时从左往右传参，所以默认值必须从右往左连续给。**
- **声明和定义分离时，缺省参数一般写在声明中。**
- **函数重载看函数名和参数列表，不看返回值。**
- **引用是别名，定义必须初始化，一旦绑定不能换对象。**
- **普通引用不能绑定 `const` 对象和临时对象，`const` 引用可以。**
- **引用更安全简洁，指针更灵活底层，二者不能互相完全替代。**
- **`inline` 是编译器展开建议，适合短小频繁调用函数。**
- **`inline` 用来替代一部分宏函数，但比宏更安全。**
- **C++ 中空指针推荐用 `nullptr`，不要优先用 `NULL`。**

---

## 十七、二刷重点建议

你已经学过一遍，复习时建议把精力主要放在这些点：

### 第一优先级：引用

引用是后续 C++ 学习的高频基础，尤其要熟：

- 引用的本质是别名。
- 引用必须初始化。
- 引用不能重新绑定。
- 引用传参。
- 引用返回值。
- `const` 引用绑定临时对象。
- 指针引用替代二级指针。

---

### 第二优先级：函数重载 + 缺省参数

重点掌握：

- 参数类型、个数、顺序不同可以重载。
- 返回值不同不能重载。
- 缺省参数可能导致调用歧义。
- 半缺省必须从右往左连续。

---

### 第三优先级：命名空间

重点掌握：

- 命名空间解决命名冲突。
- `::` 作用域限定符。
- 多文件同名命名空间会合并。
- 项目中不要随便展开整个命名空间。

---

### 第四优先级：`inline` 和 `nullptr`

重点掌握：

- `inline` 是建议，不保证展开。
- 短小频繁调用函数适合内联。
- 宏函数容易出错，`inline` 更安全。
- `nullptr` 比 `NULL` 更类型安全。

---

## 十八、建议复习顺序

建议按下面顺序复习：

```text
命名空间 → C++输入输出 → 缺省参数 → 函数重载 → 引用 → const引用 → 指针和引用区别 → inline → nullptr
```

其中最值得反复敲代码验证的是：

```text
引用、函数重载、缺省参数、nullptr
```

这些内容后面在类和对象、构造函数、拷贝构造、运算符重载、STL 中都会不断出现。
