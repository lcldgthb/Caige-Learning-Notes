# C++ stack 和 queue 复习总结

> 来源：`11.stack和queue.pdf`  
> 定位：已学一遍后的重点复习笔记，用于快速回忆 `stack`、`queue`、`priority_queue` 的常用接口、OJ 场景、容器适配器思想以及默认底层容器选择。

---

## 一、本讲核心主线

这一讲实际上讲了三类东西：

1. **`stack` 的使用与模拟实现**
2. **`queue` 的使用与模拟实现**
3. **`priority_queue` 与容器适配器思想**

一句话概括：

> `stack`、`queue`、`priority_queue` 虽然表面上像容器，但本质上更像“对底层容器接口的限制性封装”，因此它们在 STL 中被称为**容器适配器**。

---

## 二、为什么要学 stack 和 queue？

这几个容器虽然接口不多，但在 OJ 和面试里使用频率非常高：

- `stack`：括号匹配、表达式求值、单调栈、模拟出入栈过程
- `queue`：层序遍历、BFS、滑动窗口、先进先出调度
- `priority_queue`：TopK、堆、最值维护、贪心题

所以这一讲真正要掌握的，不只是接口名字，而是：

- 它们分别适合什么场景
- 底层为什么能这样实现
- 默认底层容器为什么这么选

---

## 三、stack 的介绍与使用

## 1. stack 的本质

`stack` 是一种：

> **后进先出（LIFO）** 的线性结构。

特点：

- 只能在一端插入和删除。
- 访问元素时，只关心“栈顶”。

---

## 2. stack 的常用接口

| 接口 | 作用 |
|---|---|
| `stack()` | 构造空栈 |
| `empty()` | 判断是否为空 |
| `size()` | 返回元素个数 |
| `top()` | 返回栈顶元素引用 |
| `push()` | 压栈 |
| `pop()` | 弹栈 |

---

## 3. stack 的使用特点

### `top()`

```cpp
s.top()
```

返回栈顶元素引用。

注意：

> 栈不能为空时才能调用。

---

### `push()`

```cpp
s.push(x)
```

把元素压入栈顶。

---

### `pop()`

```cpp
s.pop()
```

弹出栈顶元素。

注意：

> `pop()` 只删除，不返回值。要先 `top()` 再 `pop()`。

这是 STL 栈和很多语言栈接口的一个不同点。

---

## 四、stack 的典型题型

## 1. 最小栈

题意：

- 普通栈支持 `push / pop / top`
- 还要支持 `getMin()`，且尽量高效

核心思路：

> 用两个栈：

- `_elem`：保存所有元素
- `_min`：保存当前最小值轨迹

课件核心逻辑：

```cpp
void push(int x)
{
    _elem.push(x);
    if (_min.empty() || x <= _min.top())
        _min.push(x);
}

void pop()
{
    if (_min.top() == _elem.top())
        _min.pop();
    _elem.pop();
}
```

重点理解：

- `_elem` 负责正常栈行为
- `_min` 负责同步维护“当前最小值”
- 只有当出栈元素刚好等于当前最小值时，`_min` 才同步出栈

这是非常经典的辅助栈思想。

---

## 2. 栈的压入弹出序列

核心问题：

- 已知入栈序列 `pushV`
- 判断出栈序列 `popV` 是否合法

核心思路：

> 用一个辅助栈模拟真实入栈 / 出栈过程。

逻辑：

1. 先不断入栈，直到栈顶元素等于当前目标出栈元素
2. 如果一直入栈都凑不出来，说明不合法
3. 若凑出来，就弹出并继续匹配下一目标

复习重点：

- 这是“模拟过程类题目”的典型代表
- 关键不是背代码，而是理解“入栈序列固定，栈顶是否能匹配出栈需求”

---

## 3. 逆波兰表达式求值

逆波兰表达式（后缀表达式）适合用栈处理。

核心规则：

- 如果当前 token 是数字：压栈
- 如果当前 token 是运算符：
  1. 弹出右操作数
  2. 再弹出左操作数
  3. 计算后把结果压回栈

重点细节：

### 1）左右操作数顺序不能反

```cpp
int right = s.top(); s.pop();
int left = s.top(); s.pop();
```

不能写反，尤其是减法和除法。

### 2）字符串转整数

课件使用：

```cpp
atoi(str.c_str())
```

这里用到了：

- `string::c_str()`
- C 风格转换函数 `atoi`

---

## 五、stack 的模拟实现

课件结论：

> `stack` 本质上可以看成一种特殊的 `vector` 封装。

因为它只需要：

- `push_back`
- `pop_back`
- `back`
- `size`
- `empty`

所以可以用：

```cpp
std::vector<T>
```

作为底层容器模拟实现：

```cpp
template<class T>
class stack
{
public:
    void push(const T& x) { _c.push_back(x); }
    void pop() { _c.pop_back(); }
    T& top() { return _c.back(); }
    const T& top() const { return _c.back(); }
    size_t size() const { return _c.size(); }
    bool empty() const { return _c.empty(); }
private:
    std::vector<T> _c;
};
```

重点：

> `stack` 不需要迭代器，因为它不强调遍历，只强调栈顶操作。

---

## 六、queue 的介绍与使用

## 1. queue 的本质

`queue` 是一种：

> **先进先出（FIFO）** 的线性结构。

特点：

- 从一端进入
- 从另一端出去

---

## 2. queue 的常用接口

| 接口 | 作用 |
|---|---|
| `queue()` | 构造空队列 |
| `empty()` | 判断是否为空 |
| `size()` | 返回元素个数 |
| `front()` | 返回队头元素引用 |
| `back()` | 返回队尾元素引用 |
| `push()` | 在队尾入队 |
| `pop()` | 在队头出队 |

---

## 3. queue 的关键特点

### `front()`

```cpp
q.front()
```

返回队头元素引用。

### `back()`

```cpp
q.back()
```

返回队尾元素引用。

### `push()`

```cpp
q.push(x)
```

尾插。

### `pop()`

```cpp
q.pop()
```

头删。

注意：

> 和栈一样，`pop()` 只删除，不返回值。

---

## 七、queue 的模拟实现

课件给出的关键判断：

> `queue` 需要尾插 + 头删。

因此：

- 用 `vector` 来做底层很差，因为头删需要整体搬移元素，效率低
- 用 `list` 做底层很自然，因为链表头删尾插都高效

所以可以这样模拟：

```cpp
template<class T>
class queue
{
public:
    void push(const T& x) { _c.push_back(x); }
    void pop() { _c.pop_front(); }
    T& back() { return _c.back(); }
    const T& back() const { return _c.back(); }
    T& front() { return _c.front(); }
    const T& front() const { return _c.front(); }
    size_t size() const { return _c.size(); }
    bool empty() const { return _c.empty(); }
private:
    std::list<T> _c;
};
```

重点：

> `queue` 本质上就是对底层容器“只开放队列接口”的一层包装。

---

## 八、priority_queue 的介绍与使用

## 1. priority_queue 的本质

`priority_queue` 是：

> 一种基于堆实现的容器适配器。

特点：

- 不是普通 FIFO 队列
- 每次取出的都是“当前优先级最高”的元素
- 默认取最大值，因此默认是**大堆**

---

## 2. priority_queue 的常用接口

| 接口 | 作用 |
|---|---|
| `priority_queue()` | 构造空优先队列 |
| `empty()` | 判断是否为空 |
| `top()` | 返回堆顶元素 |
| `push()` | 插入元素 |
| `pop()` | 删除堆顶元素 |

注意：

> `top()` 返回的是优先级最高的元素，即堆顶元素。

---

## 3. 默认是大堆

```cpp
priority_queue<int> q;
```

默认情况下：

- `top()` 返回最大值
- 底层按堆结构维护

例如：

```cpp
priority_queue<int> q1;
for (auto e : v)
    q1.push(e);
cout << q1.top() << endl;
```

输出的是最大值。

---

## 4. 小堆写法

如果想构造小堆：

```cpp
priority_queue<int, vector<int>, greater<int>> q2(v.begin(), v.end());
```

重点记忆：

```cpp
priority_queue<元素类型, 底层容器, 比较器>
```

其中：

- 默认比较器让它成为大堆
- 使用 `greater<int>` 可以变成小堆

---

## 5. 自定义类型放入 priority_queue

课件重点：

> 如果放自定义类型，通常需要提供比较规则。

例如 `Date`：

- 做大堆时，需要支持 `<`
- 做小堆时，需要支持 `>`

原因：

- `priority_queue` 需要依赖比较规则维持堆结构
- 编译器不知道自定义类型哪个更“大”

所以你必须让比较有定义。

---

## 九、priority_queue 的典型题型

### 数组中第 K 个大的元素

经典思路之一：

```cpp
priority_queue<int> p(nums.begin(), nums.end());
for (int i = 0; i < k - 1; ++i)
{
    p.pop();
}
return p.top();
```

本质：

- 把所有元素建成大堆
- 连续弹出 `k-1` 个最大的
- 当前堆顶就是第 `k` 大

这题说明：

> 只要题目跟“最大 / 最小 / TopK / 动态最值”有关，就应该立刻想到 `priority_queue`。

---

## 十、priority_queue 的模拟实现

课件结论：

> `priority_queue` 的底层本质就是堆。

因此模拟实现时，本质上不是重新发明一个全新结构，而是：

- 选择一个支持随机访问的底层容器
- 再配合堆算法：
  - `make_heap`
  - `push_heap`
  - `pop_heap`

这说明：

> `priority_queue` 本质是“容器 + 堆算法”的组合封装。

---

## 十一、什么是容器适配器（重点概念）

课件给出的解释非常关键：

> 容器适配器是一种设计模式，它把一个已有类的接口，转换成用户更希望使用的另一种接口。

对 STL 来说：

- `stack`
- `queue`
- `priority_queue`

都属于**容器适配器**。

原因：

- 它们底层并不直接发明一种全新存储结构
- 而是“借用已有容器”，再限制 / 包装对外接口

例如：

- `stack`：底层容器只开放“栈顶”操作
- `queue`：底层容器只开放“队头队尾”操作
- `priority_queue`：底层容器只开放“堆顶”操作

所以：

> 它们能存数据，但 STL 不把它们归为普通容器，而称为容器适配器。

---

## 十二、为什么 stack 和 queue 默认底层用 deque？

这是本讲最值得理解的一点。

---

## 1. deque 是什么？

`deque` 是双端队列。

特点：

- 可以在头尾两端高效插入删除
- 支持随机访问
- 底层不是完全连续空间，而是**分段连续空间**
- 可以理解成一种“假想连续”的结构

课件里强调：

> `deque` 像一个动态二维数组，由一段段连续的小空间拼接而成。

---

## 2. deque 的优点

和 `vector` 比：

- 头插、头删效率高
- 扩容时不需要像 `vector` 那样整体搬移大量元素

和 `list` 比：

- 底层仍然是分段连续空间
- 空间利用率更高
- 不需要像链表那样给每个节点额外保存前驱后继字段

---

## 3. deque 的缺陷

课件指出一个关键缺点：

> 不适合高频遍历。

原因：

- `deque` 迭代器设计复杂
- 遍历时需要频繁检查是否跨越小块边界
- 因此线性扫描效率不如 `vector`

所以：

> 需要高频遍历时，通常优先考虑 `vector` 或 `list`，而不是 `deque`。

---

## 4. 那为什么默认又选 deque？

原因正好在于：

### 对 `stack`

- 不需要遍历
- 只需要 `push_back / pop_back / back`
- 元素增长时，`deque` 扩容代价比 `vector` 更平滑

### 对 `queue`

- 不需要遍历
- 只需要 `push_back / pop_front / front / back`
- `deque` 比 `vector` 更适合头删
- `deque` 又不像 `list` 那样节点额外开销大

结论：

> `stack` 和 `queue` 恰好只使用 `deque` 的优点，而几乎避开了它“遍历慢”的缺点。

这就是 STL 默认选择 `deque` 作为它们底层容器的原因。

---

## 十三、stack 和 queue 的模板适配写法

课件给出的模拟实现模板：

### stack

```cpp
template<class T, class Con = deque<T>>
class stack
{
public:
    void push(const T& x) { _c.push_back(x); }
    void pop() { _c.pop_back(); }
    T& top() { return _c.back(); }
    const T& top() const { return _c.back(); }
    size_t size() const { return _c.size(); }
    bool empty() const { return _c.empty(); }
private:
    Con _c;
};
```

### queue

```cpp
template<class T, class Con = deque<T>>
class queue
{
public:
    void push(const T& x) { _c.push_back(x); }
    void pop() { _c.pop_front(); }
    T& back() { return _c.back(); }
    const T& back() const { return _c.back(); }
    T& front() { return _c.front(); }
    const T& front() const { return _c.front(); }
    size_t size() const { return _c.size(); }
    bool empty() const { return _c.empty(); }
private:
    Con _c;
};
```

重点：

- 底层容器是模板参数 `Con`
- 默认给成 `deque<T>`
- 但也允许替换成别的容器，只要该容器支持所需接口

这非常体现“适配器”思想。

## 十四、易错点汇总

### 易错点 1：认为 stack / queue 是普通容器

更准确地说：

> 它们是容器适配器。

它们依赖底层容器实现，并不强调迭代遍历。

---

### 易错点 2：以为 stack / queue 的 `pop()` 会返回值

错误想法：

```cpp
int x = s.pop();
```

实际上：

- `pop()` 只删除
- 先 `top()` / `front()`，再 `pop()`

---

### 易错点 3：逆波兰表达式里左右操作数顺序写反

尤其是：

- 减法
- 除法

必须：

```cpp
right = s.top(); s.pop();
left = s.top(); s.pop();
```

不能反过来。

---

### 易错点 4：queue 用 vector 做底层以为也一样高效

`vector` 头删代价高，因为要整体搬移元素。

所以对 `queue` 来说不合适。

---

### 易错点 5：priority_queue 默认以为是小堆

课件结论：

> 默认是大堆。

如果想要小堆，要显式写：

```cpp
greater<int>
```

---

### 易错点 6：自定义类型放进 priority_queue 却没提供比较规则

这会导致编译器无法判断元素优先级。

---

### 易错点 7：deque 以为是完全连续空间

更准确理解：

> `deque` 是分段连续空间，通过复杂迭代器维持“整体连续的假象”。

---

### 易错点 8：deque 很万能，所以遍历也应该优先用它

不是。

课件明确指出：

> `deque` 不适合高频遍历，这是它的明显缺陷。

## 十六、一页纸记忆版

- **`stack`：后进先出，只关心栈顶。**
- **`queue`：先进先出，只关心队头和队尾。**
- **`priority_queue`：本质是堆，默认大堆。**
- **`pop()` 只删除，不返回值。**
- **最小栈常用“双栈维护最小值”。**
- **逆波兰表达式：数字入栈，运算符弹两个数计算后再入栈。**
- **`stack` 可用 `vector` 模拟，因为只需要尾插尾删。**
- **`queue` 更适合用 `list` 模拟，因为需要尾插头删。**
- **`priority_queue` 默认底层是 `vector` + 堆算法。**
- **`stack / queue / priority_queue` 在 STL 中是容器适配器。**
- **`deque` 是分段连续空间，不是真正完全连续。**
- **`deque` 头尾操作强，但遍历效率不如 `vector`。**
- **默认用 `deque` 作为 `stack/queue` 底层，是因为它正好避开了自身遍历缺陷。**

## 十七、二刷重点建议

### 第一优先级：容器适配器思想

这一讲的真正主线不是背接口，而是理解：

```text
stack / queue / priority_queue
不是自己发明全新底层结构
而是对已有容器做接口封装
```

这是 STL 设计思想层面的重点。

---

### 第二优先级：stack / queue / priority_queue 的应用场景

重点掌握：

- `stack`：匹配、回溯、表达式、单调结构
- `queue`：层序、BFS、先进先出调度
- `priority_queue`：最值维护、TopK、堆题

---

### 第三优先级：为什么默认底层是 deque

这是高频理解题，必须能自己讲清楚：

- `vector` 扩容搬移大
- `list` 节点开销大
- `deque` 头尾操作强、随机访问也有、适配器又不需要高频遍历

所以默认选 `deque` 很合理。

---

### 第四优先级：priority_queue 的大堆 / 小堆 / 自定义类型

这部分很常考，也很容易在 OJ 里直接用到。

重点掌握：

```cpp
priority_queue<int>
priority_queue<int, vector<int>, greater<int>>
priority_queue<Date>
priority_queue<Date, vector<Date>, greater<Date>>
```
