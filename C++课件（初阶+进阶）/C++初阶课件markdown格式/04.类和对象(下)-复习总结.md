# 04.类和对象(下) 复习总结

> 来源：`04.类和对象(下).pdf`
> 定位：已学一遍后的重点复习笔记，用于快速回忆核心知识、易错点和后续学习基础。

## 一、本讲核心主线

这一讲是在“类和对象(上)”的基础上，把类的几个**高频考点和易错机制**补完整，主线可以概括为：

1. **初始化列表**：构造函数并不只是“进函数体赋值”，很多成员在进入函数体前就已经要完成初始化。
2. **类型转换**：单参数构造函数会带来隐式类型转换，`explicit` 用来卡住这种“自动转”。
3. **static 成员**：从“对象自己的成员”提升到“类共享的成员”。
4. **友元 / 内部类**：在封装基础上，提供少量“开后门”的受控访问方式。
5. **匿名对象**：对象可以只为“一次调用”而创建，生命周期很短。
6. **对象拷贝时的编译器优化**：很多看起来会发生的拷贝，实际可能被编译器省掉。

这是一份**知识型课件**，复习重点应放在：**规则、条件、例外、易错点、程序结果判断**。

---

## 二、为什么学 / 这一讲解决什么问题

如果只学“类和对象(上)”，你通常只能写出基本的类，但在下面这些场景里很容易出错：

- 类里有 `const` 成员、引用成员、没有默认构造的成员对象时，构造函数怎么写？
- 为什么有些代码看起来像赋值，实际上必须在初始化列表里做？
- 为什么 `A a = 1;` 能过，而加了 `explicit` 后就不行？
- 为什么静态成员变量要单独处理？静态成员函数为什么不能直接访问普通成员？
- 友元和内部类到底是干什么的，为什么说它们方便但不能滥用？
- 返回对象、传值传参时，到底会不会调用拷贝构造？

所以这一讲的作用是：

> **把类从“会写”推进到“能正确判断构造、转换、访问控制和拷贝行为”。**

这部分内容在：

- 选择题 / 判断题
- 程序运行结果题
- 类设计题
- 后续 `string` / `vector` / 模拟实现

里都会反复出现。

## 三、核心内容展开

### 3.1 再探构造函数：初始化列表

#### 1）基本形式

构造函数除了函数体，还可以在函数名后面写初始化列表：

```cpp
Date(int year, int month, int day)
    : _year(year)
    , _month(month)
    , _day(day)
{}
```

可以把它理解为：

- 构造函数体负责“进入对象之后做事”；
- 初始化列表负责“对象成员一开始怎么建出来”。

#### 2）为什么初始化列表重要

课件的关键结论是：

- **每个构造函数都有初始化列表**；
- **每个成员变量最终都要走初始化列表这一关**；
- 没在初始化列表里显式写的成员，也不是“完全不初始化”，而是按其规则处理。

#### 3）哪些成员必须放初始化列表

下面这些成员，**必须**在初始化列表里初始化：

- **引用成员**
- **`const` 成员**
- **没有默认构造函数的类类型成员对象**

因为它们不能等进构造函数体后再赋值。

#### 4）C++11 的类内缺省值

课件提到：C++11 支持在成员声明位置给缺省值，例如：

```cpp
int _year = 1;
int _month = 1;
```

它的作用是：

- 当该成员**没有在初始化列表里显式初始化**时，可使用这个缺省值；
- 如果初始化列表已经写了该成员，则以初始化列表为准。

例如：

```cpp
Date()
    : _month(2)
{}
```

若成员声明中有：

```cpp
int _year = 1;
int _month = 1;
int _day;
```

则可快速判断：

- `_year` → 用类内缺省值 `1`
- `_month` → 用初始化列表里的 `2`
- `_day` → 若未初始化，结果不确定

#### 5）初始化顺序看什么

这是本节**最重要的易错点之一**：

> **成员的实际初始化顺序，只看它们在类中“声明的顺序”，不看它们在初始化列表中书写的顺序。**

也就是说，下面这种写法：

```cpp
class A
{
private:
    int _a2 = 2;
    int _a1 = 2;
public:
    A(int a)
        : _a1(a)
        , _a2(_a1)
    {}
};
```

判断时要先看：

- 类里先声明的是 `_a2`
- 后声明的是 `_a1`

所以初始化顺序是 `_a2` 再 `_a1`，不是看初始化列表谁写在前面。

#### 6）本节复习结论

- **尽量使用初始化列表初始化成员。**
- 赋值和初始化不是一回事。
- 能在初始化列表完成的，不要拖到函数体里再做。
- 对结果题，先看：
  1. 成员声明顺序
  2. 初始化列表是否显式写出
  3. 类内是否有缺省值
  4. 是否涉及引用 / `const` / 无默认构造成员

### 3.2 类型转换

#### 1）单参数构造函数会带来隐式类型转换

如果类有“可用一个参数调用”的构造函数，就可能支持：

```cpp
A aa1 = 1;
```

本质上是：

- 先用 `1` 构造一个临时 `A` 对象；
- 再用这个对象去完成初始化（实际过程可能被优化）。

#### 2）`explicit` 的作用

在构造函数前加 `explicit` 后：

- **不再允许隐式类型转换**；
- 只能显式构造。

例如：

```cpp
explicit A(int a1);
```

这时：

```cpp
A aa1 = 1;   // 不允许
A aa1(1);    // 可以
```

#### 3）类类型对象之间也可能发生转换

如果一个类的构造函数参数是另一个类类型，也可以发生对象到对象的转换。

课件里的思路是：

- `B(const A& a)`
- 那么 `B b = aa3;` 就可能成立

本质还是：

> **有没有“合适的构造函数”接住这个对象。**

#### 4）C++11 的列表初始化也要会看

例如：

```cpp
A aa3 = { 2, 2 };
```

复习时记住：

- 这也是一种构造方式；
- 最终还是看类里是否有匹配的构造函数。

#### 5）本节复习结论

- **单参数构造函数**是隐式转换的来源。
- **`explicit`** 是禁止隐式转换的关键字。
- 判断转换题时，先找“有没有对应构造函数”。

### 3.3 `static` 成员

#### 1）静态成员变量

用 `static` 修饰的成员变量称为静态成员变量。课件强调：

- 它**属于类**，不属于某一个具体对象；
- 被所有对象共享；
- 不在对象内部，通常理解为存放在静态区。

典型用途：

- 统计创建了多少个对象；
- 维护所有对象共享的一份状态。

#### 2）静态成员变量的初始化

按本课件的教学语境，应重点记住：

> **静态成员变量通常要在类外定义和初始化。**

例如：

```cpp
class A
{
private:
    static int _scount;
};

int A::_scount = 0;
```

#### 3）静态成员函数

静态成员函数的特点：

- 没有 `this` 指针；
- 可以访问静态成员；
- 不能直接访问普通成员变量，因为普通成员属于对象，需要对象上下文。

#### 4）访问方式

静态成员既可以通过：

```cpp
A::GetACount()
```

也可以通过对象：

```cpp
a1.GetACount()
```

但从语义上说，更推荐用：

```cpp
类名::静态成员
```

因为它更能体现“这是类共享的，不是对象独有的”。

#### 5）典型题型：求 1+2+...+n

课件给出的经典思路：

- 定义一个类 `Sum`
- 每创建一个对象，构造函数里就做累加
- 用静态成员记录当前加到了几、总和是多少
- 最后利用“创建 `n` 个对象”完成求和

这题本质考的是：

- 静态成员共享
- 构造函数自动执行
- 不显式写循环也能累加

#### 6）本节复习结论

- `static` 成员变量是“类级别”的。
- `static` 成员函数里没有 `this`。
- 静态函数能访问静态成员，不能直接访问普通成员。
- 统计对象个数、全局共享状态，是静态成员的典型应用场景。

### 3.4 友元

#### 1）友元是什么

友元是对封装的一种“受控突破”。

它允许：

- 某个**外部函数**
- 或另一个**类**

访问本类的私有和保护成员。

常见形式：

- 友元函数
- 友元类

#### 2）友元函数的特点

课件要点：

- 友元函数需要在类里用 `friend` 声明；
- 它**不是**这个类的成员函数；
- 但它可以访问该类的私有成员；
- 一个函数可以同时是多个类的友元函数。

#### 3）友元类的特点

如果写：

```cpp
friend class B;
```

那么 `B` 的成员函数就可以访问该类的私有成员。

#### 4）友元关系的性质

这是高频判断点：

- **友元关系是单向的**
- **友元关系不具有交换性**
- **友元关系不能传递**

例如：

- A 是 B 的友元，不代表 B 是 A 的友元
- A 是 B 的友元，B 是 C 的友元，不代表 A 是 C 的友元

#### 5）友元的使用原则

课件也强调：

> 友元提供了便利，但会增加耦合、破坏封装，所以**不宜滥用**。

复习时不要把友元当常规手段，它更像是“必要时开的特例口子”。

### 3.5 内部类

#### 1）内部类是什么

如果一个类定义在另一个类的内部，就叫内部类。

复习时要抓住两个关键词：

- **它本质上仍然是一个独立的类**
- **但它的作用域受外部类限制**

#### 2）课件中的理解方式

按本课件示例，可以把内部类理解成：

- 它和外部类联系很紧；
- 适合“只服务于外部类”的辅助类型；
- 示例中内部类可以访问外部类的静态成员，以及传入对象的普通成员。

#### 3）什么时候考虑内部类

当一个类：

- 只为另一个类服务；
- 单独放到外部意义不大；
- 与外部类关系非常紧密；

就可以考虑设计成内部类。

#### 4）典型题：求 1+2+...+n

课件把前面静态成员做法进一步改成“内部类版本”，目的是说明：

- 内部类也能参与这类设计；
- 类之间的作用域关系会更紧。

#### 5）本节复习结论

- 内部类不是“对象里的对象”。
- 它是独立类，只是定义位置在另一个类内部。
- 它适合承载与外部类强相关、但不想暴露到全局作用域的结构。

---

### 3.6 匿名对象

#### 1）什么是匿名对象

用类型(实参)直接创建、但**不给名字**的对象，叫匿名对象。

例如：

```cpp
A();
A(1);
Solution().Sum_Solution(10);
```

#### 2）生命周期特点

课件强调：

> **匿名对象的生命周期通常只在当前这一行 / 当前语句。**

所以它适合：

- 只想临时调用一次构造 / 成员函数；
- 不需要后续继续使用对象。

#### 3）与有名对象区分

```cpp
A aa2(2);   // 有名对象
A(2);       // 匿名对象
```

前者后面还能继续使用 `aa2`，后者通常这一句结束后就销毁。

#### 4）本节复习结论

- 匿名对象适合“一次性使用”。
- 判断题里要特别注意它的生命周期很短。
- 写法像函数声明时，要小心区分语法含义。

---

### 3.7 对象拷贝时的编译器优化

#### 1）为什么会有这部分

如果严格按照“构造 / 拷贝构造 / 赋值 / 析构”一步步执行，很多场景会产生额外开销。

现代编译器为了提高效率，常会在**不影响正确性**的前提下省略一些拷贝。

#### 2）课件重点

课件强调两个核心认识：

1. **很多看起来会调用拷贝构造的地方，实际可能不会调用。**
2. **这种优化细节并不是所有编译器、所有模式下都完全一样。**

尤其在：

- 传值传参
- 函数返回对象
- 一个表达式里连续构造临时对象

这些地方最容易出题。

#### 3）怎么观察

课件给了一个典型方法：

- 在构造函数、拷贝构造、赋值运算符、析构函数里打印信息；
- 通过运行结果观察对象生命周期；
- 在 Linux 下还可以通过：

```bash
g++ test.cpp -fno-elide-constructors
```

来尽量关闭相关优化，帮助观察“本来可能发生的拷贝”。

#### 4）复习时的正确态度

这部分不要死背“到底打印几次”。更重要的是：

- 先会画对象流转过程；
- 再知道编译器**可能**把中间临时对象优化掉；
- 明白结果可能随编译器与构建模式变化。

#### 5）本节复习结论

- 拷贝省略是性能优化的重要来源。
- 调试输出只能反映“当前编译环境下的行为”。
- 不要把某个编译器某次输出，当成永远固定的标准答案。

## 四、易错点汇总

### 1. 把“初始化”当成“赋值”

最常见错误：以为成员变量先进来默认建好，再在构造函数体里赋值。

正确理解：

- 很多成员在进入函数体前就必须完成初始化；
- 尤其是引用、`const`、无默认构造成员对象。

### 2. 误以为初始化顺序看初始化列表书写顺序

错误想法：谁写前面谁先初始化。  
正确规则：**只看成员在类中的声明顺序。**

### 3. 忽略类内缺省值与初始化列表的关系

要会区分：

- 初始化列表显式写了 → 用初始化列表
- 没显式写 → 才考虑类内缺省值

### 4. 把单参数构造函数的隐式转换忘掉

看到：

```cpp
A a = 1;
```

要立刻想到：

- 是否有单参数构造函数
- 是否被 `explicit` 禁掉

### 5. 误以为静态成员函数能直接访问普通成员

静态成员函数里没有 `this`，因此不能直接访问对象级普通成员。

### 6. 把友元当成“常规封装方案”

友元是例外，不是常规默认设计。

### 7. 误以为匿名对象能一直活到作用域结束

本课件语境下要记：**匿名对象常用于当前语句，生命周期很短。**

### 8. 死背某个编译器下的构造 / 拷贝输出顺序

拷贝省略与优化行为会受编译器和构建模式影响，不应把某一次打印结果绝对化。

## 六、一页纸记忆版

### 1）一句话串全讲

> **初始化列表管“成员怎么生出来”，`explicit` 管“能不能偷偷转”，`static` 管“类共享”，友元 / 内部类管“特殊访问”，匿名对象管“一次性用”，拷贝优化管“少拷贝提效率”。**

### 2）高频结论表

| 主题 | 最关键结论 |
|---|---|
| 初始化列表 | 成员初始化顺序看声明顺序，不看初始化列表书写顺序 |
| 必须初始化列表的成员 | 引用成员、`const` 成员、无默认构造成员对象 |
| 类内缺省值 | 仅在初始化列表未显式写该成员时生效 |
| 隐式类型转换 | 单参数构造函数可能触发 |
| `explicit` | 禁止隐式类型转换 |
| 静态成员变量 | 属于类，被所有对象共享 |
| 静态成员函数 | 没有 `this`，不能直接访问普通成员 |
| 友元 | 能访问私有成员，但破坏封装，不宜滥用 |
| 友元关系 | 单向、不可传递 |
| 内部类 | 独立类，只是定义在外部类内部 |
| 匿名对象 | 临时创建、通常当前语句结束即销毁 |
| 拷贝优化 | 实际拷贝次数可能少于“表面看到的步骤” |

### 3）结果题通用判断顺序

遇到“程序输出什么 / 是否报错”时，建议按这个顺序看：

1. 成员声明顺序是什么？
2. 初始化列表里显式写了哪些成员？
3. 类内有没有缺省值？
4. 有没有引用、`const`、无默认构造对象成员？
5. 是否发生了隐式类型转换？
6. 是否是静态成员访问问题？
7. 是否涉及匿名对象生命周期？
8. 是否有拷贝省略导致输出变化？

## 七、二刷重点建议

### 第一遍复习：先抓“必背规则”

优先背会下面这些：

- 初始化顺序看声明顺序
- 引用 / `const` / 无默认构造成员必须走初始化列表
- 单参数构造函数可能触发隐式转换
- `explicit` 禁止隐式转换
- 静态成员变量属于类、被对象共享
- 静态成员函数没有 `this`
- 友元单向、不传递
- 匿名对象生命周期短
- 拷贝优化结果与编译环境有关

### 第二遍复习：做“结果题专项”

建议重点拿本讲中的代码例子练：

- 初始化列表 + 类内缺省值
- 成员声明顺序影响结果
- `explicit` 前后代码能否通过编译
- 静态成员统计对象数量
- 友元函数 / 友元类访问私有成员
- 匿名对象是否会立刻析构
- 返回对象时打印顺序为什么变化

### 第三遍复习：和后续容器课衔接

你后面学 `string`、`vector`、`list`、`map` 时，会不断用到本讲内容：

- 构造函数与初始化列表
- 临时对象与匿名对象
- 拷贝构造 / 赋值 / 析构
- 编译器优化对行为观察的影响

所以这讲要达到的目标不是“看懂例子”，而是：

> **以后见到类相关代码，能第一时间判断：它在构造什么、怎么初始化、会不会隐式转换、是不是共享成员、会不会发生拷贝优化。**

---

## 附：本讲最值得反复看的 10 句话

1. 初始化不是赋值。
2. 每个构造函数都有初始化列表。
3. 每个成员最终都要经过初始化阶段。
4. 成员初始化顺序只看声明顺序。
5. 引用、`const`、无默认构造成员必须走初始化列表。
6. 单参数构造函数可能带来隐式类型转换。
7. `explicit` 是阻止隐式转换的关键字。
8. 静态成员属于类，不属于某个对象。
9. 友元是对封装的例外，不宜滥用。
10. 拷贝是否发生、发生几次，常受编译器优化影响。
