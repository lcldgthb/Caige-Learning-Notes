## 三、核心知识讲解

### 1. 默认成员函数到底是什么

**结论：** 默认成员函数是编译器在需要时可能为类自动生成的一组特殊成员函数，它们对应的不是普通业务逻辑，而是对象生命周期和对象基本行为。

最重要区别：

> **默认成员函数关心的是“对象怎么活、怎么拷、怎么死”，不是“对象能做什么业务操作”。**

本讲最重要的 6 个默认成员函数可以先记成：

| 默认成员函数 | 主要作用 | 当前优先级 |
|---|---|---|
| 构造函数 | 初始化对象 | 最高 |
| 析构函数 | 清理对象资源 | 最高 |
| 拷贝构造函数 | 用已有对象初始化新对象 | 最高 |
| 赋值运算符重载 | 已有对象之间赋值 | 最高 |
| 普通取地址运算符重载 | 获取对象地址 | 了解 |
| `const` 取地址运算符重载 | 获取 `const` 对象地址 | 了解 |

本讲里真正必须掌握的是前 4 个。

### 2. 构造函数：初始化对象，不是申请对象空间

**结论：** 构造函数的核心任务是对象初始化，而不是申请对象空间。

最重要区别：

> **对象空间通常先有，构造函数再在这块空间上建立对象的初始状态。**

你真正要区分的是下面三种概念：

| 名称 | 最重要区别 |
|---|---|
| 无参构造函数 | 形参为空 |
| 全缺省构造函数 | 所有参数都有默认值 |
| 默认构造函数 | 不传实参就能调用 |

因此：

- 无参构造函数可以是默认构造；
- 全缺省构造函数也可以是默认构造；
- 二者不能同时都成为“无参可调用版本”，否则实例化时会歧义。

经典易错点：

```cpp
Date d1;   // 正确，定义对象
Date d2(); // 错误理解：这不是定义对象，而是函数声明
```

这类写法非常适合转成判断题或选择题去记。

### 3. 编译器默认生成的构造函数行为

**结论：** 如果用户不写构造函数，编译器可能生成默认构造函数，但它对不同成员类型的处理并不相同。

最重要区别：

> **内置类型成员通常不保证被初始化；自定义类型成员则会调用它自己的默认构造函数。**

所以：

- `int / char / double / 指针` 这类内置类型，默认构造下的初值不能想当然；
- `class / struct` 类型的成员，则要看它自己的默认构造行为。

### 4. 析构函数：资源类的生命线

**结论：** 析构函数的核心职责是对象结束时清理资源，尤其是堆资源。

最重要区别：

> **没有资源的类，析构函数常可依赖默认行为；有资源的类，析构函数通常必须自己写。**

以 `Stack` 为例：

```cpp
~Stack()
{
    free(_a);
    _a = nullptr;
    _top = _capacity = 0;
}
```

这说明：

- `_a` 指向堆内存；
- 不析构就会泄漏；
- 析构时既要释放资源，也要重置状态。

还要记一个题感很强的点：

> 同一作用域里的多个局部对象，通常按“后定义先析构”的顺序销毁。

### 5. 拷贝构造函数：新对象初始化，不是老对象覆盖

**结论：** 拷贝构造函数负责“用一个已有对象初始化一个新对象”。

最重要区别：

> **拷贝构造发生在新对象出生时；赋值运算符重载发生在两个对象都已经存在之后。**

常见触发场景：

- `Date d2(d1);`
- `Date d3 = d1;`
- 值传参；
- 值返回（若未被优化）。

为什么参数通常写成 `const T&`？

```cpp
Date(const Date& d)
{
    _year = d._year;
    _month = d._month;
    _day = d._day;
}
```

最重要区别：

> **不能写成传值，因为传值本身就会再次触发拷贝构造。**

这本身就是高频考点。

### 6. 资源类为什么不能直接默认拷贝

**结论：** 对资源类，默认拷贝通常只会逐成员复制资源地址，导致浅拷贝问题。

最重要区别：

> **值成员拷贝复制的是值；资源成员拷贝如果只复制地址，就可能把所有权也错误共享了。**

`Stack` 是最典型的例子：

```cpp
Stack(const Stack& st)
{
    _a = (STDataType*)malloc(sizeof(STDataType) * st._capacity);
    memcpy(_a, st._a, sizeof(STDataType) * st._top);
    _top = st._top;
    _capacity = st._capacity;
}
```

这里真正要记住的是：

- 不能只复制 `_a` 地址；
- 必须重新申请空间；
- 再复制原数据内容；
- 这才是深拷贝。

### 7. 赋值运算符重载：两个已有对象之间赋值

**结论：** `operator=` 解决的是两个已存在对象之间的状态覆盖。

典型形式：

```cpp
Date& operator=(const Date& d)
{
    if (this != &d)
    {
        _year = d._year;
        _month = d._month;
        _day = d._day;
    }
    return *this;
}
```

最重要区别：

> **拷贝构造是“新对象初始化”，赋值重载是“老对象覆盖旧状态”。**

这里的两个高频点：

- `this != &d`：防止自赋值；
- `return *this;`：支持连续赋值，也符合运算符语义。

### 8. 运算符重载：本质仍然是函数

**结论：** 运算符重载不是让符号“变魔法”，而是给自定义类型提供自然写法，本质仍是函数调用。

最重要区别：

> **运算符重载改变的是“写法体验”，不是语言底层逻辑。**

例如：

- `d1 == d2`
- `++d1`
- `d1++`
- `cout << d1`
- `cin >> d1`

都对应不同的重载实现。

题感很强的几个点：

1. **不是所有运算符都能重载；**
2. **后置 `++` 里的 `int` 参数只是占位，不代表真实业务含义；**
3. **`<<` / `>>` 常更适合写成友元，因为左操作数通常不是当前类对象。**

### 9. Date 类：本讲的贯穿案例

**结论：** Date 类不是零散示例，而是本讲多个机制的统一载体。

它串联了：

- 比较运算符：`< <= > >= == !=`
- 算术与复合赋值：`+= -= + -`
- 自增自减：`++ --`
- 差值运算：`d1 - d2`
- 流插入与流提取：`<< >>`
- `const` 成员函数：`Print() const`

最重要区别：

> **Date 类的价值不在于“日期功能”本身，而在于它用一个完整对象，把运算符重载和对象行为管理串成了一条线。**

这一点正是本章复习时必须保留的“贯穿案例意识”。

### 10. `const` 成员函数：限制的是 `this` 权限

**结论：** `const` 成员函数本质上约束的是隐藏的 `this` 指针视角，让当前对象在函数体内被当作只读对象对待。

例如：

```cpp
void Print() const;
```

最重要区别：

> **普通成员函数默认面对的是可写对象；`const` 成员函数面对的是只读对象。**

因此：

- `const Date d2(...); d2.Print();` 合理；
- 需要修改对象状态的成员函数，`const` 对象就不能调用。

### 11. 取地址运算符重载：了解即可，但不能漏掉

**结论：** 取地址运算符重载不是本讲主战场，但它确实属于默认成员函数体系中的一部分。

示例形式：

```cpp
Date* operator&();
const Date* operator&() const;
```

最重要区别：

> **普通取地址重载和 `const` 取地址重载的区别，本质仍然是对象只读性差异。**

这一节优先级低，但在完整复习稿里不能完全丢失。

## 四、关键代码与案例

### 1. 默认构造歧义案例

```cpp
Date();
Date(int year = 1, int month = 1, int day = 1);
```

要点：

- 两者都可能成为默认构造；
- 一旦同时存在，`Date d;` 会歧义；
- “默认构造函数只能有一个可无参匹配版本”是高频判断题结论。

### 2. `Date d2();` 陷阱

```cpp
Date d2();
```

要点：

- 这不是定义对象；
- 而是声明一个返回 `Date` 的函数；
- 是非常典型的编译陷阱。

### 3. `Stack` 深拷贝案例

```cpp
Stack(const Stack& st)
{
    _a = (STDataType*)malloc(sizeof(STDataType) * st._capacity);
    memcpy(_a, st._a, sizeof(STDataType) * st._top);
    _top = st._top;
    _capacity = st._capacity;
}
```

要点：

- 重新申请堆空间；
- 复制内容而不是复制地址；
- 深拷贝是资源类的高频核心点。

### 4. 赋值运算符重载案例

```cpp
Date& operator=(const Date& d)
{
    if (this != &d)
    {
        _year = d._year;
        _month = d._month;
        _day = d._day;
    }
    return *this;
}
```

要点：

- 自赋值保护；
- 返回 `*this`；
- 和拷贝构造的使用场景不同。

### 5. Date 类中的运算符重载案例

```cpp
bool operator==(const Date& d) const;
Date& operator++();
Date operator++(int);
ostream& operator<<(ostream& out, const Date& d);
istream& operator>>(istream& in, Date& d);
```

要点：

- 前置与后置 `++` 语义不同；
- `<<` / `>>` 更适合友元或非成员；
- Date 类是本章运算符重载的统一落地案例。

## 五、易混概念与易错点

### 易混概念

| 概念 A | 概念 B | 最重要区别 |
|---|---|---|
| 默认构造函数 | 编译器自动生成的构造函数 | 默认构造强调“无参可调用”，不等于“编译器生成” |
| 拷贝构造 | 赋值运算符重载 | 前者发生在新对象初始化时，后者发生在已有对象赋值时 |
| 浅拷贝 | 深拷贝 | 浅拷贝复制地址值，深拷贝复制资源本体 |
| 前置 `++` | 后置 `++` | 前置返回更新后对象，后置返回修改前旧值 |
| 普通成员函数 | `const` 成员函数 | 后者通过 `this` 权限保证只读语义 |
| 普通取地址重载 | `const` 取地址重载 | 差别来自对象是否只读 |

### 易错点

1. **判断题型误区：** 默认构造函数只指编译器自动生成的构造函数。→ 错。
2. **编译陷阱：** `Date d2();` 不是定义对象，而是函数声明。
3. **拷贝构造陷阱：** 参数若写成传值，会在逻辑上再次触发拷贝构造。
4. **资源类陷阱：** 带堆资源的类直接默认拷贝，常导致重复释放。
5. **运算符误区：** 不是所有运算符都可以重载。
6. **后置 `++` 误区：** 形参里的 `int` 只是占位，不是业务参数。
7. **`const` 误区：** `const` 对象不能调用非 `const` 成员函数。
8. **自赋值误区：** 赋值运算符重载中忽略 `this != &d` 的判断。

## 七、核心总结

- **本讲核心是对象生命周期与对象行为管理。**
- **默认成员函数关心的是对象如何创建、拷贝、赋值、销毁和取地址。**
- **默认构造函数强调“无参可调用”，不等于“编译器自动生成”。**
- **构造函数负责初始化对象，不负责申请对象空间。**
- **析构函数对资源类至关重要。**
- **拷贝构造用于新对象初始化，赋值重载用于已有对象赋值。**
- **资源类若默认拷贝，最容易出浅拷贝问题。**
- **Date 类是本讲运算符重载与对象行为管理的贯穿案例。**
- **`const` 成员函数的本质是限制 `this` 的可写权限。**
