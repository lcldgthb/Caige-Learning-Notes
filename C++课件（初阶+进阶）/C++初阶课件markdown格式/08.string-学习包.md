## 2. 为什么 C++ 要有 `string`

### 2.1 C 风格字符串的问题

C 语言里常见字符串写法：

```cpp
char str[] = "hello";
const char* p = "hello";
```

它们的共同特点是：

- 本质还是字符数组或字符指针。
- 通常依赖 `\0` 作为结束标记。
- 相关操作分散在很多函数中，比如 `strlen`、`strcpy`、`strcmp`、`strcat`。

这样会带来几个问题：

1. **容易越界**：数组大小和实际字符串长度分离。
2. **接口不统一**：查长度、拷贝、拼接都要记不同函数。
3. **不符合面向对象风格**：数据和操作没有封装在一起。
4. **资源管理麻烦**：动态开空间时要自己申请、扩容、释放。

### 2.2 `string` 解决了什么

`string` 是 C++ 标准库中的字符串类，它把“字符串数据 + 常用操作”封装到一起。

你可以把它理解成：

> **一个专门管理字符串的类。**

相比 C 风格字符串，`string` 的优势是：

- 自动管理空间。
- 支持拷贝、赋值、比较、拼接。
- 提供统一成员函数接口。
- 更适合 OJ 和工程开发。

## 3. 学 `string` 前最好先掌握的两个工具：`auto` 和范围 `for`

课件在讲 `string` 前专门引入了两个语法工具，因为后面遍历容器、遍历字符串时会非常好用。

---

### 3.1 `auto` 自动类型推导

#### 基本用法

```cpp
int a = 10;
auto b = a;      // b 推导为 int
auto c = 'a';    // c 推导为 char
```

也可以配合指针、引用：

```cpp
int x = 10;
auto y = &x;   // y 是 int*
auto* z = &x;  // z 是 int*
auto& m = x;   // m 是 int&
```

### 3.2 `auto` 的作用

当类型很长时，`auto` 很方便。

例如：

```cpp
std::map<std::string, std::string> dict;
std::map<std::string, std::string>::iterator it = dict.begin();
```

可以简化成：

```cpp
auto it = dict.begin();
```

### 3.3 `auto` 的注意点

1. **必须初始化**，因为编译器要根据初始值推导类型。
2. 一个语句里多个变量如果都用 `auto`，推导结果必须一致。
3. `auto` 只是让编译器帮你写类型，不是“没有类型”。

---

### 3.4 范围 `for`

C++11 引入了范围 `for`，适合遍历数组、字符串、容器。

#### 传统写法

```cpp
int array[] = {1, 2, 3, 4, 5};
for (int i = 0; i < sizeof(array) / sizeof(array[0]); ++i)
{
    cout << array[i] << " ";
}
```

#### 范围 `for` 写法

```cpp
for (auto e : array)
{
    cout << e << " ";
}
```

遍历字符串：

```cpp
string str("hello world");
for (auto ch : str)
{
    cout << ch << " ";
}
```

#### 修改元素时要用引用

```cpp
for (auto& e : array)
{
    e *= 2;
}
```

如果写成：

```cpp
for (auto e : array)
{
    e *= 2;
}
```

修改的是副本，原数组不会变。

> 记忆点：**只读遍历可用值传递，要改内容就用引用。**

## 4. `string` 的基础使用

---

### 4.1 常见构造函数

课件给出的核心构造方式有：

```cpp
string s1;
string s2("hello bit");
string s3(s2);
string s4(5, 'a');
```

对应理解：

| 写法 | 含义 |
|---|---|
| `string s1;` | 构造空字符串 |
| `string s2("hello bit");` | 用 C 字符串构造 |
| `string s3(s2);` | 拷贝构造 |
| `string s4(5, 'a');` | 构造 5 个 `'a'` 组成的字符串 |

### 4.2 先掌握一个事实

`string` 虽然底层也是一串字符，但你平时应该把它当成一个“类对象”来看，而不是简单字符数组。

也就是说，你日常写法应该是：

```cpp
string s = "hello";
s += " world";
cout << s << endl;
```

而不是总想着手动 `strlen`、`strcpy`。

## 5. 容量与大小相关接口

课件重点讲了下面几组接口：

- `size()`
- `length()`
- `capacity()`
- `empty()`
- `clear()`
- `reserve()`
- `resize()`

---

### 5.1 `size()` 和 `length()`

对于 `string`：

```cpp
s.size()
s.length()
```

二者含义相同，都是返回当前字符串中有效字符个数。

例如：

```cpp
string s = "hello";
cout << s.size() << endl;    // 5
cout << s.length() << endl;  // 5
```

### 5.2 `capacity()`

`capacity()` 表示**当前已分配空间中可容纳的字符规模**。

- `size()` 看“现在有多少字符”。
- `capacity()` 看“当前空间最多能较稳定容纳多少字符而不扩容”。

考试和面试中通常不要求死记具体扩容策略，但要知道：

> **`capacity` 关注空间，`size` 关注内容长度。**

### 5.3 `empty()`

```cpp
if (s.empty())
{
    // 空字符串
}
```

返回值：

- 空字符串返回 `true`
- 非空返回 `false`

### 5.4 `clear()`

```cpp
s.clear();
```

作用：把字符串清空。

注意：

- 清空后 `size()` 会变成 0。
- `capacity()` 是否缩小，不要想当然依赖具体实现。

### 5.5 `resize(size_t n)` 和 `resize(size_t n, char c)`

#### 情况 1：只写长度

```cpp
string s = "abc";
s.resize(5);
```

如果扩长，多出的字符会补默认值字符 `\0` 对应的效果位置；在实际打印时往往不直接可见。

#### 情况 2：指定填充值

```cpp
string s = "abc";
s.resize(5, 'x');
```

结果变成：

```cpp
"abcxx"
```

#### 如果缩短

```cpp
string s = "abcdef";
s.resize(3);
```

结果：

```cpp
"abc"
```

### 5.6 `reserve(size_t n)`

```cpp
string s;
s.reserve(100);
```

作用：**预留空间容量**，减少频繁扩容。

注意区分：

| 接口 | 影响什么 |
|---|---|
| `reserve(n)` | 主要影响容量 `capacity`，不直接改变逻辑长度 `size` |
| `resize(n)` | 直接改变字符串长度 `size` |

这是高频易混点。

## 6. `string` 的遍历方式

课件强调了几种常见遍历方法。

---

### 6.1 下标访问 `operator[]`

```cpp
string s = "hello";
for (size_t i = 0; i < s.size(); ++i)
{
    cout << s[i] << " ";
}
```

特点：

- 最直观。
- 适合已知下标、需要随机访问时使用。

### 6.2 迭代器遍历

```cpp
string s = "hello";
string::iterator it = s.begin();
while (it != s.end())
{
    cout << *it << " ";
    ++it;
}
```

也可以用 `auto` 简化：

```cpp
for (auto it = s.begin(); it != s.end(); ++it)
{
    cout << *it << " ";
}
```

### 6.3 反向迭代器

```cpp
for (auto rit = s.rbegin(); rit != s.rend(); ++rit)
{
    cout << *rit << " ";
}
```

这适合逆序遍历。

### 6.4 范围 `for`

```cpp
for (auto ch : s)
{
    cout << ch << " ";
}
```

如果要修改字符：

```cpp
for (auto& ch : s)
{
    if (ch >= 'a' && ch <= 'z')
        ch -= 32;
}
```

## 7. `string` 的常用修改与查找接口

课件把下面这些接口列为重点：

- `push_back`
- `append`
- `operator+=`
- `c_str()`
- `find`
- `rfind`
- `substr`

---

### 7.1 `push_back`

在字符串尾部追加一个字符：

```cpp
string s = "abc";
s.push_back('d');
```

结果：

```cpp
"abcd"
```

### 7.2 `append`

追加字符串：

```cpp
string s = "hello";
s.append(" world");
```

结果：

```cpp
"hello world"
```

也可以追加指定数量字符：

```cpp
s.append(3, '!');
```

### 7.3 `operator+=`

这个在 OJ 和日常代码里很常用。

```cpp
string s = "ab";
s += 'c';
s += "def";
```

结果：

```cpp
"abcdef"
```

课件也强调：

> `+=` 在追加字符、追加字符串时都很好用。

### 7.4 `c_str()`

把 `string` 转成 C 风格字符串接口需要的形式：

```cpp
string s = "hello";
const char* p = s.c_str();
```

使用场景：

- 调用只接受 `const char*` 的旧式 C 接口。
- 与某些底层库交互。

### 7.5 `find`

查找子串或字符第一次出现的位置。

```cpp
string s = "hello world";
size_t pos1 = s.find('o');
size_t pos2 = s.find("world");
```

如果没找到，返回：

```cpp
string::npos
```

这是必须会写的判断：

```cpp
if (pos != string::npos)
{
    // 找到了
}
```

### 7.6 `rfind`

从右往左找最后一次出现的位置。

```cpp
size_t pos = s.rfind(' ');
```

这在“最后一个单词长度”这类题里非常常用。

### 7.7 `substr`

取子串：

```cpp
string s = "hello world";
string sub = s.substr(6, 5);
```

结果：

```cpp
"world"
```

理解：

- 第一个参数：起始位置 `pos`
- 第二个参数：截取长度 `len`

## 8. 输入输出：`>>`、`<<` 和 `getline`

---

### 8.1 `operator>>`

```cpp
string s;
cin >> s;
```

特点：

- 遇到空格、制表符、换行会停止。
- 适合读“单个单词”。

例如输入：

```text
hello world
```

如果用 `cin >> s`，读到的是：

```text
hello
```

### 8.2 `getline`

```cpp
string line;
getline(cin, line);
```

特点：

- 按整行读取。
- 可以读入带空格的句子。

这在 OJ 和实际开发中都很常见。

### 8.3 什么时候用哪个

| 需求 | 推荐 |
|---|---|
| 读一个不含空格的单词 | `cin >> s` |
| 读一整行文本 | `getline(cin, s)` |

## 9. OJ / 笔试中的典型题型

课件后半段给了几道典型题，重点不是死背题，而是提炼模型。

---

### 9.1 只反转字母：双指针 + 判断函数

核心思想：

- 左指针从前往后找字母。
- 右指针从后往前找字母。
- 找到后交换。

示意代码：

```cpp
bool isLetter(char ch)
{
    if (ch >= 'a' && ch <= 'z') return true;
    if (ch >= 'A' && ch <= 'Z') return true;
    return false;
}

string reverseOnlyLetters(string s)
{
    if (s.empty()) return s;

    size_t begin = 0;
    size_t end = s.size() - 1;

    while (begin < end)
    {
        while (begin < end && !isLetter(s[begin])) ++begin;
        while (begin < end && !isLetter(s[end])) --end;
        swap(s[begin], s[end]);
        ++begin;
        --end;
    }

    return s;
}
```

#### 这题训练什么

- `string` 下标访问
- 双指针
- 分类跳过无效字符

---

### 9.2 第一个只出现一次的字符：计数统计

典型思路：

1. 先遍历一遍统计每个字符出现次数。
2. 再遍历一遍，找到第一个出现次数为 1 的位置。

示意：

```cpp
int firstUniqChar(string s)
{
    int count[256] = {0};
    int size = (int)s.size();

    for (int i = 0; i < size; ++i)
    {
        count[(unsigned char)s[i]] += 1;
    }

    for (int i = 0; i < size; ++i)
    {
        if (count[(unsigned char)s[i]] == 1)
            return i;
    }

    return -1;
}
```

#### 这题训练什么

- `string` 遍历
- 字符统计
- 两遍扫描思维

---

### 9.3 最后一个单词的长度：`getline + rfind`

课件代码主线是：

```cpp
string line;
while (getline(cin, line))
{
    size_t pos = line.rfind(' ');
    cout << line.size() - pos - 1 << endl;
}
```

#### 思路

- 先读整行。
- 找最后一个空格位置。
- 用总长度减去这个位置，得到最后一个单词长度。

#### 易错点

如果题目可能没有空格，要额外判断 `pos == string::npos`。

---

### 9.4 验证回文串：双指针 + 过滤非法字符

课件做法核心是：

1. 先把小写字母转成大写，或统一成同一种大小写。
2. 左右双指针向中间逼近。
3. 跳过非字母数字字符。

示意：

```cpp
bool isLetterOrNumber(char ch)
{
    return (ch >= '0' && ch <= '9')
        || (ch >= 'a' && ch <= 'z')
        || (ch >= 'A' && ch <= 'Z');
}

bool isPalindrome(string s)
{
    for (auto& ch : s)
    {
        if (ch >= 'a' && ch <= 'z')
            ch -= 32;
    }

    int begin = 0;
    int end = (int)s.size() - 1;

    while (begin < end)
    {
        while (begin < end && !isLetterOrNumber(s[begin])) ++begin;
        while (begin < end && !isLetterOrNumber(s[end])) --end;

        if (s[begin] != s[end])
            return false;

        ++begin;
        --end;
    }

    return true;
}
```

#### 这题训练什么

- 引用遍历修改字符
- 分类过滤
- 双指针模板

---

### 9.5 字符串相加：从后往前模拟竖式加法

课件里的做法非常典型。

思路：

1. 从两个字符串尾部开始取数字。
2. 加上进位。
3. 把当前位结果先追加到答案末尾。
4. 最后整体 `reverse`。

示意：

```cpp
string addStrings(string num1, string num2)
{
    int end1 = (int)num1.size() - 1;
    int end2 = (int)num2.size() - 1;
    int next = 0;
    string ret;

    while (end1 >= 0 || end2 >= 0)
    {
        int value1 = (end1 >= 0) ? num1[end1--] - '0' : 0;
        int value2 = (end2 >= 0) ? num2[end2--] - '0' : 0;

        int sum = value1 + value2 + next;
        if (sum > 9)
        {
            next = 1;
            sum -= 10;
        }
        else
        {
            next = 0;
        }

        ret += (sum + '0');
    }

    if (next == 1)
    {
        ret += '1';
    }

    reverse(ret.begin(), ret.end());
    return ret;
}
```

#### 为什么最后要 `reverse`

因为我们是从低位往高位算，但字符串从左到右应该是高位到低位。

## 10. `string` 使用中的几个关键习惯

### 10.1 追加大量字符前可先 `reserve`

如果你知道后面会频繁拼接，提前预留空间可以减少扩容次数：

```cpp
string s;
s.reserve(1000);
```

这在刷题拼接大字符串时常见。

### 10.2 查找失败要会写 `string::npos`

很多初学者会误写成 `-1`。虽然很多实现里它表现得像一个很大的无符号数，但规范写法是：

```cpp
if (pos == string::npos)
{
    // 没找到
}
```

### 10.3 `getline` 和 `cin >>` 混用要小心换行

如果前面用了：

```cpp
cin >> x;
```

后面直接：

```cpp
getline(cin, line);
```

可能会读到残留换行。这是 OJ 高频坑点。

### 10.4 修改字符时优先用引用

```cpp
for (auto& ch : s)
{
    // 改 ch 才能真的改到字符串本体
}
```

## 11. VS 和 g++ 下 `string` 的简单认识

课件提到不同编译器实现下 `string` 对象大小可能不同。

### 11.1 你真正需要记什么

不是记住具体字节数，而是记住：

1. **`string` 的底层实现不是语言标准固定死的。**
2. 不同编译器、不同标准库实现，内部结构可能不同。
3. 之所以对象本身看起来不大，是因为它通常内部维护长度、容量、指针，或者做了小字符串优化。

### 11.2 小字符串优化（了解）

课件里提到 VS 的实现现象，本质是在说明：

> **较短字符串可能直接存在对象内部，不必马上额外堆分配。**

这叫小字符串优化（SSO，了解即可）。

当前阶段不要在考试中硬背具体结构体字段，更重要的是知道：

- `string` 不等于“仅仅一个 `char*`”。
- 它背后还有长度、容量、空间管理等机制。

## 12. 自己实现 `String` 类：为什么这是本章真正的难点

如果只会调 `std::string` 接口，这一章只能算“会用”。

真正能拉开理解层次的是：

## 13. 自定义 `String` 类第一版：构造与析构

课件一开始先写了一个最基础的版本。

```cpp
class String
{
public:
    String(const char* str = "")
    {
        if (nullptr == str)
        {
            assert(false);
            return;
        }

        _str = new char[strlen(str) + 1];
        strcpy(_str, str);
    }

    ~String()
    {
        if (_str)
        {
            delete[] _str;
            _str = nullptr;
        }
    }

private:
    char* _str;
};
```

### 13.1 这个版本做对了什么

1. 支持从 C 字符串构造。
2. 自己申请字符空间。
3. 析构时能释放空间。

### 13.2 但马上会出什么问题

看下面代码：

```cpp
String s1("hello bit!!!");
String s2(s1);
```

如果你没有自己写拷贝构造，编译器默认生成的是：

> **逐成员拷贝**

也就是 `_str` 这个指针值直接拷贝过去。

结果：

- `s1._str` 和 `s2._str` 指向同一块空间。
- 两个对象析构时都会 `delete[]` 这块空间。
- 最终发生**重复释放**。

这就是浅拷贝问题。

## 14. 深拷贝版 `String`

为了解决浅拷贝，课件给出了深拷贝版本。

```cpp
class String
{
public:
    String(const char* str = "")
    {
        if (nullptr == str)
        {
            assert(false);
            return;
        }
        _str = new char[strlen(str) + 1];
        strcpy(_str, str);
    }

    String(const String& s)
        : _str(new char[strlen(s._str) + 1])
    {
        strcpy(_str, s._str);
    }

    String& operator=(const String& s)
    {
        if (this != &s)
        {
            char* pStr = new char[strlen(s._str) + 1];
            strcpy(pStr, s._str);
            delete[] _str;
            _str = pStr;
        }
        return *this;
    }

    ~String()
    {
        if (_str)
        {
            delete[] _str;
            _str = nullptr;
        }
    }

private:
    char* _str;
};
```

### 14.1 这个版本的核心思想

#### 拷贝构造

- 新对象自己重新开一块空间。
- 把源对象内容复制过来。
- 两个对象各管各的空间。

#### 赋值运算符

- 先判断是否自赋值。
- 先申请新空间。
- 拷贝内容。
- 再释放旧空间。
- 最后让 `_str` 指向新空间。

### 14.2 为什么不能先删旧空间再开新空间

如果写成：

```cpp
delete[] _str;
_str = new char[...];
```

一旦 `new` 失败，对象就处于被破坏状态。

所以更稳妥做法是：

1. 先申请新空间。
2. 申请成功后再释放旧空间。

这体现的是**异常安全思维**。

## 15. 更优雅的写法：拷贝交换法（copy-swap）

课件还给出了更简洁的一版。

```cpp
class String
{
public:
    String(const char* str = "")
    {
        if (nullptr == str)
        {
            assert(false);
            return;
        }
        _str = new char[strlen(str) + 1];
        strcpy(_str, str);
    }

    String(const String& s)
        : _str(nullptr)
    {
        String strTmp(s._str);
        swap(_str, strTmp._str);
    }

    String& operator=(String s)
    {
        swap(_str, s._str);
        return *this;
    }

    ~String()
    {
        if (_str)
        {
            delete[] _str;
            _str = nullptr;
        }
    }

private:
    char* _str;
};
```

### 15.1 赋值运算符为什么写成 `String s`

这里参数不是 `const String& s`，而是**按值传参**。

这意味着：

- 传参时先调用拷贝构造，得到一个副本 `s`。
- 然后把当前对象和副本的资源交换。
- 函数结束时，副本析构，把旧资源释放掉。

### 15.2 这种写法的优点

1. 代码简洁。
2. 自动处理自赋值。
3. 异常安全性更自然。
4. 把“拷贝”和“资源交换”分离得更清楚。

### 15.3 这一版最值得学到什么

不是死记代码，而是学会这个思想：

> **先构造一个安全副本，再交换资源。**

这是资源管理类里非常经典的写法。

## 17. 高频易错点清单

### 易错点 1：把 `reserve` 和 `resize` 混为一谈

- `reserve(n)`：预留容量。
- `resize(n)`：直接改字符串长度。

这是最常见混淆点之一。

---

### 易错点 2：以为范围 `for` 一定能改原字符串

错误写法：

```cpp
for (auto ch : s)
{
    ch = 'x';
}
```

这只改了副本。

正确写法：

```cpp
for (auto& ch : s)
{
    ch = 'x';
}
```

---

### 易错点 3：查找失败不会写 `string::npos`

错误理解：

```cpp
if (pos == -1)
```

更规范的写法：

```cpp
if (pos == string::npos)
```

---

### 易错点 4：`cin >> s` 能读带空格整行

不能。

如果要读：

```text
hello world cpp
```

应该用：

```cpp
getline(cin, s);
```

---

### 易错点 5：自定义 `String` 不写拷贝构造和赋值

如果类中有 `_str` 这种动态资源指针，而你不自己处理拷贝控制，就会发生浅拷贝问题。

---

### 易错点 6：`String& operator=(const String& s)` 中不考虑自赋值

虽然很多写法看起来能跑，但如果释放顺序、申请顺序处理不好，自赋值可能出问题。

## 18. 面试 / 考试常问题

### 题 1：为什么 C++ 要提供 `string`，而不只用 C 字符串？

**标准回答思路：**

C 风格字符串本质上是字符数组或字符指针，以 `\0` 结尾，操作依赖 `strlen`、`strcpy`、`strcmp` 等函数，使用繁琐且容易越界。`string` 是 C++ 标准库中的字符串类，封装了字符串数据和常用操作，能够自动管理空间，支持拷贝、赋值、拼接、查找等功能，更符合面向对象和泛型编程风格。

---

### 题 2：`size`、`capacity`、`reserve`、`resize` 有什么区别？

**标准回答思路：**

- `size()` 表示当前字符串有效字符个数。
- `capacity()` 表示当前已分配空间的容量规模。
- `reserve(n)` 用于预留容量，主要影响容量，不直接改变字符串长度。
- `resize(n)` 用于修改字符串长度，长度变大时可能填充默认字符或指定字符，长度变小时会截断内容。

---

### 题 3：`find` 没找到返回什么？

返回 `string::npos`。

---

### 题 4：`operator>>` 和 `getline` 的区别是什么？

- `operator>>` 遇到空白字符停止，适合读单词。
- `getline` 按整行读取，适合读带空格字符串。

---

### 题 5：自己写 `String` 类为什么要重写拷贝构造和赋值运算符？

因为类中管理了动态开辟的字符空间，如果使用编译器默认生成的逐成员拷贝，只会拷贝指针地址，导致多个对象共享同一块内存，析构时发生重复释放。因此需要深拷贝，让每个对象各自拥有独立空间。

---

### 题 6：拷贝交换法有什么好处？

它通过“先构造副本，再交换资源”的方式，把资源管理写得更简洁，同时更容易处理自赋值和异常安全问题。
