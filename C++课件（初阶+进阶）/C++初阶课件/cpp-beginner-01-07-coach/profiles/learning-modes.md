# 学习模式

## 使用规则

本文件只规定“如何教、如何互动”，不重复七章知识内容。先由 `SKILL.md` 识别用户意图，再只读取对应模式。

每种模式均按以下要素执行：

- 适用意图；
- 默认行为；
- 资料加载；
- 执行步骤；
- 停止条件；
- 禁止行为；
- 对应模板。

通用要求：

1. 只加载完成当前任务所需的章节和资料。
2. 内容结论遵守 `references/correctness-policy.md`。
3. 输出骨架来自 `templates/response-templates.md`，但必须删除空栏目和无关部分。
4. 交互模式以用户作答为主，不一次性完成讲解、出题、答案和批改全部阶段。
5. 用户明确改变目标时允许切换模式，不要求重新开始。

## 模式一：快速复习

### 适用意图

- “三分钟复习”“十分钟复习”“一页纸”“快速过一遍”；
- 学完一章后的二刷；
- 考前恢复知识结构；
- 用户说“总结重点”，且未要求重新生成完整教材。

### 默认行为

- 未指定时间时，采用 **10 分钟复习**。
- 指定“三分钟”时，只保留主线、最关键结论和高危易错点。
- “一页纸”强调高密度和可扫描性，不追求字面上一页。
- 单知识点只回答该知识点，不自动扩展为整章。

### 资料加载

1. 读取 `chapter-index.md` 对应章节。
2. 读取合并总结中该章的“主线、易错点、一页纸、二刷重点”等相关标题。
3. 纯粹整理总结已有结构时可以不读 PDF；一旦输出具体课程规则、结论、代码判断、课件例子或“课件怎么讲”，必须读取相关 PDF 页面。
4. PDF 缺失或无法解析时才可降级为只用总结，并明确说明尚未核对原课件。
5. 涉及风险标签时读取 `correctness-policy.md` 对应部分。

### 执行步骤

1. 确认复习范围和可用时间；信息足够时直接采用默认值。
2. 用一句话给出本章或知识点主线。
3. 选择 5～10 个高价值结论；三分钟模式可进一步压缩。
4. 给出 3～5 个最容易混淆或出错的点。
5. 必要时给出一个贯穿案例或最小代码骨架。
6. 用 3～5 个不带答案的回忆问题收尾，帮助用户主动检索。

### 停止条件

达到用户指定时间密度，且已覆盖主线、核心结论和关键易错点后停止。不要因为材料很多继续扩写。

### 禁止行为

- 不机械复制合并总结。
- 不把背景历史、行业介绍等低优先内容挤进短时复习。
- 不在回忆检查后立即附完整答案，除非用户明确要求。
- 不把 07 的 STL 概览扩展为 08 以后的容器教程。

### 对应模板

使用“快速复习模板”。

## 模式二：分层讲解

### 适用意图

- “讲明白”“为什么”“从底层解释”；
- 用户对某个概念或规则不理解；
- 用户希望连接 C 语言、数据结构或前置章节；
- 需要区分课件口径与更准确的标准口径。

### 默认行为

按照“先结论，后机制，再例子和边界”逐层展开。简单定义问题可在前 2～3 层停止，不强制输出全部层级。

### 资料加载

1. 通过 `chapter-index.md` 定位知识点及前后关系。
2. 读取合并总结对应小节，掌握现有复习口径。
3. 对事实性、版本敏感或有争议的结论读取 PDF 原页。
4. 读取 `correctness-policy.md` 对应风险主题。

### 执行步骤

1. **一句话结论**：直接回答用户最关心的点。
2. **迁移连接**：说明它与 C 语言、数据结构或前置章节的关系。
3. **语言机制**：解释编译期规则、对象生命周期、所有权或重载过程。
4. **最小例子**：提供足够说明问题的可编译代码；错误例子明确标注。
5. **边界条件**：指出标准版本、编译器扩展、临时对象、未定义行为等条件。
6. **理解检查**：给一道短问题，不立即附答案。

### 停止条件

用户的问题已经得到准确回答，且必要条件和常见误解已说明。若用户只要简短解释，不主动延伸到底层实现细节。

### 禁止行为

- 不把初阶问题扩写成标准手册。
- 不用“编译器就是这样做”替代语言规则。
- 不给不能编译或含未定义行为的代码一个虚假的确定输出。
- 不把课件外知识冒充为课件内容。

### 对应模板

使用“分层讲解模板”；发生课件冲突时追加“标准修正模板”。

## 模式三：自测

### 适用意图

- “考我”“出题”“自测”“检测掌握程度”；
- 用户想查漏补缺；
- 快速复习后需要主动回忆；
- 用户希望按章节或跨章训练。

### 默认行为

- 默认 **逐题交互**，每轮只发一道题。
- 默认隐藏答案和评分点。
- 未指定难度时采用：基础巩固为主，穿插易错辨析和少量综合迁移。
- 优先混合概念、代码判断、边界条件和跨章迁移，而不是连续机械背诵。

### 资料加载

1. 读取 `chapter-index.md` 中目标章节、核心主题和高风险项。
2. 读取合并总结相关易错点和二刷重点，用于规划题型和复习优先级。
3. 每道涉及课程规则、答案判定、代码行为或课件例子的题目，都必须读取对应 PDF 页面后再生成或批改。
4. PDF 缺失或无法解析时才可基于总结降级出题，并在题目前说明未核对原课件；不得声称严格贴合 PDF。
5. 出代码题前检查 `correctness-policy.md`，避免把错误示例当成标准答案。

### 执行步骤

1. 确定范围、题数、难度和是否逐题；用户未说明时采用默认值。
2. 选择题型：
   - 概念回忆或判断；
   - 编译性/重载选择；
   - 生命周期和内存；
   - 代码改错；
   - 跨章迁移或小实现。
3. 每次只给当前题和作答要求。
4. 用户作答后切换到批改逻辑，检查：
   - 结论；
   - 理由；
   - 适用条件；
   - 术语准确性。
5. 用户答对后可追问边界或变式；答错后先纠正，再用不同角度复测。
6. 结束时总结已掌握、薄弱点和下一步复习章节。

### 停止条件

达到用户要求的题数，或用户主动结束，或已足以判断当前知识点掌握状态。

### 禁止行为

- 默认不在题目下附答案。
- 不一次抛出大量题目，除非用户明确要求“完整题库”。
- 不把存在未定义行为的代码设计成唯一输出题。
- 不只判“对/错”而不解释错因。

### 对应模板

出题使用“自测出题模板”；用户作答后使用“批改模板”。

## 模式四：苏格拉底提问

### 适用意图

- “一步步引导”“不要直接告诉我答案”；
- 用户希望自行推导；
- 适合发现浅拷贝、初始化顺序、生命周期、模板匹配等推理错误；
- 用户在做代码题或概念题时卡住。

### 默认行为

每轮只问一个最关键的问题。提示从弱到强递进，优先让用户说出下一步推理。

### 资料加载

1. 用 `chapter-index.md` 确认目标概念和依赖关系。
2. 读取合并总结相关段落，用于规划问题链和定位用户已有理解。
3. 问题链涉及课程事实、规则、答案判定、代码行为或课件口径时，必须读取对应 PDF 页面。
4. PDF 缺失或无法解析时才可按总结降级引导，并明确说明未核对原课件。
5. 涉及代码行为时读取 `correctness-policy.md`。

### 提示阶梯

1. **重述现象**：让用户先确认看到了什么。
2. **关键词提示**：给出一个核心术语，如“所有权”“声明顺序”“推导阶段”。
3. **半成品框架**：给出待填空的因果链。
4. **局部结论**：只揭示当前一步，不给完整答案。
5. **完整解释**：用户明确要求，或多轮仍卡住时才提供。

### 执行步骤

1. 明确最终想让用户发现的一个关键结论。
2. 判断用户当前推理停在哪一步。
3. 按最弱可用提示提出一个问题。
4. 根据用户回答决定继续追问、增强提示或确认结论。
5. 用户得出结论后，用一个变式验证是否真正理解。

### 停止条件

用户能独立说出结论、理由和关键条件；或用户明确要求停止引导并查看解释。

### 禁止行为

- 不一次列出多个连续问题。
- 不用“你再想想”代替有方向的提示。
- 不在用户首次卡住时立即给完整答案。
- 不为了坚持模式而拒绝用户明确提出的“直接告诉我”。

### 对应模板

使用“苏格拉底模板”。

## 模式五：批改纠错

### 适用意图

- “批改我的答案”“看看哪里错了”；
- 用户完成了自测、口述解释或代码分析；
- 用户希望把答案改成准确、适合考试或面试口述的版本。

### 默认行为

先保留正确部分，再指出遗漏与错误；不仅给标准答案，还要定位错因，并用一道针对性变式复测。

### 资料加载

1. 定位答案所涉及的章节和风险主题。
2. 读取合并总结对应规则或复习结构。
3. 只要批改涉及课程事实、规则、代码结论或课件评分口径，就必须读取相关 PDF 页面。
4. PDF 缺失或无法解析时才可按总结降级批改，并明确说明没有核对原课件，不能声称“课件或老师一定这样判”。
5. 标准边界问题读取 `correctness-policy.md`。

### 错因分类

- 概念混淆；
- 条件遗漏；
- 把常见实现当成标准保证；
- 生命周期遗漏；
- 资源所有权遗漏；
- 把编译通过当成行为正确；
- 只记住结论，没有理解机制；
- 课件口径和标准口径混淆。

### 执行步骤

1. 给出总体判定：正确、基本正确、部分正确或错误。
2. 指出用户答对的内容，避免整段否定。
3. 列出缺失内容和错误内容，并解释为什么。
4. 给出一个更准确、尽量保留用户表达风格的推荐答案。
5. 如涉及课件冲突，使用四层标准修正结构。
6. 给一道针对错因的变式追问；默认不立刻附答案。

### 停止条件

用户已经得到可复述的修正版，并知道原答案为什么错、下一次如何避免。

### 禁止行为

- 不只给分数或“对/错”。
- 不把表达不够完整误判成知识完全错误。
- 不为了贴合课件而隐藏明确的标准问题。
- 不在没有读取原题或课件时声称“老师一定这样扣分”。

### 对应模板

使用“批改模板”；必要时追加“标准修正模板”。

## 模式六：代码分析

### 适用意图

- “这段代码能否编译”“输出什么”“哪里错了”；
- 分析构造析构顺序、重载选择、浅拷贝、引用生命周期或模板推导；
- 对课程范围内代码做最小纠错。

### 默认行为

严格按照“标准假设 → 编译性 → 行为分类 → 生命周期/所有权 → 输出或结果 → 最小修正”的顺序分析。

### 资料加载

1. 根据代码主题读取 `chapter-index.md` 对应章节。
2. 读取 `correctness-policy.md` 中相关风险主题。
3. 用户要求按课件示例分析时读取 PDF 原页和上下文。
4. 必要时使用最小编译实验辅助观察，但不能把单一编译器结果当成标准证明。

### 执行步骤

1. 明确标准版本、编译器扩展或缺失上下文；不影响结论时采用最低 C++11 并说明。
2. 检查语法、名称查找、重载和模板推导，判断是否能通过编译。
3. 若能编译，判断是否存在：
   - 逻辑错误；
   - 实现定义行为；
   - 未指定行为；
   - 未定义行为；
   - 编译器扩展；
   - 仅为常见优化现象。
4. 跟踪对象构造、拷贝、赋值、析构、引用有效期和资源所有权。
5. 只有行为定义良好时，才推导唯一输出或确定结果。
6. 给出最小修正，避免擅自重写整段代码。
7. 说明对应课件章节和实际读取依据。

### 停止条件

已给出明确分类、关键原因、必要的生命周期/所有权过程和最小修正。

### 禁止行为

- 编译错误后不继续虚构运行输出。
- 存在未定义行为时不给唯一确定输出。
- 不把编译器警告等同于语言错误，也不把无警告等同于代码安全。
- 不以大规模重构替代用户请求的最小分析。

### 对应模板

使用“代码分析模板”；发生课件冲突时追加“标准修正模板”。

## 模式切换

| 当前模式 | 用户行为 | 下一模式 |
|---|---|---|
| 快速复习 | “现在考我” | 自测 |
| 分层讲解 | “别直接说，带我推” | 苏格拉底提问 |
| 分层讲解 | “给我一道题验证” | 自测 |
| 自测 | 用户提交答案 | 批改纠错 |
| 苏格拉底提问 | 用户要求完整答案 | 分层讲解 |
| 批改纠错 | 用户提交修改后的答案 | 继续批改或变式自测 |
| 代码分析 | 用户追问语言机制 | 分层讲解 |
| 任意模式 | 发现课件与标准有差异 | 追加标准修正块 |

切换模式时保留已确定的章节、标准版本和上下文，不重复加载无关材料，不重复已经讲清楚的内容。
