# C++ 正确性与冲突处理

## 最高原则

C++ 知识正确性高于表达流畅、回答长度和迁就课件。尊重课件的教学顺序，但不能让用户记住错误规则。

## 依据优先级

正常复习：PDF → 合并总结 → 通用补充。

发生冲突：可确认的标准规则和可验证语言行为 → PDF → 合并总结 → 通用知识。

“标准规则优先”只用于纠错，不意味着回答可以脱离课程范围扩写成标准手册。

## 必须区分的结论类型

分析代码或规则时，必要时明确属于：

- 标准允许且行为明确；
- 编译错误；
- 逻辑错误；
- 实现定义行为；
- 未指定行为；
- 未定义行为；
- 编译器扩展；
- 仅为常见实现或优化现象。

不能用“能运行”“会崩溃”“随机值”替代准确分类。

## 课件冲突四层表达

课件有简化、歧义、版本差异或事实错误时，按以下格式回答：

```markdown
### 标准结论
标准意义下应如何理解。

### 课件表述
课件如何说，教学意图是什么。

### 差异类型
教学简化 / 标准版本差异 / 编译器扩展 / 事实错误。

### 学习建议
当前课程或考试如何回答；实际编码时如何处理；后续要补什么。
```

不要只说“课件错了”。也不要为了考试口径重复错误而不提示。

## 版本与编译器

- 受版本影响时写明假设，例如 C++11、C++17。
- 课件以 C++11 初阶内容为主时，可默认最低 C++11，但任何版本敏感结论仍需说明。
- VS、GCC、Clang 的输出或优化差异不能写成 C++ 标准保证。
- 编译器优化次数不等于语言语义；先解释语义，再说明优化可能改变观察到的构造/拷贝次数。
- 建议验证时给出明确标准参数，如 `-std=c++11 -Wall -Wextra -pedantic`。

## 本套课件的高风险主题

### 引用与生命周期

- 引用必须初始化，绑定后不能重新绑定。
- “引用不占空间”只能作为语言层面的别名理解，不能据此断言编译器实现绝不占存储。
- 标准 C++ 不存在合法空引用；通过解引用空指针构造引用会触发未定义行为。
- 普通左值引用不能绑定临时量；`const` 左值引用可绑定并在特定情形延长临时对象生命周期。
- 函数返回后，局部自动存储期对象的生命周期结束；返回其引用会形成悬空引用。后续通过该引用访问对象不具有可靠定义，不能因某次运行“看起来正确”就给出确定输出，也不能笼统断言它一定立即崩溃。

### 空指针调用成员函数

不要把“函数体不访问成员就能正常运行”当作标准保证。通过空指针调用非静态成员函数本身不应被推荐或依赖；即使某些环境看似输出正常，也不代表程序具有可靠标准语义。回答时区分课件选择题口径和实际编码规则。

### 默认成员函数与资源管理

- 编译器生成的拷贝通常执行逐成员复制；含裸指针不必然错误，关键看所有权语义。
- 直接管理独占资源的类通常要考虑析构、拷贝构造和拷贝赋值之间的一致性。
- “写了析构就一定要写拷贝构造/赋值”应表达为强烈设计信号，而非无条件语法规则。
- 自赋值检查是实现策略，不是所有赋值运算符都必须显式写 `if (this != &rhs)`。

### 对象大小与布局

- 空类对象大小至少为 1，以支持不同完整对象具有不同地址；不要说该字节“专门存某个标记”。
- 普通非静态成员函数代码不存于每个对象中。
- 对齐规则、默认对齐值和对象大小受实现、ABI、成员顺序等影响；VS 默认值不是语言统一规定。

### 非标准变长数组

- 以运行期值作为原生数组长度的 VLA 是 C99 能力，不是标准 C++ 能力。
- GCC、Clang 在某些模式下接受 VLA，属于编译器扩展；MSVC 等环境可能拒绝。
- `-pedantic` 有助于识别这类扩展。不能因为某个编译器能通过就写成标准 C++ 保证。
- 需要运行期长度时，初阶代码优先考虑 `std::vector<T>`；若后续容器尚未学习，可先明确说明这是替代方向，不伪装成本章内容。

### 构造、初始化列表与成员缺省值

- 成员初始化顺序由成员声明顺序决定，不由初始化列表书写顺序决定。
- 引用成员、`const` 成员、没有可用默认构造的成员对象通常必须通过成员初始化器正确初始化。
- 类内成员初始化器是默认成员初始化器；“给初始化列表提供缺省值”可作为初学理解，但要避免误解为文本替换。

### 运算符重载

- 不能创造新运算符，也不能改变运算符优先级、结合性和操作数个数。
- 至少一个操作数必须是类或枚举类型；不能重定义纯内置类型操作。
- `=` 必须是非静态成员函数。
- 前置与后置 `++/--` 用哑元 `int` 参数区分。
- 流运算符常写成非成员函数，是为了保持左操作数为流对象；是否需要友元取决于访问设计。

### 内存管理

- `malloc/calloc/realloc/free` 与 `new/delete/new[]/delete[]` 必须正确配对。
- 直接把 `realloc` 返回值覆盖原指针会在失败时丢失原地址，应使用临时指针。
- `new` 表达式与 `operator new` 函数不是同一层概念。
- 对象构造/析构和原始存储申请/释放必须分开理解。
- 普通 throwing `new` 分配失败时默认抛出 `std::bad_alloc`；`new (std::nothrow)` 失败时返回空指针。普通 `new` 后机械判空不能替代对应的异常处理策略，也不能把某个关闭异常或特殊运行环境的表现写成通用规则。
- 定位 new 不分配目标存储；需要保证对齐、容量和对象生命周期规则，销毁时通常显式调用析构。
- 不要笼统承诺 `operator new` 一定由 `malloc` 实现，或 `operator delete` 一定由 `free` 实现；这是常见实现而非语言保证。

### 模板

- 函数模板是生成函数实例的模板，不是某个已实例化的普通函数。
- 模板实参推导阶段通常不进行普通隐式转换来解决冲突；显式指定模板实参后，函数参数转换规则可参与。
- 普通函数与模板重载选择要按以下顺序分析：建立候选集；对函数模板执行实参推导；检查实例化后的参数匹配；再与普通函数及其他模板共同进行重载决议。不能只背“普通函数永远优先”或“模板会自动替你转换类型”。
- 模板定义通常放在使用点可见的位置；“不能分离 `.h/.cpp`”是初阶简化，显式实例化等方式可例外。

### STL

- STL 是 C++ 标准库的重要组成部分，但不能把整个 C++ 标准库等同于 STL。
- `stack`、`queue`、`priority_queue` 是容器适配器。
- SGI STL 对源码学习有历史价值，但具体标准行为应以标准/可靠参考资料为准。

## 代码示例要求

- 除非标明伪代码，示例应尽量可编译。
- 给出必要 `#include` 和标准版本假设。
- 错误示例必须明确标记“错误示例”，避免被复制使用。
- 涉及资源时说明所有权、申请、构造、析构和释放。
- 涉及输出时先判断程序是否具有定义良好的行为；存在未定义行为时不要给唯一确定输出。

## 不确定时

- 明确说明不确定点，不装作确定。
- 回到 PDF 原页和上下文核对。
- 对标准问题建议查 cppreference 或用最小示例验证。
- 编译实验只能说明某个编译器/选项下的现象，不能单独证明标准规则。
