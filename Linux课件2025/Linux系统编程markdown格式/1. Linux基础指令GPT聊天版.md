## 一、Linux 背景

学习命令之前，先建立一张整体地图：Linux 不只是几个命令的集合，它是一个以 Linux 内核为核心、由大量用户态工具和软件包组成的系统环境。后面使用的 `ls`、`cp`、`grep`，最终都要通过系统调用请求内核完成工作。

### 1. 发展史

**先问一个问题：Linux 是突然出现的吗？**

不是。Linux 的思想和工具生态与 UNIX、GNU 有很深的关系。

UNIX 在 20 世纪 60～70 年代由贝尔实验室等机构发展起来，后来形成了 System V、BSD 等不同分支。它对现代操作系统产生了许多重要影响：多用户、多任务、层次化文件系统、管道、权限模型以及强大的命令行工具。

1983 年，Richard Stallman 发起 GNU 项目，目标是构建一个自由的类 UNIX 软件生态。GNU 提供了大量用户态工具，例如 `gcc`、`bash`、`gdb` 和许多常用命令。

1991 年，Linus Torvalds 开始开发 Linux 内核。最初它是一个个人兴趣项目，后来随着全球开发者参与，逐渐成为大型开源内核。Linux 内核本身负责进程、内存、文件、设备和网络等核心管理，但我们日常使用的完整系统通常还包括 Shell、C 库、软件包管理器、服务和桌面环境。

可以用下面的关系理解：

```text
UNIX：提供重要的操作系统思想
        +
GNU：提供编译器、Shell 和大量用户态工具
        +
Linux Kernel：提供内核能力
        ↓
Linux 发行版：内核 + 工具 + 软件包 + 配置 + 安装系统
```

**容易混淆的地方**：严格说，Linux 是内核；Ubuntu、Debian、Rocky Linux 等是以 Linux 内核为基础的发行版。日常交流中，人们常把完整发行版也简称为 Linux。

**学习意义**：你以后学习 C++ Linux 系统编程时，会逐步接触进程、线程、文件描述符、系统调用、网络协议和进程间通信。理解这段历史，可以知道这些工具不是孤立的，而是同一套 UNIX/Linux 设计思想的延续。

### 2. 开源

**开源不等于免费。**

开源主要指源代码可以按照许可证规定被查看、研究、修改和再发布；免费则强调使用时是否收费。一个软件可以免费但不公开源代码，也可以公开源代码但提供收费服务或商业支持。

Linux 生态常见 GPL 等自由软件许可证。许可证不是“随便拿来用”的口头承诺，而是对复制、修改、分发和衍生作品的法律规则。使用开源代码时，要关注对应项目的许可证和自己的分发方式。

Linux 适合学习系统编程，是因为它提供了透明的观察路径：

```text
C/C++ 应用程序
      ↓
库函数与系统调用
      ↓
Linux 内核
      ↓
硬件资源
```

当你输入 `open`、`read`、`fork` 等接口时，可以通过手册、源码、调试器和系统工具观察程序与操作系统的交互过程。这种“能看到、能验证、能追踪”的特点，是系统学习的重要基础。

### 3. 官网

Linux 内核官方网站是：<https://www.kernel.org>。

需要区分三个网站概念：

- `kernel.org` 主要关注 Linux 内核源代码、版本和发布信息。
- 某个发行版的官网负责该发行版的下载、文档和软件仓库。
- 某个工具的官网负责该工具自身的安装与使用说明。

遇到命令行为差异时，应优先查看当前发行版的官方文档和命令手册，不要只依赖几年前的截图或博客。

### 4. 企业应用现状

Linux 在服务器、云计算、容器、嵌入式设备、网络设备和 Android 等领域都有广泛应用。企业选择 Linux，常见原因包括：

- 可以按需求定制系统和服务。
- 服务器资源占用和自动化能力较好。
- 生态中有成熟的网络、数据库、容器和编译工具。
- 便于通过 SSH、脚本和配置管理进行批量运维。
- 内核、工具和大量软件有公开文档与社区支持。

原课件中的市场比例属于特定年份的资料，不能直接当作今天的统计结论。学习重点不应是记住某个百分比，而是理解 Linux 为什么适合服务器和系统开发：它的权限模型、进程模型、网络工具链和自动化接口都比较完整。

桌面 Linux 也有 Ubuntu、Fedora、深度等发行版，但桌面体验取决于硬件驱动、软件生态和具体发行版。对于 C++ 后端或系统开发，通常更重要的是掌握命令行和远程服务器环境，而不是是否使用某个桌面主题。

### 5. 发行版本

Linux 发行版可以理解为“内核加上一整套可用的软件和配置”。常见发行版及其特点如下：

| 发行版或家族 | 常见特点 |
|---|---|
| Debian | 稳定、社区驱动，软件管理使用 `apt` |
| Ubuntu | 基于 Debian，桌面和服务器资料丰富，适合入门 |
| RHEL 系 | 面向企业，强调生命周期、支持和认证 |
| CentOS Stream/相关兼容发行版 | 与 RHEL 生态联系紧密，常见 `dnf`/`yum` |
| Fedora | 较早集成新技术，常被用于测试和开发 |
| Kali Linux | 面向安全测试的工具集合，不能把它当作普通服务器首选 |

软件包管理器随发行版不同而变化：Debian/Ubuntu 常用 `apt`，RHEL/Fedora 家族常用 `dnf` 或兼容命令 `yum`。命令不同，但目标都是解析软件依赖、下载软件包并完成安装或升级。

选择发行版时优先考虑课程环境、项目要求、资料可获得性和长期维护周期。初学者可以在虚拟机、云服务器或 WSL 中使用 Ubuntu 等系统练习，不要为了“发行版数量”分散精力。

### 6. os 概念、定位

操作系统的根本作用，可以概括为：**管理软硬件资源，并为应用程序提供稳定、统一的使用接口。**

应用程序不应该直接操作磁盘控制器、网卡寄存器或 CPU 调度细节。操作系统内核把这些复杂资源抽象成进程、地址空间、文件、文件描述符、套接字等对象，并通过系统调用向应用提供服务。

```text
应用程序：解决业务问题
库函数：提供更方便的编程接口
系统调用：进入内核的受控入口
内核：管理 CPU、内存、设备和文件
硬件：实际执行和存储
```

因此，本章中的命令不是最终目的。真正要建立的是“命令如何让操作系统完成任务”的思维，为后面的进程、文件、网络和线程课程做准备。

## 二、使用 XShell 远程登录 Linux

这一章的核心不是记住某个软件按钮，而是理解远程工作的基本链路：本地终端程序通过 SSH 协议连接远程主机，完成身份认证后，远程主机为你启动一个 Shell。

```text
本地 Windows
    ↓
XShell 等终端模拟器
    ↓ SSH
远程 Linux 主机
    ↓
登录 Shell
    ↓
执行 Linux 命令
```

### 关于 Linux 桌面

服务器通常不依赖图形桌面。图形界面需要额外的内存、显卡和桌面服务，而服务器管理更看重稳定性、远程可达性、脚本自动化和资源利用率。

命令行并不意味着功能少。通过 SSH、Shell 脚本、管道和重定向，可以批量完成安装、部署、日志分析和故障排查。图形界面适合直观操作，命令行适合重复、精确、可记录的操作。

学习时可以暂时保留桌面用于配置网络，但应逐渐习惯在终端中完成以下任务：定位目录、创建文件、查看日志、查找进程、编译程序和检查权限。

### 下载安装 XShell

XShell 是 Windows 上的终端模拟器和远程连接工具。安装时应从软件官网或可信渠道获取，并注意个人/学校免费版本的许可条件。XShell 本身不是 Linux，也不是 SSH 协议；它只是提供了一个操作 SSH 连接的图形化终端。

连接前通常需要准备：

- Linux 主机的 IP 地址或域名。
- SSH 服务端口，默认通常是 `22`，但服务器可能修改。
- 登录用户名。
- 密码或 SSH 密钥。

不要把服务器密码写在公开笔记、截图或聊天记录中。生产环境优先使用密钥认证、限制登录来源并关闭不必要的高权限远程登录。

### 查看 Linux 主机 ip

传统课件常用：

```bash
ifconfig
```

现代 Linux 更常用：

```bash
ip addr
# 或者查看路由和网卡信息
ip route
```

`ifconfig` 在某些系统中可能没有预装，不能据此判断网络一定有问题。查看 IP 时要区分：

- `127.0.0.1` 是本机回环地址，通常不能作为远程连接地址。
- 局域网地址常见于 `192.168.x.x`、`10.x.x.x` 等私有网段。
- 云服务器还可能有公网 IP 和内网 IP，远程连接使用哪个取决于网络拓扑和安全组配置。

### 使用 XShell 登陆主机

可以在终端中测试 SSH：

```bash
ssh 用户名@主机地址
# 指定非默认端口
ssh -p 端口 用户名@主机地址
```

课件中的 `ssh [ip]` 省略了用户名，实际使用时 SSH 会尝试当前本地用户名；为了清晰，建议显式写出用户名。

连接过程大致是：客户端找到目标地址，建立 TCP 连接，协商 SSH 协议和加密算法，校验主机指纹，再进行用户认证。第一次连接看到主机指纹提示时，应通过可信渠道核对指纹，不能在无法确认身份时盲目输入 `yes`。

登录后的提示符可能类似：

```text
[user@server project]$
[root@server project]#
```

通常 `$` 表示普通用户，`#` 表示 root，但这只是常见约定，不应只凭提示符决定操作风险。进入服务器后先执行：

```bash
whoami
pwd
hostname
```

确认当前身份、目录和主机，避免在错误服务器上执行命令。

### XShell 下的复制粘贴

不同终端软件的快捷键可能不同，XShell 常见方式是：

- 复制：`Ctrl + Insert`。
- 粘贴：`Shift + Insert`。
- 鼠标右键行为取决于 XShell 的配置。

Linux 终端中的 `Ctrl+C` 通常不是复制，而是向前台进程发送中断信号；`Ctrl+V` 也不是通用的终端粘贴快捷键。复制命令前应检查不可见空格、全角标点和多余换行，尤其是复制带有 `rm`、重定向符号或管道的命令。

## 三、Linux 下基本指令

学习命令时建议采用一个固定问题模板：**我在哪里？我要看什么？我要创建/修改什么？命令的输入和输出是什么？失败时如何判断原因？**

先建立一个安全练习目录：

```bash
mkdir -p ~/linux_demo
cd ~/linux_demo
```

后面的创建、复制和删除练习尽量都在这个目录中进行。

### ls 指令

`ls` 用来列出目录内容，是最常用的观察命令之一。

```bash
ls [选项] [目录或文件]
```

常用选项：

- `-a`：显示包括隐藏文件在内的所有目录项。
- `-l`：显示详细信息。
- `-h`：配合 `-l` 以更容易阅读的单位显示大小。
- `-i`：显示 inode 编号。
- `-d`：把目录本身当作对象显示，不展开目录内容。
- `-R`：递归列出子目录，目录很大时要谨慎使用。
- `-t`：按修改时间排序，常与 `-l` 配合。
- `-F`：在名称后添加类型标记，如目录 `/`、可执行文件 `*`、软链接 `@`。

```bash
ls
ls -alh
ls -lt
ls -ld ~/linux_demo
```

`ls -l` 输出中的典型字段依次包括文件类型与权限、硬链接数、所有者、所属组、大小、时间和名称。第一列的第一个字符描述文件类型，后面九个字符描述三组权限，权限部分会在后文详细解释。

**易错点**：`ls` 默认不显示以 `.` 开头的隐藏目录项；`ls -R` 可能输出大量内容；`ls -l` 中的大小通常是字节数，并不等于文件实际占用的磁盘块数。

### pwd 命令

`pwd` 用来显示当前工作目录：

```bash
pwd
```

Shell 会为每个进程维护当前工作目录。你在终端中看到的相对路径都以这个目录为参照。例如当前目录是 `/home/user/linux_demo`，那么 `cat main.cpp` 实际寻找的是 `/home/user/linux_demo/main.cpp`。

`pwd -L` 通常显示逻辑路径，`pwd -P` 可以尝试显示物理路径；涉及软链接时，两者可能不同。排查路径问题时，先执行 `pwd` 往往比猜测目录更可靠。

### cd 指令

`cd` 用来切换当前 Shell 的工作目录：

```bash
cd 目录
```

路径有两种基本写法：

- 绝对路径：从根目录 `/` 开始，例如 `/home/user/project`。
- 相对路径：相对于当前目录，例如 `./project`、`../project`。

常见特殊路径：

- `.` 表示当前目录。
- `..` 表示父目录。
- `~` 表示当前用户的家目录。
- `-` 表示切换到上一次工作目录。

```bash
cd /tmp
cd ..
cd ~
cd -
cd ./linux_demo
```

`cd` 是 Shell 内建命令，因为它必须改变当前 Shell 自身的工作目录。如果它只是一个普通外部程序，那么子进程切换目录后立即退出，父 Shell 的目录不会变化。

**易错点**：路径中的大小写有区别；带空格的路径要使用引号或转义；执行 `cd` 后最好用 `pwd` 验证，不要只看提示符猜目录。

### touch 指令

`touch` 的主要用途有两个：文件不存在时创建空文件，文件存在时更新时间戳。

```bash
touch [选项] 文件...
```

常见选项：

- `-a`：只修改访问时间。
- `-m`：只修改修改时间。
- `-c`：文件不存在时不创建。
- `-d`：按照指定时间设置时间戳，具体格式以当前系统手册为准。

```bash
touch note.txt
stat note.txt
touch -a note.txt
touch -m note.txt
```

Linux 文件常见时间包括访问时间、修改时间和 inode 状态变化时间。`touch -a` 或 `touch -m` 造成元数据变化时，状态变化时间也可能变化。

**易错点**：`touch` 不会自动创建中间目录；它也不是专门的文本编辑器，创建的文件内容为空。

### mkdir 指令

`mkdir` 用来创建目录：

```bash
mkdir [选项] 目录...
```

常用选项：

- `-p`：父目录不存在时一并创建，且已存在的目录不报错。
- `-m`：创建时直接指定权限，最终结果仍会受到系统规则影响。
- `-v`：显示创建过程。

```bash
mkdir logs
mkdir -p project/src/include
```

`mkdir -p` 很适合初始化项目目录，但路径写错也会一次创建出一串错误目录，所以执行前应检查当前目录和目标路径。

### rmdir 指令 && rm 指令

`rmdir` 只删除空目录：

```bash
rmdir [选项] 目录
rmdir -p path1/path2/path3
```

`rmdir -p` 会在子目录删除后，尝试继续删除变空的父目录；只要某一级仍有文件，就会停止。

`rm` 可以删除文件，也可以递归删除目录：

```bash
rm [选项] 文件或目录
```

常用选项：

- `-i`：删除前逐项询问，适合练习或重要目录。
- `-I`：批量删除前进行较少次数的确认。
- `-r`：递归删除目录及其内容。
- `-f`：强制删除，不询问不存在的文件。

```bash
rm -i note.txt
rm -r empty_or_test_directory
```

**危险提醒**：`rm -rf` 会递归、强制删除目标，通常没有回收站。不要在不确认路径时使用，不要随意对 `/`、`~`、变量展开结果或生产目录执行。实际操作前可以先用 `pwd` 和 `ls` 检查，也可以先把 `rm` 改成 `echo rm` 观察 Shell 最终展开的参数。

### man 指令

`man` 是查询 Linux 手册的主要工具：

```bash
man [选项] 名称
```

常见章节：

- `1`：普通用户命令。
- `2`：系统调用，例如 `open`、`fork`、`write`。
- `3`：库函数，例如 `printf`、`fopen`。
- `4`：特殊设备文件。
- `5`：配置文件格式，例如 `passwd`。
- `7`：约定、协议和概览主题。
- `8`：系统管理命令。

```bash
man ls
man 2 open
man 3 printf
man 5 passwd
man -k network
```

进入手册后可以使用 `/关键词` 向下搜索，`n` 查找下一个，`q` 退出。命令和 C/C++ 接口同名时，必须用章节号消除歧义。

**学习方法**：先看 `NAME`、`SYNOPSIS`、`DESCRIPTION`、`OPTIONS`、`EXAMPLES` 和 `SEE ALSO`，不要一上来试遍所有选项。

### cp 指令

`cp` 用来复制文件或目录：

```bash
cp [选项] 源文件 目标文件
cp [选项] 源文件... 目标目录
```

常用选项：

- `-i`：目标存在时询问。
- `-r` 或 `-R`：递归复制目录。
- `-p`：尽量保留权限、时间等属性。
- `-a`：归档复制，通常用于保留目录结构和属性。

```bash
touch main.cpp
cp main.cpp main_backup.cpp
mkdir backup
cp main.cpp backup/
cp -r src src_backup
```

当源文件有多个时，目标必须是已经存在的目录。目标文件存在时，普通 `cp` 可能直接覆盖，重要文件应使用 `-i` 或先备份。

### mv 指令

`mv` 用于移动或重命名：

```bash
mv [选项] 源文件或目录 目标
```

当目标是新文件名时，它表现为重命名；当目标是已存在目录时，它把源对象移动到该目录中。

```bash
mv main_backup.cpp backup/main.cpp
mv old_name.cpp new_name.cpp
mv -i result.txt archive/
```

同一文件系统内的移动通常只需要修改目录项，速度很快；跨文件系统时，工具可能表现为复制后删除。覆盖已有目标前应使用 `-i`，不要把“移动”误认为自动保留原副本。

### cat 指令

`cat` 可以把文件内容写到标准输出，也可连接多个文件：

```bash
cat [选项] [文件...]
```

常用选项：

- `-n`：所有行编号。
- `-b`：只给非空行编号。
- `-s`：压缩连续空行。

```bash
cat main.cpp
cat -n main.cpp
cat part1.txt part2.txt > all.txt
```

最后一条命令体现了重定向：`>` 会把标准输出写入文件，若目标存在通常会覆盖；`>>` 则追加。查看大文件时不要使用 `cat` 整体刷屏，使用 `less`、`head` 或 `tail` 更合适。

### more 指令

`more` 用于分页查看文本：

```bash
more [选项] 文件
```

通常按空格向后翻页，按回车前进一行，按 `q` 退出。`more` 的能力相对简单，适合快速向后查看输出。遇到大日志或需要搜索时，优先考虑 `less`。

### less 指令

`less` 是更灵活的分页查看工具：

```bash
less [选项] 文件
```

常用操作：

- 空格或 `PageDown`：向后翻页。
- `PageUp`：向前翻页。
- `/字符串`：向下搜索。
- `?字符串`：向上搜索。
- `n`/`N`：继续或反向重复搜索。
- `g`：跳到开头，`G`：跳到末尾。
- `q`：退出。

常用选项 `-N` 显示行号，`-i` 在搜索时忽略大小写。`less` 通常不会一次把整个文件内容打印到终端，查看日志和源代码时非常实用。

### head 指令

`head` 默认显示文件开头 10 行：

```bash
head [选项] 文件
head -n 5 config.txt
```

它适合快速确认文件格式、日志开头或 CSV 表头。`head -n -5` 等负数写法在不同实现上存在差异，使用前查看当前系统 `man head`。

### tail 指令

`tail` 默认显示文件末尾 10 行：

```bash
tail [选项] 文件
tail -n 20 app.log
tail -f app.log
```

`-f` 会持续跟踪文件末尾，常用于观察日志。按 `Ctrl+C` 退出跟踪。现代实现还常见 `-F`，它可以在日志轮转后重新打开文件，但是否支持要以当前系统手册为准。

`head` 与 `tail` 可以组合截取指定范围：

```bash
head -n 200 temp.txt | tail -n 20
```

这表示先取前 200 行，再从中取最后 20 行，得到原文件大约第 181～200 行。

### date 指令

`date` 用于显示或设置系统时间：

```bash
date
date '+%Y-%m-%d %H:%M:%S'
```

常见格式：`%Y` 年、`%m` 月、`%d` 日、`%H` 小时、`%M` 分钟、`%S` 秒、`%F` 日期。格式字符串前通常要加 `+`。

Unix 时间戳表示从 1970-01-01 00:00:00 UTC 起经过的秒数：

```bash
date +%s
date -d @0
```

设置系统时间通常需要 root 权限，且会影响日志、证书和分布式系统，不要在共享服务器上随意执行 `date -s`。时间显示还受到时区影响，排查时间问题时同时关注 UTC、系统时区和应用自己的格式化逻辑。

### cal 指令

`cal` 用于显示日历：

```bash
cal
cal 2026
cal 3 2026
cal -3
cal -y
```

不同发行版可能没有预装 `cal`，缺少命令时可根据发行版安装对应软件包。它是一个简单工具，但可以帮助熟悉命令参数和标准输出。

### find 指令

`find` 是在文件系统目录树中按条件查找对象的工具：

```bash
find 起始路径 条件 动作
```

常见条件：

- `-name '*.cpp'`：按名称匹配，大小写敏感。
- `-iname '*.cpp'`：忽略大小写匹配。
- `-type f`：普通文件；`-type d`：目录。
- `-size +10M`：按大小筛选。
- `-mtime -1`：按修改时间筛选，具体含义要注意时间边界。

```bash
find . -type f -name '*.cpp'
find ~/linux_demo -type d -name 'build'
```

涉及批量动作时先只显示结果，确认无误后再考虑 `-exec`。例如：

```bash
find . -type f -name '*.tmp' -print
```

**与 `grep` 的区别**：`find` 主要在文件系统的名称、类型、时间和权限等属性中找对象；`grep` 主要在文件内容中找文本。

### which 指令

`which` 用于根据当前 `PATH` 查找命令通常对应的可执行文件：

```bash
which ls
which g++
```

某些 Shell 会显示别名信息，但 `which` 的行为并不完全统一。要准确判断命令究竟是别名、函数、内建命令还是外部程序，Bash 中更推荐：

```bash
type -a cd
 type -a ls
```

### whereis 指令

`whereis` 可以查找程序的二进制文件、源代码和手册位置：

```bash
whereis ls
whereis gcc
```

它使用系统预先配置的路径进行搜索，不等同于在整个磁盘中递归查找。需要按文件名和目录条件精确搜索时使用 `find`。

### alias 指令

`alias` 为命令设置简写或默认选项：

```bash
alias ll='ls -alF'
alias
type ll
unalias ll
```

别名通常只对当前 Shell 会话有效。想长期生效，可以写入用户的 Shell 配置文件，但修改前应确认当前使用的是 Bash、Zsh 还是其他 Shell。

**安全提醒**：别名可能改变命令原本行为。脚本中通常不要依赖交互式别名，排查“明明输入同样命令却结果不同”时要先检查 `alias`。

### grep 指令

`grep` 用来在文本中搜索匹配内容：

```bash
grep [选项] 搜索模式 文件...
```

常用选项：

- `-i`：忽略大小写。
- `-n`：显示行号。
- `-v`：反向选择，不匹配的行。
- `-r` 或 `-R`：递归搜索目录。
- `-E`：使用扩展正则表达式。
- `-w`：按完整单词匹配。

```bash
grep -n 'main' main.cpp
grep -RIn --include='*.h' 'TODO' src/
grep -v '^#' config.txt
```

搜索模式可能是普通字符串，也可能是正则表达式。包含 `$`、`*`、`[` 等特殊字符时，先理解 Shell 引号和正则表达式各自的解析规则。`grep` 处理的是文本内容，不会替代 `find` 查找文件名。

### top 指令

`top` 用于实时观察进程和系统资源：

```bash
top
top -d 1 -n 5
```

`-d` 指定刷新间隔，`-n` 指定刷新次数；交互界面中常用 `q` 退出。输出通常包括负载、CPU、内存、交换区以及进程列表。

观察资源时不要只看单个 CPU 百分比，还要结合进程状态、内存使用、负载和 I/O 等信息。`top` 是观察工具，不是解决问题本身；发现异常后还需要使用 `ps`、日志和程序分析工具进一步定位。

### zip/unzip 指令

`zip` 和 `unzip` 使用 ZIP 格式进行压缩和解压：

```bash
zip archive.zip file1 file2
zip -r project.zip project/
unzip archive.zip
unzip archive.zip -d output/
```

解压未知来源的压缩包前，先查看内容并确认目标目录，避免路径穿越、同名文件覆盖或恶意脚本诱导。可以先解压到空的临时目录，再检查文件。

### 关于 rzsz

`rz` 和 `sz` 属于常见的终端文件传输工具：在终端协议支持的情况下，`rz` 接收上传，`sz` 发送下载。XShell 等客户端可能提供拖拽上传下载能力，但是否可用取决于客户端、远程端工具和网络环境。

安装命令会因发行版而异，例如：

```bash
# Debian/Ubuntu 家族示例
sudo apt install lrzsz

# RHEL/Fedora 家族示例
sudo dnf install lrzsz
```

不要把终端文件传输当作生产环境的唯一方案。传输敏感文件时应使用权限受控的 SCP、SFTP 或经过审计的制品系统。

### tar 指令（重要）

`tar` 主要是归档/打包工具，压缩通常由 gzip、bzip2 或 xz 完成。`.tar.gz` 的含义是“先用 tar 打包，再用 gzip 压缩”，不是 tar 单独完成了两件事。

常用参数：

- `-c`：创建归档。
- `-x`：解开归档。
- `-t`：列出归档内容。
- `-z`：使用 gzip。
- `-j`：使用 bzip2。
- `-J`：使用 xz。
- `-v`：显示处理过程。
- `-f`：指定归档文件名，通常紧跟文件名。
- `-C`：切换到指定目录后执行操作。

```bash
tar -cvf project.tar project/
tar -czvf project.tar.gz project/
tar -tzvf project.tar.gz
tar -xzvf project.tar.gz -C output/
```

解压外部压缩包时先查看：

```bash
tar -tf unknown.tar.gz
```

再解压到临时目录，避免覆盖当前目录中的重要文件。备份 `/etc` 等系统目录需要权限和明确的恢复方案，不要直接照抄到生产主机。

### bc 指令

`bc` 是命令行计算器，适合整数和浮点运算：

```bash
echo 'scale=4; 10/3' | bc
bc
```

`scale` 控制小数精度。管道把前一个命令的标准输出交给 `bc` 的标准输入，体现了 Unix 工具“一个程序做好一件事，再组合使用”的思想。

### uname -r 指令

`uname` 用于查看系统和内核信息：

```bash
uname -r
uname -a
```

`-r` 主要显示内核发行版本，`-a` 显示更完整的信息。查看发行版本身的信息还可以使用当前系统支持的工具，例如：

```bash
cat /etc/os-release
```

内核版本、发行版版本、CPU 架构不是同一个概念。部署程序时要分别确认内核能力、用户态库版本和硬件架构。

### 重要的几个热键 [Tab]、[Ctrl]-c、[Ctrl]-d

- `Tab`：补全命令、路径和文件名；连续按两次通常可以显示多个候选。
- `Ctrl+C`：向前台进程发送中断信号，常用于停止当前命令。
- `Ctrl+D`：在终端输入中表示 EOF；在空命令行中常用于结束当前 Shell 会话。

`Ctrl+C` 不等于强制杀死所有程序，程序可以捕获或忽略某些信号。需要终止失控进程时，应先确认进程身份，再使用合适的信号工具。

### 关机

关机和重启会影响当前主机上的所有服务，远程服务器尤其不能随意执行。传统命令形式包括：

```bash
shutdown -h now
shutdown -r now
```

现代使用 systemd 的系统还常见：

```bash
systemctl poweroff
systemctl reboot
```

执行前必须确认当前主机、登录用户、业务影响和维护窗口。普通学习环境可以使用虚拟机练习，但不要在共享服务器或生产机器上测试。

## 四、以下命令作为扩展

原课件把命令按用途进行了扩展分类。这里先建立命令地图，不要求一次性背完所有命令：

- **安装和登录**：`login`、`shutdown`、`halt`、`reboot`、`install`、`mount`、`umount`、`chsh`、`exit`、`last`。
- **文件处理**：`file`、`mkdir`、`grep`、`dd`、`find`、`mv`、`ls`、`diff`、`cat`、`ln`。
- **系统管理**：`df`、`top`、`free`、`quota`、`at`、`lp`、`adduser`、`groupadd`、`kill`、`crontab`。
- **网络操作**：`ifconfig`、`ip`、`ping`、`netstat`、`telnet`、`ftp`、`route`、`rlogin`、`rcp`、`finger`、`mail`、`nslookup`。
- **安全和权限**：`passwd`、`su`、`umask`、`chgrp`、`chmod`、`chown`、`chattr`、`sudo`、`ps`、`who`。
- **归档和其他**：`tar`、`unzip`、`gunzip`、`unarj`、`mtools`、`man` 等。

学习扩展命令时建议按“问题”分类：磁盘空间看 `df`，内存看 `free`，进程看 `ps/top`，网络连通性看 `ping`，域名解析看 `nslookup` 或 `dig`，文件差异看 `diff`。命令是否安装、参数是否一致，要以当前发行版的 `man` 为准。

涉及 `dd`、`mount`、`chattr`、`kill`、`crontab` 和网络诊断命令时，先在测试环境阅读手册，明确输入、输出和权限要求，不要把示例直接用于生产系统。

## 五、shell 命令以及运行原理

Linux 内核不能直接理解你在终端输入的每一行文本。Shell 充当命令解释器，负责读取输入、展开语法、寻找命令、创建进程并把结果呈现给用户。Bash 是一种常见 Shell，但 Shell 不等于 Linux 内核。

一次外部命令执行，可以粗略理解为：

```text
读取命令行
    ↓
处理引号、变量、通配符、重定向和管道
    ↓
判断别名、函数、内建命令或外部程序
    ↓
根据 PATH 查找外部程序
    ↓
创建进程并执行程序
    ↓
程序通过系统调用请求内核服务
    ↓
标准输出/标准错误返回到终端或下一个管道
```

例如输入：

```bash
grep -n 'main' *.cpp > result.txt
```

Shell 会先展开 `*.cpp`，再启动 `grep`，把标准输出重定向到 `result.txt`。`>` 是 Shell 处理的重定向语法，不是 `grep` 自己的参数。

**Shell 内建命令与外部命令**：`cd`、`alias`、`export` 等通常需要由当前 Shell 自身执行；`ls`、`grep`、`cat` 常见为外部程序。可以用下面的命令观察：

```bash
type cd
type ls
type -a printf
```

`PATH` 是由多个目录组成的搜索路径：

```bash
echo "$PATH"
```

直接输入 `program` 时，Shell 会按 `PATH` 中的目录顺序查找；执行当前目录下的程序通常要写成 `./program`，这是为了避免无意执行当前目录中同名的恶意文件。

管道把前一个命令的标准输出接到后一个命令的标准输入：

```bash
ps aux | grep ssh
```

重定向则改变标准输入、标准输出或标准错误的去向：

```bash
command > out.txt
command >> out.txt
command 2> error.txt
command < input.txt
```

理解 Shell 的关键不是背“它是外壳”这句话，而是知道命令文本经过解析后，会转化为进程、文件描述符、管道和系统调用。这个模型会直接帮助你理解后续的进程控制、文件 IO 和进程间通信。

## 六、Linux 权限的概念

Linux 中常见两类用户身份：超级用户 root 和普通用户。root 能执行大量不受普通权限限制的操作，因此权限越高，越要谨慎。普通用户完成日常开发更安全，确需管理权限时使用经过授权的 `sudo`。

提示符中的 `$` 和 `#` 通常分别代表普通用户和 root，但它们只是提示符约定。确认身份应使用：

```bash
whoami
id
```

`su` 用于切换用户：

```bash
su - 用户名
```

`su -` 会以登录 Shell 方式切换，加载目标用户的环境；从普通用户切换到 root 需要相应认证。实际工作中应优先使用最小权限原则，不要长时间停留在 root Shell。

### 1. Linux 权限管理

Linux 权限可以拆成两层理解：**谁在访问**，以及**被访问对象允许做什么**。

文件访问者分为：

- `u`：文件所有者（User）。
- `g`：文件所属组中的用户（Group）。
- `o`：其他用户（Others）。

文件类型常见标志：

- `d`：目录。
- `-`：普通文件。
- `l`：符号链接。
- `b`：块设备。
- `c`：字符设备。
- `p`：管道文件。
- `s`：套接字。

基本权限：

| 权限 | 对普通文件 | 对目录 |
|---|---|---|
| `r` | 读取文件内容 | 读取目录项列表 |
| `w` | 修改文件内容 | 创建、删除或重命名目录项 |
| `x` | 执行程序 | 进入目录、访问其中对象 |

例如：

```text
-rwxr-x---
```

第一个 `-` 表示普通文件；接着三位 `rwx` 是所有者权限，三位 `r-x` 是所属组权限，最后三位 `---` 是其他用户权限。

**特别注意目录权限**：删除文件通常取决于父目录的写权限和执行权限，不只取决于被删除文件本身的写权限。这也是公共目录常使用粘滞位的原因。

### 2. 文件权限值的表示方法

权限既可以用字符表示，也可以用八进制表示：

```text
r = 4
w = 2
x = 1
```

因此：

```text
7 = rwx
6 = rw-
5 = r-x
4 = r--
0 = ---
```

例如 `0644`：

```text
所有者：6 = rw-
所属组：4 = r--
其他用户：4 = r--
```

`0755` 通常表示所有者可读写执行，组用户和其他用户可读执行，常见于可执行文件或目录。数字权限的第一位还可能表示特殊权限，实际查看时应结合 `ls -l` 和 `stat`。

### 3. 文件访问权限的相关设置方法

`chmod` 修改访问权限：

```bash
chmod [选项] 权限 文件
```

符号法：

```bash
chmod u+w file.txt
chmod g-r file.txt
chmod o-x script.sh
chmod a=r file.txt
```

数字法：

```bash
chmod 640 file.txt
chmod 755 script.sh
```

`-R` 表示递归修改目录下所有对象，风险很大。不要在不确认路径时使用 `chmod -R`，尤其不要对系统目录或整个家目录盲目操作。

`chown` 修改所有者，`chgrp` 修改所属组：

```bash
chown 用户 文件
chown 用户:组 文件
chgrp 组 文件
```

这些操作通常需要 root 或相应权限。`-R` 同样表示递归，执行前要确认目标目录。

`umask` 决定新建文件和目录时哪些权限默认被屏蔽：

```bash
umask
umask 0022
```

通常普通文件的基础权限按 `0666` 计算，目录按 `0777` 计算，再去掉 umask 指定的位：

```text
实际权限 = 基础权限 & ~umask
```

普通文件默认没有执行位，即便 umask 为 `0022`，新文件通常得到 `0644`；目录则通常得到 `0755`。不同程序可能进一步调整权限，最终结果应使用 `stat` 验证。

**关于 sudoers 的安全提醒**：不要把直接修改 `/etc/sudoers` 当作普通练习。语法错误可能导致 sudo 整体不可用。需要配置授权时，应使用 `visudo`，在虚拟机或测试环境中操作，并遵循最小权限原则。

### 4. file 指令

`file` 根据文件内容和特征识别文件类型，而不是只看扩展名：

```bash
file main.cpp
file /bin/ls
file archive.tar.gz
```

常见选项包括 `-z` 尝试识别压缩内容。一个名为 `data.txt` 的文件可能实际是二进制文件；一个没有扩展名的文件也可能是 ELF 可执行文件。排查“文件打不开”时，先用 `file` 看实际类型很有帮助。

### 5. 目录的权限

目录权限和普通文件不同：

- 目录有 `r`，通常才能列出目录项名称。
- 目录有 `x`，才能进入目录并访问其中对象的属性或内容。
- 目录有 `w`，通常才能创建、删除或重命名目录项；通常还需要 `x` 配合。

因此可能出现：有 `r` 没有 `x`，能看到名字但不能访问；有 `x` 没有 `r`，知道准确路径时可能可以访问对象，但不能正常列出目录内容。

删除 `/some/dir/file` 时，关键检查通常是父目录 `/some/dir` 的写和执行权限，而不是文件是否可写。公共临时目录如果人人可写，任何用户可能删除其他用户的文件，所以常配合粘滞位保护。

建议用专门的实验目录验证权限：创建两个测试用户，分别调整目录和文件权限，每次操作前记录 `id`、`ls -ld` 和 `ls -l` 的结果。不要直接修改 `/home`、`/tmp` 或系统目录来做第一次实验。

### 6. 关于权限的总结

可以用下面的顺序分析权限问题：

1. 我当前是谁？使用 `whoami`、`id` 确认。
2. 目标是什么类型？使用 `file`、`ls -l` 判断文件、目录或链接。
3. 路径上的每一级目录是否有执行权限？
4. 对目标对象，我属于 owner、group 还是 other？
5. 文件需要读、写还是执行，目录需要列出、进入还是创建删除？
6. 是否存在 ACL、特殊权限、只读挂载或 SELinux 等额外限制？

最容易犯的错误是把“目录可读”理解成“可以进入目录”，或者只检查文件权限而忽略父目录权限。权限排查不要只凭报错猜测，要逐级执行 `namei -l`、`ls -ld` 等观察命令，并在可控环境中验证。

### 7. 粘滞位［选学］

粘滞位通常设置在多人共享且允许写入的目录上：

```bash
chmod +t shared_dir
ls -ld shared_dir
```

在设置粘滞位后，目录中的文件通常只能由以下主体删除或重命名：

1. root；
2. 目录所有者；
3. 文件所有者。

在 `ls -ld` 中，其他用户权限的执行位可能显示为 `t`，例如：

```text
drwxrwxrwt
```

`/tmp` 是理解粘滞位的典型例子，但不要为了学习随意修改真实 `/tmp`。粘滞位只限制目录项删除/重命名，不等于文件内容自动加密，也不替代 ACL、SELinux 或应用层安全控制。

# Linux 文件类型

Linux 中，文件类型**不是通过文件后缀来区分的**。系统主要通过文件的类型信息来识别文件。

> **注意：** 文件有没有 `.c`、`.txt`、`.jpg` 等后缀，并不是 Linux 判断文件类型的依据。后缀主要是给人和部分工具使用的。

## 一、Linux 常见文件类型

通过 `ls -l` 查看文件时，第一个字符可以表示文件类型：

| 符号  | 文件类型       | 说明                           |
| --- | ---------- | ---------------------------- |
| `-` | **普通文件**   | 文本、可执行文件、库、图片、视频等都可以属于普通文件   |
| `d` | **目录文件**   | 用来组织和管理其他文件                  |
| `c` | **字符设备文件** | 键盘、显示器、终端等，数据以**字符流**的形式进行读写 |
| `b` | **块设备文件**  | 磁盘等设备，数据通常以**数据块**为单位进行读写    |
| `l` | **链接文件**   | Linux 中的软链接                  |
| `p` | **管道文件**   | 用于进程之间进行数据传输                 |

### 1. 普通文件 `-`

普通文件可以存储各种类型的数据，例如：

```text
hello.txt
test.c
a.out
picture.jpg
movie.mp4
libxxx.so
```

它们在 Linux 看来都可以是**普通文件**。

所以：

> **普通文件 ≠ 文本文件 ≠ 有 `.txt` 后缀的文件**

例如一个 C 程序编译之后：

```bash
gcc test.c
```

生成的：

```text
a.out
```

也是普通文件，只不过它里面存放的是**可执行程序的数据**。

### 2. 目录文件 `d`

目录本质上也是一种文件类型，用于保存文件和目录之间的组织关系。

例如：

```text
d test/
```

其中第一个字符 `d` 表示这是一个目录。

### 3. 字符设备文件 `c`

字符设备文件通常对应以**字符流**方式进行数据传输的设备，例如：

```text
键盘
显示器
终端
```

可以简单理解为：

> **字符设备：数据像一串连续的字符一样进行读写。**

### 4. 块设备文件 `b`

块设备主要用于以**数据块**为单位进行读写，例如：

```text
硬盘
磁盘分区
```

可以简单理解为：

> **块设备：数据以一个个数据块为单位进行读写。**

### 5. 链接文件 `l`

链接文件相当于 Linux 中的“快捷方式”。

例如：

```bash
ln -s test.txt mytest
```

此时 `mytest` 就是一个软链接。

### 6. 管道文件 `p`

管道文件主要用于**进程之间的数据传输**。

例如：

```bash
ls | grep txt
```

这里的 `|` 就利用了 Linux 的管道机制，让前一个命令的输出成为后一个命令的输入。

---

## 二、最重要的两个认识

### ① Linux 不靠文件后缀判断文件类型

例如：

```text
test.c
```

并不意味着 Linux 因为看到 `.c` 才知道它是 C 文件。

`.c` 只是一个**文件名的一部分**。

甚至可以：

```bash
touch test.c
```

此时 `test.c` 只是一个普通文件，并不会因为名字叫 `test.c` 就自动变成 C 程序。

### ② “普通文件”里面可以存放各种内容

普通文件可以是：

```text
文本
可执行程序
库文件
图片
音频
视频
压缩包
```

所以：

> **文件类型和文件内容/文件后缀是两个不同的概念。**

例如：

```text
test.txt   → 普通文件
test.c     → 普通文件
a.out      → 普通文件
test.jpg   → 普通文件
test.mp4   → 普通文件
```

它们虽然内容完全不同，但从 Linux 文件类型的角度来看，都可以是 `-`。

---

## 总结

> **Linux 常见文件类型：**
>
> `-` 普通文件
> `d` 目录文件
> `c` 字符设备文件
> `b` 块设备文件
> `l` 链接文件
> `p` 管道文件
>
> **核心：Linux 系统并不依靠文件后缀判断文件类型。文件后缀主要是为了方便人和工具识别文件内容，`.c` 并不代表 Linux 就会把它当成 C 源代码。**

# 一、`date`：查看和格式化当前时间

直接输入：

```bash
date
```

例如：

```text
Thu Oct  1 16:39:30 CST 2026
```

表示当前系统时间。

如果我们希望按照自己想要的格式显示，就使用：

```bash
date +格式
```

例如：

```bash
date +%Y-%m-%d
```

得到：

```text
2026-10-01
```

如果想显示完整的年月日时分秒：

```bash
date +%Y-%m-%d_%H:%M:%S
```

例如：

```text
2026-10-01_16:39:30
```

这里要特别注意：

| 格式   | 含义        | 示例     |
| ---- | --------- | ------ |
| `%Y` | 四位年份      | `2026` |
| `%m` | 月份        | `10`   |
| `%d` | 日期        | `01`   |
| `%H` | 小时（24小时制） | `16`   |
| `%M` | 分钟        | `39`   |
| `%S` | 秒         | `30`   |

所以：

```bash
date +%Y-%m-%d_%H:%M:%S
```

实际上就是：

```text
%Y  → 年
%m  → 月
%d  → 日
%H  → 时
%M  → 分
%S  → 秒
```

# 二、Unix 时间戳是什么？

你截图中最重要的部分之一就是：

```bash
date +%s
```

例如：

```text
1725974745
```

这个数字就是：

> **Unix 时间戳（Unix Timestamp）**

它表示：

> **从 1970 年 1 月 1 日 00:00:00 UTC 开始，到当前时间经过了多少秒。**

这里有一个非常重要的细节：

### 不是从“1970年1月1日北京时间 00:00”开始

标准定义是：

```text
1970-01-01 00:00:00 UTC
```

因为中国是 UTC+8，所以在中国时区显示就是：

```text
1970-01-01 08:00:00
```

这也就是你截图中：

```text
1970-01-01 08:00:00
```

的来源。

---

# 三、为什么要使用时间戳？

假设日志里面记录：

```text
1725974746
1725974746
1725974747
1725974750
```

计算机特别喜欢这种形式，因为它本质上就是一个**整数**。

例如：

```text
1725974746
1725974750
```

直接相减：

```text
1725974750 - 1725974746 = 4
```

我们马上就知道：

> 两个事件相差 4 秒。

而如果使用：

```text
2024-09-10 21:25:46
2024-09-10 21:25:50
```

计算机还需要解析年月日时分秒。

所以时间戳特别适合：

* 日志
* 数据库存储时间
* 网络通信
* 文件时间
* 程序记录事件发生时间
* 计算两个时间之间的间隔

例如一个日志系统可能记录：

```text
1725974746 张三删除了文件 test.txt
1725974750 张三创建了文件 test.c
```

程序可以非常方便地根据时间戳判断：

```text
第二个操作比第一个操作晚 4 秒
```

# 四、时间戳和普通时间可以互相转换

这是你截图下面几个命令的核心。

## ① 普通时间 → 时间戳

```bash
date +%s
```

获取**当前时间**的时间戳。

例如：

```bash
date +%s
```

输出：

```text
1725974746
```

---

## ② 时间戳 → 普通时间

使用：

```bash
date -d @时间戳
```

例如：

```bash
date -d @1725974746
```

可能得到：

```text
Tue Sep 10 21:25:46 CST 2024
```

如果想指定格式：

```bash
date +%Y-%m-%d_%H:%M:%S -d @1725974746
```

得到：

```text
2024-09-10_21:25:46
```

所以可以记成：

```text
普通时间
   ↓ date +%s
时间戳
   ↓ date -d @时间戳
普通时间
```

这是这部分最核心的知识。

# 五、为什么 `date -d @0` 是 1970 年？

你截图中还有：

```bash
date +%Y-%m-%d_%H:%M:%S -d @0
```

结果：

```text
1970-01-01_08:00:00
```

因为：

```text
时间戳 0
    ↓
1970-01-01 00:00:00 UTC
    ↓ 中国时区 UTC+8
1970-01-01 08:00:00
```

所以：

> **Unix 时间戳 0 就代表 Unix Epoch（Unix 时间纪元）的起点。**

可以把它想象成一个“时间尺子的 0 刻度”。

```text
1970-01-01 00:00:00 UTC
             │
             │  +1秒
             ↓
            1
             │
             │
             ↓
            2
             │
             │
             ↓
           ...
             │
             ↓
      当前时间对应的时间戳
```

# 六、为什么电脑关机后，开机还能知道现在几点？

你截图右上角提出了这个问题：

> 我的计算机已经关机了，为什么开机之后还能准确记录时间？

这里涉及计算机的 **RTC（Real-Time Clock，实时时钟）**。

主板上有专门的实时时钟电路，并且通常由主板上的纽扣电池供电。

所以：

```text
电脑正常运行
    ↓
系统时间正常运行

电脑关机
    ↓
CPU停止运行
    ↓
RTC仍然工作
    ↓
记录当前时间
    ↓
重新开机
    ↓
操作系统读取RTC时间
```

另外，现代 Linux/服务器还可能通过 **NTP 网络时间同步**来校准系统时间，因此服务器的时间可以进一步保持准确。

```bash
cal 10 2026
```

表示：

> 查看 2026 年 10 月的日历。

例如：

```bash
cal 2 2026
```

就是：

> 查看 2026 年 2 月的日历。

所以可以记成：

```text
cal
    ↓
当前月份

cal 年
    ↓
指定年份全年

cal 月 年
    ↓
指定年份的指定月份
```

# 十、把这一部分整理成一张知识图

```text
                    Linux 时间
                       │
             ┌─────────┴─────────┐
             ↓                   ↓
           date                  cal
             │                   │
       查看/格式化时间           查看日历
             │
      ┌──────┴──────┐
      ↓             ↓
普通时间          时间戳
      │             │
      │          date +%s
      │             │
      │             ↓
      │        Unix Timestamp
      │             │
      │       1970-01-01 UTC
      │             │
      │             │
      └───────↔─────┘
          时间相互转换
```

### 常用命令直接记住

```bash
# 查看当前时间
date

# 按指定格式显示
date +%Y-%m-%d_%H:%M:%S

# 获取当前时间戳
date +%s

# 时间戳 → 普通时间
date -d @0

# 时间戳 → 指定格式
date +%Y-%m-%d_%H:%M:%S -d @0

# 查看当前月份日历
cal

# 查看指定年份全年日历
cal 2026

# 查看指定年月
cal 10 2026
```

## 总结

这部分你真正需要建立的核心认识不是死记命令，而是这三个概念：

> **1. `date`：处理时间**
> **2. Unix 时间戳：从 1970-01-01 00:00:00 UTC 开始经过的秒数**
> **3. `cal`：查看日历**

其中最重要的是：

```bash
date +%s
```

**普通时间 → 时间戳**

以及：

```bash
date -d @时间戳
```

**时间戳 → 普通时间**

这套“**时间 ↔ 时间戳**”的转换思维，后面学习 Linux 日志、C/C++ 时间函数、网络编程和服务器开发时会经常遇到。
