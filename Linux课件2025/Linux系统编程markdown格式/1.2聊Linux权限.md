# 1. Linux权限的概念

这一章开始正式进入 Linux 的**权限体系**。你可以先抓住一个最核心的问题：

> **Linux 为什么需要权限？——因为 Linux 是一个多用户操作系统，不同用户应该拥有不同的资源访问能力。**

你现在使用云服务器时，实际上已经接触到了这个概念。例如你之前登录服务器时使用的是：

```bash
root@iZbp1762zeqzauorez4cw0Z:~/caige/test01#
```

这里的 `root` 就代表**当前登录用户**。以后我们操作文件时，Linux 就会不断判断：

> “这个用户，有没有权限对这个文件做这个操作？”

这就是 Linux 权限系统要解决的问题。

---

## 1.1 为什么需要权限

先设想一个没有权限控制的系统。

服务器上有：

```text
/home/caige
/home/zhangsan
/home/lisi
```

假如所有用户都可以随意操作所有文件，那么：

```text
zhangsan
   ↓
修改 caige 的代码

lisi
   ↓
删除 caige 的文件

普通用户
   ↓
修改系统关键配置
```

整个系统就非常危险。

所以 Linux 需要一种机制：

```text
用户 A → 可以做什么
用户 B → 可以做什么
用户 C → 可以做什么
```

例如：

```text
caige 可以修改自己的代码
其他用户只能读取
某些用户完全不能访问
root 可以进行系统管理
```

因此可以把**权限**理解成：

> **Linux 对“某个用户能够对某个资源执行什么操作”的限制。**

这里的“资源”目前主要理解为**文件和目录**，后面还会逐渐看到 Linux 中很多东西都具有类似的权限管理思想。

---

# 1.2 Linux多用户与权限隔离

Linux 的一个重要特点就是：

> **多用户。**

这里的“多用户”不是说必须同时坐着很多个人使用电脑，而是说：

> **操作系统可以同时管理多个不同身份的用户。**

比如服务器中可能存在：

```text
root
caige
zhangsan
lisi
```

每个用户都有自己的身份。

可以使用：

```bash
whoami
```

查看当前用户：

```bash
[root@server ~]# whoami
root
```

也可以使用：

```bash
id
```

查看当前用户更详细的信息。

例如可能看到：

```text
uid=0(root) gid=0(root) groups=0(root)
```

先不用急着记住这里所有字段，我们重点认识：

```text
uid
gid
groups
```

后面会逐渐解释。

---

## 什么叫“权限隔离”？

简单来说就是：

```text
用户A
  ↓
只能访问自己有权限访问的资源

用户B
  ↓
只能访问自己有权限访问的资源
```

例如：

```text
/home/caige/test.cpp
```

这个文件属于 `caige`，Linux 可以规定：

```text
caige     → 可读、可写
其他用户 → 只能读
某些用户 → 无权访问
```

于是用户之间就被隔离开了。

### 一个非常重要的认识

权限不是简单的：

> “这个文件能不能访问。”

而是：

> **“谁，对这个文件，具有什么权限。”**

因此权限至少涉及三个东西：

```text
谁？
 ↓
用户身份

对谁？
 ↓
文件/目录

能做什么？
 ↓
读 / 写 / 执行
```

后面的整个权限章节，其实就是围绕这三件事展开的。

---

# 1.3 用户、用户组与其他用户

这是整个权限体系最重要的基础之一。

Linux 对一个文件的访问者，通常从三个身份类别来考虑：

```text
User
Group
Other
```

中文可以理解成：

```text
User   → 文件所有者
Group  → 文件所属组
Other  → 其他用户
```

注意：

> 这里的 User 不是“任意用户”，而是**这个文件的所有者**。

例如有一个文件：

```text
test.cpp
```

它的所有者是：

```text
caige
```

所属组是：

```text
dev
```

那么 Linux 就可以把访问者分成：

```text
caige
 ↓
User

属于 dev 组的其他用户
 ↓
Group

既不是 caige，又不属于 dev 组
 ↓
Other
```

可以画成：

```text
                 test.cpp
                    │
         ┌──────────┼──────────┐
         ↓          ↓          ↓
       User       Group      Other
         │          │          │
       caige      dev组      其他人
```

这三个身份非常重要，因为以后你看到：

```text
rwxr-xr--
```

实际上就是：

```text
rwx → User
r-x → Group
r-- → Other
```

所以现在不要急着背 `rwx`，先把这个结构理解清楚。

---

# 1.4 文件所有者与所属组

Linux 中，一个文件除了有自己的名字、大小、时间等信息，还会记录：

> **这个文件属于谁？属于哪个组？**

例如：

```bash
ls -l
```

可能看到：

```text
-rw-r--r-- 1 caige dev 1200 Oct 1  test.cpp
```

现在先不管最前面的：

```text
-rw-r--r--
```

我们只看：

```text
caige
dev
```

也就是：

```text
文件所有者 → caige
所属组     → dev
```

因此：

```text
test.cpp
   │
   ├── Owner：caige
   └── Group：dev
```

这里为什么还要有一个“组”？

因为实际开发中经常不是一个人操作文件，而是**一群用户共同维护一批资源**。

例如一个开发团队：

```text
dev
├── caige
├── zhangsan
└── lisi
```

某个项目文件属于：

```text
Owner → caige
Group → dev
```

那么就可以设置：

```text
caige      → 可以读写
dev组成员  → 可以读
其他用户   → 没有权限
```

这样就不需要给每个人单独设置一遍权限。

---

## 用户组到底是什么？

可以把用户组简单理解为：

> **把多个用户组织起来，方便进行权限管理。**

例如：

```text
dev组
 ├── caige
 ├── zhangsan
 └── lisi
```

当文件：

```text
test.cpp
```

属于：

```text
dev
```

那么系统就可以针对整个 `dev` 组设置一套权限。

这也是为什么 Linux 权限不是简单的：

```text
用户 → 文件
```

而是：

```text
用户
 ↓
用户所属的组
 ↓
文件所属的组
 ↓
权限
```

---

# 1.5 root与普通用户

你之前操作云服务器时，基本一直在看到：

```text
root@...
```

所以现在必须把 `root` 理解清楚。

## root是什么？

`root` 是 Linux 中一个具有特殊管理权限的用户，通常称为：

> **超级用户（superuser）**

它可以进行大量普通用户不能执行的系统级操作，例如：

```bash
rm
```

删除某些普通用户无法删除的文件；

修改系统配置；

安装系统软件；

管理用户；

修改文件所有者；

启动、停止某些系统服务等。

因此可以简单理解成：

```text
普通用户
    ↓
受到权限系统严格限制

root
    ↓
具有非常高的系统管理权限
```

---

## 为什么不应该什么都用 root？

因为：

> **权限越大，操作失误造成的影响也越大。**

比如普通用户执行：

```bash
rm 某个文件
```

可能只能删自己的文件。

但 root 如果误执行一个危险命令，可能直接影响整个服务器。

所以实际 Linux 使用中经常采用：

```text
日常操作 → 普通用户
需要管理员权限 → sudo
```

例如：

```bash
sudo apt install gcc
```

这里的思想不是：

> “把当前用户永久变成 root。”

而是：

> **让某个命令以更高权限执行。**

不过 `sudo` 是否能够使用，还取决于用户是否被配置为具有相应权限。

---

# 2. Linux权限管理

现在从“权限是什么”进入：

> **Linux 到底是怎么管理权限的？**

---

## 2.1 Linux权限管理的基本思想

Linux 权限管理可以先抽象成：

```text
用户
  ↓
访问
  ↓
文件/目录
  ↓
检查权限
  ↓
允许 / 拒绝
```

例如：

```text
caige
  ↓
访问 test.cpp
  ↓
Linux检查：
    你是不是文件所有者？
    你属于文件所属组吗？
    如果都不是，就属于Other
  ↓
再检查对应的权限
  ↓
允许 or 拒绝
```

因此 Linux 权限管理实际上就是：

> **根据访问者身份，决定访问者对资源能够执行什么操作。**

而目前我们主要关注三种基本操作：

```text
r → read
w → write
x → execute
```

这些我们将在下一大部分详细学习。

---

# 2.2 User、Group、Other

现在把前面的概念正式整理起来。

假设：

```text
文件：
test.cpp

所有者：
caige

所属组：
dev
```

有三个用户：

```text
caige
zhangsan
lisi
```

其中：

```text
caige       → 文件所有者
zhangsan    → 属于dev组
lisi        → 不属于dev组
```

那么：

```text
caige
 ↓
User

zhangsan
 ↓
Group

lisi
 ↓
Other
```

这里有一个非常重要的点：

> **Group 并不是“文件所属组的名字对应的那个用户”。**

Group 是一个**用户集合**。

例如：

```text
dev
├── caige
├── zhangsan
└── lisi
```

这里 `dev` 是组，里面可以有多个用户。

---

# 2.3 Linux如何判断当前用户的权限

这是这一批里最值得你理解透的知识之一。

假设：

```text
文件：
test.cpp

Owner：
caige

Group：
dev
```

当前用户是：

```text
caige
```

Linux 首先判断：

```text
当前用户是不是文件所有者？
```

如果是：

```text
→ 使用 User 对应的权限
```

如果不是，再判断：

```text
当前用户是否属于文件所属组？
```

如果是：

```text
→ 使用 Group 对应的权限
```

如果也不是：

```text
→ 使用 Other 对应的权限
```

可以记成：

```text
当前用户
   ↓
是不是 Owner？
   │
  是
   ↓
使用 User 权限

不是
   ↓
是否属于文件所属 Group？
   │
  是
   ↓
使用 Group 权限

不是
   ↓
使用 Other 权限
```

### 举一个非常重要的例子

假设：

```text
test.cpp
Owner = caige
Group = dev
```

权限：

```text
rwxr-xr--
```

那么：

```text
User   → rwx
Group  → r-x
Other  → r--
```

如果：

```text
caige
```

访问它：

```text
caige 是 Owner
↓
看 rwx
```

如果：

```text
zhangsan
```

属于 `dev`：

```text
zhangsan 不是 Owner
↓
zhangsan 属于 dev
↓
看 r-x
```

如果：

```text
lisi
```

既不是 `caige`，也不属于 `dev`：

```text
lisi
 ↓
Other
 ↓
看 r--
```

所以我们之后学习权限字符串时，就不会再觉得：

```text
rwxr-xr--
```

是一串莫名其妙的字符。

它其实就是：

```text
文件所有者 → 一套权限
文件所属组 → 一套权限
其他用户   → 一套权限
```

---

## 一个很容易犯的错误

假设：

```text
Owner = caige
Group = dev
```

现在：

```text
caige
```

同时也属于：

```text
dev
```

那么他到底使用 User 还是 Group 权限？

答案是：

> **因为他首先就是文件所有者，所以判断到 Owner 后，就使用 Owner 权限，而不是再使用 Group 权限。**

也就是说，不能简单理解成：

> “我属于这个组，所以我一定使用 Group 权限。”

Linux 的权限分类判断是有顺序的。

---

# 2.4 权限管理相关命令概览

这一节我们先**认识命令的职责**，具体使用方法按照课程后面的顺序详细讲。

| 命令      | 主要作用                 |
| ------- | -------------------- |
| `ls -l` | 查看文件的详细权限、所有者、所属组等信息 |
| `chmod` | 修改文件/目录的权限           |
| `chown` | 修改文件所有者              |
| `chgrp` | 修改文件所属组              |
| `umask` | 查看/设置创建文件或目录时的默认权限掩码 |
| `file`  | 判断文件实际类型             |

例如以后会经常出现：

```bash
ls -l test
```

查看权限。

```bash
chmod 755 test
```

修改权限。

```bash
chown caige test
```

修改所有者。

```bash
chgrp dev test
```

修改所属组。

但是现在**不要急着记这些命令的参数**，因为接下来的第 3、4 节会正式学习。

# 三、把目前的知识串起来

到这里，你应该已经能够建立这样一个模型：

```text
                 Linux文件/目录
                       │
             ┌─────────┴─────────┐
             ↓                   ↓
          所有者               所属组
          Owner                Group
             │                   │
             └─────────┬─────────┘
                       ↓
                 权限管理体系
                       │
             ┌─────────┼─────────┐
             ↓         ↓         ↓
           User      Group      Other
             │         │         │
             └─────────┼─────────┘
                       ↓
                    r / w / x
                       ↓
                  是否允许操作
```

而一个完整的权限问题，实际上可以拆成三个问题：

```text
① 我是谁？
② 我要访问谁？
③ 我对它有什么权限？
```

比如：

```text
当前用户：caige
访问对象：test.cpp
文件所有者：caige
```

那么：

```text
caige == Owner
↓
使用 User 权限
↓
再判断有没有对应的 r / w / x
↓
决定操作是否允许
```

这条思路非常重要。以后你遇到：

```text
Permission denied
```

不要只想着：

> “Linux 怎么突然不让我操作了？”

而应该开始主动分析：

```text
当前用户是谁？
    ↓
文件属于谁？
    ↓
文件属于哪个组？
    ↓
我属于这个组吗？
    ↓
我是 User、Group 还是 Other？
    ↓
对应身份具有什么权限？
```

这才是学习 Linux 权限真正应该建立的思维方式。

# 本节总结

这一批我们主要建立了 Linux 权限的**整体框架**：

**1. 权限存在的原因**：Linux 是多用户系统，需要通过权限隔离不同用户对资源的访问。

**2. 权限的三个身份类别**：

```text
User   → 文件所有者
Group  → 文件所属组中的用户
Other  → 其他用户
```

**3. 文件具有两个重要身份信息**：

```text
Owner → 谁拥有它
Group → 它属于哪个用户组
```

**4. Linux 判断权限的大致过程**：

```text
当前用户
 ↓
Owner？
 ↓否
属于文件所属Group？
 ↓否
Other
```

**5. 当前阶段先认识几个权限管理命令**：

```text
ls -l     查看
chmod     改权限
chown     改所有者
chgrp     改所属组
umask     默认权限
file      判断文件类型
```

其中最重要的是先理解：

> **权限不是“这个文件能不能操作”，而是“某个身份对这个文件能进行什么操作”。**

# 3. 文件权限值的表示方法

前面我们已经知道，Linux 权限的核心是：

```text
谁？ → User / Group / Other
对谁？ → 文件 / 目录
能做什么？ → r / w / x
```

这一节正式解决一个问题：

> **Linux 是怎么把这些权限写在文件信息里的？**

你以后在服务器上执行：

```bash
ls -l
```

会大量看到类似：

```text
-rwxr-xr-- 1 root root 1234 Oct  1 20:30 test
```

这一整行其实包含了非常多信息，而权限主要就在最前面的这一部分：

```text
-rwxr-xr--
```

所以我们从 `ls -l` 开始。

---

## 3.1 ls -l查看权限

我们之前已经学过：

```bash
ls
```

作用是查看当前目录中的文件。

例如：

```bash
ls
```

可能得到：

```text
a  b  test.c  test.txt
```

但是 `ls` 只告诉我们：

> **有哪些文件。**

它不会告诉我们文件的所有者、所属组、权限、大小、修改时间等详细信息。

这时候使用：

```bash
ls -l
```

例如：

```bash
root@server:~/caige/test01# ls -l
total 8
drwxr-xr-x 3 root root 4096 Oct  1 20:30 a
-rw-r--r-- 1 root root   25 Oct  1 20:31 test.txt
```

我们先观察第二行：

```text
-rw-r--r-- 1 root root 25 Oct 1 20:31 test.txt
```

这一行可以拆成：

```text
-rw-r--r--  1  root  root  25  Oct 1 20:31  test.txt
│           │   │     │     │       │             │
│           │   │     │     │       │             └─ 文件名
│           │   │     │     │       └─ 最后修改时间
│           │   │     │     └─ 文件大小
│           │   │     └─ 所属组
│           │   └─ 所有者
│           └─ 硬链接数
└─ 文件类型 + 权限
```

这里我们重点关注：

```text
-rw-r--r--
```

它就是我们这一节的重点。

---

# 3.2 文件类型字段

先不要把：

```text
-rw-r--r--
```

整个看成“权限”。

**这是一个非常容易犯的错误。**

最前面的第一个字符：

```text
-
```

表示的是：

> **文件类型，而不是权限。**

所以实际上应该拆成：

```text
- rw- r-- r--
│  │    │   │
│  │    │   └─ Other权限
│  │    └───── Group权限
│  └────────── User权限
└───────────── 文件类型
```

这和你之前学习过的 Linux 文件类型知识正好联系起来。

常见的类型包括：

| 第一个字符 | 含义     |
| ----- | ------ |
| `-`   | 普通文件   |
| `d`   | 目录     |
| `l`   | 软链接    |
| `b`   | 块设备文件  |
| `c`   | 字符设备文件 |
| `p`   | 管道文件   |
| `s`   | 套接字文件  |

目前最重要的是：

```text
- → 普通文件
d → 目录
l → 软链接
```

比如：

```text
-rw-r--r--    test.txt
drwxr-xr-x    test01
lrwxrwxrwx    softlink
```

可以分别判断：

```text
test.txt  → 普通文件
test01    → 目录
softlink  → 软链接
```

---

## 注意：文件类型和文件后缀是两回事

比如：

```bash
touch test.txt
```

这里 `test.txt` 最终还是一个：

```text
-
```

即普通文件。

把它改名：

```bash
mv test.txt test.cpp
```

它依然是：

```text
-
```

再改成：

```bash
mv test.cpp hello.abc
```

仍然是：

```text
-
```

也就是说：

> **Linux 文件的实际类型，不是由 `.txt`、`.cpp`、`.abc` 这样的后缀决定的。**

这一点你之前已经学过，这里要和权限章节中的 `file` 指令继续联系起来，后面会专门讲。

---

# 3.3 r、w、x

现在把最前面的文件类型去掉：

```text
-rw-r--r--
```

剩下：

```text
rw-r--r--
```

一共正好 **9 个字符**。

为什么是 9 个？

因为：

```text
User    → 3个
Group   → 3个
Other   → 3个
```

也就是：

```text
rw- r-- r--
└──┘ └──┘ └──┘
User Group Other
```

每组三个字符分别代表：

```text
r
w
x
```

它们分别表示：

```text
r → read    读
w → write   写
x → execute 执行
```

---

## `r`：read

对于普通文件：

```text
r
↓
读取文件内容
```

例如：

```bash
cat test.txt
```

本质上就是想：

> 读取 `test.txt` 的内容。

如果当前用户没有相应的读取权限，就可能出现：

```text
Permission denied
```

---

## `w`：write

对于普通文件：

```text
w
↓
修改文件内容
```

例如使用编辑器修改：

```text
test.txt
```

或者程序向文件中写入内容，都涉及写权限。

---

## `x`：execute

对于普通文件：

```text
x
↓
允许以程序/可执行文件的方式执行
```

例如一个具有执行权限的程序：

```bash
./test
```

其中：

```text
./test
```

表示执行当前目录下的 `test`。

如果没有执行权限，即使文件存在，也可能出现：

```text
Permission denied
```

这里先建立一个重要认识：

> **存在一个文件，不代表就一定允许执行这个文件。**

“有没有文件”和“有没有执行权限”是两个不同的问题。

---

# 3.4 User、Group、Other对应的权限

现在把前面的知识全部结合起来。

假设：

```text
-rwxr-xr--
```

完整拆解：

```text
- rwx r-x r--
│  │   │   │
│  │   │   └─ Other
│  │   └───── Group
│  └───────── User
└──────────── 文件类型
```

那么：

```text
User   → rwx
Group  → r-x
Other  → r--
```

再把 `rwx` 翻译成人话：

```text
User
rwx
↓
可以读、写、执行

Group
r-x
↓
可以读、执行
不能写

Other
r--
↓
只能读
不能写、不能执行
```

因此：

```text
-rwxr-xr--
```

完整含义就是：

> 这是一个普通文件；文件所有者拥有读、写、执行权限；所属组拥有读、执行权限；其他用户只有读权限。

这就是 Linux 权限字符串真正表达的内容。

---

# 3.5 权限的字符表示法

我们现在正式来认识 Linux 权限的**字符表示法**。

还是这个：

```text
rwxr-xr--
```

按照三个一组拆：

```text
rwx
r-x
r--
```

每一组都有三个固定位置：

```text
第1位 → r
第2位 → w
第3位 → x
```

如果某个权限没有，就使用：

```text
-
```

例如：

```text
rwx
```

表示：

```text
r = 有读权限
w = 有写权限
x = 有执行权限
```

而：

```text
r-x
```

表示：

```text
r = 有
w = 没有
x = 有
```

于是：

```text
r-x
```

中的 `-` 就表示：

> **这个位置对应的权限不存在。**

---

## 典型组合

| 权限    | 含义       |
| ----- | -------- |
| `rwx` | 读、写、执行都有 |
| `rw-` | 读、写，没有执行 |
| `r-x` | 读、执行，没有写 |
| `r--` | 只有读      |
| `-wx` | 写、执行，没有读 |
| `-w-` | 只有写      |
| `--x` | 只有执行     |
| `---` | 什么权限都没有  |

因此你以后看到：

```text
-rw-------
```

可以立刻理解成：

```text
文件类型：普通文件

User  → rw-
Group → ---
Other → ---
```

也就是：

> 文件所有者可以读写，组用户和其他用户都没有权限。

再例如：

```text
-r--------
```

就是：

```text
User  → r--
Group → ---
Other → ---
```

只有文件所有者可以读。

---

# 3.6 权限的数字表示法

前面的字符表示法非常直观，但 Linux 中还有一种非常常见的表示方式：

> **数字表示法。**

你以后在服务器上一定会经常看到：

```bash
chmod 755 test
chmod 644 test.txt
chmod 600 config
```

这里的：

```text
755
644
600
```

就是权限的数字表示。

---

## 为什么是 4、2、1？

Linux 把：

```text
r
w
x
```

分别对应：

```text
r = 4
w = 2
x = 1
```

为什么？

因为每一组权限其实可以看成三个二进制位：

```text
r w x
1 1 1
```

分别对应：

```text
4 2 1
```

所以：

```text
rwx
```

就是：

```text
4 + 2 + 1 = 7
```

---

## 不同权限组合对应的数字

| 字符权限  | 数字 | 计算        |
| ----- | -: | --------- |
| `---` |  0 | 0         |
| `--x` |  1 | 1         |
| `-w-` |  2 | 2         |
| `-wx` |  3 | 2 + 1     |
| `r--` |  4 | 4         |
| `r-x` |  5 | 4 + 1     |
| `rw-` |  6 | 4 + 2     |
| `rwx` |  7 | 4 + 2 + 1 |

所以一定要掌握这张关系：

```text
r = 4
w = 2
x = 1
```

这是以后使用数字权限的基础。

---

# 3.7 字符表示与数字表示的转换

这是这一小节最重要的实操能力。

例如：

```text
rwx
```

转换：

```text
r = 4
w = 2
x = 1

4 + 2 + 1 = 7
```

所以：

```text
rwx → 7
```

---

再看：

```text
r-x
```

因为：

```text
r = 4
- = 0
x = 1
```

所以：

```text
4 + 0 + 1 = 5
```

因此：

```text
r-x → 5
```

---

再看：

```text
rw-
```

就是：

```text
4 + 2 + 0 = 6
```

所以：

```text
rw- → 6
```

---

## 例如：`rwxr-xr-x`

拆成：

```text
rwx | r-x | r-x
```

分别计算：

```text
rwx → 7
r-x → 5
r-x → 5
```

因此：

```text
rwxr-xr-x
    ↓
755
```

所以：

```bash
chmod 755 test
```

你以后看到这个命令时，就应该能直接想到：

```text
755
 ↓
User   → rwx
Group  → r-x
Other  → r-x
```

---

## 再例如：`rw-r--r--`

拆开：

```text
rw- | r-- | r--
```

计算：

```text
rw- → 6
r-- → 4
r-- → 4
```

所以：

```text
rw-r--r--
   ↓
644
```

这就是 Linux 中非常常见的一种普通文件权限。

---

# 一个非常重要的规律

以后看到三个数字：

```text
755
```

不要把它看成：

```text
7 5 5
```

而应该看成：

```text
755
│││
││└─ Other
│└── Group
└─── User
```

然后每一个数字再转换成 `rwx`：

```text
7 → rwx
5 → r-x
5 → r-x
```

最终：

```text
755
↓
rwxr-xr-x
```

反过来也一样。

---

# 到这里，先把 `ls -l` 完整看懂

例如：

```text
-rwxr-x--- 1 caige dev 1024 Oct 1 20:30 test
```

我们现在已经能够解释：

```text
-          → 普通文件

rwx        → User：读、写、执行
r-x        → Group：读、执行
---        → Other：没有任何权限

1          → 硬链接数

caige      → 所有者

dev        → 所属组

1024       → 文件大小

Oct 1 20:30 → 最后修改时间

test       → 文件名
```

因此权限部分：

```text
-rwxr-x---
```

实际上可以转换成：

```text
750
```

因为：

```text
rwx → 7
r-x → 5
--- → 0
```

所以：

```text
rwxr-x---
↓
750
```

---

# 一个需要特别注意的地方：权限数字不是“等级”

比如：

```text
755
```

不能理解成：

> “权限等级是 755。”

更准确的理解是：

```text
7 → User的权限组合
5 → Group的权限组合
5 → Other的权限组合
```

也就是说，数字实际上是对每组三个权限位的**编码/简写**。

我们前面学习的是：


现在继续往下：

```text
         ↓
       各有一组
         ↓
       r / w / x

```

所以完整结构已经越来越清楚：

```text
│
├── User
│    └── rwx
│
├── Group
│    └── rwx

```

例如：

```text

```

其实就是：


再进一步：

```text

```

所以：

```text
      754
```

**“`rwx` → `数字`”这个转换一定要熟练，因为下一部分开始学习 `chmod` 后，你会直接使用这些数字修改权限。**

# 4. 文件访问权限的相关设置方法

前面我们已经学会了：

```text
User / Group / Other
        ↓
      r / w / x
        ↓
字符表示 / 数字表示
```

现在进入一个非常实用的部分：

> **既然我们已经知道权限是什么，那么如何修改权限？**

这一部分最核心的几个命令就是：

```text
chmod  → 修改权限
chown  → 修改所有者
chgrp  → 修改所属组
umask  → 控制新创建文件/目录的默认权限
```

可以先建立一张整体关系图：

```text
文件
│
├── 所有者是谁？
│      ↓
│    chown
│
├── 所属组是谁？
│      ↓
│    chgrp
│
└── 权限是什么？
       ↓
     chmod
```

而 `umask` 负责的是另一个问题：

```text
“以后新创建出来的文件，默认应该具有什么权限？”
```

---

# 4.1 chmod命令

## 4.1.1 chmod是什么

`chmod` 是：

```text
change mode
```

用于：

> **修改文件或目录的访问权限。**

基本格式：

```bash
chmod [选项] 权限 文件/目录
```

例如：

```bash
chmod 755 test
```

表示把 `test` 的权限设置为：

```text
rwxr-xr-x
```

---

## 4.1.2 先看一个完整的例子

创建文件：

```bash
touch test
```

然后：

```bash
ls -l test
```

可能看到：

```text
-rw-r--r-- 1 root root 0 Oct 1 20:50 test
```

权限：

```text
rw-r--r--
```

转换成数字就是：

```text
644
```

现在执行：

```bash
chmod 755 test
```

再次查看：

```bash
ls -l test
```

会变成：

```text
-rwxr-xr-x 1 root root 0 Oct 1 20:50 test
```

也就是：

```text
644
 ↓
755
```

所以 `chmod` 本质就是：

```text
原来的权限
   ↓
chmod修改
   ↓
新的权限
```

---

# 4.2 chmod数字方式

这是我们最常使用，也最值得掌握的一种方式。

## 4.2.1 基本格式

```bash
chmod 3位数字 文件
```

例如：

```bash
chmod 755 test
```

三个数字分别对应：

```text
    755
    │││
    ││└── Other
    │└─── Group
    └──── User
```

每个数字的含义：

```text
r = 4
w = 2
x = 1
```

所以：

```text
7 = 4+2+1 = rwx
6 = 4+2   = rw-
5 = 4+1   = r-x
4 = 4     = r--
3 = 2+1   = -wx
2 = 2     = -w-
1 = 1     = --x
0 = 0     = ---
```

---

## 4.2.2 常见例子

### `chmod 777 test`

```text
777
↓
rwx rwx rwx
```

表示：

```text
User   → rwx
Group  → rwx
Other  → rwx
```

也就是所有三类用户都拥有读、写、执行权限。

但要注意：

> **“777 权限大”不等于“任何情况下都应该使用 777”。**

实际服务器上通常应该根据实际需求设置尽可能合适的权限，不能因为“权限不够”就习惯性地 `chmod 777`。

---

### `chmod 755 test`

```text
755
↓
rwx r-x r-x
```

表示：

```text
User   → rwx
Group  → r-x
Other  → r-x
```

也就是所有者可以读写执行，其他两类用户可以读和执行，但不能写。

---

### `chmod 644 test.txt`

```text
644
↓
rw- r-- r--
```

表示：

```text
User   → rw-
Group  → r--
Other  → r--
```

这是非常常见的普通文件权限组合。

---

### `chmod 600 secret`

```text
600
↓
rw- --- ---
```

表示：

> 只有文件所有者可以读写，其他用户没有权限。

例如保存私密配置、密钥类文件时，经常会看到比较严格的权限设置。

---

# 4.2.3 `chmod`设置的是“最终权限”

例如当前：

```text
-rw-r--r--
```

执行：

```bash
chmod 755 test
```

不是：

> “在原来的权限上增加一些权限。”

而是：

> **直接把对应权限设置成 `755`。**

也就是：

```text
原来：644
   ↓
chmod 755
   ↓
现在：755
```

因此数字方式更像：

```text
chmod 目标权限 文件
```

---

# 4.2.4 `-R`：递归修改

`chmod` 还有一个非常重要的选项：

```bash
-R
```

表示：

> **递归地修改目录本身以及目录中的内容。**

例如：

```bash
chmod -R 755 project
```

表示对：

```text
project
├── a
├── b
│   ├── test1
│   └── test2
└── c
```

递归设置相应权限。

不过这里必须形成一个重要习惯：

> **使用 `-R` 要非常谨慎。**

因为如果目录下面有大量文件和子目录，一条命令可能一次修改成千上万个对象的权限。

---

# 4.3 chmod字符方式

除了数字方式：

```bash
chmod 755 test
```

还可以写成：

```bash
chmod u+x test
```

这种方式叫：

> **字符方式 / 符号方式（symbolic mode）**

它的优势是：

> **可以针对 User、Group、Other 分别增加、删除或设置某一种权限。**

---

## 4.3.1 `u g o a`

首先记住四个符号：

| 符号  | 含义          |
| --- | ----------- |
| `u` | User，文件所有者  |
| `g` | Group，文件所属组 |
| `o` | Other，其他用户  |
| `a` | All，以上全部    |

例如：

```bash
chmod u+x test
```

就是：

> 给 User 增加执行权限。

```bash
chmod g+w test
```

就是：

> 给 Group 增加写权限。

```bash
chmod o-r test
```

就是：

> 删除 Other 的读权限。

---

## 4.3.2 `+`、`-`、`=`

这三个符号非常关键：

```text
+  增加
-  删除
=  直接设置
```

例如：

```bash
chmod u+x test
```

```text
u → User
+ → 增加
x → 执行权限
```

即：

> 给文件所有者增加执行权限。

---

例如：

```bash
chmod g-w test
```

表示：

> 删除 Group 的写权限。

---

再例如：

```bash
chmod o=rx test
```

表示：

> 把 Other 的权限直接设置成 `r-x`。

这里的 `=` 和 `+` 有本质区别。

---

# `+` 和 `=` 的区别

假设当前：

```text
Other → rwx
```

现在执行：

```bash
chmod o-x test
```

那么变成：

```text
rwx
 ↓
rw-
```

因为只删除了 `x`。

而如果执行：

```bash
chmod o=rx test
```

则直接变成：

```text
r-x
```

原来的 `w` 也会消失。

所以：

```text
+ → 在原来的基础上增加
- → 在原来的基础上删除
= → 重新指定这一类用户的权限
```

---

# 4.3.3 一次修改多个权限

可以同时写多个：

```bash
chmod u+x,g+w,o-r test
```

表示：

```text
User   → 增加 x
Group  → 增加 w
Other  → 删除 r
```

也可以：

```bash
chmod ug+r test
```

表示：

> User 和 Group 都增加读权限。

还可以：

```bash
chmod a+x test
```

表示：

> User、Group、Other 全部增加执行权限。

---

# 4.3.4 数字方式和字符方式对比

| 对比       | 数字方式             | 字符方式             |
| -------- | ---------------- | ---------------- |
| 示例       | `chmod 755 test` | `chmod u+x test` |
| 特点       | 直接设置最终权限         | 针对特定权限进行操作       |
| 优点       | 简洁               | 灵活、直观            |
| 常用场景     | 已经明确知道目标权限       | 只想增删某个权限         |
| 是否适合精细修改 | 一般               | 很适合              |

可以这样理解：

```text
数字方式
↓
“我要最终变成什么样？”

字符方式
↓
“我要在现在的基础上改什么？”
```

这是非常实用的区别。

---

# 4.4 chown修改文件所有者

前面的 `chmod` 改的是：

> **权限**

但是如果我们想修改：

> **这个文件到底属于谁？**

就要使用：

```bash
chown
```

`chown`：

```text
change owner
```

即：

> **修改文件所有者。**

---

## 4.4.1 基本格式

```bash
chown 用户 文件
```

例如：

```bash
chown caige test
```

表示：

> 把 `test` 的所有者改成 `caige`。

修改前：

```text
root root test
```

修改后：

```text
caige root test
```

这里第二个 `root` 是所属组，没有改变。

---

# 4.4.2 为什么要修改所有者？

假设：

```text
test.cpp
```

当前属于：

```text
root
```

但是我们希望普通用户：

```text
caige
```

负责这个文件。

那么就可以：

```bash
chown caige test.cpp
```

于是：

```text
所有者：
root
 ↓
caige
```

---

## 注意：权限和所有者是两回事

这个概念非常重要。

例如：

```text
-rw-r--r-- 1 root root test
```

其中：

```text
root → 所有者
root → 所属组
rw-r--r-- → 权限
```

执行：

```bash
chown caige test
```

只修改：

```text
root → caige
```

不会自动把：

```text
rw-r--r--
```

变成其他权限。

所以：

```text
chown → 改“是谁的”
chmod → 改“能干什么”
```

千万不要混淆。

---

# 4.5 chgrp修改文件所属组

如果要修改：

> **文件属于哪个组**

可以使用：

```bash
chgrp
```

即：

```text
change group
```

基本格式：

```bash
chgrp 组名 文件
```

例如：

```bash
chgrp dev test.cpp
```

表示：

> 把 `test.cpp` 的所属组修改成 `dev`。

原来：

```text
caige root
```

修改后：

```text
caige dev
```

可以发现：

```text
caige → 没变
dev   → 改变
```

所以：

```text
chown → 所有者
chgrp → 所属组
```

---

# 4.6 chown同时修改所有者和所属组

实际开发中经常希望：

> 所有者和所属组一起修改。

这时候 `chown` 可以同时完成。

格式：

```bash
chown 用户:组 文件
```

例如：

```bash
chown caige:dev test.cpp
```

表示：

```text
Owner → caige
Group → dev
```

例如原来：

```text
root root test.cpp
```

执行：

```bash
chown caige:dev test.cpp
```

变成：

```text
caige dev test.cpp
```

---

## 4.6.1 一个容易混淆的点

你可能会看到：

```bash
chown caige test
```

和：

```bash
chown caige:dev test
```

两者不同：

```text
chown caige test
```

只修改所有者。

而：

```text
chown caige:dev test
```

同时修改：

```text
所有者 + 所属组
```

---

# 4.6.2 还可以只修改组

例如：

```bash
chown :dev test
```

表示：

> 只把所属组修改为 `dev`。

因此：

```text
chown caige test
      ↓
      改Owner

chown :dev test
      ↓
      改Group

chown caige:dev test
      ↓
      Owner + Group一起改
```

---

# 4.6.3 权限、所有者、所属组形成完整体系

到这里非常值得把三种命令放在一起：

```text
                    文件
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
    所有者          所属组         权限
       │             │             │
     chown          chgrp          chmod
```

例如：

```text
-rwxr-xr-- 1 caige dev test
```

可以分别修改：

```bash
chmod 754 test
chown zhangsan test
chgrp group1 test
```

这三个命令解决的是**三个不同维度的问题**。

---

# 4.7 umask默认权限

这一节是权限管理里比较有意思的一个知识点。

我们经常会产生一个问题：

> 为什么我执行 `touch test`，新文件不是 `777`？

或者：

> 为什么 `mkdir test` 创建出来的目录默认是 `755` 左右的权限？

答案就涉及：

```bash
umask
```

---

## 4.7.1 umask是什么

可以先把 `umask` 理解成：

> **在创建新的文件或目录时，用来屏蔽某些默认权限的掩码。**

查看当前 `umask`：

```bash
umask
```

例如：

```text
0022
```

这很常见。

这里暂时重点关注最后三位：

```text
022
```

---

# 4.7.2 文件和目录的“基础权限”不同

这里非常容易产生一个误区：

有人会直接记：

```text
文件默认权限 = 666 - umask
目录默认权限 = 777 - umask
```

这个说法可以帮助初学者快速计算，但**严格来说，不能把它理解成普通的十进制减法**。

更准确的理解是：

```text
普通文件的基础权限 → 0666
目录的基础权限     → 0777

umask负责屏蔽其中对应的权限位
```

为什么文件基础权限不是 `0777`？

因为：

> **普通文件创建时不会因为默认权限机制自动获得执行权限。**

---

## 4.7.3 例如 umask = 022

假设：

```bash
umask
```

得到：

```text
0022
```

对于普通文件：

```text
基础权限
0666
```

`022` 会屏蔽：

```text
Group → w
Other → w
```

于是得到：

```text
0644
```

也就是：

```text
rw-r--r--
```

这就解释了为什么：

```bash
touch test
ls -l test
```

经常看到：

```text
-rw-r--r--
```

---

再看目录。

目录基础权限：

```text
0777
```

`umask=022`：

```text
User   → rwx
Group  → r-x
Other  → r-x
```

所以通常得到：

```text
0755
```

即：

```text
drwxr-xr-x
```

这就是你在 Linux 上经常看到：

```text
文件  → 644
目录  → 755
```

的一个重要原因。

---

# 4.7.4 为什么文件基础权限是666？

这个问题很值得理解。

假设普通文件默认创建出来就是：

```text
777
```

那么：

```text
rwxrwxrwx
```

所有者、组用户、其他用户一开始都拥有执行权限。

这通常并不是我们希望的默认行为。

因此普通文件的基础权限是：

```text
0666
```

即：

```text
rw-rw-rw-
```

经过 `umask` 再进行屏蔽。

所以：

```text
普通文件：
0666 → 屏蔽权限 → 最终权限

目录：
0777 → 屏蔽权限 → 最终权限
```

---

# 4.7.5 修改umask

例如：

```bash
umask 077
```

这表示：

> 屏蔽 Group 和 Other 的相关权限。

此时新创建普通文件通常会得到：

```text
600
```

即：

```text
rw-------
```

而新创建目录通常会得到：

```text
700
```

即：

```text
rwx------
```

再比如：

```bash
umask 000
```

表示不屏蔽这些基本权限位。

那么：

```text
文件 → 666
目录 → 777
```

但这只是说明权限计算机制，实际系统管理中不能简单为了方便就随意设置宽松的 `umask`。

---

# 一个非常重要的理解：umask不是“给权限”

这是 `umask` 最容易搞错的地方。

```text
chmod
↓
直接修改现有对象权限
```

而：

```text
umask
↓
影响以后“新创建出来的对象”的默认权限
```

例如：

```bash
umask 077
touch test
```

`umask` 不是把 `test` 从已有权限改成 `077`。

而是：

```text
以后创建 test
      ↓
系统按照基础权限 + umask规则
      ↓
决定 test 的初始权限
```

所以：

```text
chmod → 已经存在的文件/目录
umask → 新创建的文件/目录的默认权限
```

这个区别一定要记住。

---

# 再把4个命令放到一起

现在我们终于可以把这一大节完整串起来：

| 命令      | 修改什么        | 示例                 |
| ------- | ----------- | ------------------ |
| `chmod` | 文件/目录权限     | `chmod 755 test`   |
| `chown` | 文件所有者       | `chown caige test` |
| `chgrp` | 文件所属组       | `chgrp dev test`   |
| `umask` | 新建对象的默认权限规则 | `umask 022`        |

可以记成一句话：

> **`chown` 决定“是谁的”，`chgrp` 决定“属于哪个组”，`chmod` 决定“能干什么”，`umask` 决定“新建出来默认能干什么”。**

---

# 一个完整实战例子

假设我们创建：

```bash
touch test
```

查看：

```bash
ls -l test
```

得到：

```text
-rw-r--r-- 1 root root 0 Oct 1 20:55 test
```

现在：

### 第一步：修改所有者

```bash
chown caige test
```

变成：

```text
-rw-r--r-- 1 caige root ... test
```

### 第二步：修改所属组

```bash
chgrp dev test
```

变成：

```text
-rw-r--r-- 1 caige dev ... test
```

### 第三步：修改权限

```bash
chmod 750 test
```

变成：

```text
-rwxr-x--- 1 caige dev ... test
```

此时：

```text
Owner → caige → rwx
Group → dev   → r-x
Other →       → ---
```

这样三个维度就全部串起来了。

---

# 一个很重要的安全提醒

你现在是在自己的云服务器里学习，所以后面可以放心做各种权限实验，但**不要随意对整个系统执行**：

```bash
chmod -R 777 /
```

或者：

```bash
chown -R xxx:xxx /
```

这种命令。

因为 `-R` 是递归操作，目标如果是 `/`，会影响整个系统，非常危险。

学习权限时，建议一直在你自己的测试目录，例如：

```bash
~/caige/test01
```

里面实验。

# 5. file指令

前面我们已经知道，`ls -l` 的第一个字符可以帮助我们判断文件类型：

```text
- → 普通文件
d → 目录
l → 软链接
```

但是 `ls -l` 给我们的信息还是比较有限。Linux 中还有一个专门用来判断**文件实际类型**的命令：

```bash
file 文件名
```

这一节主要解决：

> **`file` 是怎么判断文件类型的？为什么文件名后缀并不能决定 Linux 中的文件类型？**

---

## 5.1 file的基本使用

最基本的语法：

```bash
file 文件
```

例如：

```bash
touch test.txt
file test.txt
```

可能得到类似：

```text
test.txt: empty
```

如果我们向里面写一些文本：

```bash
echo "hello linux" > test.txt
file test.txt
```

可能看到：

```text
test.txt: ASCII text
```

这时候你会发现：

```text
文件名：
test.txt

file判断：
ASCII text
```

这两个概念并不是一回事。

再例如：

```bash
file /bin/ls
```

可能得到：

```text
/bin/ls: ELF 64-bit LSB pie executable, ...
```

也就是说，`file` 不只是告诉你：

> “它的名字叫什么。”

而是在尝试告诉你：

> **“这个文件里面的数据表现出来的实际类型是什么。”**

---

# 5.2 file如何判断文件类型

这里需要纠正一个非常常见的误解：

> `file` 不是简单地“看后缀”。

例如：

```bash
cp test.txt test.cpp
file test.cpp
```

假如 `test.txt` 中保存的仍然是普通文本内容，那么 `file` 依然可能判断：

```text
test.cpp: ASCII text
```

因为文件内容根本没有因为：

```text
.txt
```

变成：

```text
.cpp
```

而改变。

再比如：

```bash
mv test.cpp abc.xyz
file abc.xyz
```

文件改了名字，但里面的数据没有发生变化，所以 `file` 判断出来的实际类型通常也不会因为后缀变化而改变。

---

## 那file到底看什么？

`file` 会结合文件中的**数据特征**进行判断，典型思路包括：

```text
文件
 ↓
读取文件内容中的特征
 ↓
与已知格式的特征进行匹配
 ↓
给出一个类型判断
```

对于一些二进制格式，文件开头经常存在专门的标识信息，称为 **magic number（魔数）/ 文件签名**。`file` 会利用这类信息以及其他规则进行识别。

例如 Linux 可执行文件通常是 ELF 格式，而 ELF 文件具有明显的格式特征，因此：

```bash
file ./a.out
```

能够识别出它是一个 ELF executable。

所以可以建立这样的理解：

```text
文件后缀
   ↓
主要给人和某些应用程序看

file
   ↓
根据实际数据特征判断文件类型
```

---

# 5.3 文件后缀与Linux文件类型的关系

这一点和你之前学过的：

> **Linux 中不是通过文件后缀判断文件类型**

是直接连起来的。

例如：

```bash
touch test.txt
```

此时：

```text
test.txt
```

在 Linux 文件类型意义上还是：

```text
普通文件
```

也就是：

```bash
ls -l test.txt
```

最前面：

```text
-
```

如果改名：

```bash
mv test.txt test.cpp
```

仍然：

```text
-
```

如果再改成：

```bash
mv test.cpp aaa.jpg
```

依然：

```text
-
```

因为：

> **改名不会改变文件本身的类型。**

---

## 那为什么 Windows等系统大量使用后缀？

这里需要区分两个概念：

```text
Linux的文件类型
```

和：

```text
应用程序如何识别文件
```

Linux 内核本身并不要求：

```text
.txt → 文本文件
.cpp → C++源文件
.jpg → 图片
```

但各种用户态程序完全可以使用文件后缀来帮助自己判断如何打开文件。

所以更准确的说法是：

> **文件后缀不是 Linux 内核定义普通文件类型的依据，但应用程序可以利用文件后缀来识别文件格式或决定如何处理它。**

这就是老师板书里“系统不关心，但是工具关心”更严谨的理解。

---

# 一个很好的对比

| 判断方式              | 主要依据      | 作用             |
| ----------------- | --------- | -------------- |
| `ls -l` 第一个字符     | 文件系统对象类型  | 判断普通文件、目录、链接等  |
| `file`            | 文件内容及格式特征 | 进一步识别实际文件类型/格式 |
| `.txt`、`.cpp` 等后缀 | 文件名       | 主要方便人和应用程序识别   |

因此：

```text
ls -l
```

更偏向：

> **“这是什么类型的文件系统对象？”**

而：

```text
file
```

更偏向：

> **“这个文件里面的数据看起来是什么格式？”**

这是两者的重要区别。

---

# 6. 目录的权限

这一部分是整个权限章节中**非常重要、非常容易出错**的一块。

到现在为止，我们已经理解普通文件的：

```text
r → 读
w → 写
x → 执行
```

但是当对象从：

```text
普通文件
```

变成：

```text
目录
```

以后，`rwx` 的含义就发生了变化。

这是因为：

> **目录本身不是“文件内容”，它更像是一个保存文件名以及对象关系的容器。**

所以一定不要机械地把普通文件的 `r/w/x` 含义原封不动套到目录上。

---

# 6.1 目录的r权限

对于目录：

```text
r
```

主要表示：

> **允许读取目录中的目录项信息，也就是查看里面有哪些名字。**

例如：

```bash
mkdir dir
touch dir/a dir/b dir/c
```

此时：

```bash
ls dir
```

可能看到：

```text
a
b
c
```

这里实际上涉及读取目录内容的能力。

可以先建立一个近似理解：

```text
目录 r
↓
“我能不能知道这个目录里有什么名字？”
```

但是注意：

> **能看到文件名，不等于一定能访问这个文件。**

例如目录里面有：

```text
secret.txt
```

你可能知道：

```text
secret.txt
```

这个名字存在，但如果后续访问它还缺少必要权限，仍然可能打不开。

所以：

```text
看到名字
≠
能够访问文件内容
```

---

# 6.2 目录的w权限

目录的：

```text
w
```

主要表示：

> **是否可以修改目录中的目录项。**

这会影响：

```text
创建文件
删除文件
重命名文件
```

例如：

```bash
touch dir/test
```

本质上是：

> 在 `dir` 这个目录中增加一个新的目录项。

删除：

```bash
rm dir/test
```

本质上也是：

> 修改父目录中的目录项关系。

重命名：

```bash
mv dir/a dir/b
```

同样涉及对目录中的目录项进行修改。

所以这里有一个非常重要的结论：

> **删除文件主要检查的是父目录的写权限，而不是被删除文件本身的写权限。**

这个结论以后做权限实验时非常重要。

---

# 一个经典例子

假设：

```text
dir/
└── test.txt
```

`test.txt` 本身权限是：

```text
r--r--r--
```

看起来完全没有 `w`。

很多初学者会觉得：

> “那我肯定不能删除 `test.txt`。”

其实不一定。

如果：

```text
dir/
```

这个目录对当前用户具有：

```text
w
```

权限，那么仍然**可能能够删除**：

```bash
rm dir/test.txt
```

因为：

```text
删除 test.txt
↓
修改 dir 的目录项
↓
关键看 dir 是否允许这种修改
```

这正是目录权限和普通文件权限最容易混淆的地方。

---

# 6.3 目录的x权限

目录的：

```text
x
```

是最容易误解的。

目录的 `x`：

> **不是“执行目录”。**

更准确地说，它表示：

> **允许进入/遍历目录，并按照路径访问其中的对象。**

例如：

```bash
cd dir
```

需要目录具备相应的 `x` 权限。

你可以把目录的 `x` 暂时理解成：

```text
x
↓
“我有资格进入这个目录，并沿着这个目录继续访问”
```

---

# 为什么“进入目录”需要x？

假设：

```text
/home/caige/test01/a/b
```

要访问：

```text
/home/caige/test01/a/b/test.txt
```

实际上你是在不断地沿着路径向下走：

```text
/
 ↓
home
 ↓
caige
 ↓
test01
 ↓
a
 ↓
b
 ↓
test.txt
```

每一级目录都需要具备相应的**遍历/搜索能力**。

所以：

> **路径访问是逐级检查的。**

这也是为什么 Linux 权限问题中，经常出现：

```text
文件本身权限看起来没问题
但是仍然 Permission denied
```

因为可能是：

```text
文件权限没问题
↓
某一级父目录没有x权限
↓
根本走不到这个文件
```

这个思想非常重要。

---

# 6.4 目录权限与普通文件权限的区别

现在正式做一张必须记住的表：

| 权限  | 普通文件   | 目录              |
| --- | ------ | --------------- |
| `r` | 读取文件内容 | 查看目录中的目录项/文件名   |
| `w` | 修改文件内容 | 创建、删除、重命名目录中的对象 |
| `x` | 执行文件   | 进入/遍历目录、访问其中对象  |

可以把它压缩成一句话：

> **文件的 `rwx` 是对“文件内容”进行控制；目录的 `rwx` 是对“目录中的对象以及路径访问”进行控制。**

---

# 一个特别值得做的实验

在你自己的测试目录中，比如：

```bash
cd ~/caige/test01
mkdir testdir
touch testdir/a
```

先看：

```bash
ls -ld testdir
```

注意这里使用的是：

```bash
ls -ld
```

而不是单纯的：

```bash
ls -l testdir
```

因为：

```bash
ls -l testdir
```

默认会查看目录**里面的内容**。

而：

```bash
ls -ld testdir
```

中的 `-d` 表示：

> 把 `testdir` 自己当作一个对象来查看。

例如：

```text
drwxr-xr-x
```

然后我们就可以围绕：

```text
r
w
x
```

分别实验，观察哪些操作成功、哪些操作失败。

这会比单纯背定义理解得更牢。

---

# 6.5 父目录权限与文件操作的关系

这是这一部分的核心。

假设：

```text
/home/caige/test01/a/test.txt
```

我们不能只看：

```text
test.txt
```

而应该把整个路径考虑进去：

```text
/
↓
home
↓
caige
↓
test01
↓
a
↓
test.txt
```

因为访问：

```text
/home/caige/test01/a/test.txt
```

实际上是一个**路径遍历过程**。

因此可能出现：

```text
test.txt
权限：777

但是：

a
权限：---
```

这种情况下，当前用户仍然可能无法访问：

```text
/home/caige/test01/a/test.txt
```

因为：

> **你连 `a` 这个目录都没有相应的遍历权限。**

---

# 为什么删除主要看父目录？

再强调一次，因为这个知识点非常重要。

假设：

```text
dir/
└── test.txt
```

执行：

```bash
rm dir/test.txt
```

这里并不是在修改：

```text
test.txt
```

中的内容。

而是在修改：

```text
dir
```

这个目录所记录的目录项。

因此主要看：

```text
dir
↓
是否允许修改目录项
```

也就是通常需要：

```text
w + x
```

---

# 为什么目录经常需要 `wx` 一起理解？

单独的 `w` 往往不足以完成你日常理解中的目录修改操作。

例如想在目录中：

```bash
touch dir/test
```

除了需要能够修改目录内容之外，还需要能够遍历/访问这个目录。

所以实际理解目录操作时，经常要一起考虑：

```text
w → 是否允许修改
x → 是否允许访问/遍历
```

于是可以形成一个很实用的判断：

```text
创建/删除/重命名目录中的对象
        ↓
重点看父目录
        ↓
通常需要 w + x
```

---

# 一个非常容易混淆的例子

假设：

```text
dir
权限：r-x
```

也就是：

```text
r → 有
w → 没有
x → 有
```

那么当前用户可能：

```bash
cd dir
```

成功，因为有：

```text
x
```

也可能：

```bash
ls dir
```

成功，因为有：

```text
r
```

但是：

```bash
touch dir/test
```

可能失败，因为：

```text
没有 w
```

也就是说：

```text
r → 看
x → 进/走
w → 改
```

这个理解非常有用。

---

# 普通文件和目录，一定不要混为一谈

最终一定要形成这两个模型：

## 普通文件

```text
r → 看文件内容
w → 改文件内容
x → 执行文件
```

## 目录

```text
r → 看目录中有什么
w → 修改目录中的对象
x → 进入/遍历目录
```

所以：

```text
“x就是执行”
```

只适用于普通文件的一个典型解释。

对于目录，`x` 更应该理解为：

> **搜索/遍历权限。**

# 7. 关于权限的总结

前面已经把 Linux 权限的各个组成部分分别学习了一遍，现在这一节不再增加太多新知识，而是把前面的内容**真正串成一个完整的权限体系**。

这一部分非常重要，因为学习 Linux 时，真正让你遇到问题的往往不是“不会某一个命令”，而是：

> **面对一个权限问题，不知道应该从哪里分析。**

所以这一节我们重点建立一套完整的分析方法。

---

## 7.1 权限表示体系

先把整个权限表示体系重新建立起来。

当你执行：

```bash
ls -l
```

例如看到：

```text
-rwxr-xr-- 1 caige dev 1234 Oct 1 21:00 test
```

最前面的：

```text
-rwxr-xr--
```

应该拆成：

```text
- | rwx | r-x | r--
```

分别表示：

```text
-    → 文件类型
rwx  → User
r-x  → Group
r--  → Other
```

所以整个模型是：

```text
文件
│
├── 文件类型
│
├── User权限
│   └── rwx
│
├── Group权限
│   └── rwx
│
└── Other权限
    └── rwx
```

而每组三个字符：

```text
r w x
```

分别表示：

```text
r → read
w → write
x → execute
```

---

## 字符表示和数字表示

Linux 同时支持两套表示方式。

例如：

```text
rwxr-xr--
```

拆成：

```text
rwx | r-x | r--
```

再转换：

```text
rwx → 7
r-x → 5
r-- → 4
```

所以：

```text
rwxr-xr-- → 754
```

反过来也一样：

```text
754
↓
rwxr-xr--
```

核心对应关系：

| 权限    | 数字 |
| ----- | -: |
| `---` |  0 |
| `--x` |  1 |
| `-w-` |  2 |
| `-wx` |  3 |
| `r--` |  4 |
| `r-x` |  5 |
| `rw-` |  6 |
| `rwx` |  7 |

最需要熟练的是：

```text
r = 4
w = 2
x = 1
```

---

## 一个完整例子

```text
-rwxr-xr--
```

可以同时理解成：

```text
文件类型 → 普通文件

User   → rwx → 7
Group  → r-x → 5
Other  → r-- → 4
```

所以：

```text
-rwxr-xr--
        ↓
       754
```

这样你以后看到：

```bash
chmod 754 test
```

就不是死记：

> “754 是一个权限。”

而是知道：

> **754 是 User、Group、Other 三组权限的数字化表示。**

---

# 7.2 chmod / chown / chgrp / umask

现在把四个命令重新放在一起。

| 命令      | 解决的问题             |
| ------- | ----------------- |
| `chmod` | 文件/目录“能干什么”       |
| `chown` | 文件“属于谁”           |
| `chgrp` | 文件“属于哪个组”         |
| `umask` | 新创建文件/目录“默认是什么权限” |

可以记成：

```text
谁的？
 ↓
chown

属于哪个组？
 ↓
chgrp

能干什么？
 ↓
chmod

新建时默认能干什么？
 ↓
umask
```

---

## chmod

```bash
chmod 755 test
```

修改的是：

```text
权限
```

变成：

```text
rwxr-xr-x
```

字符方式：

```bash
chmod u+x test
chmod g-w test
chmod o-r test
```

这里：

```text
u → User
g → Group
o → Other
a → All

+ → 增加
- → 删除
= → 设置
```

---

## chown

```bash
chown caige test
```

修改：

```text
Owner
```

也就是文件所有者。

还可以：

```bash
chown caige:dev test
```

一次修改：

```text
Owner → caige
Group → dev
```

---

## chgrp

```bash
chgrp dev test
```

只修改：

```text
Group
```

---

## umask

```bash
umask
```

查看当前掩码。

例如：

```text
0022
```

它影响的是**以后新创建对象的默认权限**。

最重要的理解：

```text
chmod
↓
修改已经存在的对象权限

umask
↓
影响以后新创建对象的初始权限
```

例如：

```text
普通文件基础权限 → 0666
目录基础权限     → 0777
        ↓
      umask
        ↓
    最终初始权限
```

这里要特别注意：

> `umask` 并不是“给文件增加权限”，而是用来屏蔽创建时的部分默认权限。

# 7.3 文件权限与目录权限

这是整个章节最容易混淆，也是最值得总结的一部分。

普通文件：

| 权限  | 含义     |
| --- | ------ |
| `r` | 读取文件内容 |
| `w` | 修改文件内容 |
| `x` | 执行文件   |

目录：

| 权限  | 含义            |
| --- | ------------- |
| `r` | 查看目录中的目录项/文件名 |
| `w` | 修改目录中的目录项     |
| `x` | 进入、遍历、访问目录    |

一定不能把：

```text
目录 x
```

理解成：

> “执行这个目录。”

目录没有所谓“像程序一样执行”的概念。

---

## 为什么目录的权限这么特殊？

因为目录本身的作用主要是组织文件和目录。

例如：

```text
test01/
├── a
├── b
└── test.txt
```

目录需要解决的是：

```text
能不能看到里面有什么？
能不能修改里面的对象？
能不能进入并沿着路径访问？
```

于是分别对应：

```text
r → 看
w → 改
x → 走
```

可以把它记成：

> **目录：r 看、w 改、x 走。**

这个口诀对于初学阶段非常好用。

---

# 父目录权限为什么如此重要？

假设：

```text
/home/caige/test01/a/test.txt
```

你要访问：

```text
test.txt
```

系统不能直接“跳到文件那里”，而是要沿着：

```text
/
↓
home
↓
caige
↓
test01
↓
a
↓
test.txt
```

一路遍历。

所以访问一个文件时：

> **不仅要看文件本身，还要考虑路径上各级父目录的权限。**

这就是为什么会出现：

```text
文件权限看起来完全没问题
↓
仍然 Permission denied
```

因为很可能：

```text
某一级父目录没有 x 权限
```

导致根本无法走到目标文件。

---

## 删除文件为什么主要看父目录？

例如：

```text
dir/
└── test.txt
```

执行：

```bash
rm dir/test.txt
```

这里主要是在修改：

```text
dir
```

这个目录中的目录项，而不是修改 `test.txt` 的内容。

因此：

```text
删除文件
↓
重点看父目录
↓
通常需要父目录的 w + x
```

所以：

> **“文件不可写”不一定意味着“文件不能删除”。**

这是 Linux 权限中非常经典的知识。

---

# 7.4 常见权限问题总结

现在我们来建立一套真正实用的排查方法。

以后遇到：

```text
Permission denied
```

不要立即乱执行：

```bash
chmod 777
```

而应该按照顺序分析。

---

## 第一问：我是谁？

使用：

```bash
whoami
```

或者：

```bash
id
```

确认当前用户。

例如：

```text
root
```

或者：

```text
caige
```

---

## 第二问：目标是谁的？

使用：

```bash
ls -l test
```

例如：

```text
-rw-r--r-- 1 caige dev test
```

可以看到：

```text
Owner → caige
Group → dev
```

---

## 第三问：我属于哪一类？

假设：

```text
Owner = caige
Group = dev
```

当前用户：

```text
zhangsan
```

那么继续判断：

```text
zhangsan 是 Owner 吗？
↓
否

zhangsan 属于 dev 组吗？
↓
是

→ 使用 Group 权限
```

如果两者都不是：

```text
→ 使用 Other 权限
```

---

## 第四问：对应权限够不够？

例如：

```text
-rwxr-x---
```

如果当前用户属于 Group：

```text
Group → r-x
```

那么：

```text
读 → 可以
写 → 不可以
执行 → 可以
```

于是：

```bash
cat test
```

和：

```bash
echo hello > test
```

结果可能完全不同。

前者需要读取权限，后者需要写权限。

---

## 第五问：如果操作的是目录，别只看文件

例如：

```bash
cd /home/caige/test01
```

如果失败，重点检查：

```text
/home
caige
test01
```

这些目录的遍历权限。

例如：

```bash
ls -ld /home
ls -ld /home/caige
ls -ld /home/caige/test01
```

因为：

> **目录权限可能是问题的真正来源。**

---

# 一个完整的权限排错思路

以后可以把它记成：

```text
Permission denied
        ↓
① 当前用户是谁？
        ↓
② 目标文件/目录是谁的？
        ↓
③ 当前用户属于 User / Group / Other 哪一类？
        ↓
④ 对应的 r/w/x 是什么？
        ↓
⑤ 如果是目录，检查目录的 r/w/x
        ↓
⑥ 如果是路径，检查每一级父目录的 x
        ↓
⑦ 再决定是否需要 chmod/chown 等操作
```

这比：

```bash
chmod 777 xxx
```

重要得多。

# 8. 粘滞位【选学】

现在进入老师标记的：

> **粘滞位（Sticky Bit）**

这一部分属于权限体系中的**特殊权限**，基础阶段了解其工作原理即可。

最经典的使用场景就是：

```text
/tmp
```

---

## 8.1 什么是粘滞位

粘滞位是 Linux 中的一种特殊权限位。

最经典的效果是：

> **对于设置了粘滞位的目录，即使多个用户都拥有对该目录的写权限，普通用户也不能随意删除其他用户拥有的文件。**

为什么需要这个机制？

想象一下：

```text
/tmp
```

这是一个公共临时目录。

多个用户都可能在里面创建文件。

例如：

```text
/tmp/
├── caige.txt
├── zhangsan.txt
└── lisi.txt
```

如果目录允许所有用户：

```text
rwx
```

那么按照普通的目录写权限理解：

> 用户理论上可以修改目录中的目录项。

这就可能导致：

```text
zhangsan
 ↓
删除
 ↓
caige.txt
```

显然不太合理。

所以 Linux 提供了：

```text
Sticky Bit
```

帮助公共目录实现：

> **大家都可以使用，但不能随便删除别人拥有的文件。**

---

# 8.2 粘滞位的表示

最典型的目录权限可能是：

```text
drwxrwxrwt
```

注意最后一个字符：

```text
t
```

普通情况下：

```text
drwxrwxrwx
```

特殊情况下：

```text
drwxrwxrwt
```

最后的：

```text
t
```

就表示：

> **Sticky Bit 被设置。**

---

## 为什么出现的是`t`？

我们以前已经知道：

```text
rwx
```

是三个权限位。

在特殊权限存在时，某些位置会使用特殊字符进行表示。

对于 Sticky Bit，最后一个位置对应：

```text
x
```

如果同时具有执行权限，通常显示：

```text
t
```

如果没有执行权限，可能显示：

```text
T
```

也就是说：

```text
t → Sticky Bit + x
T → Sticky Bit，但没有 x
```

初学阶段重点记住：

```text
t
↓
Sticky Bit
```

即可。

---

# 8.3 /tmp中的粘滞位

你在 Linux 服务器上可以查看：

```bash
ls -ld /tmp
```

可能看到类似：

```text
drwxrwxrwt ... /tmp
```

重点观察：

```text
drwxrwxrwt
         ↑
         t
```

这说明 `/tmp` 使用了 Sticky Bit。

为什么 `/tmp` 需要它？

因为：

```text
很多用户
   ↓
共享同一个目录
   ↓
都可能创建自己的临时文件
```

但又不能允许：

```text
用户A
 ↓
随便删除
 ↓
用户B的文件
```

所以：

```text
公共目录 + 写权限
        ↓
     Sticky Bit
        ↓
限制普通用户删除其他用户拥有的文件
```

---

# 8.4 粘滞位解决什么问题

它解决的核心问题可以概括成：

> **共享可写目录中的文件删除控制。**

特别是在：

```text
/tmp
```

这种典型公共目录中非常重要。

例如：

```text
/tmp
├── caige
├── zhangsan
└── lisi
```

大家都可以创建自己的临时文件。

但设置 Sticky Bit 后：

```text
caige
 ↓
不能随便删除 zhangsan 拥有的文件

zhangsan
 ↓
不能随便删除 lisi 拥有的文件
```

当然，`root` 等具有特殊系统管理权限的身份不受普通用户权限限制，这也是为什么你作为 `root` 做实验时，经常会发现“权限限制和普通用户不一样”。

# Sticky Bit 和普通 `x` 的关系

这里再补充一个容易混淆的点。

看到：

```text
drwxrwxrwt
```

不要认为最后的：

```text
t
```

是普通的 `x`。

实际上它同时表达了：

```text
x
+
Sticky Bit
```

所以：

```text
t
```

是一个特殊权限位状态的表示。

# 这一章最核心的知识

如果把整章压缩成一张图，就是：

```text
                    Linux权限
                       │
             ┌─────────┴─────────┐
             ↓                   ↓
          谁在访问？          访问什么？
             │                   │
       User / Group / Other    文件 / 目录
             │                   │
             └─────────┬─────────┘
                       ↓
                 能做什么？
                       ↓
                    r / w / x
                       │
             ┌─────────┴─────────┐
             ↓                   ↓
          文件权限             目录权限
             │                   │
       r → 读内容          r → 看目录
       w → 改内容          w → 改目录
       x → 执行            x → 进入/遍历
             │                   │
             └─────────┬─────────┘
                       ↓
                  chmod等工具
             ┌─────────┼─────────┐
             ↓         ↓         ↓
           chmod      chown     chgrp
             │
             ↓
           umask
             │
             ↓
        新对象默认权限
```

真正应该掌握的不是某几个命令，而是这个思维：

> **Linux 权限 = 访问者身份 + 目标对象 + 操作类型 + 对应权限。**

例如：

```text
caige
 ↓
访问
 ↓
/home/caige/test01/a/test.txt
 ↓
是不是Owner？
属于哪个Group？
 ↓
对应身份有什么r/w/x？
 ↓
路径上的目录有没有x？
 ↓
最终决定允许还是拒绝
```

这已经是 Linux 权限问题的基本分析框架了。
