# 4. 进程控制

## 1. 进程创建
**`fork` 接口与返回值**：
- `<unistd.h>`：`pid_t fork(void)`；无参数，`pid_t` 为可表示 PID 和 `-1` 的整数类型。
- 父进程返回子进程 PID；子进程返回 `0`；失败返回 `-1`，**失败时没有子进程**。
- 失败原因：系统进程数过多、实际用户 ID 对应的进程数超限、内存等资源不足；用 `perror("fork")` 查看实际原因。
**内核过程与写时拷贝**：
- 分配独立 PCB 等管理结构 → 继承父进程部分信息、设置新 PID → 纳入系统管理并可被调度 → 父子从 `fork` 返回处继续执行；先后顺序不确定。
- 独立管理信息不等于立即复制全部内存；写时拷贝将共享页的副本分配推迟到需要写入时，**不是推迟创建子进程**。
**常规用法**：

| 需求 | 做法 | 子进程内容 |
|---|---|---|
| 原程序内分工 | 父子按返回值分支；如父进程接收请求、子进程处理请求 | 原程序不同代码段 |
| 执行其他程序 | `fork` 后由子进程调用 `exec*` | 替换后的新程序 |

## 2. 进程终止
**终止方式与任务结果**：

| 情况 | 终止方式 | 结果判断 |
|---|---|---|
| 主动结束，报告成功 | 正常终止 | 通常退出码 `0` |
| 主动结束，报告失败 | 正常终止 | 通常非零退出码 |
| 被信号终止 | 信号终止 | 查看终止信号 |

- **正常终止不等于任务成功**；退出码由程序报告，操作系统不验证业务结果；具体非零值的含义由程序约定。
- `Ctrl+C` 通常向前台进程组发送 `SIGINT`（`2`），默认终止；可以被处理或忽略。`SIGTERM`（`15`）默认终止；`SIGKILL`（`9`）强制终止。
- C 整数除零是未定义行为；常见 Linux 环境可能触发 `SIGFPE`，不能认定退出码为 `1`。
**退出接口与缓冲区**：

| 项目 | `exit` | `_exit` |
|---|---|---|
| 原型、头文件 | `void exit(int status)`，`<stdlib.h>` | `void _exit(int status)`，`<unistd.h>` |
| 登记的退出清理函数 | 执行 `atexit` / `on_exit` 登记函数；后者非标准 C | 不执行 |
| C 库输出缓冲区 | 刷新，再关闭流 | 不刷新，未提交数据可能丢失 |
| 终止路径 | C 库清理后进入底层终止路径 | 系统调用封装；现代 Linux 常经 `exit_group` |
| 范围、返回值 | 结束整个进程，不返回 | 结束整个进程，不返回 |

- `status` 报告终止结果；父进程可取得的正常退出码仅为低 8 位，范围 `0～255`；`_exit(-1)` 对外报告 `255`。
- 两者均会触发内核资源回收；区别是 **C 库清理**，不是内核是否回收资源。
- 刷新 C 库缓冲区只是把数据交给操作系统，不保证已经落盘；全缓冲下 `printf("hello")` 后调用 `exit(0)` 会输出，调用 `_exit(0)` 可能丢失。
**`return` 的作用范围**：

| 写法 | 效果 |
|---|---|
| `main` 中 `return n` | 正常启动的 C 程序中，相当于 `exit(n)` |
| 普通函数中 `return n` | 仅结束本次函数调用 |
| 任意函数中 `exit(n)` | 结束整个进程，不回到调用点 |

**Shell 状态、等待状态与错误编号**：

| 信息 | 含义 | 查看方式 |
|---|---|---|
| 退出码 | 程序自行约定的结果 | 正常终止后用 `WEXITSTATUS(status)` |
| 等待状态 `status` | 内核编码的退出码、信号等信息 | `wait` / `waitpid` 获取，再用宏解析 |
| Shell 的 `$?` | 当前 shell 上一条命令的状态 | 紧接着执行 `echo $?` |
| `errno` 错误编号 | 系统调用或库函数失败原因 | `perror`、`strerror` |

- 中间执行其他命令会覆盖 `$?`；它不是系统中最近结束的任意进程状态。退出信息由父进程读取，父进程不固定为 Bash。
- Bash 对信号终止通常报告 `128+n`：`SIGINT` → `130`，`SIGTERM` → `143`；程序也能主动返回这些数，**仅凭 `$?` 不能严格判定终止方式**。
- `<string.h>`：`char *strerror(int errnum)`，接收错误编号，返回描述字符串；如 `strerror(EACCES)`。**不是退出码翻译器**，不能用 `strerror(130)` 解释 Bash 状态。
- 内核在 `task_struct` 等记录中保留编码后的终止信息，供父进程等待读取；不等同于 `$?`。

## 3. 进程等待
**用途与接口**：
- **等待首先用于回收子进程退出后遗留的资源，避免僵尸；是否读取退出信息可选。**
- 头文件：`<sys/types.h>`、`<sys/wait.h>`。
- `pid_t wait(int *status)`：等待并回收任意一个子进程；成功返回其 PID，失败返回 `-1`。
- `pid_t waitpid(pid_t pid, int *status, int options)`：选择子进程及等待方式；`options` 必须传入。
- `status` 是输出型参数；传 `&status` 接收状态，传 `NULL` 仅回收。**返回值回答“收到了谁”，`status` 回答“怎样结束”。**
- `wait(&status)` 等效于 `waitpid(-1, &status, 0)`；一次成功调用回收一个子进程。
**`waitpid` 的对象选择**：

| `pid` | 等待对象：均限于调用者的子进程 |
|---|---|
| `> 0` | PID 为 `pid` 的子进程 |
| `-1` | 任意子进程 |
| `0` | 与调用者同进程组的任意子进程 |
| `< -1` | 进程组 ID 为 `abs(pid)` 的任意子进程 |

**阻塞、非阻塞与返回值**：

| 符合条件的子进程情况 | `options = 0`：阻塞 | `options = WNOHANG`：非阻塞 |
|---|---|---|
| 已退出、尚未回收 | 返回 PID，完成回收 | 返回 PID，完成回收 |
| 存在，但均未退出 | 阻塞在调用处 | 立即返回 `0` |
| 没有可等待子进程 | 返回 `-1` | 返回 `-1` |

- 返回正数只表示成功收取结果，**不表示任务成功，也不表示一定正常终止**。
- 仅 `ret > 0` 时解析本次 `status`；`ret == 0` 尚无结果；`ret == -1` 检查错误，`errno == EINTR` 时通常重试，其他错误报错。
- 阻塞时父进程不执行后续语句；这里的“挂起”不是特指换出到 swap。
**Linux 终止状态低 16 位**：

| 位号 | 正常终止 | 信号终止 |
|---|---|---|
| `15～8` | 正常退出码 | 不作为有效退出码 |
| `7` | `0` | core dump 标志 |
| `6～0` | `0` | 终止信号编号 |

| 宏 | 作用 | 前提 |
|---|---|---|
| `WIFEXITED(status)` | 判断正常终止 | 成功获取状态 |
| `WEXITSTATUS(status)` | 提取正常退出码 | `WIFEXITED(status)` 为真 |
| `WIFSIGNALED(status)` | 判断信号终止 | 成功获取状态 |
| `WTERMSIG(status)` | 提取终止信号 | `WIFSIGNALED(status)` 为真 |

- 手工理解：`(status >> 8) & 0xFF` 取退出码；`status & 0x7F` 取终止信号；实际程序优先使用宏。
- 位图结论仅针对 Linux 常见终止状态，不直接扩展到暂停、恢复事件；core 标志不保证当前目录存在转储文件。
- `task_struct.exit_signal` 通常是退出时通知父进程的信号，**不是杀死子进程的信号**。
**非阻塞轮询与回调**：
- `waitpid(child, &status, WNOHANG)` 返回 `0` 后，父进程主动执行其他任务，再次查询；`WNOHANG` 本身不会安排其他工作。
- 回调可用 `typedef void (*handler_t)(void)`，登记到函数指针数组后逐项调用；需携带状态的任务可用 `std::function<void()>`。
- `sleep(1)` 控制查询频率，避免忙轮询；属于主动延时，不是 `waitpid` 阻塞。间隔及其他任务耗时越长，发现退出越迟。
```c
pid_t ret; // 保存等待结果
do {
    ret = waitpid(child, &status, 0); // 等待指定子进程
} while (ret == -1 && errno == EINTR); // 被信号打断时重试
if (ret > 0 && WIFEXITED(status))
    printf("exit=%d\n", WEXITSTATUS(status)); // 正常终止才取退出码
else if (ret > 0 && WIFSIGNALED(status))
    printf("signal=%d\n", WTERMSIG(status)); // 信号终止才取信号
```

## 4. 进程程序替换
**替换语义**：

| 对比项 | `fork` | `exec*` |
|---|---|---|
| 创建新进程 | 是 | 否 |
| PID | 子进程获得新 PID | 调用进程 PID 不变 |
| 程序内容 | 起初延续原程序 | 替换用户空间代码、数据及地址映射 |
| 执行位置 | 父子从返回处继续 | 从新程序启动例程开始，不直接从 `main` 开始 |
| 返回 | 父、子分别返回 | 成功不返回；失败返回 `-1` 并设置 `errno` |

- `exec` 是函数族统称；保留进程身份不代表 `task_struct` 所有字段不变。
- **只要 `exec*` 返回，就说明替换失败**；新程序退出不是 `exec` 返回。
- 失败常见原因：目标不存在、无执行权限、格式不符合要求；用 `perror("exec")` 报错。
- 父子地址空间独立，子进程替换不影响父进程；不是先复制父进程全部程序再覆盖。父进程直接调用则替换父进程自身。
**命名与接口**：

| 字母 | 含义 |
|---|---|
| `l`：list | 参数逐个列出 |
| `v`：vector | 参数放在数组中 |
| `p`：path | 按 `PATH` 搜索程序 |
| `e`：env | 显式指定环境数组 |

- 均声明于 `<unistd.h>`，返回类型均为 `int`；成功不返回，失败返回 `-1`。

| 函数原型 | 典型调用 | 环境 |
|---|---|---|
| `int execl(const char *path, const char *arg, ...)` | `execl(path, arg0, ..., (char *)NULL)` | 继承 |
| `int execlp(const char *file, const char *arg, ...)` | `execlp(file, arg0, ..., (char *)NULL)` | 继承 |
| `int execle(const char *path, const char *arg, ...)` | `execle(path, arg0, ..., (char *)NULL, envp)` | 显式 `envp` |
| `int execv(const char *path, char *const argv[])` | `execv(path, argv)` | 继承 |
| `int execvp(const char *file, char *const argv[])` | `execvp(file, argv)` | 继承 |
| `int execve(const char *path, char *const argv[], char *const envp[])` | `execve(path, argv, envp)` | 显式 `envp` |

**路径与参数约束**：
- `path` 定位程序；`arg0` / `argv[0]` 是新程序收到的名称，惯例写程序名，不负责定位文件，也不强制与文件名相同。
- 无 `p` 可用绝对或相对路径，只是不搜索 `PATH`；有 `p` 时，`file` 含 `/` 则直接按路径执行。
- 相对路径 `./other` 相对于**当前工作目录**，不是启动器文件所在目录。
- 每个参数分开传递：`execlp("ls", "ls", "-l", "-a", (char *)NULL)`；不能把 `"ls -l -a"` 当成一个参数。
- 列表用 `(char *)NULL` 结束；`argv`、`envp` 数组也必须以空指针结束；`execle` 的 `envp` 放在参数列表终止空指针之后。
**环境与底层关系**：

| 方式 | 效果 |
|---|---|
| 不带 `e` | 继承调用进程当前环境 |
| 先 `putenv(setting)`，再调用不带 `e` 的接口 | 修改当前环境后继承 |
| `execle` / `execve` 传 `envp` | 使用显式环境，**不自动合并旧环境** |

- `envp` 各项为 `"NAME=value"`；`<stdlib.h>` 中 `int putenv(char *string)` 成功返回 `0`、失败非零；直接使用字符串存储，必须保持有效。
- 六种接口中 `execve` 对应系统调用，手册第 2 节；其余五个是库封装，手册第 3 节，最终交由 `execve` 完成替换。
- 可执行系统程序或自编译程序；替换前需要保留的 C 库缓冲输出应先 `fflush(stdout)`，成功替换不会替旧程序执行 `exit` 清理。
```c
if (child == 0) { // fork 成功后的子进程分支
    execvp(argv[0], argv); // 成功后不再执行旧代码
    perror("execvp"); // 仅失败到达
    _exit(127); // 报告失败，避免落入父进程逻辑
}
```

## 5. 自主Shell命令行解释器
**循环与实现边界**：
- 提示符 → 读取 → 解析 → 优先检查内建命令 → 外部命令 `fork` + `execvp` + `waitpid` → 保存结果 → 下一轮。
- 仅处理按空格拆分的简单命令；不实现引号、管道、重定向、完整本地变量赋值。
**内建与外部命令**：

| 项目 | 外部命令 | 本节内建命令 |
|---|---|---|
| 执行位置 | 子进程中的外部程序 | shell 自己调用函数 |
| 例子 | `ls`、`ps`、`cat` | `cd`、`export`、`env`、`echo` |
| 状态影响 | 不直接改变父 shell 的目录、环境 | 可改变当前 shell 状态 |
| 执行后 | 父 shell 等待、继续循环 | 直接记录结果、继续循环 |

- `cd`、`export` 要影响当前 shell，必须在当前 shell 中执行；`env`、`echo` 也可以由外部程序实现。
- 交互 shell 不直接在自身调用 `execvp`，否则成功后输入循环消失。
**关键数据**：

| 数据 | 用途与约束 |
|---|---|
| `char *gargv[64]`、`int gargc = 0` | 本轮参数及数量；含命令名，最多 63 个有效项，末尾 `NULL` |
| `char *genv[64]` | 自维护环境表；最多 63 项，末尾 `NULL`，可能不足以容纳继承环境 |
| `char pwd[1024]` | 当前路径缓存，不是 `pwd` 命令 |
| `char pwdenv[1024]` | `"PWD=路径"`；需额外容纳前缀及终止符 |
| `int lastcode = 0` | 上一条命令状态；外部命令与内建命令均应更新 |
| `extern char **environ` | 当前进程实际环境表入口 |

**提示、输入与解析**：
- `snprintf(command_line, size, "[%s@%s %s]# ", user, host, dir)` 构造提示符，检查截断；提示符无换行，输出后 `fflush(stdout)`。
- `fgets(command_buffer, sizeof command_buffer, stdin)`：返回 `NULL` 时处理 EOF / 错误；检查输入是否完整，过长行拒绝执行并处理剩余输入。
- `command_buffer[strcspn(command_buffer, "\n")] = '\0'` 去换行；每轮 `gargc = 0`。
- `strtok(command_buffer, " ")` 开始拆分，`strtok(NULL, " ")` 继续，返回 `NULL` 表示结束；最后 `gargv[gargc] = NULL`。
- `strtok` 修改原数组，`gargv` 仅指向其中内容；不理解引号，分隔符 `" "` 不包含制表符。
- `gargc == 0` 直接下一轮，不访问命令名；超过 63 项应拒绝。
- `TrimSpace` 仅让指针跳过前导空白，`strtok` 拆分参数；已被 `strtok` 跳过的前导空格无需重复处理。宏参数避免复杂、有副作用的表达式。
**外部命令执行与状态记录**：
- `fork` 失败报错；子进程执行 `execvp(gargv[0], gargv)`，失败报错并 `_exit`，**不得进入 shell 读命令循环**。
- 父进程 `waitpid(id, &status, 0)`；`EINTR` 重试，其他失败不解析状态。
- 成功后：`WIFEXITED(status)` → `lastcode = WEXITSTATUS(status)`；`WIFSIGNALED(status)` → 可按 Bash 风格记录 `128 + WTERMSIG(status)`。
**环境初始化与一致性**：
- 从 `environ` 复制环境项到 `genv`，补 `NULL`；课件式实现可令 `environ = genv`，使显示表与后续 `execvp` 使用的环境一致。
- **只向 `genv` 写字符串，不等于已更新实际环境。**
- 复制指针不等于复制字符串；新增项不能引用下一轮会覆盖的输入缓冲区，必须提供独立、有效的存储。
- 检查容量、替换同名项、维护末尾 `NULL`；`putenv` 等可能调整 `environ` 指向，混用后不能假定仍为 `genv`。
**内建命令要点**：

| 命令 | 关键步骤与易错点 |
|---|---|
| `cd 目录` | 检查参数 → `chdir(gargv[1])` → 成功后 `getcwd` → 更新 `pwd`、环境 `PWD`；失败不伪造路径记录 |
| `export NAME=value` | 项目辅助函数 `AddEnv(gargv[1])` 验证名称和 `=`；同名替换，否则检查容量后新增；保存有效副本，同步实际环境 |
| `env` | 遍历实际使用的环境表至 `NULL`；若 `genv` 与 `environ` 脱节，打印结果不代表子程序环境 |
| `echo $?` | 先打印旧 `lastcode`，再记录本次 `echo` 的结果 |
| `echo $PATH` | 去掉 `$`，查询环境变量；未找到按空字符串处理，不能把空指针传给 `%s` |
| `echo 普通文字` | 输出参数，参数间补空格 |

- `<unistd.h>`：`int chdir(const char *path)`，改变调用进程真实工作目录，成功 `0`、失败 `-1`；`char *getcwd(char *buf, size_t size)`，成功返回 `buf`、失败返回 `NULL`。
- `<stdlib.h>`：`char *getenv(const char *name)`，返回环境值指针，不存在返回 `NULL`。
- **修改 `PWD` 字符串不等于改变工作目录**；`putenv(pwdenv)` 要求存储寿命足够长，并检查 `"PWD=路径"` 拼接是否截断。
- `export` 修改当前自主 shell 及其未来子程序的环境，不修改启动它的父 shell。
- `$?` 不是名为 `?` 的环境变量，匹配时优先于一般 `$变量`；内建命令成功记 `0`，失败记非零。
