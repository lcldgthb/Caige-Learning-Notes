# 3. 进程概念

## 1. 冯诺依曼体系结构

- **五大基本部件：输入设备、输出设备、存储器、运算器、控制器；CPU = 运算器 + 控制器。**
- 本节“存储器”主要指内存：保存正在使用的程序和数据；磁盘属于外部存储设备。
- 输入/输出按数据方向区分：网卡接收时是输入设备，发送时是输出设备。
- 教学数据流模型：`输入设备 → 内存 → CPU → 内存 → 输出设备`；外设间交换：`外设 A → 内存 → 外设 B`。这是简化模型，不应理解为硬件绝不存在直接 I/O 或设备间传输。
- CPU、内存、外设速度差异巨大；**整体效率不仅取决于计算速度，也取决于数据传输、拷贝效率。**寄存器访问极快；外设延迟因设备与操作而异，不能统一认定为毫秒级。

| 存储层次：由快到慢 | 特点 |
|---|---|
| 寄存器 | CPU 内部；容量极小，速度最快 |
| 高速缓存 `L1 → L2 → L3` | 通常采用 SRAM（静态随机存取存储器）；缓存近期可能复用的数据 |
| 内存 | 通常采用 DRAM（动态随机存取存储器）；存放运行中的程序与数据 |
| 磁盘 | 长期保存数据，断电后通常仍保留 |
| 网盘 | 数据位于远程服务器，访问受网络影响 |

- 一般规律：越靠上，越快、单位容量成本越高、容量越小。
- QQ 文字流：`A 键盘 → A 内存 → A 网卡 → 网络 → B 网卡 → B 内存 → B 显示器`。
- QQ 文件流：`A 磁盘 → A 内存 → A 网卡 → 网络 → B 网卡 → B 内存 → B 磁盘`。
- 两台机器各有自己的体系结构与内存；上述路径省略 CPU 对数据的处理环节。

## 2. 操作系统(Operator System)

### 2-1 概念

- 操作系统（OS，Operating System）：统一管理计算机软硬件资源、为程序提供运行环境的软件。

| 范围 | 组成 |
|---|---|
| 狭义 OS | 内核 `kernel` |
| 广义 OS | 内核 + `shell`、函数库、系统工具等配套程序 |

- `shell`：接收、解释并执行命令；`glibc`：Linux 常用 C 函数库。
- `printf` 是格式化输出库函数，写入标准输出；标准输出通常连接终端，也可重定向到文件，**不等于直接操作显示器**。

### 2-2 设计OS的目的

- 对下：管理软硬件资源，分配、调度、回收并保护资源。
- 对上：提供统一、方便、安全的程序执行环境。
- **对下管理是手段，对上提供良好执行环境是目的。**

### 2-3 核心功能

- 进程管理：创建、调度、暂停、唤醒、退出与回收。
- 内存管理：分配、回收、地址映射与访问保护。
- 文件管理：文件读写、组织、权限与磁盘空间管理。
- 设备管理：通过驱动控制硬件，协调 I/O；驱动负责设备相关操作。

### 2-4 如何理解"管理"

- 管理者不必直接接触对象；依据描述对象的数据决策；信息可由中间层采集、整理。
- **先描述，再组织：结构体描述对象，链表、队列等数据结构组织对象。**
- 进程：`task_struct` 描述身份、状态、资源等；链表、调度队列组织多个进程。
- 管理对象，落实为对描述数据及组织结构的增、删、查、改。

### 2-5 系统调用和库函数概念

- 典型访问层次：`用户程序 / shell / 库函数 → 系统调用接口 → 内核 → 驱动 → 硬件`；并非所有库函数都涉及硬件或系统调用。
- 系统调用：用户程序请求内核服务的受控入口；包含服务标识、参数、返回值；内核检查地址、权限、资源及参数合法性。

| 对比项 | 库函数 | 系统调用 |
|---|---|---|
| 所属层次 | 用户态函数库 | 内核服务接口 |
| 主要作用 | 格式化、封装、提供方便的编程接口 | 请求受保护的系统服务 |
| 是否进入内核 | 不一定 | 是 |
| 关系 | 可封装零个、一个或多个系统调用 | 可由库函数封装调用 |
| 示例 | `printf`、`getenv` | `fork`、`getpid` |

- `printf`：先格式化、可能缓冲；实际输出时通常借助系统调用。
- 不同 OS 的系统调用不同；标准库可屏蔽部分差异，提高可移植性。

## 3. 进程

### 3-1 基本概念与基本操作

- 执行视角：进程是程序的一次执行实例。
- 资源视角：进程是操作系统分配资源的基本实体。
- **本节模型：进程 = 内核管理数据结构 + 自己的代码和数据。**
- 程序是静态文件；进程包含执行状态、地址空间和资源。同一程序可对应多个进程。

#### 3-1-1 描述进程-PCB

- PCB（Process Control Block，进程控制块）：描述进程管理信息的数据结构。
- 每个进程具有自己的管理信息；PCB 属于内核，用户程序不能任意直接修改。
- 多个 PCB 通过链表、队列等组织；进程管理不只是管理程序代码。

#### 3-1-2 task_struct

- Linux 用 `task_struct` 描述任务，是本节 PCB 的具体实现。

| 信息 | 作用 |
|---|---|
| 标示符 | PID、父子关系等 |
| 状态 | 运行、睡眠、停止等 |
| 优先级 | 调度依据 |
| 程序计数器、上下文 | 保存执行位置与寄存器现场 |
| 内存信息 | 关联地址空间、代码与数据 |
| I/O 信息 | 打开的文件、等待的设备或事件 |
| 记账信息 | CPU 时间等资源使用记录 |

- 相关信息可由结构体直接保存，也可通过指针关联其他内核结构。
- Linux 链表节点 `list_head` 内含 `next`、`prev`，嵌入被管理结构体；链表操作无需理解对象的全部字段。
- `offsetof(type, member)`：返回成员相对结构体起始地址的字节偏移，定义于 `<stddef.h>`。
- **结构体首地址 = 成员地址 − 成员偏移量**；内核常借助 `container_of` 从链表成员定位所属对象。

#### 3-1-3 查看进程

| 命令/路径 | 用途 |
|---|---|
| `ps aux` | 用户格式查看进程，包含无终端进程 |
| `ps axj` | 作业格式，查看 PID、PPID、进程组等 |
| `ls -l /proc/PID/` | 查看指定进程的内核信息目录 |
| `ls -l /proc/PID/exe` | 查看运行的可执行文件链接 |
| `ls -l /proc/PID/cwd` | 查看当前工作目录链接 |

- `ps` 选项：`a` 扩展到其他用户的终端进程，`x` 纳入无终端进程，`u` 用户格式，`j` 作业格式。
- PID：进程 ID；PPID：父进程 ID。
- `/proc`：内核动态生成内容的虚拟文件系统，不是普通磁盘文件集合。

| 控制方式 | 行为 |
|---|---|
| `Ctrl+C` | 通常向终端前台进程组发送 `SIGINT`，可被捕获或忽略 |
| `kill -9 PID` | 向指定进程发送 `SIGKILL`，不能被捕获或忽略；不保证任何状态下都立即退出 |

#### 3-1-4 通过系统调用获取进程标示符

- 头文件 `<unistd.h>`；`pid_t` 为进程 ID 类型。
- `pid_t getpid(void)`：无参数，返回当前进程 PID。
- `pid_t getppid(void)`：无参数，返回当前父进程 PID。
- 手册：`man 2 getpid`、`man 2 getppid`；第 2 区为系统调用。
- 命令行启动的程序通常是当前 shell 的子进程，因此 PPID 通常等于 `bash` 等 shell 的 PID。
- 编译运行：`g++ pid.cpp -o pid`、`./pid`。

#### 3-1-5 通过系统调用创建进程-fork初识

- `<unistd.h>`：`pid_t fork(void)`；无参数，以当前进程为模板创建子进程。

| 结果 | 父进程返回值 | 子进程返回值 |
|---|---:|---:|
| 成功 | 子进程 PID，正数 | `0` |
| 失败 | `-1`，设置 `errno` | 不产生子进程 |

```c
pid_t ret = fork();             // 调用一次，成功后两个执行流继续
if (ret < 0) return 1;          // 创建失败
if (ret == 0) {                 // 子进程分支
    printf("child\n");          // 执行子进程任务
} else {
    printf("child=%ld\n", (long)ret); // 父进程获得子进程 PID
}
```

- 成功后父子均从 `fork` 返回处继续，**不会重新执行 `fork` 之前的代码**；执行先后由调度决定。
- 父子具有独立 `task_struct`、执行流和地址空间；只读代码可共享，私有数据逻辑上独立。
- 写时拷贝（COW）：初始共享物理页，写入时按需复制并调整写入方映射；子进程改全局变量，不改变父进程的值。
- 三个经典问题：
  - 返回不同值：父进程获得子 PID 以便管理；子进程用 `0` 识别自身分支。
  - “返回两次”：一次创建成功后，两个进程各自返回；并非同一进程调用两次。
  - 同名变量进入不同分支：父子各有自己的变量与返回值；相同虚拟地址不代表同一私有物理数据。
- 内核创建子进程管理结构、继承相关信息并加入调度体系；父子关系可为 `1:n`。
- `sleep` 只能延时，不能保证父子执行顺序；确定性同步需使用等待等机制。

### 3-2 进程状态

| 理论状态 | 核心含义 | 所在位置/特征 |
|---|---|---|
| 运行/可运行 | 正在用 CPU，或已准备好等待 CPU | `runqueue` |
| 阻塞 | 等待非 CPU 资源或事件 | 相应 `wait_queue`；事件完成后可被唤醒 |
| 挂起 | 教学模型中，部分代码/数据暂时换出 | 管理结构保留，数据可位于 `swap` |

- 单个逻辑 CPU 同一时刻只执行一个任务；运行队列可含多个可运行任务。
- **阻塞不是等待 CPU；换出不等于停止。**现代 Linux 按页换出，挂起不是与 `R/S/D` 一一对应的独立状态字母。
- 状态变化涉及状态字段更新、运行队列/等待队列等结构调整。

#### 3-2-1 Linux内核源代码怎么说

| 字母 | 状态 | 要点 |
|---|---|---|
| `R` | running/runnable | 正在执行或可运行，不保证此刻占用 CPU |
| `S` | interruptible sleep | 可中断睡眠；等待事件，可响应信号 |
| `D` | uninterruptible sleep | 不可中断等待，常见于 I/O；`kill -9` 通常需待等待结束后生效 |
| `T` | stopped | 信号导致停止 |
| `t` | tracing stop | 被调试器追踪并暂停 |
| `X` | dead | 死亡的短暂内部状态，通常难以观察 |
| `Z` | zombie | 已退出，退出信息尚未回收 |

#### 3-2-2 进程状态查看

- `ps aux`、`ps axj`：查看 `STAT` 列；`+` 表示属于前台进程组。
- `kill -STOP PID`：暂停；`kill -CONT PID`：继续运行。
- `dd if=/dev/zero of=bigfile bs=1M count=1024`：写入约 1 GiB 数据，可能观察到 `D`，不保证一定出现。
- `dd` 参数：`if` 输入文件，`of` 输出文件，`bs` 块大小，`count` 块数；实验注意磁盘空间与文件覆盖。

#### 3-2-3 Z(zombie)-僵尸进程

- 子进程退出，父进程尚未回收退出状态：进入 `Z`。
- 已停止执行，大部分资源已释放；仍保留退出状态、PID 和必要内核管理信息。
- 保留结果：正常退出与否、退出码、终止信号等；父进程等待并读取后，内核完成回收。
- 实验：`fork` 后子进程立即退出，父进程延时且不等待；用 `ps axj | grep Z` 辅助观察，注意筛选可能误匹配。
- `kill -9` 不能替代回收：僵尸已经退出。

#### 3-2-4 僵尸进程危害

- 长期不回收会持续占用 PID、进程表项及内核资源。
- 大量积累可能耗尽资源，妨碍新进程创建；不占用 CPU 执行时间，不保留完整用户地址空间。
- 根本处理：父进程正确等待、回收子进程。

#### 3-2-5 孤儿进程

| 对比项 | 僵尸进程 | 孤儿进程 |
|---|---|---|
| 子进程状态 | 已退出 | 通常仍运行 |
| 原父进程 | 尚未回收子进程 | 已退出 |
| 核心问题 | 退出信息未回收 | 需要重新确定父子关系 |
| 处理 | 父进程等待回收 | 被收养，退出后由新父进程回收 |

- 孤儿进程通常由 `init/systemd`（PID 1）或适用的子收割器接管；并非所有情况都直接交给系统 PID 1。
- **孤儿不等于僵尸；原父进程退出，不意味着子进程必须同时退出。**

### 3-3 进程优先级

#### 3-3-1 基本概念

- 多进程竞争有限 CPU；优先级影响调度机会或 CPU 份额。
- 本节数值约定：优先级数值越小，优先级越高；不等于严格保证先运行。

#### 3-3-2 查看系统进程

- `ps aux`、`ps axj`：静态快照，查看进程身份、状态和父子关系。
- `top`：动态监控；观察 CPU、内存、状态及优先级相关列。

#### 3-3-3 PRI and NI

- `PRI`：工具显示的调度优先级。
- `NI` / `nice`：普通任务的优先级修正值，范围 `[-20, 19]`，共 40 级，默认 `0`。
- nice 越小，通常获得的 CPU 份额越大；nice 越大，越谦让。

#### 3-3-4 PRI vs NI

| 项目 | `PRI` | `NI` |
|---|---|---|
| 含义 | 优先级表示 | nice 修正值 |
| 来源 | 调度策略与工具显示口径 | 用户或程序设置 |
| 调整关系 | 随调度参数变化 | 常用调整入口 |
| 数值比较 | 同一口径下通常越小越优先 | 越小越优先 |

- 课件简化式：`PRI(new) = PRI(old) + nice`；应按固定基准理解，**不是每次调整都在上次结果上累加**。
- 某些 `ps` 显示口径：普通进程基准 `80`，可近似记为 `PRI = 80 + NI`；如 `NI=5` 时为 `85`。
- `top`、`ps`、内核内部优先级编码可能不同，不可混用。

#### 3-3-5 查看进程优先级的命令

- `ps -l`：查看 `PRI`、`NI` 等字段。
- `top` → 按 `r` → 输入 PID → 输入新 nice 值。
- `nice -n 10 ./program`：启动程序时调整 nice。
- `renice 10 -p 1234`：把 PID 1234 的 nice 设置为 `10`。
- 降低 nice、提高优先级通常需要相应权限。
- `<sys/resource.h>`：
  - `int getpriority(int which, id_t who)`：返回选定对象的 nice；失败返回 `-1` 并设置 `errno`。合法 nice 也可能为 `-1`，调用前应清零 `errno` 后检查。
  - `int setpriority(int which, id_t who, int prio)`：设置 nice；成功 `0`，失败 `-1` 并设置 `errno`。
  - `which`：`PRIO_PROCESS`、`PRIO_PGRP`、`PRIO_USER`；`who`：相应 ID，`0` 表示当前对象；`prio`：目标 nice。

#### 3-3-6 补充概念-竞争、独立、并行、并发

| 概念 | 核心 |
|---|---|
| 竞争性 | 多个进程争夺有限资源 |
| 独立性 | 各有管理信息和地址空间；私有数据修改互不影响 |
| 并行 | 多个执行流在同一时刻真正执行，需要多个执行单元 |
| 并发 | 多个任务在同一时间段内推进；单 CPU 可通过交替执行实现 |

### 3-4 进程切换

- 分时模型：CPU 时间划分为时间片；耗尽、阻塞或发生抢占时可切换任务。
- 上下文：程序计数器、通用寄存器、栈指针、状态寄存器等执行现场。
- **切换核心：保存旧任务现场，恢复新任务现场，从暂停位置继续执行。**
- 流程：`A 运行 → 保存 A 上下文 → 选择 B → 恢复 B 上下文 → B 继续运行`。
- 每个逻辑 CPU 有自己的寄存器现场；每个任务有独立的保存区域，位于相关内核结构、内核栈等。
- 课件用“上下文保存到 `task_struct`”概括；实际进程切换还可能涉及地址空间等，不仅是复制寄存器。
- 内核完成切换；切换本身有开销。

### 3-5 Linux2.6内核进程O(1)调度队列

- 以下为早期 Linux 2.6 的经典 `O(1)` 调度器模型，不代表所有 Linux 2.6 版本或现代内核调度实现。

#### 3-5-1 一个CPU拥有一个runqueue

- 每个 CPU 对应一个 `runqueue`，维护本 CPU 的可运行任务。
- 多 CPU 通过任务迁移、负载均衡避免部分 CPU 过忙、部分过闲。

#### 3-5-2 优先级

| 内部优先级范围 | 类型 |
|---|---|
| `[0, 99]` | 实时任务 |
| `[100, 139]` | 普通任务 |

- 普通任务静态优先级：`120 + nice`；`nice=-20 → 100`，`nice=0 → 120`，`nice=19 → 139`。
- `queue[140]`：数组下标对应优先级，同优先级任务按队列顺序选取。
- 非空位图：对应队列非空置 `1`，为空置 `0`。
- 32 位字模型下 `bitmap[5]` 提供 `160` 位，足够覆盖 `140` 个优先级；具体数组长度依实现与字长而定。

#### 3-5-3 活动队列

- `active`：当前一轮仍可参与调度的优先级数组。
- 根据位图定位最高优先级非空队列，再取队首任务；同优先级基本按 FIFO/轮转推进。

#### 3-5-4 过期队列

- `expired`：保存本轮时间片耗尽、等待后续轮次的任务。
- 简化流程：任务耗尽时间片后，重新计算相关调度参数并移入 `expired`。

#### 3-5-5 active指针和expired指针

| 时机 | 操作 |
|---|---|
| `active` 非空 | 从活动数组选取任务 |
| `active` 为空 | 交换 `active` 与 `expired` 指针 |
| 交换后 | 原过期数组成为活动数组，原空活动数组成为过期数组 |

- **交换的是两个数组的指针，不是逐个复制、移动全部任务。**

#### 3-5-6 总结

- 调度主线：`位图定位 → 优先级队列 → 队首任务 → 时间片耗尽移入 expired → active 空时交换指针`。
- 核心结构：优先级数组 + 非空位图 + 双数组指针轮换。
- `O(1)`：选取下一任务的工作量不随可运行进程总数线性增长；不表示调度系统所有操作都是常数时间。

## 4. 命令行参数和环境变量

### 4-1 基本概念

| 信息来源 | 形式 | 作用 |
|---|---|---|
| 命令行参数 | `argc`、`argv` | 指定本次运行的选项与输入 |
| 环境变量 | `NAME=value` | 提供命令搜索路径、用户目录等运行环境 |

- `int main(int argc, char *argv[])`：
  - `argc`：参数数量，包含 `argv[0]`。
  - `argv[0]`：通常为程序调用名；后续元素为用户参数。
  - `argv[argc] == NULL`；每个参数都是以 `'\0'` 结束的字符串。
- `ls -a -l`：`argc=3`，参数依次为 `"ls"`、`"-a"`、`"-l"`。
- 同一程序根据参数执行不同功能；可用 `strcmp(argv[i], "-a") == 0` 判断选项。
- bash 为启动的程序构造参数与环境；不是所有程序共享 bash 内同一张表。

### 4-2 常见环境变量

| 变量 | 含义 |
|---|---|
| `PATH` | 命令搜索目录列表，用 `:` 分隔 |
| `HOME` | 用户主目录 |
| `SHELL` | 通常为用户配置的登录 shell，不保证等于当前解释器 |
| `USER` | 环境中的用户名，不是可信认证凭据 |

- 无 `/` 的外部命令名通常按 `PATH` 顺序搜索；`./program`、`/usr/bin/ls` 明确指定路径。
- `export PATH="$PATH:$HOME/bin"`：保留原路径并追加目录。
- `export PATH="$HOME/bin"`：覆盖原内容，可能使常用命令无法按名称找到。

### 4-3 查看环境变量方法

- `echo "$PATH"`、`echo "$HOME"`、`echo "$SHELL"`：查看单个变量；`$` 表示展开变量值。
- `env`：查看当前环境；`env | grep '^PATH='`：筛选 `PATH`。
- `set`：查看当前 bash 的变量等信息，包含本地变量与环境变量，通常还含函数。

### 4-4 和环境变量相关的命令

| 命令 | 含义 |
|---|---|
| `NAME=value` | 设置 shell 变量；新变量默认未导出 |
| `export NAME=value` | 设置变量并标记导出，供后续启动程序继承 |
| `export NAME` | 导出已存在的变量 |
| `unset NAME` | 删除当前 shell 中的变量 |
| `echo "$NAME"` | 显示变量值 |
| `env` | 显示环境变量 |
| `set` | 显示 shell 变量等信息 |
| `type export`、`type ls` | 查看命令是内建、别名还是外部程序 |

- 含空格的值使用引号：`export MESSAGE="hello linux"`。
- 配置文件：`~/.bash_profile` 常用于登录 shell；`~/.bashrc` 常用于交互式非登录 bash，具体读取方式取决于启动模式。
- 当前 shell 中修改只影响本进程及以后启动的后代；持久配置需写入适当启动文件。

### 4-5 环境变量的组织方式

- 环境表：`char **` / 字符指针数组；每个元素指向 `"NAME=value"` 字符串。
- 每个字符串以 `'\0'` 结束；整个指针数组以 `NULL` 结束。
- **字符串结束符 `'\0'` 与表结束标志 `NULL` 不同。**
- 运行库通过 `environ` 指向当前进程环境表；修改环境后表的存储位置可能改变。

### 4-6 通过代码如何获取环境变量

| 方式 | 接口 | 获取内容 |
|---|---|---|
| `main` 第三个参数 | `int main(int argc, char *argv[], char *envp[])` | 启动时环境表；常见扩展，非 ISO C 标准形式 |
| 全局环境指针 | `extern char **environ` | 当前进程环境表 |
| 按名称查询 | `char *getenv(const char *name)` | 指定变量的值 |

- `getenv` 定义于 `<stdlib.h>`；`name` 不含 `=`；存在则返回值字符串指针，不存在返回 `NULL`。
- 返回的是环境内部存储，不应直接修改或 `free`；后续环境修改可能使指针失效。
- 全表遍历：`for (int i = 0; envp[i] != NULL; ++i)`；当前位置也可使用 `environ[i]`。

```c
#include <stdlib.h>             // getenv 声明
#include <stdio.h>              // printf 声明
char *value = getenv("HOME");   // 只读取 HOME 的值
if (value != NULL)              // 不存在时不能当字符串使用
    printf("%s\n", value);      // 输出用户主目录
```

### 4-7 通过系统调用获取或设置环境变量

- **环境变量访问通常由用户态库函数完成；`getenv` 等不是直接的系统调用。**
- `<stdlib.h>` 中常用接口：

| 接口 | 参数与功能 | 返回值 |
|---|---|---|
| `char *getenv(const char *name)` | 查询变量名 `name` | 值指针；不存在为 `NULL` |
| `int setenv(const char *name, const char *value, int overwrite)` | 设置变量；`overwrite=0` 保留已有值，非零允许覆盖 | 成功 `0`；失败 `-1` 并设置 `errno` |
| `int unsetenv(const char *name)` | 删除变量；名称不能空或包含 `=` | 成功 `0`；失败 `-1` 并设置 `errno` |

- 这些操作只修改调用进程的环境，不修改父进程或已运行的其他进程。

### 4-8 环境变量通常是具有全局属性的

- “全局”指可沿父子进程关系继承，**不是全系统共享、实时同步的一份数据**。
- shell 导出的变量可传给后续启动的程序；子进程修改自己的环境，不反向改变父进程。
- 未导出的 shell 本地变量不会进入新执行程序的环境；已导出的变量重新赋值，通常仍保持导出属性。
- `export` 是 bash 内建命令，直接修改当前 bash 的变量及导出状态。

### 4-9 实验

```bash
unset MYENV                    # 清除旧值及导出状态
MYENV=hello                    # 新建未导出的本地变量
env | grep '^MYENV='           # 无输出
export MYENV                  # 标记导出
env | grep '^MYENV='           # 输出 MYENV=hello
bash -c 'export MYENV=child'   # 子 shell 只修改自身环境
echo "$MYENV"                 # 父 shell 仍为 hello
```

- C 程序用 `getenv("MYENV")` 验证：导出前通常为 `NULL`，导出后为 `"hello"`。
- 身份实验：`getenv("USER")` 可以影响程序分支，但 `export USER=alice` 可伪造值。
- **真正权限控制依靠内核维护的用户身份与权限，不依靠环境中的用户名。**

## 5. 程序地址空间

### 5-1 研究平台

- 典型 32 位 Linux 模型：字节寻址范围 `2^32 = 4 GiB`。
- 常见划分：低地址 `3 GiB` 用户空间，高地址 `1 GiB` 内核空间；具体划分依平台与配置。
- 64 位理论地址范围为 `2^64` 字节；实际 CPU、OS 通常只实现其中一部分。
- **地址空间容量不等于实际物理内存大小，也不表示已分配等量物理内存。**

### 5-2 程序地址空间回顾

| 典型低地址 → 高地址布局 | 内容 |
|---|---|
| 代码段 | 机器指令，通常可执行、不可写 |
| 已初始化数据段 | 非零初始化的全局、静态变量等 |
| BSS | 未显式初始化或零初始化的全局、静态变量，启动时清零 |
| 堆 | `malloc`、`new` 等动态分配；传统堆通常向高地址扩展 |
| 映射/共享区 | 动态库、文件映射、匿名映射等 |
| 栈 | 调用帧、部分参数与局部变量，通常向低地址增长 |
| 初始参数与环境 | 参数、环境字符串及相关启动数据，通常位于初始栈 |
| 内核空间 | 内核使用，用户态不可任意访问 |

- 布局受 ABI、编译器、分配器、地址随机化影响；不是语言标准保证。
- 相邻 `malloc` 返回值不保证连续或递增；同一栈帧内局部变量顺序不能证明栈增长方向。
- 地址验证：用 `printf("%p", (void *)&obj)` 输出对象地址，对比全局变量、BSS、堆对象、栈对象及 `argv/envp`。
- 编译运行：`g++ -o layout layout.cpp`、`./layout hello`；动态分配后记得释放。
- **这些程序可见指针是虚拟地址，不是内存条上的物理地址。**

### 5-3 虚拟地址

| 概念 | 含义 |
|---|---|
| 虚拟地址 | 进程使用的地址，属于进程地址空间 |
| 物理地址 | 实际物理存储位置 |
| 页表 | 描述虚拟页到物理页的映射及访问属性 |

- 地址转换：`虚拟地址 → MMU/页表映射 → 物理地址`；内核维护映射与权限。
- 普通独立进程各有地址空间和页表；同一虚拟地址在不同进程中可映射不同物理页。
- `fork` 实验：全局变量初值 `0`；子进程改为 `100`；父子打印 `&g_val` 相同，但分别读到 `0`、`100`。
- 写时拷贝：父子初始共享私有映射的物理页；写入触发保护异常，内核按需复制、更新写入方页表，随后完成写入。
- **相同虚拟地址 ≠ 相同物理地址；数据独立 ≠ 创建时立即复制所有物理内存。**
- 实验同步可用 `<sys/wait.h>` 中 `pid_t waitpid(pid_t pid, int *status, int options)`：
  - `pid>0` 等待指定子进程；`status` 接收编码状态，`NULL` 表示不接收；`options=0` 阻塞等待。
  - 成功返回子进程 PID，失败返回 `-1`；非阻塞 `WNOHANG` 下无可报告状态返回 `0`。
  - `waitpid(pid, NULL, 0)`：父进程等待子进程退出并回收，再观察自己的变量。

### 5-4 进程地址空间

- 虚拟地址空间是地址范围、权限与映射的抽象描述，不是一块预先全部分配好的物理内存。
- `task_struct → mm → mm_struct`：任务通过指针关联地址空间管理结构。
- 边界字段：`start_code/end_code` 描述代码范围；`start_brk/brk` 描述传统堆边界；`start_stack` 记录初始栈位置。
- 区域扩展可先调整范围和映射描述，不要求立即搬运整块数据或分配全部物理页。
- 普通进程模型：一个 `task_struct`、一个地址空间及对应页表；同进程线程可共享 `mm_struct`，内核线程存在例外。
- 进程独立性：管理结构独立；私有地址空间与映射隔离。显式共享内存不适用“修改互不影响”。

### 5-5 虚拟内存管理 - 第一讲

| 结构 | 职责 |
|---|---|
| `mm_struct` | 描述整个用户地址空间、边界及区域管理信息 |
| VMA / `vm_area_struct` | 描述一段连续虚拟区域，记录范围、权限、映射属性等 |
| 页表 | 描述页级地址映射与访问属性 |

- VMA 不一定与“代码、数据、堆、栈”一一对应；一个逻辑区域可有多个映射。

| 课件所用较早 Linux VMA 组织 | 用途 |
|---|---|
| `mmap` 关联的链表 | 按地址顺序遍历 |
| `mm_rb` 红黑树 | 快速按地址查找，通常为 `O(log n)` |

- 旧实现中链表与红黑树同时维护，不是按 VMA 数量二选一；现代内核实现已变化。
- 初始化：加载器读取可执行文件的装载信息，建立相应区域、权限与映射描述，并准备栈等区域。
- 创建管理结构、描述虚拟区域，不要求程序全部驻留物理内存。
- 按需分页：首次访问尚未驻留、但合法的页面时触发缺页异常；内核分配或调入物理页、建立映射后继续执行。

### 5-6 为什么要有虚拟地址空间

| 直接耦合物理内存的问题 | 虚拟地址空间的收益 |
|---|---|
| 程序可能破坏其他进程或内核 | 地址隔离、页级权限与合法性检查 |
| 加载位置不确定，程序依赖物理布局 | 虚拟布局与物理位置分离 |
| 连续物理分配、整体搬运不灵活 | 非连续物理页映射；按页分配、换入换出与回收 |

- **虚拟上连续，不要求物理上连续；物理布局变化不必改变程序所用虚拟地址。**
- 写只读页、访问无有效映射的地址等可能触发异常并终止进程；并非所有野指针错误都能被发现。
- `malloc/new` 返回可用虚拟地址，但物理页可能已存在，也可能首次访问时才分配；不是每次调用都立即申请新物理页。
- **进程管理与物理内存管理解耦：进程使用虚拟地址，内核管理映射、保护、共享及实际物理占用。**
