# 1. 软件包管理器聊天版

## 1-1 什么是软件包

先想一个问题：在 Linux 上想用一个软件，怎么装？

最原始的办法是**源码安装**：下载程序的源代码，自己编译，得到可执行程序。这条路最大的问题是麻烦——每个软件都要自己配环境、自己编译，对新手极不友好。

于是有人换了个思路：**把常用软件提前编译好，打包放在服务器上**，你想要的时候直接下载这个"成品"安装即可。这个"成品"就是**软件包**，可以理解成 Windows 上的安装程序。

管理这些软件包的工具，就叫**包管理器**：

> **软件包和包管理器的关系，就好比"App"和"应用商店"。**

不同发行版用不同的包管理器：

| 发行版 | 包管理器 |
|---|---|
| CentOS / RedHat / Fedora | `yum` |
| Ubuntu | `apt` |

包管理器真正的价值不只是"帮你下载"，而是**自动解决依赖问题**。一个软件往往依赖其他一堆软件（A 依赖 B，B 依赖 C……），手动安装你得自己把依赖链找齐，还可能碰上版本不兼容。包管理器会把这条链自动算好、一次装全——这就是它存在的意义。

关于"安装"还有三个直觉要建立：

1. **安装的本质 = 网络下载 + 拷贝**（把软件文件拷到系统目录里）。
2. 因为写的是系统目录，所以**必须用 root 权限**（`sudo`）。
3. 软件装进系统后**只需装一次，所有用户都能用**。

## 1-2 Linux软件生态

接着追问一句：这些软件包是谁做好、放在服务器上给你下载的？

链条是这样的：

```text
开发者发布源码
   ↓
社区把源码编译、打包成软件包
   ↓
放到官方源服务器（centos.org / ubuntu.org）
   ↓
你的机器通过 yum/apt 下载
```

为什么有人愿意免费做这些还维护服务器？因为**开源的本质是一种商业模式**——生态越繁荣，使用的人越多，围绕它的商业价值越大。这也回答了"如何评估一款操作系统的好坏"：不只看内核本身，更要看**生态**——社区活跃度、文档、用户群、配套软件是否丰富。配套软件本身就是生态的一环。

最后一个实际问题是：你的机器怎么知道去哪下载？答案是 yum/apt **内置了下载链接**，默认指向官方源。所谓**切换镜像源**，本质就是把这个内置链接改成国内镜像站（阿里云、清华、中科大等），下载更快。

> **换源 = 更改包管理器的下载链接，没有其他魔法。**

## 1-3 yum具体操作

yum 的日常使用就三条命令（老师板书的"三板斧"）：

```bash
yum list | grep lrzsz        # 查：列出软件包，配合 grep 筛选
sudo yum install -y lrzsz    # 装：-y 表示全程自动确认
sudo yum remove -y lrzsz     # 卸
```

Ubuntu 下把 `yum` 换成 `apt`，查看用 `apt search 包名` / `apt show 包名`，安装卸载同样是 `sudo apt install/remove`。

几点必须注意的：

- 包名有讲究：`lrzsz.x86_64 0.12.20-36.el7 @base` 里，`x86_64` 表示 64 位系统包（`i686` 是 32 位），`el7` 表示适配 CentOS7/RedHat7，最后的 `base` 是软件源的名字——相当于标明这个包来自哪个"应用商店"。
- **yum/apt 同一时刻只能安装一个软件**。一个还没装完就开第二个，会直接报错。
- 安装报错不要慌，错误信息复制去搜索，基本都有人踩过。
- 刚入门时"不知道自己会装哪些软件"很正常——软件是**由需求驱动**的，用到什么装什么。

还有一个大前提：**yum/apt 的所有操作都必须网络畅通**，可以用 `ping www.baidu.com` 先验证。

## 1-4 安装源

"源"的配置文件就放在系统里，看一眼就知道自己的包从哪来：

```bash
# CentOS
ll /etc/yum.repos.d/
# CentOS-Base.repo   ← 标准源（base，稳定软件）
# epel.repo          ← 扩展源（epel，官方源之外的补充软件）

# Ubuntu
cat /etc/apt/sources.list      # 标准源
ll /etc/apt/sources.list.d/    # 扩展源
```

标准源（base）收录的是发行版官方维护的稳定软件；**epel** 是社区维护的扩展源，软件更全。安装扩展源只需：

```bash
sudo yum install -y epel-release
```

> **标准源求稳，扩展源求全——先装 base 里的，找不到再考虑 epel。**

如果你用的是云服务器，软件源一般已经是国内镜像，不需要再折腾换源。
