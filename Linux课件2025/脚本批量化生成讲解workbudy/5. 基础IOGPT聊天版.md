# 5. 基础 IO：文件、文件描述符与重定向

程序运行时经常需要保存数据。例如，`printf` 把内容显示到屏幕，日志程序把内容保存到文件，配置程序从文件读取参数。它们看起来用途不同，但本质都是：程序和外部设备之间传输数据。

本节先从 C 文件操作出发，再逐步过渡到 Linux 内核提供的文件接口。

---

## 1. 复习 C 文件 IO 相关操作

### 1.1 为什么需要文件 IO

程序中的变量保存在内存里，程序结束后通常就消失了。如果希望数据在程序结束后仍然存在，就需要把数据写入文件。

C 语言用 `FILE *` 表示一个已经打开的文件。`FILE` 可以理解为 C 标准库为文件准备的“操作管理对象”，里面记录了文件位置、缓冲区等信息。

常见操作如下：

| 操作 | 函数 |
|---|---|
| 打开文件 | `fopen` |
| 关闭文件 | `fclose` |
| 读取字符 | `fgetc` |
| 写入字符 | `fputc` |
| 读取字符串 | `fgets` |
| 写入字符串 | `fputs` |
| 读取二进制数据 | `fread` |
| 写入二进制数据 | `fwrite` |
| 格式化写入 | `fprintf` |
| 格式化读取 | `fscanf` |

### 1.2 `fopen`：打开文件

#### 语法

```cpp
FILE *fopen(const char *path, const char *mode);
```

#### 功能

`fopen` 根据路径和打开方式打开文件，成功时返回 `FILE *`，失败时返回 `NULL`。

常见打开方式：

| 模式 | 含义 |
|---|---|
| `"r"` | 只读，文件必须存在 |
| `"w"` | 只写，不存在则创建，存在则清空 |
| `"a"` | 追加写入，不存在则创建 |
| `"r+"` | 读写，文件必须存在 |
| `"w+"` | 读写，不存在则创建，存在则清空 |
| `"a+"` | 读写，写入位置在文件末尾 |

#### 示例

```cpp
#include <stdio.h>

int main()
{
    FILE *fp = fopen("log.txt", "w");  // 以写方式打开文件
    if (fp == NULL) {                  // 判断打开是否失败
        perror("fopen");               // 输出失败原因
        return 1;                      // 返回非零表示失败
    }

    fprintf(fp, "hello file\n");       // 向文件写入格式化文本
    fclose(fp);                        // 关闭文件并刷新 C 库缓冲区
    return 0;                          // 程序正常结束
}
```

注意：`"w"` 会清空原文件。如果只想在末尾增加内容，应使用 `"a"`。

### 1.3 读取和写入

```cpp
#include <stdio.h>

int main()
{
    FILE *fp = fopen("log.txt", "r");  // 以只读方式打开文件
    if (fp == NULL) {                  // 判断文件是否打开成功
        perror("fopen");               // 输出错误原因
        return 1;                      // 返回失败
    }

    char buffer[128];                  // 准备存放读取结果的数组
    while (fgets(buffer, sizeof(buffer), fp) != NULL) { // 每次读取一行
        fputs(buffer, stdout);         // 把这一行写到标准输出
    }

    fclose(fp);                        // 关闭文件
    return 0;                          // 正常结束
}
```

`fgets` 读取到文件末尾或发生错误时会返回 `NULL`，因此可以用它作为循环条件。

> **C 文件 IO 用 `FILE *` 管理文件，并通过库函数完成打开、读取、写入和关闭。**

## 2. 认识文件相关系统调用接口

### 2.1 为什么需要系统调用

刚才的 `fopen`、`fgets` 等函数来自 C 标准库。可是，真正管理磁盘、键盘和显示器的是操作系统内核，普通程序不能直接操作内核中的设备。

因此，程序需要通过**系统调用**：用户程序请求操作系统内核执行某项工作的接口，进入内核完成文件操作。

Linux 中常见的文件系统调用有：

| 系统调用 | 作用 |
|---|---|
| `open` | 打开或创建文件 |
| `close` | 关闭文件 |
| `read` | 读取数据 |
| `write` | 写入数据 |
| `lseek` | 移动文件读写位置 |
| `dup2` | 复制文件描述符，常用于重定向 |

### 2.2 `open`：打开文件

#### 语法

```cpp
int open(const char *path, int flags, ...);
```

#### 功能

`open` 打开文件并返回一个整数，这个整数叫**文件描述符**，简称 `fd`：进程用来代表一个打开文件的编号。

常用选项：

| 选项 | 含义 |
|---|---|
| `O_RDONLY` | 只读 |
| `O_WRONLY` | 只写 |
| `O_RDWR` | 读写 |
| `O_CREAT` | 文件不存在时创建 |
| `O_TRUNC` | 打开时清空文件 |
| `O_APPEND` | 每次写入都追加到文件末尾 |

使用 `O_CREAT` 时，还要传入新文件权限。

#### 示例

```cpp
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main()
{
    int fd = open("syscall.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644); // 打开或创建文件
    if (fd == -1) {                                                   // 判断打开是否失败
        perror("open");                                               // 输出错误原因
        return 1;                                                     // 返回失败
    }

    const char *msg = "hello syscall\n";                              // 准备写入的数据
    write(fd, msg, 14);                                               // 通过系统调用写入文件
    close(fd);                                                        // 关闭文件描述符
    return 0;                                                         // 正常结束
}
```

`0644` 是文件权限表示法，具体权限含义已经在前面的权限内容中学习过。

### 2.3 `read` 和 `write`

#### 语法

```cpp
ssize_t read(int fd, void *buf, size_t count);
ssize_t write(int fd, const void *buf, size_t count);
```

#### 功能

- `read` 从 `fd` 对应的对象读取最多 `count` 个字节到 `buf`。
- `write` 从 `buf` 取出最多 `count` 个字节，写入 `fd` 对应的对象。
- 返回值表示实际读取或写入的字节数。
- 返回 `0` 通常表示读取到了文件末尾。
- 返回 `-1` 表示出错。

#### 示例

```cpp
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main()
{
    int fd = open("syscall.txt", O_RDONLY); // 以只读方式打开文件
    if (fd == -1) {                         // 判断打开是否失败
        perror("open");                     // 输出错误原因
        return 1;                           // 返回失败
    }

    char buffer[128];                       // 准备接收文件内容的数组
    ssize_t n = read(fd, buffer, sizeof(buffer) - 1); // 读取最多127个字节
    if (n == -1) {                          // 判断读取是否失败
        perror("read");                     // 输出错误原因
        close(fd);                          // 关闭文件
        return 1;                           // 返回失败
    }

    buffer[n] = '\0';                       // 把读取结果补成 C 字符串
    printf("%s", buffer);                   // 输出读取到的内容
    close(fd);                              // 关闭文件描述符
    return 0;                               // 正常结束
}
```

注意：`read` 不会自动在数据末尾添加 `'\0'`。如果把读取结果当作 C 字符串使用，需要手动补上，并确保数组空间足够。

## 3. 认识文件描述符，理解重定向

### 3.1 文件描述符解决了什么问题

一个进程可能同时打开多个文件、键盘、显示器和管道。内核需要为这些对象分别编号，进程只要拿着编号，就能告诉内核“我要操作哪个对象”。

这个编号就是文件描述符 `fd`。

进程启动时通常已经打开了三个标准文件描述符：

| fd | 名称 | 默认对象 |
|---:|---|---|
| `0` | 标准输入 `stdin` | 键盘 |
| `1` | 标准输出 `stdout` | 屏幕 |
| `2` | 标准错误 `stderr` | 屏幕 |

它们本质上都是文件描述符，只是默认连接到了不同对象。

```text
fd 0 ── 标准输入 ── 键盘
fd 1 ── 标准输出 ── 屏幕
fd 2 ── 标准错误 ── 屏幕
```

### 3.2 重定向解决了什么问题

程序通常把输出写到 `fd 1`，也就是标准输出。如果每个程序都必须自己学习“如何写文件”，使用起来会很麻烦。

Shell 的重定向把 `fd 1` 换成文件：

```bash
./a.out > result.txt  # 把程序标准输出写入 result.txt
```

程序本身仍然执行 `write(1, ...)` 或 `printf`，但 `fd 1` 已经不再指向屏幕，而是指向 `result.txt`。

因此：

> **重定向不是修改程序的输出代码，而是修改文件描述符和目标对象之间的连接关系。**

### 3.3 `dup2`：修改文件描述符连接

#### 语法

```cpp
int dup2(int oldfd, int newfd);
```

#### 功能

`dup2` 让 `newfd` 和 `oldfd` 指向同一个打开的文件对象。

例如：

```cpp
dup2(fd, 1);
```

表示让标准输出 `fd 1` 改为指向 `fd` 对应的文件。

#### 示例：把标准输出重定向到文件

```cpp
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main()
{
    int fd = open("redirect.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644); // 打开输出文件
    if (fd == -1) {                                                    // 判断打开是否失败
        perror("open");                                                // 输出错误原因
        return 1;                                                      // 返回失败
    }

    if (dup2(fd, STDOUT_FILENO) == -1) {                               // 让标准输出指向该文件
        perror("dup2");                                                // 输出错误原因
        close(fd);                                                     // 关闭文件
        return 1;                                                      // 返回失败
    }

    close(fd);                                                         // 关闭多余的文件描述符
    printf("this goes to file\n");                                     // 内容会进入 redirect.txt
    return 0;                                                          // 正常结束
}
```

`STDOUT_FILENO` 就是标准输出对应的 `1`。

注意：重定向必须发生在目标程序执行前。如果子进程先完成重定向，再调用 `exec`，新程序会继承修改后的 `fd 0`、`fd 1` 和 `fd 2`。

## 4. 对比 `fd` 和 `FILE`：系统调用和库函数的关系

### 4.1 `fd` 和 `FILE` 的区别

| 对比项 | `fd` | `FILE *` |
|---|---|---|
| 本质 | 一个整数编号 | C 标准库中的结构对象 |
| 所属层次 | Linux 系统调用层 | C 库函数层 |
| 常用接口 | `open`、`read`、`write`、`close` | `fopen`、`fread`、`fprintf`、`fclose` |
| 是否有格式化功能 | 没有 | 有，如 `fprintf` |
| 是否自带用户空间缓冲区 | 通常没有 | 有 |
| 能否直接用于 `dup2` | 可以 | 不可以，需要先取得 fd |

`FILE *` 内部通常会保存一个文件描述符，因此它不是另一种文件，而是对文件描述符的更高层封装。

### 4.2 `fileno` 和 `fdopen`

#### `fileno`：从 `FILE *` 得到 fd

```cpp
int fileno(FILE *stream);
```

```cpp
#include <stdio.h>
#include <unistd.h>

int main()
{
    FILE *fp = fopen("data.txt", "w"); // 用 C 库打开文件
    if (fp == NULL) {                  // 判断打开是否失败
        perror("fopen");               // 输出错误原因
        return 1;                      // 返回失败
    }

    int fd = fileno(fp);               // 取得 FILE 内部对应的文件描述符
    write(fd, "hello\n", 6);           // 用系统调用写入同一个文件
    fclose(fp);                        // 关闭 FILE
    return 0;                          // 正常结束
}
```

#### `fdopen`：从 fd 得到 `FILE *`

```cpp
FILE *fdopen(int fd, const char *mode);
```

它把已有的文件描述符包装成 `FILE *`，这样就可以使用 `fprintf`、`fgets` 等 C 库函数。

### 4.3 为什么混用时容易出问题

`FILE *` 可能已经把数据放在 C 库的用户空间缓冲区中，而 `write` 绕过了这个缓冲区直接进行系统调用。两者混用时，数据先后顺序可能和代码顺序不一致。

例如，使用 `fprintf` 后又使用 `write`，应先调用：

```cpp
fflush(fp);  // 把 FILE 的用户空间缓冲区立即交给内核
```

> **系统调用是程序进入内核的直接接口；库函数通常在系统调用之上提供缓冲、格式化和更方便的操作。**

## 5. 理解文件和内核文件缓冲区

### 5.1 为什么写入后不一定立即落盘

程序写文件时，数据不一定立刻写入磁盘。直接访问磁盘速度较慢，如果每次写一个字符都等待磁盘，程序会非常低效。

因此，Linux 通常先把数据放入内核中的**文件缓冲区**：内核暂时保存文件数据的内存区域，之后再批量写入磁盘。

数据可能经过这样的路径：

```text
程序缓冲区
    ↓ write / fflush
内核文件缓冲区
    ↓ 内核异步写回
磁盘
```

这里有两层常见缓冲：

| 缓冲位置 | 由谁管理 | 典型触发方式 |
|---|---|---|
| 用户空间缓冲区 | C 库中的 `FILE` | `fflush`、`fclose` |
| 内核文件缓冲区 | Linux 内核 | 内核自动写回、`fsync` |

### 5.2 `fflush` 和 `fsync` 的区别

- `fflush`：把 C 库的用户空间缓冲区交给内核。
- `fsync`：请求内核把对应文件的数据进一步写入存储设备。

```cpp
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>

int main()
{
    FILE *fp = fopen("important.txt", "w"); // 打开文件
    if (fp == NULL) {                       // 判断打开是否失败
        return 1;                           // 返回失败
    }

    fprintf(fp, "important data\n");        // 数据先进入 FILE 的缓冲区
    fflush(fp);                             // 把 C 库缓冲区刷新到内核
    fsync(fileno(fp));                      // 请求内核把数据同步到存储设备
    fclose(fp);                             // 关闭文件
    return 0;                               // 正常结束
}
```

普通程序通常不需要每次写入都调用 `fsync`，因为频繁同步会降低性能。只有日志、数据库等特别关注突然断电后数据是否保留的场景，才会谨慎使用。

> **`fflush` 主要处理 C 库缓冲区，`fsync` 主要要求内核把文件数据同步到存储设备。**

## 6. 自定义 Shell，新增重定向功能

### 6.1 Shell 需要增加什么逻辑

已有 Shell 的基本流程是：

```text
读取命令
  ↓
解析参数
  ↓
创建子进程
  ↓
子进程执行程序
  ↓
父进程等待
```

加入重定向后，子进程执行程序前需要多一步：

```text
读取命令
  ↓
解析普通参数和重定向符号
  ↓
子进程打开目标文件
  ↓
dup2 修改标准输入或标准输出
  ↓
exec 执行程序
```

例如命令：

```bash
cat < input.txt > output.txt  # 从 input.txt 读取，并把输出写入 output.txt
```

解析后：

- `< input.txt`：打开 `input.txt`，复制到标准输入 `fd 0`。
- `> output.txt`：打开 `output.txt`，复制到标准输出 `fd 1`。
- `cat`：真正传给 `exec` 的参数中不应再包含 `<`、`>` 和文件名。

### 6.2 一个支持 `<`、`>`、`>>` 的简易 Shell

下面程序支持：

- 普通命令执行；
- `<` 标准输入重定向；
- `>` 覆盖写标准输出；
- `>>` 追加写标准输出。

```cpp
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/wait.h>

#define MAX_LINE 1024                                      // 命令行最大长度
#define MAX_ARG 64                                         // 最大参数数量

int main()
{
    char line[MAX_LINE];                                   // 保存用户输入的命令行

    while (1) {                                            // Shell 持续读取命令
        printf("mini-shell$ ");                            // 显示提示符
        fflush(stdout);                                    // 立即显示提示符

        if (fgets(line, sizeof(line), stdin) == NULL) {    // 读取一行命令
            break;                                         // 输入结束时退出 Shell
        }

        line[strcspn(line, "\n")] = '\0';                  // 删除行末换行符
        if (line[0] == '\0') {                             // 忽略空命令
            continue;                                      // 重新读取下一条命令
        }

        char *argv[MAX_ARG];                               // 保存传给 exec 的参数
        int argc = 0;                                      // 当前参数数量
        char *input_file = NULL;                           // 保存输入重定向文件名
        char *output_file = NULL;                          // 保存输出重定向文件名
        int append = 0;                                    // 记录是否使用追加模式

        char *token = strtok(line, " ");                   // 按空格取得第一个单词
        while (token != NULL && argc < MAX_ARG - 1) {      // 逐个解析单词
            if (strcmp(token, "<") == 0) {                 // 判断是否为输入重定向符号
                token = strtok(NULL, " ");                 // 取得输入文件名
                input_file = token;                        // 保存输入文件名
            } else if (strcmp(token, ">") == 0) {          // 判断是否为覆盖输出符号
                token = strtok(NULL, " ");                 // 取得输出文件名
                output_file = token;                       // 保存输出文件名
                append = 0;                                // 设置为覆盖模式
            } else if (strcmp(token, ">>") == 0) {         // 判断是否为追加输出符号
                token = strtok(NULL, " ");                 // 取得输出文件名
                output_file = token;                       // 保存输出文件名
                append = 1;                                // 设置为追加模式
            } else {                                        // 当前单词是普通参数
                argv[argc++] = token;                      // 保存普通参数
            }

            token = strtok(NULL, " ");                     // 继续取得下一个单词
        }

        argv[argc] = NULL;                                  // exec 参数必须以 NULL 结束
        if (argc == 0) {                                    // 没有普通命令时跳过
            continue;                                       // 重新读取命令
        }

        pid_t pid = fork();                                 // 创建子进程
        if (pid == 0) {                                     // 子进程执行重定向和程序
            if (input_file != NULL) {                      // 如果存在输入重定向
                int fd = open(input_file, O_RDONLY);       // 只读打开输入文件
                if (fd == -1) {                             // 判断打开是否失败
                    perror("open input");                  // 输出错误原因
                    exit(1);                               // 子进程失败退出
                }
                dup2(fd, STDIN_FILENO);                    // 让标准输入来自文件
                close(fd);                                  // 关闭多余的文件描述符
            }

            if (output_file != NULL) {                     // 如果存在输出重定向
                int flags = O_WRONLY | O_CREAT;             // 设置写入和创建选项
                flags |= append ? O_APPEND : O_TRUNC;      // 选择追加或覆盖模式
                int fd = open(output_file, flags, 0644);   // 打开输出文件
                if (fd == -1) {                             // 判断打开是否失败
                    perror("open output");                 // 输出错误原因
                    exit(1);                               // 子进程失败退出
                }
                dup2(fd, STDOUT_FILENO);                   // 让标准输出写入文件
                close(fd);                                  // 关闭多余的文件描述符
            }

            execvp(argv[0], argv);                          // 执行用户输入的程序
            perror("exec");                                 // exec 失败时输出原因
            exit(1);                                        // 子进程执行失败退出
        } else if (pid > 0) {                               // 父进程继续管理 Shell
            waitpid(pid, NULL, 0);                          // 等待子进程结束
        } else {                                            // fork 创建失败
            perror("fork");                                 // 输出错误原因
        }
    }

    return 0;                                               // Shell 正常退出
}
```

编译和运行：

```bash
g++ mini_shell.cpp -o mini_shell  # 编译简易 Shell
./mini_shell                       # 启动简易 Shell
```

在简易 Shell 中测试：

```bash
echo hello > result.txt   # 把 hello 写入 result.txt
cat < result.txt          # 从 result.txt 读取并显示
echo world >> result.txt  # 把 world 追加到 result.txt
```

注意：这个示例按空格分割命令，因此要求重定向符号两边有空格，例如使用 `echo hello > result.txt`，暂不处理引号、管道、环境变量展开等复杂语法。

## 7. 理解 Glibc 的 IO 库

### 7.1 Glibc 解决了什么问题

直接使用系统调用需要自己处理文件描述符、字节数、缓冲区和错误。为了让 C 程序更容易编写，Linux 通常使用 **Glibc**：Linux 中提供 C 标准库实现的运行库。

Glibc 的 IO 库在系统调用之上提供了：

- `FILE *` 文件对象；
- 用户空间缓冲区；
- `fopen`、`fclose`、`fgets`、`fprintf` 等函数；
- 格式化输入输出；
- 对不同系统接口的统一封装。

大致关系如下：

```text
C 程序
  ↓
Glibc IO 库函数：fopen / fprintf / fgets
  ↓
Linux 系统调用：open / write / read
  ↓
Linux 内核
  ↓
文件、键盘、屏幕、磁盘
```

### 7.2 `printf` 为什么能输出到屏幕

`printf` 是 Glibc 提供的格式化输出函数。它默认操作标准输出 `stdout`，而 `stdout` 内部对应标准输出文件描述符 `fd 1`。

因此：

```cpp
printf("hello\n");        // 通过 stdout 输出
```

和：

```cpp
write(1, "hello\n", 6);   // 直接向标准输出 fd 1 写入
```

默认情况下都显示在屏幕上。执行 Shell 重定向后，`fd 1` 被改成文件，`printf` 的输出也会进入文件。

> **Glibc IO 库不是独立于系统调用的另一套文件系统，而是对系统调用的更高层封装。**

# 1. 理解“文件”

## 1-1 狭义理解

日常说“文件”，通常是指保存在磁盘上的数据，例如文本、图片、程序等。**磁盘是永久性存储介质**，意思是：程序退出、电脑重启后，数据仍然可以保留；这和程序运行时使用的内存不同，内存断电后通常就没有原来的数据了。

程序想把数据长期保存，就要把数据从内存写入磁盘；下次使用时，再从磁盘读回内存。因此，磁盘既是：

- **输入设备**：磁盘把数据输入到内存；
- **输出设备**：内存把数据输出到磁盘。

```text
程序数据在内存中
      │
      ├── 写入磁盘：内存 → 磁盘
      │
      └── 读取磁盘：磁盘 → 内存
```

**IO（Input/Output，输入/输出）**：程序和外部设备之间进行数据传输的过程。因为对磁盘中文件的读取和写入，本质上都是程序与外设之间的数据传输，所以对文件的操作也属于 `IO`。

> **文件操作在狭义上就是对磁盘这个外设进行输入和输出。**

---

## 1-2 广义理解

如果每种设备都使用完全不同的操作方法，程序员就必须分别学习键盘、显示器、磁盘、网卡等设备的接口，程序也很难通用。因此，Linux 对不同设备进行统一抽象：程序可以用操作文件的思路来操作许多设备。

**抽象**：把复杂的具体实现隐藏起来，只向使用者提供一套统一的操作方式。

所以在 Linux 中常说：

> **Linux 下一切皆文件。**

这里的“一切”不是说键盘和普通文本文件在磁盘上的保存方式完全相同，而是说 Linux 尽量把它们统一表示成“可以被打开、读取、写入和关闭的对象”。

例如：

- 磁盘文件：保存和读取磁盘数据；
- 键盘：读取用户输入；
- 显示器：输出程序结果；
- 网卡：收发网络数据。

它们的底层实现不同，但对程序来说，都可以采用类似的输入输出思路。

---

## 1-3 文件操作的归类认知

### 0KB 文件也会占用磁盘空间

创建一个没有任何内容的文件时，文件内容大小可能显示为 `0KB`。但文件系统仍然需要记录：

- 这个文件叫什么；
- 它属于谁；
- 它有什么权限；
- 它什么时候被创建和修改；
- 文件数据存放在哪里。

这些记录本身也要占用磁盘空间。因此，`0KB` 只表示“文件内容没有数据”，不表示“完全不占磁盘空间”。

### 文件 = 属性 + 内容

**文件属性**也叫**元数据**，意思是“描述文件本身的信息”，例如文件名、权限、拥有者、大小、时间等；**文件内容**则是文件中真正保存的数据。

> **文件 = 文件属性（元数据）+ 文件内容。**

例如，一个文本文件可以这样理解：

```text
文件
├── 属性：文件名、权限、拥有者、大小、修改时间……
└── 内容：文本中的具体字符
```

修改文件内容和修改文件属性，是两类不同的操作：

- `cat` 查看的是文件内容；
- `chmod` 修改的是文件权限；
- `chown` 修改的是文件拥有者；
- 追加文字会改变文件内容；
- 修改文件名会改变文件属性中的名称信息。

因此：

> **所有文件操作，本质上都可以归为文件内容操作和文件属性操作。**

---

## 1-4 系统角度

### 为什么不能直接操作磁盘

磁盘由操作系统统一管理。如果每个程序都能直接读写磁盘，就可能发生多个程序互相覆盖数据、破坏文件系统结构，甚至读取不该读取的数据。

所以，程序不能随意直接控制磁盘，而是要请求操作系统代为完成。**操作系统是磁盘的管理者**，负责管理文件的位置、权限、读写过程以及多个程序之间的访问冲突。

### 文件相关的系统调用

**系统调用**：程序向操作系统内核请求服务的一种接口。例如，程序想打开文件、读取数据、创建进程，都需要通过相应的系统调用请求内核完成。

C/C++ 中的库函数可以让程序员更方便地使用这些能力，但库函数本身不是最终管理磁盘的主体。

以 `fopen` 为例：

```text
C/C++ 程序
   │
   └── 调用 fopen 库函数
          │
          └── 库函数内部请求文件相关的系统调用
                         │
                         └── 操作系统内核管理磁盘和文件
```

**库函数**：由语言或运行库提供的、方便程序员调用的函数。它通常会进一步封装系统调用。

因此：

- `fopen`、`fclose` 是库函数；
- 它们内部会封装操作系统提供的文件相关系统调用；
- 真正管理磁盘和文件的是操作系统内核。

> **C/C++ 库函数负责提供方便的使用方式，文件相关的系统调用才真正请求操作系统完成文件操作。**

### 访问文件前必须先打开

程序不能在完全没有建立联系的情况下直接读写文件。它必须先告诉操作系统：“我准备访问这个文件。”

这个过程叫**打开文件**。打开时，操作系统会检查文件是否存在、程序是否有权限，并为当前进程建立访问这个文件所需的信息。

注意，“打开文件”不是把整个文件一次性复制到内存中，而是让操作系统为进程准备好后续访问文件的条件。

这里的关键关系是：

```text
磁盘上的文件
      │
      │ 进程请求打开
      ▼
操作系统为该进程建立文件访问关系
      │
      ▼
进程读取、写入或修改文件
```

因此，严格来说，访问文件的主体不是“程序”这个抽象概念，而是**进程**。

**进程**：正在运行的程序。程序只是存放在磁盘上的代码，运行后才会成为可以执行操作的进程。

> **对文件的操作，本质上是进程对文件的操作。**

### 两种“文件”：磁盘级文件与内存文件

为了理解“打开文件”后的变化，可以把文件分成两个层次：

| 类型 | 含义 | 所在位置 |
|---|---|---|
| 磁盘级文件 | 长期保存在磁盘上的文件 | 磁盘 |
| 内存文件 | 文件被进程打开后，操作系统为进程维护的访问对象 | 内存中的操作系统管理区域 |

**磁盘级文件**是长期存在的实际文件；**内存文件**是文件被打开后，操作系统在内存中为进程建立的管理信息。

例如：

```text
磁盘上：notes.txt
      │
      │ 进程打开
      ▼
操作系统建立该进程对 notes.txt 的访问信息
      │
      ├── 进程读取内容
      ├── 进程写入内容
      └── 进程关闭文件
```

关闭文件后，进程与这个文件的临时访问关系被解除，但磁盘上的文件是否存在，取决于程序有没有删除它。

这里的“内存文件”不是说磁盘文件的全部内容一定已经复制到内存，而是指“文件被打开后，操作系统在内存中维护的文件访问状态”。

> **文件在磁盘上长期存在；文件被打开后，操作系统还会在内存中为进程维护一个对应的访问对象。**

## 2. 回顾 C 文件接口

程序要读写文件，不能直接“碰”磁盘，而是先让操作系统建立一个可操作的文件连接。C 语言用 `FILE *` 表示这个连接，称为**文件流：程序读写文件时使用的通道**。

### 2-1 `hello.c` 打开文件

如果程序想把内容写入文件，第一步是调用 `fopen`：

```cpp
#include <stdio.h>  // 提供 FILE、fopen、fclose、perror
#include <string.h> // 提供 strlen

int main()
{
    FILE *fp = fopen("myfile", "w"); // 以写方式打开当前路径下的 myfile
    if (fp == NULL) {                // 打开失败时返回 NULL
        perror("fopen");             // 打印失败原因
        return 1;                    // 必须结束程序，不能继续使用 NULL
    }

    const char *msg = "hello Linux\n"; // 准备要写入的字符串
    fwrite(msg, strlen(msg), 1, fp);   // 把字符串写入文件流
    fclose(fp);                       // 关闭文件流
    return 0;                         // 正常结束
}
```

`fopen("myfile", "w")` 中的 `"myfile"` 没有写目录，因此它表示**程序当前路径下的文件**。如果打开失败，`fopen` 返回 `NULL`；此时如果继续把 `fp` 传给 `fwrite` 或 `fclose`，就可能因为操作空指针而崩溃。

> **关键结论：`fopen` 失败后必须立即处理并退出，不能继续操作返回的 `NULL`。**

#### 文件到底创建在哪里

新手容易把“当前路径”理解成源代码所在目录或可执行文件所在目录，但它实际指的是**进程的当前工作目录**。

已知进程的 PID 后，可以查看进程信息：

```bash
ls /proc/[pid] -l  # 查看指定进程在 /proc 中的信息
```

其中：

- `cwd`：指向进程当前工作目录的符号链接；
- `exe`：指向启动该进程的可执行文件完整路径的符号链接。

例如，程序的可执行文件在 `/home/user/bin/hello`，但启动程序时当前路径是 `/tmp`，那么：

```text
可执行文件位置：/home/user/bin/hello
进程当前路径：  /tmp
fopen("myfile") 创建：/tmp/myfile
```

因为文件操作属于进程，进程内部保存了自己的当前工作目录，所以即使文件名没有写完整路径，系统也知道应该去哪里查找或创建。

---

### 2-2 `hello.c` 写文件

`fwrite` 的基本形式是：

```cpp
fwrite(缓冲区首地址, 每个元素大小, 元素个数, 文件流);
```

**缓冲区：内存中暂时存放要读写数据的一块空间。**

例如：

```cpp
#include <stdio.h>  // 提供文件流接口
#include <string.h> // 提供 strlen

int main()
{
    FILE *fp = fopen("myfile", "w"); // 打开文件，原内容会被清空
    if (fp == NULL) {                // 判断是否打开失败
        perror("fopen");             // 打印错误信息
        return 1;                    // 失败后立即退出
    }

    char msg[] = "hello Linux\n"; // 准备写入的字符数组
    size_t n = fwrite(msg, strlen(msg), 1, fp); // 写入 1 个、大小为 strlen(msg) 的元素
    printf("写入了 %zu 个元素\n", n);          // fwrite 返回实际写入的元素个数

    fclose(fp); // 关闭文件
    return 0;  // 正常结束
}
```

本例把整个字符串作为“1 个元素”写入，因此返回值通常是 `1`。如果希望返回值直接表示写入的字节数，也可以这样写：

```cpp
fwrite(msg, 1, strlen(msg), fp); // 每个元素 1 字节，共写入 strlen(msg) 个元素
```

两种写法写入的内容相同，但返回值的单位不同：`fwrite` 返回的是**元素个数**，不是固定的字节数。

---

### 2-3 `hello.c` 读文件

写文件时数据在内存中；读文件时则需要准备一块内存接收数据：

```cpp
#include <stdio.h>  // 提供 FILE、fopen、fread
#include <string.h> // 提供 strlen

int main()
{
    FILE *fp = fopen("myfile", "r"); // 以只读方式打开文件
    if (fp == NULL) {                // 判断文件是否打开成功
        perror("fopen");             // 打印错误原因
        return 1;                    // 打开失败后退出
    }

    char buf[128] = {0};             // 准备接收文件内容的缓冲区
    ssize_t s = fread(buf, 1, 127, fp); // 每次读 1 字节，最多读 127 个字节
    if (s > 0) {                     // 确认确实读到了内容
        buf[s] = '\0';               // 手动添加字符串结束标记
        printf("%s", buf);           // 按字符串打印读取结果
    }

    if (feof(fp)) {                  // 判断最近一次读取是否到达文件结尾
        printf("\n已经到达文件结尾\n"); // 文件读到末尾
    }

    fclose(fp); // 关闭文件
    return 0;  // 正常结束
}
```

`fread` 的形式是：

```cpp
fread(缓冲区首地址, 每个元素大小, 元素个数, 文件流);
```

本例使用 `1` 作为元素大小，因此返回值 `s` 表示实际读取的字节数。读入的内容不一定自动带有 `'\0'`，所以在按 C 字符串打印前，要在有效数据末尾补上：

```cpp
buf[s] = '\0'; // 把字节数据转换成以 \0 结尾的 C 字符串
```

`feof(fp)` 的含义是“之前的一次读取是否因为到达文件结尾而失败”。它不是“提前预测文件是否读完”，通常要先调用 `fread`，再检查它。

#### 用文件接口实现简单的 `cat`

`cat` 的基本任务是：打开命令行参数指定的文件，然后不断读取并输出。

```cpp
#include <stdio.h>  // 提供 fopen、fread、fwrite、fclose
#include <stdlib.h> // 提供 EXIT_FAILURE

int main(int argc, char *argv[])
{
    if (argc != 2) {                         // 要求命令后面必须有一个文件名
        fprintf(stderr, "用法: %s 文件名\n", argv[0]); // 错误信息输出到 stderr
        return EXIT_FAILURE;                 // 参数数量不正确
    }

    FILE *fp = fopen(argv[1], "r");          // 以只读方式打开命令行指定的文件
    if (fp == NULL) {                        // 判断打开是否失败
        perror("fopen");                     // 打印打开失败原因
        return EXIT_FAILURE;                 // 失败后退出
    }

    char buf[1024];                          // 准备一次读取 1024 字节
    size_t n = 0;                            // 保存每次实际读取的字节数

    while ((n = fread(buf, 1, sizeof(buf), fp)) > 0) { // 持续读取直到没有数据
        fwrite(buf, 1, n, stdout);           // 把读到的字节写到标准输出
    }

    fclose(fp);                              // 关闭文件
    return 0;                                // 正常结束
}
```

编译运行：

```bash
gcc cat.c -o mycat  # 编译源文件并生成 mycat
./mycat myfile      # 输出 myfile 的内容
```

这里没有把 `buf` 当作字符串打印，而是直接按读取到的字节数写出，因此即使文件中没有 `'\0'`，也能正确处理普通文本内容。

### 2-4 输出信息到显示器，你有哪些方法

程序输出到显示器，本质上也是“向一个输出流写数据”。C 语言常用三种方式：

```cpp
#include <stdio.h>  // 提供 stdout、fwrite、printf、fprintf
#include <string.h> // 提供 strlen

int main()
{
    const char *msg = "hello\n";          // 准备输出的字符串

    fwrite(msg, strlen(msg), 1, stdout);  // 直接向标准输出流写数据
    printf("%s", msg);                    // 使用格式化输出函数
    fprintf(stdout, "%s", msg);           // 指定标准输出流进行格式化输出

    return 0;                             // 正常结束
}
```

三种方式的区别：

| 方法 | 特点 |
|---|---|
| `fwrite` | 按字节块写入，不负责格式化 |
| `printf` | 默认输出到 `stdout`，支持格式化 |
| `fprintf` | 可以明确指定输出流，也支持格式化 |

---

### 2-5 `stdin`、`stdout`、`stderr`

程序如果每次都必须手动打开键盘、显示器和错误输出设备，使用起来会很麻烦。因此，C 运行环境在程序启动时就默认准备了三个文件流：

```cpp
extern FILE *stdin;   // 标准输入流
extern FILE *stdout;  // 标准输出流
extern FILE *stderr;  // 标准错误流
```

`extern` 表示“这个变量已经在别处定义，这里只声明它可以使用”。

| C 文件流 | 含义 | 默认连接到 |
|---|---|---|
| `stdin` | 标准输入 | 键盘输入 |
| `stdout` | 标准输出 | 显示器 |
| `stderr` | 标准错误 | 显示器 |

因此：

```cpp
#include <stdio.h>  // 提供三个标准文件流

int main()
{
    char buf[128] = {0};                    // 准备接收输入的缓冲区

    fprintf(stdout, "请输入内容: ");        // 输出提示信息
    fgets(buf, sizeof(buf), stdin);         // 从标准输入读取一行
    fprintf(stdout, "正常输出: %s", buf);   // 写入标准输出
    fprintf(stderr, "这是一条错误流信息\n"); // 写入标准错误

    return 0;                               // 正常结束
}
```

`stdout` 和 `stderr` 默认都显示在屏幕上，但它们是两条不同的输出流。这样，正常结果和错误信息可以被分别重定向或分别处理。

C++ 中有对应关系：

| C | C++ |
|---|---|
| `stdin` | `cin` |
| `stdout` | `cout` |
| `stderr` | `cerr` |

> **关键结论：C 默认提供 `stdin`、`stdout`、`stderr` 三个 `FILE *` 流，分别用于标准输入、标准输出和标准错误。**

### 2-6 打开文件的方式

不同的打开模式解决不同问题：有时只想读，有时要覆盖旧内容，有时必须保留旧内容并继续追加。

| 模式 | 读 | 写 | 文件不存在时 | 原有内容 | 初始定位 |
|---|---:|---:|---|---|---|
| `r` | 是 | 否 | 打开失败 | 保留 | 开头 |
| `r+` | 是 | 是 | 打开失败 | 保留 | 开头 |
| `w` | 否 | 是 | 创建文件 | **清空** | 开头 |
| `w+` | 是 | 是 | 创建文件 | **清空** | 开头 |
| `a` | 否 | 是 | 创建文件 | 保留 | 末尾 |
| `a+` | 是 | 是 | 创建文件 | 保留，写入追加到末尾 | 追加写 |

#### `r`：只读

```cpp
FILE *fp = fopen("myfile", "r"); // 只读打开，文件必须已经存在
```

文件不存在时打开失败，适合查看已有文件。

#### `r+`：读写但不清空

```cpp
FILE *fp = fopen("myfile", "r+"); // 允许读写，文件必须已经存在
```

适合修改已有文件，但写入会覆盖原位置的数据。

#### `w`：写入并清空

```cpp
FILE *fp = fopen("myfile", "w"); // 写入打开，存在则立刻清空，不存在则创建
```

“清空”发生在 `fopen` 成功时，而不是第一次 `fwrite` 时。因此，只要使用了 `"w"`，原文件内容就已经被截断为零长度。

#### `w+`：读写并清空

```cpp
FILE *fp = fopen("myfile", "w+"); // 允许读写，存在则清空，不存在则创建
```

#### `a`：追加写

```cpp
FILE *fp = fopen("myfile", "a"); // 只允许写入，写入位置始终在文件末尾
```

即使文件中原来有内容，新写入的数据也会接在末尾，不会覆盖原内容。

#### `a+`：读取并追加写

```cpp
FILE *fp = fopen("myfile", "a+"); // 允许读取，写入时始终追加到文件末尾
```

它适合日志文件：程序可以读取日志，也可以不断把新记录添加到末尾。

```cpp
#include <stdio.h>  // 提供文件流接口

int main()
{
    FILE *fp = fopen("log.txt", "a"); // 以追加方式打开日志文件
    if (fp == NULL) {                 // 判断是否打开失败
        perror("fopen");              // 打印错误信息
        return 1;                     // 失败后退出
    }

    fputs("new log record\n", fp);    // 把新记录追加到文件末尾
    fclose(fp);                       // 关闭文件
    return 0;                         // 正常结束
}
```

`fseek`、`ftell`、`rewind` 用于改变或查询文件流的位置，相关内容可结合 C 阶段知识复习。

> **关键结论：最容易造成误删的是 `"w"` 和 `"w+"`，它们成功打开文件时会立即清空原内容；需要保留旧内容并在末尾写入时使用 `"a"` 或 `"a+"`。**

## 3-1 一种传递标志位的方法

### 为什么需要标志位

假设一个函数需要同时接收多个“开关”：

- 是否只读；
- 是否创建文件；
- 是否追加写入。

如果每个开关都单独使用一个参数，函数参数会越来越多。更方便的方法是：用一个 `int` 的不同二进制位分别表示不同开关。

**标志位：用一个整数中的不同二进制位，分别表示不同选项。**

```cpp
#define ONE   0001  // 二进制 0000 0001，占用第 0 位
#define TWO   0002  // 二进制 0000 0010，占用第 1 位
#define THREE 0004  // 二进制 0000 0100，占用第 2 位
```

这里的 `0001`、`0002`、`0004` 是八进制写法，换成二进制后分别只有一个二进制位为 `1`：

```text
ONE       0000 0001
TWO       0000 0010
THREE     0000 0100
```

### 检测一个标志位

如果想检查 `flags` 中是否包含 `ONE`，使用按位与 `&`：

```cpp
if (flags & ONE) {       // 如果 ONE 对应的位为 1，结果就非 0
    // flags 中包含 ONE
}
```

因为 `ONE` 只有最低位是 `1`，所以 `flags & ONE` 只会检查最低位。

### 组合多个标志位

使用按位或 `|` 把多个标志合并：

```cpp
int flags = ONE | TWO;   // 同时打开 ONE 和 TWO 两个选项
```

按位或不会破坏已经打开的其他位：

```text
  0000 0001   ONE
| 0000 0010   TWO
------------
  0000 0011   ONE | TWO
```

> **一个 `int` 可以通过不同二进制位同时传递多组互不影响的标志，`open` 的 `flags` 参数就是这样实现的。**

## 3-2 `hello.c` 写文件（系统接口版）

### 为什么使用 `open`

C 标准库可以用 `fopen` 打开文件，但 Linux 内核真正管理文件时，需要一个整数作为文件的身份编号，这个编号就是文件描述符 `fd`。

**文件描述符：进程用来代表一个已打开文件的小整数。**

### `open` 创建并打开文件

```cpp
#include <stdio.h>      // perror
#include <string.h>     // strlen
#include <sys/types.h>  // 基本系统类型
#include <sys/stat.h>   // umask、权限类型
#include <fcntl.h>      // open 和 O_* 标志
#include <unistd.h>     // write、close

int main()
{
    umask(0);                            // 暂时不屏蔽 open 创建文件时指定的权限
    int fd = open("myfile",              // 要打开的文件名
                  O_WRONLY | O_CREAT,    // 只写；不存在时创建
                  0644);                 // 新文件的初始权限

    if (fd < 0) {                        // 返回负数表示打开失败
        perror("open");                  // 根据 errno 打印失败原因
        return 1;                        // 返回非 0 表示程序异常结束
    }

    const char *msg = "hello linux\n";   // 准备写入的字符串
    size_t len = strlen(msg);             // 计算字符串中的字节数
    ssize_t n = write(fd, msg, len);     // 把 msg 中的 len 个字节写入文件

    if (n < 0) {                         // 返回负数表示写入失败
        perror("write");                 // 打印写入失败原因
        close(fd);                       // 关闭已经打开的文件
        return 1;                        // 返回非 0 表示失败
    }

    close(fd);                           // 通知内核不再使用这个文件
    return 0;                            // 程序正常结束
}
```

`write` 的三个核心参数分别是：

```text
fd       → 写入哪个文件
msg      → 从哪块内存取数据
len      → 最多写入多少字节
```

返回值是实际写入的字节数，可能小于期望值；返回负数表示失败。

`umask(0)` 的作用是让本例中指定的 `0644` 不再被当前进程的 `umask` 屏蔽。实际程序通常应遵守系统默认的 `umask`，这里这样写是为了观察权限结果。

## 3-3 `hello.c` 读文件（系统接口版）

写文件时，程序把内存中的数据交给 `write`；读文件时，程序让 `read` 把文件数据复制到内存缓冲区中。

```cpp
#include <stdio.h>      // printf、perror
#include <string.h>     // strlen
#include <sys/types.h>  // ssize_t
#include <fcntl.h>      // open 和 O_RDONLY
#include <unistd.h>     // read、close

int main()
{
    const char *msg = "hello linux\n";   // 文件中预期存放的内容
    int fd = open("myfile", O_RDONLY);   // 以只读方式打开文件

    if (fd < 0) {                       // 打开失败时返回负数
        perror("open");                 // 打印失败原因
        return 1;                       // 程序异常结束
    }

    char buf[128] = {0};                // 准备接收文件内容的缓冲区

    while (1) {
        ssize_t s = read(fd,              // 从 fd 对应的文件读取
                          buf,             // 把数据放入 buf
                          strlen(msg));    // 本次最多读取这么多字节

        if (s > 0) {                      // 实际读到了数据
            printf("%.*s", (int)s, buf);  // 只打印实际读到的 s 个字节
        } else {
            break;                        // 0 表示读到文件末尾，负数表示失败
        }
    }

    close(fd);                            // 关闭文件
    return 0;                             // 正常结束
}
```

`read` 和 `write` 的参数结构很相似：

```text
read(fd,  buf, count)   // 从文件读到内存
write(fd, buf, count)   // 从内存写到文件
```

`read` 返回：

- 大于 `0`：实际读取的字节数；
- 等于 `0`：到达文件末尾；
- 小于 `0`：读取失败。

## 3-4 接口介绍【板书强调】

### `open` 的头文件和函数原型

```cpp
#include <sys/types.h>  // mode_t、ssize_t 等系统类型
#include <sys/stat.h>   // 文件状态和权限相关定义
#include <fcntl.h>      // open、O_RDONLY 等定义
```

`open` 有两个版本：

```cpp
int open(const char *pathname, int flags);              // 打开已有文件
int open(const char *pathname, int flags, mode_t mode); // 必要时创建文件
```

参数含义：

- `pathname`：文件路径；
- `flags`：打开方式和附加选项；
- `mode`：创建新文件时使用的权限。

返回值：

```text
成功：返回新的文件描述符
失败：返回 -1，并设置 errno
```

`errno` 是系统保存的错误编号，`perror` 可以根据它输出可读的错误原因。

### 必选的访问方式

下面三者必须选择一个：

| 标志 | 含义 |
|---|---|
| `O_RDONLY` | 只读 |
| `O_WRONLY` | 只写 |
| `O_RDWR` | 读写 |

### 可选的附加标志

| 标志 | 作用 |
|---|---|
| `O_CREAT` | 文件不存在时创建文件 |
| `O_APPEND` | 每次写入都放到文件末尾 |
| `O_TRUNC` | 打开已有文件时清空原内容 |

使用 `O_CREAT` 时，必须使用三参数版本的 `open`，因为需要通过 `mode` 指定新文件权限。

```cpp
int fd = open("log.txt",                 // 文件名
              O_CREAT | O_WRONLY | O_TRUNC, // 创建、只写、清空原内容
              0666);                      // 新文件权限
```

### `w` 和 `a` 的对应关系【板书强调】

```cpp
int fd = open("log.txt",                    // 打开 log.txt
              O_CREAT | O_WRONLY | O_TRUNC, // 不存在则创建，存在则清空
              0666);                        // 对应高级接口中的 "w"
```

```cpp
int fd = open("log.txt",                    // 打开 log.txt
              O_CREAT | O_WRONLY | O_APPEND, // 不存在则创建，写入文件末尾
              0666);                         // 对应高级接口中的 "a"
```

两者的区别：

| 写法 | 文件不存在 | 文件已存在时 | 新内容位置 |
|---|---|---|---|
| `O_TRUNC`，对应 `w` | 创建 | 清空原内容 | 从文件开头写 |
| `O_APPEND`，对应 `a` | 创建 | 保留原内容 | 从文件末尾写 |

> **`O_TRUNC` 会清空已有文件，`O_APPEND` 会保留已有内容并追加写入；二者分别对应 `w` 和 `a`。**

### `write` 函数

```cpp
ssize_t write(int fd, const void *buf, size_t count);
```

- `fd`：目标文件的文件描述符；
- `buf`：待写入数据的起始地址；
- `count`：希望写入的字节数；
- 返回值：实际写入的字节数，失败返回负数。

### 文本写入和二进制写入

`write` 本身只认识“字节”，并不知道数据是文本还是整数。文本和二进制是语言层面对数据解释方式的区分。

例如整数 `12345`：

```text
文本形式：字符 '1'、'2'、'3'、'4'、'5'
二进制形式：整数 12345 在内存中的二进制表示
```

因此，同样是写入 `12345`，保存的字节内容可能完全不同。

### C 标准库输出函数

C 库提供了更方便的输出函数：

```text
puts       // 输出字符串，并自动换行
fputs      // 向指定 FILE* 流输出字符串
putchar    // 输出一个字符到标准输出
putc       // 向指定 FILE* 流输出一个字符
printf     // 格式化输出到标准输出
fprintf    // 格式化输出到指定 FILE* 流
sprintf    // 格式化到内存字符串
snprintf   // 限制写入长度后格式化到内存字符串
```

例如 `fputs` 的原型是：

```cpp
int fputs(const char *s, FILE *stream); // 把字符串写入指定的 C 文件流
```

这些函数操作的是 `FILE *`，而 `write` 操作的是整数文件描述符 `fd`。

### `fread` 和 `fwrite`

`fread`、`fwrite` 属于 C 标准库，用于二进制流输入输出。

```cpp
size_t fread(void *ptr,       // 数据读入的位置
             size_t size,      // 每个元素的大小
             size_t nmemb,     // 读取多少个元素
             FILE *stream);    // 从哪个 C 文件流读取
```

```cpp
size_t fwrite(const void *ptr, // 待写数据的地址
              size_t size,     // 每个元素的大小
              size_t nmemb,    // 写入多少个元素
              FILE *stream);   // 写入哪个 C 文件流
```

`fread` 和 `fwrite` 的返回值是实际读写的“元素个数”，不是直接返回字节数。

## 3-5 `open` 函数返回值

`fopen`、`fclose`、`fread`、`fwrite` 是 C 标准库函数；`open`、`close`、`read`、`write`、`lseek` 是系统调用接口。

```text
C 标准库函数：fopen、fread、fwrite
        ↓ 封装
系统调用接口：open、read、write
        ↓
操作系统内核
        ↓
硬件和磁盘
```

**封装：在底层功能外面再包一层，提供更容易使用的接口。**

因此，C 库中的 `f` 系列函数本质上是在系统调用之上提供了更方便的使用方式。

> **`fopen` 等库函数通常是对 `open` 等系统调用的封装，库函数更方便，系统调用更接近内核。**

## 3-6 文件描述符 `fd`【板书强调】

### 文件描述符是什么

程序打开一个文件后，内核会返回一个整数。程序以后不再反复传递文件名，而是使用这个整数操作文件。

**文件描述符 `fd`：进程内部代表某个已打开文件的非负整数。**

例如：

```cpp
int fd = open("myfile", O_RDONLY); // fd 保存内核返回的文件编号
read(fd, buf, sizeof(buf));        // 通过 fd 读取文件
close(fd);                         // 通过 fd 关闭文件
```

文件描述符从 `0` 开始，是进程内部的一组下标。

### 3-6-1 `0`、`1`、`2`

Linux 进程启动时，通常已经默认打开三个文件描述符：

| 文件描述符 | 名称 | 通常对应设备 |
|---:|---|---|
| `0` | 标准输入 `stdin` | 键盘 |
| `1` | 标准输出 `stdout` | 显示器 |
| `2` | 标准错误 `stderr` | 显示器 |

在操作系统层面，进程默认拥有打开的 `0`、`1`、`2`。

程序可以直接使用它们：

```cpp
#include <string.h>  // strlen
#include <unistd.h>  // read、write

int main()
{
    char buf[128] = {0};             // 准备输入缓冲区
    ssize_t n = read(0, buf, sizeof(buf)); // 从标准输入读取数据

    if (n > 0) {                     // 确实读取到数据
        write(1, buf, n);             // 写到标准输出
        write(2, buf, n);             // 写到标准错误
    }

    return 0;                        // 程序结束
}
```

连续打开多个文件时，可能得到：

```text
0  → 标准输入
1  → 标准输出
2  → 标准错误
3  → 第一个新打开的文件
4  → 第二个新打开的文件
5  → 第三个新打开的文件
6  → 第四个新打开的文件
```

这里相邻的 `3、4、5、6` 只是文件描述符编号相邻，并不表示这些文件内容相邻；它们仍然可以是完全不同的文件。

### `fd` 与内核结构的关系【板书强调】

用户程序看到的是整数 `fd`，内核内部还要保存更多信息，例如：

- 文件当前读写位置；
- 文件权限；
- 文件大小；
- 文件对应的磁盘信息；
- 文件操作方法；
- 内核缓冲区。

用户层代码：

```cpp
int fd = open("log.txt", O_RDONLY); // 请求内核打开文件并返回 fd
read(fd, buffer, sizeof(buffer));   // 通过 fd 读取文件内容
close(fd);                          // 关闭 fd
```

内核中可以抽象为：

```text
进程的 task_struct
        ↓
files_struct
        ↓
文件描述符数组 fd_array[]
        ↓
struct file
        ↓
文件的 inode 和磁盘数据
```

其中：

- `task_struct`：进程在内核中的描述结构；
- `files_struct`：保存进程打开文件的信息；
- `fd_array[]`：以文件描述符为下标的数组；
- `struct file`：内核中代表一次“打开状态”的结构；
- `inode`：文件在内核中的元信息记录，例如权限、大小、位置等。

源码中相关结构大致位于：

```text
task_struct → sched.h
files_struct → fdtable.h
struct file  → fs.h
```

可以使用下面的命令查看当前内核版本：

```bash
uname -a  # 查看内核版本和系统架构
```

对文件内容或属性进行操作时，内核需要把磁盘上的相关数据读入内存中的缓冲区：

```text
磁盘文件
   ↓ 读取
内核中的文件信息和缓冲区
   ↓ 拷贝
用户程序的 buffer
```

**`struct file` 代表一个被打开的文件状态。**

同一个磁盘文件可以被多次打开，每次打开都可能产生一个新的 `struct file`，因此每次打开可以拥有独立的读写位置。

一个进程可以打开多个文件：

```text
一个进程 : 多个打开文件 = 1 : n
```

`struct file` 中可以包含：

```text
引用计数 ref_cnt
文件缓冲区
inode 信息
文件权限 mode
当前读写位置
链接属性
文件操作方法
next 指针
```

磁盘上的文件不只有内容，还包括属性：

```text
文件 = 内容 + 属性
```

每个被打开的文件，在内核中都能找到与之对应的文件信息和 inode 元信息。

> **用户程序操作文件时，先使用 `fd` 找到内核中的 `struct file`，再由内核访问文件内容和属性。**

### 3-6-2 文件描述符的分配规则【板书强调】

如果 `0、1、2` 都被占用，第一次调用 `open` 通常得到：

```text
fd = 3
```

如果先关闭 `0`：

```cpp
close(0);                         // 释放下标 0
int fd = open("myfile", O_RDONLY); // 新 open 会尝试使用最小空闲下标
```

此时新的 `fd` 通常是 `0`。

同理，关闭 `2` 后再打开文件，新的文件描述符通常是 `2`。

> **新的文件描述符一定优先选择 `files_struct` 中当前未使用的最小下标。**

### 3-6-3 重定向

#### 重定向解决什么问题

通常 `printf` 输出到显示器。如果希望同一条输出进入文件，就需要改变“标准输出 `1` 所指向的对象”。

例如：

```cpp
#include <stdio.h>      // printf、fflush、perror
#include <fcntl.h>      // open
#include <unistd.h>     // close

int main()
{
    close(1);                                  // 释放标准输出对应的下标 1
    int fd = open("myfile",                  // 打开目标文件
                  O_WRONLY | O_CREAT,        // 只写，不存在则创建
                  0666);                     // 创建时使用的权限

    if (fd < 0) {                             // 打开失败
        perror("open");                      // 打印错误
        return 1;                             // 异常结束
    }

    printf("this goes to myfile\n");          // printf 仍然写标准输出 1
    fflush(stdout);                           // 强制把 stdout 缓冲区内容写出去

    close(fd);                                // 关闭文件
    return 0;                                 // 正常结束
}
```

因为下标 `1` 已经空出，`open` 会把新文件分配为 `fd = 1`。所以 `printf` 虽然仍然访问标准输出，但标准输出现在指向了 `myfile`。

常见重定向符号：

| 符号 | 作用 |
|---|---|
| `>` | 覆盖式输出 |
| `>>` | 追加式输出 |
| `<` | 从文件输入 |

Shell 命令中的：

```bash
./myprogram > result.txt   # 把标准输出写入 result.txt
./myprogram >> result.txt  # 把标准输出追加到 result.txt
./myprogram < input.txt    # 把标准输入改为来自 input.txt
```

重定向的关键不是改变 `0、1、2` 这些下标，而是改变文件描述符表中下标对应的指针：

```text
重定向前：
fd 1 ─────→ 显示器

重定向后：
fd 1 ─────→ myfile
```

> **重定向保持文件描述符下标不变，只改变文件描述符表中该下标指向的内核文件对象。**

`printf` 可能先把内容放入 `stdout` 缓冲区，所以重定向后应先调用 `fflush(stdout)`，再关闭文件。

### 3-6-4 使用 `dup2` 系统调用【板书强调】

手动 `close(1)` 再 `open` 依赖“最小空闲下标”规则。更直接的方法是使用 `dup2`。

```cpp
#include <unistd.h>  // dup2、close
#include <fcntl.h>   // open、O_*
#include <stdio.h>   // printf、fflush、perror

int main()
{
    int fd = open("./log",                  // 打开日志文件
                  O_CREAT | O_RDWR,         // 创建并以读写方式打开
                  0666);                    // 创建时使用的权限

    if (fd < 0) {                           // 打开失败
        perror("open");                     // 打印错误
        return 1;                           // 异常结束
    }

    if (dup2(fd, 1) < 0) {                  // 让文件描述符 1 指向 fd 指向的文件
        perror("dup2");                     // 打印复制失败原因
        close(fd);                          // 关闭原文件描述符
        return 1;                           // 异常结束
    }

    printf("message in log\n");              // 标准输出 1 已经指向 log
    fflush(stdout);                          // 立即刷新输出缓冲区

    close(fd);                               // 关闭原来的 fd，不影响 1 的副本
    return 0;                                // 正常结束
}
```

函数原型：

```cpp
#include <unistd.h>                         // 提供 dup2 声明

int dup2(int oldfd, int newfd);              // 让 newfd 成为 oldfd 的副本
```

返回值：

```text
成功：返回 newfd
失败：返回 -1，并设置 errno
```

`dup2` 的规则是：

```text
dup2(oldfd, newfd)
1. 如果 newfd 原来打开，先关闭它
2. 让 newfd 指向 oldfd 当前指向的同一个文件
```

例如：

```cpp
dup2(fd, 1);  // 把标准输出 1 重定向到 fd 指向的文件
dup2(fd, 0);  // 把标准输入 0 重定向到 fd 指向的文件
dup2(fd, 2);  // 把标准错误 2 重定向到 fd 指向的文件
```

`printf` 底层访问的是标准输出 `1`。执行 `dup2(fd, 1)` 后，`1` 对应的文件对象已经发生改变，因此输出会进入文件。

> **`dup2(oldfd, newfd)` 会先关闭 `newfd`，再让 `newfd` 成为 `oldfd` 的副本，从而直接完成重定向。**

### 3-6-5 在 `minishell` 中添加重定向功能

Shell 需要先识别命令中的重定向符号，再让即将执行命令的子进程完成重定向。

#### 保存重定向类型

可以定义四种状态：

```text
NoneRedir   0   没有重定向
InputRedir  1   输入重定向 <
OutputRedir 2   覆盖输出 >
AppRedir    3   追加输出 >>
```

同时保存目标文件名：

```text
redir    → 当前重定向类型
filename → 重定向目标文件名
```

#### 解析命令

`ParseRedir` 的处理流程：

```text
原始命令
   ↓
从命令尾部查找 <、>>、>
   ↓
截断重定向符号前的命令
   ↓
取出符号后面的文件名
   ↓
TrimSpace 去除多余空格
```

例如：

```text
原命令：  cat < input.txt
解析后：
命令：    cat
类型：    InputRedir
文件名：  input.txt
```

#### 子进程执行重定向

重定向必须由子进程完成，因为子进程随后要执行程序替换；父 Shell 不能把自己的标准输入输出永久改掉。

```text
父进程 shell
    ↓ fork
子进程
    ↓ DoRedir
    ↓ execvpe
目标程序
```

`DoRedir` 的核心逻辑如下：

```cpp
if (redir == InputRedir) {
    fd = open(filename, O_RDONLY);                  // 只读打开输入文件
    dup2(fd, 0);                                    // 让标准输入来自该文件
    close(fd);                                      // 关闭多余的文件描述符
}
else if (redir == OutputRedir) {
    fd = open(filename, O_CREAT | O_WRONLY | O_TRUNC,
              0666);                               // 创建或清空输出文件
    dup2(fd, 1);                                    // 让标准输出写入该文件
    close(fd);                                      // 关闭多余的文件描述符
}
else if (redir == AppRedir) {
    fd = open(filename, O_CREAT | O_WRONLY | O_APPEND,
              0666);                               // 创建或打开并追加写入
    dup2(fd, 1);                                    // 让标准输出写入该文件
    close(fd);                                      // 关闭多余的文件描述符
}
```

子进程的完整执行顺序是：

```text
fork()
  ↓
子进程执行 DoRedir()
  ↓
子进程执行 execvpe(gargv[0], gargv, genv)
  ↓
父进程 waitpid() 等待子进程
  ↓
根据 WIFEXITED 和 WEXITSTATUS 更新 lastcode
```

`cd`、`export`、`env`、`echo` 等内建命令由 Shell 自己执行；普通外部命令则由子进程完成重定向后，再通过 `execvpe` 替换为目标程序。

# 4. 理解“一切皆文件”

## 4.1 重新准确理解重定向【板书强调】

### 4.1.1 为什么需要标准错误流

运行程序时，屏幕上可能同时出现两类信息：

- 正常结果：例如计算结果、程序运行提示；
- 错误信息：例如文件打不开、参数错误。

如果两类信息都写到同一个地方，用户就很难单独保存正常结果，或者单独查看错误。因此，Linux 给每个进程准备了不同的**标准流**：标准流就是程序默认使用的输入和输出通道。

```text
正常消息 ──> 标准输出 stdout
错误消息 ──> 标准错误 stderr
```

这样就可以只把正常结果保存到文件，而让错误信息继续显示在屏幕上。

> **标准错误流的作用：把正常消息和错误消息分开，便于分别显示、保存和处理。**

### 4.1.2 三个标准文件描述符

**文件描述符**：进程中用一个小整数表示“已经打开的文件或设备”。

每个进程启动时，通常已经打开了下面三个通道：

| 文件描述符 | 名称 | 默认连接对象 | 主要用途 |
|---|---|---|---|
| `0` | `stdin` | 键盘 | 输入 |
| `1` | `stdout` | 显示器 | 正常输出 |
| `2` | `stderr` | 显示器 | 错误输出 |

C 和 C++ 的输出函数，最终都会找到对应的文件描述符：

```cpp
#include <cstdio>       // 提供 printf 和 fprintf
#include <iostream>     // 提供 cout 和 cerr

int main() {
    printf("hello printf\n");                 // 写入标准输出 stdout，也就是文件描述符 1
    std::cout << "hello cout" << std::endl;   // 写入标准输出 stdout，也就是文件描述符 1
    std::cerr << "hello cerr" << std::endl;   // 写入标准错误 stderr，也就是文件描述符 2
    fprintf(stderr, "hello stderr\n");        // 明确写入标准错误 stderr，也就是文件描述符 2
    return 0;                                 // 程序正常结束
}
```

其中，`std::cout` 和 `printf` 都写入文件描述符 `1`；`std::cerr` 和 `fprintf(stderr, ...)` 都写入文件描述符 `2`。

**重定向**：把原本连接到屏幕或键盘的通道，改接到文件等其他对象。

```bash
g++ stream.cc -o a.out                 # 编译源文件，生成可执行程序
./a.out                                # 直接运行，标准输出和标准错误都显示在屏幕上
./a.out > log.txt                      # 只把文件描述符 1 重定向到 log.txt
cat log.txt                            # 查看保存到文件中的标准输出内容
```

执行 `./a.out > log.txt` 后：

- `printf` 和 `cout` 的内容进入 `log.txt`；
- `cerr` 和 `stderr` 的内容仍然显示在屏幕上。

因此，若代码中同时有 `cout` 和 `cerr`，`log.txt` 不会只剩 `printf`，而是包含所有写入标准输出的内容。真正被分离的是 `stdout` 和 `stderr`。

> **凡是写入文件描述符 `1` 的内容，都会写入标准输出当前连接的对象；凡是写入文件描述符 `2` 的内容，都会写入标准错误当前连接的对象。**

### 4.1.3 文件描述符表和内核中的 `file` 对象

程序看到的是文件描述符，例如 `0`、`1`、`2`；内核还需要保存更完整的文件信息。

可以把它理解成两层：

```text
进程中的文件描述符表
0 ─────────> file 对象：标准输入
1 ─────────> file 对象：标准输出
2 ─────────> file 对象：标准错误
3 ─────────> file 对象：程序后来打开的 myfile
```

`files_struct`：进程用来保存文件描述符表的内核结构。

每个文件描述符通过表项指向一个 `file` 对象。`file` 对象保存这个打开文件的状态，例如：

- 当前读写位置；
- 打开权限；
- 对应的文件信息；
- 应该调用哪组读写操作。

文件对应的基本身份信息通常由 **inode** 保存。`inode`：内核中描述文件身份和属性的数据结构，例如文件类型、大小、权限等。

因此，打开一个文件时，不只是得到一个整数，还会在内核中建立或找到相应的 `file` 对象。

### 4.1.4 把标准输出和标准错误合并

有时我们希望正常输出和错误输出全部保存到同一个文件：

```bash
./a.out 1>log.txt 2>&1                   # 先把 stdout 接到 log.txt，再让 stderr 接到 stdout 当前指向的位置
cat log.txt                              # 查看正常输出和错误输出
ls -l a.out log.txt stream.cc            # 查看文件大小
```

这里的关键是执行顺序：

```text
1>log.txt
    ↓
文件描述符 1 ──> log.txt

2>&1
    ↓
文件描述符 2 ──> 文件描述符 1 当前指向的 log.txt
```

`2>&1` 的意思不是“把数字 2 写入数字 1”，而是让文件描述符 `2` 复制文件描述符 `1` 当前的连接关系。

顺序不能随便调换：

```bash
./a.out 2>&1 1>log.txt                   # 先让 stderr 指向原来的 stdout，再让 stdout 指向 log.txt
```

此时：

- `stdout` 进入 `log.txt`；
- `stderr` 仍然可能显示在屏幕上。

> **`1>log.txt 2>&1` 必须先重定向标准输出，再让标准错误跟随标准输出。**

提要中的“stdin 和 stdout 打印到同一个文件”应准确理解为“标准输出和标准错误写入同一个文件”；`stdin` 是输入通道，不负责打印。

### 4.1.5 内核文件缓冲区

程序频繁地直接访问磁盘会比较慢，因为磁盘访问速度远低于内存。于是，内核通常会先把数据放入**内核文件缓冲区**：内核中的一块临时内存区域，用来暂存读写数据。

```text
程序
  ↓ write
内核文件缓冲区
  ↓ 合适时机写入
磁盘
```

这样做可以减少真正访问磁盘的次数，提高效率。对程序来说，调用写操作后，数据可能先进入内核缓冲区，而不是立刻完成物理磁盘写入。

## 4.2 一切皆文件的设计【板书强调】

### 4.2.1 为什么设备也要统一处理

如果磁盘、键盘、显示器、网卡都使用完全不同的访问方式，应用程序就必须分别学习每种设备的接口：

```text
读磁盘：调用磁盘专用函数
读键盘：调用键盘专用函数
读管道：调用管道专用函数
```

这样会导致应用程序和具体硬件强绑定，换设备或换系统时就需要大量修改。

Linux 的解决办法是：在操作系统这一层，把各种资源统一抽象成“文件”，这就是**一切皆文件**。

这里的“文件”不是说显示器真的存储在磁盘文件中，而是说它们都通过相似的打开、读取、写入和关闭接口被访问。

### 4.2.2 VFS：统一访问接口

**VFS**：虚拟文件系统，是 Linux 内核提供的一层统一文件接口。

```text
应用程序
    ↓ 使用统一的系统调用
VFS（虚拟文件系统）
    ↓ 根据对象类型转发操作
磁盘驱动 / 显示器驱动 / 键盘驱动 / 管道实现 / 网卡驱动
    ↓
具体设备
```

因为应用程序只面对 VFS，所以它不需要知道底层是磁盘、键盘还是管道。

> **VFS 把不同设备包装成统一的文件接口，让上层程序用相同方式访问不同对象。**

### 4.2.3 `struct file` 和操作方法

内核中可以用一个类似下面的结构描述“一个已经打开的对象”：

```cpp
struct file {
    struct inode* f_inode;                    // 指向对象的身份和属性信息
    struct file_operations* f_op;             // 指向这个对象支持的操作方法
    int f_count;                              // 引用计数，记录有多少地方正在使用它
    int f_flags;                              // 打开时的标志，例如只读或只写
    int f_mode;                               // 访问模式
    long f_pos;                               // 当前读写位置
};
```

一个 `file` 对象可以看成包含三类核心内容：

```text
struct file
├── 属性：权限、标志、当前读写位置等
├── 缓冲区：暂存读写数据
└── 操作方法：read、write、open 等函数指针
```

其中，`f_op` 指向 `file_operations`。**函数指针**：保存函数地址的指针，通过它可以间接调用不同的函数。

```cpp
struct file_operations {
    ssize_t (*read)(...);                     // 指向读取操作的函数
    ssize_t (*write)(...);                    // 指向写入操作的函数
    int (*open)(...);                         // 指向打开操作的函数
    int (*release)(...);                      // 指向关闭或释放操作的函数
    long (*ioctl)(...);                       // 指向设备控制操作的函数
};
```

真实 Linux 内核中的 `file_operations` 还包含 `llseek`、`aio_read`、`aio_write`、`readdir`、`poll`、`mmap`、`flush`、`fsync`、`lock`、`splice_read` 等成员。除了 `owner` 等管理字段外，它们主要都是函数指针，分别对应不同的系统调用能力。

### 4.2.4 设备如何实现统一接口

不同设备的底层实现不同，但可以提供相同类型的操作入口：

```text
磁盘的 read  ──> 从磁盘读取数据
显示器的 write ──> 把数据显示到屏幕
键盘的 read  ──> 从键盘取得输入
管道的 read  ──> 从管道缓冲区取数据
```

设备驱动程序：直接和具体硬件打交道的内核代码。

驱动程序为设备实现对应操作，例如：

```cpp
int disk_read(...);                          // 磁盘驱动实现读取
int screen_write(...);                       // 显示器驱动实现写入
int keyboard_read(...);                      // 键盘驱动实现读取
```

然后把这些函数的地址填入操作表：

```cpp
struct file_operations disk_ops = {
    .read = disk_read,                       // 磁盘对象的 read 指向磁盘读取函数
    .write = nullptr                         // 该示意对象暂不提供 write
};

struct file_operations screen_ops = {
    .read = nullptr,                         // 显示器通常不提供普通 read
    .write = screen_write                    // 显示器对象的 write 指向屏幕写入函数
};
```

上层只需要调用统一形式的 `read` 或 `write`，不需要判断底层具体是哪种设备。

关键在于：函数指针的类型签名和参数形式保持统一，而函数内部的具体实现可以不同。

```text
上层调用 read(fd, buffer, size)
              ↓
        file->f_op->read
          ↙       ↘
    磁盘 read    键盘 read
```

> **访问不同设备时，上层使用统一的函数指针接口；底层只需要分别实现自己的具体函数。**

### 4.2.5 `struct device`：设备自身的信息

**设备描述结构**：保存某个设备自身状态和属性的数据结构。

它可以包含：

```cpp
struct device {
    int type;                                // 设备类型，例如磁盘或键盘
    int status;                              // 设备当前状态
    void* attributes;                        // 其他设备属性
    void* queue_head;                        // 设备请求队列的头部
};
```

设备可能需要排队处理多个请求，例如多个进程同时请求读磁盘。`queue_head` 可以指向这些等待处理的请求队列。

这里的 `device` 描述“设备本身”，而 `file` 描述“某次打开设备后形成的访问对象”，两者作用不同：

| 结构 | 描述内容 |
|---|---|
| `struct device` | 设备本身的类型、状态、请求队列 |
| `struct file` | 一次打开后的属性、位置、缓冲区和操作方法 |

### 4.2.6 系统调用、驱动程序和 `file_operations`

Linux 中，很多资源的读取都可以通过 `read` 完成：

- 读取普通文件；
- 读取系统状态；
- 从管道读取数据；
- 从设备读取数据。

很多改变资源的操作都可以通过 `write` 完成：

- 向文件写入；
- 向管道写入；
- 向设备发送数据。

```text
用户程序调用 read/write
          ↓
根据文件描述符找到 file 对象
          ↓
通过 file->f_op 找到具体函数
          ↓
驱动程序或内核对象执行真正操作
```

`file_operations` 的作用，就是把“统一的系统调用入口”和“具体的驱动实现”连接起来：

```text
系统调用 read
    ↓
file_operations.read
    ↓
具体设备的 read 实现

系统调用 write
    ↓
file_operations.write
    ↓
具体设备的 write 实现
```

每个成员通常对应一类操作或系统调用能力，例如：

| `file_operations` 成员 | 作用 |
|---|---|
| `read` | 读取数据 |
| `write` | 写入数据 |
| `open` | 打开对象 |
| `release` | 释放对象 |
| `poll` | 查询是否可以进行读写 |
| `ioctl` | 执行设备专用控制命令 |
| `mmap` | 建立内存映射 |
| `fsync` | 刷新数据，要求完成同步 |

因此，应用程序不需要为每种设备设计一套全新的调用方式；它只需要使用统一接口。C++、Java、Python、Go 等语言也都在不同层次上进行封装，使程序更容易跨平台使用，从而降低学习和开发成本，并扩大使用范围。

> **`file_operations` 是连接系统调用和驱动程序的关键数据结构；每个操作成员都把统一入口连接到具体实现。**

# 5. 缓冲区

## 5-1 什么是缓冲区

直接让 CPU 每产生一小段数据，就立刻交给磁盘或打印机，会频繁等待低速设备。为暂时存放数据，程序会从内存中划出一块空间，这块空间就是**缓冲区：先把数据暂存在内存里，合适时再集中交给设备**。

> **缓冲区是内存空间的一部分。**

根据数据流动方向，缓冲区分为：

- **输入缓冲区**：设备 → 内存，例如从键盘、磁盘读数据时暂存数据。
- **输出缓冲区**：内存 → 设备，例如把程序输出的数据暂存起来，之后再交给显示器、文件或打印机。

---

## 5-2 为什么要引入缓冲区机制

假设程序要写入 1000 个字符。如果每写 1 个字符，就访问一次磁盘，就要执行 1000 次底层操作；这会浪费大量时间。

### 不使用缓冲区

每次读写都可能执行一次**系统调用：程序请求操作系统代替自己完成底层工作**。

一次系统调用大致要经历：

```text
用户程序
  ↓ 进入内核态
操作系统内核
  ↓ 访问设备
磁盘、显示器、打印机等
  ↓ 返回用户态
用户程序
```

用户程序和操作系统内核之间的切换，以及进程上下文切换，都会消耗 CPU 时间。磁盘本身速度又远低于 CPU，因此频繁访问磁盘会严重降低效率。

### 使用缓冲区

程序先把数据集中放入内存缓冲区：

```text
多次小写入
    ↓
用户级缓冲区
    ↓ 缓冲区满或满足刷新条件
一次较大的系统调用
    ↓
操作系统和磁盘
```

这样可以减少系统调用次数和磁盘访问次数。

例如，程序要写入 1000 个字符，可以先把它们放进缓冲区，最后一次性写入，而不是执行 1000 次磁盘写操作。

### 打印机的例子

打印机速度较慢。如果 CPU 每打印一个字就等待打印机完成，CPU 就会被拖住。

更合理的做法是：

1. CPU 把整篇文档交给打印机缓冲区；
2. 打印机从缓冲区中逐步取数据并打印；
3. CPU 继续处理其他任务。

因此，缓冲区可以让高速 CPU 和低速 IO 设备协调工作，减少 CPU 等待时间。

> **引入缓冲区的主要目的，是减少低效的 IO 操作，提高整体使用效率。**

## 5-3 缓冲类型

### 用户级-语言层缓冲区

前面说的“缓冲区”，在本节主要指：

> **用户级-语言层缓冲区：由 C 标准库提供，位于用户程序一侧的内存缓冲区。**

C 标准库中的 `printf`、`fprintf`、`fputs`、`fwrite` 等库函数会使用这种缓冲区。

而直接使用文件描述符的系统调用，例如 `write`，不使用 C 标准库提供的用户级缓冲区。

| 写数据的方式 | 是否使用 C 库用户级缓冲区 | 典型接口 |
|---|---:|---|
| 库函数 | 是 | `printf`、`fwrite` |
| 系统调用 | 否 | `write` |

`stdout` 是一个 `FILE *` 流，通常对应文件描述符 `1`。库函数先把数据交给 `stdout` 的缓冲区，之后再交给操作系统。

```text
printf
  ↓
stdout 对应的用户级缓冲区
  ↓ fflush 或自动刷新
write 等系统调用
  ↓
操作系统内核中的文件缓冲区
  ↓
磁盘等硬件
```

操作系统也可能有自己的内核级缓冲区，本节重点讨论的是 C 标准库额外提供的用户级缓冲区。

系统调用不是“免费操作”。程序从用户态进入内核态，再返回用户态，都需要额外时间。因此，减少系统调用次数通常能够提高效率。

### 三种刷新策略

**刷新：把用户级缓冲区中的数据交给操作系统。**

#### 1. 立即刷新：无缓冲

每次写入都立即交给操作系统，不在用户级缓冲区中暂存。

这种模式也可称为：

- 无缓冲；
- 写透模式，`WT`；
- `FLUSH_NONE`。

```text
程序写数据
  ↓
立即调用系统调用
  ↓
操作系统
```

#### 2. 缓冲区满时刷新：全缓冲

数据先放在缓冲区中，等缓冲区装满后再刷新。

普通文件通常采用全缓冲，因为文件写入不要求每一行立刻可见，集中写入更高效。

```text
数据 → 缓冲区
          ↓ 满了
       一次刷新
```

#### 3. 遇到换行时刷新：行缓冲

数据先放入缓冲区，遇到换行符 `\n` 时刷新。

显示器通常使用行缓冲，因此：

```cpp
printf("hello\n");  // 遇到换行，通常刷新 stdout
```

提要中默认行缓冲区大小为 `1024` 字节。实际大小可能由具体实现决定。

| 刷新策略 | 什么时候刷新 | 常见场景 |
|---|---|---|
| 无缓冲 | 每次写入立即刷新 | 需要立刻输出的场景 |
| 全缓冲 | 缓冲区满时刷新 | 普通文件 |
| 行缓冲 | 遇到换行时刷新 | 显示器、终端 |

除了策略本身，缓冲区还可能在以下情况下刷新：

1. 缓冲区已满；
2. 主动调用 `fflush`；
3. 进程正常结束，C 库统一刷新缓冲区。

### 数据流动的本质

把数据从一个地方交给另一个地方，本质上通常是一次拷贝：

```text
用户变量
  ↓ 拷贝
C 库用户级缓冲区
  ↓ 拷贝
操作系统内核缓冲区
  ↓ 拷贝
设备
```

因此：

> **计算机中数据流动的本质，就是在不同存储位置之间不断拷贝数据。**

### 实验一：`printf` 和 `write` 的缓冲区别

下面的程序把标准输出 `stdout` 关闭，再让 `open` 打开的文件占用文件描述符 `1`。

```cpp
#include <stdio.h>      // 提供 printf 和 fflush
#include <fcntl.h>      // 提供 open 的标志
#include <unistd.h>     // 提供 close 和 write
#include <string.h>     // 提供 strlen

int main()
{
    close(1);  // 关闭标准输出，对应文件描述符 1

    int fd = open("log.txt", O_CREAT | O_WRONLY | O_APPEND, 0666);  // 让 log.txt 占用 fd 1

    printf("fd:%d\n", fd);  // 通过 stdout 写入用户级缓冲区

    printf("hello bit\n");  // 通过 stdout 写入用户级缓冲区
    printf("hello bit\n");  // 继续写入 stdout 缓冲区
    printf("hello bit\n");  // 继续写入 stdout 缓冲区

    const char *msg = "write directly\n";  // 准备直接写入文件的字符串
    write(fd, msg, strlen(msg));  // 绕过 C 库缓冲区，直接执行系统调用

    return 0;  // 进程退出时，C 库会刷新 stdout 缓冲区
}
```

编译运行：

```bash
gcc test.c -o test  # 编译程序
./test              # 运行程序
cat log.txt         # 查看文件内容
```

因为此时 `stdout` 被重定向到普通文件，所以它变成全缓冲。`printf` 写入的内容没有立即进入文件，直到进程退出时才统一刷新；而 `write` 没有经过 C 库缓冲区，所以立即进入文件。

如果希望 `printf` 的内容在程序继续运行时就进入文件，可以主动刷新：

```cpp
#include <stdio.h>      // 提供 printf 和 fflush
#include <fcntl.h>      // 提供 open 的标志
#include <unistd.h>     // 提供 close 和 write
#include <string.h>     // 提供 strlen

int main()
{
    close(1);  // 关闭标准输出

    int fd = open("log.txt", O_CREAT | O_WRONLY | O_APPEND, 0666);  // 打开文件并占用 fd 1

    printf("fd:%d\n", fd);  // 写入 stdout 用户级缓冲区
    printf("hello bit\n");  // 写入 stdout 用户级缓冲区
    printf("hello bit\n");  // 写入 stdout 用户级缓冲区
    printf("hello bit\n");  // 写入 stdout 用户级缓冲区

    fflush(stdout);  // 立即把 stdout 缓冲区交给操作系统

    const char *msg = "write directly\n";  // 准备直接写入文件的数据
    write(fd, msg, strlen(msg));  // 直接调用系统调用写入文件

    return 0;  // 进程结束
}
```

> **`printf` 是否立即可见，取决于 `stdout` 的缓冲策略；`write` 不经过 C 库用户级缓冲区。**

### 实验二：`stderr` 通常无缓冲

`stderr` 是标准错误流，对应文件描述符 `2`。它通常采用无缓冲策略，错误信息需要尽快显示，因此不需要等待 `fflush`。

```cpp
#include <stdio.h>      // 提供 perror
#include <fcntl.h>      // 提供 open
#include <unistd.h>     // 提供 close

int main()
{
    close(2);  // 关闭标准错误流，对应文件描述符 2

    int fd = open("error.log", O_CREAT | O_WRONLY | O_APPEND, 0666);  // 让 error.log 占用 fd 2

    perror("hello world");  // stderr 通常无缓冲，内容立即交给操作系统

    close(fd);  // 关闭文件描述符

    return 0;  // 结束进程
}
```

文件中通常能看到类似内容：

```text
hello world: Success
```

`perror` 会在给定文字后面继续输出当前错误码对应的解释；本次没有发生错误，所以解释可能是 `Success`。

## 5-4 `FILE`

### `FILE` 和文件描述符的关系

C 库函数和系统调用是两层不同的接口：

```text
printf / fwrite / fopen
        ↓ C 库封装
write / open 等系统调用
        ↓
操作系统
```

但访问文件最终仍然需要文件描述符。因此：

> **C 库的 `FILE` 结构体内部必定封装了一个文件描述符。**

可以把 `FILE` 理解为 C 库为了管理一个打开的文件而维护的一份结构体对象。它不仅保存文件描述符，还保存缓冲区位置、刷新策略等信息。

### `FILE` 的定义位置

在 `/usr/include/stdio.h` 中，可以看到类似定义：

```cpp
typedef struct _IO_FILE FILE;  // 把 struct _IO_FILE 起别名为 FILE
```

`FILE` 本身是 C 标准库中的一个结构体类型。

在 `/usr/include/libio.h` 中，可以看到它的关键字段。不同系统版本的字段可能略有差异，核心含义如下：

```cpp
struct _IO_FILE
{
    int _flags;  // 文件流的状态和标志

    char *_IO_read_ptr;   // 当前读取位置
    char *_IO_read_end;   // 读取缓冲区结束位置
    char *_IO_read_base;  // 读取缓冲区起始位置

    char *_IO_write_base; // 写入缓冲区起始位置
    char *_IO_write_ptr;  // 当前写入位置
    char *_IO_write_end;  // 写入缓冲区结束位置

    char *_IO_buf_base;   // 总缓冲区起始位置
    char *_IO_buf_end;    // 总缓冲区结束位置

    char *_IO_save_base;  // 保存区域起始位置
    char *_IO_backup_base;// 备用区域起始位置
    char *_IO_save_end;   // 保存区域结束位置

    struct _IO_marker *_markers;  // 文件流标记
    struct _IO_FILE *_chain;      // 连接其他 FILE 对象

    int _fileno;  // 封装的文件描述符
};
```

其中 `_fileno` 最关键，它说明 `FILE` 最终仍然要依靠文件描述符访问文件。

C 语言中，每个文件流对象都有自己的用户级缓冲区：

```text
FILE *fp1 → fp1 自己的缓冲区
FILE *fp2 → fp2 自己的缓冲区
stdout   → stdout 自己的缓冲区
stderr   → stderr 自己的缓冲区
```

> **`FILE` 是 C 标准库中的结构体对象，内部封装了文件描述符，并管理该文件流的用户级缓冲区。**

### `fopen` 和 `fflush`

语法：

```cpp
FILE *fopen(const char *path, const char *mode);  // 打开文件并返回 FILE 指针
int fflush(FILE *stream);                         // 刷新指定文件流的用户级缓冲区
```

功能：

- `fopen`：打开指定路径的文件，创建并返回一个 `FILE *`；
- `fflush`：把指定 `FILE` 缓冲区中的输出数据交给操作系统。

示例：

```cpp
#include <stdio.h>  // 提供 fopen、fputs、fflush、fclose

int main()
{
    FILE *fp = fopen("log.txt", "w");  // 以写方式打开文件

    fputs("hello file\n", fp);  // 把字符串写入 fp 的用户级缓冲区

    fflush(fp);  // 立即刷新 fp 的输出缓冲区

    fclose(fp);  // 关闭文件流并完成必要的刷新

    return 0;  // 正常结束
}
```

注意：`fflush` 主要用于输出流。它只保证数据从 C 库用户级缓冲区交给操作系统，不等于数据已经真正写入物理磁盘。

### `fork` 和缓冲区实验

下面的程序分别使用库函数和系统调用输出数据，再执行 `fork`。

```cpp
#include <stdio.h>      // 提供 printf 和 fwrite
#include <string.h>     // 提供 strlen
#include <unistd.h>     // 提供 write 和 fork

int main()
{
    const char *msg1 = "hello fwrite\n";  // 准备给 fwrite 的字符串
    const char *msg2 = "hello write\n";   // 准备给 write 的字符串

    printf("hello printf\n");  // 通过 stdout 用户级缓冲区输出
    fwrite(msg1, strlen(msg1), 1, stdout);  // 通过 stdout 用户级缓冲区输出

    write(1, msg2, strlen(msg2));  // 直接通过文件描述符 1 调用系统调用

    fork();  // 创建子进程，父子进程各自拥有一份当前用户级缓冲区

    return 0;  // 父子进程退出时分别刷新各自的 stdout 缓冲区
}
```

在显示器上运行时：

```bash
gcc hello.c -o hello  # 编译程序
./hello               # 在显示器上运行
```

通常看到：

```text
hello printf
hello fwrite
hello write
```

每行只出现一次，因为显示器通常使用行缓冲，两个库函数输出末尾都有 `\n`，在 `fork` 之前已经刷新。`write` 本来就没有使用 C 库缓冲区。

把标准输出重定向到文件：

```bash
./hello > file  # 把标准输出重定向到普通文件
cat file        # 查看文件内容
```

通常看到：

```text
hello write
hello printf
hello fwrite
hello printf
hello fwrite
```

原因如下：

1. 输出到显示器时，`stdout` 使用行缓冲，遇到 `\n` 就刷新；
2. 输出到普通文件时，`stdout` 变成全缓冲；
3. `printf` 和 `fwrite` 的数据还留在用户级缓冲区中；
4. `fork` 发生时，父子进程各自拥有一份相同的缓冲区；
5. 父进程退出时刷新一次，子进程退出时再刷新一次；
6. `write` 没有使用 C 库用户级缓冲区，所以只写入一次。

```text
fork 前：
父进程缓冲区：hello printf、hello fwrite

fork 后：
父进程缓冲区：hello printf、hello fwrite
子进程缓冲区：hello printf、hello fwrite

两个进程分别退出：
父进程刷新一次
子进程刷新一次
```

> **`fork` 会复制尚未刷新的用户级缓冲区，因此父子进程退出时可能各自刷新一次，导致库函数输出两遍；`write` 没有这层缓冲，所以只输出一遍。**

这里的缓冲区是 C 标准库额外添加的用户级缓冲区，不属于操作系统本身。操作系统也有内核级缓冲区，但本节不展开。

## 5-5 简单设计一个 libc 库

前面已经看到，C 库函数本质上是在系统调用之上增加了缓冲区和管理逻辑。现在模拟设计一个简化版的 C 文件库。

### `my_stdio.h`

```cpp
#ifndef MY_STDIO_H  // 防止头文件被重复包含
#define MY_STDIO_H  // 定义头文件保护宏

#include <stddef.h>  // 提供 size_t 等类型

#define SIZE 1024  // 定义用户级输出缓冲区大小

#define FLUSH_NONE 0  // 无缓冲
#define FLUSH_LINE 1  // 行缓冲
#define FLUSH_FULL 2  // 全缓冲

struct IO_FILE
{
    int flag;            // 保存刷新策略
    int fileno;          // 保存底层文件描述符
    char outbuffer[SIZE];// 保存用户级输出缓冲区
    int cap;             // 保存缓冲区容量
    int size;            // 保存当前已经使用的字节数
};

typedef struct IO_FILE mFILE;  // 给结构体类型起别名 mFILE

mFILE *mfopen(const char *filename, const char *mode);  // 打开文件并创建 mFILE
int mfwrite(const void *ptr, int num, mFILE *stream);  // 写入用户级缓冲区
void mfflush(mFILE *stream);                          // 刷新用户级缓冲区
void mfclose(mFILE *stream);                           // 刷新并关闭文件

#endif  // 结束头文件保护
```

这个结构体保存了四类信息：

- `fileno`：底层文件描述符；
- `outbuffer`：用户级输出缓冲区；
- `size`：缓冲区中已经存放了多少数据；
- `flag`：采用哪种刷新策略。

### `my_stdio.c`

```cpp
#include "my_stdio.h"  // 引入自定义文件流结构和函数声明
#include <fcntl.h>     // 提供 open 和文件打开标志
#include <unistd.h>    // 提供 write、close、fsync
#include <stdlib.h>    // 提供 malloc 和 free
#include <string.h>    // 提供 memcpy
#include <stdio.h>     // 提供 perror

mFILE *mfopen(const char *filename, const char *mode)
{
    int fd = -1;  // 保存 open 返回的文件描述符

    if (mode[0] == 'r')  // 判断是否以读方式打开
    {
        fd = open(filename, O_RDONLY);  // 以只读方式打开文件
    }
    else if (mode[0] == 'w')  // 判断是否以覆盖写方式打开
    {
        fd = open(filename, O_CREAT | O_WRONLY | O_TRUNC, 0666);  // 创建并清空文件
    }
    else if (mode[0] == 'a')  // 判断是否以追加方式打开
    {
        fd = open(filename, O_CREAT | O_WRONLY | O_APPEND, 0666);  // 创建并追加写入文件
    }

    if (fd < 0)  // 判断文件是否打开失败
    {
        perror("open");  // 打印失败原因
        return NULL;  // 返回空指针表示失败
    }

    mFILE *stream = (mFILE *)malloc(sizeof(mFILE));  // 为自定义 FILE 结构申请空间

    if (stream == NULL)  // 判断动态内存申请是否失败
    {
        close(fd);  // 释放已经打开的文件描述符
        return NULL;  // 返回空指针表示失败
    }

    stream->fileno = fd;       // 保存底层文件描述符
    stream->flag = FLUSH_LINE; // 设置为行缓冲
    stream->size = 0;          // 初始时缓冲区没有数据
    stream->cap = SIZE;        // 设置缓冲区容量

    return stream;  // 返回自定义文件流指针
}

void mfflush(mFILE *stream)
{
    if (stream == NULL)  // 判断文件流指针是否有效
    {
        return;  // 无效时直接返回
    }

    if (stream->size > 0)  // 只有缓冲区有数据时才执行写入
    {
        write(stream->fileno, stream->outbuffer, stream->size);  // 写入内核文件缓冲区
        fsync(stream->fileno);  // 请求把内核中的数据刷新到外部设备
        stream->size = 0;  // 清空用户级缓冲区中的数据
    }
}

int mfwrite(const void *ptr, int num, mFILE *stream)
{
    if (ptr == NULL || stream == NULL || num <= 0)  // 检查参数是否合法
    {
        return 0;  // 参数错误时表示没有写入数据
    }

    const char *src = (const char *)ptr;  // 把输入地址看作字符数组地址
    int written = 0;  // 记录已经处理的字节数

    while (written < num)  // 直到所有数据都被处理
    {
        int remain = stream->cap - stream->size;  // 计算缓冲区剩余空间
        int count = num - written;  // 计算还没有处理的数据量

        if (count > remain)  // 判断待写数据是否超过缓冲区剩余空间
        {
            count = remain;  // 本轮只拷贝能放入缓冲区的数据
        }

        memcpy(stream->outbuffer + stream->size, src + written, count);  // 把数据拷贝进用户级缓冲区
        stream->size += count;  // 增加缓冲区已使用字节数
        written += count;  // 增加已经处理的数据量

        if (stream->size == stream->cap)  // 判断缓冲区是否已经写满
        {
            mfflush(stream);  // 缓冲区满时刷新
        }

        if (stream->flag == FLUSH_LINE && stream->size > 0 &&
            stream->outbuffer[stream->size - 1] == '\n')  // 判断行缓冲是否遇到换行符
        {
            mfflush(stream);  // 遇到换行符时刷新
        }
    }

    return written;  // 返回实际处理的字节数
}

void mfclose(mFILE *stream)
{
    if (stream == NULL)  // 判断文件流指针是否有效
    {
        return;  // 无效时直接返回
    }

    if (stream->size > 0)  // 判断关闭前是否还有未刷新数据
    {
        mfflush(stream);  // 关闭前先刷新用户级缓冲区
    }

    close(stream->fileno);  // 关闭底层文件描述符
    free(stream);  // 释放自定义文件流结构占用的内存
}
```

`mfflush` 中的数据流动是：

```text
mFILE.outbuffer
    ↓ write
操作系统内核中的文件缓冲区
    ↓ fsync
磁盘等外部设备
```

这里的 `write` 负责把数据从用户级缓冲区交给内核，`fsync` 请求内核继续把数据刷新到外部设备。`fsync` 代价较高，真实 C 库不会在每次普通刷新时都强制调用它。

### `main.c`

```cpp
#include "my_stdio.h"  // 引入自定义文件流接口
#include <stdio.h>     // 提供 snprintf
#include <unistd.h>    // 提供 sleep

int main()
{
    mFILE *fp = mfopen("./log.txt", "a");  // 以追加方式打开日志文件

    if (fp == NULL)  // 判断文件是否打开成功
    {
        return 1;  // 打开失败时返回错误码
    }

    for (int i = 0; i < 5; ++i)  // 循环生成五条日志
    {
        char msg[128];  // 准备保存一条日志的字符数组

        snprintf(msg, sizeof(msg), "message %d\n", i);  // 格式化生成日志文本

        mfwrite(msg, sizeof(msg) - sizeof(msg) + 10, fp);  // 把日志写入用户级缓冲区
        mfflush(fp);  // 主动刷新，确保每秒写入一条日志

        sleep(1);  // 暂停一秒，便于观察文件变化
    }

    mfclose(fp);  // 刷新剩余数据并关闭文件

    return 0;  // 程序正常结束
}
```

上面 `mfwrite` 的长度应当准确使用实际字符串长度，修改为下面更稳妥的版本：

```cpp
#include "my_stdio.h"  // 引入自定义文件流接口
#include <stdio.h>     // 提供 snprintf
#include <string.h>    // 提供 strlen
#include <unistd.h>    // 提供 sleep

int main()
{
    mFILE *fp = mfopen("./log.txt", "a");  // 以追加方式打开日志文件

    if (fp == NULL)  // 判断文件是否打开成功
    {
        return 1;  // 打开失败时返回错误码
    }

    {

        snprintf(msg, sizeof(msg), "message %d\n", i);  // 格式化生成日志文本

        mfwrite(msg, strlen(msg), fp);  // 把有效字符串写入用户级缓冲区
        mfflush(fp);  // 主动刷新，确保每秒写入一条日志

        sleep(1);  // 暂停一秒，便于观察文件变化
    }

    return 0;  // 程序正常结束
}
```

这个模拟库展示了 C 库文件接口的核心思路：

```text
mfopen
  ↓
open 获取 fd
  ↓
创建 mFILE 和用户级缓冲区
  ↓
mfwrite 把数据拷贝进缓冲区
  ↓
mfflush 调用 write
  ↓
mfclose 刷新并 close
```

> **C 库文件接口的核心，就是在文件描述符之上增加 `FILE` 结构体和用户级缓冲区，以减少系统调用次数并统一管理刷新、关闭等操作。**
