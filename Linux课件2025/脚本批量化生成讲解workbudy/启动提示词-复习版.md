2. 目录汇总（取对应章节的标题层级作为完整骨架，备查）：`D:\个人知识库01\规划\01_规划\C++学习路线\课件以及老师的代码\Linux课件2025\Linux 系统编程\Linux 系统编程 - 目录汇总.md`

工作流程：

1. 我在末尾指定要处理的课（或直接指定聊天版文件）
2. 你确认聊天版文件路径，并从目录汇总里提取该章的标题层级，存成《课名-大纲.md》（完整骨架，备查）
3. 运行脚本生成复习版，两种模式：
   - **单源模式**（旧）：`python generate_review.py "<聊天版.md>" "<课件骨架.md>" "<输出名.md>" --depth 2`
   - **多源整合模式（博客版，2026-10-10 起优先采用）**：把聊天版 + 对应 PDF 课件 markdown（在 `Linux系统编程markdown格式\` 目录，文件名如 `3.进程概念.md`）一起作为材料发给 GPT：
     ```
     python generate_review.py --sources "<课件markdown.md>" "<聊天版.md>" --outline "<课件骨架.md>" --output "<输出名.md>" --depth 3 --prompt blog_system_prompt.txt
     ```
     - `--sources` 后跟多份材料，按顺序拼接（建议课件 markdown 在前、聊天版在后）
     - 博客版参数：`--depth 3`（保留三级标题，约 30 个）+ `--prompt blog_system_prompt.txt`（内容不过度压缩：保留简要解释、内核源码片段、带注释命令，篇幅约材料整合去重后的 20%~30%）
     - 课件 markdown 所在目录会作为输出落盘目录，生成后把文件移动到 `脚本批量化生成讲解workbudy\` 统一保管；标题若与骨架有细微出入（如多了句号）用 sed 手动修正
   - `--depth 2`（默认提示词 review_system_prompt.txt）为**单源复习版**参数：骨架只保留到二级，**复习版最终标题极少（1 个大标题 + 各大节，通常 6 个左右）**，节内主题用 `**加粗引导词**：` + 列表/表格组织，不出现三级及以下标题
   - 默认用中转站 GPT（先 `cp config.zhehentiaohe.json config.json`，跑完 `cp config.json.kimi-backup config.json` 恢复 Kimi）
4. 生成完自查三点：**标题是否就只有骨架给的那几个（不得多出子标题）**、**关键命令与易混点有没有漏**、**结尾是否完整收束（若被截断脚本会自动「继续」补全）**；有问题就重跑

**命名规范（必须遵守）**：复习版文件名固定为 `源文件名-复习版.md`（源文件名去掉 .md 再加 `-复习版.md`）。若这个名字已被旧版本占用，**把旧文件改名为 `xxx-复习版-旧规则xx标题.md` 保留**，让规范名始终指向最新一版；不要用 `-v2`、`-新版` 之类的后缀替代规范名。

复习版的定位：**很久以后只看这一份就能回忆起本节大部分内容**——标题极少、内容高密度，只留结论/要点/关键命令/易混对比，删掉所有推导、类比、铺垫。
