# 1. 软件包管理器

## 1-1 什么是软件包

### 从源码安装为什么麻烦

假设你想在 Linux 上安装一个软件。最原始的方法是下载**源码**，也就是软件作者写出的、还没有变成可直接运行程序的代码，然后自己**编译**，也就是把代码翻译成电脑可以执行的文件。

这通常要经历：

```text
下载源码 → 准备编译工具 → 处理依赖 → 编译 → 安装
```

其中任何一步缺少文件、版本不匹配或配置错误，都可能导致安装失败。因为源码安装太麻烦，所以有人提前把常用软件编译好，打包成文件，放到服务器上供大家下载。

这种提前编译并整理好的文件，就叫**软件包**。

> **软件包解决的问题：把“自己编译软件”的复杂过程，变成“下载后安装”。**

### 软件包和包管理器

软件包可以理解为 Windows 上的安装程序；**包管理器**则是管理软件包的工具，类似手机上的应用商店。应用商店不仅能下载应用，还能查找、安装、卸载应用；包管理器也负责这些事情。

| 概念 | 生活中的类比 | 作用 |
|---|---|---|
| 软件包 | Windows 安装程序 | 提供已经准备好的软件 |
| 包管理器 | 手机应用商店 | 查找、下载、安装、卸载软件 |

Linux 中常见的包管理器有：

- `yum`：主要用于 Fedora、Red Hat、CentOS 系统。全称是 `Yellowdog Updater, Modified`。
- `apt`：主要用于 Ubuntu 系统。

### 包管理器最重要的价值：解决依赖

假设软件 A 运行时还需要软件 B，这种“软件运行还需要别的软件陪着”的关系，叫**依赖**。如果 B 没有安装，A 就可能无法安装或运行，这叫**依赖缺失**；如果 B 的版本太旧或太新，A 也可能无法正常工作，这叫**版本兼容性问题**。

手动安装时，你需要自己找齐依赖并确认版本。包管理器会根据软件包记录，自动查找、下载并安装这些依赖。

```text
安装软件 A
  ↓
发现 A 依赖软件 B
  ↓
检查 B 是否存在、版本是否合适
  ↓
自动安装或调整 B
  ↓
完成 A 的安装
```

> **包管理器的核心价值是自动解决依赖，包括依赖缺失和版本兼容性问题。**

### 安装的本质和权限要求

安装软件的本质主要是两件事：

1. 从网络上的软件源下载软件包；
2. 把文件拷贝到系统规定的位置。

因为这些文件属于整个系统，而不是某一个普通用户，所以安装、卸载软件通常需要管理员权限。Linux 中权限最高的管理员账户叫 **root**；普通用户可以在命令前使用 `sudo`，临时请求 root 权限执行一次命令。

软件安装到系统后通常只需安装一次，系统中的所有用户都可以使用，不需要每个用户重复安装。

> **软件安装的本质是“网络下载 + 文件拷贝”，因此通常必须使用 root 权限；安装一次后，所有用户都能使用。**

## 1-2 Linux 软件生态

### 什么是操作系统生态

**操作系统**是管理电脑硬件、文件和程序运行的基础软件，例如 Linux、Windows 和 macOS。评价一个操作系统不能只看它的内核版本。

**内核**是操作系统中负责管理 CPU、内存、硬盘和网络等硬件的核心部分。除此之外，还要看：

- 有没有活跃的社区；
- 有没有清楚的文档；
- 使用它的人多不多；
- 遇到问题能不能搜索到答案；
- 有没有足够多的配套软件。

这些围绕操作系统形成的硬件、软件、用户、文档和社区环境，叫做**软件生态**。配套软件当然是生态的一部分：如果系统本身很好，却没有编辑器、编译器、服务器等常用软件，使用体验仍然会很差。

> **操作系统的好坏不仅取决于内核，还取决于社区、文档、用户和配套软件共同形成的生态。**

### 软件从哪里来

软件通常由开发者发布源码。社区中的其他人会把源码编译、测试并整理成适合某个 Linux 发行版的软件包，再放到官方软件源服务器上。

**软件源**就是集中存放软件包、供包管理器下载的服务器或地址。

```text
开发者发布源码
      ↓
社区编译、测试、打包
      ↓
放入官方软件源服务器
      ↓
yum / apt 下载并安装
```

例如，CentOS 和 Ubuntu 都有自己的官方软件源网站。用户不需要手动打开网站逐个下载，包管理器会自动访问软件源。

### 开源和生态

**开源**是指软件的源代码可以按照许可证查看、使用、修改和再发布。开源的本质不仅是技术方式，也是一种商业模式：软件本身可能免费开放，但企业可以通过云服务器、技术服务、商业支持等方式获得收入。

云服务器厂商愿意投入资金建设服务器、镜像源和技术服务，是因为完整的软件生态会吸引更多用户使用相关系统和云服务；用户越多，生态越完善，生态越完善，又会吸引更多用户。

### 软件源和镜像源

电脑必须知道去哪里下载软件。`yum` 或 `apt` 内部保存了软件源的下载地址，因此它们能够自动找到软件包。

如果把默认下载地址更换成另一个服务器地址，就叫**切换镜像源**。**镜像源**是官方软件源的一个复制站点，通常放在距离用户更近的地方，以提高下载速度。

国内常见的镜像源包括：

- 阿里云；
- 清华大学 TUNA；
- 中国科学技术大学 USTC。

> **更改软件包下载地址就是切换镜像源；镜像源通常用于让软件包下载更快。**

无论软件包来自哪个镜像源，依赖关系仍然由 `yum` 或 `apt` 自动处理。

## 1-3 `yum` 具体操作

### 使用前提：网络畅通

因为安装过程需要从服务器下载软件包，所以网络不通时，安装一定可能失败。可以先使用 `ping` 命令测试是否能连通网站。

**语法：**

```bash
ping 网站地址
```

**功能：**向指定网站发送测试请求，检查网络是否能够连通。

**示例：**

```bash
ping www.baidu.com
```

**注意事项：**如果无法连通，先解决网络问题，再执行安装命令。

### 三板斧：查、装、卸

#### 1. 查：查找软件包

软件源中可能有很多软件包，直接列出全部内容会很长，因此需要使用 `grep` 筛选包含指定文字的结果。`grep` 是按关键词过滤文本的命令。

**语法：**

```bash
yum list | grep 包名
```

其中 `|` 叫**管道符**，作用是把前一个命令的输出交给后一个命令继续处理。

**功能：**列出软件源中的软件包，并筛选出名称中包含指定关键词的软件包。

**示例：**

```bash
yum list | grep vim
```

**注意事项：**这里的 `vim` 只是搜索关键词，可以替换成你要查找的软件名。

#### 2. 装：安装软件包

**语法：**

```bash
sudo yum install [-y] 包名
```

其中 `[-y]` 表示可选参数。`-y` 会自动回答安装过程中的确认问题。

**功能：**下载并安装指定的软件包，同时自动处理它需要的依赖。

**示例：**

```bash
sudo yum -y install man-pages
```

`man-pages` 是一组帮助文档软件包，安装后可以查看许多 Linux 命令的说明。

**注意事项：**

- 安装通常需要 `sudo` 或 root 权限；
- 不加 `-y` 时，安装过程中通常会要求手动确认；
- `yum` 同一时刻只能进行一个安装或卸载操作，不能同时运行多个 `yum` 安装命令，否则可能报错。

#### 3. 卸：卸载软件包

**语法：**

```bash
sudo yum remove [-y] 包名
```

**功能：**卸载指定的软件包。

**示例：**

```bash
sudo yum -y remove man-pages
```

**注意事项：**卸载前要确认软件名称，避免误删其他程序需要的依赖。

### Ubuntu 中的对应命令

Ubuntu 使用 `apt`，基本操作与 `yum` 类似。

| 目的 | CentOS / Red Hat | Ubuntu |
|---|---|---|
| 搜索软件 | `yum list \| grep 包名` | `apt search 包名` |
| 查看软件信息 | 通过 `yum` 查询 | `apt show 包名` |
| 安装软件 | `sudo yum install 包名` | `sudo apt install 包名` |
| 卸载软件 | `sudo yum remove 包名` | `sudo apt remove 包名` |

例如，在 Ubuntu 中安装软件：

```bash
sudo apt install -y 软件包名
```

这里仍然需要 `sudo`，因为安装会修改整个系统。

### 软件包名称怎么看

软件包名称中通常包含软件版本、发行信息、系统版本和 CPU 架构等内容。例如：

```text
软件名-主版本号.次版本号.源程序发行号-软件包发行号.el7.x86_64
```

各部分含义如下：

| 部分 | 含义 |
|---|---|
| 主版本号、次版本号 | 软件自身的版本 |
| 源程序发行号 | 这份源码发布的编号 |
| 软件包发行号 | 社区重新打包或修订软件包的编号 |
| `el7` | 面向 Enterprise Linux 7，通常对应 CentOS 7 或 Red Hat 7 |
| `x86_64` | 面向 64 位 x86 CPU |
| `i686` | 面向 32 位 x86 CPU |

软件查询结果最后一列通常是软件源名称，例如 `base`。软件源名称可以类比为“软件来自哪个应用商店”。

### 不知道安装什么软件怎么办

刚开始学习时，不知道软件名称和用途是正常的。软件安装通常不是先把所有软件都装一遍，而是遇到具体需求时再安装：

```text
出现具体任务
  ↓
发现缺少某个工具
  ↓
搜索工具名称和安装方法
  ↓
使用包管理器安装
```

> **软件不是靠提前全部安装来学习，而是由实际需求驱动：需要什么，再查什么、装什么。**

## 1-4 安装源

### CentOS 的 yum 源配置

CentOS 中保存 `yum` 软件源配置文件的目录是：

```text
/etc/yum.repos.d/
```

**目录**是用来存放文件的文件夹；这里的路径表示根目录下的 `etc/yum.repos.d` 文件夹。

这个目录中的文件会告诉 `yum`：

- 软件源叫什么；
- 下载地址是什么；
- 软件包是否启用；
- 软件源中包含哪些内容。

> **`/etc/yum.repos.d/` 是 CentOS 的 yum 源配置文件目录。**

#### `CentOS-Base.repo`：标准源

```text
/etc/yum.repos.d/CentOS-Base.repo
```

`CentOS-Base.repo` 是 CentOS 的标准软件源配置文件。`base` 表示基础、稳定的软件源，里面通常包含系统常用软件。

#### `epel.repo`：扩展源

```text
/etc/yum.repos.d/epel.repo
```

`epel` 表示扩展软件源，里面包含标准源没有提供的一些额外软件。

如果需要安装并启用 EPEL 扩展源，可以执行：

```bash
sudo yum install -y epel-release
```

这条命令安装的是 `epel-release` 配置包，它的作用是把 EPEL 软件源信息加入系统，使 `yum` 之后能够使用 EPEL 源。

### Ubuntu 的软件源配置

Ubuntu 的标准软件源配置文件是：

```text
/etc/apt/sources.list
```

扩展软件源配置文件通常放在：

```text
/etc/apt/sources.list.d/
```

两者的关系是：

| 路径 | 作用 |
|---|---|
| `/etc/apt/sources.list` | Ubuntu 的标准软件源 |
| `/etc/apt/sources.list.d/` | Ubuntu 的扩展软件源配置目录 |

### 云服务器的软件源

许多云服务器在创建系统时，已经将软件源设置为国内镜像地址。因此在云服务器上使用 `yum` 或 `apt` 时，通常不需要自行更换软件源。
