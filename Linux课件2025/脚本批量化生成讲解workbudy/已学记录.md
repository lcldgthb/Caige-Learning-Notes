## 第 3 课 进程概念

- 冯诺依曼体系：五大部件、CPU 和外设都只和内存打交道、存储金字塔、QQ 聊天/发文件数据流
- 操作系统：概念（广义=外壳+狭义=内核）、设计目的（对下管理是手段、对上服务是目的）、管理方法论（先描述 struct 再组织链表）、系统调用 vs 库函数、OS 不相信任何用户
- 进程基本概念：进程 = task_struct(PCB) + 代码和数据、对进程的管理 = 对链表的增删查改、task_struct 内容分类
- 查看与控制：ps aux/axj、/proc/PID（exe/cwd）、kill -9、getpid/getppid、命令行进程的父进程是 bash
- fork：父子代码共享数据写时拷贝、两个返回值（父得子 PID / 子得 0）、fork 三个经典问题、if/else 分流
- 进程状态：运行（runqueue 中即 running）/阻塞（设备等待队列）/挂起（换出到 swap）；状态变化 = 队列间流动；list_head 嵌入式双向链表
- 内核状态：R/S/D（不可中断）/T/t（gdb 追踪）/X/Z；僵尸进程（子退出父不读取→内存泄漏）与孤儿进程（被 1 号 init/systemd 领养）
- 优先级：PRI（默认 80，越小越优先）、NI（修正数据，-20~19，PRI(new)=PRI(old)+nice）、top+r 修改；竞争/独立/并行/并发
- 进程切换：时间片、上下文 = CPU 寄存器内容保存到 task_struct 再恢复
- O(1) 调度：一个 CPU 一个 runqueue、queue[140]（下标=优先级，FIFO）、bitmap[5] 快速定位、active/expired 指针 swap
- 环境变量：bash 有 argv 和 environ 两张表、PATH/HOME/SHELL、export/env/unset/set、三种代码获取方式（main 第三参数 / extern environ / getenv）、环境变量从 ~/.bash_profile 等配置文件读来、全局性=被子进程继承、本地变量不继承、export 是内建命令
- 程序地址空间：4G 布局（代码段→数据段→堆→共享区→栈→命令行参数/环境变量→内核）、虚拟地址实验（fork 后地址相同值不同）、页表映射（1 进程 1 空间 1 套页表）、大富翁与 38 线类比、mm_struct 与 VMA（链表+红黑树并存）、虚拟地址空间三大收益（有序/保护/解耦合）、写时拷贝

## 第 4 课 进程控制

- 进程创建：fork 内部（分配新内存块→拷贝父 PCB→添加进程列表→返回调度）、写时拷贝（代码共享数据写时拷贝）、fork 常规用法（父子分流 / exec 新程序）、fork 失败原因
- 进程终止：退出场景（正确/错误/异常）、退出码（0 成功 / 128+n 信号 / strerror）、exit 与 _exit 区别（exit 刷新缓冲区 _exit 不刷新）、return 等同于 exit(n)
- 进程等待：wait/waitpid、status 低16位位图（高8位退出码低7位信号）、WIFEXITED/WEXITSTATUS、阻塞等待 vs 非阻塞等待（WNOHANG 轮询）、非阻塞回调机制
- 进程程序替换：exec 系列（execl/execlp/execle/execv/execvp/execve）、命名规律 l/v/p/e、只有 execve 是真正的系统调用、exec 成功不返回 PID 不变、环境变量三种传入方式
- 自主 Shell：fork→execvp→waitpid 循环、内建命令（cd/export/env/echo）由 shell 自己执行不创建子进程、strtok 解析命令行、lastcode 保存退出码供 echo $? 使用

## 第 5 课 基础IO

- 文件概念：文件 = 内容 + 属性（元数据）、空文件也占磁盘空间、文件操作本质 = 进程对文件的操作、读写本质走系统调用而非库函数、内存文件（被打开）与磁盘级文件
- C 文件接口：fopen/fwrite/fread/fclose、/proc/PID 的 cwd 与 exe（fopen 不带路径默认创建在 cwd）、stdin/stdout/stderr 三个标准流（FILE*）、打开方式 r/r+/w/w+/a/a+（w 先清空、a 追加）
- 系统调用：open(pathname, flags[, mode])、read/write/close/lseek；flags 用比特位传标志（O_RDONLY/O_WRONLY/O_RDWR 必选其一，O_CREAT/O_TRUNC/O_APPEND 组合）；umask 影响创建权限；成功返回 fd 失败 -1
- fd：本质是 files_struct 中 fd_array 指针数组的下标（task_struct→files→fd_array→struct file）；默认 0=键盘/1=显示器/2=显示器；分配规则 = 找最小未被使用的下标；每个打开文件在内核有 struct file（引用计数、缓冲区、操作方法）和 inode 元信息
- 重定向：close(1) 后 open 的新文件占用 fd=1；dup2(oldfd, newfd) 让 newfd 拷贝 oldfd（必要时先关 newfd），下标不变改指针指向；minishell 中重定向由子进程 DoRedir 完成，程序替换不影响重定向
- 一切皆文件：struct file{属性、内核缓冲区、操作方法 f_op}、file_operations 函数指针集合、驱动为每个设备实现 read/write；同一套 read/write 访问所有设备；stdout 与 stderr 分离（>、>>、<，1>log.txt 2>&1 合并）
- 缓冲区：用户级缓冲区由 C 标准库提供（FILE 内含缓冲区字段和 _fileno）、write 系统调用无缓冲；三种策略：无缓冲立即刷新（stderr）/ 行缓冲（显示器，1024，遇 \n）/ 全缓冲（普通文件，满才刷）；刷新条件：缓冲区满、fflush、进程退出；重定向后 stdout 由行缓冲变全缓冲需 fflush；fork 时缓冲区写时拷贝导致父子各刷一份重复输出
- 模拟 libc：mFILE{flag,fileno,outbuffer,cap,size}、mfopen/mfwrite/mfflush/mfclose；行缓冲检测末尾 '\n'；mfflush 用 write 写入内核文件缓冲区 + fsync 落盘
