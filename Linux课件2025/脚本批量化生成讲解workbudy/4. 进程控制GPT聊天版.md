# 4. 进程控制（GPT版）

# 1. 进程创建

本节内容已在第 3 课中掌握，以下仅按提要保留知识定位，不重复展开细节。

## 1.1 `fork` 函数

`fork` 的接口、返回值和父子进程分流方式已掌握：

- 父进程得到子进程 PID；
- 子进程得到 `0`；
- 调用失败得到 `-1`。

> **`fork` 的核心作用：复制出一个子进程，让父子进程从同一位置继续执行。**

## 1.2 `fork` 的内核过程

`fork` 的内部流程已掌握：

```text
分配资源
  ↓
复制父进程部分数据结构
  ↓
把子进程加入系统进程列表
  ↓
父子进程分别返回
  ↓
由调度器决定谁先执行
```

父子进程的代码和初始数据状态相同，但执行先后由调度器决定，不能依赖固定顺序。

## 1.3 写时拷贝

写时拷贝的含义已掌握：父子进程暂时共享代码和未修改的数据；某一方尝试写入时，系统才为它复制对应数据副本。

> **写时拷贝把“立即复制”延迟到“真正写入”时，减少了不必要的内存占用。**

## 1.4 `fork` 的常规用法

常见结构有两类：

1. 父子进程从同一位置分流，分别执行不同任务；
2. 子进程调用 `exec`，把自身替换为另一个程序。

```text
fork
 ├── 父进程：继续执行父进程任务
 └── 子进程：执行子进程任务，或调用 exec 替换程序
```

## 1.5 `fork` 调用失败

`fork` 失败通常表示系统无法再创建进程，常见原因是：

- 系统中的进程数量过多；
- 当前用户创建的进程数超过限制。

# 2. 进程终止

进程不可能一直运行，代码执行结束或被信号打断后，内核会回收它，并把执行结果交给父进程。这个结果主要通过“退出码”表示。

## 2-1 进程退出场景

进程结束通常有三种情况：

| 场景 | 含义 | 退出结果 |
|---|---|---|
| 代码运行完毕，结果正确 | 程序正常完成任务 | 通常退出码为 `0` |
| 代码运行完毕，结果不正确 | 程序执行结束，但发现操作失败 | 通常返回非 `0` 退出码 |
| 代码异常终止 | 程序没有主动执行完，而是收到信号被终止 | 退出状态主要由信号表示 |

例如，程序运行过程中按下 `Ctrl+C`，Shell 会向前台进程发送 `SIGINT` 信号，进程通常会立即终止。

> **关键结论：进程结束不一定代表执行成功，退出码和终止信号共同反映进程的结束原因。**

---

## 2-2 常见退出方法

### 正常终止

进程可以通过以下三种方式主动结束：

1. 从 `main` 函数执行 `return`
2. 调用库函数 `exit`
3. 调用系统调用 `_exit`

### 异常终止

按下 `Ctrl+C` 会产生 `SIGINT` 信号，进程收到该信号后通常会异常终止。

### 查看退出码

Shell 会保存最近一次执行命令的退出状态，可以使用 `echo $?` 查看：

```bash
echo $?  # 查看最近一次命令的退出码
```

这里的 `$?` 是 Shell 保存的特殊变量，表示最近一次命令的退出码。

> **关键结论：`echo $?` 查看的是最近一次命令的退出码，`0` 通常表示成功，非 `0` 通常表示失败或异常。**

---

## 2-2-1 退出码

### 退出码表示什么

退出码，也叫退出状态，是进程结束时留下的一个整数，用来告诉父进程“这次执行结果如何”。

- `0`：执行成功
- 非 `0`：执行失败或发生异常
- `1`：常见的普通错误，例如操作不被允许
- `128 + n`：进程被编号为 `n` 的信号终止

例如：

- `130 = 128 + 2`，表示收到 `SIGINT`
- `143 = 128 + 15`，表示收到 `SIGTERM`

因此，退出码 `128+n` 中的 `n` 表示终止进程的信号编号。

不同的退出码值可以表示不同的错误原因，程序设计时可以自定义退出码含义。`strerror()` 可以把错误编号转换成对应的文字描述。

### 退出码保存在哪里

进程退出时，退出信息会记录到内核为进程维护的 `task_struct` 中，父进程之后可以通过等待接口读取。

> **关键结论：退出码会写入进程的 `task_struct`，不同退出码通常表示不同的错误原因。**

### 异常退出时退出码是否有效

进程状态可以理解为两部分：

- 低 7 位：终止进程的信号编号
- 更高部分：正常退出时使用的退出码

如果低 7 位不为 `0`，说明进程是被信号终止的，此时应优先关注信号编号，正常退出码没有实际意义。

> **关键结论：低 7 位非 `0` 表示异常退出，此时退出原因由信号决定，退出码本身无意义。**

---

## 2-3-2 `_exit` 函数

### 语法

```cpp
#include <unistd.h>  // 声明 _exit
void _exit(int status);  // 立即终止当前进程
```

### 功能

`_exit(status)` 立即终止当前进程，并把 `status` 作为进程的终止状态。父进程可以通过等待接口取得这个状态。

虽然 `status` 的类型是 `int`，但父进程实际只能使用它的低 8 位，也就是最低一个字节。

```cpp
#include <unistd.h>  // 声明 _exit
#include <stdio.h>   // 声明 printf

int main()
{
    _exit(-1);       // -1 的低 8 位为 255，立即终止进程
}
```

因此，使用 `_exit(-1)` 后，Shell 中通常可以看到退出码 `255`，因为：

```text
-1 的低 8 位 = 255
```

### 注意事项

`_exit` 是系统调用，结束进程时不会刷新 C 语言库提供的缓冲区。

> **关键结论：`_exit` 会立即结束进程，不刷新 C 语言库缓冲区。**

---

## 2-3-3 `exit` 函数

### 语法

```cpp
#include <stdlib.h>  // 实际声明 exit
void exit(int status);  // 正常终止当前进程
```

有些资料会写成包含 `<unistd.h>`，但标准库函数 `exit` 实际声明在 `<stdlib.h>` 中。

### `exit` 的执行过程

调用 `exit(status)` 时，进程不会直接结束，而是依次进行清理：

1. 执行通过 `atexit` 或 `on_exit` 注册的清理函数
2. 关闭已经打开的流，并刷新缓冲区中的数据
3. 最后调用 `_exit` 结束进程

```cpp
#include <stdio.h>   // 声明 printf
#include <stdlib.h>  // 声明 exit

int main()
{
    printf("hello\n");  // 数据可能先进入 C 语言库缓冲区
    exit(0);             // 刷新缓冲区后结束进程
}
```

### `exit` 与 `_exit` 的区别

| 对比项 | `exit` | `_exit` |
|---|---|---|
| 类型 | 库函数 | 系统调用 |
| 是否执行清理函数 | 是 | 否 |
| 是否刷新 C 语言库缓冲区 | 是 | 否 |
| 是否最终结束进程 | 是 | 是 |

这里的缓冲区不是操作系统内部的缓冲区，而是 C 语言库为了提高输入输出效率提供的缓冲区。

> **关键结论：`exit` 和 `_exit` 都能结束进程，本质区别是 `exit` 会刷新 C 语言库缓冲区，而 `_exit` 不会。**

---

## 2-3-4 `return` 退出

### `main` 中的 `return`

在 `main` 函数中执行：

```cpp
int main()
{
    return 0;  // 返回 0，表示正常结束
}
```

等同于执行：

```cpp
exit(0);  // 以 0 作为退出状态结束进程
```

调用 `main` 的运行时函数会接收 `main` 的返回值，再把它作为 `exit` 的参数。

因此：

```cpp
return n;
```

在 `main` 中等同于：

```cpp
exit(n);
```

### `main` 的 `return` 与普通函数的 `return`

| 位置 | `return` 的含义 |
|---|---|
| `main` 函数 | 结束进程，并把返回值作为退出码 |
| 其他函数 | 结束本次函数调用，把返回值交给调用者 |

例如，普通函数中的 `return` 只会返回到调用它的位置，不会结束整个进程。

### 在任意位置调用 `exit`

无论在什么函数中调用 `exit`，都表示结束整个进程，而不是只结束当前函数。退出状态最终会交给父进程；如果父进程是 Shell，那么可以通过 `echo $?` 查看。

> **关键结论：只有 `main` 的 `return` 会结束进程；其他函数的 `return` 只结束函数调用，而任意位置调用 `exit` 都会结束整个进程。**

# 3. 进程等待

本节内容已在已学清单中掌握，以下仅保留知识结构与关键结论。

## 3-1 进程等待必要性

子进程退出后，如果父进程不等待，子进程会留下僵尸状态，造成内核资源泄漏；此时它已经结束，`kill -9` 也无法再次杀死它。

父进程通过进程等待完成两件事：

1. 回收子进程资源，这是最重要的目的；
2. 获取子进程的退出信息，例如退出码或终止信号。

> **进程等待的核心：回收子进程资源，获取子进程退出信息。**

---

## 3-2 进程等待的方法

### 3-2-1 `wait` 方法

`wait` 等待任意一个子进程：

```cpp
#include <sys/types.h>  // 提供 pid_t
#include <sys/wait.h>   // 提供 wait

pid_t wait(int* status); // 等待任意子进程并获取其状态
```

若子进程尚未退出，父进程会阻塞在 `wait` 调用处；子进程退出后，`wait` 返回其 PID，并完成资源回收。

---

### 3-2-2 `waitpid` 方法

`waitpid` 可以精确指定等待对象和等待方式：

```cpp
pid_t waitpid(pid_t pid, int* status, int options); // 按条件等待子进程
```

`pid` 决定等待范围：

| `pid` | 等待对象 |
|---|---|
| `< -1` | 进程组 ID 等于 `|pid|` 的任意子进程 |
| `-1` | 任意子进程，与 `wait` 等效 |
| `0` | 与调用进程同一进程组的任意子进程 |
| `> 0` | PID 等于 `pid` 的指定子进程 |

`options` 为 `0` 时阻塞等待；指定 `WNOHANG` 时，子进程未退出则立即返回 `0`，不挂起父进程。

调用结果：

- 子进程已退出：立即返回，回收资源并获取状态；
- 子进程仍在运行：阻塞模式下等待，非阻塞模式下返回 `0`；
- 不存在符合条件的子进程：立即返回错误。

> **`wait` 只能等待任意子进程；`waitpid` 还能指定子进程、进程组和是否阻塞。**

---

### 3-2-3 获取子进程 `status`

`status` 不能直接当作普通整数理解，而应看作低 16 位组成的位图：

```text
正常终止：| 退出状态(8位) | 0(1位) | 0(7位) |
被信号所杀：| 未用(8位) | core dump(1位) | 终止信号(7位) |
```

- 高 8 位：正常退出时保存退出码；
- 第 7 位：`core dump` 标志；
- 低 7 位：被信号终止时保存信号编号。

常用宏：

```cpp
WIFEXITED(status);    // 判断子进程是否正常退出
WEXITSTATUS(status);  // 在正常退出时提取退出码
```

没有异常时，低 7 位为 `0`；若低 7 位非 `0`，说明进程被信号终止，此时退出码没有意义。

操作系统会先把 `exit_code`、`exit_signal` 等信息保存到子进程的 `task_struct` 中，再在 `wait` 或 `waitpid` 时交给父进程。

> **先用 `WIFEXITED` 判断是否正常退出，再使用 `WEXITSTATUS` 读取退出码。**

---

### 3-2-4 阻塞与非阻塞等待

阻塞等待：

```cpp
waitpid(-1, &status, 0); // 等待任意子进程，父进程会挂起
```

非阻塞等待：

```cpp
waitpid(-1, &status, WNOHANG); // 子进程未退出时立即返回
```

非阻塞等待通常使用轮询：父进程反复检查子进程状态，未结束时处理自己的任务，之后再次检查。

```cpp
do {
    ret = waitpid(-1, &status, WNOHANG); // 不阻塞地检查子进程
    if (ret == 0) {
        printf("child is running\n");    // 子进程仍在运行
    }
    handler();                           // 父进程执行其他任务
} while (ret == 0);                      // 未结束就继续检查
```

阻塞与非阻塞的区别：

| 方式 | 子进程未退出时 | 父进程行为 |
|---|---|---|
| 阻塞等待 | 持续等待 | 挂起，不能做其他事情 |
| 非阻塞等待 | 立即返回 `0` | 继续执行，可稍后再次检查 |

父进程要在等待期间执行不同任务，可以把任务封装成回调，通过函数指针数组或 `std::function` 统一调用。

> **`WNOHANG` 的含义是：如果没有子进程退出，就立即返回，不等待。**

---

# 4. 进程程序替换

本节内容已在已学清单中掌握，按要求仅保留逻辑骨架与关键结论，不展开命令和示例细节。

## 4-1 替换原理

`fork` 创建子进程后，子进程默认继续执行与父进程相同的代码；如果子进程要执行另一个程序，就需要调用 `exec` 系列函数。

**进程替换：把磁盘上的新程序代码和数据加载到当前进程的地址空间中。**

> **调用 `exec` 不会创建新进程，调用前后 PID 不变。**

进程由两部分组成：

```text
进程 = 内核数据结构 task_struct + 用户空间的代码和数据
```

`exec` 只替换用户空间的代码和数据，`task_struct` 不变。因此，进程身份仍然是原来的进程，但执行内容已经变成新程序。

> **程序替换成功后，原程序后续代码已经不存在，进程从新程序的启动例程重新开始执行。**

`exec` 的返回规律特殊：

> **`exec` 成功时不返回；只有返回 `-1` 才表示替换失败。**

---

## 4-2 替换函数

六个函数为：

```text
execl   execlp   execle
execv   execvp   execve
```

### 命名规律

| 字母 | 含义 | 参数特点 |
|---|---|---|
| `l` | list，列表 | 参数逐个传入，最后用 `NULL` 结束 |
| `v` | vector，数组 | 参数集中放在 `argv` 数组中 |
| `p` | path，路径搜索 | 自动根据 `PATH` 查找程序 |
| `e` | environment，环境 | 手动传入环境变量数组 |

可按两个维度理解：

```text
l / v：命令行参数如何传入
有无 p：程序路径是否自动搜索
有无 e：环境变量是否手动传入
```

### 函数使用关系

- `execl`：完整路径 + 列表参数。
- `execlp`：程序名 + 列表参数，自动搜索 `PATH`。
- `execv`：完整路径 + `argv` 数组。
- `execvp`：程序名 + `argv` 数组，自动搜索 `PATH`。
- `execle`：完整路径 + 列表参数 + 自定义环境变量。
- `execve`：完整路径 + `argv` 数组 + 自定义环境变量。

使用列表形式时，第二个参数通常是程序名，后面依次是命令行参数，并以 `NULL` 表示参数结束。

使用数组形式时，数组中的 `argv[0]` 通常保存程序名，后续元素保存各个命令行参数。

带 `p` 的函数可以只写程序名；不带 `p` 的函数需要提供程序路径。路径既可以是系统程序路径，也可以是自己编写的可执行程序，例如 `./other`。

### 环境变量的三种传入方式

1. 通过 `putenv` 修改当前进程的环境，后续程序可以继承这份环境。
2. 通过 `execle` 或 `execve` 传入全新的 `envp` 数组，只用于被替换后的程序。
3. 不特别处理时，默认继承调用进程的环境变量。

> **环境变量要么来自当前进程环境的继承，要么由 `execle`/`execve` 显式传入。**

### 函数簇与系统调用

只有 `execve` 是真正的系统调用，位于 `man` 手册第 2 节；其余五个是库函数，位于第 3 节，最终都会转到 `execve`。

```text
execl / execlp / execle / execv / execvp
                         ↓
                    库函数封装
                         ↓
                       execve
                         ↓
                      系统调用
```

### 为什么替换不影响父进程

`fork` 后父子进程具有独立的地址空间；由于写时拷贝，子进程替换自己的代码和数据时，只修改自己的空间，不会修改父进程的空间。

> **`exec` 只替换调用它的那个进程，因此子进程执行新程序不会改变父进程。**

替换目标不局限于系统程序，也可以是自己编译出的可执行程序；只要文件具备可执行权限，就能通过对应路径进行程序替换。

# 5. 自主 Shell 命令行解释器

## 5-1 目标

平时输入 `ls`、`ps`、`cat` 时，实际上不是 Linux 直接“执行字符串”，而是由 `shell` 完成一系列工作：

1. 读取你输入的一整行文字；
2. 判断这是内建命令还是普通命令；
3. 普通命令由子进程运行；
4. shell 等待子进程结束；
5. 根据退出码记录执行结果；
6. 再显示新的提示符。

这里的 `shell` 是“接收命令、启动程序的命令解释器”，例如常见的 `bash`。

自主实现一个简化版 shell，主要为了看清楚：命令行文字如何变成 `argv`，普通命令如何通过 `fork + execvp + waitpid` 执行，以及为什么 `cd` 不能像 `ls` 一样交给子进程。

> **核心目标：自己实现一个“读取命令 → 解析命令 → 执行命令 → 等待结果”的循环。**

---

## 5-2 实现原理

### shell 的典型互动过程

假设输入：

```text
ls -l
```

shell 不会把整行文字直接交给操作系统，而是先拆成：

```text
argv[0] = "ls"
argv[1] = "-l"
argv[2] = NULL
```

然后根据命令类型选择执行方式：

```text
读取命令行
    ↓
拆分成 argv 数组
    ↓
判断是否为内建命令
    ├── 是：shell 自己调用函数处理
    └── 否：fork 创建子进程
                  ↓
             execvp 执行程序
                  ↓
             父进程 waitpid 等待
    ↓
读取下一条命令
```

### 自主 shell 循环过程

#### 第一步：打印命令行提示符

提示符用于告诉用户“shell 正在等待输入”，例如：

```text
[用户名@主机名 当前目录]#
```

`当前目录` 会随着 `cd` 改变，所以提示符必须每次循环重新生成。

#### 第二步：获取用户命令

`fgets` 一次读取一整行，例如：

```text
ls -l
```

读取后通常还会保留结尾的换行符 `\n`，因此解析时要把它作为分隔字符处理。

#### 第三步：解析命令行

解析就是把一整行拆成多个字符串。`strtok` 是“按照指定分隔符逐段切分字符串”的函数。

例如：

```text
echo hello linux
```

会被拆成：

```text
gargv[0] = "echo"
gargv[1] = "hello"
gargv[2] = "linux"
gargv[3] = NULL
```

最后一个元素必须是 `NULL`，因为 `execvp` 需要通过它判断参数列表结束。

#### 第四步：检查并执行内建命令

如果命令是 `cd`、`export`、`env` 或 `echo`，shell 自己调用对应处理函数，不创建子进程。

#### 第五步：执行普通命令

如果命令不是内建命令，就执行：

```text
fork 创建子进程
    ↓
子进程调用 execvp
    ↓
父进程调用 waitpid 等待子进程
    ↓
提取退出码并保存
```

### 内建命令和普通命令

| 类型 | 例子 | 谁执行 | 是否创建子进程 |
|---|---|---|---|
| 普通命令 | `ls`、`ps`、`cat` | 子进程中的目标程序 | 是 |
| 内建命令 | `cd`、`export`、`env`、`echo` | shell 自己的函数或系统调用 | 否 |

为什么 `cd` 必须由 shell 自己执行？

假设 shell 创建子进程执行 `cd ..`：

```text
父 shell 当前目录：/home/user/project
    ↓ fork
子进程执行 cd ..
子进程当前目录：/home/user
    ↓ 子进程结束
父 shell 当前目录仍然是：/home/user/project
```

子进程改变的是自己的工作目录，父进程不会跟着改变。因此 `cd` 必须直接修改 shell 进程自己的当前目录。

同理，`export` 要改变 shell 的环境变量表，也必须由 shell 自己执行。

> **内建命令的本质：shell 自己调用函数或系统调用完成，不创建子进程。**

## 5-3 源码关键结构

### 全局数据结构

自主 shell 需要保存几类状态：

- `gargv`：当前命令拆分后的参数数组；
- `genv`：shell 自己维护的环境变量数组；
- `pwd`：当前工作路径；
- `pwdenv`：格式为 `PWD=路径` 的环境变量字符串；
- `lastcode`：上一条命令的退出码。

```cpp
char *gargv[64];       // 保存当前命令的参数
int gargc = 0;         // 当前命令的参数个数

char *genv[64];        // 保存 shell 的环境变量
int g_env_count = 0;   // 环境变量个数

char pwd[1024];        // 保存当前工作目录
char pwdenv[1024];     // 保存 PWD=当前目录
int lastcode = 0;      // 保存上一条命令的退出码
```

这里的 `genv` 可以理解为 shell 自己手中的“环境变量清单”。启动时，它需要从父 shell 的 `environ` 复制初始化。

### 命令行提示符

提示符需要用户名、主机名和当前目录名：

```text
[用户名@主机名 当前目录]#
```

`snprintf` 是“按照格式把多个数据拼成字符串，并限制最大长度”的函数。

```cpp
snprintf(command_line, size, "[%s@%s %s]# ",
         username, hostname, current_dir);
```

使用 `snprintf` 而不是不限制长度的字符串拼接，可以避免写出数组边界。

### 解析命令行

解析时需要注意三件事：

1. 清空上一次命令留下的 `gargv`；
2. 用 `strtok` 逐个获取参数；
3. 让 `gargv[gargc]` 等于 `NULL`。

`TrimSpace` 用于跳过字符串开头的空白字符，例如输入 `" file.txt"` 时，直接取得 `"file.txt"`。

### 普通命令的执行

普通命令的关键结构如下：

```cpp
pid_t id = fork();                         // 创建子进程

if (id == 0) {                             // 子进程分支
    execvp(gargv[0], gargv);                // 用目标程序替换当前子进程
    perror("execvp");                       // execvp 失败时输出原因
    _exit(127);                             // 执行失败，返回约定错误码
}

int status = 0;                            // 保存子进程状态
waitpid(id, &status, 0);                   // 父进程阻塞等待子进程结束

if (WIFEXITED(status)) {                    // 判断是否正常退出
    lastcode = WEXITSTATUS(status);         // 提取 exit(n) 中的 n
}
```

`execvp` 成功后不会返回，因为当前子进程的程序内容已经被新程序替换；只有执行失败时，才会回到下一行。

### 内建命令实现

#### `cd`

`cd` 解决的是“改变 shell 当前工作目录”的问题，因此直接调用 `chdir`：

```cpp
chdir(gargv[1]);                            // 修改当前 shell 的工作目录
```

改变目录后，还要更新 `PWD`，否则提示符和环境变量中的路径可能不一致。

#### `export`

`export` 解决的是“让变量进入环境变量表”的问题。例如：

```text
export MYNAME=Tom
```

shell 需要把 `MYNAME=Tom` 加入 `genv`，同时更新进程环境，使之后执行的普通程序也能继承它。

#### `env`

`env` 不需要创建新程序，shell 直接遍历 `genv` 并打印每一项。

#### `echo`

`echo` 根据参数决定打印内容：

```text
echo $?       → 打印 lastcode
echo $PATH    → 打印 PATH 的值
echo hello    → 打印 hello
```

其中 `$?` 不是普通变量名，而是 shell 用来表示上一条命令退出码的特殊符号。

### 环境变量初始化

父 shell 启动自主 shell 时，会把环境变量传给它。C 程序可以通过：

```cpp
extern char **environ;
```

访问环境变量表。

初始化时，把 `environ` 中的每个字符串复制到 `genv`：

```text
父 shell 的 environ
        ↓ 拷贝
自主 shell 的 genv
```

这样自主 shell 启动时就能继承父 shell 已有的 `PATH`、`HOME` 等环境变量。

## 一个可运行的简化版 Shell

保存为 `myshell.c`：

```cpp
#include <stdio.h>          // 提供 printf、fgets、perror
#include <stdlib.h>         // 提供 exit、free
#include <string.h>         // 提供 strtok、strcmp、strchr、strdup
#include <unistd.h>         // 提供 fork、execvp、chdir、getcwd、gethostname
#include <sys/types.h>      // 提供 pid_t
#include <sys/wait.h>       // 提供 waitpid、WIFEXITED、WEXITSTATUS
#include <pwd.h>            // 提供 getpwuid
#include <unistd.h>         // 提供 getuid

#define MAX_ARG 64                              // 最多保存 63 个参数和 1 个 NULL
#define MAX_ENV 64                              // 最多保存 63 个环境变量和 1 个 NULL
#define MAX_LINE 1024                           // 命令行最大长度

#define TrimSpace(s) ((s) + strspn((s), " \t\r\n")) // 跳过字符串开头的空白字符

char *gargv[MAX_ARG];                           // 当前命令的参数数组
int gargc = 0;                                  // 当前命令的参数个数

char *genv[MAX_ENV];                            // shell 自己维护的环境变量数组
int g_env_count = 0;                            // 环境变量个数

char pwd[MAX_LINE];                             // 当前工作目录
char pwdenv[MAX_LINE];                          // PWD=当前工作目录
int lastcode = 0;                               // 上一条命令的退出码

extern char **environ;                          // 父 shell 传给当前程序的环境变量表

void InitEnv(void)                              // 初始化自主 shell 的环境变量
{
    int i = 0;                                  // 遍历 environ 的下标

    while (environ[i] != NULL && i < MAX_ENV - 1) { // 逐项复制环境变量
        genv[i] = strdup(environ[i]);          // 为环境变量复制一份字符串
        i++;                                   // 移动到下一项
    }

    g_env_count = i;                            // 保存环境变量数量
    genv[g_env_count] = NULL;                  // 环境变量表以 NULL 结尾
}

char *FindEnvValue(const char *name)            // 根据变量名查找变量值
{
    size_t name_len = strlen(name);             // 获取变量名长度

    for (int i = 0; i < g_env_count; i++) {     // 遍历环境变量表
        if (strncmp(genv[i], name, name_len) == 0 &&
            genv[i][name_len] == '=') {         // 判断是否匹配 NAME=
            return genv[i] + name_len + 1;      // 返回等号后面的变量值
        }
    }

    return NULL;                                // 没找到时返回 NULL
}

void AddEnv(const char *env_string)             // 添加或更新环境变量
{
    const char *equal = strchr(env_string, '='); // 查找 NAME=VALUE 中的等号

    if (equal == NULL) {                         // 没有等号就不是合法环境变量
        return;                                  // 直接忽略这次添加
    }

    size_t name_len = equal - env_string;       // 计算变量名长度

    for (int i = 0; i < g_env_count; i++) {     // 查找是否已经存在同名变量
        if (strncmp(genv[i], env_string, name_len) == 0 &&
            genv[i][name_len] == '=') {         // 找到同名变量
            free(genv[i]);                      // 释放旧字符串
            genv[i] = strdup(env_string);      // 保存新的变量字符串
            putenv(strdup(env_string));         // 更新当前进程的环境
            return;                             // 更新完成
        }
    }

    if (g_env_count < MAX_ENV - 1) {             // 检查环境变量数组是否还有空间
        genv[g_env_count] = strdup(env_string); // 把新变量加入 genv
        g_env_count++;                          // 更新变量数量
        genv[g_env_count] = NULL;               // 保证数组以 NULL 结尾
        putenv(strdup(env_string));             // 让 execvp 启动的程序也能继承它
    }
}

void UpdatePWD(void)                             // 更新当前目录和 PWD 环境变量
{
    if (getcwd(pwd, sizeof(pwd)) == NULL) {      // 获取当前绝对路径
        perror("getcwd");                       // 获取失败时输出错误
        return;                                 // 结束更新
    }

    snprintf(pwdenv, sizeof(pwdenv),            // 生成 PWD=/xxx 格式的字符串
             "PWD=%s", pwd);

    AddEnv(pwdenv);                              // 更新 genv 和当前进程环境
}

void PrintPrompt(void)                           // 生成并打印命令提示符
{
    char hostname[128];                         // 保存主机名
    char username[128];                         // 保存用户名
    char command_line[MAX_LINE];                // 保存最终提示符

    struct passwd *user = getpwuid(getuid());   // 根据当前用户 ID 获取用户信息

    if (user != NULL) {                          // 判断是否成功获取用户信息
        snprintf(username, sizeof(username),    // 保存用户名
                 "%s", user->pw_name);
    } else {
        snprintf(username, sizeof(username),     // 获取失败时使用 unknown
                 "unknown");
    }

    gethostname(hostname, sizeof(hostname));    // 获取主机名
    getcwd(pwd, sizeof(pwd));                   // 获取当前工作目录

    const char *current_dir = strrchr(pwd, '/'); // 查找路径中最后一个斜杠

    if (current_dir == NULL || current_dir[1] == '\0') { // 判断是否为根目录
        current_dir = pwd;                      // 根目录直接显示完整路径
    } else {
        current_dir++;                          // 跳过斜杠，只保留目录名
    }

    snprintf(command_line, sizeof(command_line), // 组合最终提示符
             "[%s@%s %s]# ",
             username, hostname, current_dir);

    printf("%s", command_line);                  // 显示提示符
    fflush(stdout);                              // 立即刷新输出
}

void ParseCommand(char *command_buffer)         // 把命令行解析成 gargv
{
    gargc = 0;                                  // 清空上一条命令的参数数量

    char *token = strtok(command_buffer, " \t\r\n"); // 获取第一个参数

    while (token != NULL && gargc < MAX_ARG - 1) {   // 逐个读取参数
        gargv[gargc] = token;                   // 保存当前参数
        gargc++;                                // 参数数量加一
        token = strtok(NULL, " \t\r\n");        // 获取下一个参数
    }

    gargv[gargc] = NULL;                        // execvp 要求参数表以 NULL 结束
}

int RunBuiltin(void)                           // 检查并执行内建命令
{
    if (gargc == 0) {                           // 空命令不需要执行
        return 1;                               // 表示已经处理
    }

    if (strcmp(gargv[0], "cd") == 0) {          // 判断是否为 cd
        const char *path = gargv[1];            // 获取目标路径

        if (path == NULL) {                     // 没写路径时进入 HOME
            path = FindEnvValue("HOME");        // 查找 HOME 环境变量
        }

        if (path == NULL || chdir(path) != 0) { // 改变当前目录
            perror("cd");                       // 改变失败时输出原因
            lastcode = 1;                       // 保存失败退出码
        } else {
            UpdatePWD();                        // 改变成功后更新 PWD
            lastcode = 0;                       // 保存成功退出码
        }

        return 1;                               // 表示这是内建命令
    }

    if (strcmp(gargv[0], "export") == 0) {      // 判断是否为 export
        if (gargc > 1) {                        // 检查是否提供变量
            AddEnv(gargv[1]);                   // 添加变量到环境变量表
            lastcode = 0;                       // 保存成功退出码
        } else {
            lastcode = 1;                       // 没有参数时返回失败
        }

        return 1;                               // 表示这是内建命令
    }

    if (strcmp(gargv[0], "env") == 0) {         // 判断是否为 env
        for (int i = 0; i < g_env_count; i++) { // 遍历所有环境变量
            printf("%s\n", genv[i]);            // 打印环境变量
        }

        lastcode = 0;                           // env 正常结束
        return 1;                               // 表示这是内建命令
    }

    if (strcmp(gargv[0], "echo") == 0) {        // 判断是否为 echo
        for (int i = 1; i < gargc; i++) {       // 遍历 echo 后面的参数
            if (strcmp(gargv[i], "$?") == 0) {  // 判断是否打印上一条退出码
                printf("%d", lastcode);         // 打印 lastcode
            } else if (gargv[i][0] == '$') {    // 判断是否为环境变量形式
                char *value = FindEnvValue(gargv[i] + 1); // 查找变量值

                if (value != NULL) {            // 判断变量是否存在
                    printf("%s", value);        // 打印环境变量值
                }
            } else {
                printf("%s", gargv[i]);         // 直接打印普通字符串
            }

            if (i + 1 < gargc) {                // 参数之间需要空格
                printf(" ");                    // 打印参数分隔空格
            }
        }

        printf("\n");                           // echo 最后输出换行
        lastcode = 0;                           // echo 正常结束
        return 1;                               // 表示这是内建命令
    }

    return 0;                                   // 表示不是内建命令
}

void RunExternalCommand(void)                    // 执行普通命令
{
    pid_t id = fork();                           // 创建子进程

    if (id < 0) {                                // 判断 fork 是否失败
        perror("fork");                          // 输出 fork 失败原因
        lastcode = 1;                            // 保存失败退出码
        return;                                  // 返回主循环
    }

    if (id == 0) {                               // 子进程执行这里
        execvp(gargv[0], gargv);                 // 用目标程序替换子进程

        perror("execvp");                        // execvp 失败时输出原因
        _exit(127);                              // 执行失败后结束子进程
    }

    int status = 0;                              // 保存子进程退出状态
    waitpid(id, &status, 0);                     // 父进程等待子进程结束

    if (WIFEXITED(status)) {                     // 判断子进程是否正常退出
        lastcode = WEXITSTATUS(status);          // 提取子进程退出码
    } else {
        lastcode = 128;                          // 非正常结束时保存非零结果
    }
}

int main(void)                                  // 程序入口
{
    char command_buffer[MAX_LINE];               // 保存用户输入的一整行命令

    InitEnv();                                   // 从父 shell 初始化环境变量
    UpdatePWD();                                 // 初始化当前目录和 PWD

    while (1) {                                  // shell 持续读取命令
        PrintPrompt();                           // 打印命令行提示符

        if (fgets(command_buffer, sizeof(command_buffer), stdin) == NULL) {
            printf("\n");                        // Ctrl+D 时输出换行
            break;                               // 结束 shell
        }

        char *trimmed = TrimSpace(command_buffer); // 去掉开头的空白字符

        if (*trimmed == '\0') {                  // 判断是否只输入了空白
            continue;                            // 空命令直接读取下一行
        }

        ParseCommand(trimmed);                  // 把命令行拆成 gargv
        if (RunBuiltin()) {                      // 优先尝试执行内建命令
            continue;                            // 内建命令执行完成后继续循环
        }

        RunExternalCommand();                   // 非内建命令交给子进程执行
    }

    for (int i = 0; i < g_env_count; i++) {     // 释放复制的环境变量
        free(genv[i]);                           // 释放每个环境变量字符串
    }

    return 0;                                   // shell 正常结束
}
```

```bash

```

```text

pwd

```

注意：`strtok` 会直接修改输入缓冲区，把分隔符替换成 `\0`；因此这里必须先把命令读入可修改的字符数组，不能直接传入字符串常量。

> **执行分流规则：内建命令直接在当前 shell 中执行，普通命令才走 fork、execvp、waitpid。**

## 5-4 总结

可以把进程之间的调用关系类比成 C 函数调用：

| C 函数调用 | Linux 进程调用 |
|---|---|
| `call` 进入函数 | `fork` 创建子进程 |
| 函数开始执行 | `exec` 替换为目标程序 |
| `return` 返回结果 | `exit(n)` 返回退出码 |
| 调用者获得返回值 | `wait` / `waitpid` 获取退出码 |

完整过程是：

```text
父进程 fork
    ↓
子进程 exec 执行另一个程序
    ↓
子进程 exit(n) 返回结果
    ↓
父进程 wait(&ret) 获取结果
```

> **一个 C 程序可以通过 fork 创建子进程、通过 exec 执行另一个程序、通过 exit 返回结果，再由父进程通过 wait 获取这个结果。**
