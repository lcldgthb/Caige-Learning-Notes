# 1. 理解“文件”

## 1-1 狭义理解

文件通常保存在磁盘中。磁盘属于永久性存储介质，断电后文件仍然存在；它同时具有输入和输出功能：

- 从磁盘读取文件：磁盘向计算机输入数据。
- 向磁盘写入文件：计算机向磁盘输出数据。

因此，对文件的读、写等操作，本质上都是对外设进行输入输出，简称 `IO`。

---

## 1-2 广义理解

Linux 采用“一切皆文件”的抽象方式，将键盘、显示器、网卡、磁盘等对象统一表示为文件。

这样，程序可以使用统一的读写接口处理不同对象，而不必为每种设备学习完全不同的操作方式。

---

## 1-3 文件操作的归类认知

即使文件内容为 `0KB`，文件本身仍然会占用一定的磁盘空间，因为系统还要保存文件名、权限、大小等信息。

> **文件 = 内容 + 属性（元数据）。**

文件的操作可以统一归为两类：

```text
文件操作
├── 文件内容操作：读、写
└── 文件属性操作：查看、修改权限、修改拥有者等
```

因此：

> **所有文件操作，本质上都是文件内容操作和文件属性操作。**

---

## 1-4 系统角度

### 文件操作的真正执行者

程序不能直接管理磁盘，因为磁盘由操作系统统一管理。程序必须通过操作系统提供的接口访问文件。

同时，操作文件的主体也不是程序本身，而是进程：

> **对文件的操作，本质是进程对文件的操作。**

### 库函数与系统调用

C/C++ 库函数为用户提供了更方便的接口，但真正请求操作系统完成文件操作的，是文件相关的系统调用接口。

例如：

- `fopen`、`fclose`：C 库函数；
- 底层会封装操作系统提供的文件系统调用；
- 最终由操作系统完成文件的打开和关闭。

因此，库函数与系统调用的关系可以理解为：

```text
C/C++ 程序
    ↓
库函数：fopen、fclose 等
    ↓
系统调用接口
    ↓
操作系统管理文件
```

### 打开文件的含义

访问文件前必须先打开文件。这里的“打开”不是把整个文件复制到内存，而是由进程向操作系统申请访问该文件，并获得后续操作所需的信息。

所以，“打开文件”更准确地说是：

> **进程打开文件，而不是文件自己被打开。**

### 两类文件

从操作系统角度，可以区分：

| 类型    | 含义                       |
| ----- | ------------------------ |
| 磁盘级文件 | 保存在磁盘上的文件                |
| 内存文件  | 文件被进程打开后，操作系统在内存中维护的相关信息 |

```text
磁盘级文件
    ↓ 进程调用打开接口
内存文件
    ↓ 进程进行读写、关闭等操作
回到磁盘级文件
```

> **文件访问的完整链条是：进程通过库函数或系统调用，请求操作系统打开并操作磁盘上的文件。**

## 2. 回顾 C 文件接口

程序要保存或读取文件，首先必须“打开”文件；打开成功后，程序通过一个 `FILE *` 句柄操作它。句柄可以理解为程序手里的“文件联系卡”，里面记录了文件的位置、读写状态等信息。

### 2-1 `hello.c` 打开文件

#### 语法

```cpp
FILE *fp = fopen("myfile", "w");  // 以写方式打开 myfile，返回文件流指针
```

#### 功能

`fopen` 用来打开文件：

- 成功：返回一个 `FILE *`，保存到 `fp`
- 失败：返回 `NULL`
- `"w"`：以写方式打开文件

打开文件可能失败，例如权限不足、路径不存在或磁盘出现问题。因此，必须先检查返回值，再继续操作。

```cpp
#include <stdio.h>  // 提供 FILE、fopen、printf 等接口

int main()
{
    FILE *fp = fopen("myfile", "w");  // 在当前路径下以写方式打开文件

    if (fp == NULL)                   // 判断打开是否失败
    {
        perror("fopen error");        // 输出失败原因
        return 1;                     // 立即退出，避免继续使用 NULL
    }

    fclose(fp);                       // 关闭文件
    return 0;                         // 表示程序正常结束
}
```

如果 `fopen` 失败后仍然使用 `fp`，就相当于对 `NULL` 指针进行操作，程序可能崩溃。

> **打开文件失败后必须立即处理，不能继续对 `NULL` 文件指针进行读写。**

#### 文件默认创建在哪个路径？

代码中的 `"myfile"` 没有写目录，这叫**相对路径**：它不是从根目录开始写，而是相对于程序的当前路径。

```text
"myfile"       → 当前路径下的 myfile
"./myfile"     → 当前路径下的 myfile
"/tmp/myfile"  → /tmp 目录下的 myfile
```

查看某个进程的当前路径，可以查看 `/proc/[pid]`：

```bash
ls /proc/[pid] -l  # 查看指定进程在 proc 中的信息
```

重点看两个符号链接：

```text
cwd → 进程当前运行目录
exe → 启动该进程的可执行文件完整路径
```

- `cwd`：**current working directory**，即当前工作目录
- `exe`：**executable**，即正在运行的可执行文件

例如，一个程序的 `cwd` 是 `/home/user/test`，执行：

```cpp
fopen("myfile", "w");  // 没有目录，因此文件创建在 /home/user/test/myfile
```

这里的关键是：文件操作本质上是**进程在操作文件**。进程拥有自己的当前路径，所以即使只写 `"myfile"`，系统也知道应该到哪里寻找或创建它。

> **不写路径时，文件默认位于进程的 `cwd`，而不是可执行文件所在的目录。**

### 2-2 `hello.c` 写文件

#### 语法

```cpp
fwrite(msg, strlen(msg), 1, fp);  // 把 msg 中的数据写入 fp 指向的文件
```

`fwrite` 的四个参数依次是：

```text
缓冲区首地址、每个元素的大小、元素个数、文件流
```

例如：

```cpp
#include <stdio.h>   // 提供文件接口
#include <string.h>  // 提供 strlen

int main()
{
    const char *msg = "hello file\n";        // 准备写入的字符串
    FILE *fp = fopen("myfile", "w");         // 打开文件，w 会清空原内容

    if (fp == NULL)                          // 判断打开是否失败
    {
        perror("fopen error");               // 打印错误原因
        return 1;                            // 失败时退出
    }

    fwrite(msg, strlen(msg), 1, fp);         // 写入一个元素，每个元素大小是字符串长度
    fclose(fp);                              // 关闭文件
    return 0;                                // 正常结束
}
```

这里把整段字符串看成“一个元素”，元素大小是 `strlen(msg)`。也可以把数据看成许多字节：

```cpp
fwrite(msg, 1, strlen(msg), fp);  // 写入 strlen(msg) 个字节
```

这两种写法写出的内容相同，只是“元素大小”和“元素个数”的划分方式不同。

### 2-3 `hello.c` 读文件

#### 语法

```cpp
ssize_t s = fread(buf, 1, strlen(msg), fp);  // 从 fp 读取数据到 buf
```

`fread` 的参数依次是：

```text
目标缓冲区、每个元素的大小、要读取的元素个数、文件流
```

返回值 `s` 表示**实际读取了多少个元素**，不是永远等于请求读取的数量。

因为这里每个元素大小是 `1` 字节，所以：

```text
s = 实际读取的字节数
```

#### 示例

```cpp
#include <stdio.h>   // 提供 FILE、fopen、fread 等接口
#include <string.h>  // 提供 strlen

int main()
{
    const char *msg = "hello file\n";        // 假设文件中有这段内容
    char buf[1024] = {0};                    // 准备接收读取结果的缓冲区
    FILE *fp = fopen("myfile", "r");         // 以只读方式打开文件

    if (fp == NULL)                          // 判断打开是否失败
    {
        perror("fopen error");               // 打印错误原因
        return 1;                            // 失败时退出
    }

    ssize_t s = fread(buf, 1, strlen(msg), fp); // 读取指定数量的字节

    if (s > 0)                               // 确认确实读取到了数据
    {
        buf[s] = '\0';                       // 在数据末尾补字符串结束标志
        printf("%s", buf);                   // 按字符串输出读取结果
    }

    if (feof(fp))                            // 判断读取过程是否到达文件结尾
    {
        printf("end of file\n");             // 文件已经读到结尾
    }

    fclose(fp);                              // 关闭文件
    return 0;                                // 正常结束
}
```

`fread` 读出来的是一段字节，不会自动在末尾添加 `'\0'`。如果要把它当作 C 字符串打印，需要自己写：

```cpp
buf[s] = '\0';  // 在有效数据之后补字符串结束标志
```

`feof(fp)` 不是用来判断“这次读取的数据是否正好到达末尾”，而是判断流是否已经遇到文件结尾状态。通常要在读取后检查。

> **`fread` 的返回值表示实际读取的元素个数；需要按字符串使用时，必须手动补 `'\0'`。**

#### 用文件接口实现简单的 `cat`

`cat` 的基本功能是：打开指定文件，把文件内容读出来，再输出到显示器。

```cpp
#include <stdio.h>   // 提供文件和输入输出接口

int main(int argc, char *argv[])
{
    if (argc != 2)                           // 判断命令行参数数量
    {
        printf("Usage: %s filename\n", argv[0]); // 提示正确用法
        return 1;                            // 参数错误时退出
    }

    FILE *fp = fopen(argv[1], "r");          // 打开用户指定的文件

    if (fp == NULL)                          // 判断打开是否失败
    {
        perror("fopen error");               // 打印错误原因
        return 1;                            // 失败时退出
    }

    char buf[1024];                          // 准备文件内容缓冲区
    size_t n = 0;                            // 保存本次实际读取的字节数

    while ((n = fread(buf, 1, sizeof(buf), fp)) > 0) // 不断读取文件内容
    {
        fwrite(buf, 1, n, stdout);           // 把读到的数据写到标准输出
    }

    fclose(fp);                              // 关闭文件
    return 0;                                // 正常结束
}
```

编译并运行：

```bash
gcc cat.c -o mycat  # 编译程序
./mycat myfile      # 输出 myfile 的内容
```

### 2-4 输出信息到显示器，你有哪些方法

显示器也可以看成一个文件，程序可以通过标准输出流把内容写到显示器。

```cpp
#include <stdio.h>   // 提供三种输出接口

int main()
{
    const char *msg = "hello display\n";     // 准备输出的字符串

    fwrite(msg, strlen(msg), 1, stdout);     // 通过标准输出流写出
    printf("%s", msg);                       // 使用格式化输出函数
    fprintf(stdout, "%s", msg);              // 指定 stdout 作为输出流

    return 0;                                // 正常结束
}
```

三种方式的区别：

| 方法        | 说明                     |
| --------- | ---------------------- |
| `fwrite`  | 按字节块写入指定流              |
| `printf`  | 默认写到 `stdout`，支持格式化    |
| `fprintf` | 写到指定的 `FILE *` 流，支持格式化 |

`printf` 本质上可以理解为默认把内容输出到 `stdout` 的格式化函数。

### 2-5 `stdin`、`stdout`、`stderr`

程序启动时，C 标准库默认准备好三个输入输出流。**流**可以理解为程序与外部设备之间连续传输数据的通道。

```cpp
extern FILE *stdin;   // 标准输入流
extern FILE *stdout;  // 标准输出流
extern FILE *stderr;  // 标准错误流
```

这三个流的默认对应关系如下：

| 名称       | 含义                   | 默认连接对象 |
| -------- | -------------------- | ------ |
| `stdin`  | standard input，标准输入  | 键盘     |
| `stdout` | standard output，标准输出 | 显示器    |
| `stderr` | standard error，标准错误  | 显示器    |

因此，程序可以从 `stdin` 读取，也可以向 `stdout` 或 `stderr` 写入：

```cpp
#include <stdio.h>   // 提供标准流和输入输出函数

int main()
{
    char buf[128];                           // 准备保存输入内容的数组

    fprintf(stdout, "请输入内容：");          // 向标准输出显示提示
    fgets(buf, sizeof(buf), stdin);           // 从标准输入读取一行
    fprintf(stdout, "正常输出：%s", buf);     // 把正常结果写到 stdout
    fprintf(stderr, "错误输出示例\n");       // 把错误信息写到 stderr

    return 0;                                // 正常结束
}
```

`stdout` 和 `stderr` 默认都显示在屏幕上，但它们是两个独立的流。以后进行输出重定向时，可以只重定向 `stdout`，而让 `stderr` 继续显示在屏幕上。

C++ 中有对应的对象：

| C        | C++    |
| -------- | ------ |
| `stdin`  | `cin`  |
| `stdout` | `cout` |
| `stderr` | `cerr` |

> **C 默认打开 `stdin`、`stdout`、`stderr` 三个 `FILE *` 流；它们分别代表标准输入、标准输出和标准错误。**

### 2-6 打开文件的方式

前面 `fopen` 的第二个参数，例如 `"r"`、`"w"`，叫**打开模式**：它决定文件能否读写、是否清空以及写入位置。

| 模式   | 功能    | 文件不存在 | 初始位置    |
| ---- | ----- | ----- | ------- |
| `r`  | 只读    | 打开失败  | 文件开头    |
| `r+` | 读写    | 打开失败  | 文件开头    |
| `w`  | 只写    | 创建文件  | 文件开头    |
| `w+` | 读写    | 创建文件  | 文件开头    |
| `a`  | 追加写   | 创建文件  | 文件末尾    |
| `a+` | 读和追加写 | 创建文件  | 写入时位于末尾 |

#### `r`：只读

```cpp
FILE *fp = fopen("myfile", "r");  // 只读打开，文件不存在时失败
```

只能读取，不能写入；文件不存在时不会自动创建。

#### `r+`：读写

```cpp
FILE *fp = fopen("myfile", "r+");  // 允许读取和写入，文件不存在时失败
```

文件必须已经存在，打开后定位在文件开头。

#### `w`：写入并清空

```cpp
FILE *fp = fopen("myfile", "w");  // 只写打开，已有内容会被清空
```

`w` 最容易造成误操作：

- 文件不存在：创建文件
- 文件已存在：**先清空文件内容**
- 打开后：从文件开头写入

```text
原文件：hello old content
使用 "w" 打开
结果：文件变为空文件
```

> **`"w"` 不只是“允许写入”，还会先把已有文件清空；需要保留原内容时不能随便使用它。**

#### `w+`：读写并清空

```cpp
FILE *fp = fopen("myfile", "w+");  // 允许读写，但打开时会清空文件
```

它和 `"w"` 一样会清空文件，只是额外允许读取。

#### `a`：追加写

```cpp
FILE *fp = fopen("myfile", "a");  // 只允许写入，新内容追加到文件末尾
```

- 文件不存在：创建文件
- 文件存在：保留原内容
- 每次写入：追加到末尾

```text
原文件：hello
追加写入： world
结果：hello world
```

#### `a+`：读取和追加写

```cpp
FILE *fp = fopen("myfile", "a+");  // 可以读取，写入内容总是追加到末尾
```

它允许读取已有内容，但写入不会覆盖中间位置，而是追加到文件末尾。

文件打开后，如果需要改变读写位置，可使用已经学过的 `fseek`、`ftell` 和 `rewind`。

# 3. 系统文件 I/O

前面已经接触过 C 标准库文件接口；本节把视线再往下移一层：程序不直接操作磁盘，而是通过操作系统提供的系统调用完成文件读写。

---

## 3-1 一种传递标志位的方法

### 问题：一个参数如何同时传递多个开关？

例如，函数既要知道“只写”，又要知道“文件不存在时创建”。如果为每个组合单独设计一个整数，组合会越来越多。

解决方法是：让一个 `int` 的不同比特位分别代表不同标志。


```cpp
#define ONE   0001  // 二进制 0000 0001，使用第 0 位
#define TWO   0002  // 二进制 0000 0010，使用第 1 位
#define THREE 0004  // 二进制 0000 0100，使用第 2 位
```

这些数使用八进制书写，转换成二进制后分别只有一位是 `1`，因此互不干扰。

### 检测标志

```cpp
int flags = ONE | TWO;  // 按位或，把 ONE 和 TWO 同时放入 flags

if (flags & ONE) {      // 按位与，检测 ONE 是否存在
    // flags 中包含 ONE
}
```

`flags & ONE` 的结果不为 `0`，说明对应比特位已经被设置。

### 组合标志

```cpp
int flags = ONE | TWO;  // 同时传递 ONE 和 TWO
```

`|` 是按位或：某一位只要有一个操作数是 `1`，结果就是 `1`。

> **一个整数的不同比特位可以分别表示不同选项，多个选项用按位或组合，检测选项用按位与。**

`open` 的 `flags` 参数就是使用这种方式传递多个文件操作选项。

## 3-2 `hello.c` 写文件：系统接口版

### 问题：不使用 `fopen`，如何写入文件？

系统调用版本需要完成四步：

```text
设置创建权限规则
    ↓
open 打开文件并获得 fd
    ↓
write 写入内容
    ↓
close 关闭文件
```

```cpp
#include <fcntl.h>      // 提供 open 和 O_* 标志
#include <unistd.h>     // 提供 write 和 close
#include <sys/stat.h>   // 提供 umask 和权限类型
#include <stdio.h>      // 提供 perror
#include <string.h>     // 提供 strlen

int main()
{
    umask(0);                                      // 暂时不屏蔽创建权限
    const char *msg = "hello system io\n";         // 准备要写入的字符串
    int fd = open("myfile", O_WRONLY | O_CREAT, 0644); // 只写打开，不存在则创建

    if (fd < 0) {                                 // fd 小于 0 表示打开失败
        perror("open");                            // 根据 errno 打印失败原因
        return 1;                                  // 返回非 0 表示程序失败
    }

    ssize_t n = write(fd, msg, strlen(msg));       // 把字符串写入文件
    if (n < 0) {                                   // 返回负数表示写入失败
        perror("write");                           // 打印写入失败原因
        close(fd);                                 // 关闭已经打开的文件
        return 1;                                  // 返回失败状态
    }

    close(fd);                                     // 释放文件描述符
    return 0;                                      // 返回 0 表示成功
}
```

`write` 的三个核心参数是：

```text
fd       → 写入哪个打开文件
msg      → 数据在内存中的起始地址
strlen   → 希望写入多少字节
```

返回值是实际写入的字节数；小于 `0` 表示失败。

## 3-3 `hello.c` 读文件：系统接口版

### 问题：写入之后，如何用系统接口读回来？

读文件与写文件结构相似，只是把 `write` 换成 `read`：

```cpp
#include <fcntl.h>      // 提供 open 和 O_RDONLY
#include <unistd.h>     // 提供 read、write 和 close
#include <stdio.h>      // 提供 perror
#include <string.h>     // 提供 strlen

int main()
{
    const char *msg = "hello system io\n";         // 约定读取的字节数
    int fd = open("myfile", O_RDONLY);             // 以只读方式打开文件

    if (fd < 0) {                                 // fd 小于 0 表示打开失败
        perror("open");                            // 打印失败原因
        return 1;                                  // 返回失败状态
    }

    char buf[128] = {0};                           // 准备接收文件内容的缓冲区

    while (1) {
        ssize_t s = read(fd, buf, strlen(msg));   // 从文件读取指定数量的字节

        if (s > 0) {                               // s 大于 0 表示成功读到数据
            write(1, buf, s);                      // fd 为 1，写到标准输出
        } else if (s == 0) {                       // s 等于 0 表示已经读到文件末尾
            break;                                 // 结束读取
        } else {                                   // s 小于 0 表示读取失败
            perror("read");                        // 打印读取失败原因
            break;                                 // 结束读取
        }
    }

    close(fd);                                     // 关闭文件
    return 0;                                      // 返回成功状态
}
```

`read` 的返回值含义：

| 返回值    | 含义       |
| ------ | -------- |
| 大于 `0` | 实际读到的字节数 |
| 等于 `0` | 文件结束     |
| 小于 `0` | 读取失败     |

## 3-4 接口介绍

### `open`

使用 `open` 时，先根据目标文件是否存在决定参数个数。

```cpp
#include <sys/types.h>  // 提供系统类型
#include <sys/stat.h>   // 提供 mode_t 和文件状态接口
#include <fcntl.h>      // 提供 open 和 O_* 标志

int open(const char *pathname, int flags);              // 打开已有文件
int open(const char *pathname, int flags, mode_t mode); // 可能创建文件
```

- `pathname`：文件路径。
- `flags`：打开方式和操作选项。
- `mode`：创建新文件时使用的权限位。

返回值：

```text
成功：返回新的文件描述符
失败：返回 -1，并设置 errno
```

### 必选的访问方式

以下三者必须选择一个：

| 标志         | 含义 |
| ---------- | -- |
| `O_RDONLY` | 只读 |
| `O_WRONLY` | 只写 |
| `O_RDWR`   | 读写 |

### 可选的组合标志

| 标志         | 含义                   |
| ---------- | -------------------- |
| `O_CREAT`  | 文件不存在时创建，需要提供 `mode` |
| `O_APPEND` | 每次写入都追加到文件末尾         |
| `O_TRUNC`  | 打开已有文件时清空文件内容        |

`O_CREAT` 出现时必须使用三参数形式：

```cpp
int fd = open("new.txt", O_WRONLY | O_CREAT, 0644); // 不存在则创建
```

不创建文件时使用两参数形式：

```cpp
int fd = open("old.txt", O_RDONLY); // 只打开已有文件
```

### `O_TRUNC` 和 `O_APPEND` 对比

```cpp
int fd = open("log.txt", O_CREAT | O_WRONLY | O_TRUNC, 0666); // 对应 w：先清空再写
```

```cpp
int fd = open("log.txt", O_CREAT | O_WRONLY | O_APPEND, 0666); // 对应 a：保留原内容并追加
```

| 写法        | 文件不存在    | 文件已存在      | 写入位置 |    |        |
| --------- | -------- | ---------- | ---- | -- | ------ |
| \`O_CREAT | O_WRONLY | O_TRUNC\`  | 创建   | 清空 | 从开头写   |
| \`O_CREAT | O_WRONLY | O_APPEND\` | 创建   | 保留 | 每次写到末尾 |

> **`O_TRUNC` 解决“重新写一份新内容”，`O_APPEND` 解决“保留旧内容并继续追加”。**

### `write`

```cpp
ssize_t write(int fd, const void *buf, size_t count); // 向 fd 写 count 个字节
```

`write` 只认识“内存中的若干字节”，不关心这些字节原来是字符串、整数还是结构体。

因此：

- 把字符数组写出去，通常称为文本写入；
- 把整数或结构体的内存表示直接写出去，通常称为二进制写入。

例如整数 `12345`：

```text
文本写入：写入字符 '1'、'2'、'3'、'4'、'5'
二进制写入：写入整数 12345 在内存中的二进制表示
```

这是语言层面的数据表示区别，不是 `write` 提供了两种不同函数。

### C 标准库输出函数

C 标准库提供了更方便的输出接口：

| 函数         | 主要用途           |
| ---------- | -------------- |
| `puts`     | 输出字符串并自动换行     |
| `fputs`    | 向指定流输出字符串      |
| `putchar`  | 输出一个字符         |
| `putc`     | 向指定流输出一个字符     |
| `printf`   | 格式化输出到标准输出     |
| `fprintf`  | 格式化输出到指定流      |
| `sprintf`  | 格式化到内存字符串      |
| `snprintf` | 限制长度地格式化到内存字符串 |

```cpp
int fputs(const char *s, FILE *stream); // 把字符串写入指定 C 文件流
int putc(int c, FILE *stream);          // 把一个字符写入指定 C 文件流
int putchar(int c);                     // 把一个字符写到标准输出
```

### `fread` 和 `fwrite`

`FREAD(3)` 中的 `fread`、`fwrite` 属于 C 标准库，适合进行二进制流输入输出。

```cpp
size_t fread(void *ptr, size_t size, size_t nmemb, FILE *stream);        // 读取 nmemb 个对象
size_t fwrite(const void *ptr, size_t size, size_t nmemb, FILE *stream); // 写入 nmemb 个对象
```

`size` 表示每个对象占多少字节，`nmemb` 表示对象个数。

> **目标文件需要创建时使用三参数 `open` 指定权限；只打开已有文件时使用两参数 `open`。**

## 3-5 `open` 函数返回值

### 两层接口

同样是“打开文件”，实际上存在两层：

```text
C 标准库库函数
fopen / fclose / fread / fwrite
          ↓ 封装
系统调用接口
open / close / read / write / lseek
          ↓
操作系统内核
          ↓
硬件设备
```

- **库函数**：由 `libc` 提供，使用更方便，通常带有格式处理或用户层缓冲区。
- **系统调用接口**：程序请求操作系统内核完成实际的文件操作。

`open` 成功后返回一个小整数，这个小整数就是文件描述符 `fd`。

> **`fopen` 等 `f` 系列函数本质上是对系统调用的封装，用更方便的接口服务上层程序。**

## 3-6 文件描述符 `fd`

### 问题：整数 `3` 为什么能代表一个文件？

程序不能直接拿磁盘地址操作文件。操作系统会在进程内部维护一张表，表中每个位置记录一个已经打开的文件。

文件描述符就是这张表的下标：

```text
fd = 3
    ↓
进程文件描述符表的第 3 项
    ↓
内核中的 struct file
    ↓
对应的文件
```

> **文件描述符就是从 `0` 开始的小整数，本质是进程文件描述符表的数组下标。**

### 3-6-1 `0`、`1`、`2`

Linux 进程默认已经打开三个文件描述符：

| fd  | 名称            | 通常连接到 |
| --- | ------------- | ----- |
| `0` | 标准输入 `stdin`  | 键盘    |
| `1` | 标准输出 `stdout` | 显示器   |
| `2` | 标准错误 `stderr` | 显示器   |

因此可以直接使用它们：

```cpp
read(0, buf, sizeof(buf));       // 从标准输入读取
write(1, buf, strlen(buf));      // 写到标准输出
write(2, buf, strlen(buf));      // 写到标准错误
```

如果 `0`、`1`、`2` 都没有关闭，连续打开文件通常得到：

```text
3、4、5、6
```

这些数字相邻，但它们仍然可以指向不同的文件。相邻的是数组下标，不是文件内容或文件本身。

### fd 与内核结构关系

用户程序中的操作：

```cpp
int fd = open("log.txt", O_RDONLY); // 打开文件并获得下标
read(fd, buffer, sizeof(buffer));    // 通过下标读取文件
close(fd);                           // 释放这个下标
```

对应的内核关系可以表示为：

```text
task_struct
    ↓
files_struct *files
    ↓
fd_array[]
    ↓
struct file *
    ↓
inode、文件属性、读写位置、内核缓冲区、操作方法
```

`struct file` 表示一个“已经被打开的文件”。

同一个磁盘文件可以被多次打开。每次打开都可能产生不同的 `struct file`，每个打开实例可以拥有自己的读写位置。

```text
一个进程 ── 可以打开 ── 多个文件
多个进程 ── 也可以打开 ── 同一个磁盘文件
```

- 进程与打开文件的关系：`1 : n`。
- 磁盘文件不仅有内容，还有属性。
- 每个打开文件在内核中都能找到对应的文件信息和 inode 元信息。

> **文件操作必须先通过内核建立“打开文件”对象；`struct file` 就代表一个已经被打开的文件。**

### 3-6-2 文件描述符的分配规则

操作系统分配新 `fd` 时，不会随意选择数字，而是从文件描述符数组的下标 `0` 开始，寻找最小的空位置。

```cpp
close(0);                              // 释放下标 0
int fd = open("myfile", O_RDONLY);     // 新文件优先占用最小空下标
```

此时 `fd` 可能是 `0`。

同理，关闭 `2` 后再打开文件，新的文件可能得到 `2`。

> **新打开文件的文件描述符，是 `files_struct` 中当前最小的未使用下标。**

### 3-6-3 重定向

#### 问题：如何让 `printf` 不再输出到显示器？

`printf` 默认写入标准输出，也就是 `fd = 1`。如果关闭 `1`，接着打开文件：

```cpp
#include <fcntl.h>      // 提供 open 和 O_* 标志
#include <unistd.h>     // 提供 close
#include <stdio.h>      // 提供 printf 和 fflush

int main()
{
    close(1);                                      // 释放标准输出对应的下标
    int fd = open("myfile", O_WRONLY | O_CREAT, 0666); // 新文件优先占用下标 1

    printf("fd: %d\n", fd);                        // printf 仍然写 stdout，也就是下标 1
    fflush(stdout);                                // 把用户层输出缓冲区刷新到文件
    close(fd);                                     // 关闭文件

    return 0;                                      // 结束程序
}
```

此时 `open` 返回的 `fd` 是 `1`，所以 `printf` 的输出会进入 `myfile`，而不是显示器。

常见 shell 重定向：

| 写法   | 含义         |
| ---- | ---------- |
| `>`  | 输出到文件，通常覆盖 |
| `>>` | 输出到文件末尾，追加 |
| `<`  | 从文件输入      |

重定向不是改变 `printf` 的下标，而是改变文件描述符表中该下标对应的指针：

```text
fd = 1
    ↓
原来指向显示器
    ↓ close(1) + open(...)
现在指向文件
```

> **重定向保持文件描述符下标不变，只更换该下标在文件描述符表中的指针指向。**

使用 C 标准库输出时，重定向到普通文件后，`stdout` 可能变成全缓冲，因此要在关闭前调用 `fflush(stdout)`。

### 3-6-4 使用 `dup2` 系统调用

手动 `close(1)` 再 `open` 依赖“最小下标分配规则”，不够直接。`dup2` 可以明确指定目标下标。

```cpp
#include <unistd.h>     // 提供 close、dup2
#include <fcntl.h>      // 提供 open 和 O_* 标志
#include <stdio.h>      // 提供 printf 和 fflush

int main()
{
    int fd = open("./log", O_CREAT | O_RDWR, 0666); // 打开日志文件
    if (fd < 0) {                                   // 检查打开是否失败
        return 1;                                   // 失败时退出
    }

    if (dup2(fd, 1) < 0) {                          // 让 fd 1 指向 fd 对应的文件
        close(fd);                                  // 失败时关闭已打开文件
        return 1;                                   // 返回失败状态
    }

    printf("this line goes to log\n");              // stdout 底层的 fd 1 已指向 log
    fflush(stdout);                                 // 确保缓冲内容写入文件

    close(fd);                                      // 关闭原来的文件描述符
    return 0;                                       // 返回成功状态
}
```

接口：

```cpp
#include <unistd.h>                 // 提供 dup2 声明
int dup2(int oldfd, int newfd);      // 让 newfd 成为 oldfd 的副本
```


规则：

1. `newfd` 原来已打开时，先关闭它；
2. 让 `newfd` 指向与 `oldfd` 相同的打开文件；
3. 成功返回 `newfd`；
4. 失败返回 `-1`，并设置 `errno`。

```text
dup2(fd, 1)  → 让标准输出 fd 1 指向 fd 对应文件
dup2(fd, 0)  → 让标准输入 fd 0 指向 fd 对应文件
dup2(fd, 2)  → 让标准错误 fd 2 指向 fd 对应文件
```

> **`dup2(oldfd, newfd)` 会先关闭 `newfd`，再让 `newfd` 成为 `oldfd` 的副本。**

### 3-6-5 在 `minishell` 中添加重定向

shell 解析命令时，需要额外保存重定向信息：

```text
redir 类型：
NoneRedir   0   无重定向
InputRedir  1   <
OutputRedir 2   >
AppRedir    3   >>
filename         重定向目标文件名
```

解析流程：

```text
从命令字符串尾部寻找 <、>>、>
    ↓
截断重定向符号及文件名
    ↓
保存 filename
    ↓
TrimSpace 去掉文件名两侧空格
    ↓
子进程执行重定向
```

重定向必须由子进程执行，因为子进程随后会进行程序替换；这样不会破坏 shell 自己的标准输入和标准输出。

核心逻辑可表示为：

```text
fork
  ├─ 子进程：DoRedir → execvpe
  └─ 父进程：waitpid → 更新 lastcode
```

`DoRedir` 的三种情况：

```text
输入 <
    open(filename, O_RDONLY)
    dup2(fd, 0)

输出 >
    open(filename, O_CREAT | O_WRONLY | O_TRUNC, 0666)
    dup2(fd, 1)

追加 >>
    open(filename, O_CREAT | O_WRONLY | O_APPEND, 0666)
    dup2(fd, 1)
```

伪代码：

```cpp
void DoRedir()
{
    int fd = -1;                                      // 保存重定向文件描述符

    if (redir == InputRedir) {                       // 处理输入重定向 <
        fd = open(filename, O_RDONLY);               // 只读打开输入文件
        dup2(fd, 0);                                 // 把标准输入改到该文件
    } else if (redir == OutputRedir) {               // 处理输出重定向 >
        fd = open(filename, O_CREAT | O_WRONLY | O_TRUNC, 0666); // 覆盖写
        dup2(fd, 1);                                 // 把标准输出改到该文件
    } else if (redir == AppRedir) {                  // 处理追加重定向 >>
        fd = open(filename, O_CREAT | O_WRONLY | O_APPEND, 0666); // 追加写
        dup2(fd, 1);                                 // 把标准输出改到该文件
    }

    if (fd >= 0) {                                   // 确认文件打开成功
        close(fd);                                   // dup2 后原下标不再需要
    }
}
```

执行外部命令时：

```cpp
pid_t id = fork();                                   // 创建子进程

if (id == 0) {                                       // 子进程分支
    DoRedir();                                       // 子进程先完成重定向
    execvpe(gargv[0], gargv, genv);                  // 替换为目标程序
    _exit(1);                                        // exec 失败时退出
}

waitpid(id, &status, 0);                             // 父进程等待子进程
```

内建命令如 `cd`、`export`、`env`、`echo` 由 shell 自己执行；外部命令则使用“子进程重定向、再 `exec`”的顺序。

# 4. 理解“一切皆文件”

## 重新准确理解重定向【板书强调】

### 为什么需要标准错误流

假设程序同时输出两类内容：

- 正常结果：处理成功、计算结果等；
- 错误信息：文件打不开、参数错误等。

如果两类信息都写到同一个地方，那么把正常结果保存到文件时，错误信息也会混进去，后续就很难区分。因此，Linux 把输出分成两条流：

- **标准输出 `stdout`**：程序的正常输出；
- **标准错误 `stderr`**：程序的错误和提示信息。

这样就可以只保存正常结果，把错误信息继续显示在屏幕上。

> **标准输出和标准错误分开存在，是为了让正常消息与错误消息能够分别重定向。**

`printf` 和 `std::cout` 默认写入标准输出；`perror`、`std::cerr` 默认写入标准错误。

```cpp
#include <cstdio>      // 提供 printf、fprintf
#include <iostream>    // 提供 cout、cerr

int main()
{
    std::cout << "hello cout" << std::endl;       // 写入标准输出
    printf("hello printf\n");                     // 写入标准输出
    std::cerr << "hello cerr" << std::endl;       // 写入标准错误
    fprintf(stderr, "hello stderr\n");            // 写入标准错误
    return 0;                                     // 正常结束
}
```

编译并运行：

```bash
g++ stream.cc -o a.out                 # 编译源文件
./a.out                                # 标准输出和标准错误都显示在屏幕上
```

屏幕上可以看到：

```text
hello cout
hello printf
hello cerr
hello stderr
```

这里的“屏幕”并不是程序直接操作的特殊对象，而是程序写入了一个文件描述符，Shell 再把这个文件描述符连接到了显示器。

### 文件描述符与标准流

**文件描述符**：进程用来代表“已经打开的文件或设备”的一个整数下标。

每个进程启动时，通常已经打开了三个文件描述符：

| 文件描述符 | 名称            | 默认连接对象 | 常见用途   |
| ----: | ------------- | ------ | ------ |
|   `0` | 标准输入 `stdin`  | 键盘     | 读取输入   |
|   `1` | 标准输出 `stdout` | 显示器    | 输出正常结果 |
|   `2` | 标准错误 `stderr` | 显示器    | 输出错误信息 |

C++ 中的 `std::cin` 使用标准输入，`std::cout` 使用标准输出，`std::cerr` 使用标准错误。

这些数字不是普通的“输出编号”，而是进程文件描述符表中的下标。进程内部大致可以理解为：

```text
进程
 └── files_struct
      └── fd_array
           ├── fd_array[0] ──> 标准输入对应的 file 对象
           ├── fd_array[1] ──> 标准输出对应的 file 对象
           └── fd_array[2] ──> 标准错误对应的 file 对象
```

**凡是通过文件描述符 `1` 写入的内容，都会写到标准输出当前连接的对象。**&#x8FD9;个对象默认是显示器，但也可以被重定向到普通文件。

### 标准输出重定向

符号 `>` 会改变标准输出的去向：

```bash
./a.out > log.txt                     # 把文件描述符 1 的内容写入 log.txt
cat log.txt                           # 查看 log.txt 内容
```

此时：

```text
标准输出 cout/printf ──> log.txt
标准错误 cerr/perror ──> 屏幕
```

因此 `log.txt` 中通常只有：

```text
hello cout
hello printf
```

而屏幕上仍然显示：

```text
hello cerr
hello stderr
```

这正是标准输出和标准错误分离的意义。

命令 `>` 实际上可以理解为：

```text
关闭原来的 fd=1
打开 log.txt
让 log.txt 占用 fd=1
运行 ./a.out
```

因为文件描述符通常按照“最小可用下标”分配，所以关闭 `1` 后，新打开的文件就可能获得 `1`。

### 把标准输出和标准错误写入同一个文件【板书强调】

如果希望正常输出和错误输出都写入同一个文件，需要同时重定向 `1` 和 `2`：

```bash
./a.out 1>log.txt 2>&1                 # 先让标准输出写入 log.txt，再让标准错误指向 fd=1
cat log.txt                            # 查看合并后的输出
ls -l a.out log.txt stream.cc          # 查看文件大小
```

其中：

- `1>log.txt`：把文件描述符 `1` 重定向到 `log.txt`；
- `2>&1`：让文件描述符 `2` 指向文件描述符 `1` 当前指向的对象。

执行顺序很重要：

```text
先执行 1>log.txt：
fd=1 ──> log.txt

再执行 2>&1：
fd=2 ──> fd=1 当前指向的 log.txt
```

所以最终结果是：

```text
标准输出 ──┐
           ├──> log.txt
标准错误 ──┘
```

提要中的“stdin 和 stdout 打印到同一个文件”应准确理解为：**标准输出 `stdout` 和标准错误 `stderr` 写入同一个文件**；标准输入 `stdin` 是读取方向，不负责打印。

> **`2>&1` 的含义不是“把数字 2 写入 1”，而是让标准错误复制标准输出当前的去向。**

如果调换顺序，结果可能不同：

```bash
./a.out 2>&1 1>log.txt                 # 先让 fd=2 指向屏幕，再让 fd=1 指向 log.txt
```

此时：

```text
fd=1 ──> log.txt
fd=2 ──> 原来的屏幕
```

因此错误信息仍然会显示在屏幕上。

### 内核文件缓冲区

程序调用 `write` 后，数据通常先进入内核管理的文件缓冲区，再由内核安排写入设备或磁盘。这样做可以减少频繁访问慢速设备的次数。

这里要区分两层：

```text
用户程序
  ↓ write
内核文件缓冲区
  ↓
显示器、磁盘等设备
```

C 标准库还可能在用户空间额外提供一层缓冲区；本节这里强调的是内核中 `struct file` 关联的文件状态和缓冲管理。

## 一切皆文件的设计【板书强调——整块画图】

### 不同设备带来的问题

磁盘、键盘、显示器、鼠标、网卡的工作方式完全不同：

- 从磁盘读取数据；
- 从键盘获取按键；
- 向显示器输出字符；
- 从网卡接收数据。

如果上层程序必须分别学习每种设备的专用接口，程序会非常复杂，而且换一台设备就可能需要重写程序。

Linux 的解决方案是：**把各种设备统一抽象成文件，让上层程序使用统一的文件描述符和读写接口。**

### VFS：统一的文件接口

**VFS（Virtual File System，虚拟文件系统）**：内核提供的一层统一接口，让不同类型的文件和设备看起来都像文件。

```text
应用程序
   │
   │ open / read / write / close
   ▼
VFS：虚拟文件系统
   │
   ├── 普通磁盘文件
   ├── 键盘
   ├── 显示器
   ├── 鼠标
   ├── 网卡
   └── 管道 PIPE
```

应用程序只需要使用统一的 `read`、`write` 等操作，不必直接知道底层设备的具体实现。

> **“一切皆文件”不是说所有东西都真的存储在磁盘上，而是说它们都可以通过类似文件的统一接口访问。**

### `struct file` 与操作方法

在内核中，每个已经打开的文件或设备，都可以对应一个 `struct file` 对象。这个对象记录了三类重要信息：

1. 文件或设备的属性；
2. 当前文件的状态，例如读写位置；
3. 对这个对象进行操作的方法。

概念上可以表示为：

```cpp
struct file
{
    struct inode *f_inode;                  // 对应文件的 inode 元信息
    struct file_operations *f_op;           // 指向具体的操作函数集合
    int f_count;                             // 引用计数
    int f_flags;                             // 打开时使用的标志
    int f_mode;                              // 访问模式
    long f_pos;                              // 当前读写位置
};
```

`inode` 是文件在内核中的元信息对象，记录文件类型、权限、大小等信息；这里重点是 `f_op`。

`f_op` 指向 `file_operations`：

```cpp
struct file_operations
{
    ssize_t (*read)(...);                   // 读取数据的方法
    ssize_t (*write)(...);                  // 写入数据的方法
    long (*llseek)(...);                    // 修改读写位置的方法
    int (*open)(...);                       // 打开对象的方法
    int (*release)(...);                    // 关闭对象的方法
    int (*ioctl)(...);                      // 执行设备特殊控制的方法
    int (*mmap)(...);                       // 建立内存映射的方法
    unsigned int (*poll)(...);              // 查询是否可以读写的方法
};
```

这些成员大多数都是**函数指针**：变量中保存的不是数据，而是某个函数的地址。调用函数指针，就可以执行对应设备的操作。

内核源码中的 `file_operations` 还包含 `owner`、`aio_read`、`aio_write`、`readdir`、`flush`、`fsync`、`lock`、`splice_read` 等成员；除 `owner` 等管理字段外，大部分成员都是函数指针，分别对应不同的系统调用或文件操作。

### 驱动程序如何接入设备

**驱动程序**：把操作系统的统一接口翻译成某种具体硬件操作的软件。

例如：

```text
应用程序调用 write(fd, buffer, size)
                │
                ▼
VFS 根据 fd 找到 struct file
                │
                ▼
通过 f_op->write 找到对应函数
                │
                ▼
显示器驱动：把数据显示到屏幕
磁盘驱动：把数据写入磁盘
网卡驱动：把数据发送到网络
```

不同设备由不同驱动实现自己的读写函数：

```cpp
struct file_operations screen_ops
{
    .read  = screen_read,                  // 屏幕设备的读取方法
    .write = screen_write                  // 屏幕设备的写入方法
};

struct file_operations disk_ops
{
    .read  = disk_read,                    // 磁盘设备的读取方法
    .write = disk_write                    // 磁盘设备的写入方法
};
```

上层仍然只调用：

```cpp
read(fd, buffer, size);                    // 通过统一接口读取
write(fd, buffer, size);                   // 通过统一接口写入
```

设备不同，底层函数不同；但函数指针的类型、参数形式和调用方式保持统一。

> **统一的关键不是所有设备内部实现相同，而是它们向上提供相同形式的函数接口。**

### 结构体 `device`

内核还需要保存设备本身的信息，可以抽象为：

```cpp
struct device
{
    int type;                              // 设备类型
    int status;                            // 当前状态
    void *other_attributes;                // 其他设备属性
    struct list_head queue_head;           // 设备等待队列或任务队列
};
```

例如设备可能处于空闲、忙碌、错误等状态；如果设备暂时不能处理请求，请求可以进入队列等待。

### 上层看到的统一读写形式

从上层角度看，读写操作可以抽象为：

```cpp
struct upper_interface
{
    void (*read)(int fd, char *in);        // 通过 fd 读取数据
    void (*write)(int fd, char *out, int n); // 通过 fd 写出 n 字节
};
```

因此，一个文件对象的重要组成可以概括为：

```text
struct file
├── 属性和状态
├── 内核文件缓冲区
└── 操作方法：file_operations 中的函数指针
```

应用程序只拿到文件描述符 `fd`，内核则通过：

```text
fd
 ↓
files_struct 的 fd_array[fd]
 ↓
struct file
 ↓
f_op
 ↓
具体设备驱动函数
```

找到真正负责工作的代码。

### 为什么语言也要封装接口

如果每个程序都直接依赖某一种操作系统或设备的底层接口，那么程序换平台就可能无法运行。

因此，编程语言和标准库会再封装一层更容易使用、更加统一的接口：

```text
程序
 ↓
C/C++ 标准库
 ↓
操作系统系统调用
 ↓
VFS
 ↓
具体驱动
 ↓
硬件
```

这种封装可以降低使用难度，也提高程序的可移植性。程序使用者越多，语言和平台的适用范围越大，生态和市场占有率也越高。

### 系统调用与设备操作的对应关系

在 Linux 中，许多不同类型的对象都可以使用统一系统调用：

| 上层操作 | 常见系统调用  | 底层可能对应              |
| ---- | ------- | ------------------- |
| 读取数据 | `read`  | 读磁盘、读键盘、读管道、读系统状态   |
| 写出数据 | `write` | 写磁盘、写显示器、写管道、发送网络数据 |
| 修改位置 | `lseek` | 修改普通文件读写位置          |
| 控制设备 | `ioctl` | 执行设备专用控制            |
| 建立映射 | `mmap`  | 把文件或设备映射到进程地址空间     |

并不是所有设备都支持所有操作。例如普通文件通常支持 `lseek`，但某些管道和设备不支持；是否支持由对应的 `file_operations` 决定。

`file_operations` 的作用，就是把系统调用和驱动程序连接起来：

```text
系统调用 read
      │
      ▼
struct file_operations.read
      │
      ▼
具体驱动的 read 函数
```

`write`、`open`、`release`、`ioctl` 等也遵循同样的关系。

> **`file_operations` 是系统调用进入具体文件系统或设备驱动的“函数指针表”，每个成员通常对应一种操作。**

因此，Linux 能让普通文件、管道和设备共用许多操作接口，根本原因是：它们都被包装成带有统一操作方法的 `struct file` 对象，再由 `file_operations` 把统一接口分派到底层实现。
