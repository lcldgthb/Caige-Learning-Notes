## 1. 软件包管理器

### 1-1 什么是软件包
- 源码安装太麻烦 → 有人预编译成软件包放服务器上，包管理器 ≈ 手机应用商店【板书强调】
- 包管理器核心价值：自动解决依赖问题【板书强调：依赖→缺失→版本兼容性】
- 安装本质 = 网络下载 + 拷贝；必须 root 权限；装一次全系统可用【板书强调】
- yum（CentOS/RedHat）；apt（Ubuntu）

### 1-2 Linux软件生态
- 评估 OS 好坏看生态：内核/社区/文档/人群/配套软件【板书强调】
- 软件链条：开发者发源码 → 社区编译打包 → 官方源服务器 → yum/apt 下载
- 开源本质是一种商业模式【板书强调】
- yum/apt 内置下载链接；改链接 = 切换镜像源【板书强调】；国内镜像：阿里云/清华/中科大

### 1-3 yum具体操作
- 三板斧【板书强调】：`yum list | grep 包名`（查）/ `sudo yum install [-y] 包名`（装）/ `sudo yum remove [-y] 包名`（卸）
- Ubuntu：`apt search` / `apt show` / `sudo apt install/remove`
- 包名解读：x86_64=64位、el7=CentOS7、最后列 base=软件源名
- 注意：需 sudo；同一时刻只能装一个；报错自行搜索；软件由需求驱动【板书强调】
- 前提：网络畅通，`ping www.baidu.com` 验证

### 1-4 安装源
- CentOS：`/etc/yum.repos.d/`，CentOS-Base.repo=标准源（稳定）、epel.repo=扩展源（求全）【板书强调】
- 装扩展源：`sudo yum install -y epel-release`；云服务器已是国内源无需换

## 2. 编辑器Vim

### 2-1 Linux编辑器-vim使用
- 编辑器、编译器、调试器是分开的工具，vim 只是编辑器，区别于 IDE【板书强调】
- vi 的升级版，兼容 vi 全部指令，课堂统一讲 vim

### 2-2 vim的基本概念
- **多模式是 vim 的核心**【板书强调：后面所有操作都围绕模式展开】
- 三种模式：正常/命令模式（移动光标、删除复制）、插入模式（输入文字）、末行模式（保存退出、查找替换）
- 共 12 种模式，掌握 3 种即可

### 2-3 vim的基本操作
- `vim 文件名` 进入，默认正常模式；i/a/o 进插入模式（光标前/后/新行）；ESC 回正常模式；`:` 进末行模式
- `:w` 保存、`:wq` 存盘退出、`:q!` 强制不存退出
- 批量注释【板书强调】：ctrl+v 选区域 → shift+i 输入 // → ESC；去注释：ctrl+v 选区域 → d

### 2-4 vim正常模式命令集
- 移动：hjkl（左下上右）、G 文末、gg 文首、$ 行尾、^ 行首、w/e/b 按词跳、ctrl+f/b 前后翻页、ctrl+d/u 半页
- 删除：x 删字符、#x 删 n 个、dd 删行、#dd 删 n 行
- 复制：yy 复制行、#yy、yw；p 粘贴（y 系必须配 p）
- 替换 r/R；撤销 u、恢复 ctrl+r；更改 cw；跳行 #G

### 2-5 vim末行模式命令集
- `:set nu` 行号、`:#` 跳行、`/关键字` 向后找（n 下一个）、`?关键字` 向前找
- `:w` 保存、`:q` 退出、`:wq` 保存退出

### 2-6 vim操作总结
- 三模式 + 打开/关闭/查看/查询/插入/删除/替换/撤销/复制；当堂口头模式切换练习

### 2-7 简单vim配置[了解]
- 系统配置 /etc/vimrc（所有用户）；个人配置 ~/.vimrc
- 常用：syntax on 高亮、set nu 行号、set shiftwidth=4 缩进
- 插件 TagList/WinManager（了解）；官方教程 `vimtutor`

## 3. 编译器gcc/g++

### 3-1 背景知识
- 语言 → 编译器 → 可执行程序【板书强调】；编译四阶段：预处理 → 编译 → 汇编 → 链接

### 3-2 gcc编译选项
- 格式：`gcc [选项] 源文件 -o 目标文件`
- 预处理：宏替换/去注释/条件编译/头文件展开，`gcc -E hello.c -o hello.i`【板书强调：预处理的本质就是修改编辑我们的文本代码】
- 编译：`gcc -S hello.i -o hello.s` 生成汇编；汇编：`gcc -c hello.s -o hello.o` 生成机器码；链接：`gcc hello.o -o hello`
- 条件编译用途【板书强调】：专业版/收费版按业务动态裁剪、内核源代码裁剪；命令行宏定义 `gcc -DM` / `-DM=100`
- 为什么先变成汇编：从打孔编程 → 助记符（汇编）→ 高级语言的历史必然；编译器自举【板书提及】

### 3-3 动态链接和静态链接
- 多文件各自编译成 .o，链接合并成可执行程序
- 静态链接缺点：浪费空间（公共代码多份副本）、更新困难（库改了要全部重编译）；优点：运行快、不依赖外部
- 动态链接：运行时才加载库；`ldd hello` 查看依赖的动态库
- printf 的实现在哪？在 libc.so.6 里，gcc 默认去 /usr/lib 找——这就是链接的作用

### 3-4 静态库和动态库
- 静态库 .a：链接时把库代码全部拷进可执行文件，文件大但运行时不需库；动态库 .so：运行时才加载，节省资源，gcc 默认动态链接【板书强调】
- Windows 对应：动态库 .dll、静态库 .lib
- **网吧例子【板书强调，必讲】**：动态链接 = 去网吧上网（网吧=库，大家共用，网吧关门=库缺失，所有程序都无法运行）；静态链接 = 把网吧电脑买回家（拷给自己，链接完成后静态库就不再需要）
- 动静态库对比【板书强调】：动态库可执行程序体积小；静态链接内存中大量重复代码；动态库不能缺失；动态链接节省内存磁盘
- 动态库的本质【板书强调】：语言层面公共的代码，在内存中只出现一份
- 云服务器静态库需自装：`yum install glibc-static libstdc++-static -y`；否则 -static 报 cannot find -lc
- 验证：`file` 看 dynamically/statically linked；`ldd` 看依赖

### 3-5 gcc其他常用选项 - 了解即可
- -E/-S/-c/-o/-static/-g（调试信息，gdb 要用）/-shared/-O0~O3 优化级别/-w/-Wall

## 4. 自动化构建-make/Makefile

### 4-1 背景
- 大型工程源文件成千上万，手动 gcc 不现实；makefile 定义编译规则，一个 make 命令全自动编译
- **make 是命令，makefile 是文件**【板书强调】，两者搭配完成自动化构建

### 4-2 理解
- 核心概念就两个：**依赖关系 + 依赖方法**【板书强调】
- 月底要钱例子【板书强调】：儿子（目标）向父亲（依赖）打钱（依赖方法）——先有关系，才有动作

### 4-3 基本使用
```makefile
myproc:myproc.c
	gcc -o myproc myproc.c
.PHONY:clean
clean:
	rm -f myproc
```
- 目标:依赖 顶格写，命令前必须是 **Tab**【板书强调】
- clean 这类不被第一个目标关联的命令不会自动执行，需 `make clean` 显式调用；`.PHONY` 声明伪目标，总是被执行
- 为什么默认不重复编译？make 对比可执行文件和源文件的 Modify 时间【板书强调】；文件 = 内容 + 属性（Modify/Change/Access 三个时间）
- .PHONY 结论：让 make 忽略源文件和目标文件的时间对比【板书强调】

### 4-4 推导过程
- myproc ← myproc.o ← myproc.s ← myproc.i ← myproc.c，依赖链像**栈**一样入栈再出栈执行【板书强调】
- make 工作方式：找 Makefile → 第一个目标为最终目标 → 目标不存在或依赖比目标新就执行命令 → 依赖不存在就继续向下找规则 → 找不到就报错退出
- make 只管文件依赖性，不管命令本身对错

### 4-5 适度扩展语法
- 变量：BIN=proc.exe、CC=gcc、SRC=$(wildcard *.c)、OBJ=$(SRC:.c=.o)
- 自动变量：$@ 目标文件、$^ 依赖列表、$< 第一个依赖；%.o:%.c 模式匹配；@ 命令不回显

## 5. Linux第一个系统程序-进度条

### 5-1 补充-回车与换行
- 老式打字机例子【板书强调】：**回车 \r = 回到行首，换行 \n = 换到下一行**，是两个动作；键盘回车键 = \r\n

### 5-2 行缓冲区
- 现象对比：printf 带 \n 立即显示；不带 \n 则 sleep 期间看不到——内容在哪？**在缓冲区里**【板书强调】
- 缓冲区 = 一段内存块；行刷新策略；`fflush(stdout)` 立即刷新【板书强调】
- extern FILE *stdin/stdout/stderr；显示器只认字符——字符设备【板书提及】

### 5-3 练手-倒计时程序
- `printf("%-2d\r", i); fflush(stdout);` —— \r 回行首覆盖打印 + 强制刷新，是动态效果的核心组合

### 5-4 进度条代码
- 样式 `[### ][53%][/]`，旋转光标字符 |/-\【板书强调】
- version1 原理版本：固定 101 格 buffer 逐格填充；version2 真实版本：FlushProcess(total, current) 按下载进度比例刷新【板书强调：结合场景，边下载边更新进度条】
- 配套 Makefile 用 wildcard/模式规则实现多文件自动化构建

## 6. 版本控制器Git

### 6-1 版本控制器
- 手动副本之痛：报告-v1/v2/最终版/究极进化版……版本多了记不清改了什么
- 版本控制器 = 记录工程每一次改动和版本迭代的管理系统，也方便多人协作
- 两大价值【板书强调】：1. 数据安全 2. 协作开发
- git 是底层的版本控制器软件，既是 client 也是 server【板书强调】；本地仓库 vs 远端仓库（云服务器）；github/gitee 是基于 git 的网站平台【板书强调】；去中心化、分布式

### 6-2 git 简史
- Linux 内核维护 1991-2002 靠手工补丁 → 2002 用商业软件 BitKeeper → 2005 年被收回免费权 → Linus 被迫自研 Git
- 设计目标：速度、简单设计、非线性开发（成千上万并行分支）、完全分布式、高效管理超大项目

### 6-3 安装 git
- `yum install git` / `apt install -y git`；`git --version` 验证

### 6-4 在 Github 创建项目
- 注册（邮箱验证）→ New repository → 复制项目链接 → `git clone [url]` 下载到本地

### 6-5 三板斧
- `git add 文件名`（告知 git 管理，进暂存区）→ `git commit -m "日志"`（提交本地仓库）→ `git push`（同步远端）【板书强调：提交只提交变化的部分】
- 首次使用要配置 username/email【板书强调】；版本管理只管理源文件【板书强调】
- .gitignore：需要忽略的特定后缀文件列表【板书强调】
- push 冲突（rejected）：远端仓库比本地新 → 先 `git pull` 同步再 push【板书强调】
- 其他：git log/status/pull

## 7. 调试器-gdb/cgdb使用

### 7-1 样例代码
- mycmd.c：Sum(1,100) 累加示例，调试演示用

### 7-2 预备
- 程序发布两种模式：debug（测试用）和 release（上线用）【板书强调：debug→测试，release→上线】
- **gcc/g++ 默认 release 模式，无法直接调试；必须用 `-g` 编译出 debug 版本**【板书强调】
- 验证：`file mycmd` 看 with debug_info；`readelf -S 程序 | grep -i debug` 看 .debug_info 等段【板书强调】

### 7-3 常见使用
- `gdb 程序名` 进入，quit/ctrl+d 退出
- list/l 看源码、r 运行、b 行号/函数名设断点、info b 看断点
- **n/next 逐过程（不进函数，≈F10）、s/step 逐语句（进函数，≈F11）**【板书强调】
- finish 执行到函数返回、p 变量 打印、set var 修改变量、c 继续、d 断点编号删除、disable/enable 断点
- display 变量 每次停下自动显示、undisplay 取消、until 行号、bt 调用栈、info locals 局部变量
- gdb 不退出时断点编号依次递增【板书提及】；gdb 会自动记录最新一条输入指令【板书提及】

### 7-4 常见技巧-加餐（三个 debug 技巧）【板书强调】
- watch 变量：值一变就暂停并通知——怀疑某个不该变的变量被改时用
- set var 变量=值：现场改值验证猜想（如 flag=0 导致结果为 0，改成 1 验证）
- 条件断点两种加法【板书强调，语法区别易错】：新增 `b 行号 if i==30`（有 if）；给已有断点追加 `condition 2 i==30`（无 if，2 是断点编号）
- cgdb：分屏可视化版 gdb，ESC 进代码屏、i 回 gdb 屏；`yum/apt install -y cgdb`

## 附录：更新软件源实操（换源手册）

> 定位：第 1 节"安装源"的落地操作手册——理论讲了"改链接=换源"，这里是分步实操。

### 附录1 Centos7更新yum源
- 步骤主线：备份 → 下载新源配置 → 清缓存重建 → 更新系统 →（可选恢复）→ 验证
- ① 备份：`sudo mkdir /etc/yum.repos.d/backup` + `sudo mv /etc/yum.repos.d/*.repo /etc/yum.repos.d/backup/`
- ② 下载新源（二选一）：阿里云 `sudo curl -o /etc/yum.repos.d/CentOS-Base.repo http://mirrors.aliyun.com/repo/Centos-7.repo`；清华 `... https://mirrors.tuna.tsinghua.edu.cn/repo/Centos-7.repo`
- ③ 清缓存重建：`sudo yum clean all` + `sudo yum makecache`
- ④ 更新系统：`sudo yum update`
- ⑤ 恢复（可选）：`sudo mv /etc/yum.repos.d/backup/*.repo /etc/yum.repos.d/`
- ⑥ 验证：`sudo yum repolist`

### 附录2 Ubuntu 更新apt源
- 步骤主线与 yum 版一致：备份 → 替换 sources.list → 检查版本代号 → 更新缓存 →（可选升级）→ 验证 →（可选恢复）
- ① 备份：`sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak`（apt 源配置是单个文件，和 yum 的目录不同）
- ② 替换（二选一）：阿里云 `sudo wget -O /etc/apt/sources.list http://mirrors.aliyun.com/repo/ubuntu-sources.list`；清华 `... https://mirrors.tuna.tsinghua.edu.cn/ubuntu/sources.list`
- ③ 检查适配：每行必须含 Ubuntu 20.04 代号 `focal`；混入 bionic/jammy 要删掉
- ④ 更新缓存：`sudo apt update`
- ⑤ 升级（可选）：`sudo apt upgrade` 或 `sudo apt full-upgrade`
- ⑥ 验证：`sudo apt policy`
- ⑦ 恢复（可选）：`sudo cp /etc/apt/sources.list.bak /etc/apt/sources.list` + `sudo apt update`
- 易混淆点：yum 源 = /etc/yum.repos.d/ 下多个 .repo 文件；apt 源 = /etc/apt/sources.list 单文件
