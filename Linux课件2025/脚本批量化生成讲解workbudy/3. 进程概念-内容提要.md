# 3. 进程概念-内容提要

> 来源：《3. 进程概念.pdf》全文 + 板书 20241109_操作系统开始 / 20241114_进程状态 / 20241117_切换与调度 / 20241119_环境变量 / 20241121_虚拟内存
> 【板书强调】= 老师板书内容，即课堂重点
> 本节目标：冯诺依曼体系 → OS 如何"管理" → 进程/PCB/fork → 进程状态（僵尸/孤儿）→ 优先级与 O(1) 调度 → 环境变量 → 虚拟地址空间

## 1. 冯诺依曼体系结构

- 五大部件：输入单元（键盘/鼠标/网卡）、CPU（运算器+控制器）、输出单元（显示器/网卡/磁盘）、**存储器=内存**【板书强调】
- **CPU 数据层面只和内存打交道，不能访问外设；外设输入输出也只经过内存**【板书强调】——所有设备都只能直接和内存打交道
- 各设备速度差异巨大：CPU 寄存器纳秒级、外设毫秒级【板书强调】；体系结构的效率由设备间"拷贝"效率决定【板书强调】
- 存储金字塔【板书强调】：寄存器 → 高速缓存(L1~L3 SRAM) → 内存(DRAM) → 磁盘 → 网盘，越上越快越贵
- 经典应用题【板书强调】：QQ 聊天/发文件的数据流——A 的键盘→内存→网卡→网络→B 的网卡→内存→显示器（两台机器各自一套冯诺依曼体系，网卡既是输入也是输出设备）

## 2. 操作系统(Operator System)

### 2-1 概念与定位
- OS = 一款纯正的"搞管理"的软件【板书强调】；包括内核（进程/内存/文件/驱动管理）+ 其他程序（shell、函数库等）
- **广义 OS = 外壳(shell, glibc, 程序) + 狭义 OS = 内核**【板书强调】
- printf 的本质：把你的数据写到了硬件（显示器）里！【板书强调】

### 2-2 设计目的
- 对下：与硬件交互，管理所有软硬件资源（**这是手段**）【板书强调】
- 对上：为用户程序提供良好的执行环境（**这才是目的**）【板书强调】

### 2-3 如何理解"管理"
- 管理三句话【板书强调】：①管理者和被管理者可以不见面 ②靠"数据"管理 ③数据由中间层获取
- 管理的本质 = 对数据的管理（校长用 Excel 表管理学生，决策权在校长、执行在辅导员）【板书强调】
- **计算机管理的方法论：先描述（struct 结构体），再组织（链表等数据结构）**【板书强调】——这是贯穿全课的核心思想

### 2-4 系统调用和库函数
- 软硬件层次结构【板书强调】：用户 → 库/shell → 系统调用接口 → 内核 → 驱动 → 硬件；访问硬件必须贯穿整个层次
- 系统调用 = OS 提供的接口；**OS 不相信任何用户**（银行窗口类比：系统调用=窗口，参数/返回值=和柜员交互）【板书强调】
- 库函数可能底层封装了系统调用【板书强调】；Linux/Windows/MacOS → C 语言 → C 函数
- 承上启下：OS 管理进程 = 先描述（task_struct）再组织（链表）【板书强调】

## 3. 进程

### 3-1 基本概念与基本操作
- 三种视角【板书强调】：课本概念（程序执行实例，被划掉）→ 内核观点（分配系统资源的实体）→ **当前结论：进程 = 内核数据结构(task_struct) + 自己的代码和数据**【板书强调】
- OS 必须对多个加载进内存的程序进行管理：先描述再组织【板书强调】；**对进程的管理 = 对 task_struct 双向链表的增删查改**【板书强调】
- task_struct 内容：标示符、状态、优先级、程序计数器、内存指针、上下文数据、I/O 状态、记账信息
- 查看进程：`ps aux / ps axj`（a 所有用户、x 无终端、j 作业信息、u 用户格式）；`/proc/PID/` 目录（exe=可执行文件、cwd=当前工作目录）；`kill -9 PID`、ctrl+c 杀前台进程【板书强调】
- getpid/getppid 是系统调用（man 手册第 2 区）【板书强调】
- **PPID 实验：命令行进程的父进程都是 bash**——bash 是命令行解释器，每次登录生成一个 bash，分配会话【板书强调】

### 3-1-6 fork 初识【板书重点】
- fork 有两个返回值：父进程返回子进程 PID、子进程返回 0、失败返回 -1【板书强调】
- **父子代码共享（只读），数据各自私有（写时拷贝）**【板书强调】——子进程没有自己的代码和数据，以父进程为模板
- fork 三个经典问题【板书强调】：①为什么给父子返回不同值？父:子=1:n，父需要子 PID 辨识管理所有子进程 ②为什么一个函数返回两次？fork 内部：申请新 pcb→拷贝父 pcb→挂进进程列表和调度队列→return id（return 本质是写变量，此时进程已被独立调度） ③一个变量怎么让 if/else 同时成立？——牵扯虚拟地址和写时拷贝，程序地址空间一节解答
- fork 后用 if/else 分流；g_val 实验证明进程具有独立性

### 3-2 进程状态
#### 理论基础【板书重点】
- **运行：一个 CPU 一个调度队列 runqueue，队列里的进程状态都是 running**（不一定正在 CPU 上跑）【板书强调】
- **阻塞：进程等非 CPU 资源（键盘等）就绪，PCB 挂到设备的等待队列 wait_queue**；OS 管理硬件也是先描述再组织（struct device）【板书强调】
- **挂起：内存不足时，进程的代码和数据换出到磁盘 swap 分区，PCB 仍留内存**【板书强调】
- **进程状态的变化 = 数据结构的增删查改，本质是在不同队列间流动**【板书强调】
- Linux 内核双向链表实现：list_head（next/prev）嵌入 task_struct 内部，用 offsetof 偏移量换算回结构体首地址【板书强调】

#### 内核状态【板书重点】
- R 运行：在运行队列中即 running【板书强调】
- S 睡眠：可中断睡眠（浅睡眠），等待事件完成
- D 磁盘休眠：**不可中断**睡眠（深睡眠），等 IO 结束（dd 大文件实验），不可被 kill 杀掉【板书强调】
- T 停止：SIGSTOP 暂停 / SIGCONT 恢复；debug 断点即 T【板书强调】；t = tracing stop（gdb 追踪中）
- X 死亡：瞬时状态，任务列表看不到
- Z 僵尸【板书重点】：**子进程退出、父进程还在运行但不读取退出信息 → Z 状态一直存在**【板书强调】
- 进程退出的目的：让父进程知道"你交给我的任务办得怎么样了"，退出信息在 task_struct 里【板书强调】

#### 僵尸进程危害与孤儿进程【板书重点】
- 僵尸危害推理链【板书强调】：退出状态必须维持 → PCB 必须维护 → 父进程不回收则 PCB 永远占用内存 → **内存泄漏**
- 创建僵尸进程实验：子 exit 后看 STAT=Z+（ps axj）
- **孤儿进程：父进程先退出，子进程被 1 号 init/systemd 进程领养**，之后由它回收【板书强调】

### 3-3 进程优先级
- 优先级存在的原因：CPU 资源少、进程多 → 竞争性【板书强调】
- **PRI：进程优先级，值越小越早执行，默认 80**【板书强调】
- **NI（nice 值）：优先级的修正数据，不是优先级本身**【板书强调】；PRI(new) = PRI(old) + nice；nice 范围 -20~19 共 40 级；调整优先级 = 调整 nice
- 修改：top → r → 输 PID → 输 nice 值；另有 nice/renice 命令、getpriority/setpriority 系统函数
- 四个概念【板书强调】：竞争性（进程多 CPU 少）、独立性（多进程互不干扰，独享资源）、并行（多 CPU 同时跑多个进程）、并发（一个 CPU 用切换方式让多进程推进）

### 3-4 进程切换【板书重点】
- 分时操作系统：**每个进程有时间片，时间片到就被 OS 从 CPU 剥离下来**【板书强调】
- **进程切换 = 上下文切换 = CPU 寄存器内容的保存与恢复**【板书强调】
- CPU 内寄存器只有一套，**保存下来的上下文数据可以有很多份，保存在各自进程的 task_struct 里**【板书强调】
- 切换过程：离开 CPU → 保存上下文到 task_struct → 恢复下一个进程的上下文到 CPU 寄存器（学生-士兵类比）【板书强调】

### 3-5 Linux2.6 内核 O(1) 调度队列【板书重点】
- 一个 CPU 拥有一个 runqueue；多 CPU 需负载均衡
- 优先级分区：**[0,99] 实时优先级（不考虑）；[100,139] 普通优先级，对应 nice -20~19**【板书强调】
- **queue[140]：数组下标 = 优先级，相同优先级 FIFO 排队**【板书强调】
- **bitmap[5]：140 个比特位（5×32），标记队列是否为空，快速定位最高优先级非空队列**【板书强调】——查找 O(1)
- **active 指针（活动队列：时间片未耗尽的进程）与 expired 指针（过期队列：时间片耗尽的进程）**【板书强调】
- 活动队列越跑越少、过期队列越积越多 → **swap 交换两个指针 = 直接获得一批新的活动进程**【板书强调】
- 总结：找最合适调度进程的时间复杂度为常数，不随进程数增长【板书强调】

## 4. 命令行参数和环境变量

### 4-1 基本概念【板书重点】
- 环境变量 = 指定 OS 运行环境的参数（NAME=内容）；具有**全局属性，可被子进程继承**【板书强调】
- **bash 是命令行解释器**，bash 内存有两张表：**命令行参数表 argv + 环境变量表 environ**【板书强调】
- **环境变量最开始从系统配置文件读取**（~/.bash_profile、~/.bashrc）【板书强调】

### 4-2 常见环境变量与命令
- PATH（命令搜索路径）、HOME（用户主目录）、SHELL（=/bin/bash）【板书强调】
- **PATH 解释了为什么系统指令不用带路径**（ls 在 /usr/bin 下，通过 PATH 找到）【板书强调】；`export PATH=$PATH:路径` 可添加自己的程序
- 相关命令：echo（显示）、export（设置/导出）、env（显示全部）、unset（清除）、set（本地变量+环境变量都显示）

### 4-3 代码获取环境变量【板书重点】
- 三种方式【板书强调】：①main 第三参数 `char *env[]`（main 原始版有 3 参数，start 函数传入）②`extern char **environ`（libc 全局变量）③`getenv("NAME")`（最常用，查特定变量）
- 环境表 = 字符指针数组，每项指向 '\0' 结尾的环境字符串
- **命令行参数的意义：实现指令的选项功能**（如 ls -a -l：main 的 argc/argv 解析）【板书强调】

### 4-4 全局属性实验【板书重点】
- 本地变量（shell 里 `a=10`）：**只在 bash 内部使用，不被子进程继承**【板书强调】
- `export MYENV="hello"` 导出后子进程才能读到 → 证明继承性【板书强调】
- export 是 **bash 内建命令 built-in command**：不创建子进程，bash 自己调用函数完成【板书强调】
- 权限思想实验【板书强调】：getenv("USER") 判断身份——"如果我想写一个程序只能我执行，其他人一律不让执行"

## 5. 程序地址空间

### 5-1 布局与验证【板书重点】
- 32 位平台：2^32 地址 = **4GB**（1G 内核空间 + 3G 用户空间）【板书强调】；64 位 = 2^64 地址
- 布局从低到高【板书强调】：代码段 → 已初始化数据段 → 未初始化数据段(bss) → 堆 → 共享区（动态库）→ 栈 → 命令行参数/环境变量 → 内核空间（栈向下、堆向上增长）
- **这不是物理内存，是虚拟地址空间，CPU 直接访问**【板书强调】
- 区域验证实验：打印各区域地址（code/global/heap/stack/argv/env），地址从小到大与布局图对应；堆上连续 malloc 地址递增、栈上变量地址递减

### 5-2 虚拟地址实验【板书重点】
- fork 后父子打印 `&g_val`：**地址相同，但值不同**（子改 100、父仍 0）【板书强调】
- 推理链【板书强调】：内容不同 → 绝不是同一变量 → 地址却相同 → **该地址绝对不是物理地址 → C/C++ 用到的地址全部是虚拟地址！物理地址用户一概看不到，由 OS 统一管理**【板书强调】
- **页表：虚拟地址 ↔ 物理地址的映射表；1 个进程 = 1 个虚拟地址空间 + 1 套页表**【板书强调】
- 写时拷贝页表图【板书强调】：父子页表初始都映射同一物理页 → 子进程修改 g_val → OS 底层拷贝新物理页 → 修改子进程页表映射 → **进程具有独立性（内核数据结构独立 + 代码和数据独立）**【板书强调】

### 5-3 如何理解（两个类比）【板书重点】
- **大富翁类比**【板书强调】：大富翁 10 亿承诺给 4 个私生子，每个私生子都认为自己有 10 亿——实际要花钱时才兑现；每个进程都认为自己独占 4G 物理内存；**虚拟地址空间的本质 = 一个数据结构 struct mm_struct**
- **38 线类比**【板书强调】：区域划分只需确定开始和结束；区域用数值机械化表示（struct 里存 start/end，调整区域 = 改数值）；mm_struct 里全是 start_code/end_code、start_brk、start_stack 等 pair

### 5-4 mm_struct 与 VMA【板书重点】
- 每个进程只有一个 mm_struct，task_struct 中有指针指向它
- VMA（vm_area_struct）描述每个虚拟内存区域；**两种组织方式并存：区域少用单链表（mmap 指向），区域多用红黑树（mm_rb）**【板书强调】
- 并存原因【板书强调】：①减少相对时间（红黑树查找快）②减少内存浪费（链表省空间）
- mm_struct 初始化：区域的值从可执行程序加载时读来【板书强调】
- 澄清【板书强调】：创建进程可以先只创建 task_struct + mm_struct + 页表，不必先加载代码和数据

### 5-5 为什么要有虚拟地址空间【板书重点】
- 直接用物理内存的三大问题【板书强调】：①安全风险（木马可改任意内存）②地址不确定（每次加载位置不同）③效率低下（换出要整体拷贝）
- 三大收益【板书强调】：①**地址从无序变有序** ②**地址转换时做合法性判定，保护物理内存**（野指针写常量区 → 转换时拦截崩溃，而不是改坏系统）③**进程管理和内存管理解耦合**（物理内存可任意位置加载；new/malloc 先在地址空间申请，物理内存延迟分配，真正访问时才建页表映射，用户 0 感知）
- 总结一句：**地址空间，扩展一层！**【板书强调】——不让进程直接接触物理地址
