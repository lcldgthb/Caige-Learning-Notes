## 1. 冯诺依曼体系结构

- 五大部件【板书强调】：输入设备（键盘/鼠标/话筒/摄像头/网卡/磁盘）、输出设备（显示器/磁盘/网卡/打印机）、CPU=运算器+控制器、存储器=内存
- Input/Output → IO；**站在内存角度理解 IO**【板书强调】
- **软件运行必须先加载**：程序运行之前在磁盘上（文件形式）；CPU 获取、写入数据只能从内存中进行；CPU 执行我们的代码、访问我们的数据【板书强调】
- **CPU 在数据层面只和内存打交道，外设也只和内存打交道**【板书强调】——数据从一个设备"拷贝"到另一个设备，**体系结构的效率由设备间"拷贝"效率决定**【板书强调】
- 速度差：外设毫秒级 vs CPU 纳秒级【板书强调】
- 存储金字塔【板书强调】：L0 寄存器 → L1~L3 高速缓存(SRAM) → L4 主存(DRAM) → L5 本地二级存储(本地磁盘) → L6 远程二级存储(分布式文件系统/Web 服务器)；越上越快越贵越小——当代计算机是性价比的产物（芯片技术+摩尔定律）
- 经典应用题【板书强调】：QQ 聊天/发文件的数据流——A 的键盘→内存→网卡→网络→B 的网卡→内存→显示器；两台机器各自一套冯诺依曼体系，网卡既是输入也是输出设备

## 2. 操作系统(Operator System)

### 2-1 概念与定位
- OS = 一个基本的程序集合，一款进行软硬件**管理**的软件【板书强调】；三问框架：是什么？为什么？怎么办？【板书强调】
- OS 包括：内核（进程管理/内存管理/文件管理/驱动管理）+ 其他程序（函数库、shell 程序等）
- **广义 OS = 外壳(shell、glibc、原生库、预装软件) + 狭义 OS = 内核(kernel)**【板书强调】；安卓开发类比：安卓 = 外壳，Linux 内核在里
- printf 的本质：把你的数据写到了硬件（显示器）里【板书强调】

### 2-2 设计目的
- 对上：为用户程序（应用程序）提供良好的执行环境（**这才是目的**）【板书强调】
- 对下：与硬件交互，管理所有软硬件资源（**不是目的，是手段**）【板书强调】
- 软硬件体系结构层状结构【板书强调】：用户（指令/开发/管理操作）→ 用户操作接口（shell 外壳/库/部分指令）→ system call 系统调用接口 → 内核 → 驱动 → 硬件

### 2-3 如何理解"管理"
- 管理三句话【板书强调】：①管理者和被管理者可以不需要见面 ②根据"数据"进行管理 ③不见面如何得到数据？由中间层获取
- 校长类比完整链【板书强调】：校长（管理者，决策权）/ 辅导员（中间层，执行）/ 学生（被管理者）；事情=决策+执行；校长 1.0 用 Excel 表格（姓名/性别/年龄/籍贯/紧急人/各科成绩/职位/宿舍号）管理学生 → **管理学生 = 对 Excel 数据的增删查改**
- 校长 2.0 = 程序员【板书强调】：`struct stu {姓名/年龄/籍贯...; struct stu *next}` → 一个个学生对象用链表穿起来 → **日常管理学生的工作 = 对链表的增删查改 = 建模的过程，对任何"管理"场景进行建模**
- **计算机管理的方法论：先描述（struct 结构体），再组织（链表等数据结构）**【板书强调】——贯穿全课的核心思想；延伸到 C++：先描述再组织 → 类 → STL【板书强调】

### 2-4 系统调用和库函数
- **访问操作系统必须使用系统调用——其实就是函数，只不过是系统提供的**【板书强调】
- **我们的程序只要访问了硬件，就必须贯穿整个软硬件体系结构**【板书强调】
- **OS 不相信任何用户或者人**【板书强调】——银行类比：系统调用=银行窗口，用户只通过窗口（输出参数和返回值）与 OS 做数据交互；大堂经理=库/外壳/指令
- 库函数可能在底层封装了系统调用【板书强调】（上下层关系）；Linux/Windows/MacOS → C 语言 → C 函数

## 3. 进程

### 3-1 基本概念与基本操作
- 三种视角【板书强调】：课本概念（程序的一个执行实例，正在执行的程序——被划掉）→ 内核观点（担当分配系统资源 CPU 时间/内存的实体）→ **结论：进程 = 内核数据结构 PCB(task_struct) + 自己的代码和数据**【板书强调】
- OS 必然要对多个加载进内存的程序进行管理 → 先描述再组织 → **对进程的管理 = 对 task_struct 双向链表的增删查改**【板书强调】
- task_struct（进程控制块 PCB）内容分类【板书强调】：
  - 标示符：描述本进程的唯一标示符，区别其他进程
  - 状态：任务状态、退出代码、退出信号等
  - 优先级：相对于其他进程的优先级
  - 程序计数器：程序中即将被执行的下一条指令的地址
  - 内存指针：程序代码和进程相关数据的指针、和其他进程共享的内存块的指针
  - 上下文数据：进程执行时处理器寄存器中的数据
  - I/O 状态信息：显式的 I/O 请求、分配给进程的 I/O 设备、被进程使用的文件列表
  - 记账信息：处理器时间总和、时钟数总和、时间限制、记账号等
- **进程的所有属性都可以直接或间接通过 task_struct 找到；历史上执行的所有指令、工具、自己的程序，运行起来全部都是进程**【板书强调】
- 查看进程命令【板书强调】：`ps ajx`（列：PPID PID PGID SID TTY TPGID STAT UID TIME COMMAND）、`ps aux`；配合 `head -1` 显示表头、`grep` 过滤
- `kill -9 PID` 杀进程；ctrl+c 杀前台进程【板书强调】
- getpid/getppid【板书强调】：`#include <sys/types.h>` `#include <unistd.h>`；`pid_t getpid(void)` 获取进程 ID、`pid_t getppid(void)` 获取父进程 ID；是系统调用（man 手册第 2 区）
- `/proc/PID/` 目录【板书强调】：`ls /proc/PID -l` 查看；两个补充知识：**exe → 进程对应的可执行文件；cwd → 进程记录的当前工作目录**（cwd 解释了 `fopen("./b/c/d.txt","w")` 相对路径相对的是谁）
- **PPID 实验**【板书强调】：多次运行 `./myprocess`，pid 每次变、父进程 id 不变（19811）；`ps ajx | grep 19811` 查出父进程是 `-bash`（STAT=Ss+）→ **命令行解释器(bash)本质是一个进程；OS 会给每一个登录用户分配一个 bash**（王婆和实习生的关系）
- **fork 初识**【板书强调】：
  - man FORK(2)：`#include <unistd.h>`；`pid_t fork(void)`——create a child process
  - **fork 有两个返回值**：成功时父进程返回子进程 PID、子进程返回 0；失败父进程返回 -1（`perror("fork")` 报错）
  - **子进程没有自己的代码和数据，因为目前没有程序新加载**——以父进程为模板，代码共享（只读）、数据各自私有【板书强调】
  - fork 三个经典问题【板书强调】：
    ① 为什么给父子返回不同的值？——父:子 = 1:n，父进程需要子的 PID 来辨识和管理每一个子进程
    ② 为什么一个函数会返回两次？——fork 内部：申请新 pcb → 拷贝父 pcb 给子进程 → 子 pcb 放入进程 list、甚至放入调度队列 → **return 之前子进程已经被创建、甚至被调度了**；return 的本质是写入变量，父子各自执行一次
    ③ 为什么一个变量 `id` 既 ==0 又 >0，导致 if/else 同时成立？——说一半，程序地址空间一节解答
  - fork 后用 `if(id<0) / else if(id==0) / else` 分流，父子未来执行不同的代码逻辑【板书强调】
  - g_val 实验：子进程把 g_val 从 100 改到 105，父进程始终 100 → **结论：进程具有独立性**【板书强调】
  - 写时拷贝【板书强调】：把父子任何一方的数据进行修改，OS 把被修改的数据在底层拷贝一份，让目标进程修改这个拷贝

### 3-2 进程状态
#### 理论基础（课本+队列模型）
- **进程状态就是 task_struct 内的一个整数**【板书强调】
- 课本状态转换图【板书强调】：创建状态 → 就绪状态 →（被调度）运行状态 →（时间片用完回就绪 / 等待事件转阻塞 / 结束）→ 结束状态；阻塞状态（事件完成→就绪）；挂起分支：就绪挂起状态、阻塞挂起状态（激活/挂起/事件出现相互转换）
- **运行 && 阻塞 && 挂起队列模型**【板书强调】：
  - 运行：**一个 CPU 一个调度队列 runqueue，在调度队列中的进程状态都是 running**（不一定正在 CPU 上跑）；调度算法之一 FIFO
  - 阻塞：**等待某种设备或资源就绪（键盘/显示器/网卡/磁盘/摄像头/话筒……），PCB 挂到对应设备的 wait_queue**；OS 管理硬件同样先描述再组织：`struct device {int id; int vender; int status; void *data; struct device *next;}`，设备里还有 `struct task_struct *wait_queue`
  - 挂起：**内存不足时，进程的代码和数据换出到磁盘 swap 交换分区（唤出），需要时唤入，PCB 仍留内存**；阻塞+换出 = 阻塞挂起
- **进程状态的变化，表现之一就是在不同的队列中流动，本质都是数据结构的增删查改**【板书强调】
- Linux 内核链表实现【板书强调】：`struct list_head {struct list_head *next, *prev;}` 作为成员（links）嵌入 task_struct 内部；通过偏移量换算回结构体首地址：`(struct task_struct*)((char*)links - &((struct task_struct*)0)->links)`（offsetof 思想）；**一个 task_struct 可含多个 next/prev 对，同时挂在多个队列里**；`struct list_head tasks;` 为全局进程链表

#### Linux 内核状态
- 内核源码 `task_state_array[]`【板书强调】：`R (running)` / `S (sleeping)` / `D (disk sleep)` / `T (stopped)` / `t (tracing stop)` / `X (dead)` / `Z (zombie)`
- R 运行：在运行队列中即 running【板书强调】
- S 睡眠：**可中断休眠，浅睡眠**，等待事件完成【板书强调】
- D 磁盘休眠：**不可中断休眠，深度睡眠**，等磁盘 IO 结束，不可被 kill【板书强调】；dd 实验：`dd if=/dev/zero of=~/test.txt bs=4096 count=100000`（写入约 100MB 到磁盘，观察进程瞬时处于 D 状态）
- T 停止：**暂停**；18) SIGCONT 恢复、19) SIGSTOP 暂停【板书强调】；被 debug、断点命中时进程就是 T/t（tracing stop，gdb 追踪中）；`ps axj` 可见 STAT=T
- X 死亡：瞬时状态，任务列表看不到
- **Z 僵尸**【板书强调】：**子进程退出、父进程还在运行但不读取退出信息 → Z 一直存在**；`ps axj` 中显示 `Z+`、命令名变 `[myprocess] <defunct>`
- 为什么要有僵尸【板书强调】：**我们创建子进程的目的是让子进程完成某种事情，结果相关的信息父进程得知道**——僵尸就是为了获取退出信息；退出信息存在 task_struct 里
- 如何模拟验证 Z 状态：子进程先 exit，父进程不回收，`ps axj` 观察
- 僵尸危害推理链【板书强调】：退出状态必须维持 → PCB 必须维护 → 父进程不回收则 PCB 永远占内存 → **内存泄漏**
- 两个补充知识点【板书强调】：①进程退出了内存泄漏问题还在不在？**常驻内存的进程**有内存泄漏才比较麻烦 ②内核结构对象（task_struct）的内存由 **slab** 分配器管理（数据结构对象的缓存）

#### 孤儿进程
- **父子进程关系中，如果父进程先退出，子进程要被 1 号进程（init/systemd，即操作系统）领养，被领养的子进程叫做孤儿进程**【板书强调】
- 为什么要领养【板书强调】：不领养的话子进程进入僵尸之后无人回收
- 实验现象：父进程退出后子进程 PPID 变 1，且变成后台进程（`./cmd &` 形式运行，kill -9 才能结束）【板书强调】

### 3-3 进程优先级
- 三问【板书强调】：是什么——进程得到 CPU 资源的先后顺序（能得到资源、先后的问题）；为什么——目标资源稀缺，需要优先级确认谁先谁后；怎么办——task_struct 里的一个 int 数字
- **优先级 vs 权限**：优先级=先得到还是后得到资源；权限=是否能得到某种资源【板书强调】
- **值越小优先级越高；基于时间片的分时操作系统要考虑公平性，优先级可被变化，但变化幅度不能太大**【板书强调】
- `ps -al` 查看（列：F S UID PID PPID C PRI NI ADDR SZ WCHAN TTY TIME CMD）【板书强调】；UID = user id
- **PRI：进程的优先级，默认 80；NI：进程优先级的修正数据（nice 值），不是优先级本身**【板书强调】
- **进程真实的优先级 = PRI(默认) + NI**【板书强调】；nice 范围 **[-20, 19]** 共 40 级 → **Linux 进程优先级范围 [60, 99]**【板书强调】
- 修改方法【板书强调】：`renice -n 数值 -p PID`（极值实验：`renice -n -100` 被截断到 -20，`renice -n 100` 被截断到 19）；top 里按 r；`nice` 命令；系统函数 `#include <sys/time.h>` `#include <sys/resource.h>`，`int getpriority(int which, int who)` / `int setpriority(int which, int who, int prio)`
- 优先级设立不合理的后果【板书强调】：低优先级进程长时间得不到 CPU 资源 → **进程饥饿**
- 小知识【板书强调】：**系统怎么知道我访问文件的时候是拥有者、所属组还是 other？——Linux 中访问任何资源都是进程在访问，进程就代表用户**（ll / ls -ln 实验，UID 决定身份）
- 四个概念【板书强调】：
  - **竞争性**：系统进程数目众多，CPU 资源只有少量甚至 1 个，进程间具有竞争属性；为了高效完成任务、更合理竞争资源，才有了优先级
  - **独立性**：多进程运行需要独享各种资源，运行期间互不干扰
  - **并行**：多个进程在多个 CPU 下分别同时进行运行
  - **并发**：多个进程在一个 CPU 下采用进程切换的方式，在一段时间之内让多个进程都得以推进

### 3-4 进程切换【板书重点】
- 死循环进程如何运行【板书强调】：一个进程占有 CPU 会把代码跑完吗？**不会——时间片**；死循环进程不会打死系统，不会一直占有 CPU
- CPU 内寄存器清单【板书强调】：pc/EIP、ebp/esp、eax/bx/cx/dx、cs/ds/es/fs/gs、eflags、cr0~cr4
- 结论【板书强调】：①寄存器就是 CPU 内部的临时空间 ②**寄存器 ≠ 寄存器里面的数据**（数据是变化的、多份的，如 `int a=10; a=20; b=a;`）
- 如何切回——当兵故事【板书强调】：学校=CPU、导员=调度器、你=进程、学籍=进程运行的临时数据（CPU 寄存器内容=当前进程的上下文数据）；保留学籍=保存进程上下文、恢复学籍=恢复上下文到 CPU 寄存器、去当兵=进程被从 CPU 剥离下来；这是一次切换
- 具体【板书强调】：**CPU 内的寄存器只有一份，但上下文可以有多份，分别对应不同的进程**（进程A：EIP=100行 eax=10；进程B：EIP=1000行 eax=100）；进程被切下来时必须顺便带走并保存自己的上下文数据，目的：下次回来能恢复，按之前的逻辑继续向后运行
- **进程切换最核心的就是保存和恢复当前进程的硬件上下文数据，即 CPU 内寄存器的内容**【板书强调】
- 上下文保存到哪里？**保存到进程的 task_struct 里面——TSS（任务状态段，struct tss_struct）**【板书强调】；tss_struct 字段：back_link/esp0/ss0/.../cr3/eip/eflags/eax~ebx/esp/ebp/esi/edi/es~gs/ldt 等；task_struct 源码末尾内嵌 `struct tss_struct tss`
- `struct task_struct *current`——指向当前正在运行的进程【板书强调】
- 补充：内核优先级抢占 / 分时操作系统 / 实时操作系统（应用领域不同）【板书强调】

### 3-5 Linux2.6 内核 O(1) 调度队列【板书重点】
- **一个 CPU 一个运行队列 runqueue**【板书强调】；runqueue 结构字段：lock、nr_running、cpu_load（基于 CPU 队列中进程平均数量的负载因子，多 CPU 负载均衡用）、active、expired、arrays[2] 等
- 调度器如何快速挑选一个进程？两步：**1. 挑队列 2. 挑进程**【板书强调】
- 优先级分区【板书强调】：**[0,99] 实时优先级（不考虑）；[100,139] 普通优先级**，对应 nice [-20,19]（换算：PRI = 60 + 40 + nice）
- **queue[140]：`struct task_struct *queue[140]`，数组下标=优先级，相同优先级的进程 FIFO 排队**【板书强调】
- **bitmap[5]：`unsigned int bitmap[5]`，5×32=160 个比特位 ≥140；比特位的位置对应 queue[140] 哪一个 slot，比特位的内容 1/0 表示该队列是否为空**——直接定位最高优先级非空队列，查找 O(1)【板书强调】
- 活动队列与过期队列【板书强调】：`prio_array_t arrays[2]`，每个元素含 {nr_active; bitmap[5]; queue[140]}；`active = &prio_array[0]`（时间片未耗尽的进程）、`expired = &prio_array[1]`（时间片耗尽的进程）
- **active queue 进程越来越少、expired queue 进程越来越多 → `swap(&active, &expired)` 交换两个指针，直接获得一批新的活动进程**【板书强调】
- 总结：找最合适调度进程的时间复杂度为常数，不随进程数增长【板书强调】

## 4. 命令行参数和环境变量

### 4-1 概念介绍
- 环境变量(environment variables)：在操作系统中用来**指定操作系统运行环境的一些参数**；通常具有特殊用途，在系统当中具有**全局特性**【板书强调】
- 引入例【板书强调】：写 C/C++ 代码链接时，从来不知道所链接的动态/静态库在哪里，但照样链接成功——原因就是有相关环境变量帮助编译器进行查找
- bash 用环境变量 → 用户间接地用了【板书强调】

### 4-2 命令行参数
- 实验【板书强调】：`./code a b c d` → `argv[0]: ./code` `argv[1]: a` …；代码 `int main(int argc, char *argv[])` 循环打印
- argv 表结构【板书强调】：`char *argv[]` 字符指针数组，[0] 存程序名、其后存各参数、**表尾 NULL 结尾**；命令行字符串由 **bash 切分**后填入
- **进程拥有一张 argv 表，用来支持实现选项功能；main 的命令行参数是实现程序不同子功能的方法——这就是指令选项的实现原理**【板书强调】（`ls -a -b -c` 实验；`file /usr/bin/ls` 确认 ls 就是个 ELF 可执行程序）

### 4-3 一个例子：PATH
- 推理【板书强调】：①要执行一个程序，必须先找到它 ②系统中存在环境变量帮助系统找到目标二进制文件
- **PATH = 系统中搜索指令的默认搜索路径**【板书强调】；`echo $PATH`：`/usr/local/bin:/usr/bin:/usr/local/sbin:/usr/sbin:/home/whb/.local/bin:/home/whb/bin`（冒号分隔）
- PATH 解释了为什么系统指令不用带路径，而自己编译的程序要 `./`【板书强调】；`export PATH=$PATH:路径` 可添加

### 4-4 环境变量从哪来、bash 两张表
- **bash 内部有两张表：环境变量表（`char **environ`，bash 先拿到）+ 命令行参数表（argv）**【板书强调】
- **环境变量最开始从系统的相关配置文件中来的**【板书强调】：家目录下 `.bash_profile`、`.bashrc`（其内部再 source `/etc/bashrc`）
- **如果 Linux 系统有 10 个用户登录？——存在 10 个 bash，每个 bash 各自维护两张表**【板书强调】
- 认识更多环境变量【板书强调】（`env` 查看全部）：PATH、HOME（=/home/whb，`cd ~` 的原理）、SHELL（=/bin/bash）、USER、LOGNAME、HOSTNAME、TERM、HISTSIZE、SSH_CLIENT、SSH_TTY、SSH_CONNECTION、LD_LIBRARY_PATH、LS_COLORS、MAIL、PWD、LANG、SHLVL 等
- 相关命令【板书强调】：`echo $XXX`（显示某个）、`export`（设置/导出）、`env`（显示全部环境变量）、`unset`（清除）、`set`（本地变量+环境变量都显示）

### 4-5 获取环境变量的方法
- 操作级：export / env / echo $XXX / unset【板书强调】
- 代码级三种方式【板书强调】：
  ① main 第三参数 `int main(int argc, char *argv[], char *env[])`——start 函数根据参数个数选择 `main()` / `main(argc,argv)` / `main(argc,argv,env)` 调用形式
  ② `getenv("NAME")`——最常用，查特定变量
  ③ `extern char **environ;`——libc 全局变量
- 环境表 = 字符指针数组，每项指向 '\0' 结尾的环境字符串，表尾 NULL【板书强调】

### 4-6 环境变量的全局特性
- **环境变量可以被子进程继承**【板书强调】：父进程(bash) → 子进程 → 孙进程，树形继承（验证：`export MYENV=xxx` 后子进程程序里 getenv 能读到）
- 对比概念【板书强调】：**本地变量——不会被子进程继承，只在 bash 内部被使用**（`i=10` 后 `echo $i` 能打印，但子进程读不到）
- **bash 会记录两套变量：1. 环境 2. 本地**【板书强调】
- `export i` 把本地变量转成环境变量；**export 是内建命令 built-in command：不需要创建子进程，让 bash 自己亲自执行（bash 自己调用函数或系统调用完成）**【板书强调】——所以它对 bash 自身的修改才能生效
- 应用思想实验【板书强调】："如果我想写一个程序，只能我执行，其他人一律不让执行"——程序里 `getenv("USER")` 判断身份

## 5. 程序地址空间

### 5-1 布局与验证
- 虚拟地址空间一共会讲 4 次（后续课程逐步深入）【板书强调】
- 编址计算【板书强调】：1 字节编址，32 位机器 2^32 个地址 × 1 字节 = **4GB**；64 位机器 2^64 个地址
- 布局从低到高【板书强调】：正文代码 → 初始化数据 → 未初始化数据 → 堆（向上增长↑）→ 一大段镂空空间 → 共享区 → 栈（向下增长↓）→ 命令行参数/环境变量 → 内核空间 1G（[3,4]G）；用户空间 [0,3]G
- **程序地址空间是内存吗？——不是内存！它是虚拟地址空间，是一个系统的概念，不是语言层的概念**【板书强调】
- 区域验证实验【板书强调】：`./code` 打印 code/init_global/uninit_global/heap(连续 malloc，地址递增)/stack(局部变量，地址递减)/read only string/test_static/argv/env 各项地址，与布局图一一对应

### 5-2 虚拟地址实验（fork+g_val）
- 实验现象【板书强调】：fork 后父子都打印 `&g_val`：**地址一样（都是 0x60104c）**，但子进程把 g_val 从 100 改到 105、父进程始终是 100
- 推理链【板书强调】：**地址一样，如果是物理内存地址，值不同就是 bug → 不是内存地址 → 是虚拟地址！→ C/C++ 指针用到的地址，全部都是虚拟地址！！物理地址用户一概看不到，由 OS 统一管理**
- 三个预备结论【板书强调】：①一个进程，一个虚拟地址空间 ②一个进程，一套页表 ③页表是用来做虚拟地址和物理地址映射的
- 写时拷贝页表图【板书强调】：父 g_val 虚拟地址 0x111111 → 页表映射 → 物理 0x112233(=100)；fork 后子页表同样 0x111111 → 0x112233；**子进程 g_val++ → 写时拷贝：OS 拷贝新物理页 0x223344，修改子进程页表映射** → 父子虚拟地址相同、物理地址不同、值不同
- **进程具有独立性：1. 内核数据结构独立 2. 加载进入内存的代码和数据独立**【板书强调】——fork 三问之③（一个变量为何两个值）至此解答
- **为什么要写时拷贝？1. 减少创建（进程）时间 2. 减少内存浪费**【板书强调】

### 5-3 如何理解虚拟地址空间（两个类比）
- **大富翁类比**【板书强调】：大富翁（OS）有 10 个亿（物理内存），给 4 个私生子（进程）各画一张 10 亿的饼（虚拟地址空间）——饼要不要管理？要！怎么关联？**先描述，再组织！** 让每个进程都认为自己有 4GB 物理内存、认为自己在独占物理内存，实际要用时才兑现
- **虚拟地址空间的本质 = 一个数据结构 `struct mm_struct`**【板书强调】：`{long code_start; long code_end; long init_start, init_end; long unint_start, uninit_end; ...}`
- **38 线/桌子类比**【板书强调】：100cm 桌子画 38 线划分两个区域——什么叫做区域划分？**只需要确认区域的开始和结束即可**；区域用数值机械化表示：`struct Destop {int size; int zs_start; int zs_end; int ls_start; int ls_end;}`，`area = {0, 49, 50, 99}`；调整区域 = 改数值（`area.ls_start-=20; area.zs_end+=20;`）；2^32 个地址用 int 保存
- 内核中的 mm_struct【板书强调】：`unsigned long start_code, end_code, start_data, end_data; unsigned long start_brk, brk, start_stack; unsigned long arg_start, arg_end, env_start, env_end;`（还有 total_vm/locked_vm/stack_vm 等）——全是成对的 start/end
- 每个进程只有一个 mm_struct，task_struct 中 `struct mm_struct *mm` 指向它【板书强调】
- mm_struct 的两个问题【板书强调】：①开辟空间 ②初始化的值从哪里来？——**加载（可执行程序）的时候进行初始化**

### 5-4 VMA 与页表
- 页表【板书强调】：虚拟地址 ↔ 物理地址映射 + **权限列（rw- / r-- / rwx）**；虚拟地址经 MMU + 页表转化为物理地址
- 区域再细分【板书强调】：堆区不止一个起始虚拟地址——**地址空间，再扩展一层！** `struct vm_area_struct {struct mm_struct *vm_mm; unsigned long vm_start; unsigned long vm_end; ... vm_prot; vm_flags; vm_next; vm_prev;}`（VMA），mm_struct 里 `struct vm_area_struct *mmap` 串成链表
- 完整结构图【板书强调】：task_struct{pid; files_struct *files; mm_struct *mm} → mm_struct → pgd(页表) + VMA 链表（每个节点带 vm_read/vm_write/vm_exec 权限）→ 对应 内核空间/栈/文件映射与匿名映射区/堆/BSS 段/数据段/代码段
- VMA 两种组织方式并存【板书强调】：区域少用单链表、区域多用红黑树（减少查找时间 + 减少内存浪费）
- 加载/换页【板书强调】：1. 在虚拟地址空间中申请指定大小的空间 2. 加载程序申请物理空间 3. 页表进行映射；物理地址转化成虚拟地址提供给上层用户使用；缺页中断

### 5-5 为什么要有虚拟地址空间
- 三大收益【板书强调】：
  ①**将地址从无序变有序**（每个进程看到的都是同样布局的 0~4G）
  ②**地址转换过程中对地址和操作进行合法性判定，进而保护物理内存**——什么是野指针；`char *str="helloworld"; *str='H';` 为什么在字符常量区写入就会崩溃？**查找页表的时候权限拦截了！**
  ③**让进程管理和内存管理进行一定程度的解耦合**（物理内存可任意位置加载；malloc 先在地址空间申请、物理内存延迟分配，用户 0 感知）
- 澄清三个问题【板书强调】：①我们可以不加载代码和数据，只有 task_struct、mm_struct、页表 ②创建进程，先有 task_struct/mm_struct 等，还是先加载代码和数据？（先建结构）③如何理解进程挂起？（代码数据换出后，结构还在）
