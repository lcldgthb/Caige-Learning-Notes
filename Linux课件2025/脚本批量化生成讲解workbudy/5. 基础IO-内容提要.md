## 1. 理解"文件"

### 1-1 狭义理解
- 文件在磁盘里；磁盘是永久性存储介质，文件在磁盘上的存储是永久性的
- 磁盘是外设（既是输出设备也是输入设备）
- 对文件的所有操作 = 对外设的输入和输出，简称 IO

### 1-2 广义理解
- Linux 下一切皆文件（键盘、显示器、网卡、磁盘……都是抽象化的过程）

### 1-3 文件操作的归类认知
- 0KB 的空文件也占用磁盘空间
- 文件 = 属性（元数据）+ 内容【板书强调】
- 所有文件操作本质 = 文件内容操作 + 文件属性操作

### 1-4 系统角度【板书强调】
- 对文件的操作本质是**进程对文件的操作**
- 磁盘的管理者是操作系统
- 文件的读写本质不是通过 C/C++ 的库函数来操作的（库函数只是为用户提供方便），而是通过**文件相关的系统调用接口**来实现的
- fopen、fclose 是库函数 → 封装了 OS 的系统调用接口！
- 访问文件，需要先打开文件！打开文件？进程打开的文件！对文件的操作，本质是：进程对文件的操作
- 文件分类：①内存文件（被打开的）②磁盘级文件【板书强调】

## 2. 回顾C文件接口

### 2-1 hello.c打开文件
- `FILE *fp = fopen("myfile", "w")`，失败返回 NULL（打印 fopen error 后仍要 return，否则对 NULL 继续操作崩溃）
- 打开的文件在哪个路径下？——程序当前路径下
- 系统怎么知道当前路径？`ls /proc/[pid] -l` 查看：
  - **cwd**：指向当前进程运行目录的符号链接
  - **exe**：指向启动进程的可执行文件完整路径的符号链接
- 打开文件本质是进程打开，进程知道自己在哪（cwd），即便文件不带路径也知道往哪放

### 2-2 hello.c写文件
- `fwrite(msg, strlen(msg), 1, fp)`：缓冲区首地址、元素大小、个数、流

### 2-3 hello.c读文件
- `ssize_t s = fread(buf, 1, strlen(msg), fp)`：返回值和参数有坑，看 man 手册
- s > 0 时 `buf[s] = 0` 再打印；`feof(fp)` 判读是否到文件结尾
- 稍作修改可实现简单 cat 命令（argc 判断 + fopen(argv[1], "r")）

### 2-4 输出信息到显示器，你有哪些方法
- `fwrite(msg, strlen(msg), 1, stdout)`、`printf(...)`、`fprintf(stdout, ...)`

### 2-5 stdin & stdout & stderr【板书强调】
- C 默认打开三个输入输出流：stdin、stdout、stderr，类型都是 FILE*
- `extern FILE *stdin; extern FILE *stdout; extern FILE *stderr;`（standard I/O streams）
- stdin：标准输入 → 键盘文件；stdout：标准输出 → 显示器文件；stderr：标准错误 → 显示器文件
- 对应 C++ 的 cin / cout / cerr【板书强调】

### 2-6 打开文件的方式
- `r`：只读，流定位到开头
- `r+`：读写，流定位到开头
- `w`：Truncate file to zero length or create → 文件先会被清空【板书强调】，不存在则创建，流定位到开头
- `w+`：读写 + 清空/创建
- `a`：Open for appending（追加写，end of file），不存在则创建，流定位到末尾
- `a+`：读 + 追加写
- 还有 fseek、ftell、rewind 等函数（C 阶段已学，自行复习）

## 3. 系统文件I/O

### 3-1 一种传递标志位的方法
- 一个 int 用比特位传递多组标志：`#define ONE 0001 / TWO 0002 / THREE 0004`（0000 0001 / 0000 0010 / 0000 0100）
- 检测：`flags & ONE`；组合传递：`ONE | TWO`（按位或，互不影响）
- open 的 flags 就是这么实现的

### 3-2 hello.c 写文件（系统接口版）
- `umask(0)`；`int fd = open("myfile", O_WRONLY|O_CREAT, 0644)`
- fd < 0 失败，perror("open")
- `write(fd, msg, len)`：fd、缓冲区首地址、期望写入字节数；返回实际写入字节数
- `close(fd)`

### 3-3 hello.c读文件（系统接口版）
- `int fd = open("myfile", O_RDONLY)`；`ssize_t s = read(fd, buf, strlen(msg))`（类比 write）；s > 0 打印，否则 break

### 3-4 接口介绍【板书强调】
- `#include <sys/types.h> <sys/stat.h> <fcntl.h>`
- `int open(const char *pathname, int flags);`
- `int open(const char *pathname, int flags, mode_t mode);`（mode = 权限位）
- RETURN VALUE：return the new file descriptor, or -1 if an error occurred（errno 被适当设置）
- flags 必选其一：O_RDONLY（只读）/ O_WRONLY（只写）/ O_RDWR（读写）
- 可选组合：O_CREAT（不存在则创建，需 mode 指明权限）、O_APPEND（追加写）、O_TRUNC（存在则清空，对应 w 模式）【板书强调】
- 对比实例【板书强调】：`int fd = open("log.txt", O_CREAT | O_WRONLY | O_TRUNC, 0666)`①（对应 w）vs `int fd = open("log.txt", O_CREAT | O_WRONLY | O_APPEND, 0666)`②（对应 a）
- `ssize_t write(int fd, const void *buf, size_t count)`；文本写入 vs 二进制写入 12345 → 语言层面的概念！
- C 库输出函数家族：puts / fputs(int fputs(const char *s, FILE *stream)) / putchar / int putc(int c, FILE *stream) / putchar(int c) / printf / fprintf / sprintf / snprintf
- FREAD(3)：fread、fwrite — binary stream input/output；`size_t fread(void *ptr, size_t size, size_t nmemb, FILE *stream)`；`size_t fwrite(const void *ptr, size_t size, size_t nmemb, FILE *stream)`
- 目标文件不存在需要创建 → 用三参 open 指定权限；否则用两参 open

### 3-5 open函数返回值
- 系统调用 vs 库函数：fopen/fclose/fread/fwrite 是 C 标准库（libc）的**库函数**；open/close/read/write/lseek 是**系统调用接口**
- 分层：库函数（fopen 等）在上 → 系统调用（open 等）在下 → 硬件
- **f 系列函数都是对系统调用的封装，方便二次开发**【板书强调】

### 3-6 文件描述符fd【板书强调——本节核心，整块画图展开】
- 文件描述符就是从 0 开始的小整数

#### 3-6-1 0 & 1 & 2
- Linux 进程默认 3 个缺省打开的文件描述符：标准输入 0、标准输出 1、标准错误 2
- 0, 1, 2 对应的物理设备一般是：键盘，显示器，显示器
- 在 OS 层面，默认，打开文件描述符 0,1,2【板书强调】
- 可以直接用 fd 读写：`read(0, buf, sizeof(buf))`、`write(1, buf, strlen(buf))`、`write(2, buf, strlen(buf))`
- 实验：连续 open 多个文件输出 fd: 3、4、5、6 → 相邻什么？→ 文件不同！【板书强调】
- 运行 ./myfile 输出 stdin: 0、stdout: 1、stderr: 2、fd: 3 4 5 6

#### fd 与内核结构关系图（源码验证）【板书强调】
- 源码位置：task_struct → sched.h；files_struct → fdtable.h；struct file → fs.h（内核 3.10.0-1160.71.1.el7.x86_64，uname -a 查看）
- 用户层：`int fd = open("log.txt")`；`read(fd, buffer, sizeof(buffer))`；`close(fd)`
- 对文件内容、属性做操作，都必须先把文件加载到内核对应的文件缓冲区里！！【板书强调】
- 磁盘 → 内存的读写；buffer（用户级）
- **struct file 就代表"被打开的文件"**【板书强调】；一个文件可不可以被多次打开？（可以）
- task_struct → `struct files_struct *files` → 文件指针数组 `struct file* fd_array[]`
- 进程 : 打开文件 = 1 : n【板书强调】
- struct file 内容：int ref_cnt（引用计数）、文件缓冲区、属性集合（inode、mode、读写位置、链接属性、缓冲区、操作方法）、struct file *next
- 磁盘上的文件 = 内容 + 属性（log.txt）
- 每个打开文件，在内核中都有对应的 inode 元信息【板书强调】

#### 3-6-2 文件描述符的分配规则【板书强调】
- 直接 open 输出 fd: 3（0,1,2 被占用）
- close(0) 或 close(2) 后再 open：结果是 fd: 0 或 fd: 2
- **规则：在 files_struct 数组中，找到当前没有被使用的最小的一个下标，作为新的文件描述符**【板书强调】

#### 3-6-3 重定向
- close(1) 后 open("myfile", O_WRONLY|O_CREAT, 0666) → open 返回 fd=1
- printf("fd: %d\n", fd) 本该输出到显示器，结果写进了文件 myfile → **输出重定向**
- 常见重定向：`>`（输出）、`>>`（追加）、`<`（输入）
- 原理【板书强调】：数据下标不变，更改文件描述符表里的指针指向！
- 注意 printf 后要 fflush(stdout)（缓冲区原因，见第 5 节），再 close(fd)

#### 3-6-4 使用 dup2 系统调用【板书强调】
- `#include <unistd.h>`；`int dup2(int oldfd, int newfd)`
- RETURN VALUE：On success, return the new descriptor. On error, -1 is returned, and errno is set appropriately
- **dup2() makes newfd be the copy of oldfd, closing newfd first if necessary.**【板书强调】
- 示例：open("./log", O_CREAT|O_RDWR) → close(1) → dup2(fd, 1)；此后 printf 输出进 log
- dup2(fd, 1)：①②下标 1；dup2(fd, 0)：下标 0
- printf 往 stdout 输出，stdout 底层访问文件找的还是 fd:1，但 fd:1 下标内容已变成 myfile 的地址 → 输出全部进文件

#### 3-6-5 在minishell中添加重定向功能
- 全局：redir 类型（NoneRedir 0 / InputRedir 1 / OutputRedir 2 / AppRedir 3）+ filename
- ParseRedir：从命令串尾部找 `<`、`>>`、`>`，截断命令串，filename 取后面部分，TrimSpace 跳过空格
- DoRedir 由**子进程自己做**（程序替换不影响重定向）：
  - 输入：open(filename, O_RDONLY) + dup2(fd, 0)
  - 输出：open(filename, O_CREAT|O_WRONLY|O_TRUNC, 0666) + dup2(fd, 1)
  - 追加：open(filename, O_CREAT|O_WRONLY|O_APPEND, 0666) + dup2(fd, 1)
- 内建命令（shell 自己执行）：cd（chdir）、export（AddEnv）、env、echo（$? / $PATH / 字符串）
- fork 子进程 → DoRedir → execvpe(gargv[0], gargv, genv)；waitpid 回收，WIFEXITED/WEXITSTATUS 更新 lastcode

## 5. 缓冲区

### 5-1 什么是缓冲区
- **缓冲区是内存空间的一部分**【板书强调】
- 根据对应输入/输出设备分为输入缓冲区和输出缓冲区

### 5-2 为什么要引入缓冲区机制
- 提高使用效率！【板书强调】
- 不用缓冲区：每次读写都要执行一次系统调用 → CPU 用户态/内核态切换、上下文切换，损耗 CPU 时间，频繁磁盘访问严重影响效率
- 用缓冲区：一次从文件读大量数据到缓冲区，后续访问不再系统调用，减少磁盘读写次数
- 打印机例子：先把文档输出到打印机缓冲区，打印机自行逐步打印，CPU 处理别的事情
- 缓冲区使低速 IO 设备和高速 CPU 协调工作，解放 CPU

### 5-3 缓冲类型【板书强调】
- 我们口中的缓冲区，究竟是什么？→ **用户级-语言层缓冲区（C 库提供）**【板书强调】
- 库函数 printf/fprintf/fputs/fwrite 自带缓冲区；fd-系统调用（比如 write）没有缓冲区【板书强调】
- stdout→FILE*；文件 OS 快照；只要把数据交给 OS，就相当于交给了硬件了！
- 系统调用是有成本的！（用户态→内核态）
- 三种刷新策略【板书强调】：
  1. **立即刷新 --- 无缓冲 --- 写透模式 WT**
  2. **满了 --- 全缓冲**（普通文件一般采用这种方式！）
  3. **行刷新 --- 行缓冲**（显示器用！写满缓冲区，效率就高；默认行缓冲区大小 1024）
- 补充刷新条件：缓冲区满时 / 执行 flush 语句 / 进程结束
- 数据交给系统，交给硬件——本金全盘拷贝；**计算机数据流动的本质：一切拷贝！！！**【板书强调】
- 实验一【板书强调】：close(1) → open("log.txt", O_CREAT|O_WRONLY|O_APPEND, 0666) → printf("fd:%d\n", fd) + printf("hello bit\n")×3 → write(fd, msg, strlen(msg))（底层调用）→ //首次不 close → //fflush(stdout); ?????
  - 结果：write 的内容立即进了文件，printf 的内容没进（重定向后变全缓冲，没满不刷新，进程退出才刷）→ 解决：fflush(stdout)
- 实验二：close(2) → perror("hello world") → stderr 无缓冲，不用 fflush 直接进文件（hello world: Success）

### 5-4 FILE
- IO 相关函数与系统调用接口对应，库函数封装系统调用 → **访问文件都是通过 fd 访问的**
- **C 库的 FILE 结构体内部，必定封装了 fd**【板书强调】
- FILE 是什么？C 标准库中的一个 struct！里面有 int fd（_fileno）→ 设备不同【板书强调】
- C 语言中一个文件，都有自己的缓冲区【板书强调】
- `/usr/include/stdio.h`：`typedef struct _IO_FILE FILE;`
- `/usr/include/libio.h`：struct _IO_FILE 关键字段【板书强调】：
  - int _flags（_IO_file_flags）
  - 缓冲区相关：_IO_read_ptr / _IO_read_end / _IO_read_base / _IO_write_base / _IO_write_ptr / _IO_write_end / _IO_buf_base / _IO_buf_end / _IO_save_base / _IO_backup_base / _IO_save_end
  - struct _IO_marker *_markers；struct _IO_FILE *_chain
  - **int _fileno;（封装的文件描述符）**
- `FILE *fopen(const char *path, const char *mode)`；`int fflush(FILE *stream)`
- fork + 缓冲区实验【板书强调】：
  - 代码：printf("hello printf\n")；fwrite(msg1, strlen(msg0), 1, stdout)；write(1, msg2, strlen(msg2))；fork()
  - 显示器输出：hello printf / hello fwrite / hello write 各一次（行缓冲，\n 即刷新）
  - `./hello > file` 重定向后：hello write 1 次，hello printf、hello fwrite 各 2 次！
  - 解释【板书强调】：库函数写显示器是行缓冲，重定向到普通文件变全缓冲；缓冲区数据不立即刷新；fork 时父子写时拷贝各有一份缓冲区；进程退出统一刷新 → 两份；write 无缓冲所以只一次
  - **该缓冲区是二次加上的（用户级缓冲区），由 C 标准库提供**，不属于 OS；OS 也有内核级缓冲区（不在本节讨论范围）
  - 运行时看见刷新！文件导入！

### 5-5 简单设计一下libc库（模拟实现简单的 glibc → 文件接口）【板书强调】
- my_stdio.h：
  - `struct IO_FILE { int flag; int fileno; char outbuffer[SIZE]; int cap; int size; }`；typedef → mFILE
  - 刷新方式：FLUSH_NONE 0 / FLUSH_LINE 1 / FLUSH_FULL 2
  - 接口：mFILE *mfopen(const char *filename, const char *mode)；int mfwrite(const void *ptr, int num, mFILE *stream)；void mfflush(mFILE *stream)；void mfclose(mFILE *stream)
- my_stdio.c：
  - mfopen：按 mode（r/w/a）调 open（w 用 O_CREAT|O_WRONLY|O_TRUNC，a 用 O_CREAT|O_WRONLY|O_APPEND，0666）；malloc mFILE；fileno=fd、flag=FLUSH_LINE、size=0、cap=SIZE
  - mfflush：size > 0 时 write(fileno, outbuffer, size) 写到内核文件的文件缓冲区中！fsync(fileno) 刷新到外设；size=0
  - mfwrite：memcpy 拷入 outbuffer，size += num；行缓冲检测：flag==FLUSH_LINE && size>0 && outbuffer[size-1]=='\n' → mfflush
  - mfclose：size > 0 先 mfflush，再 close(fileno)
- main.c：mfopen("./log.txt", "a") → 循环 snprintf + mfwrite + mfflush + sleep(1) → mfclose
- 观察：write 直接写内核 → 每秒一条落盘；验证用户级缓冲区行为
