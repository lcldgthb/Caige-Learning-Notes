# 3. 进程概念

## 1. 冯诺依曼体系结构

- **组成**：输入单元、CPU（运算器 + 控制器）、存储器、输出单元；存储器指**内存**。
- **数据流原则**：CPU 在数据层面只能与内存交互；外设也只能读写内存，设备之间的数据传递必须经过内存。
  ```text
  输入设备 → 内存 → CPU → 内存 → 输出设备
  外设 A → 内存 → 外设 B
  ```
- **典型流程**：键盘输入 → 内存；CPU 从内存取数据并处理 → 结果写回内存；显示器从内存读取并显示。
- **设备速度差异**：CPU 寄存器、缓存、内存、磁盘、网络设备速度依次降低；内存承担不同速度设备之间的数据缓冲。
- **存储层次**：寄存器 → L1/L2/L3 Cache（通常 SRAM）→ 内存（DRAM）→ 磁盘 → 网盘；越靠上速度越快、容量越小、单位成本越高。
- **网络聊天/文件传输**：
  - 文字：发送端键盘 → 发送端内存 → 网卡 → 网络 → 接收端网卡 → 接收端内存 → 显示器。
  - 文件：发送端磁盘 → 内存 → 网卡 → 网络 → 接收端网卡 → 内存 → 磁盘。
  - 网卡既可作为输入设备，也可作为输出设备。

## 2. 操作系统(Operator System)

- **定义与组成**：OS 是管理计算机软硬件资源、为用户程序提供执行环境的程序集合。
  - 内核：进程管理、内存管理、文件管理、驱动管理。
  - 其他程序：函数库、Shell、系统工具等。
  - 狭义 OS 通常指内核；广义 OS 包括内核及配套程序。
- **设计目的**：
  - 对下：与硬件交互，统一管理 CPU、内存、文件、设备等资源。
  - 对上：为用户程序提供统一、方便、安全的运行环境。
- **管理方法**：**先描述，再组织**。
  - 用 `struct` 等结构体描述对象属性。
  - 用链表、队列、红黑树等数据结构组织对象。
- **系统调用与库函数**：

| 对比项 | 库函数 | 系统调用 |
|---|---|---|
| 所在层次 | 用户态函数库 | 内核提供的接口 |
| 作用 | 封装并简化常用功能 | 请求内核执行受保护的服务 |
| 是否进入内核 | 不一定 | 会进入内核 |
| 例子 | `printf`、`getenv` | `fork`、`getpid`、`getppid` |

- **访问硬件的层次**：用户程序 → 库函数/Shell → 系统调用 → 内核 → 驱动 → 硬件。
- `printf` 是库函数，通常通过标准输出及底层系统调用把数据交给终端或文件；库函数不等同于系统调用。

## 3. 进程

- **进程定义**：
  - 课本：程序的一次执行实例。
  - 内核：分配 CPU、内存、文件、I/O 等资源的实体。
  - Linux：`进程 = task_struct（PCB）+ 程序代码和数据`。
- **PCB / task_struct**：
  - PCB（Process Control Block）是进程属性集合；Linux 中对应 `task_struct`。
  - `task_struct` 位于内核内存中，描述 PID、状态、优先级、程序计数器、内存指针、上下文寄存器、I/O 状态、记账信息等。
  - 所有进程以 `task_struct` 双向链表及调度队列形式组织。
- **查看进程**：
  - `/proc/PID/`：查看指定进程的内核信息，如 `/proc/1/`。
  - `ps aux`：`a` 显示所有用户进程；`u` 用户格式；`x` 包含无控制终端的进程。
  - `ps axj`：`a` 所有用户；`x` 无终端进程；`j` 作业信息，如 PID、PPID、进程组 ID、会话 ID。
  - `top`：动态查看进程和资源使用情况。
  - `kill -9 PID`：发送 9 号信号，强制结束指定进程；`Ctrl+C`：向当前终端前台进程发送中断信号。
- **进程标识**：
  - `getpid()`：获取当前进程 PID。
  - `getppid()`：获取父进程 PPID。
  - `pid_t`：表示进程 ID 的整数类型。
  - `man 2 getpid`、`man 2 getppid`：查看系统调用手册。
- **创建进程 `fork`**：
  - 原型：`pid_t fork(void)`。
  - 查看：`man 2 fork` 或 `man fork`。
  - 返回值：

| 情况 | 父进程返回值 | 子进程返回值 |
|---|---:|---:|
| 成功 | 子进程 PID（大于 0） | `0` |
| 失败 | `-1` | 不产生子进程 |

  ```c
  pid_t ret = fork();
  if (ret < 0) { perror("fork"); return 1; }
  else if (ret == 0) { /* child */ }
  else { /* parent，ret 为子进程 PID */ }
  ```
  - `fork` 后父子进程都从调用点之后继续执行；“返回两次”是父、子两个执行流各得到一次返回值。
  - 父进程可能创建多个子进程，因此父进程需要获得子进程 PID；子进程只需通过返回值 `0` 判断自身身份。
  - **写时拷贝（COW）**：父子进程初始共享代码和物理数据页；任一方写入时复制数据页，修改方获得私有副本。父子代码共享，数据修改后独立。
- **进程状态**：

| 状态 | 含义 |
|---|---|
| `R` | running；正在运行或位于运行队列，不代表此刻一定占用 CPU |
| `S` | sleeping；可中断睡眠，等待事件，可被信号唤醒 |
| `D` | disk sleep；不可中断睡眠，通常等待 I/O 完成，普通信号甚至 `kill -9` 不能立即终止 |
| `T` | stopped；停止，可由 `SIGSTOP` 产生，用 `SIGCONT` 恢复 |
| `t` | tracing stop；被调试器追踪时暂停 |
| `X` | dead；死亡内部状态，通常无法在任务列表中观察 |
| `Z` | zombie；子进程已退出，父进程尚未读取退出状态 |

  - `kill -STOP PID`：暂停进程；`kill -CONT PID`：恢复进程。
  - `dd if=/dev/zero of=bigfile bs=1M count=1024`：可制造大量磁盘 I/O；`if` 输入文件，`of` 输出文件，`bs` 块大小，`count` 块数。
- **僵尸进程**：
  - 子进程退出后，退出状态需保留给父进程读取；父进程未调用 `wait`/`waitpid` 回收时，子进程进入 `Z`。
  - 僵尸进程不能继续运行，但其 `task_struct`、退出状态和进程表项仍被保留；大量僵尸进程会造成内核资源泄漏。
  - 回收接口：`pid_t wait(int *status)`；`pid_t waitpid(pid, &status, options)`。
  - 状态处理常用：`WIFEXITED(status)` 判断正常退出；`WEXITSTATUS(status)` 获取正常退出码；`WIFSIGNALED(status)` 判断是否被信号终止；信号终止常可表示为 `128 + signal`。
  - 查看：`ps axj | grep Z`。
- **孤儿进程**：
  - 父进程先退出、子进程仍运行时，子进程成为孤儿进程。
  - 被 PID 1 的 `init/systemd` 领养；子进程退出后由 PID 1 负责回收。

| 对比项 | 僵尸进程 | 孤儿进程 |
|---|---|---|
| 父进程 | 仍在运行但未回收 | 已退出 |
| 子进程 | 已退出 | 仍在运行 |
| 后续处理 | 父进程读取退出状态后回收 | 由 `init/systemd` 领养并回收 |
- **优先级**：
  - `ps -l` 可查看 `UID`、`PID`、`PPID`、`PRI`、`NI`。
  - `PRI`：实际优先级，值越小越优先。
  - `NI`/`nice`：优先级修正值，不等同于优先级。
  - 关系：`PRI(new) = PRI(old) + nice`。
  - 普通进程 `nice` 范围为 `-20`～`19`，共 40 个等级；`nice` 越小，`PRI` 越小，优先级越高。
  - 调整方式：`top` 中按 `r` → 输入 PID → 输入 nice；`nice -n 10 ./program` 启动时设置；`renice 10 -p 1234` 修改已有进程。
  - 函数原型：`int getpriority(int which, int who)`；`int setpriority(int which, int who, int prio)`。
- **竞争、独立、并行、并发**：

| 概念 | 含义 |
|---|---|
| 竞争性 | 多进程争夺有限 CPU 或其他资源 |
| 独立性 | 进程拥有独立资源和地址空间，运行互不干扰 |
| 并行 | 多个 CPU 上多个进程同一时刻执行 |
| 并发 | 一个 CPU 通过切换使多个进程在一段时间内交替推进 |
- **进程切换**：
  - 分时系统给进程分配时间片；时间片耗尽后，进程被剥离 CPU。
  - 上下文（context）是进程运行所需的 CPU 寄存器状态，包括程序计数器、通用寄存器、栈指针、状态寄存器等。
  - 上下文切换：保存当前进程寄存器内容，恢复下一个进程保存的寄存器内容；进程可从上次暂停位置继续执行。
  - CPU 寄存器只有一套，各进程的上下文保存在各自的 `task_struct`/内核栈中。
- **Linux 2.6 O(1) 调度**：
  - 每个 CPU 一个 `runqueue`；多 CPU 需负载均衡。
  - 实时优先级：`0~99`；普通优先级：`100~139`。
  - `active`：时间片未耗尽的进程；`expired`：时间片耗尽的进程。
  - `queue[140]`：下标对应优先级；同一优先级队列内按 FIFO 调度。
  - `bitmap[5]`：`5×32=160` 个比特位，标记 140 个优先级队列是否为空，快速找到最高优先级的非空队列。
  - `active` 中进程时间片耗尽后进入 `expired`；`active` 为空时直接交换 `active`、`expired` 指针，不逐个搬运进程。
  - **核心**：位图定位非空队列 + 优先级队列取队首 + 双队列指针交换，使调度查找时间复杂度为 `O(1)`，不随进程数量线性增长。

## 4. 命令行参数和环境变量

- **命令行参数**：
  - `int main(int argc, char *argv[])`。
  - `argc`：参数总数；`argv`：参数字符串数组；`argv[0]` 通常为程序名，`argv[1]` 起为用户输入参数。
  - 例：`ls -a -l` 中，`argv[0]="ls"`、`argv[1]="-a"`、`argv[2]="-l"`。
- **环境变量**：
  - 形式为 `NAME=value`，描述程序运行环境，通常具有全局继承性。
  - 父进程导出后，子进程可继承；子进程修改不会反向影响父进程。
  - 常见变量：`PATH` 命令搜索路径；`HOME` 用户主目录；`SHELL` 当前 Shell，通常为 `/bin/bash`。
- **Shell 命令**：
  - `echo $NAME`：显示变量值。
  - `export NAME=value`：设置并导出环境变量。
  - `env`：显示环境变量。
  - `unset NAME`：清除变量。
  - `set`：显示 Shell 本地变量和环境变量，通常比 `env` 多。
  - `export PATH=$PATH:$HOME/bin`：在原 `PATH` 基础上追加目录，不能直接覆盖原 `PATH`。
  - `~` 通常表示 `$HOME`；配置文件常见为 `~/.bash_profile`、`~/.bashrc`。
- **PATH**：
  - Shell 按 `PATH` 中的目录顺序查找可执行文件；因此 `/usr/bin/ls` 可直接写成 `ls`。
  - 当前目录通常不默认在 `PATH` 中，因此本地程序需用 `./hello`；加入目录后可直接执行。
  - 课件示例：`export PATH=$PATH:hello`（严格来说应追加程序所在目录，而非程序文件本身）。
- **环境表**：
  - 每个程序接收一张环境表，本质是 `char *` 指针数组；每个指针指向以 `'\0'` 结尾的 `NAME=value` 字符串，最后以空指针结束。
  - 方式一：`int main(int argc, char *argv[], char *env[])`，遍历 `env[i]`。
  - 方式二：`extern char **environ`；libc 中的全局变量 `environ` 指向环境表，不在头文件中，使用时需 `extern` 声明。
- **环境变量函数**：
  - 原型：`char *getenv(const char *name)`；成功返回变量值指针，不存在返回 `NULL`。
  - 示例：`getenv("PATH")`。
  - `putenv`：设置/修改环境变量；常与 `getenv` 一起访问特定环境变量。
- **本地变量与环境变量**：

| 操作 | 当前 Shell 可见 | 子进程可继承 |
|---|---:|---:|
| `MYENV=hello` | 是 | 否 |
| `export MYENV=hello` | 是 | 是 |

  - `export` 是 Shell 内建命令，因为必须直接修改当前 Shell 的环境表；普通子进程修改自身环境不能反向改变父 Shell。
  - 仅依赖 `getenv("USER")` 做安全认证不可靠，用户可修改环境变量；真正权限控制依赖 OS 身份和文件权限。

## 5. 程序地址空间

- **研究条件**：课件以 Linux kernel 2.6.32、32 位平台为例。
- **典型布局（低地址 → 高地址）**：
  ```text
  代码段 → .rodata 只读数据 → .data 已初始化数据
  → .bss 未初始化数据 → 堆 → 共享库/内存映射区
  → 栈 → 命令行参数与环境变量 → 内核空间
  ```
  - 代码段：函数机器指令。
  - `.rodata`：字符串常量等只读数据。
  - `.data`：有初始值的全局/静态变量。
  - `.bss`：无显式初始值的全局/静态变量。
  - 堆：`malloc`、`new` 动态空间，通常向高地址增长。
  - 栈：函数参数、局部变量，通常向低地址增长。
  - 实际布局受平台、编译器和地址随机化影响。
- **32 位地址空间**：`2^32 = 4GB`，典型划分为用户空间 3GB、内核空间 1GB；这是虚拟地址空间，不是物理内存大小。
- **虚拟地址**：
  - C/C++ 中看到的函数、全局变量、堆、栈地址均为虚拟地址；用户程序看不到并不能直接操作物理地址。
  - 页表负责虚拟地址到物理地址的映射，并进行访问权限检查。
  - 不同进程可拥有相同的虚拟地址数值，但经各自页表映射到不同物理页。
- **`fork` 与地址空间**：
  - 父子进程打印的变量地址可能相同、变量内容却不同；说明地址是虚拟地址，不是物理地址。
  - `fork` 后父子页表初始可指向同一物理页；一方写入时触发写时拷贝，建立新的物理页映射。
  - 因此父子进程既能看到相同的虚拟地址，又能保持数据独立。
- **`mm_struct`**：
  - `mm_struct` 是描述进程用户虚拟地址空间的内核结构体；普通进程的 `task_struct.mm` 指向它。
  - 内核线程通常 `mm == NULL`，通过 `active_mm` 使用已有地址空间中的内核映射。
  - 典型字段：
    - `mmap`：VMA 单链表；
    - `mm_rb`：VMA 红黑树；
    - `task_size`：虚拟地址空间大小；
    - `start_code/end_code`、`start_data/end_data`：代码和数据边界；
    - `start_brk/brk`：堆边界；
    - `start_stack`：栈起始位置；
    - `arg_start/arg_end`、`env_start/env_end`：参数和环境区域。
- **VMA（`vm_area_struct`）**：
  - 表示一段连续的虚拟内存区域，记录 `vm_start`、`vm_end`、权限标志、所属 `mm_struct`、映射文件等。
  - VMA 较少时由 `mmap` 指向的单链表组织；较多时由 `mm_rb` 指向的红黑树管理。
  - 进程通常具有代码、数据、堆、动态库、栈等多个 VMA。
- **虚拟地址空间的作用**：
  - **安全**：通过页表和权限检查隔离进程，防止任意访问其他进程或内核内存。
  - **地址稳定**：进程使用统一的虚拟布局，不必知道实际装载到哪段物理内存。
  - **提高换入换出效率**：物理内存按页管理，可按需换出，不必整体搬运进程。
  - **进程与内存管理解耦**：`malloc`/`new` 首先申请虚拟地址；真正访问时才可能触发缺页，由 OS 延迟分配物理页并建立页表映射。
  - **结论**：虚拟地址空间是 OS 为每个进程建立的地址地图和管理结构，不等于预先分配的一整块物理内存。
