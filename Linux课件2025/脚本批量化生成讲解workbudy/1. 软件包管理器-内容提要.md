> 【板书强调】= 老师板书中出现的内容，即课堂重点

## 1-1 什么是软件包

- 源码安装的痛点：下载源代码 → 自己编译，太麻烦 → 于是有人把常用软件提前编译好，做成软件包放在服务器上
- 软件包 ≈ Windows 上的安装程序；包管理器 ≈ 手机上的应用商店【板书强调】
- 包管理器的核心价值：自动解决依赖问题【板书强调：依赖 → 缺失 → 版本兼容性，知识点！】
- 安装的本质 = 网络下载 + 拷贝【板书强调】；必须使用 root 权限【板书强调】
- 装到系统里只需装一次，所有用户都能用【板书强调】
- yum（Yellowdog Updater, Modified）：Fedora/RedHat/CentOS；apt：Ubuntu

## 1-2 Linux软件生态

- 评估一款操作系统好坏看什么？内核版本、社区、文档、人群、问题……即"生态"【板书强调】；配套软件算不算生态的一环？【板书强调】
- 软件从哪来：开发者发布源码 ⇄ 社区编译打包 → 放到官方源服务器（centos.org / ubuntu.org）
- 开源的本质是一种商业模式【板书强调】；云服务器、钱与生态的关系【板书提及】
- 机器怎么知道下载链接？yum/apt 内置了下载链接；更改下载链接 = 切换镜像源【板书强调】
- 国内镜像源：阿里云、清华 TUNA、中科大 USTC 等
- 软件包依赖问题由包管理器自动处理

## 1-3 yum具体操作

- 三板斧【板书强调】：
  - 查：`yum list | grep 包名`（包太多，必须配合 grep 筛选）
  - 装：`sudo yum install [-y] 包名`
  - 卸：`sudo yum remove [-y] 包名`
- Ubuntu 对应：`apt search` / `apt show` / `sudo apt install` / `sudo apt remove`
- 板书补充示例：`sudo yum -y install man-pages`（课堂演示）
- 包名解读：主版本号.次版本号.源程序发行号-软件包发行号.主机平台.cpu架构；x86_64=64 位、i686=32 位；el7=CentOS7/RedHat7；最后一列 base=软件源名称（类似"小米应用商店"）
- 注意事项：安装需 sudo/root；yum/apt 同一时刻只能装一个，并行安装会报错；报错自行搜索
- "我不知道自己会安装哪些软件？"——正常，由需求驱动【板书强调】
- 大前提：网络必须畅通，`ping www.baidu.com` 验证

## 1-4 安装源

- CentOS 安装源路径：`/etc/yum.repos.d/`【板书强调：yum 源配置文件】
  - `CentOS-Base.repo` = 标准源（base → 稳定软件）【板书强调】
  - `epel.repo` = 扩展源（epel → 扩展软件源）【板书强调】
  - 安装扩展源：`sudo yum install -y epel-release`
- Ubuntu：`/etc/apt/sources.list`（标准源）+ `/etc/apt/sources.list.d/`（扩展源）
- 云服务器软件源已是国内镜像，无需换源
