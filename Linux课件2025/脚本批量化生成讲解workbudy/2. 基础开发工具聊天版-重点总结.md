## 1. 软件包管理器 yum/apt

### 核心概念

- **软件包**：预编译好、可直接安装的程序成品（对应 Windows 安装包）。
- **包管理器**：负责搜索/下载/安装/卸载软件包的工具，≈ 手机应用商店。**【重点】**
- **依赖**：软件运行还需要其他软件陪着；包管理器的核心价值 = 自动解决依赖（缺失 + 版本兼容）。
- 安装本质 = 网络下载 + 拷贝到系统目录 → 需要 `sudo`（root 权限），装一次全系统可用。
- **软件生态**：评估 OS 好坏不只看系统本身，还看内核/社区/文档/用户群体/配套软件。**【重点】**
- 软件链条：开发者发源码 → 社区编译打包 → 官方源服务器 → yum/apt 下载安装。
- **镜像源**：保存同样软件包的"复制站点"；改内置下载链接 = 换源（国内：阿里云/清华/中科大）。
- **开源本质是一种商业模式**：代码开放，靠服务/支持/定制/平台盈利。**【易忘】**

### yum 三板斧【重点】

```bash
yum list | grep 包名          # 查：列出并筛选软件包（| 是管道，把前面输出交给后面处理）
sudo yum install [-y] 包名    # 装：下载安装并自动处理依赖，-y 自动确认
sudo yum remove [-y] 包名     # 卸：卸载软件包
```

**【易忘】** 注意事项：

- 安装前先 `ping www.baidu.com` 验证网络。
- 同一时刻只能进行一个 yum/apt 操作，否则报"被占用"。
- 查不到包：包名写错 / 源未配置 / 网络问题。

### yum 与 apt 对照【易混】

| 目的 | CentOS `yum` | Ubuntu `apt` |
|---|---|---|
| 搜索 | `yum list \| grep 包名` | `apt search 包名` |
| 查看信息 | 看查询结果 | `apt show 包名` |
| 安装 | `sudo yum install 包名` | `sudo apt install 包名` |
| 卸载 | `sudo yum remove 包名` | `sudo apt remove 包名` |

### 安装源与包名解读

- CentOS 源配置目录：`/etc/yum.repos.d/`。**【易混】** `CentOS-Base.repo` = 标准源（稳定）；`epel.repo` = 扩展源（求全）。
- 装扩展源：`sudo yum install -y epel-release`。
- 包名 `xxx.x86_64  1.0-3.el7  base`：`x86_64` = 64 位架构；`el7` = 面向 CentOS 7；`base` = 提供它的软件源名。

## 2. 编辑器 Vim

### 核心：多模式【重点】

- vim 只是**编辑器**（写代码），不管编译（gcc）和调试（gdb）；IDE = 三者集成。
- vim 是 vi 升级版，兼容 vi 全部指令；共 12 种模式，掌握 3 种即可。

| 模式 | 用途 | 进入方式 |
|---|---|---|
| 正常/命令模式（默认） | 移动、删除、复制 | `Esc` 随时返回 |
| 插入模式 | 输入文字 | `i` 光标前 / `a` 光标后 / `o` 下方新行 |
| 末行模式 | 保存、退出、查找 | 正常模式按 `:` |

**【易忘】** 进入 vim 默认是正常模式，直接打字不会输入，是在执行命令。

### 正常模式命令集（`#` = 数字）

| 类别 | 命令 |
|---|---|
| 移动 | `h/j/k/l` 左下上右；`G` 文末；`gg` 文首；`#G` 跳第 # 行；`$` 行尾；`^` 行首；`w/e/b` 按词跳；`ctrl+f/b` 整页；`ctrl+d/u` 半页 |
| 删除 | `x` 删字符；`#x` 删 n 个；`dd` 删行；`#dd` 删 n 行 |
| 复制粘贴 | `yy` 复制行；`#yy` 复制 n 行；`yw` 复制词；`p` 粘贴 |
| 替换撤销 | `r` 替换 1 字符；`R` 连续替换；`cw` 删词并进入插入；`u` 撤销；`ctrl+r` 恢复 |

**【易混】** `u` = 撤销（后退）；`ctrl+r` = 恢复（前进）。
**【易忘】** 复制以 `y` 开头，必须配 `p` 才能看到结果。

### 末行模式命令集

| 命令 | 功能 |
|---|---|
| `:w` / `:q` / `:wq` / `:q!` | 保存 / 退出 / 保存并退出 / 强制不存退出 |
| `:set nu` | 显示行号 |
| `:#` | 跳第 # 行 |
| `/关键字` + `n` | 向后查找 + 下一个 |
| `?关键字` | 向前查找 |

### 批量注释【重点】

1. `ctrl+v` 块选择（按列选）→ 2. 选中多行 → 3. `shift+i` 输入 `//` → 4. `Esc` 应用到所有行。
- 去注释：`ctrl+v` 选中 `//` → 按 `d`。

### 配置文件

- `/etc/vimrc`（全用户）vs `~/.vimrc`（当前用户）。**【易混】**
- 常用三行：`syntax on`（高亮）、`set nu`（行号）、`set shiftwidth=4`（缩进 4）。
- 自带教程：`vimtutor`。

## 3. 编译器 gcc/g++

### 编译四阶段【重点】

| 阶段 | 工作 | 产物 | 选项 | 记忆 |
|---|---|---|---|---|
| 预处理 | 宏替换、删注释、条件编译、展开头文件 | `.i` | `-E` | 只改文本 |
| 编译 | 翻译成汇编代码 | `.s` | `-S` | 还是文字 |
| 汇编 | 翻译成机器码 | `.o` 目标文件 | `-c` | 不链接 |
| 链接 | 合并 .o + 库代码 | 可执行程序 | 无（默认） | 补 printf 等 |

```bash
gcc hello.c -o hello   # 一步完成全部四阶段
./hello                # 运行（Linux 不自动搜索当前目录，必须写 ./）
```

**【易忘】** 分阶段验证：`gcc -E/-S/-c` 逐步生成 `.i → .s → .o`，最后 `gcc hello.o -o hello`。

### 常用选项

| 选项 | 功能 |
|---|---|
| `-o` | 指定输出文件名 |
| `-g` | 加调试信息（gdb 调试必需）**【重点】** |
| `-static` | 静态链接 |
| `-shared` | 生成动态库 |
| `-O0~-O3` | 优化级别（O0 不优化便于调试） |
| `-w` / `-Wall` | 关警告 / 开常用警告（推荐 -Wall） |
| `-DM` / `-DM=100` | 命令行定义宏，等价 `#define M`（用于条件编译、功能裁剪）**【易忘】** |

### 动态链接 vs 静态链接【易混】【重点】

| 对比项 | 动态链接 | 静态链接 |
|---|---|---|
| 库代码位置 | 运行时从 `.so` 加载 | 生成时复制进程序 |
| 程序体积 | 小 | 大 |
| 外部依赖 | 依赖，库缺失就挂（网吧关门） | 不依赖（电脑买回家） |
| 多程序共享 | 共享一份，省内存磁盘 | 各自一份副本 |
| 库更新 | 换库即生效 | 需重新链接 |
| gcc 默认 | **是** | 加 `-static` |

- 库后缀：Linux 动态 `.so` / 静态 `.a`；Windows 对应 `.dll` / `.lib`。**【易忘】**
- 本质：动态链接 = 多程序共享内存中同一份公共代码。

### 验证与静态链接准备

```bash
file hello                        # 看 dynamically linked / statically linked
ldd hello                         # 列出依赖的 .so（静态程序显示 not a dynamic executable）
sudo yum install -y glibc-static libstdc++-static   # 云服务器静态链接前必须先装静态库
```

报错 `cannot find -lc` = 找不到 C 标准库的静态版本 → 装 `glibc-static`。

## 4. 自动化构建 make/Makefile

### 核心概念【重点】

- `make` 是**命令**（执行者），`Makefile` 是**文件**（规则说明书）。
- 规则两要素：**依赖关系**（先找谁）+ **依赖方法**（找到后做什么）。

### 规则格式与使用

```makefile
myproc:myproc.c              # 目标:依赖（顶格写）
	gcc -o myproc myproc.c   # 命令前必须是一个真正的 Tab，不能用空格【易错】

.PHONY:clean                 # 声明伪目标
clean:                       # 无依赖
	rm -f myproc
```

- `make` = 执行**第一个**目标；`make clean` = 指定执行 clean（clean 不会自动跑）。
- `.PHONY` 作用：防止目录里恰好有同名文件 `clean` 导致 make 误判"已完成"而不执行。**【重点】**

### 不重复编译原理【重点】【易忘】

- make 比较目标与依赖的 **Modify 时间**（内容修改时间）。
- 目标不存在 → 执行；依赖比目标新 → 执行；否则不执行。
- 文件三时间【易混】：`Modify` 内容修改 / `Change` 属性或内容变化 / `Access` 访问。
- 推导链像栈：先沿依赖向下找到最底层源文件，再从底向上逐层生成（入栈查找、出栈生成）。
- make 只管"是否执行命令"，不管命令本身对错（gcc 没装、代码有错它都不管）。

### 变量与自动变量

```makefile
BIN=proc.exe                 # 定义变量，使用时 $(BIN)
SRC=$(wildcard *.c)          # 找出当前目录所有 .c
OBJ=$(SRC:.c=.o)             # 后缀替换：a.c b.c → a.o b.o
```

**【易混】** 三个自动变量（只能用在规则的命令里）：

| 变量 | 含义 |
|---|---|
| `$@` | 目标文件 |
| `$^` | 全部依赖 |
| `$<` | 第一个依赖 |

- 模式匹配：`%.o:%.c` = 任意 .o 依赖同名 .c。
- 命令前加 `@` = 执行但不回显该命令。**【易忘】**

## 5. 第一个系统程序：进度条

### 回车 vs 换行【易混】【重点】

| 写法 | 名称 | 动作 |
|---|---|---|
| `\r` | 回车 | 回到**当前行行首**（不换行） |
| `\n` | 换行 | 移到**下一行**（不回行首） |

键盘回车键 ≈ `\r\n` 两个动作合一（老式打字机：打字头移动 + 纸张移动）。

### 行缓冲区【重点】

- printf 的文字先进**缓冲区**（中转暂存区），不一定立刻显示。
- **行缓冲**：遇到 `\n` 才送出；缓冲区满、程序结束也会触发刷新。
- 手动刷新：`fflush(stdout);` —— 只负责送出，**不换行**。
- 三个标准流【易忘】：`stdin` 键盘输入 / `stdout` 屏幕输出 / `stderr` 错误输出；终端是字符设备。

### 动态显示核心组合【重点】

```c
printf("%-2d\r", i);   # %-2d：宽度2左对齐（防止 10→9 残留字符）；\r：回行首覆盖
fflush(stdout);        # 立即刷新，否则留在缓冲区看不到变化
```

### 进度条实现要点

- 结构：`[####    ][53%][/]` = 已完成 + 百分比 + 旋转光标 `|/-\`（C 字符串里反斜杠写 `\\`）。
- v1：固定 101 格数组（100 格 + `\0`），每轮填一个 `#`，`\r` 重绘。
- v2：`percent = current * 100 / total`，`filled = current * bar_width / total`，真实下载每完成一块调一次刷新。
- `%3d` 固定百分比宽度，防抖动；`%%` 输出字面量 `%`。

## 6. 版本控制器 Git

### 核心概念

- 版本控制器两大价值：**数据安全**（改错可找回）+ **协作开发**（记录谁改了什么）。**【重点】**
- **仓库** = 项目文件 + 完整修改记录；本地仓库（自己电脑）vs 远端仓库（云端，共享备份）。
- Git 是**分布式**：每个本地仓库都有完整历史，断网也能本地提交。
- GitHub/Gitee 是基于 Git 的平台，≠ Git 本身。**【易混】**
- 首次使用配身份：`git config --global user.name "名"` + `user.email "邮箱"`。

### 三板斧【重点】

```bash
git add main.cpp             # ① 修改 → 暂存区（git add . 暂存全部，慎用）
git commit -m "修复登录错误"  # ② 暂存区 → 本地仓库（-m 写清做了什么；只提交变化部分）
git push                     # ③ 本地仓库 → 远端仓库
```

流程记忆：工作目录 →(add)→ 暂存区 →(commit)→ 本地仓库 →(push)→ 远端仓库。
**【易忘】** push 只能传 commit 过的内容；只 add 没 commit 的内容传不上去。

### 辅助命令与 .gitignore

- `git status`（add/commit 前查状态）、`git log`（看提交历史）、`git pull`（拉远端并合并）。
- **push 被拒绝（rejected）**= 远端比本地新 → 先 `git pull` 同步，再 `git push`；同一位置两边都改 = 冲突，手动改完后重新 add/commit/push。**【重点】**
- `.gitignore`：列出要忽略的文件/后缀/目录（`*.o`、`build/`）；只管理源文件，可执行文件/临时文件不进仓库。
- **【易忘】** `.gitignore` 本身应提交；已被管理过的文件再加入 .gitignore 不会从历史消失。

## 7. 调试器 gdb/cgdb

### 预备：必须先 -g【重点】

- debug（测试用，带调试信息）vs release（上线用，无调试信息）。
- **gcc/g++ 默认编译 release，无法源码级调试** → 必须 `gcc -g mycmd.c -o mycmd`。
- 验证：`file mycmd` 看 `with debug_info`；或 `readelf -S mycmd | grep -i debug` 看 `.debug_info` 段。

### 常用命令速查

| 命令 | 功能 |
|---|---|
| `gdb 程序名` / `quit` 或 `ctrl+d` | 进入 / 退出 |
| `l`（list） / `r`（run） | 看源码 / 运行到断点或结束 |
| `b 行号` / `b 函数名` / `info b` | 设断点 / 看断点 |
| `n` / `s` / `finish` | 逐过程 / 逐语句 / 执行到函数返回 |
| `p 变量` / `set var 变量=值` | 打印 / 现场改值（不改源码） |
| `c` / `until 行号` | 继续到下一断点 / 执行到指定行 |
| `d 编号` / `disable 编号` / `enable 编号` | 删 / 禁用 / 启用断点 |
| `display 变量` / `undisplay 编号` | 每次停下自动显示 / 取消 |
| `bt` / `info locals` | 看调用栈 / 看当前函数局部变量 |

**【易忘】** 断点编号只增不减（删了 2 再设新的不会补回 2）；`↑` 重复上一条命令；`undisplay` 跟的是显示编号不是变量名。

### next vs step【易混】【重点】

| 命令 | 遇函数调用 | 类比 |
|---|---|---|
| `n`（next）逐过程 | 不进函数，整体执行完 | F10 |
| `s`（step）逐语句 | 进入函数内部 | F11 |

### 三个调试技巧【重点】

1. `watch 变量`：值一变就暂停并显示新旧值 —— 查"变量在哪一刻被改了"。
2. `set var 变量=值`：现场改值验证猜想 —— 不重编译，只改本次运行。
3. 条件断点【易混】：

| 目的 | 语法 | 有 if 吗 |
|---|---|---|
| 新增条件断点 | `b 9 if i==30` | **有 if** |
| 给已有断点加条件 | `condition 2 i==30` | **没有 if**，2 是断点编号 |

### cgdb

- 分屏可视化版 gdb，命令完全不变；`yum/apt install -y cgdb` 安装；ESC 进代码屏，`i` 回命令屏。

## 8. 附录：换源实操

### 步骤主线（两者一致）

备份 → 下载/替换新源配置 → 清缓存更新 →（可选升级）→ 验证 →（可选恢复）

### CentOS 7 换 yum 源

```bash
sudo mkdir /etc/yum.repos.d/backup                          # ① 建备份目录
sudo mv /etc/yum.repos.d/*.repo /etc/yum.repos.d/backup/    # ② 备份全部旧源
sudo curl -o /etc/yum.repos.d/CentOS-Base.repo http://mirrors.aliyun.com/repo/Centos-7.repo  # ③ 下载阿里云源（清华源二选一）
sudo yum clean all && sudo yum makecache                    # ④ 清旧缓存 + 重建【重点：缺这步仍走旧源】
sudo yum update                                             # ⑤ 更新系统
sudo yum repolist                                           # ⑥ 验证
# 恢复：sudo mv /etc/yum.repos.d/backup/*.repo /etc/yum.repos.d/
```

### Ubuntu 换 apt 源

```bash
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak     # ① 备份（apt 是单个文件）
sudo wget -O /etc/apt/sources.list http://mirrors.aliyun.com/repo/ubuntu-sources.list  # ② 替换（二选一）
# ③ 检查每行都含 focal（Ubuntu 20.04 代号），混入 bionic/jammy 要删【易错】
sudo apt update                                             # ④ 更新缓存
sudo apt policy                                             # ⑤ 验证
# 恢复：sudo cp /etc/apt/sources.list.bak /etc/apt/sources.list && sudo apt update
```

**【易混】** yum 源 = `/etc/yum.repos.d/` 目录下多个 `.repo` 文件；apt 源 = `/etc/apt/sources.list` 单个文件。

## 易混淆对比速查卡

| 主题 | A | B |
|---|---|---|
| 链接方式 | 动态：运行时加载 .so，gcc 默认 | 静态：复制进程序 .a，需 -static |
| vim 撤销 | `u` 撤销（后退） | `ctrl+r` 恢复（前进） |
| 回车换行 | `\r` 回行首 | `\n` 下一行 |
| gdb 步进 | `n` 不进函数（F10） | `s` 进函数（F11） |
| 条件断点 | 新增 `b 9 if i==30`（有 if） | 追加 `condition 2 i==30`（无 if） |
| 自动变量 | `$@` 目标 / `$<` 第一个依赖 | `$^` 全部依赖 |
| 安装源 | base 标准稳定 | epel 扩展求全 |
| 软件源配置 | yum：.repo 目录 | apt：sources.list 单文件 |
| make 时间 | Modify 内容修改（make 看这个） | Change 属性变化 / Access 访问 |
