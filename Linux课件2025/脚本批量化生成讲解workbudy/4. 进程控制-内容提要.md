# 4. 进程控制-内容提要

> 来源：《4. 进程控制.pdf》全文 + 板书 20241124_进程控制 / 20241128_自定义shell_file开始（仅提取自定义shell部分）
> 【板书强调】= 老师反复强调/画图展开的权重标记；未标注的条目同样来自板书或课件，全部收录
> 本节主线：进程创建(fork) → 进程终止(exit/_exit/return/退出码) → 进程等待(wait/waitpid) → 进程程序替换(exec系列) → 自主Shell命令行解释器

## 1. 进程创建

- fork 函数：`#include <unistd.h>`，`pid_t fork(void)`；返回值：子进程得 0、父进程得子 PID、失败得 -1
- fork 内部（内核层面）：分配新内存块和内核数据结构 → 拷贝父进程部分数据结构 → 添加子进程到系统进程列表 → fork 返回，调度器调度
- fork 之后：父子代码相同，运行到相同位置；谁先执行由调度器决定
- 写时拷贝：父子代码共享，数据在不写入时也共享；任意一方试图写入时，以写时拷贝方式各自复制一份副本；写时拷贝 = 延时申请技术，提高整机内存使用率
- fork 常规用法：①父进程复制自己，父子同时执行不同代码段（如父等待客户端请求，子处理请求）②子进程执行完全不同的程序（子 fork 返回后调用 exec 函数）
- fork 调用失败原因：系统中进程太多；实际用户进程数超过限制

## 2. 进程终止

### 2-1 进程退出场景
- 代码运行完毕，结果正确
- 代码运行完毕，结果不正确
- 代码异常终止（收到信号）

### 2-2 常见退出方法
- 正常终止：①从 main 返回 ②调用 exit ③调用 _exit
- 异常终止：ctrl+c（SIGINT 信号终止）
- `echo $?` 查看最近一个进程/命令的退出码【板书强调】

### 2-2-1 退出码
- 退出码（退出状态）反映最后一次执行命令的状态；0 表示执行成功
- 退出码 1：不被允许的操作（如无 sudo 权限用 yum、除以 0）
- 退出码 130（128+2）：SIGINT（^C）；退出码 143（128+15）：SIGTERM
- 退出码 128+n：n 代表终止信号编号
- `strerror()` 函数获取退出码对应的描述
- 退出码写到进程的 task_struct 内部【板书强调】
- 不同的退出码值表示不同的出错原因【板书强调】
- 进程出现异常一般是进程收到了信号；一旦低7个比特位非0（异常退出），退出码无意义【板书强调】

### 2-3-2 _exit 函数
- `#include <unistd.h>`，`void _exit(int status)`
- status 定义进程终止状态，父进程通过 wait 获取该值
- status 虽是 int，但仅有低 8 位可被父进程所用；所以 `_exit(-1)` 时终端显示 $? = 255（-1 的低8位 = 255）
- _exit 是系统调用，进程退出时不进行缓冲区刷新【板书强调】

### 2-3-3 exit 函数
- `#include <unistd.h>`（实际在 stdlib.h），`void exit(int status)`
- exit 最后也会调用 _exit，但在此之前还做了：①执行用户通过 atexit 或 on_exit 定义的清理函数 ②关闭所有打开的流，刷新缓冲区数据 ③调用 _exit
- exit(库函数) vs _exit(系统调用) 的本质区别：exit 会刷新缓冲区，_exit 不会【板书强调】
- 缓冲区不是操作系统内部的缓冲区，是 C 语言库提供的缓冲区【板书强调】

### 2-3-4 return 退出
- return 是更常见的退出进程方法；执行 `return n` 等同于执行 `exit(n)`
- 调用 main 的运行时函数将 main 的返回值当作 exit 的参数
- main 函数结束表示进程结束；其他函数 return 只表示函数调用完成返回【板书强调】
- 任何地方调用 exit 都表示进程结束，并返回给父进程 bash 子进程的退出码【板书强调】

## 3. 进程等待

### 3-1 进程等待必要性
- 子进程退出，父进程不管不顾 → 僵尸进程 → 内存泄漏
- 僵尸状态的进程"刀枪不入"，kill -9 也杀不死（已经死去的进程无法再次杀死）
- 父进程需要知道子进程任务完成得如何（结果对不对、是否正常退出）
- 父进程通过进程等待回收子进程资源、获取子进程退出信息【板书强调】
- 回收子进程资源（最重要的）+ 获取子进程退出信息（可选的）【板书强调】

### 3-2 进程等待的方法

#### 3-2-1 wait 方法
- `#include <sys/types.h>` `#include <sys/wait.h>`
- `pid_t wait(int* status);`
- 返回值：成功返回被等待进程的 PID，失败返回 -1
- status：输出型参数，获取子进程退出状态；不关心可设为 NULL
- 如果等待子进程而子进程没有退出，父进程会阻塞在 wait 调用处【板书强调】

#### 3-2-2 waitpid 方法
- `pid_t waitpid(pid_t pid, int *status, int options);`
- pid 参数【板书强调】：
  - `< -1`：等待进程组 ID 等于 pid 绝对值的任意子进程
  - `-1`：等待任意子进程（与 wait 等效）
  - `0`：等待进程组 ID 与调用进程相同的任意子进程
  - `> 0`：等待进程 ID 等于 pid 的子进程
- status：输出型参数，由操作系统填充
- options：默认为 0（阻塞等待）；`WNOHANG`：若 pid 指定的子进程没有结束，waitpid 返回 0，不予以等待；若正常结束返回该子进程 PID
- 如果子进程已退出，调用 wait/waitpid 会立即返回并释放资源、获得退出信息
- 如果子进程存在且正常运行，调用 wait/waitpid 可能阻塞
- 如果不存在该子进程，立即出错返回

#### 3-2-3 获取子进程 status
- status 不能简单当作整型看待，应当作位图看待（只研究低 16 位）【板书强调】
- 低16位结构【板书强调】：高8位（15~8）= 退出状态（正常终止时有效）；低7位（6~0）= 终止信号（被信号杀死时有效）；第7位 = core dump 标志
  ```text
  正常终止：| 退出状态(8位) | 0(1位) | 0(7位) |
  被信号所杀：| 未用(8位) | core dump(1位) | 终止信号(7位) |
  ```
- `WIFEXITED(status)`：若为正常终止子进程返回的状态，则为真（查看进程是否正常退出）
- `WEXITSTATUS(status)`：若 WIFEXITED 非零，提取子进程退出码（查看进程的退出码）
- 没有异常时：低7个比特位为 0；异常退出时低7位非0，此时退出码无意义【板书强调】
- 测试代码：正常退出提取 `(st>>8)&0xFF`；被 kill 提取 `st&0x7F`
- OS 把子进程的退出信息（exit_code、exit_signal）保存到 task_struct 中，wait/waitpid 时拷贝给父进程【板书强调】

#### 3-2-4 阻塞与非阻塞等待
- 阻塞等待：`waitpid(-1, &status, 0)`，父进程挂起直到子进程结束【板书强调】
- 非阻塞等待：`waitpid(-1, &status, WNOHANG)`，子进程未结束则返回 0，父进程不挂起【板书强调】
- 非阻塞轮询模式【板书强调】：
  ```c
  do {
      ret = waitpid(-1, &status, WNOHANG);
      if (ret == 0) { printf("child is running\n"); }
      handler(); // 做其他事情
  } while (ret == 0);
  ```
- 非阻塞调用：可以让父进程在等待的同时做自己的事情【板书强调】
- 阻塞调用 vs 非阻塞调用类比【板书强调】：
  - 阻塞 = 打电话给李四，李四不接，你一直拿着电话等（挂起）
  - 非阻塞 = 打电话给李四，李四不接，你挂了电话去做别的事，过会儿再打（轮询）
- 如何让父进程做其他事情？→ 用函数指针数组 handler_t / std::function 实现回调机制【板书强调】
- `WNOHANG`：return immediately if no child has exited【板书强调】

## 4. 进程程序替换

### 4-1 替换原理
- 用 fork 创建子进程后，子进程执行的是和父进程相同的程序；子进程往往要调用 exec 函数执行另一个程序
- 进程替换：加载磁盘上一个全新的程序（代码和数据）到调用进程的地址空间中【板书强调】
- 调用 exec 后，该进程的用户空间代码和数据完全被新程序替换，从新程序的启动例程开始执行
- **调用 exec 并不创建新进程**，所以调用前后该进程的 PID 并未改变【板书强调】
- 进程 = 内核数据结构 + 代码和数据；替换只换代码和数据，内核数据结构（task_struct）不变【板书强调】
- 一旦程序替换成功，就去执行新代码了，原始代码的后半部分已经不存在了【板书强调】
- exec* 系列函数：只有失败返回值 -1，没有成功返回值；只要返回就是失败【板书强调】

### 4-2 替换函数
- 六种 exec 函数：`execl` / `execlp` / `execle` / `execv` / `execvp` / `execve`
- 命名规律【板书强调】：
  - `l` (list)：参数采用列表形式（可变参，以 NULL 结尾）
  - `v` (vector)：参数用数组形式（char *const argv[]）
  - `p` (path)：有 p 则自动搜索环境变量 PATH，无需写全路径
  - `e` (env)：自己维护/传入环境变量
- `execl` 用法：`execl("/usr/bin/ls", "ls", "-l", "-a", NULL);`【板书强调】
  - 第一个参数：路径+程序名；第二个参数：程序名（命令行怎么写就怎么传）；后续：参数；必须以 NULL 结尾表明参数传递完成
- `execlp` 用法：`execlp("ls", "ls", "-l", "-a", NULL);`——只传程序名，自动在 PATH 中搜索【板书强调】
- `execv` 用法：`execv("/usr/bin/ls", argv);`——路径 + argv 数组【板书强调】
- `execvp` 用法：`execvp("ls", argv);`——带 p + argv 数组【板书强调】
- `execle` / `execve`：最后一个参数传自定义环境变量数组 `char *const envp[]`
- 环境变量传入方式【板书强调】：
  ① 直接 putenv 新增环境变量（影响当前进程环境）
  ② execle/execve 传全新 envp 列表（只影响被替换的子进程）
  ③ 继承父进程环境（默认）
- **只有 execve 是真正的系统调用**（man 手册第 2 节），其他五个函数最终都调用 execve（man 手册第 3 节）【板书强调】
- exec 函数簇关系图：execl/execlp/execle/execv/execvp → 库函数封装 → execve → 系统调用
- 为什么 exec 替换不影响父进程？①进程具有独立性 ②数据发生写时拷贝【板书强调】
- 能替换我们自己写的程序吗？能！【板书强调】（示例：替换为 `./other` 可执行程序）

## 5. 自主 Shell 命令行解释器

### 5-1 目标
- 能处理普通命令（fork + execvp + wait）
- 能处理内建命令（shell 自己执行）
- 帮助理解内建命令/本地变量/环境变量概念
- 帮助理解 shell 的运行原理

### 5-2 实现原理
- shell 的典型互动：读取命令行 → 建立新进程 → 在新进程中运行程序 → 等待进程结束 → 读取下一行
- 自主 shell 循环过程【板书强调】：
  1. 打印命令行提示符（`[用户名@主机名 当前目录]# `）
  2. 获取用户命令（`fgets` 读取一整行）
  3. 解析命令行（`strtok` 按空格切分，构建 argv 数组）
  4. 检查并执行内建命令（cd/export/env/echo 等由 shell 自己调用函数完成）
  5. 普通命令：fork 创建子进程 → execvp 替换执行 → waitpid 父进程等待
- 内建命令 vs 普通命令【板书强调】：
  - 普通命令：必须由子进程执行（如 ls/ps/cat）
  - 内建命令：不能由子进程执行，必须由 shell 自己执行（如 cd 改变当前目录、export 设置环境变量、env 显示环境变量、echo 打印）
- 内建命令的本质：shell 自己调用函数或系统调用完成，不创建子进程【板书强调】

### 5-3 源码关键结构
- 全局命令行参数表：`char *gargv[64]`，`int gargc = 0`
- 全局环境变量表：`char *genv[64]`（从父 shell 的 environ 拷贝初始化）
- 当前工作路径：`char pwd[1024]`，`char pwdenv[1024]`（`PWD=xxx` 用于 putenv）
- 上一个命令退出码：`int lastcode = 0`（供 `echo $?` 使用）
- 命令行提示符生成：`snprintf(command_line, size, "[%s@%s %s]# ", 用户名, 主机名, 当前目录名)`
- 解析命令行：`strtok(command_buffer, " ")` 循环切分，构建 gargv 数组，gargv[gargc] 以 NULL 结尾
- 执行普通命令：fork → 子进程 execvp(gargv[0], gargv) → 父进程 waitpid(id, &status, 0) → 提取 WEXITSTATUS 保存到 lastcode
- 内建命令实现【板书强调】：
  - `cd`：`chdir(gargv[1])` 改变当前目录 + 更新 PWD 环境变量
  - `export`：`AddEnv(gargv[1])` 将新环境变量加入 genv 数组
  - `env`：遍历 genv 数组打印
  - `echo`：`echo $?` 打印 lastcode；`echo $PATH` 打印环境变量；其他直接打印字符串
- 环境变量初始化：从父 shell 的 `extern char **environ` 拷贝到 genv 数组【板书强调】
- TrimSpace 宏：跳过字符串开头的空白字符（处理 `" file.txt"` 这类带前导空格的输入）

### 5-4 总结
- exec/exit 就像 call/return：C 程序中函数通过 call/return 通信；Linux 中进程通过 fork/exec/wait/exit 通信
- 一个 C 程序可以 fork/exec 另一个程序并传参数；被调用程序执行后通过 exit(n) 返回值；调用进程通过 wait(&ret) 获取 exit 的返回值
