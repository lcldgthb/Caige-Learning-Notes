# 3. 进程概念

## 1. 冯诺依曼体系结构

双击一个 QQ 图标，程序就开始运行了。但你想过没有：这个程序平时躺在磁盘上，而执行它的是 CPU——中间隔着一个内存，为什么不能省略内存，让 CPU 直接读磁盘？要回答这个问题，得先看清一台计算机内部到底有哪些部件、它们之间谁和谁能直接说话。

### 五大部件与"只和内存打交道"

冯诺依曼体系结构把计算机分成五大部件【板书强调】：

| 部件 | 常见设备 | 干什么 |
|---|---|---|
| 输入设备 | 键盘、鼠标、话筒、摄像头、**网卡、磁盘** | 把外部数据送进计算机 |
| 输出设备 | 显示器、打印机、**网卡、磁盘** | 把计算机的数据送出去 |
| CPU | 运算器 + 控制器 | 执行指令、处理数据 |
| 存储器 | **就是内存** | 存放正在运行的程序和数据 |

注意磁盘和网卡出现了两次——它们既能读又能写，所以既是输入也是输出设备。

这套结构最重要的一条规矩【板书强调】：

> **CPU 在数据层面只和内存打交道；所有外设（磁盘、网卡、键盘……）也只和内存打交道。CPU 和外设之间绝不直接交换数据。**

输入和输出合称 IO。**理解 IO 要站在内存的角度**：数据流进内存叫输入，流出内存叫输出【板书强调】。

### 为什么程序必须先加载进内存

由上面那条规矩直接推出结论【板书强调】：程序运行之前以文件形式存在磁盘上，而 CPU 只能执行内存里的代码、访问内存里的数据——所以**任何软件运行前都必须先从磁盘加载到内存**，这不是操作系统的癖好，是体系结构的规定。

那 CPU 为什么不能直接读磁盘？因为速度差太悬殊【板书强调】：外设操作是毫秒级（千分之一秒），CPU 操作是纳秒级（十亿分之一秒），相差约百万倍。如果 CPU 死等磁盘，它 99.9999% 的时间都在空转。于是整个体系里数据都是在设备之间一级一级"拷贝"流动的，由此得到第二个结论：

> **计算机体系的效率，本质上由设备之间"拷贝"数据的效率决定。**

### 存储金字塔：用差价换速度

既然慢设备拖后腿，工程上的对策是在快慢之间加缓冲层，形成存储金字塔【板书强调】：

| 层级 | 介质 | 特点 |
|---|---|---|
| L0 | 寄存器 | CPU 内部的临时存储空间，最快最小 |
| L1~L3 | 高速缓存（SRAM） | 夹在 CPU 和内存之间的缓冲 |
| L4 | 主存（DRAM），即内存 | 程序运行的主战场 |
| L5 | 本地二级存储（本地磁盘） | 文件长期存放地 |
| L6 | 远程二级存储（分布式文件系统、Web 服务器） | 网络上的存储 |

越往上越快、越贵、越小。为什么不全用最快的？贵。所以当代计算机是**性价比的产物**——靠芯片技术和摩尔定律（集成电路上可容纳的晶体管数目约每两年翻一倍），用金字塔结构在成本和速度之间取平衡。

### 经典应用题：QQ 聊天的数据流

用上面的规矩推一遍"你给南京的好友发一条消息"的全过程，就能检验是否真懂了【板书强调】：

```text
你的键盘 → 你的内存 → 你的网卡 → 网络 → 好友的网卡 → 好友的内存 → 好友的显示器
```

发送文件同理，只是源头换成你的磁盘。要点：这是**两台机器，各自一套完整的冯诺依曼体系**；每台机器内部，数据都严格走"外设 → 内存 → 外设"的路线，网卡在这里先当输出设备（发）、后当输入设备（收）。
