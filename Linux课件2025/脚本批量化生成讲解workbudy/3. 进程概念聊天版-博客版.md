# 3. 进程概念

## 1. 冯诺依曼体系结构

- **基本组成**：
  - 输入单元：键盘、鼠标、扫描仪、网卡等。
  - 中央处理器（CPU）：包含运算器和控制器。
  - 存储器：这里主要指内存。
  - 输出单元：显示器、打印机、网卡、磁盘等。
- **核心数据流**：
  - 不考虑缓存时，CPU 在数据层面只能直接读写内存，不能直接访问外设。
  - 外设输入数据时写入内存，输出数据时从内存读取。
  - 所有设备都只能直接和内存打交道，典型路径为：
  
```text
输入设备 → 内存 → CPU → 内存 → 输出设备
```

- **设备速度差异**：
  - CPU 寄存器、缓存通常是纳秒级；键盘、磁盘、网络等外设通常慢得多。
  - 内存作为统一中转站，可以减少 CPU 直接等待慢速设备的时间。
  - 数据传输本质上涉及多次拷贝，系统效率不仅取决于 CPU 速度，也取决于设备间数据拷贝效率。
- **存储层次**：
  
```text
寄存器 → L1/L2/L3 高速缓存 → DRAM 内存 → 磁盘 → 网盘
```

  - 越靠近 CPU，速度越快、单位容量成本越高、容量越小。
  - L1 通常比 L2 快，L2 通常比 L3 快；缓存常用 SRAM，内存常用 DRAM。
- **网络聊天的数据流**：
  - 发送文字：
  
```text
A 键盘 → A 内存 → A 网卡 → 网络 → B 网卡 → B 内存 → B 显示器
```

  - 发送文件：
  
```text
A 磁盘 → A 内存 → A 网卡 → 网络 → B 网卡 → B 内存 → B 磁盘
```

  - 网卡接收数据时是输入设备，发送数据时是输出设备。

## 2. 操作系统(Operator System)

### 2-1 概念

- **定义**：任何计算机系统都包含一个基本程序集合，称为操作系统（OS）。
- **组成**：
  - 内核：进程管理、内存管理、文件管理、驱动管理。
  - 其他程序：函数库、Shell、系统工具等。
- **广义与狭义**：
  - 狭义操作系统通常指内核。
  - 广义操作系统包括内核、Shell、函数库和其他配套程序。
- **定位**：操作系统是负责统一管理计算机资源的软件。

### 2-2 设计OS的目的

- **对下**：与硬件交互，管理所有软硬件资源，包括 CPU、内存、文件、磁盘和各种设备。
- **对上**：为用户程序提供统一、方便、安全的执行环境。
- **驱动**：驱动程序负责把内核的通用操作转换为具体硬件能够理解的操作。

### 2-3 核心功能

- 操作系统的核心定位是：**一款纯正的“搞管理”的软件**。
- 管理对象包括：
  - 进程；
  - 内存；
  - 文件；
  - 设备；
  - CPU 等系统资源。

### 2-4 如何理解"管理"

- **管理步骤**：
  1. 描述被管理对象；
  2. 组织被管理对象；
  3. 根据描述信息进行调度、分配、回收和控制。
- **计算机中的实现**：
  - 用 `struct` 结构体描述对象；
  - 用链表、队列、树等数据结构组织对象。
- **进程管理的例子**：
  - 用 `task_struct` 描述进程；
  - 用双链表、运行队列等组织多个进程。
- **核心结论**：操作系统管理任何资源，本质上都是“先描述，再组织”。

### 2-5 系统调用和库函数概念

- **系统调用**：
  - 操作系统对外暴露的接口，供用户程序请求内核服务。
  - 功能通常较基础，参数和使用要求较严格。
- **库函数**：
  - 对系统调用或常用功能进行封装，给上层程序提供更易用的接口。
  - 库函数不一定进入内核；系统调用则是进入内核的正式接口。
- **典型层次**：

```text
用户程序 → 库函数/Shell → 系统调用 → 内核 → 驱动 → 硬件
```

- `printf` 是库函数，负责格式化输出；当数据需要写入终端或文件时，底层通常还要通过系统调用完成。
- **易混淆概念**：

| 对比项 | 库函数 | 系统调用 |
|---|---|---|
| 所在位置 | 用户空间函数库 | 操作系统提供的内核接口 |
| 作用 | 提供方便的编程方式 | 请求内核完成受保护的服务 |
| 是否一定进入内核 | 不一定 | 会进入内核 |
| 例子 | `printf`、`malloc` | `fork`、`getpid` 等 |

## 3. 进程

### 3-1 基本概念与基本操作

- **三种理解**：
  - 课本观点：程序的一次执行实例、正在执行的程序。
  - 内核观点：承担系统资源分配的实体，如 CPU 时间、内存、文件和 I/O。
  - 当前结论：
  
```text
进程 = task_struct（PCB）+ 自己的代码和数据
```

- **PCB 与 task_struct**：
  - PCB（Process Control Block）是进程控制块，保存进程属性。
  - Linux 中 PCB 的具体实现是 `task_struct`。
  - `task_struct` 是 Linux 内核中的结构体，会被装载到内存中。
- **task_struct 记录的信息**：
  - 标识符：PID 等，用于区别不同进程。
  - 状态：任务状态、退出代码、退出信号等。
  - 优先级：相对于其他进程的优先级。
  - 程序计数器：下一条待执行指令的地址。
  - 内存指针：代码、数据、共享内存等指针。
  - 上下文数据：CPU 寄存器中的进程运行现场。
  - I/O 状态信息：I/O 请求、设备以及打开的文件列表。
  - 记账信息：CPU 时间、时钟数、时间限制、记账号等。
  - 其他内核管理信息。
- **组织进程**：
  - 所有运行中的进程都以 `task_struct` 双链表等形式组织在内核中。
- **查看进程**：
  - `/proc/PID/`：查看指定进程的内核信息，如 `/proc/1`。
  - `top`、`ps`：用户级进程查看工具。
- **获取 PID 和 PPID**：

```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

int main()
{
    printf("pid: %d\n", getpid());    // 当前进程 PID
    printf("ppid: %d\n", getppid());  // 父进程 PID
    return 0;
}
```

- `getpid()`：获取当前进程 PID。
- `getppid()`：获取父进程 PID。
- **fork 原型与返回值**：

```c
#include <sys/types.h>
#include <unistd.h>

pid_t fork(void);
```

| 情况 | 父进程返回值 | 子进程返回值 |
|---|---:|---:|
| 创建成功 | 子进程 PID | `0` |
| 创建失败 | `-1` | 不产生子进程 |

- `pid_t`：用于表示进程 ID 的整数类型。
- **fork 的特点**：
  - `fork` 之后父子进程执行同一份代码。
  - 父子进程拥有各自独立的数据空间。
  - 初始数据可共享，任一方写数据时通过写时拷贝分离。
  - 代码通常共享，数据在写入时复制。
- **fork 分流示例**：

```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

int main()
{
    int ret = fork();
    if (ret < 0) { perror("fork"); return 1; }
    else if (ret == 0)       // 子进程中返回 0
        printf("I am child: %d, ret: %d\n", getpid(), ret);
    else                     // 父进程中返回子进程 PID
        printf("I am father: %d, ret: %d\n", getpid(), ret);
    sleep(1);
    return 0;
}
```

- **为什么“返回两次”**：
  - 不是同一个进程调用两次，而是父进程和新创建的子进程都从 `fork` 后继续执行。
  - 父进程获得子进程 PID，子进程获得 `0`，因此同一个源代码中的 `if/else` 会在两个进程中分别进入不同分支。
- **为什么父子进程需要不同返回值**：
  - 一个父进程可以创建多个子进程，父进程必须知道每个子进程的 PID 以便管理。
  - 子进程只需通过 `0` 表示“我是子进程”。

### 3-2 进程状态

- **状态总表**：

```c
static const char *const task_state_array[] = {
    "R (running)",      /* 0 */
    "S (sleeping)",     /* 1 */
    "D (disk sleep)",   /* 2 */
    "T (stopped)",      /* 4 */
    "t (tracing stop)", /* 8 */
    "X (dead)",         /* 16 */
    "Z (zombie)",       /* 32 */
};
```

| 状态 | 含义 | 说明 |
|---|---|---|
| `R` | running | 正在运行或处于运行队列中，并不一定正在占用 CPU |
| `S` | sleeping | 可中断睡眠，等待事件完成，可被信号唤醒 |
| `D` | disk sleep | 不可中断睡眠，通常等待 I/O 完成 |
| `T` | stopped | 被暂停，可由 `SIGSTOP` 停止、`SIGCONT` 恢复 |
| `t` | tracing stop | 被调试器追踪时暂停 |
| `X` | dead | 死亡状态，通常不会在任务列表中看到 |
| `Z` | zombie | 子进程退出但父进程尚未读取退出状态 |

- **运行与阻塞**：
  - `R` 表示进程可运行或正在运行；一个 CPU 同时真正执行的进程通常只有一个。
  - 等待磁盘、键盘、网络等非 CPU 资源时，进程会离开运行队列，进入相应等待队列。
  - 进程状态变化通常表现为从一个队列删除，再加入另一个队列。
- **查看状态命令**：

```bash
ps aux   # a：所有用户；u：用户格式；x：无控制终端的进程
ps axj   # a：所有用户；x：无终端；j：作业信息、进程组和会话信息
```

- `j` 常用于查看 PID、PPID、进程组 ID、会话 ID 以及作业控制信息。
- **T 状态控制**：

```bash
kill -STOP PID   # 暂停进程
kill -CONT PID   # 恢复进程
```

- **D 状态**：
  - 常见于等待磁盘 I/O，普通信号通常不能立即终止该进程。
  - 可用以下命令制造大量 I/O 进行观察：

```bash
dd if=/dev/zero of=bigfile bs=1M count=1024
# if：输入文件；of：输出文件；bs：块大小；count：块数
```

- **僵尸进程 Z**：
  - 子进程退出后，父进程没有使用 `wait()` 等接口读取其退出状态，子进程进入 `Z`。
  - 子进程已不能运行，但退出代码、退出信号等信息仍保存在 `task_struct` 中，等待父进程回收。
  - 僵尸进程会持续占用 PCB 和进程表项；大量僵尸进程会造成内核资源泄漏。
- **僵尸进程示例**：

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>

int main()
{
    pid_t id = fork();
    if (id < 0) { perror("fork"); return 1; }
    if (id > 0) {
        printf("parent[%d] is sleeping...\n", getpid());
        sleep(30);                 // 父进程暂不回收子进程
    } else {
        printf("child[%d] is begin Z...\n", getpid());
        sleep(5);
        exit(EXIT_SUCCESS);        // 子进程退出，可能进入 Z
    }
    return 0;
}
```

- **孤儿进程**：
  - 父进程先退出、子进程仍在运行时，子进程称为孤儿进程。
  - 孤儿进程会被 1 号 `init/systemd` 进程领养，之后由 1 号进程负责回收。

| 对比项 | 僵尸进程 | 孤儿进程 |
|---|---|---|
| 父进程 | 仍在运行但未回收 | 已经退出 |
| 子进程 | 已经退出 | 仍在运行 |
| 主要问题 | 占用 PCB 和进程表项 | 原父进程消失 |
| 后续处理 | 父进程读取退出状态后回收 | 由 1 号进程领养并回收 |

### 3-3 进程优先级

- **优先权**：CPU 资源分配的先后顺序。优先级高的进程更有机会先获得 CPU。
- **`ps -l` 重点字段**：

| 字段 | 含义 |
|---|---|
| `UID` | 执行者身份 |
| `PID` | 进程 ID |
| `PPID` | 父进程 ID |
| `PRI` | 进程实际优先级 |
| `NI` | nice 值，优先级修正值 |

- **PRI 与 NI**：
  - `PRI` 越小，优先级越高，越早获得 CPU。
  - `NI` 不是优先级本身，而是修正值。
  - 关系为：
  
```text
PRI(new) = PRI(old) + nice
```

  - `nice` 取值范围为 `-20` 至 `19`，共 40 个级别。
  - `nice` 越小，新的 `PRI` 越小，优先级越高。
- **调整优先级**：

```text
top
按 r → 输入 PID → 输入 nice 值
```

```bash
nice -n 10 ./program   # 以 nice=10 启动程序
renice 10 -p 1234      # 修改 PID 1234 的 nice 值
```

```c
#include <sys/time.h>
#include <sys/resource.h>

int getpriority(int which, int who);
int setpriority(int which, int who, int prio);
```

- `getpriority`：获取优先级。
- `setpriority`：设置优先级。
- **竞争性、独立性、并行、并发**：

| 概念 | 含义 |
|---|---|
| 竞争性 | 进程数量多、CPU 资源少，进程争夺资源 |
| 独立性 | 进程拥有相对独立的资源和地址空间，运行互不干扰 |
| 并行 | 多个进程在多个 CPU 上同时执行 |
| 并发 | 多个进程在一个 CPU 上通过切换交替推进 |

### 3-4 进程切换

- **时间片**：
  - 分时操作系统把 CPU 时间划分为多个小段，进程在时间片内运行。
  - 时间片耗尽后，操作系统将进程从 CPU 上剥离，调度其他进程。
- **上下文切换**：
  - 上下文是进程运行时 CPU 寄存器中的全部状态。
  - 进程切换时，内核保存当前进程的寄存器内容，再恢复下一个进程的寄存器内容。
  - 保存与恢复通常涉及程序计数器、通用寄存器、栈指针、状态寄存器等。
- **基本过程**：

```text
进程 A 运行
  ↓
保存 A 的 CPU 寄存器状态
  ↓
将 A 的上下文保存到其内核数据结构/任务栈
  ↓
读取进程 B 保存的上下文
  ↓
恢复到 CPU 寄存器
  ↓
进程 B 从上次暂停的位置继续运行
```

- **核心结论**：进程切换本质上是任务切换或 CPU 上下文切换；CPU 寄存器只有一套，但每个进程都保存有自己的运行现场。

### 3-5 Linux2.6内核进程O(1)调度队列

- **一个 CPU 一个 runqueue**：
  - 每个 CPU 拥有一个运行队列。
  - 多 CPU 系统需要考虑负载均衡，将进程在不同 CPU 的队列间迁移。
- **优先级范围**：

| 范围 | 类型 | 说明 |
|---|---|---|
| `0~99` | 实时优先级 | 本节不重点讨论 |
| `100~139` | 普通优先级 | 普通进程使用 |

  - 普通进程的 40 个等级与 `nice=-20~19` 对应。
- **活动队列 active**：
  - 保存时间片尚未耗尽的进程。
  - `nr_active`：活动队列中的运行进程数量。
  - `queue[140]`：140 个优先级队列，数组下标就是优先级。
  - 相同优先级的进程按 FIFO 排队。
- **选择进程的逻辑**：
  1. 找到最高优先级的非空队列；
  2. 从该队列队首取出进程；
  3. 调度其运行。
- **bitmap[5]**：
  - 140 个优先级需要 140 个比特位。
  - `5 × 32 = 160` 个比特位，足以表示 140 个队列是否为空。
  - 位为 `1` 表示对应优先级队列非空，位为 `0` 表示为空。
  - 通过位图可快速定位最高优先级非空队列，避免线性扫描全部队列。
- **过期队列 expired**：
  - 结构与活动队列相同。
  - 保存时间片已经耗尽的进程。
  - 活动队列处理完毕后，为过期队列中的进程重新计算时间片。
- **active 与 expired 指针**：
  - `active` 永远指向活动队列，`expired` 永远指向过期队列。
  - 当 `active` 为空时，直接交换两个指针，不需要逐个移动进程。
- **核心结构**：

```c
struct prio_array {
    unsigned int nr_active;
    DECLARE_BITMAP(bitmap, MAX_PRIO + 1);
    struct list_head queue[MAX_PRIO];
};

struct rq {
    spinlock_t lock;
    unsigned long nr_running;
    unsigned long long nr_switches;
    struct task_struct *curr, *idle;
    struct prio_array *active, *expired, arrays[2];
};
```

- **O(1) 含义**：
  - 通过优先级数组、位图以及 `active/expired` 指针交换，在常数级时间内找到合适进程。
  - 调度查找时间不随进程总数增加而线性增长。

## 4. 命令行参数和环境变量

### 4-1 基本概念

- **命令行参数**：用户启动程序时附加的参数，例如 `ls -a -l` 中的 `-a`、`-l`。
- **环境变量**：用于描述程序运行环境的名称和值，格式为：

```text
NAME=value
```

- 环境变量通常具有全局属性：父进程导出后，子进程可以继承；子进程修改不会反向影响父进程。
- 常见配置文件包括：
  - `~/.bash_profile`：登录时配置；
  - `~/.bashrc`：Shell 启动时配置。

### 4-2 常见环境变量

| 变量 | 含义 |
|---|---|
| `PATH` | 命令搜索路径，多个目录用冒号分隔 |
| `HOME` | 用户主工作目录 |
| `SHELL` | 当前 Shell，通常为 `/bin/bash` |

- `PATH` 例如：

```text
/usr/local/bin:/usr/bin:/bin
```

- Shell 执行不带路径的命令时，会依次在 `PATH` 中查找。
- `HOME` 与 `~` 通常对应当前用户主目录，`cd ~; pwd` 可验证。

### 4-3 查看环境变量方法

```bash
echo $NAME       # 查看指定环境变量
echo $PATH       # 查看命令搜索路径
echo $HOME       # 查看主目录
echo $SHELL      # 查看当前 Shell
```

- 测试自定义程序：
  - `./hello`：明确从当前目录执行。
  - `hello`：Shell 只会在 `PATH` 指定目录中查找，当前目录通常不默认在其中。
- 添加路径：

```bash
export PATH=$PATH:hello       # 课件形式；实际应追加目录而非文件
export PATH=$PATH:$HOME/bin   # 推荐：追加可执行程序所在目录
```

- 不要直接覆盖原 `PATH`：

```bash
export PATH=$HOME/bin         # 会丢失原有搜索路径
```

### 4-4 和环境变量相关的命令

```bash
echo $NAME       # 显示指定环境变量
export NAME=value # 设置并导出环境变量
env              # 显示环境变量
unset NAME       # 清除指定变量
set              # 显示 Shell 本地变量和环境变量
```

- `env` 主要显示环境变量。
- `set` 通常比 `env` 输出更多，因为还包含 Shell 本地变量。
- `export` 是 Shell 内建命令，必须直接修改当前 Shell 的变量表。

### 4-5 环境变量的组织方式

- 每个程序都会收到一张环境表。
- 环境表本质上是字符指针数组：

```text
char *env[]
 ├── "PATH=/usr/bin:/bin"
 ├── "HOME=/root"
 ├── "SHELL=/bin/bash"
 └── NULL
```

- 每个指针指向一个以 `'\0'` 结尾的环境字符串，最后以空指针结束。
- 命令行参数表与环境表是两类不同信息：
  - `argv`：本次启动命令附带的参数；
  - `environ`：进程继承到的环境变量。

### 4-6 通过代码如何获取环境变量

- **方式一：`main` 的第三个参数**：

```c
#include <stdio.h>

int main(int argc, char *argv[], char *env[])
{
    int i = 0;
    for (; env[i]; i++)
        printf("%s\n", env[i]);  // 输出 NAME=value
    return 0;
}
```

- **方式二：使用 `environ`**：

```c
#include <stdio.h>

extern char **environ;  // libc 提供，但不在普通头文件中声明

int main()
{
    int i = 0;
    for (; environ[i]; i++)
        printf("%s\n", environ[i]);
    return 0;
}
```

- **方式三：命令行参数 `argc/argv`**：

```c
#include <stdio.h>

int main(int argc, char *argv[])
{
    for (int i = 0; i < argc; i++)
        printf("argv[%d] = %s\n", i, argv[i]);
    return 0;
}
```

- `argc`：参数总数。
- `argv`：参数字符串数组。
- `argv[0]`：通常是程序名。
- `argv[1]` 及之后：用户输入的选项或其他参数。

### 4-7 通过系统调用获取或设置环境变量

- 常用接口：

```c
#include <stdlib.h>

char *getenv(const char *name);
int putenv(char *string);
```

- `getenv`：按名称获取环境变量。
  - 成功：返回变量内容字符串指针；
  - 不存在：返回 `NULL`。
- 示例：

```c
#include <stdio.h>
#include <stdlib.h>

int main()
{
    char *path = getenv("PATH");
    if (path)
        printf("%s\n", path);
    return 0;
}
```

- `putenv`：设置环境变量，本节只要求了解。
- 三种获取方式对比：

| 方式 | 获取内容 | 适用场景 |
|---|---|---|
| `env` 参数 | 整张环境表 | `main` 中遍历全部环境变量 |
| `environ` | 整张环境表 | 程序其他位置访问环境表 |
| `getenv("NAME")` | 指定变量 | 只需要某个变量，最常用 |

### 4-8 环境变量通常是具有全局属性的

- **继承关系**：

```text
父进程设置并 export
        ↓
子进程继承环境表
        ↓
更深层子进程继续继承
```

- 父进程：

```bash
export MYENV="hello world"
```

- 子进程可以读取：

```c
#include <stdio.h>
#include <stdlib.h>

int main()
{
    char *env = getenv("MYENV");
    if (env)
        printf("%s\n", env);
    return 0;
}
```

- 本地变量未导出时，子进程不能通过环境表获取：

```bash
MYENV="hello"       # 仅当前 Shell 本地变量
./program           # 子进程通常读取不到
export MYENV="hello"
./program           # 子进程可以读取
```

- **易错点**：
  - 环境变量的“全局”不是所有进程共享同一份可写变量，而是父进程环境表可被子进程继承。
  - 子进程修改自己的环境不会影响父进程。
  - `USER` 等环境变量可以被普通用户修改，不能单独作为可靠的安全认证依据。

### 4-9 实验

- **PATH 实验**：
  1. 编译 `hello.c` 生成可执行文件。
  2. 对比 `./hello` 与 `hello`。
  3. 将程序所在目录加入 `PATH`：

```bash
export PATH=$PATH:$HOME/bin
```

  4. 再直接执行程序，观察 Shell 是否能找到。
- **HOME 实验**：

```bash
echo $HOME
cd ~
pwd
```

  - 分别使用 root 和普通用户观察 `HOME` 差异。
- **本地变量与环境变量实验**：

```bash
a=10
env | grep '^a='     # 通常没有输出

export a=10
env | grep '^a='     # 可以看到 a=10
```

- **配置持久化**：
  - 将 `export PATH=...` 等设置写入 `~/.bash_profile` 或 `~/.bashrc`。
- **Shell 内建命令**：

```bash
type export
type ls
```

  - `export` 通常显示为 `shell builtin`；
  - `ls` 通常是独立可执行程序或别名。
  - 原因是 `export` 必须直接修改当前 Shell 的环境表，不能在子进程中修改后再影响父 Shell。

## 5. 程序地址空间

### 5-1 研究平台

- 课件研究环境：
  - Linux kernel `2.6.32`；
  - 32 位平台。
- 32 位虚拟地址空间理论大小：

```text
2^32 = 4GB
```

- 典型划分：

```text
4GB 虚拟地址空间 = 3GB 用户空间 + 1GB 内核空间
```

- 这表示虚拟地址空间划分，不表示机器物理内存一定为 4GB。

### 5-2 程序地址空间回顾

- **从低地址到高地址的典型布局**：

```text
代码区（.text）
只读数据段（.rodata）
已初始化数据段（.data）
未初始化数据段（.bss）
堆（heap）
共享库/内存映射区
栈（stack）
命令行参数与环境变量
内核空间
```

- **各区域特点**：
  - 代码区：函数机器指令。
  - `.rodata`：字符串常量等只读数据。
  - `.data`：有初始值的全局变量、静态变量。
  - `.bss`：未显式初始化的全局变量、静态变量。
  - 堆：`malloc`、`new` 动态申请的空间，通常向高地址增长。
  - 共享库/映射区：动态库和内存映射区域。
  - 栈：函数参数、局部变量等，通常向低地址增长。
  - 参数和环境变量：程序启动时由系统放置。
- **验证示例**：

```c
#include <stdio.h>
#include <stdlib.h>

int g_unval;
int g_val = 100;

int main(int argc, char *argv[], char *env[])
{
    const char *str = "helloworld";
    static int test = 10;
    char *p = malloc(10);

    printf("code: %p\n", (void *)main);
    printf("data: %p\n", (void *)&g_val);
    printf("bss : %p\n", (void *)&g_unval);
    printf("heap: %p\n", (void *)p);
    printf("static: %p\n", (void *)&test);
    printf("stack: %p\n", (void *)&p);
    printf("rodata: %p\n", (void *)str);
    printf("argv[0]: %p\n", (void *)argv[0]);
    printf("env[0]: %p\n", (void *)env[0]);
    free(p);
    return 0;
}
```

- 地址每次运行可能不同，原因包括地址空间布局随机化；应观察区域的整体关系，不应把具体地址当作固定值。
- 连续 `malloc` 返回地址通常向高地址变化，局部变量地址通常向低地址变化，但堆分配器可能复用空间，不能把连续性当作语言保证。

### 5-3 虚拟地址

- **实验现象**：
  - `fork` 后父子进程打印同一个全局变量的地址，数值地址通常相同。
  - 子进程修改变量后，父进程仍看到原值。
- **示例**：

```c
#include <stdio.h>
#include <unistd.h>

int g_val = 0;

int main()
{
    pid_t id = fork();
    if (id < 0) { perror("fork"); return 1; }

    if (id == 0) {             // 子进程
        g_val = 100;
        printf("child[%d]: %d : %p\n",
               getpid(), g_val, (void *)&g_val);
    } else {                   // 父进程
        sleep(3);
        printf("parent[%d]: %d : %p\n",
               getpid(), g_val, (void *)&g_val);
    }
    return 0;
}
```

- **结论**：
  - 父子进程内容不同，说明不是同一个物理变量。
  - 地址数值相同，说明该地址不是物理地址。
  - C/C++ 程序看到的地址全部是虚拟地址。
  - 物理地址由操作系统统一管理，用户程序不能直接看到和随意访问。
- **页表**：
  - 页表记录虚拟地址到物理地址的映射。
  - 每个进程通常拥有独立的虚拟地址空间和页表。
  - 不同进程可以有相同的虚拟地址数值，但映射到不同的物理地址。
- **写时拷贝**：
  - `fork` 后，父子进程开始时可共享同一物理页。
  - 任一方写入时，操作系统复制物理页，并修改写入方的页表，使双方数据分离。
  - 这同时节省初始复制开销并保证进程独立性。

### 5-4 进程地址空间

- “程序地址空间”更准确的说法是“进程地址空间”。
- 每个进程都有一套独立的虚拟地址空间，操作系统通过页表将其映射到物理内存。
- **地址映射关系**：

```text
进程虚拟地址
      ↓
    页表
      ↓
物理地址
```

- 同一个变量在父子进程中可能拥有相同的虚拟地址，但因页表不同，实际物理地址可以不同。
- 虚拟地址空间不是预先分配好的完整物理内存，而是进程可见的地址地图和区域描述。

### 5-5 虚拟内存管理 - 第一讲

- **`mm_struct`**：
  - 描述 Linux 进程虚拟地址空间的整体信息。
  - 普通用户进程的 `task_struct->mm` 指向其用户地址空间。
  - 内核线程的 `mm` 通常为 `NULL`，但通过 `active_mm` 使用已有地址空间中的内核映射。

```c
struct task_struct {
    struct mm_struct *mm;         // 用户进程的虚拟地址空间
    struct mm_struct *active_mm;  // 内核线程使用的地址空间
};
```

- **`mm_struct` 关键字段**：

```c
struct mm_struct {
    struct vm_area_struct *mmap;  // VMA 单链表
    struct rb_root mm_rb;         // VMA 红黑树
    unsigned long task_size;      // 虚拟地址空间大小

    unsigned long start_code, end_code;
    unsigned long start_data, end_data;
    unsigned long start_brk, brk;
    unsigned long start_stack;
    unsigned long arg_start, arg_end;
    unsigned long env_start, env_end;
};
```

- `mm_struct` 所在头文件为 `mm_types.h`。
- **VMA（`vm_area_struct`）**：
  - 表示一段独立的虚拟内存区域。
  - 不同区域可能具有不同的权限、用途和内部机制。
  - 关键字段包括：

```c
struct vm_area_struct {
    unsigned long vm_start;       // 区域起始地址
    unsigned long vm_end;         // 区域结束地址
    struct vm_area_struct *vm_next, *vm_prev;
    struct rb_node vm_rb;
    struct mm_struct *vm_mm;      // 所属 mm_struct
    unsigned long vm_flags;       // 权限和属性标志
    unsigned long vm_pgoff;       // 文件映射偏移
    struct file *vm_file;         // 映射文件
    void *vm_private_data;
};
```

- **VMA 的组织方式**：

| 方式 | 字段 | 特点 |
|---|---|---|
| 单链表 | `mmap` | 虚拟区较少时结构简单 |
| 红黑树 | `mm_rb` | 虚拟区较多时查找更快 |

- 一个进程可拥有多个 VMA，例如代码段、数据段、堆、动态库、栈等。
- **地址空间与物理内存分离**：
  - 创建进程时先建立 `task_struct`、`mm_struct` 和页表，不要求所有代码数据立即装入物理内存。
  - 程序真正访问某个页面时，操作系统才按需分配物理页并建立映射，这称为延迟分配。
  - `malloc`、`new` 首先涉及虚拟地址空间；物理页可能在真正访问时才分配。

### 5-6 为什么要有虚拟地址空间

- **直接使用物理地址的问题**：
  - 安全风险：进程可以任意读写其他进程或内核数据。
  - 地址不确定：程序每次装入物理内存的位置可能不同，程序无法固定使用物理地址。
  - 效率低下：内存不足时若按整个进程搬入、换出磁盘，拷贝成本很高。
- **虚拟地址空间的收益**：
  - **安全隔离**：
    - 页表由操作系统维护，访问时可检查映射和读写执行权限。
    - 非法访问、写只读区域等行为会被拦截。
  - **地址有序**：
    - 虚拟空间可以为每个进程提供连续、有序的代码、数据、堆、栈布局。
    - 物理页可以分散在任意位置，进程无需感知。
  - **分页与高效换出**：
    - 物理内存以页为单位分配、回收和换出，不必整体搬运完整进程。
  - **进程管理与内存管理解耦**：
    - 进程只面对虚拟地址，物理内存由操作系统按需分配。
    - 物理内存可以被加载到任意空闲位置，页表负责建立映射。
- **核心结论**：虚拟地址空间通过“虚拟地址 + 页表 + 分页机制”解决了安全、地址不确定和效率问题，并实现了进程与物理内存管理的解耦。
