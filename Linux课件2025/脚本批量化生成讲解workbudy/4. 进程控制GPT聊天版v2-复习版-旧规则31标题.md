# 4. 进程控制

## 1. 进程创建

### 1-1 fork函数初识

- 头文件 `<unistd.h>`；原型：`pid_t fork(void)`；无参数，创建子进程；`pid_t` 是可表示 PID 和 `-1` 的整数类型。
- 内核流程：分配独立 PCB 等管理结构 → 复制可继承信息、设置新 PID → 纳入管理并允许调度 → 父子分别继续执行。
- **父子从 `fork` 返回处继续执行，谁先运行不确定。**

### 1-2 fork函数返回值

| 返回位置／结果 | 返回值 |
|---|---|
| 父进程，创建成功 | 子进程 PID，`> 0` |
| 子进程 | `0` |
| 创建失败 | 原进程返回 `-1`，没有子进程 |

- 失败分支：`if (pid == -1) { perror("fork"); return 1; }`。
- `perror("fork")` 输出提示文字及 `errno` 对应的错误描述；**不存在“收到 `-1` 的子进程”。**

### 1-3 写时拷贝

- 父子拥有独立的进程管理信息和地址空间；初始可共享物理内存页，发生写入时再复制相应页面。
- **创建进程不等于立即复制父进程的全部代码、数据。**
- “延时申请”推迟的是相关内存副本的分配，不是子进程的创建。

### 1-4 fork常规用法

| 用法 | 父进程 | 子进程 |
|---|---|---|
| 同一程序内分工 | 继续接收客户端请求 | 处理当前请求 |
| 运行其他程序 | 继续原程序，按需等待 | `fork` 后调用 `exec*` |

- **`fork` 创建进程；`exec` 替换调用进程的程序，不创建新进程。**

### 1-5 fork调用失败的原因

| 常见原因 | 限制范围 |
|---|---|
| 系统进程数量过多 | 整个系统 |
| 实际用户的进程数超过限制 | 实际用户 ID 对应的用户 |
| 内存等资源不足 | 系统资源 |

- 原因不止数量超限；检查返回值并用 `perror` 获取实际错误。

## 2. 进程终止

### 2-1 进程退出场景

| 场景 | 终止方式 | 结果判断 |
|---|---|---|
| 主动结束，报告成功 | 正常终止 | 通常退出码 `0` |
| 主动结束，报告失败 | 正常终止 | 通常退出码非零 |
| 被信号终止 | 异常终止 | 查看终止信号 |

- **正常终止 ≠ 任务成功；操作系统不验证业务结果，只接收程序报告。**

### 2-2 进程常见退出方法

| 方法 | 分类 | 要点 |
|---|---|---|
| 从 `main` 返回 | 正常终止 | 返回值作为退出状态 |
| `exit(status)` | 正常终止 | 先做 C 库退出清理 |
| `_exit(status)` | 正常终止 | 不做 C 库退出清理 |
| 被 `SIGINT` 等信号终止 | 异常终止 | 不依赖程序主动退出 |

- `Ctrl+C` 通常向前台进程组发送 `SIGINT`（编号 `2`），默认终止；可被处理或忽略。
- `echo $?`：读取**当前 shell 上一条命令**的状态；必须紧接目标命令执行，其他命令会覆盖状态。

#### 2-2-1 退出码

- 通常 `0` 成功、非零失败或其他结果；具体含义由程序约定，**没有通用退出码错误表**。
- “退出码 `1` = 不允许的操作”不是通用规则；C 整数除零属于未定义行为，常见 Linux 环境可能触发 `SIGFPE`，并非必然返回 `1`。

| 数字／记录 | 含义 |
|---|---|
| 程序正常退出码 | 父进程通常只能取得低 `8` 位，范围 `0～255` |
| Bash 信号终止状态 | 通常为 `128 + 信号编号` |
| `errno` | 系统调用／库函数的错误编号 |
| `wait` 得到的 `status` | 编码后的等待状态，不是直接退出码 |

- `SIGINT=2` → Bash 常见状态 `130`；`SIGTERM=15` → `143`。程序也能主动返回 `130`，不能只凭数字断定信号终止。
- `<string.h>`：`char *strerror(int errnum)`，参数是错误编号，返回对应描述字符串；例如 `strerror(EACCES)`。**不是退出码翻译器**，不能用 `strerror(130)` 解释 Bash 状态。
- Linux 将终止信息保存在 `task_struct` 等内核记录中，供父进程等待时收取；低 `7` 位属于等待状态，不属于 `$?`；位图及解析宏见 `3-2-3`。

#### 2-3-2 _exit函数

- `<unistd.h>`：`void _exit(int status)`；`status` 为终止状态；结束整个进程，**不返回**。
- 父进程只能取得正常退出码的低 `8` 位：`_exit(-1)` 后，`echo $?` 通常为 `255`。
- 不执行退出回调、不刷新 C 库输出缓冲区；未提交给内核的缓冲数据可能丢失。
- 严格说是 C 库提供的底层终止封装；现代 Linux 常通过 `exit_group` 结束整个进程。跳过 C 库清理不等于内核不回收资源。

#### 2-3-3 exit函数

- `<stdlib.h>`：`void exit(int status)`；报告终止状态，**不返回**；正常退出码同样只保留低 `8` 位。
- 流程：执行 `atexit`／`on_exit` 登记的回调 → 刷新输出缓冲并关闭流 → 底层终止；`on_exit` 非标准 C 接口。

| 对比项 | `exit` | `_exit` |
|---|---|---|
| 头文件 | `<stdlib.h>` | `<unistd.h>` |
| 层次 | 提供退出清理的库函数 | 底层终止接口封装 |
| 退出回调 | 执行 | 不执行 |
| 刷新 C 库输出缓冲 | 是 | 否 |
| 结束整个进程 | 是 | 是 |

- 全缓冲状态下，`printf("hello")` 后调用 `exit(0)` 会送出文本；调用 `_exit(0)` 可能丢失文本。
- **区别是 C 库缓冲区，不是操作系统缓冲区；刷新到内核不等于落盘。**

#### 2-3-4 return退出

| 位置／写法 | 效果 |
|---|---|
| `main` 中 `return n` | 正常 C 程序中相当于 `exit(n)` |
| 普通函数中 `return n` | 仅结束当前调用，调用者继续执行 |
| 任意函数中 `exit(n)` | 结束整个进程，不返回调用位置 |

- 退出信息由父进程读取，不固定交给 Bash；Bash 直接启动的普通前台程序，才由 Bash 等待并生成 `$?`。

## 3. 进程等待

### 3-1 进程等待必要性

- **首要任务：回收子进程退出后保留的资源，避免僵尸；读取退出信息可选。**
- 子进程已退出：直接收取；尚未退出：是否阻塞取决于接口和选项。
- 退出信息区分：正常终止／信号终止；仅正常终止时用退出码表达任务结果。

### 3-2 进程等待的方法

- 头文件：`<sys/types.h>`、`<sys/wait.h>`。
- **函数返回值表示“收到了谁”；输出参数 `status` 表示“怎样结束”。**

#### 3-2-1 wait方法

- 原型：`pid_t wait(int *status)`；等待任意一个子进程。
- `status`：输出型参数，传变量地址；传 `NULL` 仅回收、不读取信息。

| 情况 | 行为／返回值 |
|---|---|
| 已有子进程退出、未回收 | 立即回收，返回其 PID |
| 有可等待子进程，尚未退出 | 阻塞等待 |
| 失败／没有可等待子进程 | 返回 `-1` |

- `wait(NULL)` 仍回收资源；一次成功调用收取一个子进程。

#### 3-2-2 waitpid方法

- 原型：`pid_t waitpid(pid_t pid, int *status, int options)`。
- `pid` 选择对象；`status` 接收状态或为 `NULL`；`options` 必须显式提供，不能省略。

| `pid` | 等待对象：均限自己的子进程 |
|---|---|
| `< -1` | 进程组 ID 为 `abs(pid)` 的任意子进程 |
| `-1` | 任意子进程 |
| `0` | 与调用者同进程组的任意子进程 |
| `> 0` | PID 为 `pid` 的指定子进程 |

| 符合条件的子进程情况 | `options = 0` | `options = WNOHANG` |
|---|---|---|
| 已退出、未回收 | 返回 PID，并回收 | 返回 PID，并回收 |
| 存在，但均未退出 | 阻塞 | 立即返回 `0` |
| 无可等待子进程 | 返回 `-1` | 返回 `-1` |

- `waitpid(-1, &status, 0)` 等效于 `wait(&status)`。
- **仅返回正数时解析本次 `status`；返回 PID 不表示任务成功，信号终止也会返回 PID。**
- 返回 `-1` 检查 `errno`；`EINTR` 表示被信号打断，可重试；无子进程通常为 `ECHILD`。

#### 3-2-3 获取子进程status

- `status` 类型为 `int`，内容为位图；下表仅针对 Linux **已终止子进程**的常见低 `16` 位编码，不扩展到暂停、恢复事件。

| 位位置 | 正常终止 | 信号终止 |
|---|---|---|
| 第 `15～8` 位 | 正常退出码 | 不作为有效退出码 |
| 第 `7` 位 | `0` | core dump 标志 |
| 第 `6～0` 位 | 全 `0` | 终止信号编号 |

| 宏 | 作用／前提 |
|---|---|
| `WIFEXITED(status)` | 判断正常终止 |
| `WEXITSTATUS(status)` | 提取退出码；先确认 `WIFEXITED` 为真 |
| `WIFSIGNALED(status)` | 判断信号终止 |
| `WTERMSIG(status)` | 提取终止信号；先确认 `WIFSIGNALED` 为真 |

- 手工提取：`(status >> 8) & 0xFF` 取退出码；`status & 0x7F` 取低 `7` 位。实际优先使用宏。
- **低 `7` 位为零只表示正常终止，不代表退出码为零。**
- core dump 标志不保证当前目录存在 core 文件。
- 内核保留退出信息 → `wait`／`waitpid` 整理写入父进程的 `status` → 完成回收。
- `task_struct.exit_signal` 通常是**子进程退出时通知父进程的信号**，不是杀死子进程的信号。

```c
pid_t ret;  // 保存等待结果
do {
    ret = waitpid(child, &status, 0);  // 阻塞等待指定子进程
} while (ret == -1 && errno == EINTR);  // 被信号打断则重试
if (ret == -1) perror("waitpid");  // 失败时不解析状态
else if (WIFEXITED(status)) printf("%d\n", WEXITSTATUS(status));  // 正常退出码
else if (WIFSIGNALED(status)) printf("%d\n", WTERMSIG(status));  // 终止信号
```

#### 3-2-4 阻塞与非阻塞等待

| 对比项 | 阻塞等待 | 非阻塞等待 |
|---|---|---|
| 调用 | `waitpid(-1, &status, 0)` | `waitpid(-1, &status, WNOHANG)` |
| 子进程均未退出 | 暂停在调用处 | 返回 `0` |
| 父进程执行其他任务 | 等待期间不能继续 | 返回后主动安排 |
| 最终回收 | 一次调用等待结果 | 需后续再次检查 |

- 轮询分支：`ret > 0` 回收并解析；`ret == 0` 做其他任务；`ret == -1` 时 `EINTR` 重试，其他错误退出无效轮询。
- `sleep(1)` 可限制查询频率、避免忙等；这是主动暂停，不是 `WNOHANG` 导致的阻塞。轮询间隔和任务耗时越长，发现退出越迟。
- “挂起等待”此处指阻塞，不专指换出到 swap。
- 回调：`typedef void (*handler_t)(void)` 定义函数指针类型；数组登记函数，返回后逐个调用；`handler_t` 是自定义名称。
- 需要携带数据的 C++ 任务可用 `<functional>` 中的 `std::function<void()>`；普通函数使用指针数组即可。

## 4. 进程程序替换

### 4-1 替换原理

- `exec`／`exec*` 是函数族统称：加载新程序，替换调用进程用户空间的代码、数据和地址映射；从新程序启动例程开始执行，而非旧调用点之后。
- 保留进程身份及 PID；`task_struct` 不被新进程对象替代，但相关字段会更新。

| 对比项 | `fork` | `exec*` |
|---|---|---|
| 创建新进程 | 是 | 否 |
| PID | 子进程获得新 PID | 调用进程 PID 不变 |
| 程序内容 | 初始延续原程序 | 成功后换为新程序 |
| 原代码 | 父子分别继续 | 成功后不再继续 |

- **成功不返回；返回必为失败，值为 `-1` 并设置 `errno`。** 新程序后来退出，不是 `exec` 返回。
- 常见失败：目标不存在、无执行权限、文件不可执行；用 `perror` 报错。
- 子进程替换不改变父进程地址空间；不是先完整复制父程序再覆盖。
- 谁调用就替换谁；父进程调用也会被替换。
- 自编译程序可用 `execl("./other", "other", (char *)NULL)`；相对路径基于当前工作目录，不是启动器文件所在目录。
- 替换前需保留的 C 库输出应先 `fflush(stdout)`；不能指望 `exec` 自动刷新旧程序缓冲。

### 4-2 替换函数

- 六种接口均声明于 `<unistd.h>`，返回类型均为 `int`，成功不返回、失败返回 `-1`。
- `path`：程序路径；`file`：程序名或路径；`arg`／`argv[0]`：新程序参数表首项；`envp`：显式环境数组。

#### 4-2-1 函数解释

| 原型 | 参数组织 | 定位／环境 |
|---|---|---|
| `int execl(const char *path, const char *arg, ...)` | 列表，以 `(char *)NULL` 结束 | 指定路径，继承环境 |
| `int execlp(const char *file, const char *arg, ...)` | 列表，以 `(char *)NULL` 结束 | 可搜索 `PATH`，继承环境 |
| `int execle(const char *path, const char *arg, ...)` | 列表结束标记之后再传 `envp` | 指定路径，显式环境 |
| `int execv(const char *path, char *const argv[])` | 参数数组 | 指定路径，继承环境 |
| `int execvp(const char *file, char *const argv[])` | 参数数组 | 可搜索 `PATH`，继承环境 |
| `int execve(const char *path, char *const argv[], char *const envp[])` | 参数数组、环境数组 | 指定路径，显式环境 |

- 列表示例：`execl("/usr/bin/ls", "ls", "-l", "-a", (char *)NULL)`；搜索版本：`execlp("ls", "ls", "-l", "-a", (char *)NULL)`。
- `argv[0]` 惯例为程序名，不负责定位程序，也不要求严格等于文件名；每个参数单独传，不能把 `"ls -l -a"` 当作一个参数。
- 数组必须以空指针结束：`argv = {"ls", "-l", "-a", NULL}`；环境每项为 `"NAME=value"`，`envp` 同样以 `NULL` 结束。
- `execle(path, arg0, ..., (char *)NULL, envp)`：先结束参数列表，再传环境。
- 无 `p`：可用绝对或相对路径，但不搜索 `PATH`；有 `p`：参数含 `/` 时按路径执行，不再搜索。

| 环境方式 | 新程序环境 | 易忘点 |
|---|---|---|
| 不带 `e` | 继承调用进程当前环境 | 包含调用前的环境修改 |
| `putenv` 后调用不带 `e` 的接口 | 继承修改后的环境 | 先修改调用者环境 |
| 带 `e`，传 `envp` | 仅使用显式环境 | **不自动合并旧环境** |

- `<stdlib.h>`：`int putenv(char *string)`；传入 `"NAME=value"`；成功 `0`，失败非零；直接使用字符串存储，必须保持其寿命。
- 六种接口中，`execve` 对应系统调用，查 `man 2 execve`；其余五种为库函数封装，查第 `3` 节，最终通过 `execve` 完成替换。

#### 4-2-2 命名理解

| 字母 | 含义 | 记忆点 |
|---|---|---|
| `l` | list | 参数逐个列出 |
| `v` | vector | 参数放入数组 |
| `p` | path | 可按 `PATH` 搜索 |
| `e` | environment | 显式提供环境数组 |

- `l/v` 是参数组织方式；`p/e` 是附加能力。

## 5. 自主Shell命令行解释器

### 5-1 目标

- 实现提示、输入、解析、执行循环；普通命令使用 `fork`＋`execvp`＋`waitpid`，内建命令直接调用 shell 内部函数。
- 环境变量参与后续程序执行；`echo` 支持读取环境和上一条命令结果。
- 范围：按空格拆分简单命令；不实现引号、管道、重定向、完整本地变量赋值系统。

### 5-2 实现原理

- 循环顺序：打印并刷新提示符 → `fgets` 读取、去换行 → `strtok` 构造参数表 → 跳过空行 → **优先检查内建命令** → 普通命令创建子进程 → 子进程替换 → 父进程等待并记录结果。

| 对比项 | 普通命令 | 内建命令 |
|---|---|---|
| 本节执行者 | 子进程中的外部程序 | shell 自身函数 |
| 是否创建子进程 | 是 | 否 |
| 示例 | `ls`、`ps`、`cat` | `cd`、`export`、`env`、`echo` |
| 状态影响 | 不直接改变父 shell 状态 | 可改变 shell 目录、环境 |

- **`cd`、`export` 要影响当前 shell，必须在当前 shell 执行。**
- `env`、`echo` 也可由外部程序实现，并非所有内建命令都不能在子进程运行。
- 交互 shell 不直接执行 `execvp`：成功会替换自身，丢失输入循环。

### 5-3 源码

| 全局数据 | 用途／约束 |
|---|---|
| `char *gargv[64]` | 命令及参数地址；最多 `63` 项，末尾 `NULL` |
| `int gargc = 0` | 有效参数数，包含命令名；每轮重置 |
| `char *genv[64]` | 环境字符串地址；最多 `63` 项，末尾 `NULL` |
| `char pwd[1024]` | 当前目录字符串，不是执行 `pwd` 命令 |
| `char pwdenv[1024]` | `"PWD=路径"`；需额外容纳 `PWD=` |
| `int lastcode = 0` | 上一条命令状态，供 `echo $?` 使用 |

- **提示与读取**
  - `int snprintf(char *s, size_t n, const char *format, ...)`：最多写入 `n` 字节（含结尾空字符）；返回原本所需字符数（不含结尾），`>= n` 表示截断，负数表示错误。
  - 提示格式：`snprintf(command_line, size, "[%s@%s %s]# ", user, host, dir)`；无换行时 `fflush(stdout)`。
  - `char *fgets(char *s, int n, FILE *stream)`：最多读取 `n-1` 个字符，可能保留换行；成功返回 `s`，EOF／错误返回 `NULL`。
  - 去换行：`command_buffer[strcspn(command_buffer, "\n")] = '\0'`；超长输入应拒绝并处理剩余行，不能执行截断命令。

- **参数解析**
  - `<string.h>`：`char *strtok(char *str, const char *delim)`；首次 `strtok(command_buffer, " ")`，后续 `strtok(NULL, " ")`；返回下一项地址，无下一项返回 `NULL`。
  - 修改原输入数组；`gargv` 只保存其中地址，依赖输入缓冲寿命；不识别引号，分隔符 `" "` 不包含制表符。
  - 每轮清零 `gargc`，检查容量，结束写入 `gargv[gargc] = NULL`；`gargc == 0` 直接下一轮，不访问命令名。

- **普通命令执行与结果**
  - 检查 `fork` 失败；子进程执行 `execvp(gargv[0], gargv)`。
  - `execvp` 返回则报错并退出，**不能落入 shell 输入循环**。
  - 父进程 `waitpid(id, &status, 0)`，`EINTR` 重试；等待成功后再解释状态。
  - 正常终止：`lastcode = WEXITSTATUS(status)`；信号终止：可按 shell 约定保存 `128 + WTERMSIG(status)`，不可直接套用 `WEXITSTATUS`。

- **环境初始化与一致性**
  - 从 `extern char **environ` 复制环境项到 `genv`，补 `NULL`；课件式实现可设 `environ = genv`。
  - **仅修改显示用的 `genv` 不等于修改后续程序继承的环境。**
  - 继承环境可能超过 `63` 项；复制指针不等于复制字符串；新增项不能指向下一轮覆盖的输入。
  - `putenv` 等接口可能调整 `environ`，不能永久假定 `environ == genv`；打印、修改、执行必须使用一致环境。

| 内建命令／工具 | 核心操作 | 必要检查 |
|---|---|---|
| `cd 目录` | `chdir(gargv[1])` → `getcwd` → 更新 `pwd`、环境 `PWD` | 参数、调用失败、缓冲容量；失败不伪造新路径 |
| `export NAME=value` | 自定义 `AddEnv(gargv[1])` 新增／替换环境项 | 合法名称与 `=`、同名替换、容量、独立字符串、末尾 `NULL` |
| `env` | 遍历实际环境表至 `NULL` 并打印 | `genv` 必须与实际环境一致 |
| `echo $?` | 打印旧 `lastcode` | 先打印，再记录本次 `echo` 结果 |
| `echo $NAME` | 去掉 `$` 后查环境 | 不存在时按空字符串处理 |
| `echo 普通文字` | 输出各参数，间隔空格 | 支持多个参数 |
| `TrimSpace` | 指针跳过前导空白 | 不负责拆词；宏实参保持简单 |

- `<unistd.h>`：`int chdir(const char *path)`，改变调用进程真实工作目录，成功 `0`、失败 `-1`；`char *getcwd(char *buf, size_t size)`，获取目录，成功返回 `buf`、失败 `NULL`。
- **修改 `PWD` 字符串不能代替 `chdir`。** `putenv(pwdenv)` 要求存储长期有效，并检查 `"PWD=..."` 拼接截断。
- `AddEnv` 非标准函数；修改当前自主 shell 环境，只供以后启动的程序继承，不反向修改其父进程环境。
- `<stdlib.h>`：`char *getenv(const char *name)`，返回变量值指针，未找到返回 `NULL`；不能直接把空指针交给 `%s`。
- `$?` 不是名为 `?` 的环境变量；先匹配 `$?`，再处理普通 `$NAME`。
- 内建命令也更新 `lastcode`：成功 `0`，失败非零。
- `TrimSpace` 只跳过前导空白；`strtok(..., " ")` 已跳过前导空格时，不必重复处理。

### 5-4 总结

| 易混概念 | 必须区分 |
|---|---|
| 函数调用与启动程序 | `call` 不创建进程；`fork` 创建进程、`exec` 替换程序 |
| 函数返回值与退出状态 | 普通 `return` 返回调用者；进程退出信息由父进程等待收取 |
| `exec` 与普通函数返回 | 替换成功不返回原调用点 |
| `wait(&ret)` 与直接退出码 | `ret` 是编码状态；先判断终止方式，再提取退出码或信号 |
