# 3. 进程概念

## 1. 冯诺依曼体系结构
**组成与分工**：
- 五大部件：**输入设备、输出设备、存储器、运算器、控制器**；运算器与控制器组成 CPU。
- 本节的存储器主要指内存：保存正在使用的程序和数据；磁盘属于外存，用于持久保存。
- 输入/输出按数据方向划分；网卡接收时是输入设备，发送时是输出设备；磁盘也可读、可写。
**数据流与效率**：
- 本节简化模型：`输入设备 → 内存 → CPU → 内存 → 输出设备`；外设间传输：`外设 A → 内存 → 外设 B`。
- **内存是主要的数据交换中心**；“CPU 只与内存打交道”是教学抽象，不是对实际硬件 I/O 的绝对限制。
- CPU、内存、外设速度差异巨大；寄存器访问极快，外设延迟依设备与操作而异，不能一概视为毫秒级。
- 拷贝：把数据从一处复制到另一处；整体效率不仅取决于 CPU，也取决于数据传输、拷贝和等待开销。
**存储层次**：

| 从快到慢的典型层次 | 特点 |
|---|---|
| 寄存器 | CPU 内部；容量极小，访问最快 |
| 高速缓存 `L1 → L2 → L3` | 通常使用 SRAM；保存近期可能再使用的数据；一般 L1 最快 |
| 内存 DRAM | 保存运行中的程序与数据；容量较大、成本较低 |
| 磁盘 | 长期存储，断电后通常保留数据 |
| 网盘 | 远程服务器存储；访问受网络影响 |

- 越靠上，通常速度越快、单位容量成本越高、容量越小；SRAM 为静态随机存取存储器，DRAM 为动态随机存取存储器。
**跨主机通信**：
- QQ 文字：`A 键盘 → A 内存 → A 网卡 → 网络 → B 网卡 → B 内存 → B 显示器`。
- 文件传输：`A 磁盘 → A 内存 → A 网卡 → 网络 → B 网卡 → B 内存 → B 磁盘`。
- 两台主机各有自己的体系结构；上述为简化数据路径，省略 CPU 处理等环节。

## 2. 操作系统(Operator System)
**定位与目的**：
- OS 的英文全称为 **Operating System**；本质是统一管理计算机软硬件资源的软件。
- 狭义 OS＝内核；广义 OS＝内核＋shell、函数库、系统工具等配套软件。
- 内核负责进程、内存、文件、设备等管理；shell 解释命令；`glibc` 是 Linux 常用的 C 函数库；驱动负责具体硬件控制。
- **对下管理资源是手段，对上提供统一、方便、安全的程序执行环境是目的。**
**管理方法**：
- 管理依据是描述对象的数据；信息可由中间层获取，操作由内核模块、驱动等执行。
- **先描述，再组织**：结构体记录对象信息，链表、队列等组织多个对象；管理落到数据结构的增、删、查、改。
- 进程描述结构为 `task_struct`；组织方式包括进程链表、调度队列、等待队列。
**访问层次**：
- 典型路径：`用户程序 / shell → 库函数或系统调用接口 → 内核 → 驱动 → 硬件`；库函数不是必经层。
- 系统调用是用户程序请求内核服务的正式入口；关注**服务、参数、返回值**；内核检查地址、权限、资源及参数合法性。
- `printf` 是格式化输出库函数：写入标准输出 `stdout`；通常连接终端，也可重定向到文件；实际输出时通常借助系统调用，可能先经过用户态缓冲。
**库函数与系统调用**：

| 对比项 | 库函数 | 系统调用 |
|---|---|---|
| 所在层次 | 用户态函数库 | 内核提供的服务接口 |
| 作用 | 提供便捷封装、格式化等功能 | 请求受保护的系统服务 |
| 是否进入内核 | 不一定 | 会 |
| 关系 | 可能封装一个或多个系统调用 | 由内核处理请求 |
| 跨平台 | 标准库接口可屏蔽部分差异 | 不同 OS 的接口可能不同 |

## 3. 进程
**定义与描述**：
- 课本视角：程序的一次执行实例；资源视角：操作系统分配资源的实体。
- **进程＝内核管理数据结构＋自己的代码和数据**；Linux 用 `task_struct` 描述进程，用户程序不能任意直接修改它。
- 管理不只是操作一条链表，还涉及调度队列、地址空间、文件资源等。

| `task_struct` 相关信息 | 作用 |
|---|---|
| 标识符 | PID 区分进程，PPID 表示父进程 |
| 状态、优先级 | 表示运行条件与调度属性 |
| 程序计数器、上下文 | 保存执行位置、寄存器现场 |
| 内存管理信息 | 关联代码、数据、地址空间 |
| I/O 状态 | 关联打开的文件、等待的事件 |
| 记账信息 | 记录 CPU 时间等资源使用情况 |

**查看与控制**：
- `ps aux`：用户格式查看进程；`a` 扩展到其他用户的终端进程，`x` 包含无终端进程，`u` 使用用户格式。
- `ps axj`：作业格式查看 PID、PPID、进程组等；`j` 表示作业格式；状态见 `STAT` 列。
- `/proc`：内核动态生成信息的虚拟文件系统；`ls -l /proc/PID/` 查看进程信息，`ls -l /proc/PID/exe` 查看可执行文件链接，`ls -l /proc/PID/cwd` 查看当前工作目录链接。
- `kill` 的本质是发送信号，不一定终止进程。

| 操作 | 信号与效果 |
|---|---|
| `Ctrl+C` | 向终端前台进程组发送 `SIGINT`，默认终止 |
| `kill -9 PID` | 向指定进程发送 `SIGKILL`，不可捕获、阻塞或忽略；`D` 状态下可能延迟生效 |
| `kill -STOP PID` | 暂停进程 |
| `kill -CONT PID` | 继续运行 |

**身份接口**：
- 头文件 `<unistd.h>`；`pid_t` 为进程 ID 类型。
- `pid_t getpid(void)`：无参数，返回当前 PID；`pid_t getppid(void)`：无参数，返回当前父进程 PID。
- `man 2 getpid`、`man 2 getppid`：查看第 2 区系统调用手册。
- 命令行启动的普通外部程序，其父进程通常是当前 shell，如 `bash`。
**`fork` 接口与执行流**：
- 头文件 `<unistd.h>`；原型 `pid_t fork(void)`：无参数，以调用进程为模板创建子进程。

| 结果 | 父进程返回值 | 子进程返回值 |
|---|---:|---:|
| 成功 | 子进程 PID，正数 | `0` |
| 失败 | `-1` | 不创建子进程 |

```c
pid_t ret = fork();                 // 一次调用，成功后两个进程继续执行
if (ret < 0) return 1;              // 创建失败
if (ret == 0) {
    /* 子进程：ret 为 0 */         // 独立执行流
} else {
    /* 父进程：ret 为子进程 PID */ // 可据此管理子进程
}
```

- 成功时建立子进程管理结构，初始化继承信息，加入管理结构与调度队列；父子都从 `fork` 返回处继续，**不会从 `main` 开头重跑**。
- “返回两次”指两个进程各返回一次；父子分别拥有自己的 `ret`，不是同一进程中的 `if/else` 同时成立。
- 父子关系可为 `1:n`；父进程取得子 PID，子进程可通过 `getppid()` 获取父 PID。
- 父子执行先后由调度决定；`sleep` 只能影响时机，不是可靠同步。
**共享与独立性**：
- 父子可共享只读代码物理页；私有数据在逻辑上独立，最初可共享物理页，写入时通过写时拷贝分离。
- 子进程修改全局变量，不改变父进程中的变量值；相同虚拟地址不代表同一个物理存储位置。
**理论状态与队列**：

| 状态 | 核心含义 | 队列或内存特征 |
|---|---|---|
| 运行/就绪 | 正在执行或等待 CPU | 可运行任务由 `runqueue` 管理 |
| 阻塞 | 等待事件或非 CPU 资源 | 离开运行队列，进入相应等待队列 |
| 挂起 | 教学模型中，暂不运行且相关内存被换出 | 管理信息仍需保留；现代 Linux 通常按页换出，不单列“挂起”状态 |

- 单个逻辑 CPU 同一时刻通常执行一个任务；`running` 不等于此刻正在占用 CPU。
- 阻塞解除：事件就绪后转为可运行；**状态变化通常伴随状态字段及队列关系变化**。
- `swap` 是内存页的后备存储区域；换出不等于进程退出，也不等于 `T` 停止状态。
**Linux 内核状态**：

| 字母 | 含义 | 易忘点 |
|---|---|---|
| `R` | running/runnable | 正在执行或已就绪 |
| `S` | 可中断睡眠 | 等待事件，可被相关信号唤醒 |
| `D` | 不可中断睡眠 | 常见于 I/O 等内核等待；`kill -9` 也可能无法立即终止 |
| `T` | 停止 | 可由 `SIGSTOP` 产生，`SIGCONT` 恢复 |
| `t` | 跟踪停止 | 调试器追踪、断点等 |
| `X` | 死亡 | 短暂内部状态，通常难以观察 |
| `Z` | 僵尸 | 已退出，退出信息尚未回收 |

- `STAT` 中 `+` 表示属于终端前台进程组，不是独立状态。
- `dd if=/dev/zero of=bigfile bs=1M count=1024`：写入约 1 GiB 数据，可尝试观察 I/O 等待；不保证一定捕获 `D`。
- `dd` 参数：`if` 输入文件，`of` 输出文件，`bs` 块大小，`count` 块数。
**僵尸与孤儿**：

| 对比项 | 僵尸进程 | 孤儿进程 |
|---|---|---|
| 核心条件 | 子进程退出，尚未被回收 | 原父进程先退出 |
| 子进程能否运行 | 不能 | 可以继续运行 |
| 保留内容 | 退出状态、PID、部分内核管理信息 | 正常运行所需资源 |
| 后续处理 | 父进程通过等待接口读取退出信息并回收 | 由子收割者或 PID 1（如 `init/systemd`）接管，退出后回收 |

- 退出信息包括退出码、终止信号等；**保留退出信息不等于仍保留全部用户内存**。
- 大量未回收僵尸持续占用 PID、进程表项等内核资源，可能导致资源耗尽；不能靠再次杀死僵尸回收。
- 实验关键：子进程退出，父进程 `sleep(60)` 且不等待；用 `ps axj | grep Z` 粗略观察，以 `STAT` 列为准。
- `waitpid(pid, NULL, 0)`：阻塞等待指定子进程，忽略退出状态；头文件 `<sys/wait.h>`，原型 `pid_t waitpid(pid_t pid, int *status, int options)`。
- `pid` 指定等待对象，`status` 接收状态或为 `NULL`，`options` 控制等待方式；返回已报告状态的子 PID，失败返回 `-1`；非阻塞模式无可报告状态时返回 `0`。
**内核嵌入式链表**：
- `list_head` 保存 `next`、`prev`；嵌入 `task_struct` 等宿主结构，链表算法只操作链接节点。
- `offsetof(type, member)` 得到成员相对结构体起始位置的字节偏移。
- **宿主首地址＝成员地址－成员偏移**；实际常借助 `container_of`、`list_entry` 等宏恢复宿主指针。

```c
struct list_head {
    struct list_head *next, *prev; // 双向链接
};
struct task_demo {
    int pid;                      // 业务字段
    struct list_head node;        // 嵌入节点，示意结构
};
```

**优先级与调整**：

| 项目 | 含义与范围 |
|---|---|
| `PRI` | 优先级的显示值；本节普通进程模型中数值越小，优先级越高 |
| `NI` / `nice` | 优先级修正值，范围 `[-20, 19]`，共 40 级 |
| 教学显示模型 | 默认 `PRI=80`，可记为 `PRI=80+NI`；不应反复累加旧 PRI |
| 实际调度效果 | nice 越小通常获得更高 CPU 权重，不保证严格先执行 |

- `PRI` 的显示尺度依工具、调度策略而异；不要把 `ps` 显示值直接当作内核数组下标。
- `top` → 按 `r` → 输入 PID → 输入新 nice 值。
- `nice -n 10 ./program`：以指定 nice 调整量启动；`renice 10 -p 1234`：将已有进程 nice 设为 `10`；降低 nice、提高优先级通常需要权限。
- `<sys/resource.h>`：`int getpriority(int which, id_t who)`、`int setpriority(int which, id_t who, int prio)`。
- `which` 选择进程、进程组或用户，`who` 指定对象；`PRIO_PROCESS` 配合 `who=0` 表示当前进程；`prio` 为 nice 值。
- `getpriority` 返回 nice 值，`-1` 也可能是合法值，需结合 `errno` 判断失败；`setpriority` 成功返回 `0`，失败返回 `-1`。
**竞争、独立、并发、并行**：

| 概念 | 判断重点 |
|---|---|
| 竞争性 | 多个进程争夺有限资源 |
| 独立性 | 地址空间与管理信息隔离；私有数据修改互不影响 |
| 并发 | 多个任务在同一时间段推进；单 CPU 可交替执行 |
| 并行 | 多个任务同一时刻真正执行；需要多个执行单元 |

**时间片与上下文切换**：
- 分时：CPU 时间分段分配；时间片耗尽、阻塞、抢占等可触发调度。
- 上下文包含程序计数器、通用寄存器、栈指针、状态寄存器等。
- 核心过程：`保存 A 的现场 → 选择 B → 恢复 B 的现场 → B 继续执行`。
- 每个任务保留自己的上下文，存储涉及 `task_struct` 相关结构及内核栈；进程切换还可能切换地址空间，不只是寄存器复制。
**早期 Linux 2.6 的经典 `O(1)` 调度器**：
- 每个 CPU 对应一个 `runqueue`；多 CPU 间通过任务迁移实现负载均衡；此处是历史模型，不代表所有后续内核。
- 内核优先级共 140 级：`[0,99]` 为实时范围，`[100,139]` 为普通范围；普通静态优先级对应 `120+nice`。
- `queue[140]`：下标表示优先级，每项为任务链表；同级任务按队列次序轮转。
- 非空位图：队列非空置 `1`，为空置 `0`；在 32 位字的教学表示中，`bitmap[5]` 提供 `160` 位，足以标记 140 级。

| 集合 | 保存任务 |
|---|---|
| `active` | 当前可参与本轮调度的任务 |
| `expired` | 本轮时间片耗尽、等待后续轮次的任务 |

- 简化流程：`位图定位最高优先级非空队列 → 取队首 → 运行 → 时间片耗尽后进入 expired`。
- `active` 为空时，**交换 `active/expired` 指针**，不逐个复制任务。
- `O(1)` 指选择下一任务等核心操作不随任务总数线性增长，不表示所有调度相关操作均为常数复杂度。

## 4. 命令行参数和环境变量
**两类输入**：

| 对比项 | 命令行参数 | 环境变量 |
|---|---|---|
| 表示 | 参数字符串数组 `argv` | `NAME=value` 字符串表 |
| 用途 | 本次调用的选项、文件名等 | 搜索路径、主目录等运行环境 |
| 来源 | shell 解析命令后传入 | 父进程提供，通常继承导出的环境 |
| 结束标志 | `argv[argc] == NULL` | 环境表最后一项为 `NULL` |

- `int main(int argc, char *argv[])`：`argc` 包含程序名，`argv[0]` 通常为程序名，`argv[1]` 起为用户参数。
- `ls -a -l`：`argc=3`，参数依次为 `"ls"`、`"-a"`、`"-l"`；程序根据参数选择行为。
- 比较选项可用 `strcmp(argv[i], "-a") == 0`；`<string.h>` 中 `int strcmp(const char *s1, const char *s2)`，相等返回 `0`，否则返回负值或正值。
**环境变量与继承**：
- **“全局属性”指沿父子进程关系向下继承，不是整台机器共享同一张表。**
- 父进程导出的环境可传给后续启动的子程序；子进程修改不会反向修改父进程或自动同步给其他进程。
- shell 的普通本地变量未导出时，不会进入启动外部程序时传递的环境表；不要与 `fork` 复制父进程地址空间混淆。
- `~/.bash_profile` 常用于登录 shell；`~/.bashrc` 常用于交互式非登录 bash，登录配置也常主动读取它。

| 变量 | 含义 |
|---|---|
| `PATH` | 命令搜索目录，冒号分隔，按顺序搜索 |
| `HOME` | 用户主目录 |
| `SHELL` | 通常记录用户的登录 shell，不一定是此刻正在执行的 shell |
| `USER` | 环境中的用户名信息，可被修改 |

**常用命令**：

| 命令 | 用途与易忘点 |
|---|---|
| `echo $PATH`、`echo $HOME`、`echo $SHELL` | `$` 展开变量值 |
| `export MYENV="hello"` | 设置并导出变量 |
| `export MESSAGE="hello linux"` | 带空格的值使用引号 |
| `export PATH=$PATH:$HOME/bin` | 保留旧 PATH，追加搜索目录 |
| `env` | 显示环境变量 |
| `env \| grep '^PATH='` | 筛选 PATH |
| `set` | 显示 shell 变量，包括本地变量、环境变量及其他 shell 信息 |
| `unset MYENV` | 删除当前 shell 的变量 |
| `type export`、`type ls` | 查看内建命令、别名或外部命令类型 |

- `export PATH=$HOME/bin` 会覆盖旧搜索目录；命令名不含 `/` 时通常通过 `PATH` 搜索，`./program`、`/usr/bin/ls` 使用指定路径。
- `export` 是 bash 内建命令，直接修改当前 shell 的数据；普通子进程不能替父 shell 完成这种修改。
**读取环境变量**：

| 方式 | 接口 | 内容与注意点 |
|---|---|---|
| `main` 第三个参数 | `int main(int argc, char *argv[], char *envp[])` | 常见 Unix 扩展，非 ISO C 标准形式；可遍历整表 |
| 全局变量 | `extern char **environ` | 指向当前进程环境表，可在其他函数访问 |
| 库函数 | `char *getenv(const char *name)` | `<stdlib.h>`；按名称查找，最常用 |

- 环境表每项是以 `'\0'` 结尾的 `"NAME=value"`，整张表以空指针结束。
- `getenv("PATH")` 中名称不带 `=`；找到返回**值部分**的指针，不存在返回 `NULL`；使用前检查空指针，不应自行 `free` 返回值。
**继承实验与安全边界**：

```bash
unset MYENV                       # 清除已有值与导出状态
MYENV="hello"                     # 仅设置本地变量
env | grep '^MYENV='              # 无输出
export MYENV                      # 导出已有变量
env | grep '^MYENV='              # 输出 MYENV=hello
```

- 已导出的变量重新赋值通常仍保留导出属性；对比实验应先 `unset`。
- `getenv("USER")` 可影响程序行为，但**不能用于可靠身份认证**：用户可执行 `export USER=alice` 伪造值；权限判断应依据 OS 用户身份及权限机制。

## 5. 程序地址空间
**地址类型与范围**：

| 项目 | 含义 |
|---|---|
| 物理内存 | 实际内存硬件提供的存储空间 |
| 虚拟地址空间 | 进程可使用的地址范围、区域及权限描述 |
| 页表 | 虚拟页到物理页及访问权限等的映射信息 |

- 普通用户程序中的函数、变量、堆指针等地址通常都是**虚拟地址**，不直接表示物理内存位置。
- 32 位地址范围为 `2^32` 字节＝4 GiB；典型 32 位 Linux 采用用户 3 GiB＋内核 1 GiB，具体划分可配置。
- 64 位理论范围为 `2^64` 字节；实际硬件与 OS 通常只实现部分地址位。
- **拥有大虚拟地址空间，不等于已占用同等大小的物理内存。**
**典型布局与增长方向**：

| 低地址到高地址的教学布局 | 内容 |
|---|---|
| 代码段、只读区域 | 机器指令、只读数据 |
| 已初始化数据段 | 非零初始化的全局、静态变量等 |
| BSS | 未显式初始化或零初始化的全局、静态变量；初始为零 |
| 堆 | `malloc/new` 等动态分配区域 |
| 映射/共享区 | 动态库、文件映射、匿名映射等 |
| 栈 | 调用现场、部分参数、局部变量等 |
| 参数与环境字符串 | 通常位于初始用户栈附近 |
| 内核空间 | 典型 32 位划分中的高地址部分 |

- 堆通常向高地址增长，栈通常向低地址增长；映射布局受平台、编译器、分配器与 ASLR 影响。
- 连续 `malloc` 不保证地址连续或递增；局部变量声明顺序不保证对应栈地址顺序；大块分配也可能使用映射区。
- 验证时打印函数、全局变量、BSS、堆、局部变量、`argv/envp` 的地址；对象指针可用 `printf("%p", (void *)&obj)`。
- 编译运行：`g++ -o layout layout.cpp`、`./layout hello`；多次地址不同可由 ASLR 引起。
**`fork` 地址实验与写时拷贝**：
- 全局变量 `g_val=0`；子进程改为 `100`，父进程等待后仍读到 `0`；父子打印的 `&g_val` 数值可以相同。
- **相同虚拟地址＋不同进程页表，可以对应不同物理页。**
- 刚 `fork` 后：父子私有地址空间逻辑独立，但部分物理页共享；写时通过受保护映射触发处理，必要时复制物理页并修改写入方映射。
- 修改后：`父虚拟地址 → 父页表 → 旧页`；`子虚拟地址 → 子页表 → 新页`。
- 写时拷贝以页为单位，不是只复制被修改的单个变量；该结论针对私有映射，显式共享内存不按此方式隔离修改。
**内核描述结构**：
- 普通独立进程的简化关系：`task_struct → mm_struct → VMA 与页表`；线程可共享 `mm_struct`。
- `mm_struct` 描述地址空间整体；VMA（虚拟内存区域）描述一段连续虚拟区域的边界、权限、映射用途等。
- 典型字段：`start_code/end_code` 表示代码边界，`start_brk/brk` 表示堆相关边界，`start_stack` 记录栈起始信息。
- 区域扩展主要修改边界与映射管理信息，不等于立即搬运整块数据。

| 旧版 Linux 的 VMA 组织 | 主要用途 |
|---|---|
| `mmap` 指向的链表 | 按地址顺序遍历 |
| `mm_rb` 红黑树 | 快速按地址查找 |

- 旧版中两者同时维护，不是“区域少只用链表、区域多才用树”；新内核已采用 Maple Tree 等结构。
**加载与按需分配**：
- 加载可执行文件时，根据加载信息建立代码、数据等映射，并初始化相关地址空间描述；栈、动态库等区域另行建立。
- 创建地址空间、建立 VMA，不要求立即把全部代码和数据装入物理内存。
- `malloc/new` 返回虚拟地址；可能复用已映射内存，也可能扩展区域；首次实际访问尚未驻留的合法页面时，可通过缺页处理分配或调入物理页。
- 页表由内核管理，CPU 地址转换硬件使用；缺页处理不只处理错误，也用于按需加载和写时拷贝。
**虚拟地址空间的收益与边界**：
- **布局抽象**：虚拟连续区域可映射到分散物理页，程序不依赖具体物理装载位置。
- **隔离与保护**：映射和读/写/执行权限限制访问；非法访问通常导致信号或程序终止。
- **管理解耦**：进程地址布局与物理内存分配分离，支持按页分配、调入、换出、回收及共享。
- 权限检查不能发现所有内存错误：野指针若落入合法可写区域，仍可能破坏本进程数据。
