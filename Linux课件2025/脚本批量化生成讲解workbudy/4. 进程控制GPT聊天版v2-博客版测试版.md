# 4. 进程控制

## 1. 进程创建

### 1-1 fork函数初识

**函数原型：**

```c
#include <unistd.h>

pid_t fork(void);
```

`fork` 从当前进程创建一个新进程。新进程称为子进程，调用 `fork` 的原进程称为父进程。

**内核执行过程：**

- 为子进程分配必要的内存和内核数据结构，例如进程管理对象。
- 复制父进程中可以继承的部分数据，并设置新的 PID 等子进程专属信息。
- 将子进程加入系统进程列表，使其可以被调度。
- `fork` 返回后，父子进程从同一条代码位置继续执行，但拥有各自的执行流。

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main(void)
{
    pid_t pid;

    printf("Before: pid is %d\n", getpid());

    if ((pid = fork()) == -1) {
        perror("fork");
        exit(1);
    }

    printf("After: pid is %d, fork return %d\n", getpid(), pid);
    sleep(1);
    return 0;
}
```

可能输出：

```text
Before: pid is 43676
After: pid is 43676, fork return 43677
After: pid is 43677, fork return 0
```

**执行规律：**

- `fork` 之前只有父进程执行，因此 `Before` 只输出一次。
- `fork` 之后父子进程都从 `fork` 后的代码继续执行，因此 `After` 输出两次。
- 子进程不会重新执行 `fork` 之前的代码。
- `fork` 后父子进程谁先执行由调度器决定，不能假定固定顺序。
- `fork` 失败时不会产生“返回值为 `-1` 的子进程”，只有原进程得到 `-1`。

### 1-2 fork函数返回值

`fork` 是同一个函数调用，但由于父子进程分别执行，因此在不同进程中得到不同返回值：

| 执行进程 | `fork` 返回值 | 含义 |
|---|---:|---|
| 子进程 | `0` | 表明当前执行流是子进程 |
| 父进程 | 子进程 PID，`>0` | 用于区分并管理新建的子进程 |
| 调用失败 | `-1` | 创建失败，通常检查 `errno`，可用 `perror` 输出原因 |

`pid_t` 是表示进程 ID 的整数类型，可以表示正常 PID，也可以表示 `-1` 等错误值。

**典型分流：**

```c
pid_t pid = fork();

if (pid < 0) {
    perror("fork");       // 创建失败
} else if (pid == 0) {
    printf("child: %d\n", getpid());
} else {
    printf("parent: child pid = %d\n", pid);
}
```

### 1-3 写时拷贝

**共享与复制：**

- `fork` 后，父子进程拥有独立的地址空间。
- 父子进程的代码通常可以共享。
- 在双方都不修改数据时，数据对应的物理页也可以暂时共享。
- 任意一方尝试写入共享页时，内核才为其创建独立副本，这就是**写时拷贝**（Copy-On-Write，COW）。

写时拷贝是一种延时申请技术：不立即复制所有内存，只有真正发生写操作时才复制，从而减少创建进程时的开销，提高内存利用率。

**关键结论：**

- 父子进程初始内容相同，但之后修改互不影响。
- 写时拷贝保证了父子进程的独立性。
- `fork` 并不意味着立即完整复制父进程的全部代码和数据。

### 1-4 fork常规用法

**复制自身并分工：**

- 父进程继续等待客户端请求。
- 每收到一个请求，就创建子进程处理当前请求。
- 父进程和子进程可以执行原程序中的不同代码段。

**创建进程后执行另一个程序：**

- 先调用 `fork` 创建子进程。
- 子进程从 `fork` 返回后调用 `exec`。
- `fork` 负责创建进程，`exec` 负责替换当前进程运行的程序。

### 1-5 fork调用失败的原因

`fork` 创建进程需要消耗内存、进程管理对象等系统资源。常见失败原因包括：

- 系统中的进程总数过多。
- 实际用户拥有的进程数超过限制。
- 内存等其他系统资源不足。

失败时应根据 `perror("fork")` 或 `errno` 判断具体原因，不能看到 `-1` 就简单认定为进程数量超限。

## 2. 进程终止

### 2-1 进程退出场景

进程终止的本质是释放该进程占用的系统资源，包括相关内核数据结构以及用户空间的代码、数据等。

**常见退出场景：**

| 场景 | 说明 | 常见状态 |
|---|---|---|
| 代码运行完毕且结果正确 | 程序主动结束并报告成功 | 通常退出码为 `0` |
| 代码运行完毕但结果不正确 | 程序主动发现错误并结束 | 通常退出码为非 `0` |
| 代码异常终止 | 被信号终止，没有正常执行到退出位置 | 需要查看终止信号 |

“正常终止”只说明结束方式正常，不代表任务一定成功。例如程序发现输入错误后执行 `return 1`，仍然属于正常终止。

### 2-2 进程常见退出方法

**正常终止：**

1. 从 `main` 返回。
2. 调用 `exit`。
3. 调用 `_exit`。

**异常终止：**

- 进程收到 `SIGINT` 等信号，例如前台程序通常可通过 `Ctrl+C` 发送 `SIGINT`。
- 信号的默认行为可能是终止进程，但程序也可以捕获或忽略某些信号。

**退出码与 `$?`：**

Shell 使用 `$?` 保存上一条命令的状态：

```bash
ls /             # 执行命令
echo $?          # 紧接着查看上一条命令的退出状态
```

- `0`：通常表示成功。
- 非 `0`：通常表示失败或其他特殊状态，具体含义由程序约定。
- `$?` 只表示当前 shell 中上一条命令的状态，不是系统中最近结束的任意进程。
- 查看时必须紧接着执行 `echo $?`，否则中间执行的命令会覆盖该值。

**常见退出状态：**

| 退出码 | 含义 |
|---:|---|
| `0` | 命令执行成功 |
| `1` | 常见的通用错误码，但不是所有程序的统一规定 |
| `130` | 通常表示被 `SIGINT`（信号 2）终止，即 `128 + 2` |
| `143` | 通常表示被 `SIGTERM`（信号 15）终止，即 `128 + 15` |
| `128+n` | Shell 通常用来表示被信号 `n` 终止 |

`130`、`143` 是 Shell 的报告值，程序也可以主动返回 `130`，因此不能仅凭这个数字绝对判断终止原因。

**`strerror`：**

`strerror` 翻译的是 `errno` 错误编号，不是任意程序的退出码。

```c
#include <string.h>

char *strerror(int errnum);
```

```c
#include <stdio.h>
#include <string.h>
#include <errno.h>

int main(void)
{
    puts(strerror(EACCES));    // 输出权限不足等错误描述
    return 0;
}
```

不能用 `strerror(130)` 判断程序为什么退出；退出码是程序约定的结果，`strerror` 解释的是系统调用或库函数使用的错误编号。

**`_exit` 函数：**

```c
#include <unistd.h>

void _exit(int status);
```

- `status` 表示进程终止状态。
- 父进程可通过 `wait` 或 `waitpid` 获取该状态。
- 虽然参数类型是 `int`，但正常退出码只有低 8 位可被父进程取得，范围为 `0～255`。
- `_exit(-1)` 的低 8 位为全 `1`，因此 Shell 中通常看到 `255`。

```c
#include <unistd.h>

int main(void)
{
    _exit(-1);
}
```

```bash
./a.out
echo $?       # 通常输出 255
```

`_exit` 直接结束进程，不执行 C 库注册的退出清理函数，也不刷新 C 库输出缓冲区。

**`exit` 函数：**

```c
#include <stdlib.h>

void exit(int status);
```

`exit` 最终也会进入底层进程终止路径，但在此之前会：

1. 执行通过 `atexit` 或 `on_exit` 注册的清理函数。
2. 刷新并关闭 C 标准 I/O 流，将缓冲数据写出。
3. 结束整个进程。

`on_exit` 并不是标准 C 接口；`exit` 的正确头文件是 `<stdlib.h>`。

| 对比项 | `exit` | `_exit` |
|---|---|---|
| 执行 `atexit`/`on_exit` 清理函数 | 是 | 否 |
| 刷新 C 库输出缓冲区 | 是 | 否 |
| 结束整个进程 | 是 | 是 |
| 典型用途 | 一般程序退出 | `fork` 后子进程需要直接结束等场景 |

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main(int argc, char *argv[])
{
    static char buffer[4096];

    setvbuf(stdout, buffer, _IOFBF, sizeof(buffer)); // 设置全缓冲
    printf("hello");                                 // 先留在 C 库缓冲区

    if (argc > 1)
        _exit(0);                                    // 不刷新，通常看不到 hello

    exit(0);                                         // 刷新后输出 hello
}
```

```bash
./a.out          # 使用 exit，通常输出 hello
./a.out direct   # 使用 _exit，通常不输出 hello
```

这里比较的是 C 语言库的缓冲区，不是操作系统内部缓冲区；刷新到操作系统也不等于已经写入磁盘硬件。

**`return` 退出：**

| `return` 所在位置 | 效果 |
|---|---|
| `main` 中 | 等同于调用 `exit(n)`，结束进程 |
| 普通函数中 | 只结束当前函数调用，将结果返回给调用者 |
| 任意函数调用 `exit(n)` | 直接结束整个进程 |

```c
#include <stdio.h>

int check(void)
{
    return 2;                // 只返回给 main
}

int main(void)
{
    int result = check();
    puts("main is still running");
    return result;            // 等价于 exit(2)
}
```

## 3. 进程等待

### 3-1 进程等待必要性

子进程退出后，父进程必须通过等待接口回收其退出信息和相关资源。

**必要性：**

- 父进程不回收子进程，子进程可能成为僵尸进程。
- 僵尸进程已经结束，`kill -9` 也无法杀死它；只能由父进程等待回收。
- 父进程可以通过等待得知子进程是否正常退出、退出码是多少、是否被信号终止。
- 即使父进程不关心退出状态，也应使用 `wait(NULL)` 或 `waitpid(..., NULL, ...)` 回收资源。

**“正常退出”和“任务成功”不同：**

- `WIFEXITED(status)` 判断的是是否通过正常退出路径结束。
- `WEXITSTATUS(status)` 才能取得正常退出路径中的退出码。
- 程序返回非零退出码仍然可能是正常终止。

### 3-2 进程等待的方法

**`wait` 函数**：

```c
#include <sys/types.h>
#include <sys/wait.h>

pid_t wait(int *status);
```

**参数与返回值：**

- `status` 是输出型参数，由内核填入子进程退出状态。
- 传入 `NULL` 表示不关心退出状态，但仍然会回收子进程。
- 成功返回被回收子进程的 PID。
- 失败返回 `-1`。
- 有尚未退出的子进程时，父进程会阻塞。
- 子进程已经退出时，`wait` 会立即回收并返回。
- 没有可等待的子进程时立即返回 `-1`。

**`waitpid` 函数**：

```c
#include <sys/types.h>
#include <sys/wait.h>

pid_t waitpid(pid_t pid, int *status, int options);
```

**`pid` 的取值：**

| `pid` 取值 | 等待对象 |
|---:|---|
| `pid > 0` | PID 等于 `pid` 的子进程 |
| `pid == -1` | 任意一个子进程，与 `wait` 等效 |
| `pid == 0` | 与调用者同一进程组的任意子进程 |
| `pid < -1` | 进程组 ID 等于 `pid` 绝对值的任意子进程 |

这些选择都受“调用者自己的子进程”限制，不能通过 `waitpid` 等待任意进程。

**`status`：**

- 与 `wait` 相同，是输出型参数。
- 不关心状态时可传 `NULL`。
- 只有返回值大于 `0`、确实回收了子进程后，才能解析 `status`。

**`options`：**

| `options` | 行为 |
|---:|---|
| `0` | 阻塞等待 |
| `WNOHANG` | 非阻塞；没有符合条件的已退出子进程时立即返回 |

**返回值：**

| 情况 | 返回值 |
|---|---:|
| 成功回收子进程 | 被回收子进程 PID，`>0` |
| 使用 `WNOHANG`，子进程尚未退出 | `0` |
| 调用失败或不存在可等待子进程 | `-1`，并设置 `errno` |

```c
int status = 0;
pid_t ret = waitpid(child_pid, &status, 0); // 阻塞等待指定子进程

if (ret > 0) {
    if (WIFEXITED(status))
        printf("exit=%d\n", WEXITSTATUS(status));
}
```

**`status` 位图：**

`status` 不是可以直接当作退出码使用的普通整数，而是一个编码后的等待状态。Linux 中常研究其低 16 位：

| 位位置 | 正常终止 | 被信号终止 |
|---|---|---|
| 第 0～6 位，低 7 位 | 全为 `0` | 终止信号编号 |
| 第 7 位 | 通常为 `0` | core dump 标志 |
| 第 8～15 位，高 8 位 | 正常退出码 | 不应当按正常退出码解释 |

**推荐使用宏：**

| 宏 | 作用 |
|---|---|
| `WIFEXITED(status)` | 判断是否正常终止 |
| `WEXITSTATUS(status)` | 在 `WIFEXITED` 为真时提取退出码 |
| `WIFSIGNALED(status)` | 判断是否被信号终止 |
| `WTERMSIG(status)` | 在信号终止时提取信号编号 |

手动理解位图时：

```c
(st >> 8) & 0xFF       // 提取高 8 位退出码
st & 0x7F               // 提取低 7 位终止信号
```

实际代码应优先使用系统宏，避免依赖具体位布局。

```c
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void)
{
    pid_t pid = fork();

    if (pid < 0) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        sleep(2);
        exit(10);
    }

    int st = 0;
    pid_t ret = wait(&st);

    if (ret > 0 && WIFEXITED(st))
        printf("child exit code: %d\n", WEXITSTATUS(st));
    else if (ret > 0 && WIFSIGNALED(st))
        printf("signal code: %d\n", WTERMSIG(st));

    return 0;
}
```

内核会暂时保存已退出子进程的终止信息，直到父进程调用 `wait`/`waitpid` 收取；收取后再完成相应资源回收。

**阻塞与非阻塞等待**：

**阻塞等待：**

```c
pid_t ret = waitpid(-1, &status, 0);
```

- 子进程未结束时，父进程停在 `waitpid`。
- 子进程结束后，返回其 PID 并回收。
- 适合父进程只需等待结果的场景。

**非阻塞等待：**

```c
pid_t ret = waitpid(-1, &status, WNOHANG);

if (ret == 0) {
    // 子进程尚未结束，父进程可以继续做其他工作
}
```

`WNOHANG` 只保证本次调用不会因子进程未结束而阻塞。要持续等待，通常需要轮询：

```c
for (;;) {
    pid_t ret = waitpid(child, &status, WNOHANG);

    if (ret > 0) {
        if (WIFEXITED(status))
            printf("exit=%d\n", WEXITSTATUS(status));
        break;
    }

    if (ret == -1) {
        perror("waitpid");
        break;
    }

    printf("child is running\n");
    // 执行父进程自己的任务
    sleep(1);                 // 主动控制轮询频率，避免空转
}
```

父进程可以将任务函数保存为函数指针：

```cpp
typedef void (*handler_t)();

void task_one() { printf("task one\n"); }
void task_two() { printf("task two\n"); }

handler_t handlers[] = {task_one, task_two};

for (handler_t handler : handlers)
    handler();
```

`handler_t` 是自定义的函数指针类型，不是系统固定类型；需要携带更多数据时，也可以使用 `std::function<void()>`。

## 4. 进程程序替换

### 4-1 替换原理

`fork` 创建的子进程默认仍然执行父进程原来的程序。若希望子进程运行磁盘上的另一个程序，需要调用 `exec` 函数簇。

**程序替换的本质：**

- 将新程序的代码和数据加载到调用进程的地址空间。
- 用新程序替换原程序的用户空间内容。
- 从新程序的启动例程开始执行。
- 不创建新的进程。
- 调用进程的 PID 不变。
- 父进程不会受到子进程 `exec` 的影响，因为父子进程地址空间相互独立。

| 对比项 | `fork` | `exec` |
|---|---|---|
| 是否创建新进程 | 是 | 否 |
| PID | 子进程拥有新 PID | 调用者 PID 不变 |
| 运行程序 | 初始仍是原程序 | 成功后运行新程序 |
| 成功后是否回到调用位置 | 父子分别继续执行 | 不返回原程序 |

**返回规律：**

- `exec` 成功：不返回，直接从新程序开始执行。
- `exec` 失败：返回 `-1`，原程序继续执行后续代码。
- 因此 `exec` 没有成功返回值，调用返回就意味着替换失败。

```c
#include <stdio.h>
#include <unistd.h>

int main(void)
{
    printf("launcher PID=%ld\n", (long)getpid());
    fflush(stdout);                         // 防止替换时旧缓冲区未输出

    execl("./other", "other", (char *)NULL);

    perror("execl");                        // 只有失败时才执行
    return 1;
}
```

`exec` 可以替换为系统程序，也可以替换为自己编译的程序，例如 `./other`。路径相对于进程当前工作目录，而不是相对于启动程序文件所在目录。

### 4-2 替换函数

**六种函数原型：**

```c
#include <unistd.h>

int execl(const char *path, const char *arg, ...);
int execlp(const char *file, const char *arg, ...);
int execle(const char *path, const char *arg, ..., char *const envp[]);
int execv(const char *path, char *const argv[]);
int execvp(const char *file, char *const argv[]);
int execve(const char *path, char *const argv[], char *const envp[]);
```

**命名规则：**

| 字母 | 含义 | 说明 |
|---|---|---|
| `l` | list | 参数逐个列出 |
| `v` | vector | 参数放在 `argv` 数组中 |
| `p` | path | 按环境变量 `PATH` 搜索程序 |
| `e` | env | 显式提供环境变量数组 |

**函数对比：**

| 函数 | 参数形式 | 程序定位 | 环境变量 |
|---|---|---|---|
| `execl` | 列表 | 指定 `path` | 继承当前环境 |
| `execlp` | 列表 | 搜索 `PATH` | 继承当前环境 |
| `execle` | 列表 | 指定 `path` | 使用 `envp` |
| `execv` | 数组 | 指定 `path` | 继承当前环境 |
| `execvp` | 数组 | 搜索 `PATH` | 继承当前环境 |
| `execve` | 数组 | 指定 `path` | 使用 `envp` |

**列表形式：**

```c
execl("/bin/ps", "ps", "-ef", (char *)NULL);
execlp("ps", "ps", "-ef", (char *)NULL);
```

- 第一个参数是程序路径或程序名。
- 第二个参数是新程序的 `argv[0]`，通常写程序名。
- 后续参数对应 `argv[1]`、`argv[2]` 等。
- 参数列表必须以空指针结束；可变参数调用中建议写 `(char *)NULL`。

**数组形式：**

```c
char *argv[] = {"ps", "-ef", NULL};

execv("/bin/ps", argv);    // 指定路径
execvp("ps", argv);        // 按 PATH 搜索
```

`argv` 必须以 `NULL` 结尾，第一项通常是程序名。程序路径用于寻找程序，参数数组用于传给新程序，二者不要混为一谈。

**环境变量形式：**

```c
char *argv[] = {"ps", "-ef", NULL};
char *envp[] = {"PATH=/bin:/usr/bin", "TERM=console", NULL};

execve("/bin/ps", argv, envp);
```

- `envp` 中每项格式为 `"NAME=value"`。
- `envp` 必须以 `NULL` 结尾。
- 不带 `e` 的函数默认继承当前环境。
- 带 `e` 的函数使用显式提供的环境，不会自动合并旧环境。
- `putenv` 可以把 `"NAME=value"` 加入当前环境，再调用不带 `e` 的 `exec` 继承。

```c
char setting[] = "COURSE=process";
putenv(setting);                 // putenv 使用传入字符串本身
execvp("./other", argv);
```

使用 `putenv` 时，传入字符串的存储空间必须保持有效，不能立即释放或让其失效。

**六种调用示例：**

```c
char args[] = "ls";
char opt1[] = "-l";
char opt2[] = "-a";
char *argv[] = {args, opt1, opt2, NULL};

char env1[] = "COURSE=process";
char *envp[] = {env1, NULL};

execl("/usr/bin/ls", "ls", "-l", "-a", (char *)NULL);
execlp("ls", "ls", "-l", "-a", (char *)NULL);
execle("/usr/bin/ls", "ls", "-l", "-a", (char *)NULL, envp);
execv("/usr/bin/ls", argv);
execvp("ls", argv);
execve("/usr/bin/ls", argv, envp);
```

**系统调用关系：**

- 只有 `execve` 是真正的系统调用接口。
- 其他五个是库函数封装，负责整理参数、搜索 `PATH` 等，最终调用 `execve`。
- `execve` 位于 `man` 手册第 2 节，其他函数通常位于第 3 节。

## 5. 自主Shell命令行解释器

### 5-1 目标

自主 Shell 用于理解命令解释器如何工作，目标包括：

- 处理普通命令。
- 处理内建命令。
- 理解本地变量、环境变量和退出状态。
- 理解 Shell 的 `fork`、`exec`、`wait` 运行模式。

普通命令通常由子进程执行；`cd`、`export` 等需要修改当前 Shell 状态的命令必须由 Shell 自己执行。

### 5-2 实现原理

**普通命令执行流程：**

1. 打印命令行提示符。
2. 获取用户输入。
3. 解析命令行。
4. 判断是否为内建命令。
5. 普通命令：`fork`。
6. 子进程调用 `execvp`。
7. 父进程调用 `waitpid`。
8. 解析退出状态并保存到 `lastcode`。
9. 回到第 1 步。

```text
读取命令
   ↓
解析为 argv
   ↓
内建命令？──是──> Shell 自己执行
   │
   否
   ↓
fork
   ↓
子进程 execvp
父进程 waitpid
   ↓
保存退出码，继续循环
```

**内建命令与普通命令：**

| 项目 | 普通命令 | 内建命令 |
|---|---|---|
| 执行者 | 子进程中的外部程序 | Shell 自身 |
| 是否创建子进程 | 是 | 否 |
| 示例 | `ls`、`ps`、`cat` | `cd`、`export`、`env`、`echo` |
| 原因 | 外部程序执行结束后返回 Shell | 必须修改 Shell 自己的目录、环境或状态 |

`cd` 若在子进程中执行，子进程改变的只是自己的当前目录，退出后 Shell 的目录不会改变。因此 `cd` 必须是当前 Shell 的内建命令。并非所有 Shell 内建命令从理论上都不能由子进程执行，本节只是统一在 Shell 内实现。

### 5-3 源码

**核心全局数据：**

```cpp
const int basesize = 1024;
const int argvnum = 64;
const int envnum = 64;

char *gargv[argvnum];     // 命令参数，最多 63 个有效项
int gargc = 0;            // 参数个数
char *genv[envnum];       // 环境变量表，最后必须为 NULL
int lastcode = 0;         // 上一条命令的退出码
char pwd[basesize];       // 当前路径
char pwdenv[basesize];    // "PWD=路径"
```

`gargv[64]` 和 `genv[64]` 都需要保留一个位置存放 `NULL`。`pwd` 是字符数组，不是 `pwd` 命令；`pwdenv` 是供环境使用的 `"PWD=..."` 字符串。

**获取环境变量与提示符：**

```cpp
#include <unistd.h>
#include <cstdio>
#include <cstdlib>
#include <string>

std::string GetUserName()
{
    const char *s = getenv("USER");
    return s ? s : "None";
}

std::string GetHostName()
{
    const char *s = getenv("HOSTNAME");
    return s ? s : "None";
}

std::string GetPwd()
{
    if (getcwd(pwd, sizeof(pwd)) == nullptr)
        return "None";

    snprintf(pwdenv, sizeof(pwdenv), "PWD=%s", pwd);
    putenv(pwdenv);                // 让 PWD 进入当前环境
    return pwd;
}
```

提示符可使用：

```cpp
void PrintCommandLine()
{
    printf("[%s@%s %s]# ",
           GetUserName().c_str(),
           GetHostName().c_str(),
           GetPwd().c_str());
    fflush(stdout);                // 无换行时主动刷新
}
```

**读取与解析命令：**

```cpp
bool GetCommandLine(char command_buffer[], int size)
{
    char *ret = fgets(command_buffer, size, stdin);
    if (!ret)
        return false;

    command_buffer[strlen(command_buffer) - 1] = '\0'; // 去掉换行
    return strlen(command_buffer) != 0;
}

void ParseCommandLine(char command_buffer[])
{
    memset(gargv, 0, sizeof(gargv));
    gargc = 0;

    const char *sep = " ";
    gargv[gargc++] = strtok(command_buffer, sep);

    while ((gargv[gargc++] = strtok(nullptr, sep)) != nullptr)
        ;

    --gargc;
}
```

- `fgets` 可能保留换行符，需要在解析前删除。
- `strtok(command_buffer, " ")` 开始拆分。
- `strtok(nullptr, " ")` 继续拆分。
- 返回 `NULL` 表示没有更多参数。
- `strtok` 会修改原始输入字符串，`gargv` 中保存的是该数组内部的地址。
- 该简化实现不处理引号、管道、重定向和复杂转义。
- 空行可能导致 `gargc == 0`，此时不能访问 `gargv[0]`。
- 若严格处理输入，还应检查输入是否过长、参数是否超过 63 个。

**执行普通命令：**

```cpp
bool ExecuteCommand()
{
    pid_t id = fork();

    if (id < 0)
        return false;

    if (id == 0) {
        execvp(gargv[0], gargv);    // 按 PATH 搜索并执行
        perror("execvp");           // 返回说明执行失败
        _exit(1);                   // 防止子进程继续进入 Shell 循环
    }

    int status = 0;
    pid_t ret = waitpid(id, &status, 0);

    if (ret <= 0)
        return false;

    if (WIFEXITED(status))
        lastcode = WEXITSTATUS(status);
    else if (WIFSIGNALED(status))
        lastcode = 128 + WTERMSIG(status);
    else
        lastcode = 100;

    return true;
}
```

子进程执行 `execvp` 失败后必须退出，不能继续执行父 Shell 的输入循环。父进程只有在 `waitpid` 成功回收后，才可以解析 `status`。

**初始化环境变量：**

```cpp
extern char **environ;

void InitEnv()
{
    int i = 0;

    while (environ[i] != nullptr) {
        genv[i] = (char *)malloc(strlen(environ[i]) + 1);
        strcpy(genv[i], environ[i]);
        ++i;
    }

    genv[i] = nullptr;
}
```

- `environ` 是当前进程的环境变量表入口。
- `genv` 是 Shell 自己维护的环境变量表。
- 仅把字符串加入 `genv` 不一定会改变外部程序实际继承的环境；显示用的环境表与 `exec` 使用的环境表必须保持一致。
- 还应注意环境变量数量上限、字符串存储空间和新增字符串的生命周期。

**内建命令：**

```cpp
bool CheckAndExecBuiltCommand()
{
    if (strcmp(gargv[0], "cd") == 0) {
        if (gargc == 2 && chdir(gargv[1]) == 0) {
            lastcode = 0;
        } else {
            perror("cd");
            lastcode = 1;
        }
        return true;
    }

    if (strcmp(gargv[0], "env") == 0) {
        for (int i = 0; genv[i] != nullptr; ++i)
            printf("%s\n", genv[i]);
        lastcode = 0;
        return true;
    }

    if (strcmp(gargv[0], "echo") == 0) {
        if (gargc == 2 && strcmp(gargv[1], "$?") == 0) {
            printf("%d\n", lastcode);  // 先读取旧值
            lastcode = 0;
        } else if (gargc == 2) {
            printf("%s\n", gargv[1]);
            lastcode = 0;
        } else {
            lastcode = 1;
        }
        return true;
    }

    return false;
}
```

**各内建命令要点：**

- `cd`：
  - 使用 `chdir` 改变当前 Shell 的真实工作目录。
  - 成功后可用 `getcwd` 更新 `PWD`。
  - 只修改 `PWD` 字符串而不调用 `chdir`，并不会真正改变工作目录。
- `export`：
  - 简化形式为 `export NAME=value`。
  - 应检查变量名和 `=`，同名变量应替换而非无限追加。
  - 新字符串必须拥有独立且有效的存储空间。
- `env`：
  - 遍历环境变量表，直到 `NULL`。
- `echo`：
  - `echo $?` 输出上一条命令的 `lastcode`。
  - `echo $PATH` 可查询环境变量。
  - 普通文本直接输出。
  - 查询不到的环境变量不能直接把空指针传给 `%s`。
- `TrimSpace`：
  - 只跳过字符串开头的空白。
  - 与 `strtok` 不同：`TrimSpace` 处理前导空白，`strtok` 负责拆分参数。

**主循环：**

```cpp
int main()
{
    InitEnv();

    char command_buffer[basesize];

    while (true) {
        PrintCommandLine();

        if (!GetCommandLine(command_buffer, basesize))
            continue;

        ParseCommandLine(command_buffer);

        if (gargc == 0)
            continue;

        if (CheckAndExecBuiltCommand())
            continue;

        ExecuteCommand();
    }

    return 0;
}
```

### 5-4 总结

**进程控制的核心链条：**

| 阶段 | 主要接口 | 作用 |
|---|---|---|
| 创建 | `fork` | 从已有进程创建子进程 |
| 替换 | `exec*` | 用新程序替换当前进程的程序内容 |
| 终止 | `return`、`exit`、`_exit` | 结束进程并报告状态 |
| 等待 | `wait`、`waitpid` | 回收子进程并取得终止信息 |
| Shell 执行 | `fork` + `execvp` + `waitpid` | 执行外部命令并继续交互 |

**关键关系：**

- `fork` 创建新进程，`exec` 不创建新进程。
- `fork` 后父子进程执行顺序由调度器决定。
- 写时拷贝使父子进程在共享初始内容的同时保持独立。
- `exit` 会执行清理并刷新 C 库缓冲区，`_exit` 不执行这些操作。
- `wait`/`waitpid` 既用于回收资源，也用于读取子进程退出信息。
- `status` 不是直接的退出码，必须先用 `WIFEXITED` 判断，再用 `WEXITSTATUS` 提取。
- Shell 对普通命令使用子进程，对必须修改 Shell 状态的内建命令直接由自身执行。
- `exec/exit` 与 `call/return` 可以类比为“启动任务/返回结果”，但 `exec` 成功后不会返回原调用位置，`wait` 得到的也是编码后的状态而不是直接退出码。
