### 1.2、磁盘结构与寻址

#### 1\. 磁盘物理结构

- 盘片：存储数据的圆盘。
- 磁头（Head）：读写数据。
- 磁道（Track）：盘片上的同心圆。
- 柱面（Cylinder）：不同盘面上相同位置的磁道。
- 扇区（Sector）：磁盘存储的基本单位，通常为 512B。

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/9768afbe46594d05ae22ce0422ddac10.png)
#### 2.磁盘的存储结构：
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/2155435669e2411c9b73e88efc3e4a9e.png)
重点理解三个概念：磁道、柱面、扇区。

- 磁道：一个盘面上的同心圆。
- 扇区：磁道进一步划分的存储区域。
- 柱面：所有盘面上相同位置的磁道组成的集合。

其中：

- 一个扇区通常为 512 字节。
- **扇区是磁盘读写数据的基本物理单位。**
- 传动臂上的多个磁头是同步移动的。

### 2\. 两种寻址方式

| 寻址方式 | 核心思想             |
| ---- | ---------------- |
| CHS  | 通过柱面、磁头、扇区定位     |
| LBA  | 将磁盘看作一维数组，通过下标定位 |

记住：**操作系统使用 LBA，磁盘内部负责转换为实际物理位置。**

#### 1.CHS 寻址：通过物理位置定位数据

既然磁盘由磁道、磁头和扇区组成，那么如何找到一个扇区？

自然可以通过三个参数：

- C（Cylinder）：柱面号。
- H（Head）：磁头号。
- S（Sector）：扇区号。

其实，LBA的本质是就是一个三维数组！
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/9c71d3d026f24659b28d2c8c9344ea92.png)
为什么后来不再直接使用 CHS？因为 **CHS 的地址空间有限。**



| 参数   | 位数     | 可表示数量           |
| ---- | ------ | --------------- |
| 磁头 H | 8 bit  | 256             |
| 柱面 C | 10 bit | 1024            |
| 扇区 S | 6 bit  | 63（实际采用的最大扇区编号） |

由此可算出，**CHS 的最大寻址容量约为 8.4GB（十进制）**。。

#### 	 2.LBA 寻址：把磁盘看成一维数组
**把整个磁盘看成一个巨大的、以扇区为元素的一维数组。每个扇区对应一个唯一的线性地址**，这就是：

**LBA（Logical Block Address，逻辑块地址）**。

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/d427054f0cec42e796703738308e53c8.png)


这样，操作系统只需要告诉磁盘：**读取 LBA = 1000 的扇区**，就可以定位数据。



那么问题来了：磁盘物理上还是由柱面、磁头、扇区组成的，**LBA 如何找到实际物理位置？**

答案是：磁盘内部的固件负责地址转换，操作系统不需要直接处理 CHS。


### CHS转成LBA

- 磁头数 * 每磁道扇区数 = 单个柱面的扇区总数
- $\boldsymbol{LBA = 柱面号C \times 单个柱面的扇区总数 + 磁头号H \times 每磁道扇区数 + 扇区号S - 1}$
- 即：$\boldsymbol{LBA = 柱面号C \times (磁头数 \times 每磁道扇区数) + 磁头号H \times 每磁道扇区数 + 扇区号S - 1}$
- 扇区号通常是从1开始的，而在LBA中，地址是从0开始的
- 柱面和磁道都是从0开始编号的
- 总柱面，磁道个数，扇区总数等信息，在磁盘内部会自动维护，上层开机的时候，会获取到这些参数。

### LBA转成CHS
- 柱面号 $\boldsymbol{C = LBA // (磁头数 \times 每磁道扇区数)}$【就是单个柱面的扇区总数】
- 磁头号 $\boldsymbol{H = (LBA \% (磁头数 \times 每磁道扇区数)) // 每磁道扇区数}$
- 扇区号 $\boldsymbol{S = (LBA \% 每磁道扇区数) + 1}$
- `"//"`: 表示除取整


其中 C、H、S 分别表示柱面号、磁头号、扇区号。
其实很好理解：
例如，1柱面有10个磁头，1磁头里面有10个扇面，为什么取10，便于理解

## 二、块、分区与 inode

1\. Block（块）

- 操作系统不会每次只读取一个扇区，而是通常按块读取。
- 常见块大小为 4KB，即 8 个 512B 扇区。
- 块是文件系统组织和存取数据的基本单位。


2\. Partition（分区）

将一块磁盘划分为多个独立区域，每个分区可以建立自己的文件系统。

3\. inode（索引节点）

Linux 文件存储的核心思想：文件属性与文件内容分离。

- inode：保存文件属性，如权限、大小、所有者、时间、数据块位置等。
- Data Block：保存文件实际内容。
- 文件名不保存在 inode 中，而是保存在目录中。

重点：**一个文件对应一个 inode，inode 具有唯一编号**

inode 中的数据块指针：

| 指针       | 作用          |
| -------- | ----------- |
| 12 个直接指针 | 直接指向数据块     |
| 一级间接指针   | 指向存放数据块地址的块 |
| 二级间接指针   | 两级索引        |
| 三级间接指针   | 三级索引        |

## 三、Ext2 文件系统
ext2文件系统是文件系统的一种，除此之外还有：
ext3、ext4等等

核心作用：组织和管理分区中的 inode 与数据块。

Ext2 将一个分区划分为多个 Block Group（块组）。

每个块组主要包含六个部分：

| 组成           | 作用            |
| ------------ | ------------- |
| Super Block  | 描述整个文件系统的信息   |
| GDT          | 描述各个块组的信息     |
| Block Bitmap | 记录数据块使用情况     |
| Inode Bitmap | 记录 inode 使用情况 |
| Inode Table  | 存放 inode 属性   |
| Data Block   | 存放文件内容        |

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/3b45294a883443498d6fda40b072497b.png)


格式化的本质：在分区中建立文件系统的管理结构。

创建文件（touch）的核心过程：

1. 分配空闲 inode，记录文件属性。
2. 需要存储数据时，分配数据块。
3. 在 inode 中记录数据块的位置。
4. 在目录中建立文件名与 inode 号的映射。

## 四、目录、路径解析与 dentry

1\. 目录也是文件

目录的特殊之处在于：**它的内容保存的是 文件名 → inode 号 的映射关系。**

所以，访问文件时，不能仅凭文件名直接找到 inode，需要先查找目录。

2\. 路径解析

访问文件需要逐级解析路径：

```
/home/caige/test.c

/        → 根目录
home     → 查找 home 对应的 inode
caige    → 查找 caige 对应的 inode
test.c   → 找到目标文件 inode
```

- 绝对路径：从根目录 `/` 开始。
- 相对路径：以当前工作目录 CWD 为起点。

3\. dentry（目录项）

每次都从磁盘逐级解析路径效率较低，因此 **Linux 会在内存中缓存路径信息。**

`struct dentry` 是内核维护路径缓存的重要结构。



## 五、分区挂载(了解）

挂载（mount）：将一个文件系统关联到 Linux 目录树中的某个目录。

核心操作：

```bash
# 创建磁盘镜像文件
dd if=/dev/zero of=disk.img bs=1M count=5
# 格式化为 ext4 文件系统
mkfs.ext4 disk.img
# 创建挂载点
mkdir /mnt/mydisk
# 挂载
sudo mount -t ext4 disk.img /mnt/mydisk
# 查看挂载情况
df -h
# 卸载
sudo umount /mnt/mydisk
```

理解两个概念：

- 挂载点：用于接入文件系统的目录。
- Loop Device：允许把普通文件当作块设备使用。

核心：不同分区有各自独立的文件系统和 inode 编号空间，通过挂载统一接入 Linux 目录树。

## 六、软链接与硬链接
简单理解：
**软连接：快捷方式，ln -s
硬链接：文件起别名，类似引用，ln**

| 对比    | 硬链接          | 软链接      |
| ----- | ------------ | -------- |
| 本质    | 文件名映射到 inode | 独立文件     |
| inode | 与目标文件相同      | 与目标文件不同  |
| 存储内容  | 不单独保存目标路径    | 保存目标路径   |
| 跨文件系统 | 不可以          | 可以       |
| 删除原文件 | 其他硬链接仍然有效    | 可能变成悬空链接 |

创建方式：

```bash
# 创建硬链接
ln abc def
# 创建软链接
ln -s abc abc_link
```

删除文件时：

- 删除硬链接：删除目录中的映射，链接数减一。
- 链接数归零且没有其他引用时，文件数据才可以被回收。
- 删除软链接：删除软链接自身，不会删除目标文件。

三个时间属性：

| 属性     | 含义         |
| ------ | ---------- |
| Access | 最后访问时间     |
| Modify | 文件内容最后修改时间 |
| Change | 文件属性最后修改时间 |
